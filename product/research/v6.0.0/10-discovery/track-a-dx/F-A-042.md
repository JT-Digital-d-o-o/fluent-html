# SEO head helpers (OpenGraph, TwitterCard, StructuredData, Canonical) copy-pasted in 6 apps — no standard library API

## Problem

Every app that serves public HTML pages needs Open Graph tags, Twitter Card meta, a canonical link, and JSON-LD structured data. The library exposes the primitives (`Meta`, `Link`, `Script`, `MetaTag.setProperty`, `MetaTag.setName`, `MetaTag.setContent`) but no composites. Each app independently implements the same helpers:

```ts
// jtdigital-landing-page/src/shared/seo.ts:7-120
export function MetaTags(props: SEOProps): View { ... }
export function OpenGraph(props: SEOProps, siteConfig: SiteConfig): View { ... }
export function TwitterCard(props: SEOProps, siteConfig: SiteConfig): View { ... }
export function Canonical(url: string): View { ... }
export function StructuredData(data: Record<string, unknown>): View { ... }
export function SEOHead(props: SEOProps, siteConfig: SiteConfig): View { ... }
```

The same six functions with the same signatures appear in `filmplast-landing-page/src/shared/seo.ts`, `filmplast-v2/src/shared/seo.ts`, `fivb-prototype/src/shared/seo.ts`, `jtdigital-blog/src/shared/seo.ts`, and `projects-template/templates/web/src/shared/seo.ts` — every public-facing project maintains its own copy.

## Evidence

```ts
// jtdigital-landing-page/src/shared/seo.ts:117-120
export function StructuredData(data: Record<string, unknown>): View {
  return Script(JSON.stringify(data, null, 2))
    .setType("application/ld+json")
}
```

```ts
// filmplast-landing-page/src/shared/seo.ts:103-106
export function StructuredData(data: Record<string, unknown>): View {
  return Script(JSON.stringify(data, null, 2))
    .setType("application/ld+json")
}
```

```ts
// fivb-prototype/src/shared/seo.ts:124-127
export function StructuredData(data: Record<string, unknown>) {
  return Script(JSON.stringify(data, null, 2))
    .setType("application/ld+json")
}
```

The implementations are near-identical, with minor divergences in nullable handling and `imageUrl` resolution. These divergences mean each copy has slightly different bugs or behaviors that don't get fixed together.

Additionally, some apps use `Meta().setProperty("og:title")` (renderbox) while others use `Meta().addAttribute("property", "og:title")` (jtdigital-landing-page, filmplast-landing-page) — the split exists because the guideline never shows the OG pattern at all, so each app author independently discovers (or misses) `MetaTag.setProperty`.

## Why it matters

6 apps / 6 copies of the same boilerplate. When the correct OG pattern changes (e.g., new `og:image:alt` field, adding `og:video` support), each copy must be updated separately. The copy in `projects-template` propagates stale patterns to every new project.

`StructuredData()` in particular uses `Script(JSON.stringify(...))` with raw JSON embedded in a `<script>` tag — if a future version of the library changes how `script` content is sanitized, each copy is independently at risk.

## Rough idea (not a design)

Export a small set of standard SEO helpers from the library (or a `fluent-html/seo` subpath): `OgMeta({title, description, image, url, type})`, `TwitterCard({title, description, image, card})`, `Canonical(url)`, `StructuredData(data)`, plus a composed `SeoHead({title, description, ...})`. This eliminates per-app boilerplate, standardizes `setProperty` usage for OG tags, and centralizes sanitization concerns.
