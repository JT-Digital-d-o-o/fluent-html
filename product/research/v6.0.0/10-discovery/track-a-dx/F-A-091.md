# `createRequiredContext` error message omits `using _=` — recovery instruction causes a silent context leak

## Problem

When `createRequiredContext<T>(name).current` is accessed outside an active scope, the error thrown is:

```
Context "AuthCtx" accessed outside of a scope. Wrap the call in AuthCtx.scope(value).
```

The suggestion `AuthCtx.scope(value)` is syntactically valid TypeScript — it compiles and runs — but it is **wrong**. Without the `using _=` prefix, the scope is never disposed. The context stack grows without bound, and the pushed value persists for the lifetime of the process. In a Fastify server handling concurrent requests this corrupts context state for all subsequent requests.

## Evidence

```ts
// fluent-html/src/control/context.ts:116
throw new Error(`Context "${name}" accessed outside of a scope. Wrap the call in ${name}.scope(value).`);
```

The correct call form is always:
```ts
using _ = AuthCtx.scope(user);   // ✓ stack pops when block exits
AuthCtx.scope(user);              // ✗ stack NEVER pops — the error message recommends this
```

The `scope()` implementation on line 92:
```ts
scope(value: T): Disposable {
  stack.push(value);
  return {
    [Symbol.dispose]() { stack.pop(); }
  };
}
```

The returned `Disposable` is the only way to clean up. If the developer follows the error hint verbatim, they leak the context indefinitely.

## Why it matters

This is a runtime DX failure on the *unhappy path* — exactly when a developer most needs accurate guidance. The message actively steers them toward a silent correctness bug (context leak) that:

1. Won't trigger any error on next use (the context now has a value, so `.current` stops throwing).
2. Will corrupt state for all subsequent requests on the same Node.js process if the leaked value is wrong.
3. Is very hard to diagnose because the symptom (wrong user/auth in a different request) is distant from the cause.

Frequency is 1 (one place in library source), but every consumer of `createRequiredContext` who hits the error path in development is exposed.

## Rough idea (not a design)

Update the error message to include the `using _=` form explicitly:

```
Context "AuthCtx" accessed outside of a scope.
  Fix: using _ = AuthCtx.scope(value);
  ⚠ Calling AuthCtx.scope(value) without "using" will leak the context indefinitely.
```

Also consider adding a dev-mode detection: if `scope()` is called and the returned Disposable is never used (detected via a setTimeout-based heuristic or a debug flag), log a warning.
