# Paired IfThen(x) + IfThen(!x) anti-pattern

## Problem

Apps routinely write two adjacent `IfThen` calls with complementary conditions — one for the truthy case and one for the falsy case — instead of a single `IfThenElse`. The guidelines teach `IfThenElse` but never flag the two-call form as an anti-pattern, so LLMs and developers reach for `IfThen` for both branches.

## Evidence

`ttl/src/admin/views/projects-list.view.ts:157-163` — perfectly symmetric pair:

```ts
IfThen(projects.length > 0, () =>
  ProjectsTable({ projects }),
),
IfThen(projects.length === 0, () =>
  EmptyState(),
),
```

`ttl/src/admin/views/project-detail.view.ts:169-170` — consecutive pair on the same condition:

```ts
IfThen(members.length > 0, () => MembersTable({ project, members })),
IfThen(members.length === 0, () => EmptyMembers()),
```

`rideshare/src/reservations/reservations.view.ts:210,224` — non-adjacent but same condition (`reservations.length === 0` / `reservations.length > 0`).

The correct form is `IfThenElse`:

```ts
// ✓ single-expression, semantically clear
IfThenElse(members.length > 0,
  () => MembersTable({ project, members }),
  () => EmptyMembers()
)
```

The two-call form has two subtle bugs: (1) if the condition is an expression with side effects it evaluates twice; (2) if the conditions are not perfectly complementary (e.g. both branches are enabled when a third state is possible), both or neither render.

## Why it matters

5+ apps, 12+ paired-IfThen sites identified. The pattern is reinforced by the guidelines showing `IfThen` prominently (it's the first example) and `IfThenElse` only secondarily. The ✗ anti-pattern is completely absent. Given that LLMs read the guidelines as rules, the missing negative example causes systematic repetition.

## Rough idea (not a design)

One-line guideline edit in `fluent-html.md` under the Control Flow section:

```ts
// ✗ paired IfThen — evaluates condition twice, fragile if conditions drift
IfThen(items.length > 0, () => List(items))
IfThen(items.length === 0, () => EmptyState())

// ✓ IfThenElse — single expression, both branches always synchronized
IfThenElse(items.length > 0, () => List(items), () => EmptyState())
```

No code change to the library is needed; this is a pure guidelines fix.
