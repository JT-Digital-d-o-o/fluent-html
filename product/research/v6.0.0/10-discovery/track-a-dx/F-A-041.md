# No DOCTYPE support — every app emits `Raw('<!DOCTYPE html>')` (40+ layout files)

## Problem

`render(HTML(...))` never emits `<!DOCTYPE html>`. There is no API for it — `grep doctype src/` returns nothing in the library source. Every SSR app that serves a full HTML document must prepend the declaration manually by wrapping it in `Raw()`, which is the library's explicit XSS escape hatch:

```ts
// renderbox/src/app/shared/components/layout.view.ts:68
export function Layout(props: LayoutProps) {
  return [
    Raw("<!DOCTYPE html>"),   // ← forced escape-hatch for a standard, static string
    HTML(Head(...), Body(...)).setLang("en"),
  ];
}
```

The `render()` function at `render.ts:33` takes variadic `View[]` and concatenates the output; there is no wrapper type or option that triggers a doctype prefix.

## Evidence

Every layout file in the monorepo uses the same `[Raw("<!DOCTYPE html>"), HTML(...)]` pattern:

```ts
// jt-vault-cloud/src/shared/components/layout.view.ts:84
Raw("<!DOCTYPE html>"),

// jt-cut/src/shared/components/layout.view.ts:84
Raw("<!DOCTYPE html>"),

// jtdigital-landing-page/src/shared/layout.ts:128
Raw('<!DOCTYPE html>'),

// filmplast-landing-page/src/shared/layout.ts:130
Raw("<!DOCTYPE html>"),
```

`find` over the working tree identifies **40+ layout source files** (plus 20+ test files) with this pattern across renderbox, jt-vault-cloud, jt-cut, storysell-ai, glimm, jtdigital-landing-page, filmplast-landing-page, fluent-html-demos, mngmt, planet-positive-sport, jt-draw, jt-draw2, jt-i18n, vabilo30, rideshare, orca, and every project template instance.

The guidelines show `HTML(Head(), Body()).setLang("en")` as the document root example (`fluent-html.md:177`) but say nothing about DOCTYPE — a reader following the guideline will produce invalid HTML.

## Why it matters

`<!DOCTYPE html>` is **required** for browsers to render in standards mode. Its absence triggers quirks mode — a correctness issue, not a style concern. Using `Raw()` works but:
1. It forces an escape hatch for a static, trusted, library-owned string.
2. The return type changes from `HtmlTag` to `View[]`, which means you lose method chaining on the root and callers must type the return as `View`.
3. 40+ files duplicate the same pattern, and the project template propagates it to every new app.

## Rough idea (not a design)

Add a `Document(...children: View[])` factory (or `renderDocument(view)` render variant) that wraps `HTML(...)` with an automatic `<!DOCTYPE html>` prefix. The `Document` factory could accept the same children as `HTML` and return an opaque type that renders with the doctype. Alternatively, `render(view, { doctype: true })` adds minimal surface area. Either approach eliminates `Raw()` from document construction entirely.
