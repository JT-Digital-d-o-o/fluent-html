# `setAria()` key parameter is fully untyped — typos in ARIA attribute names compile and render silently

## Problem

`setAria` on `Tag` takes `attrs: Record<string, string | boolean>`:

```typescript
// fluent-html/src/core/tag.ts:298
setAria(attrs: Record<string, string | boolean>): this {
```

This means any string key is accepted at compile time. A typo like `.setAria({ lable: "Close" })` (note: `lable` not `label`) compiles cleanly, renders as `aria-lable="Close"`, and silently produces broken accessibility. The library enforces strict types for Tailwind methods, HTMX options, route parameters, and input types — but not for the most important accessibility API.

## Evidence

The current signature:
```typescript
// fluent-html/src/core/tag.ts:298
setAria(attrs: Record<string, string | boolean>): this {
  if (this.attributes === EMPTY_ATTRS) this.attributes = Object.create(null) as Record<string, string>;
  for (const [key, value] of Object.entries(attrs)) {
    const kebabKey = key.replace(/[A-Z]/g, letter => `-${letter.toLowerCase()}`);
    this.attributes[`aria-${kebabKey}`] = String(value);
  }
  return this;
}
```

Real calls in production code that would silently accept any key:
```typescript
// planet-positive-sport/src/expert/action-scoring/action-scoring.components.ts:131
.setAria({ live: "polite", label: ariaLabel });  // "live" → aria-live (correct)

// planet-positive-sport/src/loc/assessment/assessment.components.ts:108
.setAria({ hidden: "true" });  // "hidden" → aria-hidden (correct)

// rideshare/src/shared/components/tooltip.view.ts:74
.setAria({ describedby: id.id })  // "describedby" → aria-describedby (correct)
```

All of these happen to be correct. But `{ decribedby: id.id }` or `{ lable: "Close" }` would also compile, render, and silently fail AT users.

WAI-ARIA 1.2 defines a fixed set of ~50 global and role-specific aria attributes (`label`, `labelledby`, `describedby`, `hidden`, `expanded`, `checked`, `disabled`, `selected`, `pressed`, `current`, `live`, `atomic`, `relevant`, `busy`, `controls`, `owns`, `flowto`, `posinset`, `setsize`, `level`, `valuenow`, `valuemin`, `valuemax`, `valuetext`, `multiline`, `multiselectable`, `required`, `readonly`, `invalid`, `autocomplete`, `haspopup`, `modal`, `orientation`, `sort`, `colcount`, `colindex`, `colspan`, `rowcount`, `rowindex`, `rowspan`, `keyshortcuts`, `roledescription`).

## Why it matters

- Every other key API in fluent-html is typed: `InputType`, `BooleanAttribute`, `HxSwap`, `TailwindColor`, route param types — but the accessibility API is not.
- The library already exports `BooleanAttribute` with `(string & {})` for unknown values; the same pattern applies here.
- Accessibility bugs are silent at compile time, silent at render time, and only visible to screen-reader users or automated a11y audits.
- The fix is additive: a typed key union with `(string & {})` escape hatch preserves backward compat while surfacing typos.

## Rough idea

Define `AriaAttributeName` as a string literal union of the ~50 WAI-ARIA 1.2 global aria attribute names (without the `aria-` prefix) plus `(string & {})`. Change `setAria` signature to:

```typescript
type AriaAttributeName =
  | "label" | "labelledby" | "describedby" | "hidden" | "expanded"
  | "checked" | "disabled" | "selected" | "pressed" | "current"
  | "live" | "atomic" | "relevant" | "busy" | "controls" | "owns"
  | "valuenow" | "valuemin" | "valuemax" | "valuetext"
  | "haspopup" | "modal" | "multiselectable" | "required" | "readonly"
  | "invalid" | "autocomplete" | "orientation" | "sort"
  | "colcount" | "colindex" | "rowcount" | "rowindex"
  | "level" | "posinset" | "setsize"
  | "roledescription" | "keyshortcuts"
  | (string & {});

setAria(attrs: Partial<Record<AriaAttributeName, string | boolean>>): this
```

Export `AriaAttributeName` from `core/index.ts` for consumers building custom component types.
