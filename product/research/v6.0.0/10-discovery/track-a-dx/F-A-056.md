# `ariaDescribeAlgebra` ignores `aria-label` from the attributes bag — produces inaccurate descriptions for labeled elements

## Problem

`ariaDescribeAlgebra` is an accessibility auditing algebra that generates human-readable descriptions of a tag tree. However, the `tag` handler only checks `attrs.id`, element name, and element-specific fields (`href`, `alt`, `type`). It never reads `attrs.attributes["aria-label"]`, `attrs.attributes["aria-labelledby"]`, or `attrs.attributes["role"]`.

This means that:
1. A `Button("").setAria({ label: "Close modal" })` is described as `"button"` — missing the programmatic label entirely.
2. An `Img().setSrc("chart.png").setAria({ label: "Monthly revenue chart" })` is described as `"image (no alt)"` — wrong on both fronts (has a label, wrongly says no alt).
3. `Div().addAttribute("role", "dialog").setAria({ label: "Confirm action" })` is described as `"div"` — the role and label are both ignored.

## Evidence

The current implementation (`aria-describe.ts:22-46`):
```typescript
export const ariaDescribeAlgebra: ParaAlgebra<string> = {
  tag: (element: string, attrs: TagAttrs, children: string, _original: View) => {
    const label = attrs.id ? `${element}#${attrs.id}` : element;
    // No check for attrs.attributes?.["aria-label"] ← missing

    if (element === "a" && attrs.href) { ... }

    if (element === "img") {
      const alt = attrs.alt ?? attrs.attributes?.alt;  // checks "alt" but not "aria-label"
      return alt ? `image '${alt}'` : "image (no alt)";
      //                               ↑ wrong when aria-label is set via setAria
    }
    ...
  },
};
```

The test at `recursion-schemes.ts:116-118`:
```typescript
it("describes image with alt", () => {
  const desc = paraView(ariaDescribeAlgebra, Img().addAttribute("alt", "Logo"));
  assert.equal(desc, "image 'Logo'");
});
// No test for: Img().setAria({ label: "Logo" }) → currently "image (no alt)" ← bug
```

## Why it matters

- `ariaDescribeAlgebra` is exported as a public API and documented as "useful for accessibility auditing." If it misreports aria-labeled elements as unlabeled, it misleads auditors.
- The most common accessibility pattern for icon-only buttons is `.setAria({ label: "..." })` with no visible text child — these render as the useless description `"button"` with the algebra.
- The fix is small and additive: check `aria-label` in the general `tag` handler before falling back to the element name.
- `role` from `attrs.attributes?.["role"]` should also be used to produce richer descriptions (e.g., `"dialog 'Confirm action'"` instead of `"div#modal"`).

## Rough idea

Update `aria-describe.ts` tag handler:

```typescript
tag: (element: string, attrs: TagAttrs, children: string, _original: View) => {
  const ariaLabel = attrs.attributes?.["aria-label"];
  const role = attrs.attributes?.["role"];
  const semanticEl = role ?? element;
  const nameId = attrs.id ? `${semanticEl}#${attrs.id}` : semanticEl;
  const label = ariaLabel ? nameId + ` '${ariaLabel}'` : nameId;
  ...
}
```

Also add a test case for `Button().setAria({ label: "Close" })` → `"button 'Close'"`.
