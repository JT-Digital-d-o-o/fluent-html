# `TailwindBreakpoint` missing container-query variants for Tailwind v4

## Problem

Tailwind v4 ships container queries as a first-class feature without any plugin. Container-query responsive variants use an `@` prefix (`@sm:`, `@md:`, `@max-lg:`) and require a parent element to have the `@container` marker class.

fluent-html's `TailwindBreakpoint` type — the type parameter for `.at()` — only covers standard viewport breakpoints:

```ts
// fluent-html/src/core/tailwind-types.ts:191
export type TailwindBreakpoint = "sm" | "md" | "lg" | "xl" | "2xl";
```

There is no `@sm`, `@md`, `@lg`, `@xl`, `@2xl`, `@max-sm`, `@[480px]`, or `@container` listed. `.at("@sm", t => t.flexDirection("col"))` is therefore a type error on the current API, even though the resulting class `@sm:flex-col` is valid Tailwind v4 syntax.

The `.at()` method is a thin wrapper around `withVariant`:

```ts
// fluent-html/src/core/tailwind-methods.ts:326 (approx)
Tag.prototype.at = function(bp, fn) { return withVariant(this, bp, fn); };
```

The class generation itself would work (it just prepends `@sm:` as a prefix), so the block is purely the type constraint on `TailwindBreakpoint`.

There is also no `containerQuery()` method (or `container()`) to emit the `@container` marker class that enables container-query scoping on a parent element — users must use `addClass("@container")`.

## Evidence

- `fluent-html/src/core/tailwind-types.ts:191` — `TailwindBreakpoint` is `"sm" | "md" | "lg" | "xl" | "2xl"` only
- `fluent-html/src/core/tailwind-methods.ts:326` — `.at()` is mechanically fine; the gap is purely the type

The recon doc (§2.3 and §5 open question 6) lists container queries among v4 new features that "warrant first-class fluent methods in v6." This finding confirms the concrete type-table work required.

## Why it matters

Container queries are the most-anticipated responsive design feature in Tailwind v4 — they replace media-query-only responsive patterns for reusable component cards, sidebars, and widget grids. Any app on v4 that tries to use `.at("@sm", ...)` gets a TS error and must fall back to `addClass("@sm:flex-col")`. Because the extractor's `extractVariantClasses` (index.ts L637) handles all `.at()` calls including new breakpoint values, the extractor would work correctly — the only fix needed is the type table.

## Rough idea (not a design)

Extend `TailwindBreakpoint` with container-query variants, or introduce a separate `TailwindContainerBreakpoint` union used in an overloaded `.at()` signature:

```ts
// Option A — extend existing union
export type TailwindBreakpoint =
  | "sm" | "md" | "lg" | "xl" | "2xl"           // viewport breakpoints
  | "@sm" | "@md" | "@lg" | "@xl" | "@2xl"       // container-query min
  | "@max-sm" | "@max-md" | "@max-lg" | "@max-xl" // container-query max
  | `@[${string}]`;                               // arbitrary container size

// Option B — separate type, overloaded .at()
export type TailwindContainerBreakpoint = "@sm" | "@md" | ... | `@[${string}]`;
```

Also add a `.containerQuery(name?)` method emitting `@container` / `@container/${name}` on the parent element.
