# .gradientTo() emits dead `bg-gradient-*` classes on Tailwind v4

## Problem

In Tailwind v4 the linear-gradient utility was renamed from `bg-gradient-to-*` to `bg-linear-to-*`. fluent-html's `.gradientTo()` method still hard-codes `bg-gradient-${direction}` in three independent places, so on v4 the method produces class names that Oxide does not recognise — no CSS is generated and the gradient simply disappears silently.

```ts
// fluent-html/src/core/tailwind-methods.ts:576
p.gradientTo = function (direction: string) { return this.addClass(`bg-gradient-${direction}`); };
```

```ts
// fluent-html-tailwind-extractor/src/index.ts:390-391
methodName: "gradientTo",
generateClass: (args) => args.length === 1 ? [`bg-gradient-${args[0]}`] : [],
```

```ts
// fluent-html-eslint-plugin/src/rules/no-known-modifiers-in-setclass.ts:384
{ pattern: "bg-gradient-", methodName: "gradientTo" },
```

```ts
// fluent-html/src/core/tailwind-types.ts:197-199
export type TailwindGradientDirection =
  | "to-t" | "to-tr" | "to-r" | "to-br" | "to-b" | "to-bl" | "to-l" | "to-tl"
  | (string & {});
```

## Evidence

All three packages encode `bg-gradient-` independently. On v4 this emits a dead class: Tailwind's JIT scanner sees the string but the utility no longer exists under that name, so it produces no CSS. The failure is completely silent — no type error, no build error, no runtime error; the element just renders without a gradient.

The ESLint auto-fix map at L384 will also *suggest* the wrong fluent call path to any user who writes `bg-linear-to-r` in `setClass` directly, because the map only knows the v3 form — making the ESLint plugin actively harmful on v4.

## Why it matters

Gradients are used in landing pages, hero sections, and decorative cards. Three packages must be updated consistently. The divergence between the three independent copies means a partial fix (updating methods but not the extractor) is a latent bug that survives code review.

## Rough idea (not a design)

In `tailwind-methods.ts` change line 576 to emit `bg-linear-${direction}`. Mirror the same change in the extractor's `METHOD_PATTERNS` (L391) and the ESLint auto-fix map (L384). Extend `TailwindGradientDirection` with numeric angle values (`"45"`, `"135"`, …) that v4 now supports. If the v3/v4 dual-target decision (open question 1 in 03-tailwind4.md) is resolved in favour of a target flag, gate this rename behind it.
