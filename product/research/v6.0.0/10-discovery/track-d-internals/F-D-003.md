# renderAlgebra is a second, incomplete HTML renderer — only 3 of 20+ HTMX attrs, no script/style sanitization, exported as public API

## Problem

`src/fold/algebras/render.ts` exports `renderAlgebra`, a `ViewAlgebra<string>` that produces HTML. It is a complete parallel implementation of the renderer — but an incomplete and insecure one.

**Missing HTMX attrs.** The canonical `render()` handles 20+ HTMX attrs via the `HTMX_ATTRS` table (render.ts:105-126). `renderAlgebra.buildAttributes` handles only 3 (`target`, `swap`, `trigger`) with a comment acknowledging the gap:

```ts
// src/fold/algebras/render.ts:34-40
if (attrs.htmx) {
  const htmx = attrs.htmx;
  parts.push(`hx-${htmx.method}="${escapeAttr(htmx.endpoint)}"`);
  if (htmx.target) parts.push(`hx-target="${escapeAttr(htmx.target)}"`);
  if (htmx.swap)   parts.push(`hx-swap="${escapeAttr(htmx.swap)}"`);
  if (htmx.trigger) parts.push(`hx-trigger="${escapeAttr(htmx.trigger)}"`);
  // Add other HTMX attributes as needed...
}
```

The remaining 17 HTMX attrs (`pushUrl`, `replaceUrl`, `vals`, `headers`, `confirm`, `indicator`, `swapOob`, `status`, `preload`, `optimistic`, etc.) are silently dropped.

**No script/style sanitization.** The `tag` case passes `childHtml` directly with no check for `element === 'script' | 'style'` and no `sanitizeRawContent` call:

```ts
// src/fold/algebras/render.ts:66-71
tag: (element, attrs, childHtml) => {
  const attrString = buildAttributes(attrs);
  // Note: For raw text elements (script, style), children should not be escaped
  // This simplified version doesn't handle that - use render() for production
  return `<${element}${attrString}>${childHtml}</${element}>`;
},
```

The comment explicitly warns against production use (line 69). Despite this, `renderAlgebra` is exported from `src/fold/algebras/index.ts` and appears in the public API surface, and is used in the test suite (`test/fold.ts:8`, `test/recursion-schemes.ts:9`). The test `foldView(renderAlgebra, Span("<script>"))` passes because the *text* is escaped, but `foldView(renderAlgebra, Script("alert(1)"))` would not apply `</script>` injection protection.

**`buildAttributes` doubles-escapes element-specific attrs.** Lines 23-30 iterate `Object.entries(attrs)` a second time for element-specific keys, after already handling `id`/`class`/`style`/`attributes` — so `href`, `src`, etc. are emitted twice in the output.

## Why it matters

The fold-based `renderAlgebra` diverges silently from `render()`. Any app using `foldView(renderAlgebra, view)` as a "render alternative" will produce broken HTMX output and potential XSS via unescaped `</script>` content. The public export signals "this is supported."

## Rough idea (not a design)

Delete `renderAlgebra` from the public export and add a deprecation notice, or reimplement it as a pass-through to `render()` using the shared emitter from F-D-001's de-recursion refactor. A redirect like `export const renderAlgebra: ViewAlgebra<string> = { ..., tag: (el, _, child) => ... }` that calls into the canonical path removes the drift risk permanently.
