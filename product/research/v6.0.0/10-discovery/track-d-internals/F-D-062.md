# createContext and createRequiredContext duplicate the scope() Disposable body verbatim

## Problem

`createContext` (line 77) and `createRequiredContext` (line 121) each contain an identical `scope()` implementation:

```ts
// src/control/context.ts:77-84 (createContext)
scope(value: T): Disposable {
  stack.push(value);
  return {
    [Symbol.dispose]() {
      stack.pop();
    },
  };
}

// src/control/context.ts:121-128 (createRequiredContext)
scope(value: T): Disposable {
  stack.push(value);
  return {
    [Symbol.dispose]() {
      stack.pop();
    },
  };
}
```

The two functions differ only in how `current` is implemented (default fallback vs throw). The `scope()` body is byte-for-byte identical.

## Evidence

`context.ts` is 131 lines; 16 of them (the two `scope` blocks) are duplicated. Any change to `scope()` — a future singleton optimization (see F-D-061), a change to the dispose symbol, or an added push/pop escape hatch — must be applied twice and tested twice, with no compiler guard against drift.

## Why it matters

Small module but a growth surface: as the context API gains more escape hatches or strategies, the duplication will compound. The fix is mechanical and can be combined with any scope() optimization work from F-D-061.

## Rough idea (not a design)

Extract `function makeScope<T>(stack: T[]): (value: T) => Disposable` as a module-private helper. Both `createContext` and `createRequiredContext` set `scope: makeScope(stack)`. Single source of truth, single test target.
