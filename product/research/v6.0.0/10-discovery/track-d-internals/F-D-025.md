# `setStyles`, `setDataAttrs`, and `setAria` each allocate a per-key regex closure at construction time

## Problem

Three convenience methods on `Tag` — `setStyles`, `setDataAttrs`, and `setAria` — all perform camelCase-to-kebab-case conversion using an inline regex with a closure callback. The regex `/[A-Z]/g` is a regex literal but the replace callback `letter => \`-${letter.toLowerCase()}\`` is a **new arrow-function closure created per call to each method**, plus the regex itself is re-evaluated per replace call. Additionally:

- `setStyles` calls `Object.entries(styles).map(...).join("; ")` — a full functional pipeline that allocates an intermediate string array.
- `setDataAttrs` and `setAria` use `for...of Object.entries(attrs)` which creates an entries iterator and 2-element tuple arrays per key.

```ts
// src/core/tag.ts:249-259 — setStyles
setStyles(styles: Record<string, string | number>): this {
  const styleString = Object.entries(styles)
    .map(([key, value]) => {
      const kebabKey = key.replace(/[A-Z]/g, letter => `-${letter.toLowerCase()}`);
      return `${kebabKey}: ${value}`;
    })
    .join("; ");
  this.style = styleString;
  return this;
}

// src/core/tag.ts:275-283 — setDataAttrs
setDataAttrs(attrs: Record<string, string>): this {
  if (this.attributes === EMPTY_ATTRS) this.attributes = Object.create(null) as Record<string, string>;
  for (const [key, value] of Object.entries(attrs)) {
    const kebabKey = key.replace(/[A-Z]/g, letter => `-${letter.toLowerCase()}`);
    this.attributes[`data-${kebabKey}`] = value;
  }
  return this;
}

// src/core/tag.ts:298-305 — setAria
setAria(attrs: Record<string, string | boolean>): this {
  if (this.attributes === EMPTY_ATTRS) this.attributes = Object.create(null) as Record<string, string>;
  for (const [key, value] of Object.entries(attrs)) {
    const kebabKey = key.replace(/[A-Z]/g, letter => `-${letter.toLowerCase()}`);
    this.attributes[`aria-${kebabKey}`] = String(value);
  }
  return this;
}
```

In all three cases the same pattern repeats: regex replacement with a function literal that creates a new closure each time the regex matches a capital letter.

## Evidence

These methods sit in the construction hot path. In an SSR pattern every request rebuilds the tree, so any component that calls `setAria({ label: "...", expanded: "false" })` or `setStyles({ backgroundColor: "blue" })` pays closure allocation on every request per attribute key. With typical ARIA patterns using 2–5 attributes per interactive element, and `setStyles` potentially called with 3–5 CSS properties for custom layouts, this allocates several closures per element per request in aria-heavy or custom-styled pages.

The fix is simple: hoist the replace callback as a named module-level constant so it is allocated once:

```ts
const toKebab = (letter: string) => `-${letter.toLowerCase()}`;
```

Then `key.replace(/[A-Z]/g, toKebab)` reuses the same function reference on every call. The regex literal `/[A-Z]/g` is also re-used as a constant (JS engines cache regex literals at compile time, but the `g` flag carries `lastIndex` state — using `lastIndex = 0` or a fresh regex per call is needed for safety; a module-level const with `.exec` or a split-join approach avoids the issue entirely).

`setStyles`'s use of `.map(...).join()` can be replaced with a direct `+=` loop to avoid the intermediate array:

```ts
let styleString = '';
for (const [key, value] of Object.entries(styles)) {
  if (styleString) styleString += '; ';
  styleString += key.replace(/[A-Z]/g, toKebab) + ': ' + value;
}
this.style = styleString;
```

## Why it matters

Each of these methods is a construction-time cost, paid on every SSR request. While individual closure allocations are small, they add to the aggregate ~14.5 KB/1000-node construction baseline that the recon identifies as a first-class concern. Aria attributes are particularly relevant for accessible SSR apps where interactive elements routinely carry 3–6 `aria-*` attributes. The fix is a one-line hoist — zero API impact, zero behavior change.

## Rough idea (not a design)

Hoist `const toKebab = (letter: string) => \`-${letter.toLowerCase()}\`` to module scope in `tag.ts`. Replace all three inline arrow functions with the shared reference. Replace `setStyles`'s `.map().join()` with a `+=` accumulation loop. Run `bench:mem` to confirm reduction in per-construction heap delta.
