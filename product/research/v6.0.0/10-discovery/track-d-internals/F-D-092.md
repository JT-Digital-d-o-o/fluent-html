# `renderImpl`/`streamImpl` use a tri-typed `boolean | string` flag for raw-context dispatch

## Problem

Both `renderImpl` (render.ts:184) and `streamImpl` (stream.ts:120) take an `isRawContext: boolean | string` parameter that encodes three distinct meanings:

| Value | Meaning |
|-------|---------|
| `false` | Normal mode — escape all text and attribute values |
| `true` | Raw passthrough — emit string content unescaped (used for `Raw()` children) |
| `'script'` | Script sanitization mode — sanitize `</script>` but do not HTML-escape |
| `'style'` | Style sanitization mode — sanitize `</style>` but do not HTML-escape |

This is three semantically distinct dispatch modes collapsed into one `boolean | string` flag. The dispatch logic requires two type guards per branch:

```ts
// src/render/render.ts:184-192
function renderImpl(view: View, isRawContext: boolean | string): string {
  if (typeof view === "string") {
    if (isRawContext === false) return escapeHtml(view);             // normal
    if (typeof isRawContext === 'string') return sanitizeRawContent(view, isRawContext); // script/style
    return view;                                                     // raw passthrough (true)
  }

  if (isRawString(view)) {
    if (typeof isRawContext === 'string') return sanitizeRawContent(view.html, isRawContext);
    return view.html;
  }
```

The same pattern is copied verbatim in `streamImpl`:

```ts
// src/render/stream.ts:120-129
function streamImpl(stream: Readable, view: View, isRawContext: boolean | string): void {
  if (typeof view === "string") {
    if (isRawContext === false) { stream.push(escapeHtml(view)); return; }
    if (typeof isRawContext === 'string') { stream.push(sanitizeRawContent(view, isRawContext)); return; }
    stream.push(view);
    return;
  }

  if (isRawString(view)) {
    if (typeof isRawContext === 'string') { stream.push(sanitizeRawContent(view.html, isRawContext)); return; }
    stream.push(view.html);
    return;
  }
```

The boolean `true` case (raw passthrough) is a silent fallthrough — there is no explicit `isRawContext === true` branch, making the semantics of each case non-obvious without careful reading. A future maintainer adding a new context (e.g. `'noscript'`, or a `'template'` element) must understand the implicit encoding and manually place new branches in the right order.

## Why it matters

This pattern appears in both `renderImpl` and `streamImpl` (2 call sites, ~12 branches total). When render.ts and stream.ts are eventually unified via a shared emitter (see F-D-012), the unified emitter will need a clean, typed context parameter — the current overloaded flag will complicate that refactor. It also makes the code harder to read during security audits: the escaping behavior at any call site requires tracing the `isRawContext` value through multiple levels.

The recon document (04-performance.md §4) explicitly calls this out as a quality issue: "tri-typed `boolean|string` rawCtx flag — works but is a clever-but-fragile encoding."

## Rough idea (not a design)

Define:

```ts
type RenderCtx = 'escape' | 'raw' | 'script' | 'style';
```

Replace all `false` with `'escape'`, `true` with `'raw'`, and `'script'`/`'style'` with themselves. Every branch becomes an explicit equality check with no type guards:

```ts
if (ctx === 'escape') return escapeHtml(view);
if (ctx === 'raw') return view;
return sanitizeRawContent(view, ctx); // only 'script' | 'style' remain
```

The change is purely internal to `renderImpl`/`streamImpl` — no public API surface is affected. The `render()` entry-point starts the recursion with `'escape'`.
