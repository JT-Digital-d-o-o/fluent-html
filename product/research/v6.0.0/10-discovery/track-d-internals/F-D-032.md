# `renderAlgebra` serializes only 3 of 20+ HTMX attrs — exported public API silently drops swap-oob, push-url, vals, headers, status, etc.

## Problem

`renderAlgebra`'s `buildAttributes` function handles HTMX by hard-coding only 3 attributes — `hx-method`, `hx-target`, `hx-swap`, `hx-trigger` — and leaves a `// Add other HTMX attributes as needed...` comment for the remaining 17+:

```ts
// src/fold/algebras/render.ts:34-41
if (attrs.htmx) {
  const htmx = attrs.htmx;
  parts.push(`hx-${htmx.method}="${escapeAttr(htmx.endpoint)}"`);
  if (htmx.target) parts.push(`hx-target="${escapeAttr(htmx.target)}"`);
  if (htmx.swap) parts.push(`hx-swap="${escapeAttr(htmx.swap)}"`);
  if (htmx.trigger) parts.push(`hx-trigger="${escapeAttr(htmx.trigger)}"`);
  // Add other HTMX attributes as needed...
}
```

`render.ts` handles 20 HTMX attributes through a data-driven `HTMX_ATTRS` table (lines 105-126) plus special-cases for `optimistic`, `preload`, and `status` (lines 139-153). Attributes silently omitted by `renderAlgebra`:

- `hx-push-url`, `hx-replace-url` (navigation — dropped entirely)
- `hx-swap-oob` (out-of-band swap — dropped entirely)
- `hx-vals`, `hx-headers`, `hx-include`, `hx-encoding`
- `hx-confirm`, `hx-indicator`, `hx-disable`, `hx-sync`
- `hx-validate`, `hx-preserve`, `hx-boost`, `hx-ignore`
- `hx-config`, `hx-optimistic`, `hx-preload`, `hx-status:*`

## Evidence

`src/fold/algebras/render.ts:34-41` — the 3-attr stub with a TODO comment.

`src/render/render.ts:105-155` — the authoritative 20-attr implementation using `HTMX_ATTRS: AttrConfig[]` plus `buildHtmx`.

Both `buildHtmx` functions are duplicated in `render.ts` and `stream.ts` already. `renderAlgebra` adds a third, far more limited copy.

A consumer using `hyloView(myCoalgebra, renderAlgebra, data)` to generate HTML with navigation links (`hx-push-url`, `hx-replace-url`) or multi-section updates (`hx-swap-oob`) silently produces functionally broken HTML — no error, no warning, just missing HTMX attributes that the app relies on.

```ts
// What renderAlgebra produces today for a nav link:
// <a hx-get="/page">Go</a>
// (hx-push-url and hx-target silently dropped)

// What render() produces:
// <a hx-get="/page" hx-push-url="true" hx-target="#main">Go</a>
```

## Why it matters

`renderAlgebra` is exported public API (`src/index.ts`). The recon file (`04-performance.md:§4`) notes it as a "second, lossy renderer" and recommends deletion or implementation via the shared emitter — this finding provides concrete evidence of *how lossy* it is. With the `hyloView` pattern (coalgebra drives data expansion, `renderAlgebra` renders), the HTMX omissions make the fold-based render path unusable for any real-world HTMX app.

## Rough idea (not a design)

Extract `HTMX_ATTRS: AttrConfig[]`, `buildHtmx`, and `buildStatusConfig` from `render.ts` into `src/render/htmx-serializer.ts`. Import and reuse in `stream.ts` (eliminating that duplication) and `algebras/render.ts` (replacing the 3-attr stub). This gives all three renderers a single authoritative HTMX serialization path.
