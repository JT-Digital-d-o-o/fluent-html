# Overlay() wraps children in an array literal — violates the library's own variadic-children contract

## Problem

The library's canonical contract (enforced in CLAUDE.md and README) is:

```ts
Div(H1("Title"), P("Body"))   // ✓ variadic
Div([H1("Title"), P("Body")]) // ✗ never wrap in arrays
```

`Overlay` in the library's own source does the forbidden form:

```ts
// src/control/overlay.ts:23-29
return Div([
  content,
  Div(overlay)
    .setStyle(`position: absolute; ${positionStyles[position]} z-index: 10`),
])
  .setStyle("position: relative");
```

## Evidence

The `Tag` constructor at `src/core/tag.ts:59-61` correctly handles variadic children:

```ts
constructor(element: string, ...children: View[]) {
  this.el = element;
  this.child = children.length === 0 ? "" : children.length === 1 ? children[0]! : children;
}
```

Passing an array literal as the sole child stores a `View[][]` (an array-of-array) as `tag.child`. The renderer handles this at `render.ts:243-253` because it tests `Array.isArray` recursively — so the output is correct — but the construction is semantically wrong and sets a bad example in library code that beginners read.

## Why it matters

`Overlay` is library-shipped code visible in `src/control/overlay.ts` and exported from `src/index.ts:250`. App developers learning the API often read library sources as reference. An anti-pattern in library internals undermines the guideline. Additionally, wrapping in `[content, overlay]` forces an extra array allocation at construction time — avoidable with variadic args.

## Rough idea (not a design)

`return Div(content, Div(overlay).setStyle(...)).setStyle("position: relative")` — two-argument variadic, no array wrapper. Zero behavior change.
