# renderAlgebra silently omits 16+ HTMX attrs and skips script/style sanitization — parity tests miss this

## Problem

`renderAlgebra` (`src/fold/algebras/render.ts`) is a public, exported HTML renderer built on the fold layer. It serializes only 4 HTMX attributes (`method/endpoint`, `target`, `swap`, `trigger`) while the main `render()` function handles 20+. It also skips `script`/`style` sanitization entirely. The parity tests in `test/fold.ts` (lines 246–265) compare only simple, non-HTMX, non-script views — they would not catch any of these gaps.

## Evidence

```ts
// src/fold/algebras/render.ts:34-40 — only 4 HTMX attrs
if (attrs.htmx) {
  const htmx = attrs.htmx;
  parts.push(`hx-${htmx.method}="${escapeAttr(htmx.endpoint)}"`);
  if (htmx.target) parts.push(`hx-target="${escapeAttr(htmx.target)}"`);
  if (htmx.swap) parts.push(`hx-swap="${escapeAttr(htmx.swap)}"`);
  if (htmx.trigger) parts.push(`hx-trigger="${escapeAttr(htmx.trigger)}"`);
  // Add other HTMX attributes as needed...
}
```

The main renderer (`src/render/render.ts:105-126`) handles 20+ HTMX attrs via a data-driven table:

```ts
// src/render/render.ts:105-126
const HTMX_ATTRS: AttrConfig[] = [
  str('target'), str('swap'), boolOrStr('swapOob', 'swap-oob'), str('select'),
  str('trigger'), boolOrStr('pushUrl', 'push-url'), boolOrStr('replaceUrl', 'replace-url'),
  jsonOrStr('vals'), json('headers'), str('include'), str('encoding'),
  boolVal('validate'), str('confirm'), str('indicator'), str('disable'),
  str('sync'), boolVal('preserve'), boolVal('boost'), boolVal('ignore'),
  jsonOrStr('config'),
  // + htmx.optimistic, htmx.preload, htmx.status (special-cased)
];
```

The comment in `renderAlgebra` itself admits it:
```ts
// src/fold/algebras/render.ts:58,68
// Note: For raw text elements (script, style), children should not be escaped
// This simplified version doesn't handle that - use render() for production
```

The parity tests that do exist compare only simple views without HTMX or script/style:
```ts
// test/fold.ts:246-265
const views = [
  Div("Hello World"), Div(P("Paragraph"), Span("Inline")),
  H1("Title"), Div(Ul(Li("A"), Li("B"), Li("C"))),
  Div().setId("test").setClass("cls"),
  A("Link").setHref("/path"),
  Div(Raw("<b>raw</b>")),
  // No HTMX tag, no Script(), no Style() — parity gaps are invisible
];
```

## Why it matters

1. **Security** (`guardrail §11.3`): `renderAlgebra` is exported public API. A caller who uses it instead of `render()` for script/style content gets unsanitized output. The self-comment says "use render() for production" but there is no deprecation marker or runtime warning.
2. **HTMX correctness**: any caller (or tool) using `renderAlgebra` on a real app page loses 16 HTMX attributes silently — `pushUrl`, `vals`, `headers`, `confirm`, `boost`, `swapOob`, etc. — with no error.
3. **Fold-layer drift risk**: as `render()` grows (e.g. new HTMX attrs, new behaviors), `renderAlgebra` silently falls further behind. The parity tests don't catch this.

## Rough idea (not a design)

Option A (preferred): implement `renderAlgebra` via the shared Sink/emitter extracted for the render/stream dedup RFC — so parity is structurally guaranteed, not tested after the fact.

Option B: mark `renderAlgebra` `@deprecated` and add a test that drives `foldView(renderAlgebra, ...)` over HTMX-carrying and Script/Style tags and asserts equality with `render()`. The test would fail today on HTMX attributes and script sanitization, exposing the true scope of the gap before deciding to fix or remove.
