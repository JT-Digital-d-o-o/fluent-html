# setHref used for in-app navigation despite explicit guideline prohibition — guideline teaches the rule but apps still violate it

## Problem

`htmx.md` explicitly states: _"**Never use `setHref` for in-app navigation** — it causes a full page reload, bypassing HTMX."_ The guideline exists and is correct. Yet jt-cut has **17 internal-navigation `setHref` call sites** and mngmt has at least 4. This is not ignorance of the rule — apps clearly know `setHtmx` exists (jt-cut has 150 `setHtmx`/`hxGet`/`hxPost` calls). The pattern persists because the guideline is text-only with no enforcement.

The violations fall into two sub-patterns:
1. **Full-page navigation links** that should be `setHtmx(route({ swap: "outerMorph ...", target: ids.mainContent, pushUrl: true }))` — jt-cut's project list card, auth links
2. **Filter/sort anchors** where the query string changes — mngmt's changelog sort/filter chips use `.setHref(chipUrl(category))` building a string URL rather than using `.setHtmx(route({ query: { ... } }))`

## Evidence

**jt-cut — HTMX-capable SaaS pages using setHref for internal navigation:**

```ts
// jt-cut/src/projects/views/projects.list.view.ts:295 — project detail card
.setHref(projectRoutes.detail.resolve({ id: project.id }))
.cursor("pointer")

// jt-cut/src/home/views/home.hero.view.ts:646 — login link (internal page)
.setHref(authRoutes.login.resolve({ locale }))

// jt-cut/src/home/views/home.pricing.view.ts:98 (and 3 more in same file)
.setHref(authRoutes.login.resolve({ locale }))

// jt-cut/src/auth/auth.view.ts:227 — OAuth navigation
.setHref(authRoutes.oauthStart.resolve({ locale, provider: "google" }))

// jt-cut/src/projects/media/media.view.ts:87 — media detail
.setHref(mediaRoutes.viewMedia.resolve({ id: project.id, mediaId: m.id }))
```

**mngmt — sort/filter chips use setHref with hand-built URLs:**

```ts
// mngmt/src/changelog/changelog.view.ts:250
A("Newest").setHref(sortUrl("newest"))
A("Oldest").setHref(sortUrl("oldest"))

// mngmt/src/changelog/changelog.view.ts:236
return A(FILTER_LABELS[category])
  .setHref(chipUrl(category))  // chipUrl builds URL string manually
```

**The guideline (htmx.md:161) correctly prohibits this but provides no enforcement:**

```ts
// ✓ HTMX swap
A("Users").setHtmx(userRoutes.list({ target: ids.mainContent }))
// ✗ full page reload — GUIDELINE SAYS NEVER
A("Users").setHref(userRoutes.list.resolve())
```

## Why it matters

Every `setHref` for internal navigation causes a **full browser page reload**: the HTMX state machine resets, the loading indicator doesn't fire, scroll position is lost, and the URL push happens via the browser rather than HTMX's history management. In jt-cut's project list (line 295), clicking any project card causes a full reload instead of a morph swap — visually jarring and slower than an HTMX swap.

The guideline is correct but text-only rules don't prevent copy-paste. jt-cut has 150 HTMX calls and 17 setHref violations — this isn't ignorance, it's tooling gap: there's no automated check.

Frequency: 2 apps confirmed (jt-cut 17, mngmt 4+); likely more in unreached apps. Pain: medium (UX regression — full reload instead of HTMX swap on internal links).

## Rough idea (not a design)

Two complementary fixes:
1. **Guideline patch** (immediate): add a clearer callout in `CLAUDE.md` under the HTMX section — _"setHref is for external links and downloads only. Every internal link that navigates to a page within the app must use setHtmx."_
2. **ESLint rule** (enforcement): in `fluent-html-eslint-plugin`, flag `tag.setHref(anyRouteResolve)` when the resolved URL pattern matches a known `defineRoutes` route (detectable from import shape). Auto-fix suggestion: convert to `.setHtmx(route({ target: ids.mainContent, swap: "outerMorph scroll:top", pushUrl: true }))`.
