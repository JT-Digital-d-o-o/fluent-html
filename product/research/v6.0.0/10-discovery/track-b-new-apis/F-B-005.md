# `.on()` does not cover `placeholder:` pseudo-element — forces `addClass` in every styled input definition

## Problem

The `placeholder:` Tailwind variant styles the `::placeholder` pseudo-element of an input. It is routinely needed in styled input definitions to set the placeholder text color. The `.on()` method covers pseudo-classes (`hover`, `focus`, `disabled`, `checked`, etc.) and breakpoints live in `.at()`, but `placeholder` (a pseudo-element, not a pseudo-class) is not supported by `.on()`. Every styled input in every app falls back to `addClass("placeholder:text-slate-400")` as the only way to express this.

## Evidence

**storysell-ai** brand input — `placeholder:` via `addClass`:

```ts
// storysell-ai/src/shared/components/brand/ui.brand.forms.ts:26
export const brandInputStyle = (t: InputTag) => t
  .w("full").padding("x","4").padding("y","2.5").textSize("sm")
  .background("slate-50").border().borderColor("slate-200").rounded("xl")
  .transition("all")
  .addClass("placeholder:text-slate-400")  // ← no fluent alternative
  .on("focus", f => f.outline("none").addClass("ring-2 ring-brand-500/30").borderColor("brand-500"));
```

Note the mixed: `.on("focus", ...)` is used for focus (covered by `.on()`), but `placeholder:` must fall back to `addClass`.

**storysell-ai** product list — inline input styling where the entire class string is a raw `addClass` because `placeholder:` is needed alongside other pseudo-classes:

```ts
// storysell-ai/src/product/views/product.list.view.ts:157
.w("full").padding("x","4").padding("y","2.5").textSize("sm").background("white/70")
  .border().borderColor("200").rounded("xl").transition("all")
  .addClass("placeholder:text-slate-400 focus:outline-none focus:ring-2 focus:ring-brand-500/30 focus:border-brand-500"),
```

Here the developer gave up on fluent methods for `focus:` as well — precisely because `placeholder:` already forces `addClass`, it is convenient to dump all pseudo-class styles into the same string.

**planet-positive-sport** form — similar pattern where `[&>input]:` arbitrary child selectors accompany `placeholder:` in the same `addClass` call, all because neither is supported by `.on()`.

## Why it matters

The guideline at `web-development/fluent-html.md` says to use `.on()` for pseudo-classes and never `addClass` with raw Tailwind strings. But `placeholder:` (and by extension `placeholder-shown:`, `file:`, `marker:`, `selection:`) are Tailwind pseudo-element variants that `.on()` does not accept. This is a documented gap: once a dev needs `placeholder:` they must use `addClass`, and once they are in `addClass` they often bundle adjacent pseudo-class styles there too (as seen in the product list view above), quietly eroding the fluent API in that component.

`addClass` counts across the fleet (storysell: 327, pps: 176) have `placeholder:` as a frequent driver. Closing this gap would let the guideline be respected without sacrificing placeholder styling.

## Rough idea (not a design)

Extend `.on()` to accept a set of pseudo-element targets: `'placeholder'`, `'file'`, `'marker'`, `'selection'`, `'first-line'`, `'first-letter'`, `'before'`, `'after'`. These map to `placeholder:`, `file:`, etc. in Tailwind. The same modifier callback shape as existing pseudo-classes works. Alternatively, add a dedicated `.placeholder(t => ...)` method if the mixed pseudo-class/pseudo-element overload creates type complexity. Either approach closes the `addClass` escape for this category.
