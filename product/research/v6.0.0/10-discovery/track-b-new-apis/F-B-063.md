# Enum-to-color mapping split across parallel bg()/text() helpers breaks fluent type-safety and leaks raw Tailwind strings

## Problem

When a domain enum (PaymentStatus, ProjectStatus, Priority) must drive badge/pill coloring, apps have no fluent-native way to express "map this value to a color pair." They fall into one of two patterns, both anti-idiomatic:

**Pattern A — parallel helper functions** (jt-cut): two separate functions `statusBg(status)` and `statusTextColor(status)` each return a Tailwind color string. The StatusBadge passes these to `.background()` / `.textColor()`. Superficially fluent, but the two maps can diverge (one updated without the other) and there is no compile-time guarantee that `statusBg("PENDING")` and `statusTextColor("PENDING")` form a readable pair.

**Pattern B — raw class string records** (mngmt, parts of jt-cut): a `Record<Status, { bg: string; text: string }>` holding bare Tailwind class strings (e.g. `"bg-emerald-500/10"`, `"text-emerald-400"`) fed to `.setClasses([...])` or `.addClass(...)`. This is the worst outcome — it works today but is invisible to the Tailwind extractor (v4 purge will break it) and produces strings that won't be type-checked.

**Pattern C — inline `.when()` chains** (storysell-ai billing view): the mapping is expressed imperatively as a series of `.when(status === "active", …)` calls directly on the Span. Readable for 2–3 states, but degrades badly for 6-state enums like PaymentStatus.

## Evidence

Pattern A — jt-cut parallel helpers:
```ts
// jt-cut/src/payments/payments.utils.ts (approx lines 14-38)
export function statusBg(status: PaymentStatus) {
  const map = {
    PENDING: "yellow-100",
    COMPLETED: "green-100",
    FAILED: "red-100",
    REFUNDED: "blue-100",
    PARTIALLY_REFUNDED: "purple-100",
    CANCELLED: "gray-100",
  } as const satisfies Record<PaymentStatus, string>;
  return map[status];
}

export function statusTextColor(status: PaymentStatus) {
  const map = {
    PENDING: "yellow-800",
    COMPLETED: "green-800",
    …
  } as const satisfies Record<PaymentStatus, string>;
  return map[status];
}

// jt-cut/src/payments/payments.view.ts:52-61
function StatusBadge({ status }: StatusBadgeProps) {
  return Span(statusLabel(status))
    .background(statusBg(status))       // ← two separate lookups, can diverge
    .textColor(statusTextColor(status));
}
```

Pattern B — mngmt raw class strings:
```ts
// mngmt/src/dashboard/dashboard.components.ts:37-48
const STATUS_COLORS: Record<ProjectStatus, { bg: string; text: string }> = {
  "On track": { bg: "bg-emerald-500/10", text: "text-emerald-400" },  // raw class strings
  "At risk":  { bg: "bg-amber-500/10",   text: "text-amber-400"   },
  "Blocked":  { bg: "bg-red-500/10",     text: "text-red-400"     },
};
export function StatusBadge({ status }: { status: ProjectStatus }) {
  const colors = STATUS_COLORS[status] ?? STATUS_COLORS["On track"];
  return Span(status)
    .setClasses([colors.bg, colors.text])  // bypasses fluent type-safety entirely
    …
}
```

Pattern C — storysell-ai billing inline `.when()`:
```ts
// storysell-ai/src/payments/views/payments.billing.view.ts:55-63
Span(sub.status)
  .textSize("xs").fontWeight("medium").padding("x","2").padding("y","1").rounded("full").margin("l","2")
  .when(sub.status === "active", t => t.background("green-100").textColor("green-800"))
  .when(sub.status !== "active", t => t.background("yellow-100").textColor("yellow-800")),
```

## Why it matters

Pattern B (raw class strings) is the most dangerous: when Tailwind v4 renames `bg-emerald-500/10` syntax or purges unused classes, these strings are invisible to the extractor. It affects at least mngmt's StatusBadge and SeverityBadge. Pattern A (parallel functions) is safer for the extractor but the two maps can silently diverge. Pattern C scales poorly past 2 states. All three are symptomatic of the same gap: no first-class API for "map this typed value to a fluent color pair."

## Rough idea (not a design)

`Badge.of(value, colorMap)` where `colorMap` is typed as `Record<typeof value, { variant: BadgeVariant }>` (semantic) or `Record<typeof value, { bg: TailwindColor, text: TailwindColor }>` (direct fluent token pair, no raw strings). The fluent layer resolves colors from its type table, keeping the extractor happy. One map instead of two functions.
