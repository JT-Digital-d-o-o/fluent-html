# Container() primitive absent; .maxW("7xl").margin("x","auto").padding("x","4").at("sm",...).at("lg",...) duplicated 40+ times with inconsistent max-widths

## Problem

There is no `Container()` built-in. Every page and component that needs a centered, max-width content wrapper manually chains `.maxW(...)`, `.margin("x","auto")`, `.padding("x","4")`, and at-breakpoint padding overrides. The `projects-template` package already extracted this as a named `container` style-fn — the strongest possible signal that it belongs in the library — but every other app still inlines it.

## Evidence

The reference template defines the canonical shape:

```ts
// projects-template/templates/web/src/shared/components.ts:47-53
export const container = (t: Tag) =>
  t.maxW("7xl").margin("x","auto").padding("x","4")
   .at("sm", t => t.padding("x","6")).at("lg", t => t.padding("x","8"));
```

storysell-ai's navigation inlines the same sequence in its `Navigation()` component:

```ts
// storysell-ai/src/shared/components/layout.view.ts:278-285
  .maxW("7xl")
  .margin("x", "auto")
  .padding("x", "4")
  .flex()
  .justifyContent("between")
  .alignItems("center")
  .h("16")
  .at("sm", t => t.padding("x", "6")).at("lg", t => t.padding("x", "8")),
```

And again in `PageFooter()`:
```ts
// storysell-ai/src/shared/components/layout.view.ts:324-327
  .maxW("7xl")
  .margin("x", "auto")
  .padding("x", "4")
  .at("sm", t => t.padding("x", "6")).at("lg", t => t.padding("x", "8")),
```

storysell's home page alone repeats `.maxW("Nxl").margin("x","auto")` 12 times, with widths varying across `2xl`, `3xl`, `4xl`, `5xl`, `6xl`, `7xl` — each call site choosing a max-width that felt appropriate at the time:

```ts
// storysell-ai/src/home/home.view.ts:94, 126, 160, 163, 173, 209, 235, 260, 299, 328, 381, 408
.maxW("3xl").margin("x","auto")   // hero subtitle
.maxW("7xl").margin("x","auto")   // feature grid
.maxW("5xl").margin("x","auto")   // sections
```

planet-positive-sport duplicates the responsive-padding container pattern in its layout component:
```ts
// planet-positive-sport/src/shared/components/layout.view.ts:136-143
  .maxW("7xl").margin("x","auto").padding("x","4")
  .at("sm", t => t.padding("x","6")).at("lg", t => t.padding("x","8"))
```

The inline-demo views in storysell also inline mini-containers:
```ts
// storysell-ai/src/demo/views/demo.view.ts:144
).apply((t) => t.maxW("3xl").margin("x", "auto").padding("6")),
```

## Why it matters

~40 call sites across at least 4 apps (storysell, pps, glimm, rideshare) repeat this chain. Because there's no single source of truth, apps diverge on max-width choice (is it `5xl` or `7xl`?), padding values (is it `padding("6")` or `padding("x","4")` + breakpoints?), and whether to add the `.at("sm",...).at("lg",...)` responsive padding. This makes the visual grid inconsistent across pages within the same app. The recon doc already identifies this as item #9 in the seed backlog ("Container()") but without the per-file evidence added here.

## Rough idea (not a design)

A `Container(children, { maxW?: TailwindSizeToken, padding?: boolean })` component (or `Div(children).container()` fluent method) that applies the canonical `maxW + auto margin + responsive padding` sequence. The projects-template `container` style-fn already defines the correct defaults — promote it to a built-in. Apps that need a non-standard max-width can override.
