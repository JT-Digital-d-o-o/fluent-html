# No typed SVG container elements for gradients / clip-paths / filters

## Problem

fluent-html exports typed classes for SVG shapes (`Path`, `Circle`, `Rect`, `Line`, `Ellipse`, `Polygon`, `Polyline`, `Text`, `Use`, `G`, `Defs`) but has **no typed classes for SVG presentation elements**: `linearGradient`, `radialGradient`, `stop`, `clipPath`, `mask`, `filter`, and `feGaussianBlur`. These are required for SVG chart authoring (gradient fills under line charts, donut rings with opacity, progress arcs).

Without typed elements, every gradient must be built via `El()` which returns the generic base `Tag`, requiring `addAttribute` for all gradient-specific properties and triggering the `prefer-set-method` ESLint rule:

```ts
// jt-cut/src/analytics/views/analytics.chart.ts:75-97
function createLinearGradient(id: string, stops: GradientStop[], x1=0, y1=0, x2=0, y2=1) {
  return {
    addStop(offset: number, color: string, opacity?: number) { … },
    ref() { return `url(#${id})`; },
    build() {
      // eslint-disable-next-line fluent-html/prefer-set-method -- El() returns generic Tag without typed SVG setters
      return El("linearGradient",
        ForEach(stops, s => {
          const el = El("stop")
            .addAttribute("offset", `${s.offset * 100}%`)
            .addAttribute("stop-color", s.color);
          return s.opacity != null ? el.addAttribute("stop-opacity", String(s.opacity)) : el;
        }),
      )
        .setId(id)
        .addAttribute("x1", String(x1)).addAttribute("y1", String(y1))
        .addAttribute("x2", String(x2)).addAttribute("y2", String(y2));
    },
  };
}
```

A second `addAttribute` call appears at line 295 for `stroke-opacity` on a chart path:

```ts
// jt-cut/src/analytics/views/analytics.chart.ts:295
  .addAttribute("stroke-opacity", "0.5"),
```

(`stroke-opacity` is also absent from `SvgShapeTag`.)

## Evidence

- `jt-cut/src/analytics/views/analytics.chart.ts:75-97` — `createLinearGradient()` builder uses `El("linearGradient"…)` + `El("stop")` with 6 `addAttribute` calls; ESLint suppress comment explains the forced workaround.
- `jt-cut/src/analytics/views/analytics.chart.ts:295` — `addAttribute("stroke-opacity", "0.5")` because `SvgShapeTag` lacks `setStrokeOpacity`.
- `glimm/src/analytics/views/charts.components.ts` — independently implements SVG chart components (donut, bar); likely the same pattern (confirmed by recon `02-app-patterns.md:§4` which lists `LineChart`/`BarChart`/`DonutChart` as custom helpers in glimm).
- `fluent-html/src/elements/svg.ts` — exports `Circle`, `Rect`, `Line`, `Path`, `Ellipse`, `Polygon`, `Polyline`, `Text`, `Tspan`, `Use`, `G`, `Defs` but no `LinearGradient`, `Stop`, `ClipPath`, `Filter`, etc.

## Why it matters

SVG charts are a recurring need across at least 2 apps (`jt-cut` analytics, `glimm` analytics). They require `<defs>` + `<linearGradient>` + `<stop>` + `<clipPath>` as first-class elements. Currently, every chart author must either:
(a) Use `El()` + `addAttribute` with ESLint suppresses (jt-cut's approach), or
(b) Fall back to `Raw("<svg>…")` for the whole chart.

The problem is compounded by the missing `setStrokeOpacity` on `SvgShapeTag` (separate from `setOpacity` on the element level) — `stroke-opacity` is a distinct SVG attribute used in chart stroke rendering (fade effects on area charts).

## Rough idea

Add typed tag classes to `fluent-html/src/elements/svg.ts`:
- `LinearGradient(id, …children)` with `setX1/Y1/X2/Y2`, `setGradientUnits`
- `RadialGradient(id, …children)` with `setCx/Cy/R/Fx/Fy`
- `Stop()` with `setOffset(pct)`, `setStopColor(color)`, `setStopOpacity(n)`
- `ClipPath(id, …children)`
- `Filter(id, …children)` + `FeGaussianBlur()` with `setStdDeviation`
- Add `setStrokeOpacity(n)` to `SvgShapeTag`

These are additive, zero-dep, and follow the existing `SvgShapeTag` pattern exactly.
