# SvgTag missing setStrokeLinecap / setStrokeLinejoin

## Problem

`SvgTag` (the `<svg>` root element returned by `Svg()`) has `setStrokeWidth`, `setStroke`, and `setFill`, but is missing `setStrokeLinecap` and `setStrokeLinejoin`. Those two attributes are the most commonly used presentation attributes on the `<svg>` container when authoring icon components, because setting them on the root propagates to all children via CSS inheritance, avoiding the need to set them on every `Path()` individually.

As a result, `mngmt` ships with a file-level ESLint suppression comment just to write its icon helper:

```ts
// mngmt/src/shared/icons.ts:3-7
/* eslint-disable fluent-html/prefer-set-method -- setStrokeWidth doesn't exist on SvgTag */
const icon = (t: ReturnType<typeof Svg>) =>
  t.w("5").h("5").setFill("none").setStroke("currentColor")
    .addAttribute("stroke-width", "1.5").setViewBox("0 0 24 24");
/* eslint-enable fluent-html/prefer-set-method */
```

Note: the comment says `setStrokeWidth doesn't exist on SvgTag` but the lib actually added it (`media.ts:343`). The suppression was written when the method was missing and never updated — but `setStrokeLinecap` and `setStrokeLinejoin` still don't exist on `SvgTag`.

In `jt-cut`, the same gap forces `addAttribute` calls for SVG gradient child elements (which use `El()` and therefore receive only the base `Tag` type, not `SvgShapeTag`):

```ts
// jt-cut/src/analytics/views/analytics.chart.ts:85-96
// eslint-disable-next-line fluent-html/prefer-set-method -- El() returns generic Tag without typed SVG setters
return El("linearGradient",
  ForEach(stops, s => {
    const el = El("stop")
      .addAttribute("offset", `${s.offset * 100}%`)
      .addAttribute("stop-color", s.color);
    return s.opacity != null ? el.addAttribute("stop-opacity", String(s.opacity)) : el;
  }),
)
  .setId(id)
  .addAttribute("x1", String(x1)).addAttribute("y1", String(y1)).addAttribute("x2", String(x2)).addAttribute("y2", String(y2));
```

## Evidence

- `mngmt/src/shared/icons.ts:3-7` — file-level ESLint suppress for `prefer-set-method` due to missing setters on `SvgTag`. This file defines all 6 navigation icons for the `mngmt` app — the suppression is not an edge case, it's on the primary icon authoring site.
- `jt-cut/src/analytics/views/analytics.chart.ts:85-96` — `El("linearGradient"…)` must use `addAttribute` for all gradient-specific attrs because `El()` returns generic `Tag` without SVG-typed methods.
- `fluent-html/src/elements/media.ts:304-347` — `SvgTag` definition: has `setStroke`, `setFill`, `setStrokeWidth`, but lacks `setStrokeLinecap` and `setStrokeLinejoin`.
- `fluent-html/src/elements/svg.ts:7-63` — `SvgShapeTag` definition: has the full set including `setStrokeLinecap`, `setStrokeLinejoin`, `setStrokeDasharray`, `setOpacity`, `setTransform`, `setFilter` — none of which are present on `SvgTag`.

## Why it matters

`setStrokeLinecap("round")` and `setStrokeLinejoin("round")` are the two most commonly repeated SVG attributes in icon authoring — virtually every Heroicons/Lucide icon uses them. Having them on `SvgShapeTag` but not `SvgTag` means every app that authors icons with the fluent API either (a) duplicates the calls on every `Path()` child, (b) uses `addAttribute` with an ESLint suppress, or (c) falls back to `Raw("<svg>…")`. The fix is purely additive and fully backward-compatible.

The `El()` / `linearGradient` case is a related but distinct issue: SVG container elements that fluent-html doesn't model as typed classes (`linearGradient`, `radialGradient`, `stop`, `clipPath`, `mask`, `filter`, `feGaussianBlur`) must use `El()` + `addAttribute`, defeating the type-safety and ESLint-enforcement story for SVG chart authoring.

## Rough idea

Add `setStrokeLinecap`, `setStrokeLinejoin`, `setStrokeDasharray`, `setStrokeDashoffset`, and `setTransform` to `SvgTag` to match the attributes most commonly set on the `<svg>` root when building icons. Alternatively, make `SvgTag` extend `SvgShapeTag` and add only the `<svg>`-specific attrs (`viewBox`, `xmlns`) on top. The second approach is more principled and removes the duplication between `media.ts` and `svg.ts`.
