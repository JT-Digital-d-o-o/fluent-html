# 261 request.user! non-null assertions across 4 apps

## Problem

`request.user` is typed `AuthUser | null` because an unauthenticated request may arrive at any route. Once a `preHandler: [requireAuth]` guard is in place the value is guaranteed non-null, but TypeScript doesn't know that — so every handler that reads the user must either assert `request.user!` or re-check.

The `!` assertion is the overwhelming convention across all four apps: **96 in rideshare, 88 in storysell-ai, 47 in mngmt, 30 in glimm = 261 total**.

```ts
// rideshare/src/rides/rides.controller.ts:43
const userId = request.user!.id;

// rideshare/src/settings/settings.controller.ts:68
const user = request.user!;

// mngmt/src/settings/settings.controller.ts:90
const user = request.user!;

// mngmt/src/comments/comments.controller.ts:47
currentUserId: request.user!.id,
isAdmin: request.user!.role === "ADMIN",
```

The guideline even endorses this pattern explicitly:

```ts
// web-development/fastify.md:94
const user = request.user!; // safe after requireAuth
```

## Evidence

- 96 `request.user!` occurrences in rideshare/src (count: `grep -r "request\.user!" rideshare/src --include='*.ts' | wc -l`)
- 88 in storysell-ai/src
- 47 in mngmt/src
- 30 in glimm/src
- Representative: `rideshare/src/rides/rides.controller.ts:43`, `rideshare/src/rides/rides.controller.ts:57`, `glimm/src/auth/auth.permissions.ts:64`

## Why it matters

`!` is an escape hatch. If the guard is accidentally removed from a route, TypeScript remains silent and the runtime throws on `.id`. The pattern also clutters every handler. A narrowing helper would make the guarantee explicit in the type system rather than in a comment.

## Rough idea (not a design)

A `requireUser(request: FastifyRequest): AuthUser` helper (throws a typed 401 FastifyError if null) that apps call at the top of guarded handlers instead of `request.user!`. Alternatively, a typed request wrapper `AuthenticatedRequest` with `user: AuthUser` (non-nullable) that `handle()` accepts as a generic parameter when a `requireAuth` guard is declared — so TypeScript knows `request.user` is non-null without any assertion. The second approach is zero-runtime-cost but requires tighter `handle()` generics.
