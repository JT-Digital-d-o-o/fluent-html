# No first-class `FormField` component — FormGroup+StyledInput triad reimplemented in 8 apps with diverging signatures

## Problem

Every app independently reimplements the same three-part form primitive: a wrapper that pairs a label with a styled input and optionally shows an error message below it. The implementations have the same shape but diverge in small details (color tokens, `required` asterisk style, error margin, helper text support) that make cross-app components non-portable. There is no built-in first-class replacement.

## Evidence

**rideshare** (`rideshare/src/shared/components/form.view.ts:4-45`):

```ts
export function FormGroup(label: string, input: View, required = false) {
  return Div(
    Label(label + (required ? " *" : ""))
      .textSize("sm").fontWeight("medium").textColor("body").margin("b","1").display("block"),
    input,
  ).margin("b","4");
}
export const styledInputStyle = <T extends Tag>(t: T): T =>
  t.w("full").padding("x","4").padding("y","3")
    .border("2").borderColor("site-border").rounded("lg")
    .transition("colors").on("focus", t => t.borderColor("leaf").outline("none")) as T;
```

**mngmt** (`mngmt/src/settings/settings.view.ts:36-73`) — identical structure, different color tokens:

```ts
function FormGroup({ label, input, required = false }: FormGroupProps): View {
  return Div(
    Label(label + (required ? " *" : ""))
      .textSize("sm").fontWeight("medium").textColor("slate-300").margin("b","2").display("block"),
    input,
  ).margin("b","4");
}
function StyledInput(): ReturnType<typeof Input> { ... }
function Alert({ message, type = "danger" }: AlertProps): View { ... }
```

**storysell-ai** (`storysell-ai/src/shared/components/ui.form.components.ts:14-51`) — another near-duplicate:

```ts
export function FormGroup({ label, input, required = false }: FormGroupProps) { ... }
export const inputStyle = (t: InputTag) => t.w("full").padding("x","4").padding("y","3")
  .border("2").borderColor("gray-200").rounded("lg")
  .transition("colors").on("focus", tt => tt.borderColor("primary").outline("none"));
export function StyledInput(): InputTag { return Input().apply(inputStyle); }
export function Alert({ message, type = "danger" }: AlertProps) { ... }
```

**storysell-ai** additionally has `BrandFormGroup` (`storysell-ai/src/shared/components/brand/ui.brand.forms.ts:92-105`) — a second, slightly richer variant in the same codebase (adds `helper?` field, uses `InputLabel` and `InputHelper` sub-components), making this the only app with two divergent form-group implementations.

## Why it matters

8 apps reimplement the same 40–80 LOC helper. Divergence accumulates: `required` asterisk color, label margin, error positioning, helper-text support. When the library adds `BrandFormGroup.helper` in one app it is invisible to the others. The pattern is so uniform it is a direct indication of a missing built-in. Deleting these would eliminate roughly 100 LOC of helper definitions and 200+ call-site lines fleet-wide, while making cross-app portability possible.

## Rough idea (not a design)

A built-in `FormField({ name, label, type?, required?, error?, value?, hint?, input? })` component that renders a label + input + inline error block, with the input style driven by a theme token (so apps configure once via `createContext` rather than rewriting the function). Works with `formFor<T>()` so the `name` is type-checked against the schema type. The `input?` override slot keeps it composable for non-standard controls.
