# behavior('toggle') can't manage modal's hidden+flex two-class state; 30+ raw hx-on:click strings result

## Problem

The `behavior("toggle")` built-in only does `.classList.toggle('hidden')`. But every app-level modal overlay uses a two-class pattern: visible = `flex`, hidden = `hidden`. Toggling only `hidden` leaves `flex` stranded on a hidden element (or missing when shown), breaking the centering layout. Apps therefore cannot use `.behavior()` for modals and must fall back to raw JS strings via `addAttribute("hx-on:click", ...)`.

The modal component's own doc comment even calls this out:

```ts
// planet-positive-sport/src/shared/components/display/modal.ts:56
/**
 * Hidden by default — toggle visibility via HTMX or `.behavior("toggle")`.
 */
```

But the actual close button uses raw JS, not `.behavior()`:

```ts
// planet-positive-sport/src/shared/components/display/modal.ts:41-52
export function closeModalJs(id: string): string {
  return `document.getElementById('${id}').classList.add('hidden'); document.getElementById('${id}').classList.remove('flex')`;
}
export function showModalJs(id: string): string {
  return `document.getElementById('${id}').classList.remove('hidden'); document.getElementById('${id}').classList.add('flex')`;
}
```

And the `toggle` behavior is literally incapable of replicating this:

```ts
// fluent-html/src/core/behavior-methods.ts:47-50
toggle: (opts) => [
  "click",
  `${el(opts.target)}.classList.toggle('hidden')`,
],
```

## Evidence

Every modal open/close is wired with `addAttribute("hx-on:click", closeModalJs(id))` or `addAttribute("hx-on:click", showModalJs(...))`:

```ts
// planet-positive-sport/src/loc/assessment/assessment.components.ts:488
.addAttribute("hx-on:click", closeModal(id))  // local duplicate of closeModalJs

// planet-positive-sport/src/admin/organizations/organizations.view.ts:223
.addAttribute("hx-on:click", toggleHidden(rejectModalId))

// planet-positive-sport/src/loc/events/views/event-overview/submit-button.component.ts:57
.addAttribute("hx-on:click", showModalJs(eventOverviewIds.submitConfirmModal.id))
```

Grep for `addAttribute.*hx-on` in pps gives 30 hits, the majority tied to modal show/hide. The `assessment.components.ts` file defines its own local `closeModal()` JS-string generator (line 477–479) — a second reimplementation of `closeModalJs` from `modal.ts` — because the call sites are far from the shared helper.

## Why it matters

30+ `addAttribute("hx-on:click", closeModal(id))` calls in pps alone. Every new modal adds 2–3 more (backdrop click, close-X, footer dismiss). The guideline says "`.behavior()` for client-side interactions — never raw inline JS" but the modal use-case is structurally impossible to satisfy with the current `toggle` implementation. It is the highest-frequency `.behavior()` adoption blocker in the fleet.

## Rough idea (not a design)

Extend `BehaviorMap` with `showOverlay: { target: Id }` and `hideOverlay: { target: Id }` (or a unified `openModal`/`closeModal`) that emit `classList.remove('hidden'); classList.add('flex')` and the inverse. The behavior names should be semantic (not CSS-mechanic) so they remain correct if the CSS approach changes. Existing `toggle` stays; the new behaviors are additive.
