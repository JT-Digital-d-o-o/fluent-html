# Verdict: RFC-B-05 — dx lens

> Adversary. Job: kill RFC-B-05 through the dx failure mode. Default reject under uncertainty.

## Attack

The core idea — `Icon("name")` returning a thenable `SvgTag` instead of `Raw("<svg>")`, plus typed gradient/clip/filter tags — is genuinely good DX and well-motivated (170+ `Raw("<svg>")` sites, type-eroded `icon?: string` injection slots). It is consistent with library idioms (variadic children, specialized setters, `.on()/.at()/.textColor()` chaining), discoverable, and hard to misuse once the slot is typed `View`. That part survives. The kill lands on **accuracy and guideline-edit correctness**, which §11.8 makes a first-class adoption gate.

- **dx failure mode 1 — api_surface is fiction against HEAD.** §2 frames `SvgTag` and `SvgShapeTag` as both needing a shared stroke mixin and lists `SvgShapeTag.prototype.setStrokeLinecap/setStrokeLinejoin/setStrokeDasharray/setTransform` as part of the work. **All four already exist on `SvgShapeTag`** (`src/elements/svg.ts:31-67`, `_sk` schema at :69). Worked example C ("setStrokeWidth doesn't exist on SvgTag") is right about the *root* but the RFC bleeds that into the *shape* class. An RFC whose surface inventory double-counts shipped methods cannot merge as-is: Wave-4 `_merge.md` scans `api_surface` overlaps for collisions, and a self-collision (claiming to add what exists) corrupts that input. The true gap is narrow: the `<svg>` ROOT (`src/elements/media.ts:304-347`) lacks every stroke setter past `setStrokeWidth`, and `stroke-opacity`/`stroke-dashoffset` are absent library-wide (verified: zero hits in `src/`). The claim must shrink to exactly that.

- **dx failure mode 2 — the guideline edit re-teaches a deprecated symbol.** §11.8 exists so a great API doesn't die from a bad teaching edit. The proposed `fluent-html.md` replacement (RFC lines 321, 333) presents `setSvgOpacity()` as live API. Source says `@deprecated Use setOpacity` (`src/elements/svg.ts:48-52`). Steering the LLM reader back to a deprecated method — in the very edit meant to teach the new surface — is an adoption regression. The existing guideline (`fluent-html.md:183-196`) already carries this rot (`setSvgOpacity` taught as current); the RFC inherits it instead of correcting it.

- **dx failure mode 3 — `size: TailwindSize` is an un-typed promise.** The RFC sells type-safety hard (`IconName` literal union, enum'd `setGradientUnits`) yet `IconOptions.size?: TailwindSize | false` references a type that **does not exist**; `.w()/.h()` take `TailwindWidth` (`src/core/tailwind-methods.ts:139-140`). For an RFC whose thesis is "typed, extractor-visible sizing beats embedded class strings," fumbling the one token type in its own options bag undercuts the pitch and would not compile — exactly the imprecision the dx lens must catch before it folds into the spec.

- **dx failure mode 4 (surface-area) — a 24-name frozen `BuiltinIconName` union with an unresolved canonical list.** Open Questions §1 admits the ~24 names and the license source are unresolved. Baking an unresolved set into an exported literal union is a surface bet that's breaking to unwind (renaming/removing a builtin name). Under default-reject for over-surface, the builtin union should not freeze until the list is settled; ship the registry mechanism now, the frozen names later.

## Does it survive?

**survives-with-changes.** The mechanism (`Icon` → `SvgTag`, `View` slots killing the `Raw(icon)` injection, typed gradient/clip/filter tags, root-`SvgTag` stroke setters, new `setStrokeOpacity`/`setStrokeDashoffset`) is worth the surface area and an app author would reach for it — the before/after deltas are real and large. But the api_surface double-counts existing `SvgShapeTag` setters, the type story references a non-existent `TailwindSize`, and the §11.8 edit teaches a deprecated symbol at a mis-fit/mis-numbered anchor. None is fatal to the design; each is a precise mechanical fix. Per §11.8 and the dx-lens charter, a missing-or-confusing guideline edit caps the verdict at survives-with-changes regardless of API quality — that is the ceiling here. The five required changes fold back into the RFC verbatim.

## Guardrail check (dx owns §11.8 guideline-sync)

§11.8 **FAILS as written**: the guideline edit (a) re-teaches deprecated `setSvgOpacity`, (b) appends API rules to a design-precision prose section with a mis-stated anchor line (`---` is CLAUDE.md:49, not 50; section is 44-48 prose), and (c) its api_surface coverage is unverifiable because the surface list is wrong (claims teaching coverage for `SvgShapeTag` setters that need none). Coverage of the *genuinely new* symbols (Icon/registerIcon(s)/IconRegistry, root-SvgTag setters, setStrokeOpacity/setStrokeDashoffset, the gradient/clip/filter tags) is otherwise present and in house style (✓/✗, code-first, LLM-reader). Once the four guideline-related required changes land, §11.8 passes. §11.1 zero-deps and §11.3 escape-by-default are upheld (inline path data, real escaped nodes, `View` slot removes the `Raw()` injection class) — no dx-lens objection there.
