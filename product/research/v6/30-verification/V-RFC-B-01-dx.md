# Verdict: RFC-B-01 — dx lens

> You are an ADVERSARY. Your job is to KILL this RFC through the dx lens.
> Default to `reject` under uncertainty — a good API cut is cheaper than a bad API shipped.

## Attack

Existence is not killable. The demand is the strongest in the whole Track-B set: 8 apps reimplement `FormGroup` (file:line cited), `FieldError` duplicated *twice in one feature* with mismatched margins, 6+ raw-JS reset sites, 7 dual-encoding multipart sites. The §13 "is this worth the surface area?" cut fails — this is the highest-frequency primitive in the fleet and every symbol maps to a quantified duplication. So the attack lands on *shape* and *teaching*, which this lens owns.

- **dx failure 1 — the headline override is taught with a phantom method.** `input?: (base: InputTag) => Tag` is how `f.field()` covers textarea/select/custom — the dominant non-text case, and the very controls `formFor` already has first-class methods for. The fluent-html.md edit teaches it as `base => base.replaceWith(Textarea()…)`. `replaceWith` does not exist (`grep -rn replaceWith src/` → 0). Worse, the contract is incoherent: it hands you an `InputTag` (carrying the theme/name/value wiring) and asks you to return a *different* element, so the one thing `base` gives you is the thing you must discard. The primary escape hatch is both unbuildable and conceptually backwards.

- **dx failure 2 — the discoverable path is the unsafe one.** Two ways to render a field ship: standalone `FormField(props)` and `formFor<T>().field()`. Only the latter narrows `name` to `keyof T & string`; `FormFieldProps.name` is bare `string`. The RFC's own type-safety story *admits* the risk ("apps stop reaching for untyped `FormField({ name: '…' })`") yet ships the untyped export anyway, top-level and component-shaped, shorter to type than threading a `formFor<T>()` handle. The index ✗ never names it. An author who never trips the schema check gets a silent 422-binding miss — exactly the bug `FormErrors<T>`'s typed `ErrorBag` was added to kill, reintroduced through the front door. This is the §11.8 under-adoption failure inverted: the unsafe path is the discoverable default.

- **dx failure 3 — guideline anchors don't reconcile with the live files.** I diffed every cited insertion point against `/Users/tony/jt-digital/guidelines/web-development/`. fluent-html.md's forms section is at line 63 (not "after 87"); the CLAUDE.md index anchor slug is wrong for an en-dash + backtick heading (dead link for an LLM follower); and htmx.md's existing `## Status-code routing` (line 124) teaches `status: { 422: { target: ids.formErrors, swap: 'innerHTML' } }` — a feature-target innerHTML swap that directly contradicts the RFC's "full-layout swap targeting `ids.mainContent` is the default" framing and its own example C/D. The new block lands beside a conflicting one.

## Does it survive?

**survives-with-changes.** I verified the load-bearing claims that would have *killed* it if false, and they hold: `placeholder`/`selection`/`marker`/`file` ARE valid `TailwindState` `.on()` targets (`src/core/tailwind-types.ts:185`), so the "no `addClass('placeholder:…')`" adoption fix is real; the `BehaviorMap` declaration-merge + `(opts) => [event, js]` renderer shape is exactly what the lib implements (`src/core/behavior-methods.ts`), so `resetOnSuccess` drops in cleanly and idiomatically; `setHtmx` already carries `encoding?: HxEncoding` (`src/htmx.ts:213`) so `.multipart()` drives a real attribute; `setCapture`/`multipart` are genuinely net-new and additive; `createInputTheme` as apply-fn-via-context correctly beats the named-variant alternative (the lib can't know per-app palettes) and emits zero new classes (§11.7 untouched). The bundling concern (10+ symbols) is real but the evidence carries it — every symbol is cited; I will not force a split, though splitting `multipart`/`setCapture`/`resetOnSuccess` into a sibling RFC remains a defensible editorial call for the synthesizer.

What does not survive unchanged is the DX/teaching surface: an unbuildable headline override, an unsafe discoverable default, and guideline anchors that contradict the live files. These are precisely the §11.8 "mis-taught API is an un-adopted API" failures this lens guards. They fold back as the six required changes above — all mandatory before the guideline patch ships, none individually fatal.
