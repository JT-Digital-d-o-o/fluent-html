# v6 RFC Curation — decisions log

> Live record of the RFC-by-RFC include / cut / modify / defer review. Resumable across sessions.

## Governing constraints (override the original synthesis)

1. **v6 is greenfield-only — no v5 backward-compat.** New projects use v6; existing stay on v5. → Drop all migration machinery: codemods, `@deprecated` aliases, the v6.0 "breaking bundle", dual-target. The `breaking` field is moot. `breaking-changes.md` → a "v6 vs v5 diff" note, not a gate. _(memory: v6-greenfield-no-v5-compat)_
2. **Tailwind: v6 is v4-native.** No `setTailwindTarget` dual-target, no v3 default, no v3-look-preserving remaps. Track C emits v4 names. C-02/C-03 collapse to "emit v4 / ship v4 config".
3. **`set*` overrides, `add*` accumulates.** _(memory: set-vs-add-naming-convention)_ — setStyles stays replace; RFC-D-07 already corrected.
4. **fluent-html is an instruction set, not a component kit.** _(memory: fluent-html-is-instruction-set)_ Ship primitives that NEED library support (type machinery, render support, native elements, behaviors, context, `defineTheme()`, styling methods). **Opinionated visual components are user-land** (the user's `@jtdigital/ui`): Alert, Badge, Card, Modal/Drawer shells, StatCard, Skeleton, button-variant/typography wrappers, ToastContainer, SeoHead, Container/Shell. Test: *"can a user compose this from the instruction set?"* → yes = cut. **Converge: no two ways to do the same thing** (one `defineTheme()`, not 3 theme contexts). This **re-scopes Track B** — cut the component shells, keep the primitives. → The cut user-land/app-land surface (design system + framework glue) is tracked for the template + `@jtdigital/ui` in `projects-template/project/pm/template-update/fluent-html-v6-alignment.md`.
5. **fluent-html core is a pure HTML builder — no context, no framework glue.** _(memory: fluent-html-no-context-no-framework-glue)_ `createContext`/`scope` is a standalone module-global stack with **zero render coupling** (values baked in at construction; `render()` never reads context) → leaves core. Request-scoped context is a **request-lifecycle problem the outer framework owns**. → `render()`/`renderToStream()` stay pure (nonce = render option); the render adapter (`renderView`/`renderHx`) + the context bridge → official **`@fluent-html/fastify`**; auth/i18n/errors + design system → separate `@jtdigital/*` packages (names **deferred**). **Revises A-05 / B-07 / B-08 / B-09** (their context/Fastify surface moves out of core).
6. **No fold / recursion-schemes layer — cut it entirely.** `src/fold/` (`foldView`/`paraView`/`unfoldView`/`hyloView`/`ViewAlgebra`/`ParaAlgebra`/`ViewCoalgebra` + every algebra: `renderAlgebra`/`ariaDescribeAlgebra`/`linksAlgebra`/`tocCoalgebra`/`linkedTocCoalgebra`/`createTransformAlgebra`/`countAlgebra`/text-extract) is **removed from v6** (~729 LOC). **Evidence:** zero production usage — the ONLY consumers are `fluent-html-demos` (`a11y-auditor.view.ts` + `auto-toc.view.ts`), and those showcases *disprove* the value: `paraView`'s `_original` (its whole reason to exist over `foldView`) is declared-then-unused with abandoned sibling-check logic; `foldView` can't extract heading text so it needs **two** algebras + a `data-text` fallback; `unfoldView(linkedTocCoalgebra,…)` is just `Ul(ForEach(entries, e => Li(A(e.text).setHref("#"+e.id))))`. Cleverness-for-cleverness-sake — fails §4 (instruction set). The genuine needs (a11y audit / TOC / link extraction) are <10-line plain recursive `View` walks in app-land/tooling, not core API. **Reshapes Track D — removes a whole bug class:** moots most of D-05 (fold-XSS), the `renderAlgebra` half of D-03, and the fold-traversal half of D-01. `FOLD.md` + `functional-patterns.md` get **deleted**, not updated.

Any doc / example / JSDoc that shows a discouraged pattern (`.position("absolute")`, `.display("flex")`, `addClass("@container")`, raw v3 config, `setStyle().setStyles()` chains, …) gets rewritten to the preferred one.
