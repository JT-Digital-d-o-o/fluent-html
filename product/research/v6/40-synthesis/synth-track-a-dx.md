# Track A — DX & API Improvements: v6 Synthesis

> ⚠️ **Superseded by [`v6-spec.md`](./v6-spec.md) (Track A) + [`curation.md`](./curation.md).** Curated deltas vs this narrative: `Overlay()` → **`.overlay()` fluent method**; `ForEachOr` → **`ForEachElse`**; outright renames (no `@deprecated`/v7, §1 greenfield); **context (A-05) moves to `@fluent-html/fastify`** (§5, not core); SEO head helpers (A-06) → `@jtdigital/ui`; `.position(value)`/`.display(value)`/`.flex1()` dropped for dedicated A-07 methods. Kept here for the original evidence/rationale.

**14 RFCs, all surviving.** Track A is the "make the existing surface correct, complete, and teachable" track. Almost everything is additive; three changes are genuinely breaking (one bug-fix break, two type-narrowings). A recurring theme runs through the whole track: **the library already does the right thing, but the typed path is either missing a piece, subtly wrong, or never taught — so apps fall back to `addAttribute` / `addClass` / raw JS.** Half the RFCs (the `-G` cluster) ship *zero or near-zero* code and are pure guideline edits that close adoption gaps measured in hundreds of real call-sites.

The headline wins, in one breath: **boolean attributes stop lying** (`checked="false"` no longer renders as checked), **`Document()` emits a DOCTYPE** so 40+ apps drop `Raw("<!DOCTYPE html>")`, **negative Tailwind transforms finally work** (`-translate-y-1` instead of the silently-dropped `translate-y--1`), **request-scoped context becomes concurrency-safe**, and the **whole accessibility surface gets typed setters** (`setRole`/`setTabindex`/`setTitle`/typed `setAria`).

---

## Shared infrastructure these RFCs land on (read first)

Three internal spines are touched by many Track-A RFCs and were assigned single owners in the Wave-4 merge. Track-A changes must fold into them rather than each patching independently:

- **The `_sk` attribute serializer + the three emit paths** (`render.ts`, `stream.ts`, `fold/algebras/render.ts`). A-01, A-02, A-03, A-06 all change how attributes/doctype serialize. The merge (conflict C-7) makes **D-03 the owner of emitter unification**; every Track-A attribute change either lands in D-03's single emitter or ships a **three-path parity test** asserting byte-identical output across `render`, `stream`, and `foldView(renderAlgebra)`. The fold path renders attrs generically by JS key, so `_sk`-order/tuple fixes (A-03) are invisible there unless `extractAttrs` learns the prop→attr mapping. **Sequencing: D-01 de-recursion → D-03 dedup → Track-A attribute RFCs fold in.**
- **New class-emitting fluent methods** (A-07's transforms/shortcuts, A-09's Overlay) are a **hard dependency on the Track-C extractor + ESLint vocab landing in the same milestone** (conflict C-6). The shared `@fluent-html/class-vocab` codegen (C-05) is the single source; A-07/A-09's utilities become vocab rows there. Day-one default target is `v3`, keeping output byte-identical.
- **`BehaviorMap` and `escapeJs`** — B-02 owns `BehaviorMap`, D-05 owns the single hardened `escapeJs`/`validateAttributeKey`. A-08's `formResetOnSwap`/`dismissOnEscape` live *alongside* B-02's set; A-08's `escapeJs` fix defers to D-05's impl.

## Group 1 — Additive guideline-only adoption fixes (no/near-zero code, land first)

These are the cheapest, highest-leverage changes. No runtime surface (or a one-line string fix); the deliverable is verbatim guideline patches to `web-development/{CLAUDE.md,fluent-html.md,htmx.md,fastify.md,performance.md,typescript.md}`. They exist because un-taught APIs are un-adopted APIs.

- **A-G1 — control-flow anti-patterns.** Teaches the **✗ forms** the existing APIs already solve: `IfThen`-chain on a string discriminant → `Match(value, key, cases)`; paired `IfThen(x)`+`IfThen(!x)` → `IfThenElse`; `ForEach(Array.from({length:n}))` → `ForEach(n, fn)`; DU-prop via boolean flag → `Match(props, "state", cases)` narrowing; `IfThen(!!x, () => C(x!))` → drop the `!!` so the nullable overload narrows. *(Amendments: the `!!x`→plain-x codemod is unsafe for falsy-non-null `""`/`0` — restrict to provably-non-falsy or flag-for-review; fix the non-compiling `Match` snippet; scope discriminant-key teaching to genuine DUs.)*
- **A-G4 — close the docs-vs-reality drift.** Promotes the highest-frequency *already-shipping* methods from invisible to taught: `.display()` (1263 sites), `.hidden()` (283), `.transition()` (1851), and the omnipresent `.on()`/`.at()` variant API — none were in the README table or guideline. Purges `addClass`/`setClass` raw-string anti-patterns *from the docs themselves* (the `.apply()` JSDoc and README "Traditional Tailwind" framing taught what `CLAUDE.md` bans). Fixes the `.when()` JSDoc (`t.children()` doesn't exist) and renames the blocked-event error to point at `.behavior()` instead of "client-side JS." *(Amendments: real type names are `TailwindState`/`TailwindBreakpoint` not `VariantState`/`Breakpoint`; preserve the exact error substring `Event handler attribute "<key>" is blocked` — 4 regex tests assert it.)*

## Group 2 — Additive API: control flow, styling, document/SEO, HTMX

New symbols, no breakage. These complete obvious holes in the surface.

- **A-04 — `ForEachOr` + `Tag.whenElse`.** The two-branch counterparts that were missing. `ForEachOr(items, renderItem, emptyView)` collapses the 377 paired-`IfThen(length>0)`/`IfThen(length===0)` list-or-empty sites into one drift-proof call (the mandatory `emptyView` slot makes "forgot the empty state" unrepresentable). `Tag.whenElse(cond, thenFn, elseFn)` is the two-branch `.when()`, replacing 91 `.when(x)`+`.when(!x)` pairs that evaluate the condition twice; it mirrors `when`'s nullable-narrowing overload. *(Amendments: `whenElse` must branch on `typeof === 'boolean' && != null` like `IfThenElse`, NOT truthiness — `""`/`0` must not route to `elseFn`; boolean overload listed first; `renderItem` is per-item, fix the headline example; drop count/range overloads for v6.0; codemod only auto-rewrites `() => ForEach(X, fn)`.)*
- **A-07 — Tailwind correctness for negatives, transforms, position/display shortcuts.** **Headline correctness win:** `.translate("y","-1")` emitted the invalid `translate-y--1` (silently dropped — a hover-lift that does nothing in prod); now a shared `signNeg` helper relocates the sign to produce the valid `-translate-y-1`. Same fix for `.rotate`/`.skewX`/`.skewY`. Documents the already-shipping-but-zero-uses `.neg("inset-px")` escape hatch. Adds 11 zero-arg position/display shortcuts (`.absolute()`, `.fixed()`, `.inlineFlex()`, `.contents()`, …) mirroring the existing `.flex()`/`.grid()`/`.hidden()`; `position()`/`display()` pass-throughs stay (1907 sites). *(Critical amendment: the RFC's "no Track-C change" claim is false — must widen `TailwindRotate`/`TailwindSkew` to admit negative literals (`.rotate("-45")` is a compile error today, making the core fix dead code) AND ship lockstep extractor+ESLint patches for the sign-relocation and the new shortcuts. → C-6.)*
- **A-06 — `Document()` + SEO head helpers + DOCTYPE.** **Headline correctness win:** `render(HTML(...))` never emitted `<!DOCTYPE html>`, so 40+ layout files prepend `Raw("<!DOCTYPE html>")` (quirks mode = a real bug, and the array form loses root chaining). `Document(...children): DocumentTag extends HtmlTag` auto-prefixes the doctype and stays chainable (`.setLang("en")`). Plus `SeoHead`/`OgMeta`/`TwitterCard`/`Canonical`/`StructuredData` — replacing 6 apps' near-identical, separately-buggy `seo.ts` copies — using `setProperty` so apps stop hand-rolling `addAttribute("property", "og:title")`. **A-06 is MERGE-OWNER of `Document()`/`DocumentTag`** (B-04 defers its props-shell to layer `Shell`/`Page` on top). *(Amendments: DOCTYPE branch must hit render+stream+fold, discriminated on a `_doc` prototype brand not `el==="html"`; **cut `Doctype()` from the public surface** — it re-enables the array anti-pattern; `StructuredData` HTML-safe-encodes and constrains input to a `JsonLd` type; fix double-`<title>` teaching.)*
- **A-08 — typed HTMX lifecycle escape hatch (`.hxOn`) + lifecycle behaviors.** Today the only path to lifecycle JS is `addAttribute("hx-on:...", rawJs)` — which the guideline forbids, *overwrites* on repeat (unlike `.behavior()` which concatenates), and doesn't escape. `Tag.hxOn(event: HxOnEvent, js)` is the sanctioned, concatenating, COW-backed escape hatch (127 sites need it); plus two *safe* no-raw-JS behaviors `formResetOnSwap`/`dismissOnEscape`. The `escapeJs` fix (it only escaped `\` and `'`, dropping `\n`/`\r`) defers to **D-05**'s single hardened impl. *(Amendments: resolve the htmx event-separator — colon `htmx:after:swap` vs kebab `htmx:after-swap` — BEFORE merge, a wrong guess is a silent no-op; validate the `hx-on:${event}` key as an attr-name-injection sink.)*
- **A-G3 — make the HTMX option surface discoverable.** ~90% guideline. Teaches the typed `HTMX` options (`confirm`/`vals`/`trigger`/`include`) that apps bypass via `addAttribute("hx-vals", JSON.stringify(...))`, the `hxGet(route)`-object form over `hxGet(route.resolve({...}))`, the `hx*` naming-zone rule, and `hxResponse(...)` over `reply.header("HX-*", ...)`. The one ergonomic code add is `HxResponse.applyTo(reply: HxReplyLike)` — a zero-dep, duck-typed reply adapter that collapses the two-call `.build()`→`reply.headers()` dance that made the escape hatch *look* shorter. **`applyTo` defers to B-08 as MERGE-OWNER** (A-G3 consumes it). `depends_on A-03` for the bare-`crossorigin` overload. *(Amendments: mark the `reply.header(...).renderView` migration as BEHAVIORAL — `applyTo` bypasses the app's `renderView` decorator; CRLF-sanitize header values.)*

## Group 3 — Element & ARIA setter coverage (additive surface, two narrowing breaks)

Closing the "typed setter over `addAttribute`" coverage holes — the rule is only as good as the coverage behind it.

- **A-02 — ARIA / role / global setters** *(amended additive → **breaking**)*. **Headline a11y win.** The single biggest `addAttribute` category (~300 sites) had no typed path: adds `setRole(role: AriaRole)` (WAI-ARIA union, typo = compile error), `setTabindex(index: number)` (no more hand-stringified `"-1"`), `setTitle`, and a **typed `setAria(attrs: AriaAttrs)`** whose state keys (`checked`/`expanded`/…) take a real `boolean` (killing `on ? "true":"false"` boilerplate) plus the tristate `"mixed"`. Fixes `ariaDescribeAlgebra` to read `aria-label`/`role` so the auditor stops describing a labeled icon button as `"button"`. **MERGE-OWNER of `setRole`/`setTabindex`/`setTitle`/`setAria`/ARIA types; A-G2 folds its `setAria` type in here.** *(Why breaking: the `setAria` key-narrowing rejects camelCase keys. Amendments: drop `(string & {})` from the key position — use a closed mapped type with an `aria-${string}` escape arm so `setAria({ lable })` is a compile error; keys are lowercase single-token (`hasPopup`→`aria-has-popup` is WRONG); `validateAttributeKey` on the derived key; write setters directly into the attrs bag, not via `addAttribute`.)*
- **A-G2 — retire the `addAttribute` aria/data/style escape hatch** *(FOLD-IN to A-02)*. Its `setAria`/`AriaAttrs` code folds into A-02; A-G2 retains the **ESLint enforcement** (`prefer-set-method` extended to flag/auto-fix `addAttribute("data-*"|"aria-*"|"style", …)` → `setDataAttrs`/`setAria`/`setStyle`), the `setDataAttrs` key-validation, the guideline reorder (typed path taught first), and the note that `addAttribute("style", …)` *double-renders* (writes the attrs bag while `setStyle` writes the dedicated field). *(Amendments: round-trip-safe data-* autofixer skips non-kebab keys; don't auto-fix `addAttribute('style')` when a style call already exists.)*
- **A-03 — element-setter coverage & naming consistency** (additive). The enabling change is a **`_sk` tuple form `[prop, attr]`** that decouples the JS field from the emitted attribute — which fixes the silently-broken `Meta().setHttpEquiv()` (rendered `httpEquiv`, browsers ignore it; now `http-equiv`). Adds `setInputmode`, `setHreflang`; widens `crossorigin` to admit the W3C-valid bare `""` (Google Fonts preconnect — 8 apps forced to `addAttribute`); routes SVG `opacity`/`filter` through `_sk`; loosens `OptionTag.setValue` to optional. Renames 8 lowercase multi-word setters to camelCase (`setReadonly`→`setReadOnly`, `setCrossorigin`→`setCrossOrigin`, …) with deprecated aliases kept for v6. **MERGE-OWNER of the `_sk` tuple + the bare-`setCrossOrigin("")` overload.** *(Amendments: the rename must ALSO cover `ImgTag.setCrossorigin` and `AnchorTag.setReferrerpolicy` and update the ESLint `prefer-set-method` map in lockstep, or the autofix targets a nonexistent method → C-5; patch the third (fold) render path for `http-equiv` or scope render/stream-only; delete the stale `attributes` key on the SVG setters to avoid double-emit.)*

## Group 4 — Context lifecycle + Fastify wiring (additive, one optional-vs-required break)

- **A-05 — context lifecycle hardening** *(amended; `Context<T>` additions must be optional or it's breaking)*. **Headline concurrency-safety win.** `Context.scope()` pushes a module-global stack and disposes the *top*, which is only LIFO-safe inside one sync block — but the **canonical project template** scopes in a Fastify `onRequest` hook and disposes in `onResponse`, so concurrent requests serve each other's locale/user/auth. The fix: `renderWithScopes(bindings, ...views)` scopes-renders-disposes in one uninterruptible call (physically impossible to scope across `await`); `scopeAll` groups scopes into one `using` Disposable; `Context.update(value)` mutates in place (kills the dispose+re-scope dance); `bind(value)` produces a typed `ScopeBinding`; pop-by-identity makes the primitive robust; the `createRequiredContext` error now shows the `using` form. New `fluent-html/testing` subpath (`withContext`/`withScopes`) bridges scope across `beforeEach`/`afterEach`. **MERGE-OWNER of context lifecycle; absorbs A-G5's code.** *(Amendments: make `Context<T>.bind?`/`update?` optional members or mark breaking — required members break structural implementers; keep the `using` fast path allocation-free, don't box the value stack; resolve `update()` on a default-only frame; pick ONE canonical entry path and teach it across all 3 guideline files.)*
- **A-G5 — context-in-Fastify + auth + `formFor<T>`** *(FOLD-IN to A-05)*. Its `scopeReply`/`Context.provide`/`ContextProvider` code folds into A-05's lifecycle owner. A-G5 retains the **adoption teaching**: wire auth/locale context inside the `renderView` decorator (killing 102 `user: request.user` prop-drill sites and a verbatim `createContext` reimplementation), and prefer `formFor<T>()` over bare `.setName()` when a schema type already exists (ttl has 41 `.setName()`, 0 `formFor`, despite a matching `SignInReq` type). *(Amendments: default to teaching the EXISTING `using`+`scope()` inside the decorator — justify any new symbol against a concrete failure plain `using` can't solve; drop `nonce`-as-context-value (use `renderWithNonce`); drop the unsanitized `Img().setSrc(user.avatarUrl)` flagship (URL-scheme XSS); `formFor<T>` rejects `interface` types — use `type`.)*

## Group 5 — Boolean serialization fix (the one true breaking change)

- **A-01 — boolean-attribute serialization fix + unify on `.toggle()`** (**breaking**, staged as bug-fix + soft-deprecation). **Headline correctness win.** Two parallel boolean mechanisms exist and the older `_sk` one is silently wrong: it serializes via `String(value)`, so `setChecked(false)` emits `checked="false"` — **which browsers treat as checked** — and `setDefer()` emits HTML-invalid `defer="true"`. The render fix branches on `typeof value === 'boolean'`: `true` → bare attribute name, `false` → omitted. The typed boolean setters (`setChecked`/`setDisabled`/`setDefer`/…) are `@deprecated` (removed in v7, not v6 — the lesson from the un-codemodded v5.9 `setToggles` removal that froze 11 apps); `.toggle(name, cond?)` becomes the single canonical path. Ships two **auto-fixing** codemods *with* the change: `prefer-toggle` and `no-set-toggles`. **MERGE-OWNER of the `_sk` boolean render branch; coordinate with A-03.** *(Critical amendments: `fold/algebras/render.ts` is NOT an `_sk` loop — patch all 3 emitters + add a 3-path boolean parity test; **gate the boolean branch on a boolean-FIELD registry, not `typeof value`** — a boolean landing in a string field would render bare; close the setter-coverage gap (`setSelected`/`setNovalidate`/`setAllowfullscreen`/`setPlaysinline`; drop invented `setDefault`); add `playsinline`/`nomodule` to the `BooleanAttribute` union; escape/validate the `toggle` render sink.)*

## Group 6 — Codebase self-consistency

- **A-09 — type-only exports + variadic/fluent Overlay** *(amended `false` → **breaking** for the Overlay output change)*. Two "the library should do what it teaches" fixes. (1) 15 type-only symbols (`HTMX`, `HxSwap`, `Id`, `OverlayPosition`, …) are exported in value-position `export {}` blocks, breaking consumer re-exports under `verbatimModuleSyntax` (TS1205) — split to `export type`. (2) `Overlay()` is the lone built-in shipping the array-wrapper + raw-CSS anti-patterns it forbids — rewritten variadic + fluent (`.position()`/`.zIndex()`/`.neg()`/`.apply()` position table). **The Overlay output change (inline-style → Tailwind classes) is reclassified breaking** (CSP `style-src`, selectors, snapshots all shift) and depends on C-6's vocab confirmation for `-translate-x-1/2`/`top-1/2`. The variadic-Overlay rewrite is the SAME change D-07 lists — deduped to A-09 (conflict C-9). *(Amendments: add the breaking-changes.md entry; update `test/overlay.ts` 10 inline-style assertions; drop the "byte-equivalent" framing.)*

## Dependency order (build sequence)

1. **Guideline-only, no-code (anytime, land early):** A-G1, A-G4.
2. **Emitter foundation (external to Track A, but gating):** D-01 de-recursion → D-03 emitter dedup. All Track-A attribute RFCs (A-01, A-02, A-03, A-06) fold into or parity-test against this.
3. **Track-C vocab (external, gating the class-emitters):** C-05 vocab rows for A-07/A-09 → C-01 extractor + C-04 ESLint.
4. **Additive API with no cross-deps:** A-04, A-08 (`escapeJs` via D-05).
5. **Context spine:** A-05 (owner) ← A-G5 folds in.
6. **ARIA spine:** A-02 (owner) ← A-G2 folds in.
7. **Attribute coverage:** A-03 (`_sk` tuple, lockstep ESLint map with C-04/C-05).
8. **Document/SEO:** A-06 (owner; B-04 layers on top).
9. **HTMX discoverability:** A-G3 (consumes B-08's `applyTo`; `depends_on A-03`).
10. **Breaking serialization:** A-01 (with codemods; all-3-emitter parity test).
11. **Consistency:** A-09 (Overlay output gated on C-6 vocab).

**Breaking-changes.md entries from this track:** A-01 (boolean render + setter deprecation), A-02 (`setAria` key narrowing + ariaDescribe snapshot), A-09 (Overlay inline-style → classes). Everything else is additive, with optional/lazy codemods.
