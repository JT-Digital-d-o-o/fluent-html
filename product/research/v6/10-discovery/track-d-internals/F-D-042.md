# `hyloView` always allocates a fresh `attributes: {}` object per tag node

## Problem

`hyloView` (the hylomorphism — fused unfold-then-fold) builds a `TagAttrs` object for every `tag` layer produced by the coalgebra:

```ts
// src/fold/hylo.ts:30-33
case "tag": {
  const foldedChildren = alg.list(
    layer.children.map(s => hyloView(coalg, alg, s))
  );
  const attrs = {
    attributes: {} as Record<string, string>,  // ← always allocates {}
    ...layer.attrs,
  };
  return alg.tag(layer.element, attrs, foldedChildren);
}
```

The spread `{ attributes: {}, ...layer.attrs }` allocates a fresh `{}` object on every tag node **regardless of whether the coalgebra provides `attributes`**. When `layer.attrs` itself contains `attributes`, this fresh `{}` is immediately shadowed and discarded — the allocation is pure waste. When `layer.attrs` is undefined or empty (the common case for simple coalgebras like `tocCoalgebra` and `linkedTocCoalgebra`), the `{}` survives but `foldView` and `paraView` would have used `EMPTY_ATTRS` (the frozen sentinel) rather than a fresh allocation.

## Evidence

`src/fold/hylo.ts:30-33` — the `attributes: {}` default is placed before the spread, so it is **always** allocated, even when overwritten.

Compare with how `unfoldView` (`src/fold/unfold.ts:36`) handles the same scenario — it only sets `tag.attributes = { ...attrs.attributes }` when `attrs.attributes` is truthy, avoiding the allocation when absent.

```ts
// src/fold/unfold.ts:36 — conditional, allocation only when needed
if (attrs.attributes) tag.attributes = { ...attrs.attributes };

// src/fold/hylo.ts:31 — unconditional, always allocates
attributes: {} as Record<string, string>,
```

`linkedTocCoalgebra` (`src/fold/algebras/toc.ts:77-110`) produces tag layers with `attrs` that never include `attributes` — so every `hyloView(linkedTocCoalgebra, ...)` call allocates and immediately discards one `{}` per tag node.

## Why it matters

`hyloView` is promoted as the zero-intermediate-tree path (the `hylo` in "hylomorphism" means no intermediate `View` allocation). The per-node `attributes: {}` allocation contradicts this promise. For a coalgebra that produces 100 tag nodes, this is 100 wasted empty-object allocations compared to what `foldView(alg, unfoldView(coalg, seed))` does when the `EMPTY_ATTRS` sentinel path is hit.

## Rough idea (not a design)

Use a conditional rather than a spread default:

```ts
const attrs: TagAttrs = layer.attrs
  ? { attributes: {}, ...layer.attrs }  // still wastes if layer.attrs has no attributes
  : { attributes: {} };

// Better — only allocate when actually needed:
const rawAttrs = layer.attrs ?? {};
const attrs: TagAttrs = {
  ...rawAttrs,
  attributes: rawAttrs.attributes ?? {},
};
```

Or import and reuse `EMPTY_ATTRS` from `src/core/tag.ts` as the default so the algebra receives the sentinel instead of a fresh object, matching the behavior of the direct render path.
