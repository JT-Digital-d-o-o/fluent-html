# render.ts and stream.ts share ~70 lines of verbatim duplicated HTMX/escape/void-element code, creating silent divergence risk

## Problem

`src/render/stream.ts` opens with a comment explicitly acknowledging the duplication:

```ts
// src/render/stream.ts:14-15
// Reuse the same HTMX serialization helpers from render.ts
// (duplicated here to avoid circular deps and keep streaming self-contained)
```

The following constructs are copy-pasted verbatim across both files:

- `VOID_ELEMENTS` Set — `render.ts:8-12`, `stream.ts:9-12`
- `AttrConfig` type — `render.ts:68-73`, `stream.ts:17-20`
- `str`, `boolOrStr`, `boolVal`, `jsonOrStr`, `json` factory functions — `render.ts:76-103`, `stream.ts:22-45`
- `HTMX_ATTRS` array (20+ entries) — `render.ts:105-126`, `stream.ts:47-54`
- `buildHtmx` function — `render.ts:128-156`, `stream.ts:56-76`
- `buildStatusConfig` function — `render.ts:158-167`, `stream.ts:78-87`
- `SCRIPT_CLOSE_RE` / `STYLE_CLOSE_RE` regexes — `render.ts:169-171`, `stream.ts:89-91`
- `sanitizeRawContent` function — `render.ts:173-182`, `stream.ts:93-102`

The Tag serialization body (`id`/`class`/`style` attrs, `_sk` loop, `EMPTY_ATTRS` guard, `htmx` call, `toggles` join) is structurally identical across `renderImpl` (`render.ts:196-240`) and `streamImpl` (`stream.ts:134-184`), differing only in the output sink (`result +=` vs `stream.push(...)`).

## Evidence

```ts
// render.ts:76-84  (one of five duplicated factory functions)
const str = (key: string): AttrConfig => ({
  key,
  serialize: (v) => ` hx-${key}="${escapeAttr(v)}"`,
});
```

```ts
// stream.ts:22-25  (verbatim copy)
const str = (key: string): AttrConfig => ({
  key,
  serialize: (v) => ` hx-${key}="${escapeAttr(v as string)}"`,
});
```

Note the `v as string` cast in the stream copy — a minor drift that has already occurred. The recon noted HTMX attrs handled in `renderAlgebra` (fold/algebras/render.ts) drift even further: only 3 of 20+ HTMX attrs are handled there (its own comment: _"Add other HTMX attributes as needed"_, `algebras/render.ts:40`). The render/stream duplication is the second instance of this pattern.

## Why it matters

Any new HTMX attribute, escape fix, or void-element addition must be applied in two (or three, counting `renderAlgebra`) places, with no compiler enforcement. The `v as string` drift shows this already happened once silently. As `renderToStream` gains real backpressure semantics (F-D-011), the structural divergence will become harder to maintain.

## Rough idea (not a design)

Extract `src/render/serialize.ts` defining a `Sink` interface (`append(s: string): boolean`) and implementing all shared constants and helpers once. `render.ts` passes a `StringSink` (accumulates into a `string` variable, always returns `true`). `stream.ts` passes a `StreamSink` (calls `stream.push(s)`, returns the boolean for backpressure). `renderImpl` and `streamImpl` collapse into a single `emitImpl(sink, view, ctx)`.
