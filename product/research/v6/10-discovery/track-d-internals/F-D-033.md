# `renderToStream` has no nonce variant — `renderWithNonce` parity gap leaves CSP nonce unapplicable in streaming responses

## Problem

`render()` has a `renderWithNonce(nonce, ...views)` companion that walks the tree and stamps a CSP nonce onto all `<script>` and `<style>` tags before rendering. `renderToStream()` has no equivalent.

```ts
// src/render/render.ts:49-66  — exists, exported
export function renderWithNonce(nonce: string, ...views: View[]): string {
  const view = views.length === 1 ? views[0]! : views;
  applyNonce(view, nonce);
  return renderImpl(view, false);
}

// src/render/stream.ts:111-118 — no nonce variant exists
export function renderToStream(view: View): Readable {
  return new Readable({
    read() {
      streamImpl(this, view, false);
      this.push(null);
    },
  });
}
// renderToStreamWithNonce — does not exist
```

```ts
// src/index.ts:23-24 — the asymmetry in the public export
export { render, renderWithNonce } from './render/index.js';
export { renderToStream } from './render/index.js';
// renderToStreamWithNonce missing
```

## Evidence

`src/render/render.ts:49-66` — `renderWithNonce` is implemented, tested (`test/security.ts:262-285`), and exported. The `applyNonce` helper (`render.ts:55-65`) walks the tree recursively and calls `view.setNonce(nonce)` on all `<script>` and `<style>` tags.

`src/render/stream.ts:111-118` — `renderToStream` accepts exactly one `View` with no nonce parameter.

`src/index.ts:23-24` — `renderWithNonce` is in the public surface; no `renderToStreamWithNonce` is present or exported.

`test/stream.test.ts` (entire file, 368 lines) — no test for nonce + streaming; the gap is invisible in the test suite.

Any Fastify app that uses `renderToStream` for large SSR pages (the performance reason to use streaming) and also enforces a CSP `script-src 'nonce-...'` policy cannot apply the nonce without either (a) abandoning streaming and falling back to `renderWithNonce`, or (b) hand-mutating the view tree before calling `renderToStream` — a fragile workaround.

## Why it matters

CSP nonces are a per-request value (tied to the HTTP response headers). The whole point of `renderWithNonce` is to avoid the caller having to walk the tree manually. Apps that serve pages with inline scripts or styles and that enforce a Content-Security-Policy must choose between streaming and nonce support today. For production SSR apps behind a CDN or a WAF that enforces strict CSP, this is a blocker for adopting `renderToStream`.

The security test file (`test/security.ts:262-285`) carefully verifies nonce injection and escaping for `render()` but the streaming code path has zero coverage for this.

## Rough idea (not a design)

Extract `applyNonce(view, nonce)` from `render.ts` into a shared `src/render/nonce.ts`. Add:

```ts
export function renderToStreamWithNonce(nonce: string, view: View): Readable {
  applyNonce(view, nonce);
  return renderToStream(view);
}
```

Export alongside `renderToStream` from `src/index.ts`. Add a security test covering the streaming nonce path mirroring `test/security.ts:262-285`.
