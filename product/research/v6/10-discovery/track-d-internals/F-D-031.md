# renderAlgebra emits invalid HTML for void elements — `<img></img>`, `<input></input>`

## Problem

`renderAlgebra` (the fold-layer HTML renderer) has no concept of void elements. Every element is rendered with a closing tag regardless of whether it is a void element:

```ts
// src/fold/algebras/render.ts:66-70
tag: (element, attrs, childHtml) => {
  const attrString = buildAttributes(attrs);
  // Note: For raw text elements (script, style), children should not be escaped
  // This simplified version doesn't handle that - use render() for production
  return `<${element}${attrString}>${childHtml}</${element}>`;
},
```

This means `foldView(renderAlgebra, Img().setSrc("/photo.jpg"))` produces `<img src="/photo.jpg"></img>` — invalid HTML. `render()` handles this correctly via its `VOID_ELEMENTS` Set at `render.ts:8-11, 237`.

## Evidence

`src/fold/algebras/render.ts:66-70` — the `tag` case unconditionally emits `<el attrs>childHtml</el>` with no check for void element names.

`test/fold.ts:246-265` — the round-trip test suite that compares `foldView(renderAlgebra, view)` with `render(view)` only tests non-void elements: `Div`, `P`, `H1`, `Ul`, `Li`, `A`, `Span`. It never exercises `Img`, `Input`, `Br`, `Hr`, `Meta`, `Link`, `Source`, `Col`, `Track`, `Wbr`. Adding any one of these to the test suite would immediately fail.

```ts
// Would fail today — not in the test suite:
foldView(renderAlgebra, Img().setSrc("/x.png"))
// → "<img src="/x.png"></img>"   ← invalid HTML
// render(Img().setSrc("/x.png"))
// → "<img src="/x.png">"         ← correct
```

## Why it matters

`renderAlgebra` is an exported public API (re-exported via `src/index.ts`). Any consumer who uses `hyloView(coalg, renderAlgebra, seed)` or `foldView(renderAlgebra, view)` with a tree containing void elements silently gets malformed HTML. Browsers may tolerate it, but: (a) validators and linters will flag it, (b) `<img></img>` inside an HTMX partial swap can confuse the morphdom/idiomorph differ, (c) the self-described purpose of `renderAlgebra` ("alternative HTML renderer using the fold pattern") is broken for ~12 of the element types the library exports.

The comment at line 69 acknowledges one limitation (`script`/`style` not handled) but misses the void-element bug entirely.

## Rough idea (not a design)

Extract the `VOID_ELEMENTS` constant from `render.ts` to a shared `src/render/constants.ts` (alongside the `HTMX_ATTRS` table), import it in `algebras/render.ts`, and add a guard in the `tag` callback:

```ts
if (VOID_ELEMENTS.has(element)) return `<${element}${attrString}>`;
return `<${element}${attrString}>${childHtml}</${element}>`;
```

Then add `Img`, `Input`, `Br`, `Hr`, `Meta`, `Link` to the fold round-trip test matrix.
