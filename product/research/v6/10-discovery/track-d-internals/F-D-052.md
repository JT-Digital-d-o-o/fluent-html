# `extraAttrs` render path calls `String(value)` on already-`string` typed values

## Problem

The `extraAttrs` branch in both `renderImpl` (render.ts) and `streamImpl` (stream.ts) wraps the attribute value in a `String()` call before passing to `escapeAttr`:

```ts
// src/render/render.ts:218-227
const extraAttrs = tag.attributes;
if (extraAttrs !== EMPTY_ATTRS) {
  const extraKeys = Object.keys(extraAttrs);
  for (let i = 0; i < extraKeys.length; i++) {
    const key = extraKeys[i]!;
    const value = extraAttrs[key];
    if (value !== undefined && value !== null) {
      attrs += ' ' + key + '="' + escapeAttr(String(value)) + '"'; // ← String() is redundant
    }
  }
}
```

```ts
// src/render/stream.ts:156-164 (verbatim copy)
const extraAttrs = tag.attributes;
if (extraAttrs !== EMPTY_ATTRS) {
  const extraKeys = Object.keys(extraAttrs);
  for (let i = 0; i < extraKeys.length; i++) {
    const key = extraKeys[i]!;
    const value = extraAttrs[key];
    if (value !== undefined && value !== null) {
      attrs += ' ' + key + '="' + escapeAttr(String(value)) + '"'; // ← String() is redundant
    }
  }
}
```

`tag.attributes` is declared as `Record<string, string>` (tag.ts:50), and `addAttribute` (tag.ts:141) only accepts `string` values. The `String()` call at runtime is therefore a guaranteed no-op — it receives a `string` and returns the same `string` object — yet it is invoked on every custom attribute of every tag that has one.

## Evidence

Tag type declaration:
```ts
// src/core/tag.ts:50
declare attributes: Record<string, string>;
```

`addAttribute` enforces the `string` constraint at the call site:
```ts
// src/core/tag.ts:141-148
addAttribute(key: string, value: string): this {
  validateAttributeKey(key);
  if (this.attributes === EMPTY_ATTRS) {
    this.attributes = Object.create(null) as Record<string, string>;
  }
  this.attributes[key] = value;
  return this;
}
```

The `value !== undefined && value !== null` guard above the `String()` call is also redundant against the `Record<string, string>` contract (a string value can never be `undefined` or `null` at that point), though that guard is not harmful beyond a negligible branch check.

## Why it matters

The `String()` function call is not free: even though V8 can inline it, the call-site indirection, type check, and object identity comparison still add instructions on the hot path. Every tag that uses `addAttribute`, `setNonce`, `setDataAttrs`, or `setAria` goes through the `extraAttrs !== EMPTY_ATTRS` branch and hits `String(value)` once per key. For a form with 10 inputs using `data-*` attributes, that is 10 redundant `String()` calls per render. Across a large page with 50 custom-attributed elements, that is 50 wasted calls per request.

The fix is a one-character change in each file: `escapeAttr(String(value))` → `escapeAttr(value)`. Both instances must be fixed simultaneously (they are verbatim copies; covered by the shared-emitter RFC).

## Rough idea (not a design)

At `render.ts:225` and `stream.ts:163`, drop the `String()` wrapper:

```ts
// Before
attrs += ' ' + key + '="' + escapeAttr(String(value)) + '"';

// After
attrs += ' ' + key + '="' + escapeAttr(value) + '"';
```

This is a zero-risk, zero-behavior-change cleanup — the types already prove `value` is `string`. If the shared-emitter refactor (F-D-012) ships first, the fix applies once in `serialize.ts` instead of two places.
