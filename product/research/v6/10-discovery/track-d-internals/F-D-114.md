# unfoldView bypasses EMPTY_ATTRS sentinel when coalgebra supplies attributes:{} — allocates a fresh empty object per tag node

## Problem

`render.ts` uses an identity check against the shared `EMPTY_ATTRS` frozen singleton to skip the custom-attribute serialization loop for tags that have no custom attributes (`extraAttrs !== EMPTY_ATTRS` at line 219). This sentinel is set on `Tag.prototype.attributes = EMPTY_ATTRS` so that tags created by element factories start with zero allocation.

`unfoldView` breaks this invariant: when a coalgebra layer carries `attrs: { attributes: {} }` (an empty map), line 36 unconditionally does `tag.attributes = { ...attrs.attributes }` — creating a fresh empty `{}`. The resulting Tag passes `extraAttrs !== EMPTY_ATTRS` in the renderer, causing a redundant `Object.keys(extraAttrs)` call that returns nothing and does no work, but still pays for the key-list allocation.

## Evidence

```ts
// src/core/tag.ts:8
export const EMPTY_ATTRS: Record<string, string> = Object.freeze(Object.create(null)) as Record<string, string>;
// ...
Tag.prototype.attributes = EMPTY_ATTRS;  // shared sentinel — no per-instance allocation
```

```ts
// src/render/render.ts:219
const extraAttrs = tag.attributes;
if (extraAttrs !== EMPTY_ATTRS) {       // ← identity check; fails for any {} created by unfoldView
  const extraKeys = Object.keys(extraAttrs);
  for (let i = 0; i < extraKeys.length; i++) { /* empty loop for {} */ }
}
```

```ts
// src/fold/unfold.ts:36  — the problem
if (attrs.attributes) tag.attributes = { ...attrs.attributes };
//                          ↑ truthy for {}, null, undefined, or a populated map
//                    allocates new {} when attributes is {} — sentinel is lost
```

The `hyloView` function performs the same bypass at `hylo.ts:32`: `attributes: {} as Record<string, string>, ...layer.attrs` always starts with a fresh `{}`, then spreads `layer.attrs` over it. If `layer.attrs.attributes` is absent, the `{}` remains and is passed to `alg.tag()` where any algebra that reconstructs Tags will also lose the sentinel.

## Why it matters

Every coalgebra that uses `attrs: { attributes: {} }` or omits `attributes` from its layer (causing `hyloView`'s default `{}` to propagate) incurs a spurious object allocation per tag node and an `Object.keys` call on an empty map during render. For a page with N nodes constructed via `unfoldView`, this is N wasted allocations paid at construction time and N redundant `Object.keys` calls at render time. The impact is bounded to fold-based rendering pipelines but hits any code that uses the algebra-layer APIs (e.g. TOC generation, custom tree transformations).

## Rough idea (not a design)

In `unfoldView`, add a length check before spreading:
```ts
if (attrs.attributes && Object.keys(attrs.attributes).length > 0) {
  tag.attributes = { ...attrs.attributes };
}
// Otherwise tag.attributes stays as EMPTY_ATTRS from the prototype
```
In `hyloView`, default to `EMPTY_ATTRS` rather than `{}`:
```ts
import { EMPTY_ATTRS } from "../core/tag.js";
const attrs = { attributes: EMPTY_ATTRS, ...layer.attrs };
```
