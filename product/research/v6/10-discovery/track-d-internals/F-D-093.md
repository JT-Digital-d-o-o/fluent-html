# Non-string `_sk` values call `escapeAttr(String(value))` unnecessarily

## Problem

The `_sk` (schema-key) render loop in `renderImpl` and `streamImpl` applies `escapeAttr` to every value, including those from typed setters that accept only `number` or `boolean`:

```ts
// src/render/render.ts:208-215
const sk = tag._sk;
if (sk !== undefined) {
  for (let i = 0; i < sk.length; i++) {
    const value = (tag as unknown as Record<string, unknown>)[sk[i]!];
    if (value !== undefined && value !== null) {
      attrs += ' ' + sk[i]! + '="' + escapeAttr(typeof value === 'string' ? value : String(value)) + '"';
    }                                     // ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  }                                       // escapeAttr runs on EVERY value, including numbers and booleans
}
```

The same pattern appears in `streamImpl`:

```ts
// src/render/stream.ts:146-154
const sk = tag._sk;
if (sk !== undefined) {
  for (let i = 0; i < sk.length; i++) {
    const value = (tag as unknown as Record<string, unknown>)[sk[i]!];
    if (value !== undefined && value !== null) {
      attrs += ' ' + sk[i]! + '="' + escapeAttr(typeof value === 'string' ? value : String(value)) + '"';
    }
  }
}
```

Many `_sk` keys are typed as `number` or `boolean` in their setter methods, meaning the value stored on the Tag instance can only be a number or boolean — never a string containing `&`, `<`, `>`, `"`, or `'`:

```ts
// src/elements/tables.ts:30-35, 58-63 — colspan/rowspan are numbers
setColspan(colspan: number): this { this.colspan = colspan; return this; }
setRowspan(rowspan: number): this { this.rowspan = rowspan; return this; }
// _sk = ['colspan', 'rowspan']  (src/elements/tables.ts:48, 71)

// src/elements/data.ts:43-56 — ProgressTag value/max are numbers
setValue(value?: number): this { this.value = value; return this; }
setMax(max?: number):     this { this.max   = max;   return this; }
// _sk = ['value', 'max']  (src/elements/data.ts:56)

// src/elements/data.ts:70-103 — MeterTag value/min/max/low/high/optimum are all numbers
// _sk = ['value', 'min', 'max', 'low', 'high', 'optimum']  (data.ts:103)
```

For these keys, `escapeAttr` runs the full charCode-scan escape loop (escape.ts) on a string like `"2"` or `"100"` that provably contains no special characters.

## Why it matters

The impact is small per-node but systemic: every `Th`/`Td` with a colspan, every `<progress>`/`<meter>` with a value, every `<svg>` shape with numeric `width`/`height`/`cx`/`cy`/`r` pays the escape cost unnecessarily. On a large data table with 50 rows × 5 columns with `colspan`/`rowspan`, that is 500 wasted `escapeAttr` calls per render. The recon document (04-performance.md §3 item #7) identified this as a "quick win": "Avoid double-escape on never-unsafe attribute values."

This is distinct from F-D-051 (which covers `escapeAttr` being aliased to `escapeHtml`, an over-broad escape for attributes). F-D-093 is specifically about the type-level knowledge that certain `_sk` fields can only ever hold numbers/booleans.

## Rough idea (not a design)

In the `_sk` loop, change the condition to skip `escapeAttr` for non-string values:

```ts
// Before
attrs += ' ' + sk[i]! + '="' + escapeAttr(typeof value === 'string' ? value : String(value)) + '"';

// After
attrs += ' ' + sk[i]! + '="' + (typeof value === 'string' ? escapeAttr(value) : String(value)) + '"';
```

No API change, no behavioral change for string-valued `_sk` keys. Must be mirrored in `streamImpl`. A comment noting the invariant would document the intentional omission: `// Non-string _sk values (number/boolean) are safe to emit without escaping`.
