# `_variantPrefix: string | null = null` is an instance field, bloating every Tag's hidden class

## Problem

`Tag` declares `_variantPrefix` as a class field with an initializer:

```ts
// src/core/tag.ts:309
_variantPrefix: string | null = null;
```

A TypeScript class field with an initializer (`= null`) is compiled as an instance assignment in the constructor — so every `new Tag(...)` call writes `this._variantPrefix = null`, creating a property on the instance object. This means every Tag instance carries this field in its property map, even though the overwhelming majority of Tags never call `.on()` or `.at()`.

The consequence is twofold:

1. **Hidden-class polymorphism.** V8 tracks object shapes via "hidden classes" (maps). When `.on()/.at()` temporarily writes a non-null string to `_variantPrefix` (via `withVariant`) and then restores `null`, V8 must deal with a string→null transition on the instance. Meanwhile, Tags that never call `.on()/.at()` have `_variantPrefix = null` as an own property — same shape but with its own slot in the object. Contrast with how `_t` is set: `(Tag.prototype as any)._t = 1` — it lives on the prototype, not the instance, which is exactly right.

2. **Per-instance allocation cost.** The field contributes to the per-Tag object size, aggravating the measured construction allocation of ~14.5 KB per 1000 divs.

## Evidence

```ts
// src/core/tag.ts:309
/** @internal Variant prefix state — used by tailwind-methods mixin */
_variantPrefix: string | null = null;
```

Compare with the correct approach used for `_t` and `attributes`:

```ts
// src/core/tag.ts:312-315
/** @internal */
// eslint-disable-next-line @typescript-eslint/no-explicit-any -- intentional prototype manipulation
(Tag.prototype as any)._t = 1;
Tag.prototype.attributes = EMPTY_ATTRS;
```

`attributes` defaults to `EMPTY_ATTRS` on the *prototype*, only becoming an instance property when `addAttribute()` is first called (`tag.ts:144`). The same pattern should apply to `_variantPrefix`: it should default on the prototype to `null` and only be written as an instance property when a variant scope is entered. The `withVariant` function in `tailwind-methods.ts:86-91` already does save/restore:

```ts
// src/core/tailwind-methods.ts:86-91
function withVariant(tag: Tag, prefix: string, fn: (tag: Tag) => Tag): Tag {
  const outer = tag._variantPrefix;
  tag._variantPrefix = outer ? `${outer}:${prefix}` : prefix;
  fn(tag);
  tag._variantPrefix = outer;   // restores to null for tags that had no prior prefix
  return tag;
}
```

After the restore, `_variantPrefix` is `null` again — but now as an *own property* (null), not the prototype default. The cleanup could instead delete the own property to restore the prototype shape.

Bench evidence: `bench/render.ts:231` measures flat-page *construction* of 1000 divs at ~14.5 KB heap per 100 iterations. Reducing per-Tag object size would reduce this directly; every Tag in the flat-page benchmark builds with `_variantPrefix = null` allocated for nothing.

## Why it matters

Construction allocation is paid on every SSR request because the tree is rebuilt each time. At 1000 nodes per realistic page, eliminating one unnecessary own-property slot across all Tags compounds across every request. This directly addresses the measured 14.5 KB/1000-node construction cost.

## Rough idea (not a design)

1. Remove the `= null` initializer so `_variantPrefix` is `undefined` as an instance field declaration only (no JS-level assignment).
2. Add `(Tag.prototype as any)._variantPrefix = null;` after the class definition (like `_t`) so the prototype carries the default.
3. In `withVariant` restore, use `delete tag._variantPrefix` instead of `tag._variantPrefix = outer` when `outer === null` — this restores the prototype default without leaving an own-property.
4. Benchmark before/after with `bench:mem` to confirm hidden-class benefit.
