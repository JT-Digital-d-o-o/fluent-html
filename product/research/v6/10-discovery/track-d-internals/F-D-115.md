# behavior("toggleClass") interpolates user-supplied class string into JS without escapeJs — inconsistent with clipboard, potential JS injection

## Problem

The `behavior-methods.ts` module includes an `escapeJs` helper that escapes `\` and `'` for safe embedding in single-quoted JS string literals. The `clipboard` behavior correctly applies it to the user-supplied value. The `toggleClass` behavior does NOT — it interpolates `opts.class` raw into the JS string. This is an inconsistency that violates the library's escape-by-default principle and is a latent JS injection vector.

## Evidence

```ts
// src/core/behavior-methods.ts:59-62 — clipboard: CORRECTLY escaped
clipboard: (opts) => [
  "click",
  `navigator.clipboard.writeText('${escapeJs(String(opts.value))}')`,  // ✓ escaped
],

// src/core/behavior-methods.ts:51-54 — toggleClass: NOT escaped
toggleClass: (opts) => [
  "click",
  `${el(opts.target)}.classList.toggle('${String(opts.class)}')`,      // ✗ raw
],
```

The escape function that already exists but was omitted:
```ts
// src/core/behavior-methods.ts:85-87
function escapeJs(str: string): string {
  return str.replace(/\\/g, "\\\\").replace(/'/g, "\\'");
}
```

A class string with a single quote — e.g., if someone passes `class: "it's-active"` (valid CSS, unusual but legal) or any class name interpolated from user data — produces broken JS:

```ts
// rendered hx-on:click value with class="it's-active":
document.getElementById('panel').classList.toggle('it's-active')
//                                                    ^ breaks JS parsing
```

The same gap exists in `el()`, which interpolates `resolveId(value)` (a raw string) unescaped into `document.getElementById('${...}')`. In practice IDs from `defineIds` are always kebab-case (safe), but the implementation casts away the type system at runtime (line 91: `options: Record<string, unknown>`), so a bad actor calling `.behavior()` through JS would bypass the typed interface.

## Why it matters

The `clipboard` behavior was written correctly with `escapeJs`; `toggleClass` was evidently written without it. This inconsistency creates a false sense of safety — a developer reading `clipboard` might assume all behaviors escape their string values. The fix is one-line and zero-risk. The escape function already exists in the file.

## Rough idea (not a design)

```ts
// Fix: apply escapeJs to opts.class
toggleClass: (opts) => [
  "click",
  `${el(opts.target)}.classList.toggle('${escapeJs(String(opts.class))}')`,
],
```

For defense-in-depth, also apply it in `el()`:
```ts
function el(value: unknown): string {
  return `document.getElementById('${escapeJs(resolveId(value))}')`;
}
```

Add a test: `behavior("toggleClass", { target: ids.panel, class: "a'b" })` should produce `classList.toggle('a\\'b')` without breaking.
