# .when() JSDoc example calls .children() which does not exist

## Problem

The JSDoc for `Tag.when()` (`core/tag.ts:195`) contains an example that calls `.children()` — a method that does not exist on `Tag`:

```ts
// fluent-html/src/core/tag.ts:195 (JSDoc for when())
.when(user.avatar, (t, avatar) => t.children(Img().setSrc(avatar)))
```

There is no `children` method on `Tag`. The `child` field is set once in the constructor (`tag.ts:61`) and is never exposed as a public setter. Any developer who follows this example will get a TypeScript error at `t.children(…)` — and since the JSDoc is the primary in-IDE documentation, the example actively misleads at the point of use.

This is related to the seed-backlog finding "`.children()` documented but does not exist" (from recon/01-architecture.md), but the when() JSDoc is an independent, separate occurrence — the JSDoc for the method itself, not just external docs.

## Evidence

```ts
// fluent-html/src/core/tag.ts:192-196
/**
 * Conditionally modify this tag…
 * @example
 * Button("Save")
 *   .when(isLoading, t => t.toggle("disabled").opacity(50))
 *   .when(isPrimary, t => t.background("blue-500").textColor("white"))
 *   .when(user.avatar, (t, avatar) => t.children(Img().setSrc(avatar)))  // ← broken
 */
```

The nullable-narrowing form of `.when()` correctly passes the non-null value as a second argument (line 197), but the example shows a method that doesn't exist. The only way to conditionally add children in the current API is to use `IfThen` at the call site or to pass them at construction time.

## Why it matters

JSDoc is the primary in-editor documentation. Any LLM or developer reading the signature of `.when()` in their IDE will see this example and attempt to use `.children()`, getting a silent type error or runtime failure. This is a correctness bug in documentation that directly undermines trust in the `when(nullable, fn)` overload — which is itself a genuinely useful API.

## Rough idea (not a design)

Fix the JSDoc example to use a real pattern. Two options:
1. Remove the nullable-narrowing example if there is no first-class "set children after construction" API, and only show the boolean form.
2. If `.children()` is to be implemented (per seed backlog), make the example conditional on that work.

Minimal fix:
```ts
// Replace:
.when(user.avatar, (t, avatar) => t.children(Img().setSrc(avatar)))  // broken

// With (no .children() — use a different real-world example):
.when(user.isAdmin, t => t.background("red-50").textColor("red-700"))
// nullable narrowing:
.when(user.avatar, (t, avatar) => t.addAttribute("data-has-avatar", avatar))
```

## Related findings

The seed backlog "`.children()` is documented but does not exist" covers the broader API design question. This finding is narrower: fix the specific `.when()` JSDoc example independently of whether `.children()` is ever implemented.
