# `InputTag` missing `inputmode` setter — forces `addAttribute('inputmode', 'tel')` for mobile keyboard UX

## Problem

`inputmode` is a standard global HTML attribute (supported on `<input>`, `<textarea>`, and any contenteditable) that controls the virtual keyboard type on mobile devices. It is not in `InputTag._sk` nor in `TextareaTag._sk`, so setting it requires falling back to the escape hatch:

```ts
// rideshare/src/shared/components/phone-input.view.ts:96
Input("tel")
  .setName("phone")
  .addAttribute("inputmode", "tel")   // ✗ forced escape hatch
```

The current `_sk` for `InputTag` has 19 fields but omits `inputmode`:

```ts
// fluent-html/src/elements/forms.ts:125
(InputTag.prototype as any)._sk = [
  'type', 'name', 'placeholder', 'value', 'accept', 'min', 'max', 'step',
  'pattern', 'minlength', 'maxlength', 'autocomplete', 'autofocus', 'checked',
  'disabled', 'readonly', 'multiple', 'list',
  // ← no 'inputmode'
];
```

## Evidence

```ts
// rideshare/src/shared/components/phone-input.view.ts:96
Input("tel")
  // ... other setters
  .addAttribute("inputmode", "tel")
```

A grep for `"inputmode"` across `fluent-html/src/elements/` returns zero results, confirming the omission is complete, not partial.

The valid values — `'none' | 'text' | 'decimal' | 'numeric' | 'tel' | 'search' | 'email' | 'url'` — are a closed, well-known set defined in the HTML spec and could be a typed union.

## Why it matters

Mobile-first apps rely on `inputmode` to avoid forcing the QWERTY keyboard on numeric fields. Without a fluent setter, every numeric input (phone, OTP, PIN, price, quantity) that should show the numeric keyboard requires `addAttribute` — an escape hatch reserved for non-standard attributes per the library's philosophy. Frequency: any field with a phone/postal/numeric keyboard need hits this gap. The rideshare app hits it; ttl and any future apps will hit it too.

## Rough idea (not a design)

Add to `html-types.ts`:
```ts
export type InputMode = 'none' | 'text' | 'decimal' | 'numeric' | 'tel' | 'search' | 'email' | 'url';
```
Add `inputmode?: InputMode` field + `setInputmode(mode?: InputMode): this` to both `InputTag` and `TextareaTag` (it is a global attribute that also applies to `contenteditable` but those are not modeled as typed elements). Add `'inputmode'` to both `_sk` arrays.
