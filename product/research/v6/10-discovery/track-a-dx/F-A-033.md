# renderbox reimplements createContext from scratch — adoption-gap for typed-value contexts

## Problem

`renderbox` defines a page-accent theme context by reimplementing the `createContext` API manually instead of using the library's `createContext<T>()`:

```ts
// renderbox/src/app/landing/views/landing.components.ts:27-34
export type PageAccent = "indigo" | "amber" | "emerald" | "slate" | "violet";

const accentStack: PageAccent[] = ["indigo"];
export const pageAccentCtx = {
  get current(): PageAccent { return accentStack[accentStack.length - 1]!; },
  scope(value: PageAccent): Disposable {
    accentStack.push(value);
    return { [Symbol.dispose]() { accentStack.pop(); } };
  },
};
```

This is a **verbatim reimplementation** of `createContext<PageAccent>("indigo")`. It differs only in the explicit type constraint on `PageAccent` — which `createContext<PageAccent>()` would provide automatically.

## Evidence

The `pageAccentCtx` is used in at least **16 view files** in renderbox:

```ts
// renderbox/src/app/landing/home/home.view.ts:700
using _ = pageAccentCtx.scope("indigo");

// renderbox/src/app/landing/video/video.view.ts:296
using _ = pageAccentCtx.scope("amber");

// renderbox/src/app/landing/agents/agents.view.ts:235
using _ = pageAccentCtx.scope("violet");
```

The `accentColor()` helper function reads `pageAccentCtx.current` directly:

```ts
// renderbox/src/app/landing/views/landing.components.ts:37
function accentColor(shade: string): string {
  const a = pageAccentCtx.current;
  ...
}
```

## Why it matters

The author clearly knows about the `using` keyword and the Disposable protocol — they use it correctly. What they didn't know was that `createContext<PageAccent>("indigo")` would give them exactly the same API with type-safety built in. The reimplementation is harmless but:

1. It skips the library's Symbol.dispose polyfill (breaking for ES2020 targets without polyfill).
2. It introduces an independent stack (instead of one managed by the library) that can't be tested with library test utilities.
3. It encourages copy-paste of the pattern into more files.

## Guideline gap

`guidelines/web-development/fluent-html.md` § Scoped Context shows only generic `createContext<"light" | "dark">("light")` but never demonstrates a **typed value with a literal union** in a component-theming scenario. A consumer authoring a theme context with `"indigo" | "amber" | ...` sees the generic example and may not realize it already covers their case. Adding a one-line example with a theme/accent type would close this gap.

## Rough idea (not a design)

Guideline fix only — no code change. Add to the Scoped Context section of `fluent-html.md`:

```ts
// Typed value context — string literal union, enum, or object
const AccentCtx = createContext<"indigo" | "amber" | "violet">("indigo");
const ThemeCtx = createContext<{ bg: string; text: string }>({ bg: "white", text: "gray-900" });
```
