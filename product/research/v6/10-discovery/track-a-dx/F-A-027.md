# No .whenElse() — paired .when(isActive,…)+.when(!isActive,…) appears 91+ times

## Problem

`Tag.when(cond, fn)` applies a modifier when `cond` is true; to also apply a different modifier when false, apps chain two calls with complementary conditions: `.when(isActive, fn1).when(!isActive, fn2)`. There is no two-branch form. This pattern occurs in at least 91 confirmed pairs across 9+ apps — every active/inactive, selected/unselected, open/closed state produces one.

## Evidence

`rideshare/src/rides/views/browse.view.ts:131-132` — active tab styling:

```ts
Button(tab.name)
  .when(selectedEventId === event.id, t =>
    t.background("forest").textColor("white").borderColor("forest"))
  .when(selectedEventId !== event.id, t =>
    t.background("white").textColor("body").borderColor("site-border")
     .on("hover", t => t.borderColor("leaf").textColor("moss")))
```

`ttl/src/analytics/analytics.view.ts:59-60`:

```ts
.when(isActive, t => t.background("accent").textColor("slate-950"))
.when(!isActive, t => t.background("slate-800").textColor("slate-400")
  .border().borderColor("slate-700")
  .on("hover", h => h.background("slate-700")).transition("colors"))
```

`glimm/src/analytics/views/dashboard.view.ts:97-98`, `jt-cut/src/home/views/home.hero.view.ts:570-571`, `jt-draw`, `jt-i18n`, `renderbox` — same pattern, copied across every app that has active/inactive tab or selected/unselected item UI.

The two-call form: (1) evaluates `condition` twice (harmless for simple booleans, but bad practice for computed values); (2) is verbose — the active and inactive styles are semantically one decision but read as two; (3) offers no way to use nullable narrowing in the two-branch case.

## Why it matters

91+ confirmed paired `.when(!x)` calls across 9+ apps. Every app that has any toggle-able visual state generates this pattern independently. A `whenElse` method is the natural "if–then–else" counterpart to `when`'s "if–then".

## Rough idea (not a design)

Add `Tag.whenElse(condition, thenFn, elseFn)`:

```ts
whenElse(condition: boolean, thenFn: (tag: this) => this, elseFn: (tag: this) => this): this;
```

Usage:

```ts
// ✓ single intent, single evaluation
Button(tab.name).whenElse(isActive,
  t => t.background("forest").textColor("white"),
  t => t.background("white").on("hover", t => t.background("gray-50"))
)

// ✗ current: two calls, conditions must be manually kept complementary
Button(tab.name)
  .when(isActive, t => t.background("forest").textColor("white"))
  .when(!isActive, t => t.background("white").on("hover", t => t.background("gray-50")))
```

Implementation is trivial — one line: `return condition ? thenFn(this) : elseFn(this)`. The method also naturally pairs with the nullable-narrowing story (the `thenFn` could receive the non-null value as second arg, parallel to `when(nullable, (t, value) => …)`).
