# No test helper for context scoping across beforeEach/afterEach — 6 test files reinvent manual disposal boilerplate

## Problem

The `using` keyword is syntactic sugar for a lexical block: `using _ = ctx.scope(value)` automatically disposes at the end of the enclosing block. But test suites need the scope to last across `beforeEach`/`afterEach` callbacks — spanning multiple function invocations that `using` can't bridge. Apps must resort to three different workarounds:

**Workaround 1 — Disposable? variable + afterEach:**
```ts
// planet-positive-sport/tests/view/loc.category.objectives.view.test.ts:15-22
let disposeScope: Disposable | null = null;
beforeEach(() => {
  disposeScope = provideAssessmentScope({ mode: "loc" });
});
afterEach(() => {
  disposeScope?.[Symbol.dispose]();
  disposeScope = null;
});
```

**Workaround 2 — Disposable[] accumulator:**
```ts
// planet-positive-sport/tests/view/setup.ts:10-18
let disposables: Disposable[] = [];
beforeEach(() => {
  disposables = [
    i18nTranslation.scope(tFn),
    i18nLocale.scope("en"),
    provideAssessmentScope({ mode: "loc" }),
    provideCanWrite(true),
  ];
});
afterEach(() => {
  for (const d of disposables) d[Symbol.dispose]();
  disposables = [];
});
```

**Workaround 3 — Vitest teardown return value:**
```ts
// planet-positive-sport/tests/view/loc.assessment.components.test.ts:19-21
function withLocScope() {
  const scope = provideAssessmentScope({ mode: "loc" });
  return () => scope[Symbol.dispose]();  // Vitest calls this as teardown
}
// ...
beforeEach(withLocScope);  // non-obvious Vitest API
```

## Evidence

6 test files in planet-positive-sport use one of these three workarounds:
- `tests/view/loc.category.objectives.view.test.ts:15-22` — Workaround 1
- `tests/view/loc.event-overview.view.test.ts` — Workaround 1
- `tests/view/settings.view.test.ts` — Workaround 1 (inlined)
- `tests/view/setup.ts:10-18` — Workaround 2 (shared setup)
- `tests/view/loc.assessment.components.test.ts:19-21` — Workaround 3
- `tests/unit/views/build-category-tabs.test.ts:31` — afterEach(`() => scope[Symbol.dispose]()`)

Additionally, `try/finally` is used for per-test scope isolation in:
```ts
// planet-positive-sport/tests/view/loc.assessment.components.test.ts:443-456
function renderUnderScope(mode: "loc" | "admin", category: CategoryWithProgress) {
  const dispose = mode === "loc"
    ? provideAssessmentScope({ mode: "loc" })
    : provideAssessmentScope({ mode: "admin", federationId: "fed-1" });
  try {
    return render(SectionTabs({ ... }));
  } finally {
    dispose[Symbol.dispose]();
  }
}
```

## Why it matters

Every new test file that needs a context-scoped environment must decide which workaround to use. Workaround 1 risks forgetting to reset `disposeScope = null`, which gives false safety (the `?` prevents the crash but may leave stale context). Workaround 2 risks disposal in wrong order. Workaround 3 relies on an obscure Vitest API. Leaking a context scope between tests causes flaky order-dependent test failures.

The library has no test utilities at all (no `src/testing.ts`, no exported test helper). Adding a minimal `withScope(ctx, value)` factory that returns `{ setup, teardown }` (or a Vitest-compatible `beforeEach`/`afterEach` registrar) would reduce each of these 6 files by ~8 lines and standardize the pattern.

## Rough idea (not a design)

Export a lightweight `withContext(ctx: Context<T>, value: T)` helper from a `fluent-html/testing` subpath:

```ts
// Usage in test files
import { withContext } from "fluent-html/testing";

const cleanup = withContext(AuthCtx, { name: "Alice" });
beforeEach(cleanup.setup);
afterEach(cleanup.teardown);
```

Or integrate with `DisposableGroup` (see F-A-036) to allow:

```ts
beforeEach(() => scopeAll([
  AuthCtx.scope(mockUser),
  LocaleCtx.scope("en"),
]));
```

where `scopeAll` returns a single Disposable, and Vitest's `afterEach` receives it via the Vitest teardown mechanism.
