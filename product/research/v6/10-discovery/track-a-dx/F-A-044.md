# `LinkTag.setCrossorigin()` typed as `'anonymous'|'use-credentials'` — can't emit bare `crossorigin` attribute required by Google Fonts preconnect, forcing 8 apps to `addAttribute`

## Problem

`LinkTag.setCrossorigin()` is typed as:
```ts
// fluent-html/src/elements/document.ts:87,116
crossorigin?: 'anonymous' | 'use-credentials';

setCrossorigin(crossorigin?: 'anonymous' | 'use-credentials'): this {
  this.crossorigin = crossorigin;
  return this;
}
```

Google Fonts preconnect links (and some CDN crossorigin hints) require the attribute with an **empty string value** or bare (`crossorigin` with no value), because when `crossorigin=""` is absent entirely, the browser uses the no-CORS fetch mode and the preconnect handshake doesn't match the subsequent CORS fetch — causing a wasted preconnection.

`''` (empty string) is not in the union, so `.setCrossorigin("")` is a TypeScript error. Apps fall back to `.addAttribute("crossorigin", "")`:

```ts
// jtdigital-landing-page/src/shared/layout.ts:88
Link()
  .setRel("preconnect")
  .setHref("https://fonts.gstatic.com")
  .addAttribute("crossorigin", "")   // ← TypeScript forced this because setCrossorigin("") is a type error
```

## Evidence

```ts
// pravila.si.v2/src/views/layout.ts:40
Link().setRel("preconnect").setHref("https://fonts.gstatic.com")
  .addAttribute('crossorigin', '')

// tela/src/views/shared.ts:51
Link().setRel("preconnect").setHref(url).addAttribute("crossorigin", "")

// movies/src/views/components.ts:68
Link().setRel('preconnect').setHref('https://fonts.gstatic.com').addAttribute('crossorigin', '')

// vabilo30/src/shared/components/invitation-layout.view.ts:97
Link()...addAttribute("crossorigin", "")

// idea-hub/src/shared/components/layout.view.ts:44
Link()...addAttribute("crossorigin", "")

// gym-crm/src/scenes/core/ui.ts:76
Link()...addAttribute("crossorigin", "")
```

8 apps independently hit the same escape hatch for the same Google Fonts pattern. The same issue applies to `ScriptTag.setCrossorigin()` which has the same `'anonymous' | 'use-credentials'` union (document.ts:200,224).

## Why it matters

`crossorigin=""` is the W3C-valid form equivalent to `crossorigin="anonymous"` (per the HTML spec, an invalid or empty value falls back to `"anonymous"`). The type union is overly strict — the spec allows `""`. The result is that 8+ apps use `addAttribute` for a perfectly standard scenario, violating the guideline "never `addAttribute` for standard HTML props."

## Rough idea (not a design)

Extend the union to `'anonymous' | 'use-credentials' | ''` on both `LinkTag` and `ScriptTag`. The empty string serializes as `crossorigin=""` which is correct HTML. Alternatively, add `toggle("crossorigin")` guidance to the docs as the canonical bare-attribute form (no quotes). The fix is small: one type change in `document.ts:87` and `document.ts:200`.
