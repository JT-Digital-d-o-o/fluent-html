# Global HTML attributes `tabindex`, `title`, and `role` have no typed setters on `Tag` — 16+ `addAttribute` call-sites across 3 apps

## Problem

`tabindex`, `title`, and `role` are universal HTML attributes valid on every element. None have typed setters on `Tag`. Apps consistently fall back to `addAttribute`, the escape hatch intended for non-standard or rarely-used attributes:

```ts
// rideshare/src/shared/components/autocomplete.view.ts:124
Div(/* ... */)
  .addAttribute("tabindex", "-1")                        // ✗ forced escape hatch

// rideshare/src/shared/components/tooltip.view.ts:73
Span("?")
  .addAttribute("tabindex", "0")                         // ✗

// rideshare/src/shared/components/layout.view.ts:463
Div(nav)
  .addAttribute("role", "dialog")                        // ✗
  .addAttribute("aria-modal", "true")                    // ✗ (setAria exists but not used)
  .addAttribute("aria-label", "Navigation menu")         // ✗

// rideshare/src/rides/rides.components.ts:231
A(Icon).setHref("#")
  .addAttribute("title", "Copy link")                    // ✗
  .addAttribute("aria-label", "Copy ride link")          // ✗
```

The grep count across three apps (rideshare, ttl, jt-draw):
- `addAttribute("tabindex", ...)` — 4 call-sites
- `addAttribute("role", ...)` — 8 call-sites
- `addAttribute("title", ...)` — 4 call-sites

Total: 16 call-sites, all avoidable with typed setters.

## Evidence

```ts
// fluent-html/src/core/tag.ts:141
addAttribute(key: string, value: string): this {
  validateAttributeKey(key);
  // ... writes to attributes bag
}
```

There is no `setTabindex`, `setTitle`, or `setRole` on `Tag`. The class currently has typed fields only for `id`, `class`, and `style` (dedicated serialization lanes) and the `attributes` escape-hatch bag. Every other universal attribute goes through `addAttribute`.

For `role` specifically, there is a `setAria()` bulk setter (for `aria-*` prefixed attributes), but no equivalent for `role` itself — which is not `aria-role` but the bare `role` attribute.

`tabindex` needs a numeric value (`-1` for focus-trap, `0` for tab order) — the current `addAttribute` requires stringing the number manually.

## Why it matters

These three attributes cover the most common accessibility and keyboard-navigation patterns:
- `tabindex="-1"` and `tabindex="0"` are the standard way to control focus for custom interactive widgets (dropdowns, modals, tooltips).
- `role` is the primary landmark/widget semantic for screen readers.
- `title` is the tooltip text for icon buttons and abbreviated text.

Requiring `addAttribute` for these suggests either that `Tag` is missing universal attribute coverage, or that the `setAria()` / `setDataAttrs()` pattern (bulk-setter objects) should be extended to `role` and `tabindex`. The current guidelines (`fluent-html.md:42`) document `addAttribute` as the right path for "custom attributes only", but `tabindex`/`title`/`role` are definitively standard — the guideline and the API are misaligned.

## Rough idea (not a design)

Three options, not exclusive:
- **Individual typed setters**: `Tag.setTabindex(n: -1 | 0 | number): this`, `Tag.setTitle(s: string): this`, `Tag.setRole(r: AriaRole | string): this`. `AriaRole` is a published typed union from the WAI-ARIA spec.
- **Extend `setAria`-style** to cover non-`aria-` global semantics: `setRole(r)` could live alongside `setAria({})`.
- **Batch universal setters**: `Tag.setAttrs({ tabindex: -1, title: "...", role: "..." })` — a typed object setter for the standard global attributes.
