# `hx-vals`, `hx-trigger`, and `hx-include` typed in HTMX interface — apps bypass via `addAttribute`

## Problem

The `HTMX` interface fully supports `vals`, `trigger`, `include`, and `confirm`:

```ts
// fluent-html/src/htmx.ts:210
export interface HTMX {
  // …
  vals?: Record<string, unknown> | string;
  trigger?: HxTrigger;
  include?: string;
  confirm?: string;
  // …
}
```

All of these serialize correctly through `buildHtmx` in `render.ts`. **The typed path works.** But `guidelines/web-development/htmx.md` only shows `target`, `swap`, `indicator`, and `status` options in its `setHtmx` / `hx()` examples. The section "Shorthand vs setHtmx" (line 83) never mentions `vals`, `trigger`, or `include`.

With no guideline example, apps treat these as unsupported and fall back to raw `addAttribute` with manual `JSON.stringify`:

```ts
// jt-cut/src/projects/timeline/timeline.view.ts:871
.addAttribute("hx-vals", JSON.stringify({ direction: "up", mediaId: slide.id }))

// jt-cut/src/projects/timeline/timeline.view.ts:902
.addAttribute("hx-vals", JSON.stringify({ slideId: slide.id }))

// jt-cut/src/projects/text-overlay/text-overlay.view.ts:369
.addAttribute("hx-vals", JSON.stringify({ section: "timeline" }))

// jt-cut/src/projects/views/projects.detail.view.ts:150
.addAttribute("hx-vals", JSON.stringify({ section: state.name }))

// jt-cut/src/projects/views/projects.components.ts:111
.addAttribute("hx-vals", JSON.stringify({ editingTitle: "true" }))

// jt-cut/src/projects/voiceover/voiceover.view.ts:125
.addAttribute("hx-trigger", "blur changed")
// line 126
.addAttribute("hx-include", "closest form")

// rideshare/src/rides/views/browse.view.ts:188
.addAttribute("hx-trigger", "change")
```

The equivalent typed call would be:

```ts
// ✓ typed, object vals auto-serialized, no manual JSON.stringify
.setHtmx(myRoute({ vals: { section: state.name } }))

// ✓ trigger in setHtmx
.setHtmx(myRoute({ trigger: "blur changed", include: "closest form" }))
```

## Why it matters

16 call-sites across 2 apps bypass a typed API that already exists, purely because it is invisible in the guidelines. Manual `JSON.stringify` adds noise and bypasses `buildHtmx`'s internal escaping. These call-sites also split HTMX config between `setHtmx()` and `addAttribute()` on the same element, which is confusing and adds a maintenance burden.

Note: `hx-confirm` adoption gap is separately tracked in F-A-016. This finding is specifically about `vals`, `trigger`, and `include`.

## Rough idea (not a design)

Guidelines-only fix. Add a `vals` / `trigger` / `include` example to `htmx.md` in the "Shorthand vs setHtmx" section:

```typescript
// ✓ pass extra HTMX parameters through setHtmx — no addAttribute needed
Button("Save").setHtmx(myRoute({ vals: { section: "photos" } }))
Input().setHtmx(myRoute({ trigger: "blur changed", include: "closest form" }))

// ✗ addAttribute with manual JSON.stringify — verbose, no type checking
Button("Save").addAttribute("hx-vals", JSON.stringify({ section: "photos" }))
```
