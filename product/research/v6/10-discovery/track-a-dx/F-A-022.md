# No ForEachOr / empty-list idiom

## Problem

Every app in the codebase repeats the same two-call pattern to render a list with an empty state:

```ts
IfThen(arr.length > 0, () => ForEach(arr, renderItem))
IfThen(arr.length === 0, () => EmptyStateView())
```

or the `IfThenElse` equivalent. There is no single function that encapsulates "map these items, or show a fallback". After counting, 307 `IfThen(…length > 0)` and 70 `IfThen(…length === 0)` call-sites exist across apps — the plurality of those 377 are paired: one for the list, one for the empty state.

## Evidence

`ttl/src/admin/views/projects-list.view.ts` — exact paired pattern on consecutive lines:

```ts
// ttl/src/admin/views/projects-list.view.ts:157-163
IfThen(projects.length > 0, () =>
  ProjectsTable({ projects }),
),
IfThen(projects.length === 0, () =>
  EmptyState(),
),
```

`ttl/src/admin/views/project-detail.view.ts:169-170` — same:

```ts
IfThen(members.length > 0, () => MembersTable({ project, members })),
IfThen(members.length === 0, () => EmptyMembers()),
```

`rideshare/src/rides/views/browse.view.ts:57,79` — two separate empty-state IfThen blocks for the same page. `rideshare/src/reservations/reservations.view.ts:210,426` — repeated in two route handlers within the same file. The pattern is so pervasive that each app reimplements the two-line idiom from scratch.

## Why it matters

Frequency: 9+ apps, 377 call-sites. Pain: medium-high — the two-call form is verbose, error-prone (one call can be omitted or the condition can drift), and forces readers to mentally pair the two `IfThen` calls. A `ForEachOr` helper would collapse this to one intent, eliminating the paired-condition split and making empty states impossible to forget.

## Rough idea (not a design)

Add an overload or companion function to `control/iteration.ts`:

```ts
// ForEachOr(items, renderItem, emptyView) 
ForEachOr(projects, (p) => ProjectRow(p), () => EmptyState())
// → renders ForEach when projects.length > 0, emptyView() when empty

// or as a standalone
IfThen(items.length > 0, () => ForEach(items, fn), EmptyView())
```

The simplest implementation is a thin wrapper:
```ts
export function ForEachOr<T>(
  items: T[],
  renderItem: (item: T, index: number) => View,
  emptyView: Thunk<View>
): View {
  return items.length > 0 ? ForEach(items, renderItem) : emptyView();
}
```

Guidelines should add a ✓/✗ pair alongside `ForEach`.
