# `Overlay()` is exported but never documented — zero app adoptions despite 455+ manual positioning patterns

## Problem

`fluent-html` exports an `Overlay(content, overlay, position?)` helper from `src/control/overlay.ts` that renders a `position:relative` wrapper with an absolutely-positioned overlay at any of 9 positions (`top`, `bottom`, `top-left`, `top-right`, `bottom-left`, `bottom-right`, `left`, `right`, `center`). Neither `guidelines/web-development/fluent-html.md` nor `guidelines/web-development/CLAUDE.md` mention it at any point.

A search across all apps finds zero imports of `Overlay` from `fluent-html`. Instead, apps hand-roll the same pattern repeatedly.

## Evidence

The API exists and is exported:

```ts
// fluent-html/src/control/overlay.ts:18
export function Overlay(
  content: View,
  overlay: View,
  position: OverlayPosition = 'center'
) {
  return Div([content, Div(overlay).setStyle(`position: absolute; ...`)])
    .setStyle("position: relative");
}
```

It is exported from the main barrel (`src/index.ts:251`) but the `OverlayPosition` type is in a value-position export block (covered separately by F-A-094).

`grep -r "Overlay" guidelines/web-development/` — no results. The function appears nowhere in `fluent-html.md` or `CLAUDE.md`.

Apps have 455+ occurrences of `position.*relative`, `z-10.*absolute`, or `inset-0` patterns across view files indicating hand-rolled overlay composition that `Overlay()` could replace. Representative example:

```ts
// manual overlay — seen across multiple apps
Div(
  Img().setSrc(avatar).w("full"),
  Div(Badge("3")).position("absolute").top("0").right("0").zIndex("10"),
).position("relative")
// ✓ with Overlay():
Overlay(Img().setSrc(avatar).w("full"), Badge("3"), "top-right")
```

The `guidelines/web-development/fluent-html.md` lists `Overlay` nowhere — not in the element factories section, not in the control flow section, not in a composition section. An LLM following those guidelines will never discover the helper.

## Why it matters

`Overlay()` has zero adoption because it is invisible to the primary consumers (LLMs running off `guidelines/web-development/**`). The pattern it wraps appears hundreds of times across apps. This is a low-effort guideline fix with measurable adoption upside; the API already exists.

Additionally, `Overlay()` internally uses `Div([content, ...])` (array wrapper anti-pattern) and `.setStyle()` inline strings instead of fluent Tailwind — a separate inconsistency finding (F-A-023), but worth noting as a factor if the API is to be promoted.

## Rough idea (not a design)

Add to `fluent-html.md` under a new "Composition helpers" or within "Modifiers & Composition":

```ts
// Overlay — positions content absolutely over a relative container
Overlay(
  Img().setSrc(avatar).w("16").h("16").rounded("full"),
  Badge("3").background("red-500").textColor("white"),
  "top-right"   // OverlayPosition: top | bottom | top-left | top-right | ...
)
```

Add a one-line entry to the `CLAUDE.md` control flow section: `Overlay(content, overlay, position?)` for image badges, tooltips, action overlays.
