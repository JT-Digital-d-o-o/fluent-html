# `setDataAttrs()` adoption gap — 62 `addAttribute("data-*", ...)` calls across apps vs only 4 `setDataAttrs` calls

## Problem

`Tag.setDataAttrs(attrs)` exists and converts camelCase keys to `data-kebab-case` attributes in one call. Yet across the codebase, `addAttribute("data-*", value)` is used 62 times in 5+ apps while `setDataAttrs` is used only 4 times. The guideline shows both patterns side-by-side without declaring which is preferred or marking the verbose one as wrong.

## Evidence

Representative `addAttribute("data-*")` call sites:

```typescript
// jt-draw/src/studio/views/studio.canvas.view.ts:292-293
.addAttribute("data-generation-id", state.generationId)
.addAttribute("data-prompt", state.prompt)
// Could be: .setDataAttrs({ generationId: state.generationId, prompt: state.prompt })

// rideshare/src/shared/components/phone-input.view.ts:66-69
.addAttribute("data-min", String(m?.minLen ?? 6))
.addAttribute("data-max", String(m?.maxLen ?? 15))
.addAttribute("data-ph", m?.placeholder ?? "")
.addAttribute("data-name", c.name)
// Could be: .setDataAttrs({ min: String(m?.minLen ?? 6), max: ..., ph: ..., name: ... })

// glimm/src/protect/views/protect.covered.view.ts:139-141
.addAttribute("data-share", fileUrl)
.addAttribute("data-share-filename", "huluma.jpg")
.addAttribute("data-share-title", "huluma")
// Could be: .setDataAttrs({ share: fileUrl, shareFilename: "huluma.jpg", shareTitle: "huluma" })

// ttl/src/admin/views/add-project.view.ts:57-58
.addAttribute("data-action", "remove-member")
.addAttribute("data-user-id", user.id)
// Could be: .setDataAttrs({ action: "remove-member", userId: user.id })
```

Raw counts in 5 major apps (excludes node_modules, library source):
- `addAttribute("data-*")`: **62 call sites** across rideshare, jt-draw, glimm, ttl, planet-positive-sport
- `setDataAttrs({})`: **4 call sites** (tela, cms, glimm, planet-positive-sport — and only when setting a single attribute each time)

The offending guideline line (`guidelines/web-development/fluent-html.md:42`):
```
  .addAttribute("data-x", "val")   // custom attributes only
  .setDataAttrs({ userId: "123" }) // data-user-id="123" (auto kebab-case)
```

The comment "custom attributes only" does not exclude `data-*` in the developer's mind — data attributes _are_ custom attributes by definition in HTML. The guideline shows `addAttribute` first, making it the "default" pattern.

## Why it matters

- **Verbosity**: each `data-*` attribute requires a separate `addAttribute` call with a manually kebab-cased key. `setDataAttrs` batches them and auto-converts camelCase.
- **Error surface**: `addAttribute("data-user-id", ...)` requires the developer to remember the kebab prefix; `setDataAttrs({ userId: ... })` handles it automatically.
- **Discoverability**: when you have multiple data attributes (4 in the phone-input case), `addAttribute` chains look like noise vs a clean object.
- The fix is a guideline edit adding a ✗ rule, not a code change.

## Rough idea

Update `guidelines/web-development/fluent-html.md` "Universal methods" block:

```typescript
// ✓ batch data-* attributes
.setDataAttrs({ userId: "123", action: "save" })  // data-user-id / data-action

// ✗ never chain addAttribute for data-* attributes
.addAttribute("data-user-id", "123")   // ✗
.addAttribute("data-action", "save")   // ✗
```

Also add a note that single data attributes should still use `setDataAttrs` (not `addAttribute`) for consistency.
