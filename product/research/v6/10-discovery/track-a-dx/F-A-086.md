# CLAUDE.md's "never raw inline JS" rule for `.behavior()` has no documented escape hatch — 127 call-sites violate it by necessity

## Problem

`CLAUDE.md` contains the rule (lines 158–165):

```typescript
// ✓ use .behavior() for client-side interactions — never raw inline JS:
Button("Toggle").behavior("toggle", { target: ids.filterPanel })
Button("Copy").behavior("clipboard", { value: apiKey })
Button("Submit").behavior("disable")
A("Back").behavior("back").cursor("pointer")

// Built-in: toggle, toggleClass, remove, clipboard, disable, focus, scrollTo, selectAll, back.
```

The `renderers` map in `behavior-methods.ts:46` is a **private constant** — there is no public API to register custom behaviors. The 9 built-ins cover common patterns but **do not cover** arbitrary click-time logic (form-reset, switchTab, class manipulation by selector, conditional guards, etc.).

When an app needs custom click-time logic, the only option is `addAttribute("hx-on:click", "...")`. This is exactly what the guideline prohibits — yet it is the only available path.

## Evidence

127 `addAttribute("hx-on:click", ...)` call-sites across 12+ apps:

```ts
// renderbox/src/app/landing/studio/studio.variant-2.view.ts:264
.addAttribute("hx-on:click", "switchTab(this, 'rbx')")

// renderbox/src/app/landing/studio/studio.variant-2.view.ts:273
.addAttribute("hx-on:click", "switchTab(this, 'rust')")

// gzs/inovacije/src/views/admin/admin-quick-grade.view.ts:423
.addAttribute("hx-on:click", "event.preventDefault()");

// tela/src/views/editor/panels/comments-panel.ts:344
.addAttribute("hx-on:keydown", "if(event.key==='Enter' && (event.metaKey || event.ctrlKey)) this.form.requestSubmit()"),

// buzzin/src/views/quiz/sponsor-exposition.view.ts:109
.addAttribute("hx-on::after-settle", `...complex JS...`)
```

The behavior system's private `renderers` map (the only way to add a named behavior) has no extension point:

```ts
// fluent-html/src/core/behavior-methods.ts:46
const renderers: Record<BehaviorName, BehaviorRenderer> = {
  toggle: ...,
  clipboard: ...,
  // ... 9 built-ins total — no way to extend from outside the library
};
```

The CLAUDE.md rule lists the 9 built-ins and says "Built-in: `toggle`, `toggleClass`, `remove`, `clipboard`, `disable`, `focus`, `scrollTo`, `selectAll`, `back`." — but does not say what to do when none of these covers the need.

## Why it matters

A rule without an enumerated exception is either unenforceable or drives users to the undocumented path silently. Both outcomes are worse than documenting the escape hatch:

1. **Unenforceable:** Apps with 127 `addAttribute("hx-on:click", ...)` calls are "violating" the rule on every commit. The rule loses credibility.
2. **Undocumented escape hatch:** Developers using `addAttribute` for custom events do so without guidance — no note about avoiding `innerHTML`-style injection, no note about the `escapeJs` concern (see F-A-065), no note about when `.behavior()` should be preferred.

Documenting the escape hatch makes the rule actionable: apps can satisfy it when `.behavior()` covers the case, and know the safe alternative when it doesn't.

## Rough idea (not a design)

Two complementary fixes:

**Fix A — guideline edit (minimum viable):**
Add a documented escape hatch paragraph to CLAUDE.md's behavior section:

```typescript
// When .behavior() doesn't cover the need, use addAttribute as a last resort:
// — escape any user-supplied data (never template-interpolate raw values)
// — prefer .behavior() for the 9 built-in cases above
Button("Tab A").addAttribute("hx-on:click", "switchTab(this,'a')")  // ✓ ok for static literals
```

**Fix B — API extension (better):**
Expose a `.hxOn(event, js): this` method that emits `hx-on:<event>` and is documented as the typed (if not type-safe) escape hatch, keeping `addAttribute` as the raw last-resort:

```typescript
Button("Tab").hxOn("click", "switchTab(this,'rbx')")  // ✓ typed escape hatch
Button("Tab").addAttribute("hx-on:click", "...")       // ✗ use .hxOn() or .behavior()
```

The behaviour extension point (registering custom named behaviors) is a separate Track-B concern.
