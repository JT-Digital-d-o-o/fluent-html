# No multi-scope helper — apps manually track Disposable[] arrays to manage groups of context scopes

## Problem

When an app needs to scope multiple contexts at once (e.g. i18n locale + translation function + timezone + available locales), it must store each `Disposable` individually and loop-dispose them manually. There is no `scopeAll()` or `DisposableGroup` in the library. All 5 apps that scope multiple contexts repeat the same pattern:

```ts
// glimm/src/core/i18n/i18n.plugin.ts:12
_i18nDispose?: Disposable[];
```

```ts
// planet-positive-sport/src/core/i18n/i18n.plugin.ts:60-66
request._i18nDispose = [
  i18nTranslation.scope(tFn),
  i18nLocale.scope(locale),
  i18nAvailableLocales.scope(availableLocales),
  i18nTimeZone.scope("UTC"),
];
```

```ts
// planet-positive-sport/src/core/i18n/i18n.plugin.ts:93-95
if (request._i18nDispose) {
  for (const d of request._i18nDispose) d[Symbol.dispose]();
  request._i18nDispose = undefined;
}
```

The manual loop is repeated in every `onResponse` hook and every `afterEach` in test setup:

```ts
// planet-positive-sport/tests/view/setup.ts:10-18
let disposables: Disposable[] = [];

beforeEach(() => {
  disposables = [
    i18nTranslation.scope(tFn),
    i18nLocale.scope("en"),
    provideAssessmentScope({ mode: "loc" }),
    provideCanWrite(true),
  ];
});

afterEach(() => {
  for (const d of disposables) d[Symbol.dispose]();
  disposables = [];
});
```

## Evidence

The `Disposable[]` tracking pattern appears in:
- `glimm/src/core/i18n/i18n.plugin.ts:12, 42-45, 57-71`
- `jt-i18n/src/core/i18n/i18n.plugin.ts:12, 42-45, 57-71`
- `redaction-renderbox/src/core/i18n/i18n.plugin.ts:12, 42-45, 57-71`
- `planet-positive-sport/src/core/i18n/i18n.plugin.ts:21, 60-66, 93-95`
- `projects-template/templates/full-stack/src/core/i18n/i18n.plugin.ts:12, 40-44, 55-60`

All 5 apps independently arrived at the same workaround because the library offers only `ctx.scope()` returning a single `Disposable`, with no combinator.

## Why it matters

The `Disposable[]` boilerplate is 8–12 lines per plugin, repeated 3× per app (initial scope, re-scope after auth, dispose in onResponse). Each repetition is an opportunity to forget to dispose an entry (stack leak) or dispose in the wrong order. A `DisposableGroup` or `scopeAll()` combinator would collapse the group to one `Disposable` compatible with `using`.

Additionally, the manual array pattern requires module augmentation on `FastifyRequest` (`_i18nDispose?: Disposable[]`) — tying the disposal bookkeeping to Fastify's request object, which leaks an implementation detail.

## Rough idea (not a design)

Export a `DisposableGroup` class (or factory) that:
1. Accepts an array of `Disposable` values.
2. Returns a single `Disposable` whose `[Symbol.dispose]()` disposes all members (in reverse order, for correct LIFO).
3. Is compatible with `using`.

```ts
// Proposed usage
using _i18n = scopeAll([
  i18nTranslation.scope(tFn),
  i18nLocale.scope(locale),
  i18nTimeZone.scope("UTC"),
]);
// On block exit, disposes all three in reverse order
```

This is a ~10-line addition to `control/context.ts` with zero new concepts.
