# `.display()` and `.hidden()` are absent from README table and guidelines despite being the most-used display APIs

## Problem

The library provides `.display(value: TailwindDisplay): this` and `.hidden(): this` on `Tag`, both in the source and the type declarations:

```ts
// fluent-html/src/core/tailwind-methods.ts:469
p.display = function (value: string) { return this.addClass(value); };
p.hidden  = function ()              { return this.addClass("hidden"); };
```

The `TailwindDisplay` union covers 14 values including `"block"`, `"inline-block"`, `"inline"`, `"flex"`, `"inline-flex"`, `"grid"`, `"hidden"`, etc. (`tailwind-types.ts:118`).

Neither `.display()` nor `.hidden()` appears in:
- The README method reference table (lines 2190–2236) — `.grid()` has an entry but `.display()` and `.hidden()` do not.
- `guidelines/web-development/fluent-html.md` — the word "display" appears only once (line 105, as a prose category label), with no code example.

## Evidence

The pair is among the most-used Tailwind methods in the codebase:

```
$ grep -rn '\.display(' apps --include="*.ts"  → 1 263 call-sites
$ grep -rn '\.hidden()'  apps --include="*.ts"  →   283 call-sites
```

Typical usage in rideshare (landing.components.ts):

```ts
// rideshare/src/landing/landing.components.ts:34
Span().display("inline-block").animate("pulse").w("1.5").h("1.5").rounded("full")

// rideshare/src/landing/landing.components.ts:36
).hidden().at("md", t => t.display("inline-flex")).alignItems("center").gap("2")

// rideshare/src/landing/landing.components.ts:91
Span(value).display("block").textSize("xl").fontFamily("display").fontWeight("black")

// rideshare/src/landing/views/browse-rides.view.ts:91
.display("inline-block").tracking("[0.15em]").textSize("xs").uppercase()
```

The README table (line 2209) lists `.grid()` — which calls `addClass("grid")` — but omits `.display("grid")`, creating a confusing inconsistency: the same class is reachable via two different APIs yet only one appears in the docs.

## Why it matters

At 1 546 call-sites, `.display()` and `.hidden()` are high-frequency APIs discovered entirely by reading TypeScript autocomplete or grepping the source — not from the documentation. Any developer consulting the README table or the guidelines file will miss them and may fall back to `.addClass("hidden")` or `.addClass("flex")` (bypassing the typed union). The adoption feedback loop is broken: the most-used display mechanism is invisible to new users.

## Rough idea (not a design)

Add `.display(value)` and `.hidden()` to the README method table and add a small ✓/✗ block in the `fluent-html.md` guidelines:

```typescript
Div().display("block")          // ✓ typed display — preferred
Div().display("inline-flex")    // ✓
Div().hidden()                  // ✓ shorthand for display("hidden")
Div().display("hidden")         // ✓ equivalent to .hidden()
Div().addClass("hidden")        // ✗ use .hidden() instead
Div().addClass("flex")          // ✗ use .display("flex") or .flex() instead
```

No code change is needed — this is a documentation-only fix.
