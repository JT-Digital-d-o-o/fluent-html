# `formFor<T>()` adoption gap — views have TypeScript request types but call `.setName()` directly; guideline never shows the connection

## Problem

The `ttl` project defines typed request bodies in `src/core/types.ts` but the auth view (`auth.view.ts`) never imports those types and never uses `formFor<T>()`. Instead it calls `.setName()` with bare string literals on every form field. The types and the form builder exist in parallel but are never connected.

The guideline (`fluent-html.md`) explains how `formFor<T>()` works once you have a type, but never shows:
1. Where `T` comes from in a real Fastify project (controller request type, Fastify-inferred body type, hand-written type alias).
2. How to name that type so the view can import it.
3. A `✗` example showing `.setName("email")` as the anti-pattern to replace.

## Evidence

Types defined — but invisible to the view layer:

```ts
// ttl/src/core/types.ts:5
export type SignInReq = {
  email: string;
  password: string;
};

// ttl/src/core/types.ts:10
export type RegisterReq = {
  email: string;
  name: string;
  password: string;
  passwordConfirm: string;
};
```

View ignores the types and uses untyped `.setName()`:

```ts
// ttl/src/auth/auth.view.ts:58
Input().setType("email").setName("email")
// ttl/src/auth/auth.view.ts:68
Input().setType("password").setName("password")
// ttl/src/auth/auth.view.ts:146
Input().setType("text").setName("name")
```

With `formFor<SignInReq>()` these would be:
```ts
const f = formFor<SignInReq>();
f.input("email", "email")    // ✓ compile error on typo
f.input("password", "password")
```

The same pattern repeats across 20+ `.setName()` calls in `ttl/src/auth/auth.view.ts` and another 20 in `ttl/src/settings/settings.view.ts`.

## Why it matters

`ttl` has zero `formFor` usages (0) while it has 40+ `.setName()` calls. `rideshare` has 28 `formFor` usages — proving the API works when adopted. The difference: `rideshare` defines `SignInReq`, `RegisterReq` etc. in `auth.schema.ts` and imports them into the view; `ttl` never made this connection.

The pain: a field name typo in `ttl` compiles silently and fails only at runtime when the server receives a request with a missing or misspelled field. The compile-time safety `formFor` promises is fully bypassed.

## Rough idea (not a design)

In `fluent-html.md` under "Type-Safe Forms — `formFor<T>()`":

1. Add a line showing where `T` comes from: "Import the same request type used by the controller handler."
2. Add a `✗` example: bare `.setName("email")` on a form that has a known schema type.
3. Add a `✓` counterpart: `formFor<SignInReq>()` imported from the schema file.

No code change required — this is a guideline-only fix.
