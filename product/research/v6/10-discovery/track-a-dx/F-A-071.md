# Multi-word HTML attribute setters use verbatim lowercase HTML names

## Problem

Eight typed setters on `*Tag` subclasses mirror the HTML attribute name verbatim — a single all-lowercase string — rather than the TypeScript camelCase convention every other method in the library follows:

| Method (current) | TypeScript expectation | HTML attribute |
|---|---|---|
| `setReadonly()` | `setReadOnly()` | `readonly` |
| `setAutofocus()` | `setAutoFocus()` | `autofocus` |
| `setNovalidate()` | `setNoValidate()` | `novalidate` |
| `setCrossorigin()` | `setCrossOrigin()` | `crossorigin` |
| `setAllowfullscreen()` | `setAllowFullscreen()` | `allowfullscreen` |
| `setReferrerpolicy()` | `setReferrerPolicy()` | `referrerpolicy` |
| `setFormaction()` | `setFormAction()` | `formaction` |
| `setFormmethod()` | `setFormMethod()` | `formmethod` |

Every other multi-word setter in the library uses camelCase: `setStrokeWidth`, `setFontFamily`, `setLetterSpacing`, `setFontSize`, `setAutoplay`, `setTextDecoration` (SVG), `setRowspan`, `setColspan` (tables). The pattern is universal — except for these eight.

## Evidence

Source definitions are all lowercase verbatim:

```ts
// fluent-html/src/elements/forms.ts:107
setReadonly(readonly: boolean = true): this { … }

// fluent-html/src/elements/forms.ts:92
setAutofocus(autofocus: boolean = true): this { … }

// fluent-html/src/elements/forms.ts:340
setNovalidate(novalidate: boolean = true): this { … }

// fluent-html/src/elements/document.ts:116
setCrossorigin(crossorigin?: 'anonymous' | 'use-credentials'): this { … }

// fluent-html/src/elements/embedded.ts:42
setAllowfullscreen(allowfullscreen: boolean = true): this { … }

// fluent-html/src/elements/embedded.ts:62
setReferrerpolicy(referrerpolicy?: string): this { … }

// fluent-html/src/elements/forms.ts:275
setFormaction(formaction?: string): this { … }

// fluent-html/src/elements/forms.ts:280
setFormmethod(formmethod?: 'get' | 'post'): this { … }
```

Consequence: developers type `setCrossOrigin` (camelCase, TypeScript natural spelling), find no autocomplete match, and fall back to `addAttribute`:

```ts
// tela/src/views/shared.ts:51  — bypass via addAttribute
Link().setRel("preconnect").setHref(url).addAttribute("crossorigin", "")

// tela/src/controllers/orgs.controller.ts:50
Input().addAttribute("autofocus", "true")

// gym-crm/src/scenes/qr/qrUI.ts:361
Input().addAttribute("readonly", "true")

// tela/src/views/editor/panels/classes-section.ts:25
textarea.addAttribute("readonly", "");

// vabilo30/src/music/views/music.detail.view.ts:114
.addAttribute("referrerpolicy", "strict-origin-when-cross-origin")
```

Total documented bypass callsites: **25** (`crossorigin`: 14, `readonly`: 7, `autofocus`: 4, `referrerpolicy`: 1) across 7+ apps, in addition to the typed-setter usages (setCrossorigin: 57, setReadonly: 5, setAutofocus: 3).

## Why it matters

The camelCase convention is hardwired into TypeScript IDE muscle memory. When a developer types `input.setRead` they expect IDE autocomplete to offer `setReadOnly`. The lowercase name is a miss that costs them two round-trips: try the camelCase name, fail to find it, discover the all-lowercase version in docs (if they look), or give up and use `addAttribute`. The 25 documented bypasses show the second path is common.

The SVG setters (`setStrokeWidth`, `setFontFamily`) were already given camelCase names — the inconsistency is not architectural, just historical (HTML attributes are lowercase, but method names should follow TypeScript).

## Rough idea (not a design)

Rename all 8 to camelCase for v6. Keep old lowercase names as deprecated aliases (a thin `setReadonly = setReadOnly`) for one major version, with an ESLint auto-fix rule. Update the ESLint plugin's `prefer-set-method` map accordingly. No behavior change — just a rename.
