# `group()` + `.on('group-hover', ...)` composition is never taught — 14 `addClass('group-hover:*')` violations

## Problem

The fluent-html Tailwind API provides `.group()` to mark a parent element as a group and `.on("group-hover", fn)` to apply styles to a child when the parent is hovered. This two-element composition is a complete fluent path for the Tailwind `group`/`group-hover:*` pattern. However, neither `guidelines/web-development/CLAUDE.md` nor `guidelines/web-development/fluent-html.md` shows the combination — `CLAUDE.md` never mentions `.group()` at all, and `fluent-html.md` lists "group/peer" only in a method-category line with no code example.

The result: 14 `addClass("group-hover:*")` violations across apps that ignore the fluent path.

## Evidence

The fluent API exists but is invisible:

```ts
// fluent-html/src/core/tailwind-methods.ts:268,583
p.group = function (name?: string) {
  return name === undefined ? this.addClass("group") : this.addClass(`group/${name}`);
};
// .on() is the generic variant prefix method (line 326)
// → parent.group() + child.on("group-hover", t => t.opacity("100")) is fully supported
```

Apps bypass it with `addClass`:

```ts
// ttl/src/time-entry/views/time-entry.view.ts:466
Div(
  actionButton.addClass("group-hover:opacity-100"),   // ✗
).addClass("group entry-row")                          // ✗ mixes plain and group class in one string

// ttl/src/shared/components/ui.components.ts:375
Div(
  icon.addClass("group-hover:bg-amber-500/20"),        // ✗
  label.addClass("group-hover:text-amber-500"),        // ✗
).addClass("group")                                    // ✗

// jt-vault/src/vault/components/activity-entry.view.ts:58
Div(editActions).addClass("opacity-0 group-hover:opacity-100 transition-opacity shrink-0")  // ✗
```

The correct idiomatic form:

```ts
// ✓ fluent path — types, extractor-safe, no raw class strings
Div(
  actionButton.on("group-hover", t => t.opacity("100")).transition("opacity"),
).group()

Div(
  icon.on("group-hover", t => t.background("amber-500/20")),
  label.on("group-hover", t => t.textColor("amber-500")),
).group()
```

The guideline check: `grep "group()" guidelines/web-development/CLAUDE.md` returns nothing. `fluent-html.md:107` lists it as a category but with no example: `group/peer (\`group()\`, \`peer()\`)`.

Note: `ttl` correctly uses `.group()` in 3 places (time-entry.view.ts:566) but uses `addClass("group entry-row")` in others — the pattern is inconsistent even within the same file, confirming guideline uncertainty rather than deliberate avoidance.

## Why it matters

The 14 `addClass("group-hover:*")` violations bypass:
1. **Type safety** — `addClass` takes any string; `.on()` accepts only typed Tailwind method calls.
2. **Extractor compatibility** — the fluent extractor can track `.on("group-hover", t => t.opacity("100"))` as `group-hover:opacity-100`; `addClass("group-hover:opacity-100")` works only because the string is static.
3. **Conflict-detection** — multiple `addClass` calls on the same element can stack conflicting group-hover classes silently.

The fix is a ✓/✗ guideline addition; no code change needed.

## Rough idea (not a design)

Add to `CLAUDE.md` Tailwind section alongside the existing `.on()` / `.at()` example:

```ts
// ✓ group() + .on("group-hover") — two-tag composition
Div(
  Button("Edit").on("group-hover", t => t.opacity("100").translate("x", "-1")),
).group()

// ✗ addClass escape hatch — untyped, mixing raw Tailwind string with fluent
Div(
  Button("Edit").addClass("group-hover:opacity-100"),
).addClass("group")
```

Add the same ✓/✗ pair to `fluent-html.md` under "Fluent Tailwind Styling".
