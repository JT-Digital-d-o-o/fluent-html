# `addAttribute` event-handler error says "use client-side JS or HTMX" — contradicts guidelines and hides `.behavior()`

## Problem

When a developer calls `Tag.addAttribute("onclick", ...)` (or any `on*` attribute), the library throws:

```
Event handler attribute "onclick" is blocked — use client-side JS or HTMX instead
```

The phrase **"use client-side JS"** is the opposite of what the guidelines say. `CLAUDE.md` §HTMX-First Architecture explicitly states: *"never inline `<script>` / `onclick`"*. The phrase "use HTMX instead" is vague — it covers both `setHtmx()` (for server round-trips) and `.behavior()` (for pure-client interactions), and the developer almost always wants `.behavior()`.

The actual intended replacement — `.behavior()` — is not mentioned at all in the error.

## Evidence

```ts
// fluent-html/src/core/tag.ts:14
const EVENT_HANDLER_RE = /^on[a-z]/i;

// fluent-html/src/core/tag.ts:27
throw new Error(`Event handler attribute "${key}" is blocked — use client-side JS or HTMX instead`);
```

The built-in behaviors are:
```ts
// behavior-methods.ts:11-21
BehaviorMap = {
  toggle, toggleClass, remove, clipboard, disable, focus, scrollTo, selectAll, back
}
```

All of these are exactly the interactions a developer would attempt to implement with an `onclick` handler, yet the error message points away from them.

## Why it matters

This error is encountered primarily by developers who are new to the library or porting existing code. The error message:

1. Suggests "client-side JS" — banned by the project guidelines.
2. Never mentions `.behavior()` — the purpose-built replacement for exactly this scenario.
3. The word "HTMX" misleads: a developer may reach for `setHtmx()` with a server endpoint when they just needed `Button(...).behavior("disable")`.

Three apps show evidence of developers falling through this gap: they use `addAttribute("hx-on:click", ...)` with raw JS strings (rideshare: 2 sites, ttl: 1 site) — the exact pattern `.behavior()` eliminates.

## Rough idea (not a design)

Replace the error with a targeted message that names the actual API:

```
Event handler attribute "onclick" is blocked.
  For toggle/clipboard/disable/scroll interactions use: .behavior("toggle"|"clipboard"|"disable"|...)
  For server round-trips use: .setHtmx(route(...))
  See: https://…/fluent-html#behavior
```
