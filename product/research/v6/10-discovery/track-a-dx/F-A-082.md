# README method reference table is incomplete — 57 Tailwind methods are undocumented there

## Problem

The README's "Tailwind Styling Quick Reference" table (lines 2190–2236) lists ~62 entries but the source (`tailwind-methods.ts`) exports ~120 distinct prototype methods. A diff of the two sets yields **57 methods with no table entry**.

The most impactful omissions by call-site frequency across all apps:

| Method | App call-sites | Documented in table? |
|--------|---------------|----------------------|
| `.transition()` | 1 851 | No |
| `.display()` | 1 263 | No |
| `.hidden()` | 283 | No |
| `.ring()` | 152 | No |
| `.ringColor()` | ~120 | No |
| `.animate()` | 116 | No |
| `.scale()` | ~100 | No |
| `.rotate()` | ~80 | No |
| `.on()` | omnipresent | No |
| `.at()` | omnipresent | No |

Full list of undocumented methods (confirmed via source diff):
`alignSelf`, `animate`, `at`, `backdropBlur`, `backdropBrightness`, `backdropContrast`, `backdropGrayscale`, `backdropHueRotate`, `backdropInvert`, `backdropSaturate`, `backdropSepia`, `borderStyle`, `bottom`, `breakAll`, `colSpan`, `display`, `divideX`, `divideY`, `duration`, `flex1`, `flexWrap`, `gridAutoCols`, `gridAutoFlow`, `gridAutoRows`, `grow`, `hidden`, `hueRotate`, `inset`, `invert`, `left`, `listStylePosition`, `neg`, `noUnderline`, `objectFit`, `on`, `order`, `outline`, `overscroll`, `placeContent`, `placeItems`, `placeSelf`, `pointerEvents`, `resize`, `right`, `ring`, `ringColor`, `rotate`, `scale`, `select`, `shrink`, `skewX`, `skewY`, `spaceX`, `spaceY`, `srOnly`, `tabularNums`, `top`, `transition`, `translate`, `whitespace`, `willChange`.

## Why it matters

The README method table is the primary discoverability surface for developers exploring the API. Missing 57 of ~120 methods means half the API is invisible to table readers. High-frequency methods like `.transition()` (1 851 uses), `.display()` (1 263), and `.ring()` (152) are discovered only through TypeScript autocomplete or reading existing app code — not from the docs. This leads to:
1. Developers falling back to `.addClass()` for methods they don't know exist.
2. New contributors not knowing the idiomatic fluent path.
3. The table giving a false impression that the API surface is small.

## Rough idea (not a design)

Two options:
1. **Auto-generate the table** from `tailwind-methods.ts` (parse prototype assignments, extract method name + param types, emit markdown). This keeps it in sync automatically.
2. **Manually complete the table** by adding the 57 missing entries, with a linting check that flags new methods without table entries.

Either way, the high-priority additions (`.transition()`, `.on()`, `.at()`, `.ring()`, `.animate()`, `.display()`, `.hidden()`) should land first. `.on()` and `.at()` warrant their own sub-section since they are the variant/responsive API, not a single utility class.

The `guidelines/web-development/fluent-html.md` "Key method categories" prose list (line 107) already mentions `transition`, `scale`, `rotate`, etc. by name but gives no code example — the table gap and the guideline prose gap are two sides of the same problem.
