# `.gradientTo()` emits `bg-gradient-*` which is a dead class name on Tailwind v4

## Problem

Tailwind v4 renamed all linear gradient utilities from `bg-gradient-to-*` to `bg-linear-to-*`. The fluent-html method `.gradientTo()`, the extractor's `METHOD_PATTERNS`, and the ESLint auto-fix map all still emit/map the v3 name. On v4, calling `.gradientTo("to-r")` emits `bg-gradient-to-r` which generates no CSS — the gradient silently disappears. This is a common utility (used in hero sections, cards, banners) and the failure is silent.

## Evidence

`fluent-html/src/core/tailwind-methods.ts` line 576:
```typescript
// tailwind-methods.ts:576
p.gradientTo = function (direction: string) { return this.addClass(`bg-gradient-${direction}`); };
//                                                                      ^^^^^^^^^^^^ dead on v4
```

`fluent-html/src/core/tailwind-types.ts` lines 197–199 — type for the direction argument is correct but the prefix in the method is wrong:
```typescript
// tailwind-types.ts:197
export type TailwindGradientDirection =
  | "to-t" | "to-tr" | "to-r" | "to-br" | "to-b" | "to-bl" | "to-l" | "to-tl"
  | (string & {});
```

`fluent-html-tailwind-extractor/src/index.ts` line 391 — the extractor independently hardcodes the same wrong prefix:
```typescript
// extractor/index.ts:391
{ pattern: "gradientTo", methodName: "gradientTo",
  generateClass: (args) => args.length === 1 ? [`bg-gradient-${args[0]}`] : [] },
//                                               ^^^^^^^^^^^^
```

`fluent-html-eslint-plugin/src/rules/no-known-modifiers-in-setclass.ts` line 384 — the auto-fix map suggests the v3 name:
```typescript
// no-known-modifiers-in-setclass.ts:384
{ pattern: "bg-gradient-", methodName: "gradientTo" },
```
On v4 this auto-fix actively suggests writing code that produces no CSS.

## Why it matters

All three packages (lib, extractor, ESLint) must agree on the class-name string — this is guardrail §11.7 ("class-string contract"). Here all three agree on the *wrong* v3 name. The ESLint rule makes it worse: it actively auto-fixes v3 gradient strings to a fluent call that emits the same dead class. Gradients are a high-visibility styling primitive used in most apps.

## Rough idea (not a design)

Update the method to emit `bg-linear-${direction}` for v4 target. Simultaneously add `.gradientRadial()` → `bg-radial-*` and `.gradientConic()` → `bg-conic-*` for the two new v4 gradient types. Update `METHOD_PATTERNS` in the extractor and the ESLint map in a single coordinated change (a cross-package version bump). Extend `TailwindGradientDirection` with new v4 angle values like `"45"`, `"90"` for `bg-linear-45`.
