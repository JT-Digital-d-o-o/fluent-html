# v4 3D transform utilities entirely absent from fluent-html

## Problem

Tailwind v4 ships a complete set of 3D transform utilities as a first-class built-in feature (no plugin required):

| v4 utility | CSS property |
|---|---|
| `rotate-x-*`, `rotate-y-*`, `rotate-z-*` | `rotateX()`, `rotateY()`, `rotateZ()` |
| `translate-z-*` | `translateZ()` |
| `scale-z-*` | `scaleZ()` |
| `perspective-*` | `perspective` |
| `perspective-origin-*` | `perspective-origin` |
| `transform-3d` | `transform-style: preserve-3d` |
| `backface-hidden`, `backface-visible` | `backface-visibility` |

None of these exist in fluent-html. The existing `rotate` and `scale` and `translate` methods only cover 2D:

```ts
// fluent-html/src/core/tailwind-methods.ts:540-543
p.scale = function (value: string | number) { return this.addClass(`scale-${value}`); };
p.rotate = function (value: string | number) { return this.addClass(`rotate-${value}`); };
p.translate = function (direction: string, value: string) {
  return this.addClass(`translate-${direction}-${value}`);  // direction: "x" | "y" only
};

// fluent-html/src/core/tailwind-types.ts:147-148
export type TailwindScale = 0 | 50 | 75 | 90 | 95 | 100 | 105 | 110 | 125 | 150 | ... | (string & {});
export type TailwindRotate = 0 | 1 | 2 | 3 | 6 | 12 | 45 | 90 | 180 | ... | `[${string}]`;
// ↑ TailwindScale/TailwindRotate have no z-axis equivalents; translate direction is "x"|"y" only
```

The extractor `METHOD_PATTERNS` (index.ts:56–540) similarly has no patterns for `rotateX`, `rotateY`, `rotateZ`, `translateZ`, `scaleZ`, `perspective`, or `backface`.

## Evidence

- `fluent-html/src/core/tailwind-methods.ts:540` — `p.rotate`, `p.scale`, `p.translate` all 2D-only; no `rotateX/Y/Z`, `translateZ`, `scaleZ`
- `fluent-html/src/core/tailwind-types.ts:147` — `TailwindScale` and `TailwindRotate` have no z-axis equivalents
- `fluent-html-tailwind-extractor/src/index.ts:56` — `METHOD_PATTERNS` array has no 3D transform entries

Users who want flip-card effects, 3D carousels, or `perspective` depth must use `addClass`:

```ts
// Today — forced escape hatch:
Div()
  .addClass("transform-3d")
  .addClass("rotate-y-180")
  .addClass("backface-hidden")
  .addClass("perspective-500")
```

## Why it matters

3D transforms are a v4-new feature that enables common UI patterns (flip cards, 3D depth indicators, perspective hover effects) without any CSS-in-JS or custom classes. The severity is **low** in existing apps (none surveyed use 3D transforms today — v4 is the catalyst), but the pattern is clearly additive and straightforward to implement. The gap will grow as teams adopt v4 and reach for these features. The extractor gap is the second risk: `addClass("rotate-y-180")` is caught by the fallback regex scanner, but dedicated `METHOD_PATTERNS` entries would be more reliable and would integrate with the explicit `.on()`/`.at()` extraction path.

## Rough idea (not a design)

Add fluent methods: `rotateX(deg)`, `rotateY(deg)`, `rotateZ(deg)`, `translateZ(value)`, `scaleZ(value)`, `perspective(value)`, `perspectiveOrigin(value)`, `transform3d()`, `backfaceHidden()`, `backfaceVisible()`. Define matching types (reuse or extend `TailwindRotate`; add `TailwindPerspective`). Add `METHOD_PATTERNS` entries in the extractor. This is purely additive — no v3 compat impact.
