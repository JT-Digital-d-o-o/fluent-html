# ESLint `no-known-modifiers-in-setclass` missing v4 `xs` scale entries

## Problem

Tailwind v4 introduced `xs` as the new smallest slot in the shadow, rounded, and blur scales (previously the smallest named slot was `sm`). The ESLint auto-fix map in `no-known-modifiers-in-setclass.ts` does not include any `xs` entries for these utilities:

```ts
// fluent-html-eslint-plugin/src/rules/no-known-modifiers-in-setclass.ts:212-220
// Rounded
{ pattern: "rounded-none", methodName: "rounded", exactMatch: true, fixedValue: "none" },
{ pattern: "rounded-sm", methodName: "rounded", exactMatch: true, fixedValue: "sm" },
// "rounded-xs" is absent
{ pattern: "rounded-md", methodName: "rounded", exactMatch: true, fixedValue: "md" },
...

// fluent-html-eslint-plugin/src/rules/no-known-modifiers-in-setclass.ts:223-230
// Shadow
{ pattern: "shadow-sm", methodName: "shadow", exactMatch: true, fixedValue: "sm" },
// "shadow-xs" is absent
{ pattern: "shadow-md", methodName: "shadow", exactMatch: true, fixedValue: "md" },
...

// fluent-html-eslint-plugin/src/rules/no-known-modifiers-in-setclass.ts:397-401
// Blur
{ pattern: "blur-", methodName: "blur" },  // prefix catch-all; but exact xs entry is absent
// "blur-xs" would be caught by prefix, but "backdrop-blur-xs" needs a prefix entry too
```

A user on v4 who writes `setClass("rounded-xs")`, `setClass("shadow-xs")`, or `setClass("blur-xs")` directly will:
- For `rounded-xs` and `shadow-xs`: get no suggestion, because the pattern is not in the exact-match list AND the prefix catch-all (`rounded-`, `shadow-`) doesn't exist in the map (only exact values are listed for those utilities)
- For `blur-xs`: this WOULD be caught by `{ pattern: "blur-", methodName: "blur" }` and auto-fixed to `.blur("xs")` — which is correct

The real gap is `rounded-xs` and `shadow-xs` where the ESLint map uses only exact-match entries (no prefix catch-all):

```ts
// Rounded uses exact-match entries, not a prefix catch-all
// So "rounded-xs" → no match → no suggestion
{ pattern: "rounded-none", ... }
{ pattern: "rounded-sm", ... }
{ pattern: "rounded-md", ... }
// ... missing: { pattern: "rounded-xs", methodName: "rounded", exactMatch: true, fixedValue: "xs" }

// Shadow also uses exact-match entries only
{ pattern: "shadow-sm", ... }
{ pattern: "shadow-md", ... }
// ... missing: { pattern: "shadow-xs", methodName: "shadow", exactMatch: true, fixedValue: "xs" }
```

The same issue applies to `drop-shadow-xs` and `backdrop-blur-xs` (new v4 scale slots).

## Evidence

Confirmed by searching the entire `no-known-modifiers-in-setclass.ts` file: zero occurrences of `xs` for any utility. The type tables also lack `xs`:

```ts
// fluent-html/src/core/tailwind-types.ts:77
export type TailwindRounded = "none" | "sm" | "md" | "lg" | "xl" | "2xl" | "3xl" | "full" | `[${string}]`;
// No "xs"

// fluent-html/src/core/tailwind-types.ts:81
export type TailwindShadow = "sm" | "md" | "lg" | "xl" | "2xl" | "inner" | "none" | (string & {});
// No "xs"

// fluent-html/src/core/tailwind-types.ts:205
export type TailwindBlur = "none" | "sm" | "md" | "lg" | "xl" | "2xl" | "3xl" | `[${string}]`;
// No "xs"
```

Finding F-C-002 already documents the type-table gap. This finding adds the ESLint-specific evidence: a v4 project that uses `setClass("rounded-xs")` or `setClass("shadow-xs")` loses auto-fix guidance because the ESLint map only knows the v3 scale slots.

## Why it matters

As v4 adoption grows, developers will naturally write `rounded-xs` and `shadow-xs` in raw `setClass()` strings (following v4 docs or design-system guidance). The ESLint plugin's core promise is to catch these and suggest fluent methods. Silently ignoring `rounded-xs` undermines that promise for a high-frequency category (border-radius and shadow are used on nearly every component).

Frequency is currently low (v4 not deployed to the monorepo apps), but will be approx 20+ call-sites once a single app migrates to v4, based on the density of `rounded-lg`, `shadow-sm` usage in rideshare and ttl.

## Rough idea (not a design)

Add exact-match entries to `FIXABLE_PATTERNS`:

```ts
{ pattern: "rounded-xs", methodName: "rounded", exactMatch: true, fixedValue: "xs" },
{ pattern: "shadow-xs", methodName: "shadow", exactMatch: true, fixedValue: "xs" },
{ pattern: "drop-shadow-xs", methodName: "dropShadow", exactMatch: true, fixedValue: "xs" },
// blur-xs is already caught by the prefix pattern { pattern: "blur-", methodName: "blur" }
// backdrop-blur-xs is caught by { pattern: "backdrop-blur-", methodName: "backdropBlur" }
```

This is purely additive and requires no other changes. Should land together with the type-table `xs` additions in F-C-002.
