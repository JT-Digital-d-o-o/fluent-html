# `TailwindState` missing media/environment pseudo-variants — `.on()` type-errors on these states

## Problem

`TailwindState` — the union type constraining the first argument of `.on()` — covers CSS pseudo-classes (`:hover`, `:focus`, `:disabled`, etc.) and a few relational variants (`group-hover`, `peer-focus`). It is entirely missing two broad categories:

**Category 1 — Media / environment pseudo-variants (v3-era, but never added to TailwindState):**

```ts
"print"           // @media print — hide/show elements for print
"motion-safe"     // @media (prefers-reduced-motion: no-preference)
"motion-reduce"   // @media (prefers-reduced-motion: reduce)
"portrait"        // @media (orientation: portrait)
"landscape"       // @media (orientation: landscape)
"supports-[...]"  // @supports arbitrary feature query
```

**Category 2 — v4-new element/attribute state variants:**

```ts
"starting"        // @starting-style — transition-in animations on first render
"open"            // [open] attribute (details/dialog/popover)
"inert"           // [inert] attribute
"nth-[...]"       // :nth-child(…) arbitrary selector
"nth-last-[...]"  // :nth-last-child(…)
"in-[...]"        // :is(…) contextual selector (v4)
```

The current `TailwindState` is:

```ts
// fluent-html/src/core/tailwind-types.ts:179-189
export type TailwindState =
  | "hover" | "focus" | "focus-within" | "focus-visible"
  | "active" | "visited"
  | "disabled" | "enabled" | "checked" | "indeterminate" | "required" | "invalid" | "valid"
  | "first" | "last" | "odd" | "even" | "empty"
  | "first-of-type" | "last-of-type" | "only-child"
  | "placeholder" | "selection" | "marker" | "file"
  | "before" | "after"
  | "dark"
  | "group-hover" | "group-focus" | "group-active" | "group-disabled"
  | "peer-hover" | "peer-focus" | "peer-checked" | "peer-invalid";
// ↑ 28 members; no print, no motion-safe, no motion-reduce, no portrait/landscape,
//   no supports-*, no starting, no open, no inert, no nth-[...], no in-[...]
```

The `.on()` implementation (`tailwind-methods.ts:107`) is purely mechanical — it just prepends the state string as a variant prefix via `withVariant`. The correct CSS output (`print:hidden`, `motion-reduce:transition-none`, `starting:opacity-0`) would be produced if only the type permitted the value.

## Evidence

```ts
// fluent-html/src/core/tailwind-methods.ts:107
on(state: TailwindState, fn: (tag: this) => this): this;

// Concrete failures today:
Div().on("print", t => t.hidden())                     // ✗ type error
Div().on("motion-reduce", t => t.transition("none"))   // ✗ type error
Div().on("portrait", t => t.flexDirection("col"))      // ✗ type error
Div().on("starting", t => t.opacity("0"))              // ✗ type error — v4 new
Div().on("open", t => t.display("block"))              // ✗ type error — v4 new
```

Two surveyed apps (`rideshare/src/landing/landing.components.ts:42` and `rideshare/src/landing/views/landing.view.ts:108`) use `addClass` for hover-transform workarounds already — while these specific cases are about negative translate values (covered separately), the same escape-to-addClass pattern applies to any state that `TailwindState` rejects.

## Why it matters

`print:hidden` / `print:block` is used in nearly every SSR app that has a print layout. `motion-reduce:transition-none` is an accessibility best-practice for reduced-motion users. `starting:opacity-0` is the primary v4 mechanism for CSS entry animations (no JS needed). All of these are rendered with correct output by `.on()` internally — the only barrier is the type union. Every missing state forces the user to `addClass("print:hidden")` — an untyped raw string with no IDE completion and no extractor `METHOD_PATTERNS` coverage through the fluent path.

The frequency count of 2 reflects confirmed apps using `addClass` for these state patterns; the real count is higher because missing states are invisible in code search (no one writes `.on("print",...)` if it type-errors).

## Rough idea (not a design)

Extend `TailwindState` in three groups:

1. **Media pseudo-variants** (v3-present, clearly safe): `"print" | "motion-safe" | "motion-reduce" | "portrait" | "landscape"`
2. **Supports arbitrary**: `` `supports-[${string}]` ``
3. **v4 element-state variants**: `"starting" | "open" | "inert"` and template-literal forms `` `nth-[${string}]` | `nth-last-[${string}]` | `in-[${string}]` ``

No extractor changes needed — `extractVariantClasses` (extractor index.ts:637) already handles all `.on()` calls generically. The ESLint `no-known-modifiers-in-setclass` map could gain entries for `print:`, `motion-reduce:` etc. pointing back to `.on()`.
