# No built-in Autocomplete/Combobox component — rideshare built 200 LOC from scratch; no other app has it

## Problem

Typeahead/autocomplete (an input that fetches suggestions from a server route as the user types and lets them select a value) is a common UI pattern in any app with search, location, user, or entity pickers. There is no built-in component; rideshare was forced to build a full one from scratch (200 LOC across component + results view). No other surveyed app (mngmt, glimm, jt-cut, storysell) has one at all, which almost certainly means those apps either lack the feature or implement it differently (native `<datalist>`, or a client-side JS component outside fluent-html).

The rideshare implementation is correct and HTMX-first (no JS, purely server-driven selections), but it required solving: hidden input for the form value, a selected-vs-typing state toggle via `IfThenElse`, query parameter forwarding for `outerMorph` targeting, a `ClearButton` that fires an HTMX mutation, and an auto-hiding dropdown list. These are all generic concerns.

## Evidence

**rideshare** — shared component, 200 LOC:

```ts
// rideshare/src/shared/components/autocomplete.view.ts:56-118
export function Autocomplete({
  name,
  instanceId,
  searchUrl,
  placeholder = "Type to search...",
  value,
  required,
  onSelect,
}: AutocompleteProps) {
  const resultsId = `${instanceId}-results`;
  const hasValue = !!value;

  // Build search URL with _target for outerMorph matching
  const searchUrlWithParams = `${searchUrl}${searchUrl.includes("?") ? "&" : "?"}_target=${encodeURIComponent(resultsId)}`;

  return Div(
    // Hidden input — carries the actual form value
    Input().setType("hidden").setName(name).setValue(value ?? "")
      .addClass("autocomplete-value"),

    IfThenElse(
      hasValue,
      () =>
        Div(
          Span(value!).textSize("sm").fontWeight("medium").textColor("body").flex("1"),
          ClearButton()
            .setHtmx(hx(onSelect.url, {
              method: onSelect.method,
              target: layoutIds.page,
              swap: "outerMorph",
              include: "closest form",
              vals: { [name]: "" },
            })),
        ).flex().alignItems("center").gap("2")…,
      () =>
        Div(
          Input()
            .setType("text")…
            .setHtmx(hx(searchUrlWithParams, {
              method: "get",
              trigger: "keyup changed delay:250ms, focus",
              target: `#${resultsId}`,
              swap: "outerMorph",
              include: "[name=q]",
            }))
            .setName("q"),
          AutocompleteDropdown({ id: resultsId, items: [] }),
        ).position("relative"),
    ),
  );
}
```

The `AutocompleteSelectConfig` type (the selection callback being a HTMX route, not a JS callback) is a clean HTMX-first design pattern. The 200-line file shows how much boilerplate is needed to do this correctly — hidden value input, two render states, URL injection, results dropdown, clear button.

**Other apps** — zero `Autocomplete` implementations found in: mngmt, glimm, jt-cut, storysell-ai. The pattern simply doesn't exist in those apps, meaning entity-picker use cases are either absent or handled with plain `<select>` dropdowns.

## Why it matters

Pain is high because: (a) rideshare already spent 200 LOC on this; (b) every app with user/entity search needs it; (c) without it, devs reach for a JS-heavy client-side library (defeating SSR) or accept a degraded `<select>` instead. The HTMX-first approach (server returns results, no JSON/JS needed) is the correct pattern for this library's SSR model — and that pattern only works if the component handles the hidden-input/state-toggle/URL-injection boilerplate automatically.

Frequency is 1 (only rideshare) but pain is high because the component is non-trivial and the other 5 apps that lack it are likely missing the feature entirely.

## Rough idea (not a design)

`Autocomplete({ name, searchRoute, placeholder?, value?, onSelect })` where `searchRoute` is a typed `RouteRef` (from `defineRoutes`) and `onSelect` is a route reference for the mutation. Library builds the `outerMorph` target, hidden-input, and state-toggle automatically. `AutocompleteResults(items, config)` is the server-side partial response that renders the dropdown. Requires `defineRoutes` route refs (already in the library) for type-safe URL generation.
