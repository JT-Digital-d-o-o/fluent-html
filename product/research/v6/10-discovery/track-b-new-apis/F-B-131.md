# Partial() is absent from CLAUDE.md index — 5 of 6 apps never use it despite htmx.md coverage

## Problem

`Partial(id, view, swapStyle?)` is the right primitive for updating multiple page sections in one HTMX response without a full-layout swap. It is documented with working examples in `htmx.md` (§ Partial swaps). It is **completely absent from `CLAUDE.md`** — the LLM-facing index that Claude Code reads before every interaction.

Result: 5 of 6 active apps — rideshare, mngmt, jt-cut, storysell-ai, jtdigital-landing-page — have **zero** `Partial()` calls. Only planet-positive-sport (pps) adopted it, accounting for all 47 uses across the fleet. All other apps default to either (a) full-layout swap into `ids.mainContent` even when only a sub-region changed, or (b) bare `hxResponse(Empty()).trigger(...)` for side-effects with no content update.

## Evidence

**pps uses Partial() correctly — the only app that does:**

```ts
// planet-positive-sport/src/admin/questionnaires/questionnaires.utils.ts:137
return [
  Partial(editorIds.qbValidationBar, EditorValidationBar({ issues: validation, questionnaire })),
  Partial(editorIds.qbStats, EditorStatsBar({ questionnaire })),
  Partial(editorIds.qbDeploySection, EditorDeploySection({ ... })),
  Partial(editorIds.qbSavedIndicator, EditorSavedIndicator({ justSaved: true }), "outerHTML"),
];
```

**rideshare and mngmt use hxResponse(Empty()) + trigger for file events — no content update possible:**

```ts
// rideshare/src/files/files.controller.ts:62  (identical in mngmt)
const { html, headers } = hxResponse(Empty())
  .trigger("showToast", { message: "File uploaded successfully" })
  .build();
reply.headers(headers);
return reply.renderView(html);
```

These controllers upload/delete files but cannot update the file list UI at the same time — they rely entirely on a client-side toast event. With `Partial()` they could update both the file list and fire the toast in one round-trip.

**CLAUDE.md has no mention of Partial():**

Searching `guidelines/web-development/CLAUDE.md` for "Partial" returns zero results. The relevant htmx.md section is well-written but never linked from the index:

```
# htmx.md, line 118 — exists but unreachable from the LLM index:
Partial(ids.mainContent, UserList(users)),
Partial(ids.userCount, Span(`${users.length} users`)),
Partial(ids.pageTitle, H1("Users")),
```

## Why it matters

`Partial()` eliminates a full round-trip re-render of the entire layout for mutations that only affect one or two regions (e.g. a nav badge count + main content). All 5 non-pps apps are losing this efficiency silently — they don't know the API exists. Because the LLM reads only `CLAUDE.md` at the start of a session, `htmx.md` content is reached only when the LLM searches for it, which it won't do if it doesn't know `Partial()` exists.

Frequency: 6 apps affected (5 zero-adoption + 1 correct). Pain: medium (perf + correctness gap, not a crash).

## Rough idea (not a design)

Add a one-paragraph "Partial swaps" rule to `CLAUDE.md` under the HTMX section — a ✓ example using `Partial()` for multi-section mutation response, and a ✗ example showing the full-layout swap alternative with a note to prefer partial when content changes are scoped. No code change required; this is a pure guideline patch.
