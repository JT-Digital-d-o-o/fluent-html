# auth.plugin.ts copy-pasted verbatim across 4 apps

## Problem

Every fluent-html Fastify app hand-rolls the same ~80-line cookie-session auth plugin. The structure is identical: register `@fastify/cookie`, decorate `request.user`, add `reply.signIn(user)` / `reply.signOut()`, add a `preHandler` hook that unsigns a cookie, does a DB lookup, and gates on `SKIP_AUTH_PREFIXES`. The only differences are the cookie name (`"userId"` vs `"__sid"`) and whether inactive users are handled.

```ts
// rideshare/src/auth/auth.plugin.ts:17  (verbatim)
const authPlugin = fp(
  async (fastify: FastifyInstance) => {
    fastify.register(cookie, { secret: requireEnv("COOKIE_SECRET"), ... });
    fastify.decorateRequest("user", null);
    fastify.decorateReply("signIn", function (this, user) {
      this.setCookie("userId", user.id, { httpOnly: true, sameSite: "lax", signed: true, maxAge: 7*24*60*60, ... });
    });
    fastify.decorateReply("signOut", function (this) { this.clearCookie("userId", { path: "/" }); });
    const SKIP_AUTH_PREFIXES = ["/public/", "/css/", "/js/", "/health", "/metrics", "/favicon.ico"];
    fastify.addHook("preHandler", async (request, reply) => { ... });
  },
  { name: "auth" }
);
```

```ts
// glimm/src/auth/auth.plugin.ts:19  (verbatim copy, cookie name "__sid")
const AUTH_COOKIE = "__sid";
const authPlugin = fp(
  async (fastify: FastifyInstance) => {
    // ... identical structure, comment "TODO: For high-traffic apps, consider caching..."
  },
  { name: "auth" }
);
```

```ts
// storysell-ai/src/auth/auth.plugin.ts:19  (identical to glimm including the TODO comment)
// mngmt/src/auth/auth.plugin.ts:17  (identical to rideshare)
```

The `SKIP_AUTH_PREFIXES` array is literally copy-pasted with the same six strings in rideshare, glimm, and storysell-ai.

## Evidence

- `rideshare/src/auth/auth.plugin.ts:43`: `const SKIP_AUTH_PREFIXES = ["/public/", "/css/", "/js/", "/health", "/metrics", "/favicon.ico"];`
- `glimm/src/auth/auth.plugin.ts:45`: identical line
- `storysell-ai/src/auth/auth.plugin.ts:45`: identical line
- `mngmt/src/auth/auth.plugin.ts:17`: same `fp(async (fastify) => { ... signIn/signOut/preHandler ...})` body

All four also do the same `declare module "fastify"` augmentation for `request.user` and `reply.signIn`/`reply.signOut`.

## Why it matters

Any security fix (e.g. stronger cookie options, correct `SKIP_AUTH_PREFIXES`, adding a `Sec-Fetch-Site` check) must be applied to 4 (and growing) copies. The `glimm` and `storysell` copies carry a `// TODO: For high-traffic apps, consider caching this lookup` comment that was never acted upon — likely because fixing it in one copy doesn't propagate. The divergence is already visible: rideshare checks `user.isActive` before setting `request.user`; the other three don't.

## Rough idea (not a design)

A `createAuthPlugin<TUser>(opts: { findUser(id: string): Promise<TUser | null>, cookieName?, maxAge?, skipPrefixes? })` factory exported from a `@fluent-html/fastify` adapter package (or from the lib itself as a zero-dep helper that only uses Fastify's own types). Apps pass in their `findUser` DB call; the factory handles everything else. The `Fastify` module augmentation for `request.user` and `reply.signIn`/`reply.signOut` is part of the package's type exports so apps stop redeclaring it.
