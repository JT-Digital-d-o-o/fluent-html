# Sidebar/tab nav active-item component reimplemented per app with identical active-state styling pattern

## Problem

fluent-html has no `NavItem` or `SidebarNavItem` primitive. Every app that has a sidebar or tab navigation defines its own private `NavItem`/`SidebarNavItem`/`TabItem` component to handle the active vs inactive styling. The active-state pattern is always the same: `.when(active, t => t.background(...).textColor(...))` + `.when(!active, t => t.textColor(...).on("hover", ...))`. The differences are purely cosmetic (color tokens, padding sizes) but the structural pattern is identical.

## Evidence

rideshare defines `NavItem` with the standard active-highlight pattern:

```ts
// rideshare/src/shared/components/layout.view.ts:237-265
function NavItem({ item, activePage }: { item: NavItemDef; activePage?: ActivePage }) {
  const isActive = activePage === item.key;
  const el = A(Span(item.icon), Span(item.label), IfThen(item.badge, (c) => ...))
    .cursor("pointer").flex().alignItems("center").gap("rem", 0.65)
    .padding("[0.62rem_0.75rem]").rounded("[9px]")
    .textSize("[0.87rem]").fontWeight("medium")
    .w("full").textAlign("left")
    .transition("all").duration("[0.14s]").margin("b", "[2px]").noUnderline()
    .background("none").border("none");

  return el
    .hxGet(item.href, { target: ids.page, swap: "outerMorph scroll:top", pushUrl: true })
    .when(isActive, t => t.background("leaf/15").textColor("sage").addClass("[&_svg]:text-leaf"))
    .when(!isActive, t => t.textColor("white/70").on("hover", t => t.background("white/5").textColor("white/90")));
}
```

mngmt defines `SidebarNavItem` with the same structure:

```ts
// mngmt/src/shared/components/layout.view.ts:237-245
function SidebarNavItem({ label, icon, href, active }: SidebarNavItemProps): View {
  return A(icon, label)
    .apply(navLink(href))
    .flex().alignItems("center").gap("3").padding("x", "3").padding("y", "2.5").rounded("lg").textSize("sm")
    .transition("colors").noUnderline()
    .when(active, (t: AnchorTag) => t.background("accent/10").textColor("accent").fontWeight("medium"))
    .when(!active, (t: AnchorTag) => t.textColor("slate-400").on("hover", h => h.textColor("accent").background("slate-800/50")));
}
```

storysell-ai defines a `TabItem` following the same active-toggle pattern for tab navigation:

```ts
// storysell-ai/src/shared/components/ui.nav.components.ts:22-35
export function TabItem({ label, active = false }: TabItemProps) {
  return A(label)
    .padding("b", "2").cursor("pointer").textSize("sm").transition("all").duration("200")
    .when(active, t => t.fontWeight("semibold").textColor("primary").border("b", "2").borderColor("primary"))
    .when(!active, t => t.textColor("gray-500").border("b", "2").borderColor("transparent")
      .on("hover", h => h.textColor("gray-700").borderColor("gray-300")));
}
```

planet-positive-sport defines `NavSection` as a discriminated union (`app-layout.view.ts:41`) and passes it through several layout layers to the nav component that applies the same `.when(active, ...)` pattern.

## Why it matters

At least 5 apps (rideshare, mngmt, storysell, glimm, pps) define their own nav-item primitive. The active-state logic is structurally identical: a two-branch `.when(active, ...)` / `.when(!active, ...)` with a hover modifier on the inactive branch. Because there's no shared primitive, the active-state class choices differ (some use `background("accent/10")`, others `background("leaf/15")`), and each app must wire the HTMX target and `pushUrl` separately inside the nav item. This creates inconsistency and duplication.

## Rough idea (not a design)

A `NavItem({ label, icon?, active, route, target })` built-in component that handles the active-state `.when()` branches, the `.setHtmx(route({ target, pushUrl: true }))` wiring, and common structural styling (flex, gap, rounded, transition). Apps override color tokens via a theme context. A `SidebarNav([items])` and `TabNav([items])` layout wrapper complete the set.
