# `ThCell`/`TdCell` table-cell helpers independently reimplemented in 5+ apps

## Problem

Every app that renders a data table defines the same two tiny wrapper functions — `ThCell` (styled `<th>`) and `TdCell` (styled `<td>`) — by hand. The implementations are structurally identical: same props (`text`/`content`, `align?`), same chain (`.padding("3").textSize("xs"/"sm").fontWeight(...).textColor(...).textAlign(align)`). The only difference is the brand color token in `.textColor()`.

## Evidence

All five apps define the same helper with the same shape:

```ts
// jt-cut/src/shared/components/ui.components.ts:125
type ThCellProps = { text: string; align?: "left" | "right" | "center" };
export function ThCell({ text, align = "left" }: ThCellProps) {
  return Th(text)
    .textAlign(align)
    .padding("3")
    .textSize("xs")
    .fontWeight("medium")
    .textColor("txt-muted")
    .uppercase();
}
type TdCellProps = { content: View | string; align?: "left" | "right" | "center" };
export function TdCell({ content, align = "left" }: TdCellProps) {
  return Td(content)
    .padding("3")
    .textSize("sm")
    .textColor("txt-secondary")
    .textAlign(align);
}
```

```ts
// rideshare/src/analytics/analytics.components.ts:128 — positional args variant
export function ThCell(text: string, align: "left" | "right" | "center" = "left") {
  return Th(text).textAlign(align).padding("3").textSize("xs").fontWeight("medium").textColor("muted").uppercase();
}
export function TdCell(content: View | string, align: "left" | "right" | "center" = "left") {
  return Td(content).padding("3").textSize("sm").textColor("body").textAlign(align);
}
```

```ts
// mngmt/src/analytics/analytics.view.ts:60 — defined locally (not even in shared components)
type ThCellProps = { text: string; align?: "left" | "right" | "center" };
function ThCell({ text, align = "left" }: ThCellProps): View { ... }
```

The glimm and storysell versions in their respective `ui.data.components.ts` files are byte-for-byte identical to each other.

## Why it matters

Five apps, each contributing ~15 lines of boilerplate that could be eliminated by two built-in primitives. The inconsistency in call signatures (props object in some, positional args in others) already causes subtle divergence (e.g. `rideshare` uses `ThCell("Time")` while `jt-cut` uses `ThCell({ text: "Time" })`), making cross-app component sharing impossible. Any table in an app that doesn't have these helpers falls back to raw `Th(...).addClass(thClass)` chains (as in `mngmt/src/dashboard/dashboard.view.ts:856`).

## Rough idea

`ThCell(label, align?)` and `TdCell(content, align?)` as built-in exports from `fluent-html`, or better: a `Table.of(rows, columns[])` data-grid builder that generates these automatically and removes the need for per-cell imperative calls entirely. Either path eliminates the boilerplate in all five apps.
