# Full i18n scaffolding reimplemented from scratch in every i18n-capable app

## Problem

`fluent-html` provides `createContext` as a primitive but zero i18n-specific support. Every app that needs internationalisation must independently implement:

- A **translation loader** that reads locale JSON files from disk, flattens nested keys to dot-notation, and caches per-locale.
- A **locale negotiation function** that parses `Accept-Language` headers and ranks by q-values.
- A **translation function factory** (`createTranslationFn`) handling fallback to a default locale and `{{param}}` interpolation.
- A **Fastify plugin** that wires all of the above into `onRequest` / `preHandler` / `onResponse` hooks, decorates the request with `request.t` and `request.locale`, manages `createContext` scope/dispose lifecycle, and optionally re-scopes after auth resolves the user's preferred locale.
- **Formatting helpers** (`formatDate`, `formatDecimal`, `formatPercent`, `formatCurrency`, `formatRelative`) that read from `i18nLocale.current` and `i18nTimeZone.current`.

The result is 200–500 LOC of identical infrastructure written independently per app.

## Evidence

**planet-positive-sport** — 500 LOC across 4 files (`i18n.ts` + `i18n.plugin.ts` + `i18n.loader.ts` + `format.ts`):

```ts
// planet-positive-sport/src/core/i18n/i18n.ts:8-11
export const i18nTranslation = createContext<TranslationFn>(fallbackT);
export const i18nLocale = createContext("en");
export const i18nAvailableLocales = createContext<readonly string[]>([]);
export const i18nTimeZone = createContext("UTC");
```

```ts
// planet-positive-sport/src/core/i18n/i18n.plugin.ts:46-87 (simplified)
fastify.addHook("onRequest", (request, _reply, done) => {
  const locale = resolveLocale(null, request.headers["accept-language"], availableLocales);
  const tFn = createTranslationFn(translations, locale);
  request._i18nDispose = [
    i18nTranslation.scope(tFn),
    i18nLocale.scope(locale),
    i18nAvailableLocales.scope(availableLocales),
    i18nTimeZone.scope("UTC"),
  ];
  done();
});
fastify.addHook("preHandler", (request, _reply, done) => {
  // re-scope if user.preferredLocale differs
  const userLocale = request.user?.preferredLocale;
  if (userLocale && userLocale !== request.locale && availableLocales.includes(userLocale)) {
    for (const d of request._i18nDispose!) d[Symbol.dispose]();
    request._i18nDispose = [ i18nTranslation.scope(...), ... ];
  }
  done();
});
fastify.addHook("onResponse", (request, _reply, done) => {
  for (const d of request._i18nDispose ?? []) d[Symbol.dispose]();
  done();
});
```

**projects-template** — 183 LOC across 3 files (identical structure, simpler variant — no user-preference upgrade, no formatters):

```ts
// projects-template/templates/web/src/core/i18n/i18n.plugin.ts:31-46
fastify.addHook("onRequest", (request, _reply, done) => {
  const locale = resolveLocale(request.headers["accept-language"], availableLocales);

```

**jt-cut** — 71 LOC (different architecture: typed object, no context; see F-B-102 for the divergence):

```ts
// jt-cut/src/i18n/locale.plugin.ts:18-28
fastify.addHook("onRequest", async (request) => {
  const localeParam = (request.params as Record<string, string>)?.locale;
  request.locale = isSupportedLocale(localeParam) ? localeParam : defaultLocale;
  request.t = getTranslations(request.locale);
});
```

The `Intl`-based formatters (date, decimal, percent, currency, relative time) in `planet-positive-sport/src/core/i18n/format.ts` are 152 LOC of caching wrappers that every app with formatting needs will have to re-derive.

## Why it matters

Three apps have implemented this boilerplate independently; any new i18n-capable app must do the same. The scope/dispose lifecycle around `createContext` is subtle (wrong disposal order = context leak), the user-preference preHandler upgrade pattern is non-obvious, and the `Intl`-caching layer is non-trivial to get right (formatter instantiation is expensive; stable cache keys require sorted options). Each app also diverges silently (pps has 4 context vars + formatters; template has 2; jt-cut skips context entirely).

## Rough idea (not a design)

A companion export — `fluent-html/i18n` or a separate `@fluent-html/i18n` package — exporting:

```ts
// rough sketch
const { i18nTranslation, i18nLocale, i18nTimeZone, t, formatDate, formatDecimal, ... }
  = createI18nContext();

// Fastify plugin factory (optional peer dep)
import { i18nPlugin } from "@fluent-html/i18n/fastify";
await server.register(i18nPlugin, {
  loadTranslations: () => loadTranslations(),
  resolveUserLocale: (req) => req.user?.preferredLocale,
});
```

Guardrail: zero hard deps on Fastify — the plugin must be a separate optional export. `Intl` is a Node built-in, safe.
