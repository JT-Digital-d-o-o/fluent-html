# No first-class Alert component; re-implemented in 6+ apps with diverging variant sets (missing info/warning variants)

## Problem

Every fluent-html app needs a feedback alert (form error, success flash, info banner). There is no built-in `Alert` so each app copy-pastes the same 8–12 line helper into its shared components folder. The copies diverge in two ways:

1. **Variant coverage**: most apps define only `danger | success`. planet-positive-sport later extracted a full 4-variant system (`success | warning | danger | info`) plus a companion `InfoCallout` component, while storysell-ai, jt-cut, glimm, and mngmt are still stuck on the 2-variant version.
2. **Semantic-color values**: each app picks slightly different Tailwind shades even for the same variant (storysell `bg-green-50` / `text-green-700`; mngmt uses custom tokens `sea-soft` / `sea` for success; glimm copies storysell's palette).

The result: the `info` variant used for non-error informational banners (e.g. "your questionnaire is under review") gets hard-coded in-place or is simply unavailable.

## Evidence

storysell-ai uses a 2-variant Alert — no `info` or `warning`:
```ts
// storysell-ai/src/shared/components/ui.form.components.ts:41-51
type AlertProps = { message: string; type?: "danger" | "success" };

export function Alert({ message, type = "danger" }: AlertProps) {
  return Div(P(message).textSize("sm"))
    .border()
    .rounded("lg")
    .padding("4")
    .margin("b", "6")
    .when(type === "danger", t => t.background("red-50").borderColor("red-200").textColor("red-700"))
    .when(type === "success", t => t.background("green-50").borderColor("green-200").textColor("green-700"));
}
```

jt-cut and glimm are structurally identical with the same 2-variant limit:
```ts
// jt-cut/src/shared/components/ui.components.ts:88
type AlertProps = { message: string; type?: "danger" | "success" };
export function Alert({ message, type = "danger" }: AlertProps) { … }
```

planet-positive-sport eventually extracted a proper 4-variant system with a shared `statusColors` token map, used by Alert + Badge + InfoCallout:
```ts
// planet-positive-sport/src/shared/components/status-colors.ts:8-28
type StatusVariant = "success" | "warning" | "danger" | "info";
export const statusColors = {
  success: { bg: "green-50", border: "green-200", text: "green-700", accent: "green-500" },
  warning: { bg: "yellow-50", border: "yellow-200", text: "yellow-800", accent: "yellow-500" },
  danger: { bg: "red-50", border: "red-200", text: "red-700", accent: "red-500" },
  info: { bg: "blue-50", border: "blue-200", text: "blue-700", accent: "blue-500" },
} satisfies Record<StatusVariant, StatusColorSet>;
```

And pps's Alert now accepts `dismissible` and `role="alert"` for accessibility — features absent from all other copies:
```ts
// planet-positive-sport/src/shared/components/display/display.ts:27-51
export function Alert({ message, type = "danger", dismissible = false }: AlertProps) {
  …
  .addAttribute("role", "alert");
}
```

mngmt duplicates `Alert` in two separate view files (`settings.view.ts:48` and `auth.view.ts:33`) rather than extracting to shared, showing how the missing built-in spreads intra-project too.

## Why it matters

7 apps (storysell-ai, jt-cut, glimm, mngmt x2, planet-positive-sport, rideshare) all maintain their own Alert. Every time a designer adds a `warning` or `info` variant it requires a per-app change. The `info` variant is actively needed (pps uses it in `questionnaire.view.ts:643`; storysell piggybacks `success` for non-error info) but is missing from the majority of the fleet. Accessibility (`role="alert"`) and dismissibility are bolted on only in the most mature app.

## Rough idea (not a design)

Ship `Alert(message, { variant: 'danger'|'success'|'info'|'warning', dismissible?, icon? })` as a built-in backed by the library's semantic-color token set. Also `Callout({ type, title?, description, icon? })` for the block-level callout shape that pps built as `InfoCallout`. Both share the same `StatusVariant` token type so apps configure once via context rather than per-file color records.
