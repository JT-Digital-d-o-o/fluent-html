# StatCard / metric-card reimplemented in 5+ apps; no built-in KPI / stat-tile primitive

## Problem

Every app with a dashboard or admin overview defines the same `StatCard` (or `MetricCard`, `KpiCard`, `OverviewStatCard`, `CrossProjectStatCard`) component: a bordered, rounded tile with a large numeric value, a small label, and an optional subtitle or trend indicator. There is no built-in primitive; each app copies the shape independently with diverging signatures (positional args vs. props object, different trend models, different color semantics).

## Evidence

**rideshare** — three variants in one file, all doing the same thing with minor styling diffs:


**glimm** — typed `StatCardTrend` struct, clean props object:

```ts
// glimm/src/shared/components/ui.data.components.ts:13-55
type StatCardTrend = { direction: "up" | "down" | "flat"; diff: string };
type StatCardProps = { label: string; value: string; trend?: StatCardTrend; sublabel?: string };

export function StatCard({ label, value, trend, sublabel }: StatCardProps) {
  return Div(
    P(label).textSize("sm").fontWeight("medium").textColor("deep-soft").margin("b", "1"),
    Div(
      Span(value).textSize("2xl").bold().textColor("deep"),
      IfThen(trend, ({ direction, diff }) => {
        const arrows = { up: "↑", down: "↓", flat: "→" } as const;
        return Span(`${arrows[direction]} ${diff}`)…;
      }),
    ).flex().alignItems("end"),
    IfThen(sublabel, (sub) => P(sub).textSize("xs").textColor("deep-soft").margin("t", "1")),
  ).background("foam").rounded("xl").shadow("sm").border().borderColor("sand-2").padding("5");
}
```

## Why it matters

Five apps, ten or more definition sites, all implementing the same 15–20 line tile. The signatures diverge (positional strings vs. props object, `number` vs. `string` value, optional `trend` vs. none), so components can't be shared across apps even within the same organization. The trend-indicator logic (arrow symbol, up/down color) is especially repetitive.

## Rough idea (not a design)

Add `StatCard({ label, value, sublabel?, trend?: { direction, diff } })` as a built-in primitive. The `value` should be a `string` (caller formats numbers). Trend indicator optional. Styling via context tokens so apps can theme it. This single addition would delete 10+ definition sites across the fleet.
