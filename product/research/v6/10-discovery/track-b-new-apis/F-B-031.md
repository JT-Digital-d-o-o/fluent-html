# No Document()/Page() helper; every app hand-rolls DOCTYPE + full <head> meta block (9+ layout files)

## Problem

There is no first-class `Document()` or `Page()` helper in fluent-html. Every app's layout file starts with `Raw("<!DOCTYPE html>")` followed by a manually assembled `Head(...)` containing charset/viewport, title, optional OG meta, favicon link, stylesheet links, and HTMX script tags — totaling 30–60 lines of near-identical boilerplate per app. Because this is done in each app independently, the pattern diverges (different OG tag coverage, different viewport strings, forgotten meta-robots on non-prod, etc.).

## Evidence

Every app duplicates the same shell:

```ts
// storysell-ai/src/shared/components/layout.view.ts:62
return [
  Raw("<!DOCTYPE html>"),
  HTML(Head(
    Meta().setCharset("utf-8"),
    Meta().setName("viewport").setContent("width=device-width, initial-scale=1.0"),
    Title(props.title + " | StorySell.AI"),
    Meta().setProperty("og:type").setContent("website"),
    Meta().setProperty("og:site_name").setContent("StorySell.AI"),
    Meta().setProperty("og:title").setContent(props.title + " | StorySell.AI"),
    Meta().setProperty("og:image").setContent(`${process.env.BASE_URL ?? ""}/og-image.png`),
    Meta().setProperty("og:image:width").setContent("1200"),
    Meta().setProperty("og:image:height").setContent("630"),
    Meta().setName("twitter:card").setContent("summary_large_image"),
    // ... 10+ more lines
  ), Body(...)).setLang("en"),
];
```

```ts
// rideshare/src/shared/components/layout.view.ts:164
return [
  Raw("<!DOCTYPE html>"),
  HTML(Head(...headChildren), body).setLang("en"),
];
```

planet-positive-sport has 5 separate layout files all beginning with `Raw("<!DOCTYPE html>")` (`app-layout.view.ts:91`, `auth-layout.view.ts:70`, `public-layout.view.ts:71`, `layout.view.ts:48`, `category-report.view.ts:49`).

jt-cut's share controller hand-rolls the document shell inline (not even in a shared component):
```ts
// jt-cut/src/share/share.controller.ts:19
Raw("<!DOCTYPE html>"),
```

## Why it matters

13 layout files across 7+ apps contain this boilerplate. Each diverges slightly: storysell covers OG + twitter; rideshare conditionally inserts OG only when `description` is provided; pps uses a separate `headLinks()` helper for scripts but still hand-rolls meta; mngmt and glimm skip OG entirely. The result is inconsistent SEO/social metadata and a non-trivial maintenance surface (any HTMX version bump must be updated in every layout file).

The recon doc already flags this as seed #9 ("Page-layout / `<head>` / DOCTYPE wrapper") at §3.9. This finding adds the exact count (13 files, 7 apps) and per-app divergence evidence.

## Rough idea (not a design)

A `Document({ lang?, title, description?, ogImage?, head?, body })` factory that: emits `<!DOCTYPE html>` (as a proper first child, not via `Raw`), sets `<html lang>`, assembles a `<head>` with charset, viewport, title + og:title, optional description + og:description, optional og:image, and accepts a `head?` slot for extra child nodes (favicon, stylesheets, per-app scripts). This subsumes the `Raw("<!DOCTYPE html>")` call and most of the `Head(...)` boilerplate in one typed API.
