# Drawer component re-invented in app alongside Modal; no library Drawer primitive despite identical structure

## Problem

`planet-positive-sport` independently implemented a `Drawer` component (`display/drawer.ts`) that mirrors the `Modal` component structure (`display/modal.ts`) almost exactly: both have a backdrop, a header with title + close button, a scrollable body, and an optional sticky footer. The implementation differences are purely layout (modal = centered overlay; drawer = right-side slide-over), yet both reach for the same raw-JS string workaround for open/close toggling because `.behavior()` doesn't support them.

```ts
// planet-positive-sport/src/shared/components/display/drawer.ts:20-63 (abridged)
export function Drawer({ id, title, body, footer }: DrawerProps) {
  return Div(
    Div()
      .position("absolute").inset("0")
      .addAttribute("hx-on:click", closeDrawerExpr(id)),  // raw JS string

    Div(
      Div(
        H2(title)...,
        Button(closeIcon("w-5 h-5"))
          ...
          .addAttribute("hx-on:click", closeDrawerExpr(id))  // raw JS string
      )...,
      Div(body)...,
      IfThen(footer, (f) => Div(f)...),
    )...,
  ).setId(id).position("fixed").inset("0")...;
}

// Helper strings — same pattern as Modal's closeModalJs/showModalJs:
export function openDrawerExpr(id: string): string {
  return `document.getElementById('${id}').classList.remove('hidden');`;
}
export function closeDrawerExpr(id: string): string {
  return `document.getElementById('${id}').classList.add('hidden');`;
}
```

Compare to Modal which has an identical structure, including inline `addAttribute("hx-on:click", closeJs)` calls on both the backdrop and the close button (`modal.ts:67, 80`).

The draw component even documents its design choice for not using `.behavior()`: "no project-level behavior registry" (drawer.ts:8-9) — the dev was aware of `.behavior()` but couldn't use it.

## Evidence

- `planet-positive-sport/src/shared/components/display/drawer.ts:1-76` — full 76-line app-level Drawer implementation
- `planet-positive-sport/src/shared/components/display/modal.ts:60-136` — structurally identical Modal
- Both have their own raw JS open/close helpers that duplicate the same `getElementById + classList` pattern
- The Drawer comment at line 7-10 explicitly notes the missing behavior support

## Why it matters

Drawer (slide-over panel) is a standard UI pattern used heavily in web apps alongside Modal. Apps that need both must implement both from scratch, doubling the boilerplate. The structural similarity is so high (backdrop + header + scrollable body + sticky footer) that a shared library primitive could cover both with a `variant: "modal" | "drawer"` flag or separate components sharing an internal shell.

The frequency count of 2 reflects confirmed implementations in pps; other apps (storysell admin has a revoke modal, jt-cut has gif-export modal) may also implement ad-hoc drawers.

## Rough idea (not a design)

Add `Drawer({ id, title, body, footer })` to the library as a companion to Modal. Both should be built on a shared internal overlay shell so the backdrop/header/close behavior is maintained in one place. Pair with `behavior("openDrawer"/"closeDrawer")` (or a unified `behavior("openOverlay"/"closeOverlay")`) to eliminate the `openDrawerExpr`/`closeDrawerExpr` raw-string helpers.
