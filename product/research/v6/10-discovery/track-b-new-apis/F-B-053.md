# AuthCard + OAuthDivider + SocialButtons reimplemented in 4 apps

## Problem

Every app with OAuth auth defines the same three view helpers: a centered card wrapper (`AuthCard`), a horizontal rule with "Or continue with" text (`OAuthDivider`), and a list of social login anchor buttons (`SocialButtons`). The structure is structurally identical across all four apps; only the brand colors differ.

```ts
// storysell-ai/src/auth/auth.components.ts:13
export function AuthCard({ title, subtitle, content }: AuthCardProps) {
  return Div(
    Div(H1(title).textSize("2xl").bold().textColor("gray-900").margin("b","2"),
        P(subtitle).textColor("gray-600"))
      .textAlign("center").margin("b","8"),
    content,
  ).addClass("glass-card").rounded("2xl").padding("8").w("full").maxW("md").margin("x","auto");
}
```

```ts
// glimm/src/auth/auth.components.ts:13
export function AuthCard({ title, subtitle, content }: AuthCardProps) {
  return Div(
    Div(H1(title).textSize("2xl").bold().textColor("deep").margin("b","2"),
        P(subtitle).textColor("deep-soft"))
      .textAlign("center").margin("b","8"),
    content,
  ).background("foam").rounded("2xl").shadow("sm").border().borderColor("sand-2")
   .padding("8").maxW("md").margin("x","auto");
}
// OAuthDivider and SocialButton/SocialButtons below: structurally identical
```

```ts
// mngmt/src/auth/auth.view.ts:53  (same three-helper pattern, inlined in the same file)
function AuthCard({ title, subtitle, content }: AuthCardProps): View { ... }
function OAuthDivider(): View { ... }
function SocialButton({ label, href }: SocialButtonProps): View { ... }
function SocialButtons(): View { return Div(OAuthDivider(), Div(SocialButton(...))) }
```

```ts
// rideshare/src/auth/auth.components.ts:51  (variant: positional args instead of props object)
export function AuthCard(title: string, subtitle: string, content: View) { ... }
```

## Evidence

- `storysell-ai/src/auth/auth.components.ts:13-76`: `AuthCard`, `OAuthDivider`, `SocialButton`, `SocialButtons`
- `glimm/src/auth/auth.components.ts:13-78`: identical four functions (brand colors: `"deep"`, `"foam"`, `"sand-2"`)
- `mngmt/src/auth/auth.view.ts:51-99`: same four functions inlined, OAuth href hardcoded as `"/auth/oauth/google"`
- `rideshare/src/auth/auth.components.ts:51`: `AuthCard` (positional), plus `OAuthDivider` in separate `auth.oauth-components.ts:29`

The recon doc (`02-app-patterns.md:191`) flags this: "`AuthCard` + `OAuthDivider` + `SocialButton(s)` — storysell `auth.components.ts:13-76`, glimm `auth.components.ts`, vabilo30 → `AuthShell`/`OAuthButtons`". vabilo30 is a fifth instance.

## Why it matters

The prop shape diverges already (storysell/glimm use `{ title, subtitle, content }`, rideshare uses positional args). Fixing a UX issue — e.g. adding keyboard focus management to the card, or changing the divider text — requires editing 4+ files. The OAuth href in mngmt is hardcoded (`"/auth/oauth/google"`) rather than using `oauthRoutes.authorize.resolve(...)`, which is the correct pattern in the other apps — a maintainability gap that only exists because it's copy-pasted.

## Rough idea (not a design)

`AuthShell({ title, subtitle, children })` as a fluent-html built-in that renders the centered card scaffold with a slot for form content. `OAuthButtons({ providers: Array<{ label, href }> })` for the divider + social button list. Both accept a theme-context token for the card background/border colors, so brand customization is a one-line context call rather than a fork of the component. The `href` is always a `string` (OAuth routes redirect to external providers so `setHref` is correct, not `setHtmx`).
