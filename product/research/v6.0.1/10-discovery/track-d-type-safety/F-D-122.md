# behavior() drops to `as any` and dereferences an unguarded renderer lookup

## Problem
`.behavior()` is registered with `(Tag.prototype as any)`, deliberately discarding the
typed overload at the implementation boundary. Inside, the implementation casts the
incoming `name: string` back to `BehaviorName` and indexes the `renderers` record
with it — with no existence check. A typed caller is safe, but any untyped/JS caller
(or a future built-in name added to the type but not the `renderers` map) gets
`renderer(options ?? {})` where `renderer` is `undefined`, producing a raw
`TypeError: renderer is not a function` with no actionable message.

This is inconsistent with the rest of the render layer, which explicitly guards
untyped callers with named errors (`buildHtmx`'s `STATUS_KEY_RE`/`BOOLEAN_ATTR_RE`
throws, and the `hxOn` event validation right below it).

## Evidence
```ts
// src/core/behavior-methods.ts:145
(Tag.prototype as any).behavior = function (name: string, options?: Record<string, unknown>) {
  if (this.attributes === EMPTY_ATTRS) this.attributes = Object.create(null) as Record<string, string>;

  const renderer = renderers[name as BehaviorName];   // :148 — no guard
  const [event, js] = renderer(options ?? {});         // :149 — crashes if renderer is undefined
```

Compare the deliberate, friendly guards a few lines over and in serialize.ts:
```ts
// src/core/behavior-methods.ts:153
if (!HX_ON_EVENT_RE.test(event)) {
  throw new Error(`Invalid behavior event: "${event}" — expected ...`);
}
```

## Why it matters
The `as any` is itself flagged in this track's mission (unsafe casts in core), and
here it actively hides a missing guard. The two surfaces this hits — JS consumers and
the "added to BehaviorMap but forgot the renderer" maintenance mistake — both fail
with a cryptic destructuring crash instead of `Unknown behavior: "<name>"`. It's a
one-line, no-shape-change robustness fix.

## Rough idea (not a design)
Add `if (!renderer) throw new Error(\`Unknown behavior: "${name}".\`)` before the
destructure. Optionally keep the `as any` but narrow it; the param could be typed
`BehaviorName` in the impl since the public overload already constrains callers. Pure
behavior fix, no public shape change. Ships 6.0.1.
