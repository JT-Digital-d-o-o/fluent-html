# `<script type>` and `<meta charset>` are untyped where a tiny enum drives behavior

## Problem
`<script type>` selects fundamentally different behavior — `module` (ESM), `importmap`, `speculationrules`, classic — and `<meta charset>` is, in practice, always `"utf-8"`. Both are bare `string`. A typo such as `.setType("moduel")` silently produces a classic non-module script (a real, hard-to-diagnose bug — the script's `import` statements throw at runtime), and there's no autocomplete to surface the four meaningful values.

## Evidence
```ts
// src/elements/document.ts:217  (ScriptTag)
type?: string;
// src/elements/document.ts:226
setType(type?: string): this {
// src/elements/document.ts:64  (MetaTag)
charset?: string;
// src/elements/document.ts:78
setCharset(charset?: string): this {
```

## Why it matters
`type="module"` is the single most consequential script attribute in a modern SSR app (ESM, deferred execution, strict mode). A silent typo downgrades to a classic script. `charset` is effectively a one-value attribute that today offers no hint. Both are open-union candidates so escape values (custom MIME types) still pass.

## Rough idea (not a design)
6.1.0 (additive): `export type ScriptType = 'module' | 'importmap' | 'speculationrules' | 'text/javascript' | (string & {})` and `export type Charset = 'utf-8' | (string & {})` in `html-types.ts`; re-type the fields + setters. Open unions → additive, no valid value dropped. No class emission → no tailwind/eslint vocab change.
