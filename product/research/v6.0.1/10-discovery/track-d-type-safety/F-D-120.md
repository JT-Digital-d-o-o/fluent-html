# defineSchemaKeys accepts bare `string[]` — schema keys are unchecked against the Tag's fields

## Problem
`defineSchemaKeys` is the ONE typed helper that registers which instance fields the
renderer emits as attributes. Its `keys` parameter is a bare `readonly SchemaKey[]`,
and `SchemaKey = string | readonly [prop, attr]` — both arms are unconstrained
`string`. Nothing ties the key to the actual property names of the class being
registered. A typo or a renamed field compiles cleanly and silently emits nothing,
because `buildAttrs` reads `bag[prop]` by string at runtime.

## Evidence
```ts
// src/core/proto.ts:18
export type SchemaKey = string | readonly [prop: string, attr: string];

// src/core/proto.ts:29
export function defineSchemaKeys(ctor: abstract new (...args: never[]) => Tag, keys: readonly SchemaKey[]): void {
  (ctor.prototype as unknown as NodeProto)._sk = keys;
}

// src/elements/forms.ts:107 — 15 magic strings, none checked against InputTag's fields
defineSchemaKeys(InputTag, ['type', 'name', 'placeholder', 'value', 'accept', 'min', 'max', 'step', 'pattern', 'minlength', 'maxlength', 'autocomplete', 'inputmode', 'capture', 'list']);
```

The runtime read that depends on these strings being real fields:
```ts
// src/render/serialize.ts:255
const value = bag[prop];
if (value !== undefined && value !== null) { attrs += ' ' + attr + '="' + ... }
```

If `'placeholder'` were misspelled `'placholder'`, `setPlaceholder()` would still set
`this.placeholder`, but `_sk` would point at `placholder` → `bag['placholder']` is
`undefined` → the attribute is silently never rendered. No test, no type error.

## Why it matters
This pattern runs across ~30 element classes (every `defineSchemaKeys` call in
`src/elements/**`). It is the exact "no magic constants / narrowest type" rule the
project's own TypeScript guideline preaches, applied to the renderer's attribute
contract — and it is the highest-leverage place a silent attribute-drop bug can
hide. Adding an element today is a hand-typed string list with zero compiler
backstop.

## Rough idea (not a design)
Make it generic: `defineSchemaKeys<C extends abstract new (...a: never[]) => Tag>(ctor: C, keys: readonly SchemaKeyOf<InstanceType<C>>[])` where `SchemaKeyOf<T> = (keyof T & string) | readonly [keyof T & string, string]`. Purely additive (the call sites already pass valid keys); turns every existing typo into a compile error. Ships 6.1.0.
