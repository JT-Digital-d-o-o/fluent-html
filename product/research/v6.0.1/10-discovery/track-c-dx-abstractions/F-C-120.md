# apply/when/whenElse reject the documented reusable style-fn pattern on element subclasses

## Problem
The composition core types every modifier as `(tag: this) => this`:

```ts
// src/core/tag.ts:246
apply(...fns: ((tag: this) => this)[]): this {
  for (const fn of fns) fn(this);   // return value is DISCARDED
  return this;
}
// src/core/tag.ts:214
when<T>(condition: T | null | undefined, fn: (tag: this, value: NonNullable<T>) => this): this;
```

On a real element subclass (`ButtonTag`, `InputTag`, `ImgTag`, `ATag`, … — `forms.ts:215` etc.), `this` is the subclass. A reusable style-fn typed `(t: Tag) => Tag` — exactly the pattern CLAUDE.md and `guidelines/web-development/fluent-html.md:120` teach (`const card = (t: Tag) => t.padding("6")…`) — does **not** satisfy `(tag: ButtonTag) => ButtonTag`, because the return type `Tag` is not assignable to `ButtonTag`. The `apply` body discards the return value anyway, so the constraint is pure friction.

## Evidence
Probe (strict, bundler resolution) against shipped source:

```
error TS2345: Argument of type '(t: Tag) => Tag' is not assignable to parameter of type '(tag: ButtonTag) => ButtonTag'.
  Type 'Tag' is missing the following properties from type 'ButtonTag': setType, setName, setValue, setFormaction, setFormmethod
error TS2345: Argument of type '(t: Tag) => void' is not assignable to parameter of type '(tag: ButtonTag) => ButtonTag'.
  Type 'void' is not assignable to type 'ButtonTag'.
```

`Div(...)` returns base `Tag` (`structural.ts:5`), so the guideline example happens to compile — but the very next teaching line `Button("Save").when(...).apply(card)` would not. The second error shows a void-returning modifier (a natural way to write a side-effecting style-fn, since the return is discarded) is also rejected.

## Why it matters
50+ element subclasses extend `Tag` (10 in forms, 9 in svg, 7 in media, …). Any shared style-fn library written against the base `Tag` type — the canonical composition primitive this track exists to enable — fails to typecheck on the most common interactive elements (Button, Input, Select, A, Img). Authors are forced to either over-narrow each helper per element or sprinkle `as` casts, defeating the reusable-style-fn ergonomics.

## Rough idea (not a design)
Loosen the modifier parameter type so the return is structurally irrelevant: `apply(...fns: Array<(tag: this) => unknown>)` (and the same on `when`/`whenElse`). This is additive (a contravariant widening of an accepted callback shape — existing call-sites still compile), so 6.1.0; carries a `guidelines/web-development/fluent-html.md` note and a regression test asserting `Button(...).apply(card)` compiles.
