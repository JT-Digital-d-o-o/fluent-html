# Children are constructor-only; no way to append a child during fluent composition

## Problem
Children can only be supplied positionally at construction:

```ts
// src/core/tag.ts:72
constructor(element: string, ...children: View[]) {
  this.el = element;
  this.child = children.length === 0 ? "" : children.length === 1 ? children[0]! : children;
}
```

There is no instance method to append children afterward. Yet the shipped `.when()` JSDoc demonstrates exactly that:

```ts
// src/core/tag.ts:212
*   .when(user.avatar, (t, avatar) => t.children(Img().setSrc(avatar)))
```

`t.children(...)` does not exist anywhere in `src/` — calling it is a runtime `TypeError`. The documented composition idiom (conditionally append a child via the modifier callback) is unreachable.

## Evidence
Grep for any `children` method on Tag returns only the constructor param and the JSDoc line; there is no `children(`/`addChild`/`appendChild` method definition. Because `this.child` is a `View | View[]` union built once in the constructor (`tag.ts:74`), the only composition path for children today is to compute the full child list before constructing the element — you cannot say "build the Button, then conditionally add an icon child." The natural fluent pattern (`Button("Save").when(loading, t => t.children(Spinner()))`) compiles against the JSDoc's promise but blows up at runtime.

## Why it matters
Conditional/iterative child composition is a core authoring need (append an icon, a badge, an error row) and is the one structural axis `.apply`/`.when` cannot touch — they can mutate classes/attrs but not children. This forces awkward pre-computation (`IfThen(...)` arrays assembled before the tag) and breaks the otherwise-uniform "construct then fluently refine" model. The dangling JSDoc means the gap is also actively mis-taught.

## Rough idea (not a design)
Add an additive `addChild(...views: View[]): this` (and/or `children(...)`) that normalizes `this.child` from scalar→array and appends, with the same escape-by-default treatment as constructor children. Update the `.when()` JSDoc to use the real method. Additive → 6.1.0. (Patch-only alternative for 6.0.1: at minimum fix the false JSDoc to not reference a non-existent method.)
