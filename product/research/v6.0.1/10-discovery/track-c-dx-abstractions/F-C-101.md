# ForEachElse accepts only readonly T[], not Iterable<T> — inconsistent with ForEach

## Problem
`ForEach` accepts any `Iterable<T>` (arrays, `Map.values()`, generators, paginators) — the implementation explicitly optimizes for that. Its sibling `ForEachElse`, introduced to mirror `IfThen→IfThenElse`, narrows the parameter to `readonly T[]` only. So the moment a caller has a `Set`, a `Map.values()`, or any lazy iterable and wants an empty-state fallback, `ForEachElse` rejects it at compile time and they must pre-spread into an array by hand.

```ts
// src/control/iteration.ts:93
export function ForEachElse<T>(
  items: readonly T[],                 // <- array-only
  renderItem: (item: T, index: number) => View,
  emptyView: View | (() => View),
): View {
  if (items.length === 0) { ... }
```

versus

```ts
// src/control/iteration.ts:26
export function ForEach<T>(
  views: Iterable<T>,                  // <- any iterable
  renderItem: (item: T, index: number) => View
): View;
```

## Evidence
The two functions live ten lines apart in the same file and deliberately advertise themselves as a mirrored pair (the `ForEachElse` doc comment says "mirrors `IfThen`→`IfThenElse`"), yet their input contracts diverge. A caller iterating `userMap.values()` with a "No users yet" fallback cannot use `ForEachElse` and is silently pushed back to `ForEach` + a separate `IfThen(size === 0, ...)`, re-creating exactly the empty-state boilerplate `ForEachElse` exists to remove.

## Why it matters
Low frequency (`ForEachElse` is brand-new and has 0 current call sites in the surveyed apps — itself an adoption signal), but the inconsistency is a paper cut that will bite the first non-array collection and undermines the "mirrored pair" mental model the docs promise. Type-safety guardrail: the asymmetry is arbitrary, not a deliberate narrowing.

## Rough idea (not a design)
Additive (6.1.0). Widen the first parameter to `Iterable<T>`; since the empty-check needs a count, materialize once (`const arr = Array.isArray(items) ? items : [...items]`) and proceed. Matches `ForEach`'s contract exactly and costs nothing for the common array case.
