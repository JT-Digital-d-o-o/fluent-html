# No guard-chain combinator (Cond / first-truthy-wins) — independent predicates selecting a value/view fall to nested ternaries

## Problem
`Match` (and the proposed value-mapping `pick`, F-C-100) dispatch on **equality against a single discriminant** — `Match(status, "status", {...})` looks up one key. But a large class of real selections are driven by **several independent boolean predicates**, not one value: "if confirmed → green, else if showing the confirm prompt → amber, else → neutral". There is no key to switch on; the conditions are unrelated booleans. The shipped control surface has nothing for this — `Match` requires a `string | number` discriminant:

```ts
// src/control/conditionals.ts:118
export function Match<T extends string | number>(
  value: T,
  cases: { [K in T]: Thunk<View> }
): View;
```

and `IfThen`/`IfThenElse` only branch two ways:

```ts
// src/control/index.ts:2
export { IfThen, IfThenElse, Match } from "./conditionals.js";
```

So a 3+-way predicate selection has no primitive and collapses to a nested ternary.

## Evidence
These are not value-equality lookups — each arm is its own boolean expression, so neither `Match` nor a `pick` can express them:

```ts
// rideshare/src/reservations/reservations.view.ts:243
const panelBg     = isConfirmed ? "green-50"  : showConfirmPrompt ? "amber-50"  : "site-bg";
// rideshare/src/reservations/reservations.view.ts:244
const panelBorder = isConfirmed ? "green-200" : showConfirmPrompt ? "amber-200" : "site-border";

// rideshare/src/rides/rides.components.ts:258
.borderColor(
  hasActiveReservation && userReservation?.status === "PENDING"   ? "blue-300"  :
  hasActiveReservation && userReservation?.status === "CONFIRMED" ? "green-300" :
  "site-border"
)
```

Nine such nested-predicate ternaries were found across rideshare/ttl/tela. Each selects a **class-vocab token** (`green-50`, `blue-300`) that the ternary keeps as a bare string off the fluent surface — the extractor still sees the literal, but the author gets no exhaustiveness, no narrowing, and the longest of these (`rides.components.ts:258`) mixes two predicates per arm with no compile-time guarantee the arms are mutually exclusive or total.

## Why it matters
Predicate-chain selection (status panels, badge colors, conditional row backgrounds) is a staple of SSR app UI, and it is exactly the place a missed/overlapping case ships silently. F-C-100 closes equality-keyed mapping; this is the orthogonal predicate-keyed case it explicitly cannot reach. Without it the ternary chain stays the only tool — verbose, unexhaustible, and a magnet for the same naked-conditional drift the control combinators exist to prevent.

## Rough idea (not a design)
Additive (6.1.0). A `Cond` first-match combinator over `[predicate, result]` pairs with a required default, in two flavors mirroring `Match`/`pick`: a value-returning `Cond([[isConfirmed, "green-50"], [showPrompt, "amber-50"]], "site-bg")` (returns the union of the value types) and a View-returning form for branch selection. Pure combinator, zero deps, no break to `Match`. Pairs with a views.md note steering predicate chains off nested ternaries.
