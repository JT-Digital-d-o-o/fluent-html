# `[${string}]` lets a runtime value into a class string the safelist will never see

## Problem
The arbitrary arm on color/size/etc. types is `` `[${string}]` ``. That template-literal type accepts **any** interpolated string, including one built from a runtime variable: `.background(\`[${userColor}]\`)` or `.textSize(\`[${size}px]\`)`. It type-checks. It renders. But the static extractor's `parseLiteralArgs` bails the instant an argument is a non-literal expression, so the resulting `bg-[…]` class is classified *unresolved* and never lands in the v4 safelist — the element ships unstyled in production while looking correct in dev (where the JIT may have seen a sibling literal).

## Evidence
The arbitrary arm is an open string-template:

```ts
// src/core/tailwind-types.ts:86
  | `[${string}]`;   // arbitrary value (e.g. [#1a2b3c]) — but `[${runtimeVar}]` also matches
```

The render path just interpolates it straight into a class with no analysis:

```ts
// src/core/tailwind-methods.ts:381
p.background = function (color: string) { return this.addClass(`bg-${color}`); };
```

The extractor cannot recover it — any non-literal arg yields `null` and the call is logged as unresolved, emitting **no** class:

```ts
// fluent-html-tailwind-extractor/src/extract.ts:88
    else return null; // variable / expression / call — not statically resolvable
```

So the type system green-lights exactly the pattern the build tooling silently cannot support. There is no compile-time, lint-time, or render-time signal; the failure mode is "works on my machine, blank in prod."

## Why it matters
This is the canonical Tailwind footgun (dynamic class names) reintroduced *through the typed API* — the one place the library promised to prevent it. It is high-pain because the failure is invisible and intermittent, and it hits exactly when a developer reaches for the escape hatch (theming, data-driven colors, computed sizes), which is the moment they most trust the types.

## Rough idea (not a design)
Additive (6.1.0): a small typed arbitrary-value primitive that is both runtime-safe and statically greppable (a branded wrapper the extractor recognizes), plus an extractor diagnostic that distinguishes "interpolated arbitrary inside a vocab method" from a benign unresolved call and surfaces it. Optionally a dev-only serializer assertion that a class literal contains no `${`. No breaking change — the raw arm remains for genuinely-static brackets.
