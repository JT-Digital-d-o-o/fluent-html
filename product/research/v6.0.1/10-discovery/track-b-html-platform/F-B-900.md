# Per-element dir/lang/translate globals are unreachable as typed setters

## Problem
`dir`, `lang`, and `translate` are **global** HTML attributes — they apply to every
element, not just `<html>`. But in v6.0.0 the only typed setters for them live on
`HtmlTag`. The base `Tag` (everything you build a page out of — `Div`, `Span`, `P`,
`Bdi`, `Blockquote`) has `setId`, `setTitle`, `setTabindex`, `setRole`, `setNonce`,
but **no `setDir` / `setLang` / `setTranslate`**.

```ts
// src/core/tag.ts:320 — base Tag globals stop at role/tabindex/title/nonce
setRole(role: AriaRole): this { ... }
setTabindex(index: number): this { ... }
setTitle(title: string): this { ... }
// (no setDir / setLang / setTranslate)
```

```ts
// src/elements/document.ts:11,17 — dir/lang exist ONLY on HtmlTag
setLang(lang?: string): this { ... }
setDir(dir?: 'ltr' | 'rtl' | 'auto'): this { ... }
```

So the moment you need direction or language on anything below `<html>` you fall back
to the stringly-typed escape hatch:

```ts
Span("مرحبا").addAttribute("dir", "rtl")            // ✗ no typed setter
Bdi(userName).addAttribute("dir", "auto")           // ✗ the canonical bdi use-case
Blockquote(quote).addAttribute("lang", "fr")        // ✗ for :lang() + screen readers
```

## Evidence
- `src/core/tag.ts:320` — the base-`Tag` global setters end at `setRole`/`setTabindex`/`setTitle`/`setNonce`; no direction/language globals.
- `src/elements/document.ts:11` / `:17` — `setLang` and the typed `'ltr'|'rtl'|'auto'` `setDir` are scoped to `HtmlTag`, unavailable on the elements that actually need per-node bidi.

## Why it matters
Three real, recurring surfaces, all accessibility-load-bearing:
1. **`dir="auto"` on user-generated content** (comments, usernames, chat) — the
   primary `<bdi>` use-case; without it RTL names corrupt surrounding LTR layout.
2. **`lang` on mixed-language runs** (`<span lang="fr">`, quotes, code) — screen
   readers switch pronunciation on it and CSS `:lang()` selectors depend on it.
3. **`translate="no"`** on brand names / code that must not be machine-translated.

These aren't exotic — any app rendering user content or multilingual copy hits #1/#2.
The typed `'ltr'|'rtl'|'auto'` union already exists on `HtmlTag`; it just isn't exposed
where it's most needed. Today every site doing it reaches for `addAttribute`, which the
eslint-plugin can't vet for valid values.

## Rough idea (not a design)
Promote `setDir` / `setLang` to the base `Tag` (reuse the existing `'ltr'|'rtl'|'auto'`
union), and add `setTranslate('yes'|'no')`. Purely additive (6.1.0) — `HtmlTag` keeps
its overrides or inherits. No class-string emitted, but the guidelines + JSDoc + the
"globals" doc surface need the new methods documented.
