# No typed Popover API surface

## Problem
The HTML Popover API (`popover`, `popovertarget`, `popovertargetaction`) is a baseline-available, JS-free way to build menus, tooltips, and dismissible overlays with light-dismiss and top-layer rendering. fluent-html v6.0.0 exposes **none** of it. There is no `popover` value in the boolean/enumerated attribute surface, and no `popovertarget` setter on `ButtonTag`.

`popover` is an *enumerated* attribute (`auto` | `manual` | `hint`, with `""`/bare meaning `auto`), so it cannot ride the closed `BooleanAttribute` union used by `.toggle()`:

```ts
// src/elements/html-types.ts:58
export type BooleanAttribute =
  | 'allowfullscreen' | 'async' | 'autofocus' | 'autoplay' | 'checked'
  ...
  | 'readonly' | 'required' | 'reversed' | 'selected';   // no 'popover', no enumerated values
```

`ButtonTag` has typed setters for `type`/`name`/`value`/`formaction`/`formmethod` but nothing for popover invocation:

```ts
// src/elements/forms.ts:215
export class ButtonTag extends Tag {
  type?: 'submit' | 'reset' | 'button';
  name?: string;
  value?: string;
  formaction?: string;
  formmethod?: 'get' | 'post';
  ...
}
```

The only escape is the untyped `addAttribute(key, value)` (src/core/tag.ts:158), which discards the type-safety-first guardrail and gives no autocomplete for the action enum.

## Why it matters
Popovers are the platform-blessed primitive for exactly the overlay/menu/tooltip patterns an SSR + HTMX app builds constantly. Today an author must hand-write `.addAttribute("popover","auto")` on the panel and `.addAttribute("popovertarget", String(id))` + `.addAttribute("popovertargetaction","toggle")` on the trigger — three raw strings, no enum guard, and `id` stringification done by hand. This is precisely the "real platform capability reachable only via addAttribute/raw strings" the Track B mission targets.

## Rough idea (not a design)
Additive (6.1.0): a `PopoverState = "auto" | "manual" | "hint"` union with a global `.setPopover(state?)` on `Tag`, plus `.setPopovertarget(id: Id)` and `.setPopovertargetaction(action: "show" | "hide" | "toggle")` on the invoking tags (Button, Input[type=image/submit/button]). No class strings, so no tailwind/eslint vocab churn; carries a guidelines edit and JSDoc.
