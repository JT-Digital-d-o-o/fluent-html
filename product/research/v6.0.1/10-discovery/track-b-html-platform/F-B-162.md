# No Speculation Rules primitive

## Problem
The Speculation Rules API (`<script type="speculationrules">{…JSON…}</script>`) is the modern, document-rule way to prefetch/prerender same-origin navigations — it supersedes `<link rel=prefetch>` for full-page speculation and is the recommended pattern for instant navigations in an MPA/SSR app like this one. There is no primitive for it. The only path is hand-writing the JSON into `Script("…")`, which (a) has no typed rule-set shape and (b) puts author-controlled JSON into a script body with no structured escaping guarantee.

## Evidence
`ScriptTag` exists but only types `src`/`type`/`crossorigin`/`integrity`; its body is an arbitrary string:

```ts
// src/elements/document.ts:244
export function Script(js: string = ""): ScriptTag {
  return new ScriptTag("script", js);
}
```

To emit speculation rules today an author must do `Script(JSON.stringify({ prerender: [{ where: { href_matches: "/*" } }] })).setType("speculationrules")` — `setType` accepts a bare string (document.ts:226), the JSON shape is unchecked, and there is no helper guiding the `where`/`eagerness`/`source` schema. No `speculationrules` reference exists anywhere in `src/`.

## Why it matters
Instant navigation via prerender is a headline performance feature for SSR/HTMX apps and the natural successor to the resource-hint links in [[F-B-161]]. Low frequency (one block per page/layout) but the manual JSON path is both error-prone and an escaping smell. A typed combinator turns a fiddly raw-string into an instruction-set primitive.

## Rough idea (not a design)
Additive (6.1.0): a `SpeculationRules(ruleset)` combinator with a typed ruleset type (`prefetch`/`prerender` arrays, `where` URL-pattern/list-rule shapes, `eagerness`), emitting a `<script type="speculationrules">` whose serialized body is JSON-encoded (no `</script>` break-out). Bar check: this is a thin typed wrapper over a platform script type, not a UI component, so it fits the instruction-set guardrail.
