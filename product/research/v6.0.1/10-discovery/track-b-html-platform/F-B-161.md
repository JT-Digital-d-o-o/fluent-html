# LinkTag rel/as are bare strings — resource hints are untyped

## Problem
`<link rel=…>` is the head-performance workhorse: `preconnect`, `dns-prefetch`, `preload`, `modulepreload`, `prefetch`, `prerender`, `stylesheet`, `icon`, `manifest`, `alternate`. On `LinkTag` the `rel` field is a bare `string`, so none of these are autocompleted or typo-checked. The companion `as` attribute (`script`/`style`/`font`/`image`/`fetch`/…), which is *mandatory and validated by the browser* for `rel=preload`, is also a bare `string`.

## Evidence
```ts
// src/elements/document.ts:102, 109
export class LinkTag extends Tag {
  rel?: string;          // bare string — no resource-hint union
  ...
  as?: string;           // bare string — preload destination unchecked
}
```

`setRel(rel?: string)` (document.ts:112) and `setAs(as?: string)` (document.ts:153) accept anything. Worse, the project *has* a `LinkRel` union (html-types.ts:30) — but it covers only anchor-style rels (`noopener`, `nofollow`, `author`, …) and is applied to `AnchorTag`/`AreaTag`, **not** to `LinkTag`, and it omits every resource-hint keyword (`preconnect`, `preload`, `modulepreload`, `dns-prefetch`, `prefetch`, `prerender`, `stylesheet`, `icon`, `manifest`):

```ts
// src/elements/html-types.ts:30
export type LinkRel =
  | 'noopener' | 'noreferrer' | 'nofollow' | 'external' | 'author'
  | 'bookmark' | 'help' | 'license' | 'next' | 'prev' | 'search' | 'tag'
  | (string & {});
```

## Why it matters
`<link rel=preload as=font crossorigin>` and `<link rel=preconnect>` are the standard first-paint optimizations every SSR head emits. A typo (`rel="prelaod"`, `as="fonts"`) silently no-ops at runtime with zero compile feedback — the exact failure mode Track B's closed unions prevent elsewhere. Medium frequency (head-of-document, a handful per app), medium pain (silent perf regressions, not crashes).

## Rough idea (not a design)
Additive (6.1.0): add a `LinkElementRel` union (resource hints + document rels) and a closed `LinkAs` destination union in html-types.ts; retype `LinkTag.rel`/`setRel` and `.as`/`setAs`. Keep a `(string & {})` tail only if forward-compat for new rel keywords is wanted. Co-requisite with `fetchpriority` ([[F-B-160]]) since both ride the preload path.
