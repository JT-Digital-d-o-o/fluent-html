# hidden="until-found" is unreachable as a typed primitive

## Problem
`hidden` is modeled only as a closed boolean attribute toggled by `.toggle("hidden")`. The HTML `hidden` attribute also accepts the enumerated value `until-found`, which keeps the subtree collapsed but searchable via find-in-page / fragment navigation and fires a `beforematch` event when the browser reveals it. That enumerated form cannot be expressed through the boolean union, and there is no typed setter for it.

## Evidence
```ts
// src/elements/html-types.ts:58
export type BooleanAttribute =
  | 'allowfullscreen' | 'async' | 'autofocus' | 'autoplay' | 'checked'
  | ...
  | 'hidden' | 'inert' | 'ismap' | 'itemscope' | 'loop' | 'multiple'
```
```ts
// src/core/tag.ts:190
toggle(name: BooleanAttribute, condition: boolean = true): this { ... }
```
`.toggle("hidden")` only emits a bare `hidden` (= `hidden=""`). To get `hidden="until-found"` a caller must drop to `.addAttribute("hidden", "until-found")`, an untyped raw string. The paired `beforematch` event likewise has no acknowledged path; `.hxOn` exists but nothing teaches it for this.

## Why it matters
`hidden=until-found` is the platform primitive for collapsible/accordion content that must remain Ctrl-F findable (FAQ entries, long-form docs, lazy-revealed sections) — a common SSR pattern. Today it is reachable only via the untyped escape hatch, which the project's own guidelines forbid for standard props.

## Rough idea (not a design)
Additive (6.1.0): a `.hidden(mode?: "until-found")` setter on `Tag` — no args (or `true`) emits bare `hidden`, `"until-found"` emits the enumerated form. Keep `.toggle("hidden")` working. Document `beforematch` via `.hxOn`.
