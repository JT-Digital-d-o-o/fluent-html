# TailwindState lacks the `:has()` / `:in()` relational class hooks

## Problem
The `:has()` relational pseudo-class is the single biggest CSS platform shift of the TW4 era — it lets a parent restyle itself based on descendant state with zero JS. Tailwind v4 exposes it as the `has-[...]`, `group-has-*`, and `peer-has-*` variants, plus the new `in-*` (implicit-group ancestor) variant. The `TailwindState` union — the closed set `.on()` accepts — ships none of them. The only escape route added by v4 is the `supports-[…]` / `nth-[…]` / `not-${string}` arms; there is no `has-` arm, so a relational hook can only be reached via raw `.addClass("has-[:checked]:bg-blue-50")`, which the `no-setclass-after-fluent-modifier` ESLint rule and the converge philosophy both discourage.

## Evidence
```ts
// src/core/tailwind-types.ts:219
export type TailwindState =
  | "hover" | "focus" | "focus-within" | "focus-visible"
  ...
  | "group-hover" | "group-focus" | "group-active" | "group-disabled"
  | "peer-hover" | "peer-focus" | "peer-checked" | "peer-invalid"
  // v4 (C-06): new states + the `not-*` negation, `supports-[…]`, `nth-[…]` arms
  | "print" | "motion-reduce" | "motion-safe" | "portrait" | "landscape"
  | "starting" | "open" | "inert"
  | `not-${string}` | `supports-[${string}]` | `nth-[${string}]`;   // ← no has-/group-has-/peer-has-/in-
```
`.on()` simply prefixes the state token (`src/core/tailwind-methods.ts:88` `withVariant`), so adding union arms is sufficient — no emitter change. There is no `has-` token anywhere in `src/`.

## Why it matters
`:has()` is Baseline-stable and a headline reason teams adopt TW4. A form that highlights its wrapper when a child is invalid (`has-[:invalid]:border-red-500`), a card that lifts when it contains a checked checkbox (`has-[:checked]:ring-2`), or "style me if my parent matches" (`in-[.dark]:text-white`) are all idiomatic v4 patterns. Today every one of them forces the raw-string escape hatch, defeating the type-safety + autocomplete that `.on()` exists to provide.

## Rough idea (not a design)
Additive (6.1.0): extend `TailwindState` with `` `has-[${string}]` ``, `` `group-has-[${string}]` ``, `` `peer-has-[${string}]` ``, and `` `in-[${string}]` `` arms. No runtime/emitter change (the prefix passes through `withVariant`). Coordinate with class-vocab: these are variant prefixes, not utilities, so the extractor must keep the full `has-[…]:utility` string intact rather than splitting it.
