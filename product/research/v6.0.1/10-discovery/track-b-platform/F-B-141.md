# DialogTag has no `closedby` setter

## Problem
`DialogTag` is an empty subclass with no element-specific setters. The modern `<dialog>` `closedby` attribute (`any` | `closerequest` | `none`) controls light-dismiss behavior (click-outside / Esc) for both modal and non-modal dialogs and is the standards-track replacement for hand-rolled `dismissOnEscape` JS. There is no typed way to set it.

## Evidence
```ts
// src/elements/interactive.ts:25
export class DialogTag extends Tag {
}

defineSchemaKeys(DialogTag, []);

export function Dialog(...children: View[]): DialogTag {
  return new DialogTag("dialog", ...children);
}
```
Compare `DetailsTag.setName` directly above it (line 9) — the pattern for a typed enumerated attribute already exists in the same file. `DialogTag` simply hasn't received its one platform setter, so `closedby` requires `.addAttribute("closedby", "any")` (untyped, no autocomplete, typo-prone).

## Why it matters
The library ships a `dismissOnEscape` behavior and an `openDialog`/`closeDialog` behavior pair, signaling `<dialog>` is a first-class supported pattern. `closedby="any"` makes click-outside dismissal declarative and removes JS — but it is the one piece a user can't reach typed. Anyone building a modal hits this.

## Rough idea (not a design)
Additive (6.1.0): `DialogTag.setClosedBy(value: "any" | "closerequest" | "none")` with `defineSchemaKeys(DialogTag, ['closedby'])`. Closed union, no escape hatch.
