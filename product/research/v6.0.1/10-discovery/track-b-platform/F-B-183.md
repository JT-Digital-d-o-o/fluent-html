# Scroll-driven animations are unreachable as typed primitives

## Problem
Scroll-driven animations (`scroll-timeline` / `view-timeline` named timelines + `animation-timeline` consumption, with `animation-range`) are the TW4-era way to do scroll progress bars, reveal-on-enter, and parallax with zero JS and zero `IntersectionObserver`. fluent-html's animation surface is only `.animate(name)` (vocab.ts:180), which sets `animation-name` but cannot attach a *timeline*. There is no `animation-timeline`, `scroll-timeline`, `view-timeline`, or `animation-range` method, and the `TailwindTransition` union (tailwind-types.ts:172) is unrelated (it covers old `transition-property`). Grep confirms total absence in `src/`.

## Evidence
```ts
// src/class-vocab/vocab.ts:177
opt("transition", "transition"),
pre("duration", "duration"),
pre("animate", "animate"),    // ← animation-name only; no timeline attachment
pre("ease", "ease"),
```
A scroll-linked element today requires `addAttribute("style", "animation-timeline: scroll();")` — untyped, unsafelistable inline CSS.

## Why it matters
Lower frequency than `:has()`/view-transitions, but it is the one remaining "zero-JS motion" platform feature with no fluent path, and it fits the SSR-only / zero-runtime-dep constitution perfectly: the entire effect is declarative CSS the server emits once. Leaving it to inline `style` strings is the same escape-hatch tax as the other CSS hooks in this cluster.

## Rough idea (not a design)
Additive (6.1.0): `.scrollTimeline(name?)`, `.viewTimeline(name?)`, `.animationTimeline(name | "scroll()" | "view()")`, and `.animationRange(start, end)` — each emitting a v4 arbitrary-property class (`[scroll-timeline-name:--x]`, `[animation-timeline:--x]`, …). Register the arbitrary-property shapes in the extractor vocab. Smallest-footprint member of the CSS-hooks cluster; can ship last.
