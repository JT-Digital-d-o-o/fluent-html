# Variadic-children "\n" separator corrupts <textarea>/<pre> content

## Problem
When a tag has more than one child, the serializer inserts a literal newline
between siblings:

```ts
// src/render/serialize.ts:358-362 (emitChunks; emit is the twin at :444-447)
// Emit v[0] '\n' v[1] '\n' … v[len-1]. Push reversed so v[0] pops first.
for (let i = len - 1; i >= 0; i--) {
  stack.push({ v: v[i]!, c });
  if (i > 0) stack.push('\n');
}
```

For most elements the inter-child `\n` is cosmetic whitespace the browser
collapses. But `<textarea>` and `<pre>` are whitespace-significant: every
character between the tags is part of the value / rendered output. Injecting a
`\n` the author never wrote silently changes the data.

## Evidence
Reproduced against the shipped build:

```
render(Textarea("line1 ", "line2"))
  → <textarea>line1 \nline2</textarea>
```

The textarea's submitted value is now `line1 \nline2` — a spurious newline. An
author writing `Textarea("Hello, ", userName)` to interpolate a value gets a
line break injected mid-string. Same for `<pre>`:

```
render(Pre(Span("a"), Span("b")))
  → <pre><span>a</span>\n<span>b</span></pre>
```

The `\n` becomes a visible blank between the spans in the rendered `<pre>`.

There is no element-aware suppression: the separator branch at
serialize.ts:358 / :444 runs for every multi-child tag regardless of `el`. (The
serializer already special-cases `script`/`style` for the *escaping* context at
serialize.ts:348/:431, so an element-aware hook exists — it just doesn't cover
the separator.)

## Why it matters
`<textarea>` prefilled from parts is a common form pattern (edit views,
draft restoration), and the corruption is invisible in a casual eyeball of the
HTML — it only shows up as an extra blank line in the user's text or a failed
round-trip test. `<pre>` (code blocks, logs, ASCII) is the other classic
whitespace-significant element. Both silently render wrong content today. This
is squarely a 6.0.1 correctness fix.

## Rough idea (not a design)
6.0.1, no shape change: when `el` is `textarea` or `pre` (the HTML
whitespace-significant content elements), join multi-children with `""` instead
of `"\n"` — i.e. gate the separator push on the element. Single-child and
text-content cases are already separator-free, so the fix is localized to the
`len > 1` branch in both `emit` and `emitChunks`. Add a parity test
(ties into [[F-A-101]]).
