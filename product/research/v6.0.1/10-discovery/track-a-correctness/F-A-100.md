# .toggle() emits duplicate boolean attributes

## Problem
`.toggle(name)` blindly pushes the attribute name onto `this.toggles` with no
idempotency. Toggling the same boolean attribute twice — directly, or once
explicitly and once through a conditional helper / re-applied component
(`.apply`, `.when`) — emits the attribute name twice into the open tag. It also
does not reconcile with the same attribute set via `_sk` or `addAttribute`.

```ts
// src/core/tag.ts:190
toggle(name: BooleanAttribute, condition: boolean = true): this {
  if (condition) {
    if (this.toggles) {
      this.toggles.push(name);          // ← no "already present?" check
    } else {
      this.toggles = [name];
    }
  }
  return this;
}
```

```ts
// src/render/serialize.ts:280-289 — joined verbatim, duplicates and all
const toggles = tag.toggles;
if (toggles !== undefined && toggles.length > 0) {
  for (...) { /* only validates the NAME regex, no dedup */ }
  attrs += ' ' + toggles.join(' ');
}
```

## Evidence
Reproduced against the shipped build (both the eager `render` and the streaming
`renderToIterable` paths — they share `buildAttrs`, so the bug is path-agnostic):

```
render(Option("x").toggle("selected").toggle("selected"))
  → <option selected selected>x</option>

render(Input().toggle("required").toggle("required"))
  → <input required required>

render(Input().toggle("disabled").addAttribute("disabled","disabled"))
  → <input disabled="disabled" disabled>      // both forms, same attribute

[...renderToIterable(Input().toggle("required").toggle("required"))].join("")
  → <input required required>                  // stream path identical
```

The serializer guards toggle names against injection (`BOOLEAN_ATTR_RE`) but
never dedups, so well-formed-but-doubled output ships.

## Why it matters
Boolean toggles are everywhere — `required`, `disabled`, `selected`, `checked`,
`readonly`, `inert` — and the framework actively encourages re-applying styling
mixins (`.apply(card)`, `.when(...)`) and conditional toggles
(`.toggle("selected", city === current)`). Any path that can run a toggle twice
(loop, composed mixin, re-render of a shared component that toggles on a prop)
silently doubles the attribute. Browsers tolerate duplicate attributes (first
wins per the HTML parser), but the output is malformed, defeats byte-identical
snapshot tests, and the `disabled="disabled" disabled` mix looks like a bug to
anyone reading the DOM. The `set*` vs `add*` convention (memory) implies a
boolean attribute is *set* (present-or-absent), not *accumulated* — current
behavior contradicts that contract.

## Rough idea (not a design)
6.0.1 patch, no shape change: make `toggles` set-like — on `toggle()`, skip the
push if the name is already in the array (cheap; the list is tiny), and at
serialize time skip a toggle name already emitted via `_sk`/`attributes`. Add a
test asserting `toggle(x).toggle(x)` and `toggle(x)+addAttribute(x)` each emit
the attribute exactly once.
