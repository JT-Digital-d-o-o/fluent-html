# Compound-attribute setters mix intercaps and lowercase tails

## Problem
The public setter surface is internally inconsistent about how multi-word HTML attribute names are camelCased. Some setters intercap the second word; the majority lowercase it. There is no rule a user can predict, so every compound setter is an autocomplete guess.

Intercapped: `setHttpEquiv`, `setCrossOrigin`, `setViewBox`.
Lowercase-tail: `setInputmode`, `setMaxlength`, `setMinlength`, `setFormmethod`, `setFormaction`, `setSrcdoc`, `setSrclang`, `setSrcset`, `setHreflang`, `setColspan`, `setRowspan`, `setTabindex`.

## Evidence
```ts
// src/elements/document.ts:84
setHttpEquiv(httpEquiv?: HttpEquiv): this {

// src/elements/document.ts:143
setCrossOrigin(crossorigin?: CrossOrigin | ''): this {

// src/elements/media.ts:253
setViewBox(viewBox: string): this {

// src/elements/forms.ts:90
setInputmode(inputmode?: InputMode): this {

// src/elements/forms.ts:242
setFormmethod(formmethod?: 'get' | 'post'): this {

// src/elements/embedded.ts:22
setSrcdoc(srcdoc?: string): this {
```
`setInputmode` (one word lowercased) sits beside `setCrossOrigin` (two words intercapped) for attributes with the same shape (`inputmode`, `crossorigin` are both single lowercase HTML tokens). `setViewBox`/`setHttpEquiv` intercap; `setSrcdoc`/`setSrclang` do not. The HTML attributes themselves are all lowercase, so the only consistent rule is "method name == attribute name with `set` prefix" — which `setCrossOrigin`/`setHttpEquiv`/`setViewBox` violate.

## Why it matters
14 setters, every form/media/document author hits them. The inconsistency defeats IDE autocomplete (you type `setCross` and don't know if it's `setCrossorigin` or `setCrossOrigin`) and contradicts the convergence goal of v6 ("one way to do each thing").

## Rough idea (not a design)
Standardize on lowercase-tail (method mirrors the attribute token: `setCrossorigin`, `setHttpequiv`, `setViewbox`). Because renaming the existing three is breaking, ship the new spellings additively in 6.1.0 with the intercapped forms kept as `@deprecated` aliases, then drop the aliases in the next major (parked).
