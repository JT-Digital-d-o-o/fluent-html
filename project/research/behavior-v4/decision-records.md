# Behavior System v4 — Decision Records

Settled choices. Each records what was decided, why, and what was rejected — the anti-relitigation ledger.

## ADR-01 Emission grammar

**Decision:** ADR-01 Emission grammar: flat, per-verb-namespaced data attributes, frozen per major. data-behavior = ordered space-separated verb tokens (camelCase built-ins; extensions as <ns>:<verb>). Per verb V and option key K: data-behavior-<kebab(V)>-<kebab(K)>="value" (extension ns kebab-delimited with a double hyphen: data-behavior-jt--listbox-nav-target). Fixed serialization table: string=identity (normal HTML-attribute escaping), Id -> id string, Id[]/string[] -> space-separated, boolean -> "true"/"false", number -> decimal, enum -> literal, nested groups flatten with hyphens, targets serialize as <id> | "@self" | "closest:<selector>". event? overrides resolve at EMIT time (focus->focusin, blur->focusout, mouseenter->mouseover, mouseleave->mouseout); the runtime has no remap table. Duplicate same-verb .behavior() on one element throws at render time; the one inexpressible case (same verb on two different events on one element) is documented with the sanctioned workaround (wrap in a child element, or register an extension verb).

**Rationale:** Attributes-only emission deletes the entire escapeJs/injection class (9224eff exists only because v2 interpolated user data into JS source). Flat attributes are greppable, debuggable in devtools, and need zero client parser — no JSON.parse, no memoization WeakMap, no pathological-payload guards. Per-verb namespacing restores v1's multi-behavior semantics and fixes v3's cross-verb option collisions. Emit-time event remapping makes 'typed but dead at runtime' structurally impossible for events.

**Alternatives rejected:** JSON tuple array in one data-fx attribute (fx/Bedrock): denser but strictly less greppable, requires a real parser + parse-cache + payload guards in the runtime, and the security lens judged its escaping margin thinnest — one future 'compact encoding' away from an executable-config injection class. hx-on:* inline JS (v2): confirmed eval-based (AsyncFunction), dead under no-unsafe-eval, and couples to htmx internals (C4). Per-app formats / monkey-patching (v3): the C5 violation v4 exists to kill.

## ADR-02 Runtime delivery

**Decision:** ADR-02 Runtime delivery: one external, version-stamped, immutable static asset (fluent-behaviors.<pkgVersion>.js for built-ins-only; fluent-behaviors.<pkgVersion>.<registryHash>.js when extensions are registered), authored as TypeScript in fluent-html src/behaviors/client/, built at package publish (and re-assembled at app boot when extensions exist), loaded by exactly ONE nonce'd <script defer src> in the initial layout head under strict-dynamic. Never inline per-request JS, never scripts inside swap targets. Static serving glue lives in the framework layer (interim home per 2026-07-20 decision: projects-template templates/*/src/core/behaviors/; extraction to @fluent-html/fastify at the framework split), which registers the route and the head helper together and enables the X-Fluent-Behaviors skew-refresh header by default.

**Rationale:** Closes three confirmed attack findings against the inline variant at once: (1) the stale-nonce cache blast radius (any cached full-HTML response kills the whole inline runtime silently — byte-for-byte the v2->v3 silent-no-op failure); (2) app-authored handler source transiting fluent-html's Script() raw-body path, whose <!--<script double-escaped-state hardening is parked; (3) forfeited HTTP caching. dispatcher-patterns evidence names this the standard pattern (LiveView precedent). The framework-layer plugin wiring route+tag atomically mitigates fx's single-point-of-failure finding (forgotten route = everything dead); dev mode: the head helper throws at render if the runtime route is not registered, and C7 asserts the data-fluent-behaviors stamp.

**Alternatives rejected:** Inline nonce'd behaviorRuntime() string per navigation (UPSTREAM's original): nonce-replay surface, zero caching, injection-adjacent Script() body path. CDN delivery: violates self-hosted CSP posture. htmx script handling / inlineScriptNonce: documented CSP bypass.

## ADR-03 Binding and lifecycle

**Decision:** ADR-03 Binding and lifecycle: capture-phase document-level delegation, listener set computed from the single EVENT_TABLE at startup, zero per-element binding, zero teardown, no MutationObserver, no custom elements, no sticky-operation store. Behavior attributes are server-authoritative: a morph rewriting them is correct by contract; client-toggled classes are transient and revert on any swap/morph that re-renders them — always, on every idiomorph path (attribute-sync strips client-added classes even when node identity is preserved). The 'always closes / always reverts' contract is what C7 pins.

**Rationale:** Delegation is inherently idempotent across any number of swaps and morphs (C2 for free) and capture:true makes descendant stopPropagation unable to silently kill a behavior. The Stimulus/turbo #1210/#1224 failure class is unrepresentable because no client-written authority exists to desynchronize. The morph-lens attack proved fx's per-path-divergence claim wrong in the safe direction; we adopt the corrected uniform contract rather than encoding a falsehood in the acceptance matrix.

**Alternatives rejected:** MutationObserver connect/disconnect lifecycle (Stimulus): the expensive fragile half, plus morph corruption evidence. Custom elements: morph-engine lifecycle mishandling, Safari is= refusal, markup changes. LiveView sticky-op store: the single largest complexity add for zero inventory call sites needing client state to survive a morph; a future reactive demand spike is the only thing that reopens this.

## ADR-04 Dispatch semantics

**Decision:** ADR-04 Dispatch semantics: from composedPath()[0], walk ancestors via closest('[data-behavior]'), innermost carrier first, all matching verbs per carrier in declaration order. A handler returning true CONSUMES the event: the walk halts and no outer carrier's verbs run for that event. Built-in click/dblclick-triggered verbs consume by default (clicking a clipboard button never also toggles its row); keyboard verbs consume conditionally (listbox consumes Escape only when its list is open; onEscape consumes when it acted). Escape precedence when a drawer is open: drawer's close path runs first and consumes.

**Rationale:** Resolves both confirmed nested-carrier defects simultaneously: UPSTREAM's innermost-only silently dropped the outer form's onEscape the day an inner keydown extension appeared; fx's all-fire double-fired Escape (closing the listbox AND cancelling the edit, discarding typed input). Runtime-conditional consumption via handler return is the only mechanism that expresses 'consume Escape only when the list is open' — static .stop modifiers cannot.

**Alternatives rejected:** Innermost-only dispatch (silent outer drop); unconditional all-carriers-fire (double-fire); static-only modifier flags.

## ADR-05 Drawer

**Decision:** ADR-05 Drawer: ONE composite verb (non-modal overlays), state model = DOM predicates with the module slot demoted to a pure cache (truth = target.isConnected && target has open class). Full close routine specified: remove open class from target, remove backdrop class, remove bodyClass from <body>, set trigger aria-expanded=false if connected, restore focus to trigger if connected (else document.body), clear cache. Close-on-nav is GATED: on htmx:after:swap, close only if (a) the swap target contains the drawer or its trigger, or (b) the request was pushUrl-bearing navigation (defensive detail read); a background poll never closes it. A reconciliation sweep on every after:swap runs the full close routine whenever the cache exists but its target is no longer connected-and-open (kills dangling focus traps and leaked scroll-locks). Opening a drawer first fully closes any open drawer (at-most-one-open is enforced behavior, not undefined behavior). Focus trap is a document keydown capture listener guarded by the same DOM predicate, never by the raw slot.

**Rationale:** Incorporates every confirmed morph-lens and DX-lens finding: unconditional after:swap close upstreamed rideshare's own poll-closes-drawer bug as contract; slot-clear was not a full close (leaked overflow-hidden = unscrollable page, stranded focus); a dangling slot turned the focus trap into a document-wide Tab-killer; two sibling drawers broke the single slot undefined-ly. Mega-verb (not a command chain) because the inventory shows the identical bundle hand-rolled 4x with the same options; composition machinery pays for generality nobody asked for. Boundary: drawer accretes no options beyond this set without a new named call site (review-enforced).

**Alternatives rejected:** LiveView-style step chains + exec slots for composing the drawer (generality with no demand, and the fx sweep's hardcoded '.is-open' bug class); Bedrock's Tier-0-only answer (five silently-omittable pieces, dialog.showModal wrong for the responsive pinned-sidebar shape, closedby='any' not Baseline — Interop 2026); unconditional slot-clear on bare after:swap; nested-drawer stack (no inventory demand; the enforced close-then-open covers siblings).

## ADR-06 Native platform boundary

**Decision:** ADR-06 Native platform boundary: MODAL dialogs use the already-shipped native path — Button().setCommand("show-modal")/setCommandfor(id) + <dialog> with the new setClosedby("any"|"closerequest"|"none") setter; openDialog/closeDialog behavior verbs are deleted (the v6.0.1 parked deprecation executes). The drawer verb owns everything non-modal or responsive (mobile off-canvas that is pinned on desktop). Autocomplete panels use onClickOutside + toggle, NOT popover=auto.

**Rationale:** Takes Bedrock's genuinely best idea (platform absorbs modal focus trap/inert/Escape/top-layer natively, self-tearing-down under morphs) exactly where Baseline supports it, while the confirmed attacks bound it: popover=auto light-dismisses when clicking back into the anchor input (breaks autocomplete), closedby isn't cross-browser, and the responsive-sidebar production shape fits neither native primitive.

**Alternatives rejected:** Behavior verbs for dialogs (redundant with shipped Invoker Commands); popover=auto for dismissal cases (anchor-input defect, CSS anchor positioning not cross-browser); making native the only drawer answer (Bedrock's failed lens).

## ADR-07 Registry constraints

**Decision:** ADR-07 Registry constraints: server registration is DATA-ONLY — registerBehavior(name, spec) where spec = { options: Record<string, OptionType> (scalars/lists/enums/target only — no functions, no JSON blobs, no expressions), events (from the closed table; first = default), preventDefault?, consume?, fixtures (MANDATORY, >=1) }. The client handler is a REAL TypeScript module in the app (isolated client tsconfig with DOM lib, project-references layout shipped in the template) calling defineBehavior(name, (el, opts, fx) => boolean|void) with the mediated FxCtx; a library-shipped esbuild step (buildBehaviorRuntime) compiles app entries + core into the single hashed asset at boot or prebuild. The registry seals at asset build; registerBehavior after seal throws; rendering an unregistered verb throws in ALL modes including production; the asset embeds a hash of the registered names+option schemas, the server stamps <html data-fluent-behaviors="<version>:<hash>">, and the runtime asserts the match (mismatch = one loud console.error, a C7-gated failure, plus a server-boot check so name skew is a deploy-time error). Extension verbs MUST be namespaced <ns>:<verb> (ns >= 2 lowercase chars); registerBehavior throws on built-in override, kebab-prefix collision, or missing namespace.

**Rationale:** Kills all three rival extension mechanisms' confirmed failure modes: raw JS source strings (UPSTREAM — unlintable, spec/handler drift, unfenced C6 breach as-written), fn.toString serialization (fx — tslib helper injection and minifier mangling ship a runtime that is provably not the one C7 validated; works-in-dev-dies-in-prod is the founding failure class), and unbundled app-served handler files (Bedrock — no handshake, event-time console.error skew, worst first-extension cost). A real compile step with a browser target has no closure-capture or downleveling hazard by construction. Mandatory fixtures close the extension-C7 gap (a verb without coverage cannot register). The namespace rule defuses cross-package BehaviorMap merge conflicts and kebab-prefix ambiguity permanently. Unconditional render-throw makes v2-style silent no-ops impossible.

**Alternatives rejected:** client: string source (convention-only staticness, opaque to lint); fn.toString at boot; 'dev-mode only' render throw (prod silent no-op with extra steps); unprefixed extension names (TS2717 conflicts located in node_modules, import-order-dependent boot throws); post-boot registration (import-order fragility the v3 fork has today).

**Amendment (2026-07-20, maintainer decision): registration is FRAMEWORK-LAYER ONLY — apps can never extend.** `registerBehavior`/`defineBehavior`/`buildBehaviorRuntime` are internal to the framework layer (@fluent-html/fastify / the projects-template core, names TBD per the framework split); apps have zero registration surface. New verbs enter via a framework PR + template bump ("fix once, every app gets it"), never app-locally. Consequences: (a) the extension namespace collapses to one framework prefix (`jt:`) — per-app prefixes like `rs:` are dead; (b) the extended runtime is prebuilt once at the framework level — apps consume a static versioned asset, no per-app esbuild step, no per-app registry hashes; (c) the registry seals after framework boot and the ESLint rule flags `registerBehavior`/`defineBehavior` imports outside framework packages, making the policy mechanical; (d) the C6 abuse surface (apps rebuilding an ad-hoc framework inside the registry) is eliminated rather than fenced. Evidence basis: the entire fleet inventory produced only two would-be extensions (listboxNav, timezone-prefill) — both generic, both belonging in the shared layer. The escape ladder's last rungs become: propose verb to framework layer → (rare, sign-off-gated) scoped vanilla island.

## ADR-08 No arbitrary event channel, no user-facing command language

**Decision:** ADR-08 No arbitrary event channel, no user-facing command language: the fire/dispatch verb is CUT; exec/slots/trigger-style command storage is NOT user-facing (the drawer's internal close paths are runtime-internal, not a slot grammar); .hxOn() is DELETED from the library.

**Rationale:** Confirmed security finding: fire is an XSS-gadget amplifier (server-composed CustomEvents with attacker-influenceable JSON detail reaching any unsafe app listener). Confirmed DX finding: fire is a dangling channel — nothing in the behavior system can listen to app:* events, so its only consumer is exactly the unmanaged public/js the system exists to absorb. Slots+exec+trigger+custom verbs formed 'the most capable ad-hoc-framework kit of the three' (C6 breached by machinery). .hxOn is equally CSP-dead and is the unofficial arbitrary-JS escape hatch C6 closes.

**Alternatives rejected:** Keeping fire with a restricted detail type (still no in-system listener; still an amplifier); user-facing exec/slots (LiveView JS.exec steal — elegant, but the confirmed MemberPicker-inside-the-fence attack showed it makes the forbidden thing the path of least resistance).

## ADR-09 Vocabulary scoping

**Decision:** ADR-09 Vocabulary scoping: exactly 10 built-ins — toggle, toggleClass, remove, clipboard, drawer, onEscape, onClickOutside, resetOnSuccess, back, focus — each justified by named call sites or a named roadmap item. Deleted with successors: disable -> htmx-native disable route option; openDialog/closeDialog -> Invoker Commands; formResetOnSuccess replaces formResetOnSwap ('exactly wrong', wiped typed values on 422); dismissOnEscape -> onEscape (fixing its focus-scoped bug); scrollTo -> htmx swap scroll:top modifier; selectAll -> deleted (zero call sites). Extension tier (documented recipes, never built-ins): listbox keyboard nav, timezone prefill, scroll-reveal. Overlap decision rule documented: drawer for overlay bundles; toggle for simple show/hide; onClickOutside for non-overlay dismissal — one blessed path per situation, stated in docs, so C5 holds inside the built-in set.

**Rationale:** The 4-repo inventory is the authority: 8 of 13 current built-ins have zero production usage while the top three gaps (drawer 4x hand-rolled, clipboard-feedback 6x bypassed, success-conditioned reset 2x raw hx-on) were unmet. focus is kept deliberately (4 lines, complements onEscape flows) — decided, not open. Greenfield v6 posture covers deleting verbs unsurveyed private consumers might use.

**Alternatives rejected:** Keeping all 13 (dead weight, two of them actively wrong); fx's keyboard-as-descriptor-grammar (hundreds-member template-literal union, unreadable diagnostics — dedicated keyboard verbs + a closed event? override cover all inventory demand); verb-per-gap growth without a named call site.

## ADR-10 Event surface

**Decision:** ADR-10 Event surface: ONE const EVENT_TABLE in src/behaviors/events.ts is the single source for the BehaviorEvent TS union (derived via typeof/satisfies), the runtime's delegated listener set, and C7's mechanical enumeration. Closed set: click, dblclick, change, input, submit, keydown, focusin, focusout, mouseover, mouseout (+ emit-time aliases focus, blur, mouseenter, mouseleave; mouseover/mouseout carry the relatedTarget containment guard). keyup is DROPPED (no inventory demand). htmx lifecycle names live in a separate single HTMX_EVENTS const (afterSwap: 'htmx:after:swap', afterRequest: 'htmx:after:request') — the only htmx literals in the runtime, read defensively (e.detail?.ctx?.response?.status, pushUrl).

**Rationale:** UPSTREAM's own proposal contained the drift it claimed was structurally gone (keyup in the union, no keyup listener) — proof the hand-maintained two-artifact sync that produced v3's 'type-checks but never fires' class is still the process unless the table is single-sourced. One HTMX_EVENTS map is the C4 quarantine: a beta rename is a one-const edit re-verified by the pinned matrix; the runtime is fully inert-degrading without htmx (templates/web profile).

**Alternatives rejected:** Hand-maintained parallel union + listener list; depending on htmx registerExtension/handle_swap (churn-heavy, C4 violation); tracking htmx betas live.

## ADR-11 Versioning and skew

**Decision:** ADR-11 Versioning and skew: the npm package version IS the grammar+runtime version (LiveView colocation — the same version renders attributes and provides the runtime, so a deploy updates both atomically). Grammar is strictly additive within a major; a verb rename is semver-major. Version + registry hash live in the asset filename and the <html data-fluent-behaviors> stamp. The one real skew window (pre-deploy page swapping post-deploy HTML) degrades defined-ly: unknown verb -> skip + exactly one console.warn + a data-behavior-unknown mark; unknown option attributes ignored. This degrade is a TESTED C7 row (two-version matrix row), not a documented hope. The fastify layer's X-Fluent-Behaviors response header + full-refresh-on-mismatch hardening ships ON by default.

**Rationale:** Deploy-window skew silent no-op is 'the precise failure class that caused BOTH prior regressions' and all three original designs left it untestable — every attack lens required making it executable. Structural colocation plus a tested degrade plus on-by-default refresh hardening is the complete answer.

**Alternatives rejected:** Separately versioned/cached client asset (drift by construction); console-only degrade with no test row (the conceded-risk posture all three designs shipped); off-by-default refresh hardening (Bedrock — the untested path).

## ADR-12 C7 executability

**Decision:** ADR-12 C7 executability: fixtures are mandatory in every BehaviorSpec (built-ins included); the shipped Playwright suite enumerates the matrix mechanically from the registry — verb x fixture x declared event x {initial load, plain outerHTML swap, outerMorph} — under the real strict CSP (per-request nonce + strict-dynamic, no unsafe-eval) with hard gates: behavior effect asserted, zero console errors, zero securitypolicyviolation events. The suite runs against the PRODUCTION-BUILT minified asset, never source form. State-bearing rows (drawer, focus, clipboard-feedback) run on Chromium + WebKit + Firefox; the full matrix runs on Chromium. A registered extension verb without fixtures cannot exist (type-level + registration throw), so a new verb without coverage fails CI by construction. Size budget is CI-enforced: <=5KB min / <=2.2KB gz for the core+built-ins asset; the '~1KB' slogan is retired in favor of a bounded, cached, honest number.

**Rationale:** Both historical regressions were silent while emission-string unit tests stayed green ('the test itself pins the wrong name'). Testing the source form while shipping a build product was fx's sharpest confirmed defect. Multi-engine rows exist because Bedrock's Chromium-green/Safari-dead finding generalizes to any state-bearing DOM behavior.

**Alternatives rejected:** SSR emission unit tests as sufficient; optional fixtures (UPSTREAM's built-ins-only enumeration gap); Chromium-only acceptance; testing pre-minification source.
