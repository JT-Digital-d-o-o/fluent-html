# AriaRole literal union under-covers WAI-ARIA 1.2/1.3

## Problem
The `AriaRole` union enumerates a solid WAI-ARIA 1.1-era set but omits a batch of roles that are now standards-track and content-semantics-relevant: `mark`, `comment`, `suggestion`, `paragraph`, `caption`, `code`, `emphasis`, `strong`, `deletion`, `insertion`, `blockquote`, `meter`, `time`, `associationlist`/`associationlistitemkey`/`associationlistitemvalue`. Because the union ends in `(string & {})`, these still *work* — but they get no autocomplete and no typo protection, which is the entire reason the union exists.

## Evidence
```ts
// src/core/aria-types.ts:8
export type AriaRole =
  // Widget ... Composite ... Document structure ... Landmark ... Live region ... Window
  | "alertdialog" | "dialog"
  | (string & {});   // line 29
```
Grepping the union body for `mark|comment|suggestion|paragraph|caption|meter|deletion|insertion` returns nothing — none are listed. The doc-comment claims it covers the role set, but the WAI-ARIA 1.2 document-structure additions (`comment`, `mark`, `suggestion`, `paragraph`, `caption`, `code`, `emphasis`, `strong`, `deletion`, `insertion`, `blockquote`, `time`, `meter`) are absent.

## Why it matters
Lower pain (the escape hatch keeps them functional) but it directly undercuts the type-safety-first promise for exactly the content-semantics roles a docs/blog/CMS surface uses most (`mark` for highlights, `comment`/`suggestion` for review UIs, `meter` for ratings). A typo like `"makr"` silently passes today.

## Rough idea (not a design)
Additive (6.1.0): append the missing WAI-ARIA 1.2/1.3 role literals to the union before the `(string & {})` arm. Purely additive — no existing call-site breaks. Tiny, mechanical.
