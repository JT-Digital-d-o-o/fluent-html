# CSS Anchor Positioning is unreachable as typed primitives

## Problem
CSS Anchor Positioning is the platform's answer to "tether this popover/tooltip/menu to that button without JS". It is the natural partner to the Popover API surface that the v6.0.0 research already flagged as missing ([[F-B-100]]). It works by setting `anchor-name: --foo` on the anchor element and `position-anchor: --foo` + `position-area`/`inset-area` (and `anchor()` in `top/left/…`) on the positioned element. fluent-html exposes none of these. The position section of the vocab stops at the classic `absolute/relative/fixed/sticky` + `inset/top/right/bottom/left` (vocab.ts:153-175); there is no anchor concept. Grep confirms no `anchor-name` / `position-anchor` anywhere in `src/`.

## Evidence
```ts
// src/class-vocab/vocab.ts:153  — Position shortcuts
stat("absolute", "absolute"),
stat("relative", "relative"),
stat("fixed", "fixed"),
stat("sticky", "sticky"),
...
// src/class-vocab/vocab.ts:171  — inset family
size("inset", "inset"), size("top", "top"), size("right", "right"), ...
```
No `anchorName` / `positionAnchor` / `positionArea` method exists; the only route is `addAttribute("style", "anchor-name:--menu")`.

## Why it matters
The core already ships HTMX behaviors `openDialog`/`closeDialog` and the research wants a typed Popover API (F-B-100). A popover without anchor positioning either needs JS positioning libraries (a runtime dep the guardrails forbid) or fragile absolute-positioning math. Anchor positioning is the zero-JS, SSR-friendly solution — precisely the kind of platform leverage this track exists to surface. Because the anchor relationship is purely declarative, it belongs at render time.

## Rough idea (not a design)
Additive (6.1.0): `.anchorName(name: string)` → `[anchor-name:--name]`; `.positionAnchor(name)` → `[position-anchor:--name]`; an optional `.positionArea(area)` with a typed `position-area` token union (`"top"|"bottom"|"block-start"|…`). All emit purge-safe single arbitrary-property classes; register their shapes in the extractor + eslint vocab. Ships alongside (not before) the Popover primitive so the pair lands coherently.
