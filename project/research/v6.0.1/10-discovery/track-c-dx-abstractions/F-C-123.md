# `setClasses` supports conditional spread; attributes have no equivalent

## Problem
For classes, there is a dedicated falsy-filtering spread combinator:

```ts
// src/core/tag.ts:264
setClasses(classes: (string | false | null | undefined)[]): this {
  this.class = classes.filter(Boolean).join(" ");
  return this;
}
```

There is no parallel for attributes. The bulk attribute setters do not filter conditionals and one of them *replaces* rather than merges:

```ts
// src/core/tag.ts:305
setDataAttrs(attrs: Record<string, string>): this { … }   // values are required `string`; no skip-when-undefined; `set*` semantics
// src/core/tag.ts:158
addAttribute(key: string, value: string): this { … }      // single key only
```

So composing a set of *optional* attributes (`{ disabled: isDisabled && "", "data-state": active ? "on" : undefined, title: tooltip }`) requires a chain of per-attribute `.when()`/`.toggle()` calls or a hand-built object passed through `filter`. There is no `addAttributes` that merges and drops `undefined`/`false`.

## Evidence
Grep across `src/` finds no `addAttributes`/`setAttributes` method. `setDataAttrs` (`tag.ts:305`) types values as required `string` and uses `set` (override) semantics — passing `undefined` for an absent data-attr is a type error, and it can't be called twice to accumulate. The class side has the ergonomic conditional-spread (`setClasses`); the attribute side forces either N `.when()` hops or external object-pruning, an asymmetry that shows up wherever optional attrs are computed (form fields, ARIA state, data-* hooks).

## Why it matters
Conditional attribute spread is a frequent authoring shape (optional `title`, `aria-*`, `data-*` driven by state). The current asymmetry means classes compose cleanly but attributes don't, pushing authors back to imperative `.when()` ladders or untyped `addAttribute` with manual guards — more code, easier to leave a stray empty attribute. A single merge-and-filter primitive closes the gap and keeps escape-by-default centralized.

## Rough idea (not a design)
Additive `addAttributes(attrs: Record<string, string | number | false | null | undefined>): this` that merges into existing attributes and skips falsy/nullish values (running the same `validateAttributeKey` + escaping path as `addAttribute`); optionally relax `setDataAttrs` to skip `undefined`. 6.1.0; carries the class-vocab note (n/a — attrs, not classes) and a guidelines example.
