# `apply` has no way to pass arguments to a modifier — variant/size composition needs a boilerplate factory

## Problem
`apply` accepts only zero-argument modifiers:

```ts
// src/core/tag.ts:246
apply(...fns: ((tag: this) => this)[]): this {
  for (const fn of fns) fn(this);
  return this;
}
```

To build a *parameterized* reusable style — the bread-and-butter of variant/size systems (`button("primary","lg")`) that the constitution wants to live in user-land *without* shipping `Modal`/`Badge`/`.variant()` components — the author must wrap every call in an ad-hoc closure:

```ts
const variant = (v: "primary" | "ghost") => (t: Tag) => v === "primary" ? t.background("blue-600") : t.background("transparent");
Button("Save").apply(variant("primary"));   // works, but `variant("primary")` is a per-call allocation + reads awkwardly
```

There is no first-class combinator (`applyWith(fn, arg)`, or an `apply` overload that threads an argument) to express "apply this reusable transform with this config" directly. `applyTo` (the inverse, used by the roadmap for HTMX response composition) is also absent from core.

## Evidence
Grep across `src/` finds no `applyWith`, `applyTo`, `variant(`, `pipe`, or `compose` export. The only composition entry points are `apply` (nullary fns) and `when`/`whenElse` (`tag.ts:236` region). So the "variant composition WITHOUT shipping components" goal this track names is reachable only via user-authored curry boilerplate, with no sanctioned primitive — meaning every app reinvents the same `(arg) => (t) => t` shape, inconsistently.

## Why it matters
Variant/size/state styling is the single most repeated UI-authoring pattern, and v6 deliberately pushed it to user-land. Without a parameterized-apply primitive, "user-land" means "re-derive the closure convention in every codebase," which is exactly the divergence (many ways to do one thing) the converge principle opposes. A tiny combinator turns variant authoring into a one-liner and gives the eslint-plugin/extractor a single shape to recognize.

## Rough idea (not a design)
Additive `applyWith<A>(fn: (tag: this, arg: A) => unknown, arg: A): this` (and optionally a free `compose(...fns)` to pre-build a style stack). Pairs with F-C-120's loosened modifier type. 6.1.0; pure combinator, no component shipped, so it respects the instruction-set guardrail. Carries a guideline section on variant authoring.
