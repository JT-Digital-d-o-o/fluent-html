# Form<T> binding has no checkbox/radio factory

## Problem
`FormBinding<T>` exposes `input`, `textarea`, `select`, `hidden`, `error` — but no `checkbox` or `radio`. These two are exactly the controls where wiring is subtle: a checkbox's checked state comes from a *boolean* field (and the value="on" default), and a radio's checked state comes from a *value match* across a group sharing one `name`. Today an author must drop out of the typed binding and hand-wire with raw `Input("checkbox").setName(...).toggle("checked", ...)`, losing the `keyof T` name guarantee that is the whole point of `Form<T>`.

## Evidence
```ts
// src/elements/forms.ts:327
export interface FormBinding<T> {
  input(name: keyof T & string, type?: InputType): InputTag;
  textarea(name: keyof T & string): TextareaTag;
  select(name: keyof T & string, options: readonly SelectOption[]): SelectTag;
  hidden(name: keyof T & string, value: string): InputTag;
  error(name: keyof T & string): View;
}
```
`createFormBinding` wires `value` for `input` (lines 340–347) but there is no path that reads a boolean from `state.values[name]` and emits `checked`. The `InputType` union already contains `'checkbox' | 'radio'` (html-types.ts:8), so `f.input("agree", "checkbox")` type-checks but silently drops the prefill: it would call `setValue(String(true))` → `value="true"`, never `checked`.

## Why it matters
Every create/edit form with a boolean toggle (terms-accepted, is-active, notify-me) or a small enum radio group hits this. It is the single most common reason an author abandons `Form<T>` mid-build and reverts to raw tags, defeating the typo-proof name binding. Pain is high because the *wrong* output (`value="true"` instead of `checked`) is a silent data bug, not a compile error.

## Rough idea (not a design)
Additive (6.1.0): `f.checkbox(name, value?)` sets `type="checkbox"`, `name`, optional `value`, and `toggle("checked", Boolean(state.values[name]))`; `f.radio(name, value)` sets `type="radio"`, shared `name`, `value`, and `toggle("checked", String(state.values[name]) === value)`. Pure primitives — no label/wrapper opinion (that stays user-land per the `f.field` cut).
