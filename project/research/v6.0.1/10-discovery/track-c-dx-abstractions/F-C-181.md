# Re-litigation verdict: NO primitive core form for the cut visual helpers

## Problem
The Track-C charter for this wave is to re-litigate whether any **cut** helper (Modal/Alert/`Table.of`/Badge/Icon/EmptyState/Skeleton/SortHeader) deserves a **primitive** core form, with a high bar and a default NO. This finding records the verdict for the candidates whose ARIA/positioning/dialog *mechanics* people assume need library support: **they are already reachable**, so re-absorbing them into core would violate guardrail #6 with no leverage gained. The genuine remaining gap (the list-vs-emptystate *control* combinator) is split out as [[F-C-180]] — that one is a combinator, not a component.

## Evidence — every assumed "needs core" mechanic is already a shipped primitive

**Modal/Drawer → already primitive.** `behavior("openDialog")`/`behavior("closeDialog")` call native `<dialog>.showModal()`/`.close()` (free backdrop, Esc, focus-trap, top-layer), and `Dialog()` is a shipped element. The visual chrome is the only thing left, and that is opinion → user-land.

**Overlay/Skeleton-shimmer positioning → already primitive.** `Tag.prototype.overlay()` is the *primitive form* of an overlay/badge-on-avatar/spinner-over-card helper — it ships the `relative`+`absolute`+inset mechanic with zero visual opinion:

```ts
// src/control/overlay.ts:44
overlay(position: OverlayPosition, ...content: View[]): Tag;
```

This is the precedent: the positioning *mechanic* lives in core; the Badge/Spinner *content* is user-land. A Skeleton is `Div().rounded().background("gray-200").animate("pulse")` — pure user-land styling; nothing in it needs library support.

**SortHeader / sortable table → ARIA already primitive.** `aria-sort` is in the **closed** `AriaAttributeName` union, so `Th().setAria({ sort: "ascending" })` type-checks today:

```ts
// src/core/aria-types.ts:44
| "rowcount" | "rowindex" | "rowspan" | "selected" | "setsize" | "sort" | "valuemax"
```

```ts
// src/core/tag.ts:360
setAria(attrs: AriaAttrs): this { ... }
```

The HTMX wiring is `defineRoutes` + `RouteHxOptions.query`; the visual caret is styling. Every load-bearing part is a shipped primitive — the app's `SortHeader` (test/aaa/.../analytics.components.ts) is a 15-line composition, exactly what guardrail #6 wants.

**Alert/Badge/Icon → composition, no machinery.** Alert = `Div(...).setRole("alert")` (role is primitive). Badge = a styled `Span`. Icon = an `Svg(...)` tree (B-05 shipped the full SVG element + stroke-setter coverage precisely so `Raw(iconString)` injection dies and `Icon` becomes a trivial `View`). None require type machinery, render support, or a native element the user can't reach.

## Why it matters
Frequency of the *helpers* is high in app code, but the frequency of an **unreachable mechanic** is **zero** — that is the whole point. The pain of re-absorbing any of these into core is high (re-opens the converge/instruction-set decision, drags visual opinion + a class-vocab + a license question (Icon set) back into a zero-dep core). The default-NO holds for all of them. The only thing missing is *discoverability*: authors reach for a remembered `Modal()`/`EmptyState()` instead of the primitive recipe, so they ask core to bring it back.

## Pre-empting the instruction-set objection (guardrail #6)
This finding *is* the defense of guardrail #6: it argues explicitly **against** adding a primitive form, having checked each candidate's load-bearing capability and found it already shipped (`overlay()`, `setAria({sort})`, `behavior("openDialog")`, SVG coverage, `setRole`). The bar ("a true leverage point, not opinion") is not cleared by any of them — there is no capability a user cannot compose. The one residual leverage point is control-flow exhaustiveness, carved out into [[F-C-180]].

## Rough idea (not a design)
No new API. Add a short "compose-it-from-primitives" recipe block per cut helper to the lib docs and `views.md` (Modal → `Dialog` + `behavior("openDialog")`; EmptyState → `IfThen`/[[F-C-180]]; Badge-on-avatar → `.overlay()`; SortHeader → `setAria({sort})` + `RouteHxOptions.query`). Adoption/docs only → 6.1.0 docs pass. Keeps the instruction-set converged and stops the "bring the component back" requests at the source.
