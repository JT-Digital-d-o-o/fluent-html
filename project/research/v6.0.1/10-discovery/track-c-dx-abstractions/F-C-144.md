# No header/cell binding primitive — table columns are declared twice and can drift

## Problem
Building a data table today means writing the `<thead>` header cells and the per-row `<tbody>` cells as two independent lists that the author must keep positionally aligned by hand. Add a column in the middle, forget to add the matching `Th`, and the header/body silently misalign — a class of bug no type can catch because the two lists are unrelated values. The deferred `Table.of`/`SortHeader`/`Pagination` *component* (v6-spec §317) is correctly out of core, but a thin **column-binding primitive** that emits header row + cell rows from one list is instruction-set, not a component.

## Evidence
```ts
// src/elements/tables.ts:6, 49 — bare element factories only
export function Table(...children: View[]): Tag { return El("table", ...children); }
export function Th(...children: View[]): ThTag { return new ThTag("th", ...children); }
```
The only iteration help is `ForEach`/`ForEachElse` (iteration.ts:93), which maps *rows* but has no notion of *columns*, so the header is authored separately:
```ts
Thead(Tr(Th("Name"), Th("Email"), Th("Role")))      // column order #1
Tbody(ForEach(users, u => Tr(Td(u.name), Td(u.email), Td(u.role))))  // column order #2 — must match by hand
```

## Why it matters
Tables are the backbone of every admin/CRUD surface (the four `ttl` PM features, `rideshare`, etc.). The duplicate column declaration is repeated at every table call-site and is a recurring source of header/body drift on edits. Medium pain, high frequency. A column list also makes `scope="col"` and keyed rows trivial to attach in one place.

## Rough idea (not a design)
Additive (6.1.0): `Rows<T>(items, columns)` where `columns: { header: View; cell: (item: T, i: number) => View }[]`, returning `[Thead(Tr(...headers)), Tbody(...rows)]` (or a Table-fragment) so header and cell are defined together and cannot misalign. No sort/paginate/style opinion — those compose on top via `defineRoutes` + control flow, exactly as the spec envisions. Optionally pair with a `keyed`/`key` field so HTMX morphs can match rows stably.
