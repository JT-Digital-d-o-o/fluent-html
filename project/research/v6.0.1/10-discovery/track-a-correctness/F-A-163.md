# class-vocab parity test is one-directional — a lib class-emitter missing from the vocab goes undetected

## Problem
`class-vocab.test.ts` is billed as "THE anti-drift guard," but it only iterates
`classVocab` and checks each row renders the expected class:

```ts
// fluent-html/test/class-vocab.test.ts:123
for (const def of classVocab) {
  it(`${def.method} renders the vocab-emitted class`, () => {
    assert.equal(typeof proto[def.method], "function", ...);
    ...
  });
}
```

There is no test in the reverse direction: "every class-emitting Tag method is in
the vocab." So if someone adds a styling method to `tailwind-methods.ts` and forgets
the vocab row, the lib renders the class fine, every test stays green, but the
extractor never safelists it (→ unstyled render under v4, no build error) and ESLint
never recognizes it as a fluent modifier. That is precisely the silent-failure the
vocab pipeline exists to prevent.

## Evidence
A cross-check of the shipped tree shows the gap is currently empty BY LUCK, not by
construction: every `p.<method> = function` in tailwind-methods.ts is in the vocab,
and the one styling method defined elsewhere — `htmxIndicator` — was manually added
to both:

```ts
// fluent-html/src/core/htmx-methods.ts:44
p.htmxIndicator = function () { return this.addClass("htmx-indicator"); };
// fluent-html/src/core/tailwind-methods.ts:537
p.flexWrap = function (value: string) { return this.addClass(`flex-${value}`); };
```

Nothing enforces this invariant; the next `.addClass(...)`-emitting method added
without a vocab row ships drift-clean through CI.

## Why it matters
The whole v6 class-string contract (guardrail #7) rests on the vocab being the
complete set of class-emitting methods. A one-directional parity test leaves the
"forgot the vocab row" path — the most likely human error — completely uncovered.
Cheap to close, high leverage.

## Rough idea (not a design)
In the parity test, collect prototype keys whose body calls `addClass`/`setClass`
(or maintain an explicit `EMITTERS` list incl. `htmxIndicator`) and assert each is
present in `classVocab`. Test-only change — 6.0.1.
