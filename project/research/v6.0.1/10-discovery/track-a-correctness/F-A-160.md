# Extractor over-emits spurious partial-/un-prefixed classes for nested .on()/.at() variants

## Problem
`scanFluent`/`scan` emit classes the app never renders whenever a fluent chain
nests variants (`.on("dark", t => t.on("hover", t => t.background("red-500")))`).
For that single chain the extractor emits FOUR classes where the app renders ONE
(`dark:hover:bg-red-500`):

```
scanFluent(`.on("dark", t => t.on("hover", t => t.background("red-500")))`)
→ ["bg-red-500", "dark:bg-red-500", "dark:hover:bg-red-500", "hover:bg-red-500"]
```

`bg-red-500` (no prefix), `dark:bg-red-500` (missing the `hover:`), and
`hover:bg-red-500` (missing the `dark:`) are all wrong — the `.background()` call
only exists under `dark:hover`. All three pass `SAFE_TOKEN`, so they ride straight
into the emitted `@source inline("…")` block and bloat the generated CSS.

## Evidence
Root cause #1 — `extractVariantClasses` runs `scanMethod` over the WHOLE outer
body, which still contains the nested `.on(...)` call text, then ALSO recurses:

```ts
// fluent-html-tailwind-extractor/src/extract.ts (extractVariantClasses)
for (const def of classVocab) {
  for (const cls of scanMethod(body, def.method).classes) classes.push(`${prefix}:${cls}`);
}
...
classes.push(...extractVariantClasses(body, prefix));
```

So `.background("red-500")` inside the nested `dark`→`hover` body is matched once
at the `dark` level (→ `dark:bg-red-500`) and again, correctly, at `dark:hover`.

Root cause #2 — `scanInternal` (extract.ts:178) calls `scanMethod(stripped, …)`
over the entire top-level source, so the same innermost `.background()` is caught
with no prefix at all (→ `bg-red-500`).

The shipped test (extract.test.ts:34) only asserts the CORRECT class is *present*
(`has(...)`) — it never asserts the spurious ones are *absent*, so the bug is green.

## Why it matters
Every app that uses nested responsive/state variants (`.at("md", t => t.on("hover", …))`
is idiomatic per CLAUDE.md) silently inflates its safelist with non-existent
classes. The wrong classes are real Tailwind utilities, so there's no build error —
just dead CSS and a safelist that no longer means "what the app renders." It also
undermines the extractor's core contract (precise render-time class capture).

## Rough idea (not a design)
Before scanning a variant body for vocab methods, blank out its nested `.on(...)`/
`.at(...)` call ranges (recurse into them only via the prefix path). And gate the
top-level `scanMethod` in `scanInternal` so calls inside a variant callback aren't
double-counted bare. Patch (6.0.1) — no public shape change; add absence assertions
to extract.test.ts.
