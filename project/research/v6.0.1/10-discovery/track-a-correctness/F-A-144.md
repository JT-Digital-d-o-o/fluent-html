# No typed path for htmx 4 ':inherited' — the guideline's own example escapes to untyped addAttribute

## Problem
htmx 4 stops inheriting attributes by default; to push an attribute down to descendants you append the `:inherited` modifier to the attribute *name* (`hx-confirm:inherited`). The shipped `HTMX` interface, the `setHtmx`/`hx*` mixin, and the `buildHtmx` serializer have **no** representation for this — every htmx attribute is emitted at its bare name only. The CLAUDE.md rule "htmx 4: attributes don't inherit — use `:inherited` modifier" therefore has no typed mechanism behind it, and the guideline's worked example falls back to the untyped escape hatch.

## Evidence

```ts
// src/htmx.ts:201+ — HTMX has no per-attr inheritance flag; e.g.
confirm?: string;        // always emitted as hx-confirm, never hx-confirm:inherited
```

```ts
// src/render/serialize.ts:142-163 — HTMX_ATTRS emit fixed `hx-<key>` names only
str('confirm'), str('target'), str('swap'), ...
```

The sanctioned workaround in the guideline bypasses the whole type-safe layer:

```ts
// guidelines/web-development/htmx.md:191-194
Div(
  Button("Delete 1").hxDelete("/item/1"),
  Button("Delete 2").hxDelete("/item/2"),
).addAttribute("hx-confirm:inherited", "Are you sure?")   // ✗ raw string, no typing
```

`addAttribute("hx-confirm:inherited", …)` defeats `HxTarget`/`HxSwap`/etc. validation, is invisible to the Tailwind/ESLint contract tooling, and is exactly the bare-string pattern the route/id system was built to eliminate.

## Why it matters
Inheritance is a core htmx 4 behavioural change; container-level `hx-confirm`/`hx-target`/`hx-trigger` shared across children is an everyday pattern. Today the only way to express it is the untyped attribute string the rest of the library's design forbids — a type-safety hole sitting on the most-used htmx surface, and one the project's own guideline is forced to teach.

## Rough idea (not a design)
Additive (6.1.0): introduce an opt-in inheritance marker on the typed surface — e.g. a per-call `inherited` set, or a thin `.hxInherited(attr, value)` setter — that serializes the attribute at its `:inherited` name through `buildHtmx`, keeping the value typed. Ship it with the htmx.md edit replacing the raw-`addAttribute` example.
