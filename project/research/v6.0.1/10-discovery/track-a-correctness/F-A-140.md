# Route param substitution uses naive substring replace — a param name that prefixes another corrupts the URL

## Problem
Both the route callable and `.resolve()` substitute `:param` placeholders with a plain, non-anchored `String.prototype.replace(":" + key, value)`. When one param name is a **prefix** of another (`:id` vs `:idCard`, `:user` vs `:userId`), the shorter name matches *inside* the longer placeholder, corrupting the path. Object key iteration order then decides whether it breaks, so the bug is order-dependent and silent until it isn't.

## Evidence

```ts
// src/routes.ts:262-268 (route callable)
function (params: Record<string, string | number>, options?: RouteHxOptions): HTMX {
  let resolvedPath = fullPath;
  for (const [key, value] of Object.entries(params)) {
    resolvedPath = resolvedPath.replace(`:${key}`, encodeURIComponent(String(value)));
  }
  assertNoUnresolvedParams(resolvedPath, fullPath);
  return buildHtmxFromRoute(resolvedPath, method, options);
}
```

```ts
// src/routes.ts:274-282 (.resolve) — same naive replace
resolved = resolved.replace(`:${key}`, encodeURIComponent(String(value)));
```

Reproduction (path `/x/:idCard/:id`, params `{ id, idCard }`, `id` iterated first):

```
.replace(":id", "AAA")  →  "/x/AAACard/:id"   // matched the :id prefix of :idCard
.replace(":idCard", …)  →  no match left
assertNoUnresolvedParams →  throws "Unresolved route param :id"
```

The dependable-looking case (`/x/:idCard/:id` where `:id` happens to come last) only works by accident of left-to-right `replace` + key order.

## Why it matters
Routes with related param names (`:id`/`:idCard`, `:org`/`:orgId`, `:user`/`:userSlug`) are common in real apps. The failure is either a thrown error at render time or — worse — a silently malformed URL pointing at the wrong resource. Two shipped code paths (callable + resolve) share the defect, so every route registry is exposed.

## Rough idea (not a design)
Patch (6.0.1): replace each `:key` with a boundary-aware regex — `new RegExp(":" + escapeRegex(key) + "(?![A-Za-z0-9_])", "g")` — so `:id` cannot match inside `:idCard`. Factor the substitution into one shared helper used by both the callable and `resolve`. No public-shape change.
