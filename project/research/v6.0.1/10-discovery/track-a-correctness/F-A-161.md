# extractDefaultClasses regex swallows whole call expressions as a single "class" token

## Problem
`extractDefaultClasses` is documented as Tailwind's class-candidate regex so apps
can let this extractor "fully replace" the built-in scanner. But its trailing
optional group `(?:\([^)]*\))?` greedily eats a fluent method call's argument list,
returning the entire call expression as one bogus class token:

```
extractDefaultClasses(`.on("dark", t => t.background("red-500"))`)
→ ['.on("dark", t => t.background("red-500")']
```

That token (quotes, spaces, `=>`) is garbage, and `scan()` returns it in its class
set (it's the full-scan path apps use to replace Tailwind's own scanner).

## Evidence
```ts
// fluent-html-tailwind-extractor/src/extract.ts:200 (extractDefaultClasses)
export function extractDefaultClasses(content: string): string[] {
  return content.match(/[:\w\-/.@#[\]]+(?:\([^)]*\))?/g) ?? [];
}
```

`scanInternal` adds every default token to the class set on the full-scan path:

```ts
// fluent-html-tailwind-extractor/src/extract.ts:178
if (includeDefaults) {
  for (const cls of extractDefaultClasses(stripped)) classes.add(cls);
  ...
}
```

The safelist path (`scanFluent`) sets `includeDefaults=false` and the garbage
token also fails `SAFE_TOKEN`, so the safelist itself is spared — but
`extractClasses`/`scan` (the documented "replace Tailwind's scanner" surface)
return it, so an app driving its content config off `scan()` sees junk candidates.

## Why it matters
The whole point of exporting `extractDefaultClasses` (per its JSDoc, F-C-054) is to
stop apps cargo-culting a "subtly-divergent copy." Shipping a copy that mis-tokenizes
every fluent call defeats that. Lower severity than F-A-160 because the safelist path
is unaffected, but it's a correctness bug on a surface sold as a drop-in scanner.

## Rough idea (not a design)
Constrain the `(...)` suffix to immediately follow a class-shaped head and to match
only arbitrary-value functions (no commas/quotes/arrows inside), or scan only the
literal class surfaces (HTML `class="…"`, `.setClass`/`.addClass`) rather than raw TS.
Patch (6.0.1).
