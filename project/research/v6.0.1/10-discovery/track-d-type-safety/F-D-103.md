# `setAria` flattens every aria value to `string | number | boolean`

## Problem
`AriaAttrs` maps every attribute name to a single `AriaValue = string | number | boolean`. But a large subset of ARIA states are token enumerations, not free strings: `aria-current` (`page|step|location|date|time|true|false`), `aria-haspopup` (`menu|listbox|tree|grid|dialog|true|false`), `aria-live` (`off|polite|assertive`), `aria-sort` (`ascending|descending|other|none`), `aria-autocomplete` (`inline|list|both|none`), `aria-orientation` (`horizontal|vertical|undefined`), `aria-invalid` (`grammar|spelling|true|false`). Today `setAria({ live: "polit" })` and `setAria({ current: "pages" })` compile and emit broken markup that screen readers ignore.

## Evidence
```ts
// src/core/aria-types.ts:52
export type AriaValue = string | number | boolean;
// src/core/aria-types.ts:59-61
export type AriaAttrs =
  & Partial<Record<AriaAttributeName, AriaValue>>
  & Record<`aria-${string}`, string>;
```
The setter trusts this map directly:
```ts
// src/core/tag.ts:360
setAria(attrs: AriaAttrs): this {
```

## Why it matters
The closed `AriaAttributeName` union (great — catches `labeledby` typos) created the expectation that aria values are checked too; they aren't. ~7 enumerable attributes silently accept garbage, and a11y bugs are exactly the class that never surfaces in dev (no console error, just a broken assistive-tech experience). The guidelines `typescript.md` preaches "string literal unions — never bare `string` where only specific values are valid" — this is the canonical violation inside the lib itself.

## Rough idea (not a design)
6.1.0 (additive): turn `AriaAttrs` from a flat record into an explicit per-key object type, giving the ~7 enumerable states their literal unions (with `boolean` where the tristate applies) while leaving `label`/`describedby`/etc. as `string` and numeric states as `number`. Existing valid calls keep compiling; only previously-invalid token strings start erroring — additive in spirit, but verify no in-repo call passes a non-spec token before deciding 6.1.0 vs parked-major.
