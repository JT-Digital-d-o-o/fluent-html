# defineTheme's type seam is decoupled from its runtime spec

## Problem
`defineTheme(spec)` is a runtime identity passthrough; all the typing comes from a
*separately hand-written* `declare module` block, one `interface FluentCustom<Family>
extends ThemeKeys<typeof tokens, "family">` line per family. Nothing ties the two
together. Define `spacing` tokens in your const but forget the matching
`FluentCustomSpacing` augmentation and you get CSS emitted with zero typed tokens —
`.padding("gutter")` stays a compile error even though the token exists. The reverse
(augment a family you didn't put in the const) also goes unnoticed.

## Evidence
```ts
// src/core/define-theme.ts:50 — runtime only; "a runtime value can't add to a type"
export function defineTheme<const T extends ThemeSpec>(spec: T): T { return spec; }

// src/core/tailwind-types.ts:22 — five EMPTY interfaces the user must each augment by hand
export interface FluentCustomColors {}
export interface FluentCustomSpacing {}
// ...

// src/core/tailwind-types.ts:29
export type ThemeKeys<T, K extends keyof T> = Record<keyof T[K] & string, true>;
```
The docblock itself spells out the foot-gun: the example augments only `colors` and
`spacing`; a project that also sets `radius`/`shadow`/`fontSize` tokens but copies
that two-line example gets no typing for the other three, with no diagnostic. The
boilerplate is per-family and order-independent of the spec, so drift is the default
failure mode.

## Why it matters
`defineTheme` is billed as "the ONE theming mechanism" whose payoff is
"typo-as-compile-error." That payoff silently evaporates per-family on the most
common mistake (incomplete augmentation), and the hand-sync grows linearly with
families. It's a DX/type-hole in the exact primitive the type-safety track elevated.

## Rough idea (not a design)
Additive (6.1.0): provide one seam that maps all families from the const in a single
augmentation — e.g. `interface FluentCustomColors extends FluentTheme<typeof tokens,
"colors"> {}` collapsed into a single `declare module` snippet generated/derivable
from `typeof tokens`, so families present in the spec are wired and families absent
from it can't be accidentally half-declared. No public-shape break; runtime untouched.
