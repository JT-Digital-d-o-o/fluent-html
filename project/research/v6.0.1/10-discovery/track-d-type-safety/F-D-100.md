# IframeTag.referrerpolicy is an untyped string but a closed union already exists

## Problem
`AnchorTag` types `referrerpolicy` as the closed `ReferrerPolicy` union, but `IframeTag` — the *same* attribute, same spec value set — types it as bare `string`. The union already exists in `html-types.ts` and is the complete spec list (8 values, no escape hatch). This is an inconsistency hole: a typo like `.setReferrerPolicy("no-refferer")` compiles on an `<iframe>` but not on an `<a>`.

## Evidence
```ts
// src/elements/embedded.ts:15
referrerpolicy?: string;
// src/elements/embedded.ts:57
setReferrerPolicy(referrerpolicy?: string): this {
```
versus the anchor, which uses the typed union:
```ts
// src/elements/links.ts:19
referrerpolicy?: ReferrerPolicy;
// src/elements/html-types.ts:35-38  — closed, complete spec list, no (string & {})
export type ReferrerPolicy =
  | 'no-referrer' | 'no-referrer-when-downgrade' | 'origin' | ... | 'unsafe-url';
```

## Why it matters
Two element classes disagree on the type of the same attribute. The union is the full spec list, so tightening drops no valid value — pure correctness win, no shape change to the public method *name*. Friction is medium: iframe referrerpolicy is set on embeds/maps/analytics frames.

## Rough idea (not a design)
Import `ReferrerPolicy` into `embedded.ts` and swap both the field and the setter param. Patch (6.0.1): no method added/removed, and because the union enumerates every spec value, no currently-valid call breaks. Confirm against the lockstep tailwind-extractor/eslint vocab (no class emission, so no vocab change).
