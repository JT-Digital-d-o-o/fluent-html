# No dedicated type-level test target; negative type assertions are ad-hoc and sparse

## Problem
The v6 surface leans heavily on compile-time guarantees the docs advertise as the
headline feature: closed themeable unions ("a typo is a compile error"), `Form<T>`
field-name narrowing, `BehaviorMap[K]` option inference, `setMin`/`setStep` typed
`never` on text inputs, the `AriaAttributeName` closed union. Yet the only negative
type tests are 8 `@ts-expect-error` lines scattered inside `test/type-safety.ts`, a
runtime test file. There is no compile-only tsd-style target. The most type-heavy new
surfaces — `defineTheme` + `ThemeKeys` declare-module augmentation, `Form<T>` typed
field builder, `behavior<K>` option narrowing — have ZERO type-level assertions
verifying the typo-is-an-error and narrowing claims.

## Evidence
```ts
// test/type-safety.ts:83 — the entire negative-type surface is a handful of inline directives
// @ts-expect-error — numeric input rejects string min
// @ts-expect-error — date input rejects numeric min
// ...
// test/type-safety.ts:319
// @ts-expect-error — "hx-boost" is not an HTML boolean attribute
```
Total `@ts-expect-error` in the suite: 8, all in one file.

```jsonc
// package.json:49 — the test target runs compiled *.js; there is no `tsc --noEmit`
// type-only pass and no tsd invocation. A regression that *widens* a closed union
// (re-adding a `(string & {})` tail) would NOT fail any test.
"test": "npm run build && node --test dist/test/...
```

```ts
// src/core/define-theme.ts:50 — the whole value of this fn is the type-level
// declare-module seam; nothing asserts that ThemeKeys closes the union or that an
// unknown token key is a compile error.
export function defineTheme<const T extends ThemeSpec>(spec: T): T { return spec; }
```

## Why it matters
A widened union or a broken `Form<T>` narrowing is a silent regression today: `tsc`
still builds, every runtime test still passes, and the library's central selling
point quietly degrades. The project's own TypeScript guideline mandates "string
literal unions — never bare `string`"; there is no test that enforces it survives a
refactor. This is the cheapest insurance for the type-safety track.

## Rough idea (not a design)
Add a `test/types/` suite of compile-only `.test-d.ts` files (tsd or a `tsc --noEmit`
project) wired into the npm test script, asserting both positive (`expectType`) and
negative (`expectError`) cases for the closed unions, `Form<T>`, `BehaviorMap`, and
the `defineTheme`/`ThemeKeys` augmentation. Additive tooling, no source change. Ships
6.1.0.
