# defineRoutes ParamTypeName has no enum/literal-union member

## Problem
`ParamTypeName` is closed to three scalar kinds, all of which widen an enum-like
segment to `string` (or `number`). A route whose path segment is really a small
token set — `/orders/:status` where `status ∈ {"open","paid","void"}` — has no way
to express that. The call site `orderRoutes.byStatus({ status: "pdai" })` compiles.

## Evidence
```ts
// src/routes.ts:43
export type ParamTypeName = "string" | "number" | "uuid";

// src/routes.ts:46
type ParamTypeMap = {
  string: string;
  number: number;
  uuid: string;
};

// src/routes.ts:57
type ResolveParamTypes<Path, Params> = {
  [K in ExtractParams<Path>]: Params extends Readonly<Record<string, ParamTypeName>>
    ? K extends keyof Params
      ? Params[K] extends ParamTypeName ? ParamTypeMap[Params[K]] : string
      : string
    : string;
};
```
`uuid` already proves the intent — narrowing a segment beyond bare `string`. But the
one shape that actually appears in routing (a status / kind / tab enum) is exactly
the one that's missing. The runtime substitution (`resolvedPath.replace`) is
type-agnostic, so an enum member is purely additive at the type level.

## Why it matters
Enum-ish path segments (`:status`, `:tab`, `:kind`, `:period`) are common in
SSR/HTMX apps — they drive `Match()` on the controller side. Today every one of
them is a bare `string` at the call site, defeating the whole point of typed
`.resolve()`/`setHtmx()` route refs, and forcing a redundant runtime guard server-side.

## Rough idea (not a design)
Additive (6.1.0): widen `ParamTypeName` to `ParamTypeName | readonly [string, ...string[]]`,
and in `ResolveParamTypes` map a tuple `T` to `T[number]`. No runtime change. Pairs
naturally with the guideline edit teaching enum segments.
