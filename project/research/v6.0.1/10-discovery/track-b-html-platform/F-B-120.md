# No typed setter for `enterkeyhint`

## Problem
v6.0.0 shipped `setInputmode` (which keyboard layout) on `InputTag`/`TextareaTag` but never shipped its sibling `enterkeyhint` (which **action button** — Go / Search / Send / Next / Done — the virtual keyboard's Enter key displays). These two attributes are designed as a pair for mobile form UX; shipping one without the other is an inconsistency. Today the only way to set it is the untyped `addAttribute("enterkeyhint", "send")`, which CLAUDE.md explicitly discourages.

## Evidence
`InputMode` is a closed union and `setInputmode` exists, but there is no `EnterKeyHint` type and no setter anywhere in the surface:

```ts
// src/elements/html-types.ts:44
export type InputMode =
  | 'none' | 'text' | 'decimal' | 'numeric' | 'tel' | 'search' | 'email' | 'url';
```

```ts
// src/elements/forms.ts:90
setInputmode(inputmode?: InputMode): this { this.inputmode = inputmode; return this; }
```

`enterkeyhint` is a **global** attribute (it applies to any contenteditable host too), so the natural home is `core/tag.ts` alongside `setRole`/`setTabindex` (src/core/tag.ts:331), not just the form classes.

## Why it matters
`enterkeyhint` is baseline-supported across all modern mobile browsers and is the standard way to label the submit affordance on a search box, a chat composer, or a multi-step wizard input. Any SSR app targeting mobile wants it on search/login/chat inputs. The capability is fully unreachable in a type-safe way today.

## Rough idea (not a design)
Additive (6.1.0): a `type EnterKeyHint = 'enter'|'done'|'go'|'next'|'previous'|'search'|'send'` and a global `setEnterkeyhint(hint?: EnterKeyHint)` on `Tag` (so it also covers contenteditable hosts). No class-emitting method, so no extractor/eslint vocab change; just JSDoc + guideline + CHANGELOG.
