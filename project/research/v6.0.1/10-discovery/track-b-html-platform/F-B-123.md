# No typed editing-globals primitives

## Problem
The editing-host attribute family — `contenteditable` (now with the baseline-supported `plaintext-only` keyword), `writingsuggestions` (Chrome's opt-out of inline AI writing suggestions), `spellcheck`, and `autocapitalize` — has no typed setter anywhere. `Tag` exposes `setRole`/`setTabindex`/`setTitle` as typed globals (src/core/tag.ts:320) but stops short of the editing globals, leaving `addAttribute` (src/core/tag.ts:158) as the only path.

## Evidence
There is no occurrence of these attribute names anywhere in `src/` (verified by grep). The closest analog — typed global setters — exists for role/tabindex/title but not editing:

```ts
// src/core/tag.ts:320
setRole(role: AriaRole): this { return this.addAttribute("role", role); }
// no setContenteditable / setSpellcheck / setAutocapitalize
```

`contenteditable="plaintext-only"` is especially notable: it is the supported, XSS-safer way to build a rich text input that strips formatting, and it cannot be expressed as a boolean `.toggle()` (it's an enumerated attribute), so the closed `BooleanAttribute` union can't reach it either.

## Why it matters
Comment composers, inline-rename fields, and lightweight rich-text areas all use `contenteditable`; `plaintext-only` is the correct primitive for "editable but no markup," and `writingsuggestions="false"` is needed on password-like or code fields. These are platform primitives squarely in Track B's mission, currently only reachable untyped.

## Rough idea (not a design)
Additive (6.1.0): a small set of global enumerated setters on `Tag` (`setContenteditable`, `setSpellcheck`, `setAutocapitalize`) plus adding `'writingsuggestions'` to the `BooleanAttribute` union. No class emission; JSDoc + guideline + CHANGELOG only.
