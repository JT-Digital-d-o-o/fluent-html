# Iframe referrerpolicy is untyped while the same attribute is typed elsewhere

## Problem
A `ReferrerPolicy` closed union already ships (html-types.ts:35) and is correctly applied to `AnchorTag.referrerpolicy` (links.ts:19). The identical attribute on `IframeTag` is typed as a bare `string`, so `setReferrerPolicy("no-refferer")` compiles on an iframe but is a compile error on an anchor — same attribute, two type contracts.

## Evidence
```ts
// src/elements/embedded.ts:15, 57
referrerpolicy?: string;                                  // iframe — bare string
setReferrerPolicy(referrerpolicy?: string): this { ... }
```

```ts
// src/elements/links.ts:19  (anchor — typed)
referrerpolicy?: ReferrerPolicy;
```

```ts
// src/elements/html-types.ts:35  (the union already exists)
export type ReferrerPolicy =
  | 'no-referrer' | 'no-referrer-when-downgrade' | 'origin'
  | 'origin-when-cross-origin' | 'same-origin' | 'strict-origin'
  | 'strict-origin-when-cross-origin' | 'unsafe-url';
```

## Why it matters
Low frequency (iframes are rare in this app class) and low pain, but it is a free consistency win: the union exists, the import is one line, and it removes a surprising hole where the same attribute is typed on `<a>` but not on `<iframe>`. Pure type tightening with no runtime change.

## Rough idea (not a design)
Additive (6.1.0): import `ReferrerPolicy` into embedded.ts and retype the field + setter. Technically narrowing, but the only values it removes were always invalid HTML, so practical breakage risk is negligible; flag for the RFC whether to treat as 6.1.0 or park.
