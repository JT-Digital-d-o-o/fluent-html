# DialogTag is empty — no setClosedby

## Problem
`<dialog>` gained the `closedby` attribute (`"any"` light-dismiss / `"closerequest"` / `"none"`) to control how a modal dismisses — the standards-track replacement for the hand-rolled `dismissOnEscape`/backdrop-click patterns. But `DialogTag` ships with **zero** typed setters:

```ts
// src/elements/interactive.ts:30 (approx)
export class DialogTag extends Tag {
}

defineSchemaKeys(DialogTag, []);

export function Dialog(...children: View[]): DialogTag {
  return new DialogTag("dialog", ...children);
}
```

Contrast `DetailsTag` in the same file, which got a typed `setName`. `closedby` is an enumerated attribute, so it can't ride `BooleanAttribute`/`.toggle()`; the only path today is untyped `addAttribute("closedby", "any")` (src/core/tag.ts:158).

## Why it matters
Native `closedby="any"` gives light-dismiss + Escape handling that the library currently approximates with the `dismissOnEscape` behavior (an `hx-on:keyup` JS snippet) and no backdrop-click handling at all. A modal-heavy SSR app sets this on every `<dialog>`. It's a one-line typed setter following an existing in-file pattern (`DetailsTag.setName`).

## Rough idea (not a design)
Additive (6.1.0): `ClosedBy = "any" | "closerequest" | "none"`; `DialogTag.setClosedby(value?: ClosedBy)` plus the schema key. Pairs naturally with F-B-101 (`command="request-close"`). No class strings; carries guidelines + JSDoc.
