# Customizable `<select>` / `<selectedcontent>` has no primitive

## Problem
The customizable-select feature (a `<button>` + `<selectedcontent>` inside a `<select>`, styled via `appearance: base-select`) lets apps render a fully styleable native dropdown with rich `<option>` content. fluent-html has `Select`, `Option`, `Optgroup` and `Button`, but no `<selectedcontent>` factory, so the trigger's mirrored content has to be produced with the raw `El("selectedcontent")` / `addAttribute` escape hatch.

## Evidence
```ts
// src/elements/forms.ts:396 — SelectTag
export class SelectTag extends Tag { name?: string; size?: number; /* ... */ }
// src/elements/forms.ts:417 — OptionTag exists, but no SelectedcontentTag / Selectedcontent()
```

`src/elements/index.ts` re-exports the form factories; `Selectedcontent` is absent. The new element is the one piece of the customizable-select markup with no typed factory.

## Why it matters
Native customizable select is the platform's answer to the perennial "styled dropdown" problem and removes a whole class of JS combobox widgets. It is the lowest-frequency item in this angle today (still rolling out across browsers), hence low pain, but it is a genuine new platform element with no home in the element table — exactly the kind of additive gap Track B tracks. Note: this is a *primitive* element factory (a one-line `El` wrapper), not an opinionated component, so it clears guardrail #6.

## Rough idea (not a design)
Additive (6.1.0): a one-line `Selectedcontent(...children)` factory alongside `Datalist`/`Legend`. The styling side (`appearance: base-select`, the `::picker(select)` pseudo) is a Tailwind-layer concern — if a method is added there it must update the extractor + eslint vocab in lockstep (class-vocab-sync).
