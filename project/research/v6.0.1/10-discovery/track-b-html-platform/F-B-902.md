# BooleanAttribute union is missing standard media boolean attributes

## Problem
`.toggle(name)` is — by the union's own docstring — "the only way to set" a boolean
attribute (the named boolean setters were removed in v6). Its parameter type is the
**closed** `BooleanAttribute` union (no `(string & {})` escape hatch), so anything not
listed is a hard compile error, not a fallback. The union covers the classic media
booleans (`autoplay`, `controls`, `loop`, `muted`, `playsinline`) but omits the two
standard media-privacy/control booleans:

```ts
// src/elements/html-types.ts:58 — closed union, no escape hatch
export type BooleanAttribute =
  | 'allowfullscreen' | 'async' | 'autofocus' | 'autoplay' | 'checked'
  | 'controls' | 'default' | 'defer' | 'disabled' | 'formnovalidate'
  | 'hidden' | 'inert' | 'ismap' | 'itemscope' | 'loop' | 'multiple'
  | 'muted' | 'nomodule' | 'novalidate' | 'open' | 'playsinline'
  | 'readonly' | 'required' | 'reversed' | 'selected';
  // (no 'disablepictureinpicture', no 'disableremoteplayback')
```

```ts
// src/core/tag.ts:190 — toggle's only accepted names come from that closed union
toggle(name: BooleanAttribute, condition: boolean = true): this { ... }
```

Result: a perfectly standard call is rejected, with no typed path forward:

```ts
Video().setSrc("/clip.mp4").toggle("disablepictureinpicture")  // ✗ compile error
Video().setSrc("/clip.mp4").toggle("disableremoteplayback")    // ✗ compile error
```

Because the union is intentionally closed, the developer can't even widen it locally —
they must drop to `addAttribute("disablepictureinpicture", "")`, defeating the typo-safety
the closed union was built to provide.

## Evidence
- `src/elements/html-types.ts:58` — the `BooleanAttribute` union is explicitly closed (docstring: no `(string & {})`), so omissions are unreachable, not soft-fallback.
- `src/elements/html-types.ts:62` — the media booleans present (`muted`, `playsinline`) stop short of `disablepictureinpicture` / `disableremoteplayback`.
- `src/core/tag.ts:190` — `toggle`'s signature is the sole entry point and is gated by that union.

## Why it matters
Low frequency (only video-heavy surfaces), but it's a clean standards gap with a
one-line fix and zero design risk: both attributes are stable HTML and the natural way
to disable PiP / remote-cast UI on embedded players. Whenever an app does need them, the
closed union forces an `addAttribute` regression precisely where type-safety was promised.

## Rough idea (not a design)
Append `'disablepictureinpicture' | 'disableremoteplayback'` to `BooleanAttribute`.
Purely additive (6.1.0) — widening a closed accepted-input union breaks no caller. Update
the `.toggle()` JSDoc list and the boolean-attributes guideline section.
