# `size-*` exists in Tailwind v4 but not in the fluent vocab

## Problem
Tailwind v4 ships the `size-*` utility (sets `width` and `height` together). The fluent API has no `.size()` method — `w` and `h` are independent vocab rows. Every avatar, icon box, spinner, and square thumbnail is authored as `.w("8").h("8")`, repeating the value and the unit, which is precisely the kind of duplicated literal the styleguide warns against (and a place where `.w("8").h("9")` typos slip through unnoticed).

## Evidence
The vocab has `w` and `h` as separate single-axis sizing rows, with no combined row:

```ts
// src/class-vocab/vocab.ts:108
  size("w", "w"),
  size("h", "h"),
  size("maxW", "max-w"),
  …
```

and the implementations are independent, so a caller must invoke both:

```ts
// src/core/tailwind-methods.ts:403
p.w = function (unitOrValue, amount?) { … return this.addClass(`w-${unitOrValue}`); };
// src/core/tailwind-methods.ts:407
p.h = function (unitOrValue, amount?) { … return this.addClass(`h-${unitOrValue}`); };
```

The `size("…")` vocab row-constructor already models exactly this shape (single-axis sizing with the `(unit, amount)` arbitrary overload), so a `size` *method* would be a one-row addition that reuses the existing emitter and the `TailwindUnit` overload (`src/core/tailwind-types.ts:293`).

## Why it matters
Equal-dimension boxes are extremely common in SSR UIs (icons, avatars, badges, loaders). Each is two calls today; the combinator halves them and removes the silent `.w(x).h(y)` mismatch class. Pain is low (it works today) but frequency is high and the fix is nearly free.

## Rough idea (not a design)
Additive (6.1.0): one new vocab row `size("size","size")` plus the `.size(value)`/`.size(unit, amount)` overloads, emitting `size-*` / `size-[…]`. Extractor and eslint inherit it from the vocab automatically (C-05 lockstep).
