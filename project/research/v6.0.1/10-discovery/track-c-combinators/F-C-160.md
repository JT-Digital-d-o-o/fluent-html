# The raw `[…]` string is the only escape hatch on scalar style methods, and it is unlinted

## Problem
The project's own house style (CLAUDE.md) uses `.textSize("[13px]")` and `.opacity("[0.33]")` as the sanctioned escape hatch. But these methods accept the arbitrary value **only** as a raw bracketed string — there is no `(unit, amount)` overload the way `w`/`h`/`padding`/`minH` have one, and the `prefer-unit-overload` ESLint rule explicitly skips them because they are not in `UNIT_METHODS`. So the cleaner, typo-resistant form simply does not exist for the most common scalar utilities, and nothing nudges the author toward it.

## Evidence
`TailwindTextSize`, `TailwindOpacity`, `TailwindZIndex` (and `TailwindLeading`/`TailwindTracking`/`TailwindFontWeight`/`TailwindRounded`/`TailwindShadow`) all terminate in a free `[${string}]` arm:

```ts
// src/core/tailwind-types.ts:91
export type TailwindTextSize =
  | "xs" | "sm" | "base" | … | (keyof FluentCustomFontSize & string) | `[${string}]`;
// src/core/tailwind-types.ts:124
  | `[${string}]`;   // TailwindOpacity
```

The unit-overload lint only fires for the spacing/sizing family — the scalar methods are absent from the generated set:

```ts
// fluent-html-eslint-plugin/src/vocab.generated.ts:9
export const UNIT_METHODS: ReadonlySet<string> =
  new Set(["bottom","gap","h","inset","left","margin","maxH","maxW","minH","minW","padding","right","top","w"]);
```

```ts
// fluent-html-eslint-plugin/src/rules/prefer-unit-overload.ts:38
if (!UNIT_METHODS.has(methodName)) return;   // textSize/opacity/zIndex never checked
```

So `.textSize("[13px]")` and `.opacity("[0.33]")` — the exact CLAUDE.md examples — type-check, lint clean, and force the author to hand-author bracket syntax with a CSS unit jammed inside a string.

## Why it matters
These are among the highest-frequency style methods in any app (font size, opacity, z-index, line-height). The raw bracket string is the single most error-prone authoring surface in the styling layer: a missing `px`, a stray space inside the brackets, or `text-[13]` (no unit) all type-check and render an invalid class. A unit overload turns those into ordinary typed arguments and lets the existing `prefer-unit-overload` autofix do the cleanup.

## Rough idea (not a design)
Additive (6.1.0): add `(unit, amount)` overloads to the unit-bearing scalar methods and a numeric-arbitrary overload to the unitless ones, mirroring the sizing family's emit shape; regenerate `UNIT_METHODS` from the widened vocab so `prefer-unit-overload` covers them for free. No public shape is removed — the `[${string}]` arm stays as the last-resort escape.
