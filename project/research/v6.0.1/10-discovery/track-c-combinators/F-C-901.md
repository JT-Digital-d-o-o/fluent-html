# No Intersperse/Join combinator — placing a separator *between* mapped items needs index math

## Problem
The iteration surface (`ForEach`, `ForEachElse`, `Repeat`) only ever *maps* — it produces one View per item with nothing in between. The whole `else`/empty axis is now covered (F-C-101, F-C-102, F-C-180), but the **separator axis** has no primitive. The single most common decorated-list pattern — a separator placed *between* items but not after the last (breadcrumb chevrons, "tag · tag · tag" pill rows, pipe-delimited footer nav, "Edit | Delete | Share" action bars) — has no combinator:

```ts
// src/control/iteration.ts:26
export function ForEach<T>(
  views: Iterable<T>,
  renderItem: (item: T, index: number) => View
): View;
```

```ts
// src/control/index.ts:8
export { ForEach, ForEachElse, Repeat } from "./iteration.js";
```

`render` joins a `View[]` with no glue (the array serializer concatenates with nothing between siblings), so a separator can only be smuggled in via `renderItem` using the index — `i > 0 ? [Sep(), item] : item` — or a post-hoc `.flatMap`. Both leak iteration plumbing into the call site and put a `false`/array-shape branch where a clean combinator should be.

## Evidence
`renderItem` exposes `index`, which is the only reason an author can fake interspersing at all:

```ts
// src/control/iteration.ts:26  — index is the lone hook for "is this the first item?"
renderItem: (item: T, index: number) => View
```

There is no `Intersperse` and no `Join` in the iteration module export list:

```ts
// src/control/index.ts:8
export { ForEach, ForEachElse, Repeat } from "./iteration.js";
```

The empty-list branch got two combinators (`ForEachElse`, plus the proposed container form in F-C-180); the between-items branch got zero. Apps currently avoid separators-from-data (six hand-rolled `· ` / `" | "` string concatenations were found, e.g. `rideshare/src/rides/rides.components.ts:110` builds `${...} · ${...}` by hand inside a template literal rather than interspersing Views) precisely because the View-level tool is missing — an adoption gap masked as low usage.

## Why it matters
"Render N things with a divider between them" is a daily UI chore (breadcrumbs, tag chips, nav, metadata rows). Hand-rolling it with `index > 0` checks is exactly the kind of off-by-one, leaks-`false`-into-children plumbing the control combinators exist to absorb, and the string-concatenation workaround pushes inline tags back into raw template literals — losing escaping guarantees and the fluent surface. Low pain today only because the absence suppresses the pattern.

## Rough idea (not a design)
Additive (6.1.0). `Intersperse(items, renderItem, separator: View | (() => View))` — maps each item and emits `separator` between adjacent results, never trailing; and/or a lower-level `Join(views: View[], separator)` over an already-built array. Single-pass, zero deps, returns a `View[]`. Pairs with a views.md example replacing the `index > 0` idiom.
