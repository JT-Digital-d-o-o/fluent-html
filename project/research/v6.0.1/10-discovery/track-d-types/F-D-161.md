# setFormmethod omits the valid 'dialog' value

## Problem
A submit button's `formmethod` attribute overrides the form's `method` and accepts the same three values the platform allows for `<form method>`: `get`, `post`, and `dialog` (the latter closes an ancestor `<dialog>` with the button's value). The setter only allows two of them.

## Evidence
```ts
// src/elements/forms.ts:242
setFormmethod(formmethod?: 'get' | 'post'): this {
```
Meanwhile the library already defines and uses the correct union for the form-level method:
```ts
// src/elements/html-types.ts:26
export type FormMethod = 'get' | 'post' | 'dialog';

// FormTag.setMethod(method?: FormMethod)  — forms.ts:282
```
So `Button(...).setType("submit").setFormmethod("dialog")` — the idiomatic way to make a button submit-and-close a native `<dialog>` (which the lib ships, `interactive.ts:25`) — is a compile error, forcing `addAttribute("formmethod","dialog")`.

## Why it matters
Low frequency but it is a literal type that is narrower than the platform, with the correct wider type already sitting in the file. It also undercuts the dialog primitives the lib ships.

## Rough idea (not a design)
Change the parameter type to `FormMethod`. Purely a widening of an input literal union — additive, no shape change to output, 6.1.0.
