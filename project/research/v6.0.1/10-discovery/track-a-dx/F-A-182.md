# CHANGELOG ordering is broken and self-contradictory

## Problem
The shipped `CHANGELOG.md` violates newest-first ordering: `[6.0.0]` — the current
release — sits at **line 185**, below `[5.11.0]` (line 5), `[5.10.0]`, `[5.9.1]`,
`[5.9.0]`. A reader opening the changelog sees 5.x at the top and must scroll past four
older releases to find what shipped. Worse, the 5.x block at lines 93–99 presents the
**Recursion Schemes** (`paraView`/`unfoldView`/`hyloView`) as new features, while the
`[6.0.0]` entry at line 226 states the entire fold/recursion-schemes layer was deleted.
The top of the file therefore advertises APIs that no longer exist in the shipped
package.

## Evidence

```md
// CHANGELOG.md:5     ## [5.11.0] - Type-Safe Routes & Contexts   <-- top of file
// CHANGELOG.md:93    #### Recursion Schemes
// CHANGELOG.md:95    Three new recursion schemes for View tree processing, complementing the existing `foldView`:
// CHANGELOG.md:97-99 paraView / unfoldView / hyloView  ("new", presented as current)
// CHANGELOG.md:185   ## [6.0.0] - Greenfield v6           <-- the actual current release, buried
// CHANGELOG.md:226   The fold layer is gone — foldView/paraView/unfoldView/hyloView ... removed
```

```sh
$ grep -n "^## \[" CHANGELOG.md | head
5:## [5.11.0] ...
51:## [5.10.0] ...
120:## [5.9.1]
128:## [5.9.0] ...
185:## [6.0.0] - Greenfield v6
```

## Why it matters
The CHANGELOG is the first artifact a consumer reads when adopting or upgrading. The
current shape (a) hides the v6 release and (b) actively teaches removed APIs as current
— a documentation correctness bug for the headline greenfield release. It also
undercuts the v6 "converge / one way to do each thing" stance by leaving the cut fold
layer presented as a feature.

## Rough idea (not a design)
6.0.1 docs patch: move `[6.0.0]` to the top of the file (newest-first), and either
delete the now-misleading 5.x "Recursion Schemes" feature block or annotate it as
removed in 6.0.0 with a forward-pointer to the 6.0.0 removal note. Pure docs; no code or
public-shape change.
