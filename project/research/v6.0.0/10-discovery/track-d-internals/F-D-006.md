# No deep-nesting render test, no stream backpressure test, bench not wired into CI

## Problem

Three test-coverage gaps mean the known bugs in this track are invisible to CI:

### 1. No deep-nesting render test

The `npm test` command lists no test file that exercises nesting beyond ~4 levels. The deepest test in `stream.test.ts` is:

```ts
// test/stream.test.ts:38-40
it("renders deeply nested", async () => {
  const view = Div(Div(Div(Div(Span("Deep")))));  // 4 levels
  assert.equal(await streamToString(view), render(view));
});
```

The bench uses 100 levels, which is safe. Neither probes anywhere near the 3468-level crash threshold documented in the recon. A simple test like:

```ts
function deep(n: number): View { return n === 0 ? Span("leaf") : Div(deep(n-1)); }
it("renders 4000-deep nesting without stack overflow", () => {
  assert.doesNotThrow(() => render(deep(4000)));
});
```

would have caught F-D-001 on first commit.

### 2. No stream backpressure test

`test/stream.test.ts:345` (the "Chunked output" section) only asserts that chunks are emitted and their concatenation equals `render()`. It does not test:
- That large outputs don't materialise entirely in one tick before EOF.
- That `push()` returning `false` causes `streamImpl` to pause (it currently does not).

### 3. Bench not wired into CI

```json
// package.json:6
"test": "npm run build && node --test dist/test/...  (no bench/render.js)"
"bench": "npm run build && node dist/bench/render.js"
```

`bench` is a separate script. A regression that cuts throughput by 50% would not surface in `npm test` or any CI step. Recon documents benchmarks at 1100–23600 ops/sec for different workloads — without a CI ceiling, a destructive change merges silently.

## Why it matters

The stack-overflow in F-D-001 is a known-severity correctness bug. The fact that no test covers it means any fix can also silently regress. The same applies to stream backpressure (F-D-002): the contract the API documents ("flush early bytes") is untenable, and no test enforces it.

## Rough idea (not a design)

- Add `test/render-deep.test.ts`: `render(deep(4000))` must not throw; `render(deep(3000))` must produce the expected string.
- Add a `stream-vs-render` property test using the existing `fuzz.ts` infrastructure: for any generated tree, `streamToString(view) === render(view)`.
- Add a `bench:smoke` script that runs the bench and asserts each case exceeds a documented floor (e.g. realistic page > 15K ops/sec). Wire it into CI as a non-blocking advisory step or a blocking P0 regression gate.
