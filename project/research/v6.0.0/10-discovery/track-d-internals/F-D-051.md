# `escapeAttr` escapes `>` and `'` unnecessarily for double-quoted attributes

## Problem

`escapeAttr` is defined as a one-line alias for `escapeHtml`:

```ts
// src/render/escape.ts:37-39
export function escapeAttr(unsafe: string): string {
  return escapeHtml(unsafe);
}
```

`escapeHtml` scans every character and branches on 5 charCodes:

```ts
// src/render/escape.ts:16-22
if (ch === 38) escaped = '&amp;';       // &
else if (ch === 60) escaped = '&lt;';   // <
else if (ch === 62) escaped = '&gt;';   // >   ← unnecessary for double-quoted attrs
else if (ch === 34) escaped = '&quot;'; // "
else if (ch === 39) escaped = '&#39;';  // '   ← unnecessary for double-quoted attrs
```

The renderer always emits double-quoted attributes (`attr="value"`). The HTML5 spec (§13.1.2) only requires that `&` and `"` be escaped inside double-quoted attribute values:

- `>` (charCode 62) — harmless inside `"..."`, the spec permits it unescaped in attribute values.
- `'` (charCode 39) — harmless inside double-quoted attributes; would only matter in `'...'`-quoted attributes, which this renderer never emits.
- `<` (charCode 60) — technically not required either in quoted attribute values, but commonly escaped as a defence-in-depth practice and kept for safety.

`escapeAttr` is called for every `id`, `class`, `style`, `_sk` field, `extraAttr` value, and every HTMX string attribute on every tag. For the "Flat page (1000 divs)" benchmark (6.4K ops/s), every one of the 1000 elements runs at least `escapeAttr` on its `class` value. Two of the five branch checks in `escapeHtml`'s inner loop are wasted on every character of every attribute value.

## Evidence

Call sites that use `escapeAttr` (both `render.ts` and `stream.ts`):

```ts
// src/render/render.ts:202
if (tid !== undefined) attrs += ' id="' + escapeAttr(tid) + '"';
// src/render/render.ts:204
if (tcls !== undefined) attrs += ' class="' + escapeAttr(tcls) + '"';
// src/render/render.ts:213
attrs += ' ' + sk[i]! + '="' + escapeAttr(typeof value === 'string' ? value : String(value)) + '"';
// src/render/render.ts:225
attrs += ' ' + key + '="' + escapeAttr(String(value)) + '"';
```

The recon file documents that escaping already benchmarks at 13.3M ops/s for clean strings and 4.4M for dirty — meaning the charCode scan runs on every attribute value. Two extra branch checks (`> ` and `'`) fire on each iteration for attributes that contain `>` or `'`, producing work that has no security benefit in the double-quoted context.

The `escape.ts:32-36` comment even acknowledges this is over-specified: "If unquoted or single-quoted attributes are ever supported, this would need to also escape backticks, equals signs, etc." — confirming the current double-quoted-only reality.

## Why it matters

Although the recon memo notes that "escaping is not a bottleneck," that assessment was for text-content escaping on paragraphs with adversarial input. Attribute escaping is a different workload: every tag, regardless of content, runs `escapeAttr` on `id`, `class`, and any schema/extra attributes. A flat page of 1000 divs each with one `class` value runs `escapeAttr` 1000 times. Removing the two unnecessary branches reduces the per-character branch count from 5 to 3 (a 40% reduction in the inner if-chain), with zero security tradeoff for the double-quoted-attribute invariant the renderer already maintains.

This is a free win: the invariant "renderer always emits double-quoted attributes" is structural (not caller-dependent), so a specialized `escapeAttr` can safely skip `>` and `'` permanently.

## Rough idea (not a design)

Implement `escapeAttr` as a separate function (not an alias) that only handles `&` (38) and `"` (34):

```ts
export function escapeAttr(unsafe: string): string {
  let result = '';
  let lastIdx = 0;
  for (let i = 0; i < unsafe.length; i++) {
    const ch = unsafe.charCodeAt(i);
    let escaped: string | undefined;
    if (ch === 38) escaped = '&amp;';     // &
    else if (ch === 34) escaped = '&quot;'; // "
    else continue;
    result += unsafe.substring(lastIdx, i) + escaped;
    lastIdx = i + 1;
  }
  if (lastIdx === 0) return unsafe;
  return result + unsafe.substring(lastIdx);
}
```

The `security/escape` verification lens must confirm no XSS vector is opened by dropping `>` and `'` from attribute escaping. The `htmlEscapes` public map should remain unchanged.
