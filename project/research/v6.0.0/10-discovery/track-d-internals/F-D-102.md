# foldView / paraView / unfoldView / hyloView are unboundedly recursive — same ~3468-depth stack overflow as renderImpl, untested

## Problem

Every public fold-layer function uses direct mutual recursion with no depth guard. The call stack grows proportionally to view tree nesting depth, identical to the already-known `renderImpl` overflow at depth ~3468–3500. Unlike `renderImpl`, none of the four fold functions have a deep-nesting test — the stack overflow would go undetected until a real-world tree hits the limit.

```ts
// src/fold/fold.ts:69
export function foldView<A>(alg: ViewAlgebra<A>, view: View): A {
  ...
  if (isTag(view)) {
    const foldedChildren = foldView(alg, view.child);   // ← unbounded recursion
    return alg.tag(view.el, attrs, foldedChildren);
  }
  if (Array.isArray(view)) {
    const foldedItems = view.map(item => foldView(alg, item));  // ← also recursive
    return alg.list(foldedItems);
  }
  ...
}
```

```ts
// src/fold/para.ts:58, 63
export function paraView<A>(alg: ParaAlgebra<A>, view: View): A {
  ...
  if (isTag(view)) {
    const foldedChildren = paraView(alg, view.child);   // ← unbounded
    ...
  }
  if (Array.isArray(view)) {
    const foldedItems = view.map(item => paraView(alg, item));  // ← unbounded
  }
}
```

```ts
// src/fold/unfold.ts:29, 43
export function unfoldView<S>(coalg: ViewCoalgebra<S>, seed: S): View {
  ...
  case "tag": {
    const children = layer.children.map(s => unfoldView(coalg, s));  // ← unbounded
    ...
  }
  case "list":
    return layer.items.map(s => unfoldView(coalg, s));  // ← unbounded
}
```

```ts
// src/fold/hylo.ts:28, 38
export function hyloView<S, A>(coalg: ViewCoalgebra<S>, alg: ViewAlgebra<A>, seed: S): A {
  ...
  case "tag": {
    const foldedChildren = alg.list(
      layer.children.map(s => hyloView(coalg, alg, s))   // ← unbounded
    );
  }
  case "list":
    return alg.list(
      layer.items.map(s => hyloView(coalg, alg, s))      // ← unbounded
    );
}
```

## Evidence

The deepest "deeply nested" test in `test/fold.ts:21-24` goes only 3 levels:

```ts
it("counts deeply nested", () => {
  assert.deepStrictEqual(foldView(countAlgebra, Div([Div([Span("Inner")])])), 3);
});
```

No test approaches the ~3468 depth where `renderImpl` overflows. Because `foldView` makes exactly the same recursive call pattern as `renderImpl` (one call per Tag node, descending into child), it will overflow at approximately the same depth. The `unfoldView` stack depth is bounded by the coalgebra's generated tree depth; a pathological `tocCoalgebra` seed could generate a deeply nested tree and immediately overflow.

## Why it matters

Any application that:
- runs `foldView` (link extraction, text extraction, accessibility audit, element count) over a deep view tree,
- uses `addClassToMatching` or `createTransformAlgebra` (both call `foldView` internally),
- or generates a view tree via `unfoldView`/`hyloView` from a recursive data structure (nested comments, org trees, nested menus),

hits the same unchecked recursion depth limit as `renderImpl`. The de-recursion work planned for `renderImpl` (existing tracked item) is necessary here too, but nobody has identified the fold layer as also needing it.

Four exported public functions are affected: `foldView`, `paraView`, `unfoldView`, `hyloView`.

## Rough idea (not a design)

De-recurse using an explicit work-stack, sharing the trampoline design with the planned `renderImpl` de-recursion. The fold/catamorphism pattern requires a two-pass stack (push nodes top-down, then pop and fold bottom-up), but the same trampoline technique applies. Do this alongside the renderImpl fix so both are covered by the same deep-nesting test suite.
