# `tocCoalgebra` "entry" case produces `<ul>` nested inside `<li>` instead of `<a>` — exported public API generates invalid HTML

## Problem

`tocCoalgebra` is an exported public coalgebra for building `<ul>/<li>` tables of contents from flat heading entries. Its `"entry"` branch (for headings that have an `id`) tries to produce `<li><a href="#id">text</a></li>`, but instead produces `<li><ul><li>text</li></ul></li>` — a `<ul>` nested inside a `<li>` with no anchor link at all.

The bug: the `"entry"` case with an `id` creates a child seed of type `"list"` with `entries: [{ text, id: undefined }]`. When `unfoldView` processes this child, it dispatches to the `"list"` case, which outputs a `<ul>` element — not the intended `<a>` element. The comment `// The <li> wraps an <a> — we reuse the list seed to produce one child` shows intent, but the logic does not produce an anchor.

## Evidence

```ts
// src/fold/algebras/toc.ts:40-55
case "entry": {
  const { text, id } = seed.entry;
  if (id) {
    return {
      type: "tag",
      element: "li",
      children: [{
        type: "list" as const,       // ← dispatches to "list" branch below
        entries: [{ text, id: undefined }],
      }],
      // The <li> wraps an <a> — we reuse the list seed to produce one child
      //   ^^^ comment is wrong; "list" produces <ul>, not <a>
    };
  }
  return { type: "text", value: text };
}
```

The `"list"` branch unconditionally wraps its entries in `<ul>`:

```ts
case "list":
  return {
    type: "tag",
    element: "ul",           // ← always a <ul>
    children: seed.entries.map(entry => ({ type: "entry" as const, entry })),
  };
```

So for any entry with an `id`, `unfoldView(tocCoalgebra, { type: "list", entries: [{ text: "Intro", id: "intro" }] })` produces:

```
<ul>
  <li>
    <ul>           ← wrong: should be <a href="#intro">Intro</a>
      <li>Intro</li>
    </ul>
  </li>
</ul>
```

The sibling `linkedTocCoalgebra` (same file, line 77) is the correct implementation. It has a dedicated `"link"` seed type that properly yields `<a href="#id">`. `tocCoalgebra` has no such seed type and no tests to catch the divergence.

Test file `test/recursion-schemes.ts` tests `linkedTocCoalgebra` at lines 210–243 but has zero tests for `tocCoalgebra`. The broken code is therefore undetected.

## Why it matters

`tocCoalgebra` and `linkedTocCoalgebra` are both exported from the public API (`src/index.ts:347`). Callers who pick `tocCoalgebra` (the simpler-looking name) receive structurally invalid HTML: `<ul>` inside `<li>` (invalid per HTML spec), no `<a>` tags, no `href` attributes. The feature silently fails. Because the output is still HTML strings with no runtime error, this may ship into production undetected.

## Rough idea (not a design)

Either (a) fix `tocCoalgebra` by adding a `"link"` seed type (matching `linkedTocCoalgebra`) and correcting the `"entry"` branch, or (b) deprecate/remove `tocCoalgebra` in favour of `linkedTocCoalgebra` (which is correct and more capable). At minimum add a test. Option (b) is a v6 simplification opportunity.
