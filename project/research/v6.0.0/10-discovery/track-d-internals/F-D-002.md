# renderToStream walks the entire tree in one synchronous read() tick — no backpressure, eager buffer fill

## Problem

`renderToStream` creates a `node:stream` `Readable` whose `read()` method calls `streamImpl` synchronously over the entire view tree and then immediately calls `this.push(null)`. Every fragment is pushed in one event-loop tick regardless of how fast the consumer (socket, pipe) can absorb it. The `push()` return value — `false` when the internal buffer is full — is never inspected.

```ts
// src/render/stream.ts:112-117
export function renderToStream(view: View): Readable {
  return new Readable({
    read() {
      streamImpl(this, view, false);   // walks whole tree synchronously
      this.push(null);                  // EOF immediately after
    },
  });
}
```

`streamImpl` itself pushes each tag boundary as a separate chunk (open tag, child content, close tag) but never pauses:

```ts
// src/render/stream.ts:181-183
stream.push('<' + el + attrs + '>');
streamImpl(stream, tag.child, childCtx);   // still recursive, no yield point
stream.push('</' + el + '>');
```

The net effect: the entire rendered page materialises in the stream's internal `BufferList` in one tick before any byte reaches the client. For large SSR pages this is equivalent to `render()` followed by a one-shot `res.send()` — the stream abstraction provides no early-flush benefit and uses more memory (chunk objects).

Additionally, `streamImpl` inherits `renderImpl`'s unbounded recursion (see F-D-001): deep trees also crash here.

## Why it matters

The public API documents streaming as a way to "flush early bytes to the client for large SSR responses" (stream.ts:108). This promise is broken. Apps using `renderToStream` get no time-to-first-byte improvement over `render()` + `send()`. The test suite confirms this is undetected: `stream.test.ts` only asserts output *equality* with `render()`, never flush timing or chunk ordering.

## Rough idea (not a design)

After de-recursing the renderer into an explicit work-stack (F-D-001), drive `streamImpl` iteratively from `read()`: each `read()` call pops work-items from the stack, pushes chunks until `push()` returns `false` (back-pressure signal), and returns — yielding to the event loop. This turns the stream into a genuinely incremental renderer at tag boundaries. The fold/unfold layer's anamorphism (`unfoldView`) could also integrate here for server-driven chunking.
