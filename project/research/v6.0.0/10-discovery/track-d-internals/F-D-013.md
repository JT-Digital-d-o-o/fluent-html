# stream.test.ts has no backpressure test — push() discard goes undetected; bench not in CI — perf regressions are invisible

## Problem

### Part A — no backpressure test

`test/stream.test.ts` has a section titled "Stream: Chunked output" (lines 344-367) that checks (a) multiple chunks are emitted and (b) the stream is a valid Readable. No test verifies that the stream _pauses_ when the consumer is slow, or that `push()` returning `false` (highWaterMark exceeded) causes the implementation to stop pushing. The current implementation silently ignores the `push()` return value (F-D-011), and the test suite cannot detect this because every test consumes the stream as fast as possible via `stream.on("data", ...)`.

```ts
// test/stream.test.ts:344-356
describe("Stream: Chunked output", () => {
  it("emits multiple chunks for a tag", async () => {
    const chunks: string[] = [];
    const stream = renderToStream(Div(P("Hello")));
    await new Promise<void>((resolve, reject) => {
      stream.on("data", (chunk: Buffer) => chunks.push(chunk.toString()));
      stream.on("end", resolve);
      stream.on("error", reject);
    });
    // At minimum: open div, open p, text, close p, close div
    assert.ok(chunks.length >= 3, `Expected at least 3 chunks, got ${chunks.length}`);
    assert.equal(chunks.join(""), render(Div(P("Hello"))));
  });
```

The test verifies chunk count and final HTML equality — but both pass regardless of whether backpressure is respected, because the `data` event listener drains the buffer as fast as Node.js fires events.

### Part B — bench not in CI

`package.json` shows `"bench"` as a separate npm script that is not included in `"test"`:

```
"test": "npm run build && node --test dist/test/elements.test.js ... dist/test/stream.test.js ...",
"bench": "npm run build && node dist/bench/render.js",
```

`bench/render.ts` measures ops/sec for flat-page, realistic-page, ForEach, fold, context. None of these measurements are asserted — they are printed to stdout. A commit that regresses flat-page from 6.4K to 1K ops/sec would pass `npm test` without any signal.

## Evidence

`test/stream.test.ts:336-341` — the "large array" test (100 Li items) verifies output equality only, not chunking behavior under backpressure.

`package.json` (test script) — `bench/render.ts` and `bench:mem` are absent; they run only on explicit `npm run bench`.

`src/render/stream.ts:181-183` — `push()` return value discarded three times in the Tag branch alone (open-tag, child recursion, close-tag), with no test catching this.

## Why it matters

The backpressure gap means the streaming guarantee stated in the JSDoc (line 104-110: _"enables flushing early bytes to the client for large SSR responses"_) is untestable and currently false. The bench gap means perf regressions during the v6 de-recursion (F-D in seed backlog) and streaming redesign (F-D-011) cannot be caught automatically.

## Rough idea (not a design)

**Backpressure test:** create a `Readable` with `highWaterMark: 1` and pipe into a slow writable (or pause the stream immediately, calling `.read()` manually). Assert that after the first `push()` returns `false`, no further pushes occur until `read()` is called again. This would have caught the current eager-push bug on day one.

**Perf-smoke in CI:** add a test file (`test/perf.test.ts`) that calls `render(realisticPage())` in a tight loop, asserts the median time-per-op is below a generous ceiling (e.g. 5× the measured baseline), and exits non-zero if the ceiling is breached. Include it in the `test` script. Thresholds should be loose enough to survive CI variance but tight enough to catch catastrophic regressions (10×).
