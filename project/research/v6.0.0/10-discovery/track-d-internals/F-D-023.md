# `ForEach` generic iterable path double-allocates: `Array.from(iter).map(fn)`

## Problem

`ForEach` has three call signatures. The array and numeric overloads pre-size a result array and fill it in one pass. But the generic iterable fallback path takes a different route:

```ts
// src/control/iteration.ts:76
return Array.from(viewsOrLowOrHigh).map(fn);
```

`Array.from(iter)` materializes the entire iterable into a new, fully-typed intermediate array, then `.map(fn)` walks that array *again* to produce the final result array. Two full allocations — the intermediate array and the result array — when only the result is needed.

## Evidence

```ts
// src/control/iteration.ts:40-76
export function ForEach<T>(
  viewsOrLowOrHigh: Iterable<T> | number,
  renderItemOrHigh: ...
  renderItem?: ...
): View {
  // ForEach(low, high, renderItem) — single-pass, pre-sized
  if (typeof viewsOrLowOrHigh === "number" && typeof renderItemOrHigh === "number") {
    const result: View[] = new Array(len);  // ✓ pre-sized, single-pass
    for (let i = 0; i < len; i++) result[i] = renderItem!(low + i);
    return result;
  }
  // ForEach(high, renderItem) — single-pass, pre-sized
  if (typeof viewsOrLowOrHigh === "number") {
    const result: View[] = new Array(len);  // ✓ pre-sized, single-pass
    for (let i = 0; i < len; i++) result[i] = fn(i);
    return result;
  }
  // ForEach(views, renderItem)
  if (Array.isArray(viewsOrLowOrHigh)) {
    const result: View[] = new Array(arr.length);  // ✓ pre-sized, single-pass
    for (let i = 0; i < arr.length; i++) result[i] = fn(arr[i], i);
    return result;
  }
  return Array.from(viewsOrLowOrHigh).map(fn);  // ✗ double-alloc for generic iterables
}
```

The fix is trivially available in the V8 standard library itself: `Array.from(iter, fn)` — the two-argument form of `Array.from` applies the mapping function during materialization, avoiding the intermediate array:

```ts
return Array.from(viewsOrLowOrHigh, fn);
```

Or with index tracking:

```ts
return Array.from(viewsOrLowOrHigh, (item, i) => (fn as (item: T, index: number) => View)(item, i));
```

## Why it matters

Generic iterables include common SSR inputs: Prisma query results (which return `PrismaPromise<T[]>` — but views are built synchronously from arrays), generator functions, `Map#values()`, `Set#values()`, and custom paginators. Apps that wrap database results in generators or use `Map.values()` for key-ordered rendering hit this path. The extra intermediate array is proportional to list length — for `ForEach(rows, ...)` over a 5000-row result, this is an additional 5000-element allocation that is immediately discarded. Given the `Large ForEach (5000 items)` bench is the slowest workload at 0.886 ms/op, reducing allocation on this path is directly in the critical path.

## Rough idea (not a design)

```ts
// Replace:
return Array.from(viewsOrLowOrHigh).map(fn);
// With:
return Array.from(viewsOrLowOrHigh, fn as (item: T, index: number) => View);
```

`Array.from(iterable, mapFn)` is a single-pass, single-allocation path standardized in ES6 and JIT-optimized in V8. The type cast is safe because the generic iterable overload's `fn` always matches `(item: T, index: number) => View`.
