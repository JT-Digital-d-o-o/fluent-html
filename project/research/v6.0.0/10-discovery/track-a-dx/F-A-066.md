# `.neg()` exists as a negative-utility escape hatch but is never documented or used

## Problem

The library provides a `.neg(cls)` method specifically to prepend a `-` prefix for negative Tailwind utility classes:

```ts
// fluent-html/src/core/tailwind-methods.ts:315 (declaration)
neg(cls: string): this;

// fluent-html/src/core/tailwind-methods.ts:663 (implementation)
p.neg = function (cls: string) { return this.addClass(`-${cls}`); };
```

This is the idiomatic fluent-HTML escape hatch for negative values. However:

1. **It is not documented** anywhere in `guidelines/web-development/fluent-html.md` or the README.
2. **Zero apps use it.** A search across all apps returns 0 `.neg(` call-sites.
3. Apps instead use `.addClass("-translate-y-1")` directly — bypassing even this escape hatch.

The intended usage would be:

```ts
// Intended: .neg() escape hatch
.on("hover", t => t.neg("translate-y-1").shadow("lg"))  // → hover:-translate-y-1

// Actual: raw addClass
.on("hover", t => t.addClass("-translate-y-1").shadow("lg"))
```

Both produce the same output, but `.neg()` keeps the value inside the fluent chain vocabulary.

## Evidence

Zero call-sites found:

```
$ grep -rn "\.neg(" /Users/tony/jt-digital --include="*.ts"
(no output)
```

Apps that need negative transforms uniformly use raw `.addClass()`:

```ts
// rideshare/src/landing/landing.components.ts:42
.on("hover", t => t.background("sage").addClass("-translate-y-0.5").shadow("lg"))

// rideshare/src/landing/views/browse-rides.view.ts:188
.on("hover", t => t.addClass("-translate-y-1").shadow("xl"));

// jt-cut/src/home/views/home.hero.view.ts:597
.addClass("-translate-x-1/2")

// jt-cut/src/projects/views/projects.list.view.ts:304
.addClass("-translate-y-1")

// jt-cut/src/shared/components/layout.view.ts:273
.opacity("0").addClass("-translate-x-1")
```

## Why it matters

The compound situation is: (a) `.translate()` generates invalid classes for negative values (F-A-061), (b) `.neg()` is the documented workaround that nobody knows about, (c) apps discover `.addClass("-translate-y-1")` by trial-and-error. The root fix is F-A-061, but even with a fixed `.translate()`, documenting `.neg()` is still useful for cases like `.neg("inset-px")`, `.neg("rotate-12")`, and other negative utilities that lack dedicated fluent methods.

## Rough idea (not a design)

Document `.neg()` in the "Fluent Tailwind Styling" section of `fluent-html.md`, positioned after the arbitrary-value overloads:

```typescript
// Negative utilities — use .neg() to prefix with -:
Div().neg("translate-y-1")    // → -translate-y-1 ✓
Div().neg("inset-px")         // → -inset-px ✓
Div().addClass("-translate-y-1")  // ✗ raw string escape hatch — use .neg() instead
```

This is a guideline-only fix. The code already works.
