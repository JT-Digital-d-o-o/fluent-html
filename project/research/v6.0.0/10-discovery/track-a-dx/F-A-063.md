# Named group and `peer-checked:` modifiers — fluent path exists but is invisible

## Problem

The `.on(state, fn)` method calls `withVariant(tag, prefix, fn)` which prefixes **any string** as a Tailwind variant:

```ts
// fluent-html/src/core/tailwind-methods.ts:326
p.on = function (state: string, fn: (tag: Tag) => Tag) {
  return withVariant(this, state, fn);
};

// line 86
function withVariant(tag: Tag, prefix: string, fn: (tag: Tag) => Tag): Tag {
  const outer = tag._variantPrefix;
  tag._variantPrefix = outer ? `${outer}:${prefix}` : prefix;
  fn(tag);
  tag._variantPrefix = outer;
  return tag;
}
```

This means `.on("peer-checked", t => t.borderColor("coral"))` correctly generates `peer-checked:border-coral`, and `.on("group-hover/info", t => t.opacity("100"))` correctly generates `group-hover/info:opacity-100`. The typed path works.

However, `guidelines/web-development/fluent-html.md` line 107 lists only named states (hover, focus, disabled) and breakpoints without ever demonstrating `peer-checked`, `group-hover/info`, `[&:has(input:checked)]`, or other compound/parametric variants. Apps discover the limitation at code-time and reach for `.addClass()` instead:

```ts
// jt-cut/src/shared/components/ui.components.ts:364
.addClass("group-hover/info:opacity-100 group-hover/info:visible")
// line 368
.addClass("group/info").cursor("help")

// jt-cut/src/projects/text-overlay/text-overlay.view.ts:136
.addClass("peer-checked:border-coral peer-checked:bg-coral-50 peer-checked:text-coral")
// line 205
.addClass("peer-checked:border-coral peer-checked:bg-coral-50")
// line 238
.addClass("peer-checked:border-amber-500 peer-checked:bg-amber-50")

// storysell-ai/src/shared/components/brand/ui.brand.buttons.ts:45
.on("active", t => t.addClass("scale-[0.98]"))  // ✓ .on() used, but falls back to addClass inside
```

Note: jt-cut does use `.on("group-hover", fn)` successfully (e.g. `projects/music/music.view.ts:157`) for simple group hover, but named groups (`group/info`) are always escaped.

## Why it matters

The `[&:has(input:checked)]` and `group/name:` patterns are increasingly common in Tailwind v3/v4 for styled checkboxes and scoped group interactions. When not documented, LLM-generated code (and human code) defaults to `.addClass()` — losing type safety, IDE autocomplete in the callback, and the ability for the ESLint plugin to detect modifier usage.

The fix is purely a guideline addition — no library code needs to change.

## Rough idea (not a design)

Add a guideline section or inline examples to `fluent-html.md`:

```typescript
// Pseudo-class modifiers — .on() accepts any Tailwind variant string:
Div().on("peer-checked", t => t.borderColor("coral").background("coral-50"))   // ✓
Div().on("group-hover/info", t => t.opacity("100").display("block"))            // ✓ named group
Div().on("[&:has(input:checked)]", t => t.borderColor("coral").background("coral/5")) // ✓ arbitrary

// ✗ don't use addClass for these — fluent path handles them:
Div().addClass("peer-checked:border-coral peer-checked:bg-coral-50")
```
