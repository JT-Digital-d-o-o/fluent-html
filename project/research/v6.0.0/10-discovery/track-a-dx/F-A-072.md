# `performance.md` teaches raw HTML for `crossorigin` without the fluent-html typed method

## Problem

`guidelines/web-development/performance.md` is the authoritative source for font-loading and resource-hint patterns. It shows the Google Fonts preconnect pattern as raw HTML:

```html
<!-- guidelines/web-development/performance.md:79-80 -->
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
```

```html
<!-- guidelines/web-development/performance.md:66 -->
<link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>
```

It explicitly requires the bare `crossorigin` attribute:

```
# performance.md:84
### DON'T: Omit `crossorigin` on `fonts.gstatic.com` — font files use CORS, without it the preconnect is wasted
```

But the guideline **never mentions `setCrossorigin()`** — the typed method on `LinkTag`. An LLM reading `performance.md` has no path to the typed API: it copies the raw-HTML example and produces `addAttribute("crossorigin", "")`.

## Evidence

Apps implement the pattern exactly as the guideline shows — via `addAttribute`:

```ts
// tela/src/views/shared.ts:139
Link().setRel("preconnect").setHref("https://fonts.gstatic.com").addAttribute("crossorigin", "")

// gym-crm/src/scenes/core/ui.ts:76
Link().addAttribute("crossorigin", "")

// idea-hub/src/auth/auth.view.ts:42
Link().setRel("preconnect").setHref(font).addAttribute("crossorigin", "")

// vabilo30/src/invite/views/invite.layout.view.ts:84
Link().setRel("preconnect").setHref("https://fonts.googleapis.com").addAttribute("crossorigin", "")

// filmplast-v2/src/shared/layout.ts:68
Link().setRel("preconnect").setHref("https://fonts.gstatic.com").addAttribute("crossorigin", "")
```

Total: **14 callsites across 7+ apps** all use `addAttribute("crossorigin", ...)` rather than the typed setter.

Note: there is a companion type-level bug (F-A-044) — `setCrossorigin()` is typed as `'anonymous' | 'use-credentials'` and cannot emit the bare boolean form required by Google Fonts. So the guideline fix depends on the F-A-044 type fix landing first (or simultaneously), but the guideline gap exists independently of the type bug.

## Why it matters

`performance.md` is an LLM-facing document read by Claude Code every time font loading or resource hints are implemented. Because it shows raw HTML, every Claude Code session that implements preconnect follows the bypass pattern — not because Claude doesn't know about `setCrossorigin`, but because the *guideline it just read* taught raw HTML. This is a systematic multiplier: each project that uses Google Fonts gets the wrong pattern baked in.

## Rough idea (not a design)

1. Once F-A-044 is resolved (bare `crossorigin` support added to `setCrossorigin()`):
   - Replace the raw-HTML snippet in `performance.md` with the fluent-html equivalent.
   - Add a ✓/✗ do-don't pairing: `Link().setCrossorigin()` ✓ vs `addAttribute("crossorigin", "")` ✗.
2. Add a matching note to the `fluent-html.md` Tag Methods section under `LinkTag` describing the preconnect pattern.

## Related findings

[[F-A-044]] — `LinkTag.setCrossorigin()` type bug (bare `crossorigin` not supported); fix that first.
[[F-A-071]] — `setCrossorigin` name is also inconsistent with TypeScript camelCase (`setCrossOrigin` expected); a rename may land alongside the type fix.
