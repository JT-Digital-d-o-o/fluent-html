# Overlay() uses Div([]) array wrapper and .setStyle() inline strings

## Problem

`Overlay()` is a first-party control-flow helper exported from the library. Its implementation violates two of the library's own core rules: (1) children must be passed as variadic args, never wrapped in an array; (2) layout/position should use fluent Tailwind methods, not raw `.setStyle()` string concatenation.

## Evidence

```ts
// fluent-html/src/control/overlay.ts:23-28
export function Overlay(
  content: View,
  overlay: View,
  position: OverlayPosition = 'center'
) {
  return Div([           // ← anti-pattern: array wrapper (CLAUDE.md says Div(a, b), not Div([a, b]))
    content,
    Div(overlay)
      .setStyle(`position: absolute; ${positionStyles[position]} z-index: 10`),  // ← raw CSS string
  ])
    .setStyle("position: relative");  // ← raw CSS string
}
```

The CLAUDE.md rule states:
```
Div(H1("Title"), P("Body"))   // ✓
Div([H1("Title"), P("Body")]) // ✗
```

And the Tailwind guidelines say to use fluent methods (`.position("absolute")`, `.zIndex(…)`) rather than `.setStyle()`. Using `positionStyles` as a raw string table forces any v4 Tailwind migration to update hand-written CSS strings rather than fluent method calls.

The implementation also uses a hand-rolled inline-style string per position variant (`top: 0; left: 50%; transform: translateX(-50%);`) instead of Tailwind utility classes. This means Tailwind's JIT scanner cannot purge these styles, the strings are not type-checked, and consumers cannot override position with `.at("md", t => …)`.

## Why it matters

Overlay is the only built-in library control that ships with these anti-patterns. It sets a bad example for LLMs reading the source, undermines the guidelines' credibility ("the library does what I teach"), and blocks fluent overrides on the overlay container. The Tailwind v4 migration (Track C) would also need to touch inline style strings here, which otherwise could be handled automatically.

## Rough idea (not a design)

Replace the array wrapper with variadic children and the inline style strings with fluent Tailwind calls:

```ts
export function Overlay(
  content: View,
  overlay: View,
  position: OverlayPosition = 'center'
) {
  return Div(
    content,
    Div(overlay)
      .position("absolute")
      .zIndex("10")
      .apply(positionClasses[position]),  // apply() with a fluent modifier function per position
  )
    .position("relative");
}
```

Where `positionClasses` maps each `OverlayPosition` to an `.apply()`-compatible modifier function using fluent methods (`.top("0")`, `.left("1/2")`, `.translate("x", "-1/2")`, etc.).
