# `MetaTag.setProperty()` exists but is undiscoverable — apps split between `setProperty` and `addAttribute('property', ...)` for Open Graph tags

## Problem

`MetaTag` has `setProperty(property?: string)` (document.ts:67) and `'property'` is in `_sk` (document.ts:75). So `Meta().setProperty("og:title").setContent("My Page")` is the correct fluent approach. But the guideline at `fluent-html.md:18` states "never `addAttribute` for standard HTML props" without showing what the standard approach for `property` looks like. There is no OG/social-tags example anywhere in the guidelines.

The result: 3 of 6 apps (jtdigital-landing-page, filmplast-landing-page, filmplast-v2) use the escape hatch; only renderbox uses the typed setter.

## Evidence

Escape-hatch pattern (jtdigital-landing-page, filmplast-landing-page, filmplast-v2):
```ts
// jtdigital-landing-page/src/shared/seo.ts:39
Meta()
  .addAttribute("property", "og:title")   // ← addAttribute for a standard _sk field
  .setContent(props.title)

// filmplast-landing-page/src/shared/seo.ts:39
Meta()
  .addAttribute("property", "og:title")   // ← same escape hatch
  .setContent(props.title)
```

Correct pattern (renderbox, the only app that discovered `setProperty`):
```ts
// renderbox/src/app/shared/components/layout.view.ts:76
Meta().setProperty("og:site_name").setContent("Renderbox")   // ✓ typed setter
Meta().setProperty("og:type").setContent(props.ogType ?? "website")
```

The `MetaTag._sk` is `['name', 'charset', 'httpEquiv', 'property', 'content']` (document.ts:75), confirming `property` is a first-class typed field. The test at `elements.test.ts:464` covers `Meta().setProperty("og:title").setContent("My Page")` but the test is not visible to app authors.

The guideline `fluent-html.md:27-29` shows tag methods for `Button`, `Input`, `Textarea`, `Select`, `A`, `Img`, `Form` — but never shows `Meta`, `Link`, `Script`, or `Title`. There is no head-element example at all in the guideline.

## Why it matters

6 apps each maintain their own `seo.ts` (see F-A-042). Half of them choose `addAttribute` because `setProperty` is never demonstrated. When the guideline says "never `addAttribute` for standard HTML props," an author must know what "standard" means for `MetaTag` — and without an OG example, they can't know that `property` has a setter. This is a pure guideline gap: the code is correct, the teaching is absent.

## Rough idea (not a design)

Add an `## HTML Document & Head` section to `guidelines/web-development/fluent-html.md` showing canonical patterns for: `Title`, `Meta` (charset, viewport, OG property, twitter name), `Link` (canonical, alternate, icon), and `Script` (async, defer via `.toggle()` not `.setAsync()`). A small ✓/✗ snippet showing `Meta().setProperty("og:title").setContent(t)` vs `Meta().addAttribute("property", ...)` would immediately fix the split.
