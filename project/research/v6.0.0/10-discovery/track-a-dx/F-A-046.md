# Guidelines never show `ScriptTag` boolean attributes via `.toggle()` — apps split between `.setDefer()` (renders `defer="true"`) and `.toggle("defer")` (correct)

## Problem

`ScriptTag.setDefer()` and `ScriptTag.setAsync()` store a JS `boolean` and serialize it via the `_sk` loop as `defer="true"` / `async="true"` — which is wrong HTML (see F-A-011). The correct approach is `.toggle("defer")` / `.toggle("async")`, which emits bare `defer` / `async` as HTML boolean attributes.

The bug is real and confirmed by the test suite itself:
```ts
// fluent-html/test/elements.test.ts:488
it("Script external", () => {
  assert.strictEqual(
    render(Script().setSrc("app.js").setDefer()),
    `<script src="app.js" defer="true"></script>`,  // ✗ asserts the wrong output
  );
});
```

The test normalizes incorrect output as correct. There is no test that asserts `defer` (bare). The guidelines have no Script example at all — no mention of `setDefer`, `setAsync`, or `.toggle("async")` for scripts.

## Evidence

Apps that correctly use `.toggle()` (discovered the right pattern independently):
```ts
// jt-vault-cloud/src/shared/components/layout.view.ts:85
Script("").setSrc("https://...gtag/js").toggle("async")   // ✓

// storysell-ai/src/shared/components/layout.view.ts:111
Script("").setSrc("https://...gtag/js").toggle("async")   // ✓

// storysell-ai/src/shared/components/layout.view.ts:147
Script("").setSrc("/js/brand-identity.js").toggle("defer")   // ✓ (×7 per file)

// glimm/src/shared/components/screen.view.ts:121
Script("").setSrc(`/js/cover-tap.js`).toggle("defer")   // ✓
```

Apps that mistakenly use `.setDefer()` (will produce `defer="true"`):
```ts
// projects-template/templates/full-stack/src/shared/components/layout.view.ts:114
Script().setSrc("/js/main.js").setDefer()   // ✗ → <script defer="true">

// gzs/inovacije/src/views/components/layout.view.ts:54
Script().setSrc("https://unpkg.com/htmx.org").setDefer(true)   // ✗

// jt-cut/src/shared/components/layout.view.ts:130
Script().setSrc("...").setDefer()   // ✗

// planet-positive-sport/src/shared/components/layout.view.ts
Script().setSrc(...).setDefer()   // ✗
```

About 12 files use `.toggle("async")` / `.toggle("defer")` (correct); about 12 files use `.setAsync()` / `.setDefer()` (wrong HTML). The split is perfectly even, proving this is a discoverability problem, not a typo.

The **project template** at `projects-template/templates/full-stack/src/shared/components/layout.view.ts:114` uses `.setDefer()` — propagating the wrong pattern to every new app.

## Why it matters

`defer="true"` is not how `defer` works. Per the HTML spec, the presence of the `defer` attribute is what defers execution; its value is irrelevant. Major browsers treat `defer="true"` the same as bare `defer`, so functionally it works, but:
1. HTML validators flag `defer="true"` as invalid.
2. The asymmetry between correct and wrong approaches is invisible — `setDefer()` and `.toggle("defer")` look equally valid to a reader.
3. The project template propagates the wrong pattern to every new project.
4. The test suite asserts wrong output, masking the bug from library authors.

The fix in F-A-011 would make `setDefer()`/`setAsync()` emit correct output, but even with that fix, the guideline gap remains: developers need to know which API to use.

## Rough idea (not a design)

Two parallel fixes needed: (1) fix the rendering in F-A-011; and (2) add a `## Scripts & Stylesheets` section to `guidelines/web-development/fluent-html.md` with a ✓/✗ table showing `.toggle("async")` and `.toggle("defer")` as the canonical idiom, with `.setAsync()` / `.setDefer()` flagged as deprecated. Update the project template to use `.toggle()`. Fix the normalizing test assertion.
