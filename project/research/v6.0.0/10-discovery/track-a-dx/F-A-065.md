# `escapeJs` in `.behavior("clipboard")` doesn't escape newlines

## Problem

The behavior system emits `hx-on:click` attributes that contain inline JS. The `clipboard` behavior interpolates a user-supplied value into a single-quoted JS string literal:

```ts
// fluent-html/src/core/behavior-methods.ts:61
clipboard: (opts) => [
  "click",
  `navigator.clipboard.writeText('${escapeJs(String(opts.value))}')`,
],
```

The `escapeJs` function only escapes backslashes and single-quote characters:

```ts
// fluent-html/src/core/behavior-methods.ts:85
function escapeJs(str: string): string {
  return str.replace(/\\/g, "\\\\").replace(/'/g, "\\'");
}
```

A value containing a newline (`\n`) or carriage return (`\r`) produces a broken attribute:

```
hx-on:click="navigator.clipboard.writeText('line1
line2')"
```

This is a **syntax error** in the generated `hx-on` attribute value. The browser will either silently discard the attribute or throw a parse error depending on the parser. The generated HTML is also not valid XML.

Additionally, a value containing `</script>` or `</style>` (even inside an attribute, via `innerHTML` injection paths) could escape a surrounding raw context.

## Evidence

The minimally-escaped `escapeJs` at line 85:

```ts
// fluent-html/src/core/behavior-methods.ts:85
function escapeJs(str: string): string {
  return str.replace(/\\/g, "\\\\").replace(/'/g, "\\'");
}
```

Missing escape sequences:
- `\n` (newline) — breaks the single-quoted string across lines
- `\r` (carriage return) — same
- ` ` (line separator) — JS treats this as a line terminator inside string literals
- ` ` (paragraph separator) — same as above
- `</script` — not in this context but the same function could be reused

The `clipboard` behavior is the only built-in that interpolates user data into JS. The other behaviors (`toggle`, `remove`, etc.) only reference element IDs which are safe (IDs must match `[a-zA-Z_][a-zA-Z0-9\-_:.]*` per `validateAttributeKey`).

## Why it matters

If a clipboard value is derived from a database field (e.g. a multi-line API key, a formatted address, or a URL with special characters that a future behavior might need), the inline JS breaks. The bug is currently latent because most clipboard values are single-line URLs or codes, but it is a correctness issue that violates the library's otherwise sound security posture (escape-by-default guardrail §11.3).

## Rough idea (not a design)

Replace the minimal `escapeJs` with a complete single-quoted JS string escaper:

```ts
function escapeJs(str: string): string {
  return str
    .replace(/\\/g, "\\\\")
    .replace(/'/g, "\\'")
    .replace(/\n/g, "\\n")
    .replace(/\r/g, "\\r")
    .replace(/ /g, "\\u2028")
    .replace(/ /g, "\\u2029");
}
```

Or switch to `JSON.stringify(value)` (which produces a double-quoted literal) and adjust the template accordingly — JSON.stringify's output is always a safe JS string literal.
