# Tailwind v4 removes cursor:pointer from button preflight — 119+ Button() calls across apps silently lose pointer cursor

## Problem

Tailwind CSS v4 changed the `preflight` (CSS reset) for `<button>` elements: in v3, buttons received `cursor: pointer` by default; in v4 they receive `cursor: default` (matching the browser's native behavior). This is a **silent visual regression** — no compile error, no class change, no warning — every `Button()` call that does not explicitly chain `.cursor("pointer")` will display the wrong cursor under Tailwind v4.

Neither the `fluent-html` library nor its guidelines currently mention this requirement. The guideline file `web-development/fluent-html.md` has no mention of `cursor` requirements for interactive elements beyond the HTMX anchor rule ("Anchors with `setHtmx` need `.cursor("pointer")`").

## Evidence

A search across two production apps reveals 119 `Button()` calls without a `.cursor("pointer")` chain:

- **rideshare** (68 calls): buttons on ride cards, booking flows, auth forms, settings — all will show `cursor: default` on v4.
- **ttl** (51 calls): buttons on time-entry forms, project management, admin views.

Representative examples from rideshare:

```ts
// rideshare/src/auth/auth.components.ts:41-42
Button(label)
  .padding("y", "3.5").rounded("full").border("none")
  .transition("all")
  .on("hover", t => t.background("sage").addClass("-translate-y-0.5").shadow("lg")) as T;
// ← no .cursor("pointer")
```

```ts
// rideshare/src/rides/views/create.view.ts:356
Button("Book ride")
  .padding("y", "3.5").rounded("xl").border("none").cursor("pointer").transition("all")
// ← this one HAS cursor("pointer") — the inconsistency shows there's no enforced pattern
```

From ttl:

```ts
// ttl/src/time-entry/views/time-entry.view.ts:193
Button("Save").transition("colors")...
// ← no .cursor("pointer")
```

```ts
// ttl/src/auth/auth.view.ts:392
.transition("colors").display("block").on("hover", t => t.background("accent-light")).cursor("pointer")
// ← this A tag correctly chains cursor, but the nearby Button() at line 390 does not
```

## Why it matters

Frequency: 119 call-sites across 2 apps (approx), with every unstyled button degrading to `cursor: default` in v4. This is a UX regression on every submit button, action button, and interactive control in the apps. Unlike most class renames where the visual change is subtle (shadow size), an invisible/wrong cursor on a button is immediately jarring to end users and easily testable — but only if you know to look for it.

The inconsistency is visible even today: some buttons have `.cursor("pointer")` and some don't, suggesting developers rely on the v3 preflight to cover the gap. Migrating to v4 without auditing all `Button()` calls will produce a large-scale UX regression.

The guideline at `web-development/fluent-html.md` only calls out cursor for HTMX anchor tags, not for buttons. This is the root cause of the inconsistency: the LLM-facing rule is incomplete.

## Rough idea (not a design)

Two complementary fixes:

1. **Library-level (optional):** `Button()` could include `cursor-pointer` as a built-in default (since virtually all interactive buttons need it). This would be a minor semantic addition and would make the library safer by default. Risk: breaks any intentional `cursor: default` on buttons.

2. **Guideline-level (certain):** Add a rule to `web-development/fluent-html.md`:
   ```
   Button().cursor("pointer")   // ✓ — required under Tailwind v4 (preflight no longer sets it)
   Button()                     // ✗ under v4 — cursor defaults to default, not pointer
   ```

3. **Migration note:** Flag all `Button()` calls missing `.cursor("pointer")` in the `breaking-changes.md` migration guide; provide a codemod search.
