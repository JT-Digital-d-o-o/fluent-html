# `TailwindShadow` / `TailwindRounded` / `TailwindBlur` type tables miss `xs` slot; bare calls silently render smaller on v4

## Problem

Tailwind v4 shifted the shadow, rounded, and blur scales by inserting a new `xs` slot at the small end. The *same class name* now renders differently:

| v3 output | v3 visual | v4 visual |
|---|---|---|
| `shadow` (bare) | medium shadow | small shadow (was `shadow-sm`) |
| `shadow-sm` | small shadow | extra-small shadow (was nothing in v3) |
| `rounded` (bare) | 0.25rem | 0.125rem (was `rounded-sm`) |
| `blur` (bare) | 8px blur | 4px blur (was `blur-sm`) |

These are **silent visual regressions**: no TypeScript error, no runtime warning, no build failure. Every card, button, and input in every app using these bare methods will look subtly different on v4.

The type tables don't include `"xs"` so users cannot even express the v4 `shadow-xs` / `rounded-xs` / `blur-xs` values via the fluent API.

## Evidence

`fluent-html/src/core/tailwind-types.ts` line 77 — `TailwindRounded` has no `"xs"`:
```typescript
// tailwind-types.ts:77
export type TailwindRounded = "none" | "sm" | "md" | "lg" | "xl" | "2xl" | "3xl" | "full" | `[${string}]`;
//                                    ^^^^ on v4 this is 0.125rem, not 0.25rem; "xs" is missing entirely
```

`tailwind-types.ts` line 81 — `TailwindShadow` has no `"xs"`:
```typescript
// tailwind-types.ts:81
export type TailwindShadow = "sm" | "md" | "lg" | "xl" | "2xl" | "inner" | "none" | (string & {});
//                           ^^^^ on v4 this is shadow-xs visually; users can't type "xs" at all
```

`tailwind-types.ts` line 205 — `TailwindBlur` has no `"xs"`:
```typescript
// tailwind-types.ts:205
export type TailwindBlur = "none" | "sm" | "md" | "lg" | "xl" | "2xl" | "3xl" | `[${string}]`;
//                                  ^^^^ same scale shift; "xs" missing
```

`fluent-html/src/core/tailwind-methods.ts` line 596 — bare `.blur()` emits the bare class name:
```typescript
// tailwind-methods.ts:596
p.blur = function (value?: string) {
  return value === undefined ? this.addClass("blur") : this.addClass(`blur-${value}`);
  //                                         ^^^^^^ renders differently on v4
};
```

`fluent-html-tailwind-extractor/src/index.ts` line 289 — extractor mirrors the same bare form:
```typescript
// extractor/index.ts:289
{ methodName: "shadow",
  generateClass: (args) => args.length === 0 ? ["shadow"] : [`shadow-${args[0]}`] },
```

## Why it matters

These are the most pervasive styling utilities in any UI: shadows on cards/modals/dropdowns, rounded corners on buttons/inputs/badges, blur on overlays/backdrops. Every app using `fluent-html` with bare `.shadow()`, `.rounded()`, or `.blur()` will see different rendering on v4 without a single code change or error. The TypeScript type gap (`"xs"` absent) also means there is no way to opt into the new v4 small values without using the `(string & {})` escape hatch.

## Rough idea (not a design)

Add `"xs"` to `TailwindShadow`, `TailwindRounded`, `TailwindBlur` (and `TailwindDropShadow`/`TailwindBackdropBlur` if they exist). For the scale-shift migration, produce a CHANGELOG / migration guide table mapping v3 bare values to their v4 visual equivalents (`shadow` → `shadow-sm`, `rounded` → `rounded-sm`, etc.). Consider a v3-compat mode shim (e.g. `.shadow()` emits `shadow-sm` on a v4 target flag) to preserve visual parity for existing apps.
