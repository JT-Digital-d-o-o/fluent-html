# `.on("hover", ...)` semantics silently change in Tailwind v4 — `hover:` now requires a pointer device

## Problem

In Tailwind v3, `hover:` styles apply to all `:hover` events regardless of input device. In Tailwind v4, `hover:` is wrapped in `@media (hover: hover)`, which means it fires **only on pointer devices** (mouse/trackpad) — touch-only devices never trigger `hover:` styles.

The fluent-html `.on("hover", ...)` method emits `hover:` verbatim:

```ts
// fluent-html/src/core/tailwind-methods.ts:326-328
p.on = function (state: string, fn: (tag: Tag) => Tag) {
  return withVariant(this, state, fn);
};
```

There is no warning, no alternative API, and no documentation that this behavioral change occurs when upgrading to v4. Apps that rely on hover interactions for interactive feedback — navigation links, buttons, cards — will silently lose those effects on touch devices after a v4 upgrade.

## Evidence

The ttl app has heavy `.on("hover", ...)` usage across interactive elements:

```ts
// ttl/src/home/views/landing.components.ts:43
.on("hover", t => t.textColor("accent"))

// ttl/src/home/views/landing.view.ts:83
.on("hover", t => t.background("accent-light"))

// ttl/src/auth/auth.view.ts:78
.on("hover", t => t.underline()).cursor("pointer")

// ttl/src/auth/auth.view.ts:392
.transition("colors").display("block").on("hover", t => t.background("accent-light")).cursor("pointer")
```

Over 20 `.on("hover", ...)` call-sites in `ttl/src` alone. CLAUDE.md already notes "anchors with `setHtmx` need `.cursor("pointer")`" which hints at hover-related guidance, but there is no mention of the v4 behavioral change or the need to pair `hover:` with `focus-visible:` for accessible touch-device support.

## Why it matters

This is a **silent semantic regression** — the class string `hover:bg-accent-light` is valid in both v3 and v4, so no linting or type errors surface. The visual regression only appears at runtime on touch devices. Given the number of call-sites and the fact that the apps target web (where mobile is a primary use case), this is a medium-pain issue that could cause significant UX degradation post-migration without a migration note.

The CLAUDE.md fluent-html guidelines document `.on("hover", ...)` as the correct pattern without any caveats about v4 pointer-device gating, making this an `adoption-gap`-adjacent issue for the guidelines workstream.

## Rough idea (not a design)

Add a migration note to `TAILWIND-SETUP.md` and the fluent-html guidelines that `.on("hover", ...)` behavior changes in v4 and that interactive elements should always pair hover with `.on("focus-visible", ...)` for keyboard/touch accessibility. Optionally expose a `.onPointerHover()` helper that emits `[@media(hover:hover)]:hover:` for explicit pointer-only intent vs `.on("hover", ...)` for the v4 default.
