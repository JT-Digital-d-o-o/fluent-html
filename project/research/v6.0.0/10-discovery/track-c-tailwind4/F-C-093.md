# spaceX()/spaceY() emit space-x-*/space-y-* whose underlying CSS selector changed in Tailwind v4

## Problem

`spaceX(value)` and `spaceY(value)` produce `space-x-{value}` / `space-y-{value}` Tailwind utility classes. In Tailwind **v3**, these classes use the selector `> :not([hidden]) ~ :not([hidden])` with a **negative margin** on the leading sibling — this intentionally skips elements that have the `hidden` attribute or are conditionally hidden. In Tailwind **v4**, the selector was changed to `> :not(:last-child)` with the margin applied to the **last child direction** (margin-bottom for `space-y`, margin-right for `space-x`). The class *name* is unchanged; only the generated CSS differs.

This means every existing `spaceX()`/`spaceY()` call silently changes behavior on v4 migration:
- Elements with `hidden` attribute that were previously skipped now receive spacing.
- The margin direction flips, which may cause border/edge-case layout shifts.
- There is no compile error, no type error, and no ESLint warning.

## Evidence

```ts
// fluent-html/src/core/tailwind-methods.ts:514-515
p.spaceX = function (value: string) { return this.addClass(`space-x-${value}`); };
p.spaceY = function (value: string) { return this.addClass(`space-y-${value}`); };
```

```ts
// rideshare/src/rides/views/detail.view.ts:126 — spaceY used for child stack layout
).spaceY("3"),

// rideshare/src/rides/views/detail.view.ts:142 — same
).spaceY("2"),

// rideshare/src/reservations/reservations.view.ts:383
).spaceY("4"),

// rideshare/src/reservations/reservations.view.ts:437
).spaceY("4"),

// rideshare/src/co2/co2.view.ts:116
).spaceY("6"),
```

In all 5 cases the parent element may conditionally render or hide child elements (the reservation and ride detail views have conditional children based on ride state). When a child is hidden via `[hidden]` or `display:none`, v3 correctly excluded it from the spacing chain; v4 no longer does.

**v3 generated CSS (space-y-4 example):**
```css
.space-y-4 > :not([hidden]) ~ :not([hidden]) {
  --tw-space-y-reverse: 0;
  margin-top: calc(1rem * calc(1 - var(--tw-space-y-reverse)));
  margin-bottom: calc(1rem * var(--tw-space-y-reverse));
}
```

**v4 generated CSS (space-y-4 example):**
```css
.space-y-4 > :not(:last-child) {
  margin-bottom: 1rem;
}
```

The selector change removes the `[hidden]` guard. Any conditionally-hidden child element now gets `margin-bottom: 1rem` even when it's hidden, which can cause phantom spacing when the element is `display:none` or `visibility:hidden` (but not `[hidden]` attribute which triggers `display:none`). More critically, if any sibling uses `[hidden]` to toggle visibility, v4 no longer skips it in the sibling count.

## Why it matters

Five call-sites in rideshare use `spaceY()`, and the reservation and detail views conditionally render children (e.g., an info block that appears only when a booking is confirmed). These will silently gain extra spacing in v4 when hidden siblings exist.

The existing fluent-html documentation for `spaceX`/`spaceY` does not mention this v3/v4 behavioral difference. Neither the extractor, ESLint plugin, nor CLAUDE.md warn about it.

The preferred v4 alternative is `gap()` on a flex/grid container — which has no hidden-element selector complication and is broadly the recommendation from the Tailwind team for v4.

## Rough idea (not a design)

1. Add a note to the v4 migration guide: `spaceX`/`spaceY` change semantics; replace with `flex().gap()` or `grid().gap()` for reliable v4 behavior.
2. Add an ESLint rule or warning for `spaceX`/`spaceY` usage when migrating to v4.
3. Update CLAUDE.md with a ✓/✗ showing `gap()` as the preferred alternative to `spaceX`/`spaceY` under v4.

```ts
// ✗ v3 behavior silently changes in v4 (selector no longer skips [hidden] siblings)
Div(childA, childB).flexDirection("col").spaceY("4")

// ✓ v4-safe alternative using flex gap
Div(childA, childB).flex().flexDirection("col").gap("4")
```
