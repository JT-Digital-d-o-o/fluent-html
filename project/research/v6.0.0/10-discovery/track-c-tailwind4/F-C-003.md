# `.outline('none')` is a silent a11y regression on Tailwind v4

## Problem

In Tailwind v4 the meaning of `outline-none` changed:

- **v3 `outline-none`**: sets `outline: 2px solid transparent; outline-offset: 2px` — visually invisible but present for accessibility (high-contrast mode, forced-colors mode still sees it).
- **v4 `outline-none`**: sets `outline-style: none` — the outline is completely absent. This is an a11y regression.
- **v4 `outline-hidden`** (new): carries the old `outline-none` a11y-safe behaviour.

fluent-html's type for `.outline()` does not include `"hidden"`, and there is no dedicated `.outlineHidden()` method:

```ts
// fluent-html/src/core/tailwind-types.ts:165
export type TailwindOutline = "none" | "dashed" | "dotted" | "double";
//                                                                       ^^ "hidden" is missing
```

```ts
// fluent-html/src/core/tailwind-methods.ts:568
p.outline = function (value: string) { return this.addClass(`outline-${value}`); };
// No .outlineHidden() dedicated method; no type-safe alternative to .outline("none")
```

```ts
// fluent-html-tailwind-extractor/src/index.ts:282-283
methodName: "outline",
generateClass: (args) => args.length === 0 ? ["outline"] : [`outline-${args[0]}`],
// Will emit `outline-none` on v4 — produces the wrong a11y behaviour
```

## Evidence

`.outline("none")` is used throughout both shipped apps to suppress default browser outlines on focusable elements, expecting v3 semantics (accessible hidden outline). On v4 these calls now produce a real `outline-style:none`, stripping the element's outline entirely:

```ts
// ttl/src/home/views/landing.view.ts:84
.on("focus-visible", t => t.ring("2").ringColor("accent").outline("none"))

// ttl/src/home/views/landing.components.ts:44
.on("focus-visible", t => t.ring("2").ringColor("accent").outline("none").rounded("lg"))

// ttl/src/shared/components/layout.view.ts:148
.on("focus-visible", t => t.ring("2").ringColor("accent").outline("none").rounded("lg"))

// ttl/src/shared/components/ui.components.ts:36
.on("focus", t => t.borderColor("accent").outline("none"))

// rideshare/src/rides/views/create.view.ts:340
.on("focus", t => t.borderColor("leaf").outline("none"))

// rideshare/src/auth/auth.components.ts:31
.outline("none").transition("colors")
```

Approx 26 `.outline("none")` call-sites across two apps (14 in ttl, 12 in rideshare). The pattern is nearly always part of a focus-ring replacement pattern: replace the default outline with a custom ring. On v4 the outline is *actually* removed rather than hidden, which is a regression in browsers/assistive tech that rely on forced-colors mode.

The ESLint auto-fix rule at L343 (`{ pattern: "outline-", methodName: "outline" }`) will continue to route `outline-hidden` → `.outline()` suggestion, which is correct direction but misses the opportunity to distinguish the two semantically.

## Why it matters

This is an a11y regression hidden behind a type-correct API call. No TypeScript error fires. The visual ring (`.ring("2")`) is still there, so manual visual testing won't catch it — only forced-colors/high-contrast testing will. Given the frequency (approx 26 sites in two apps), this is a high-pain silent regression that affects every keyboard user.

The correct v4 pattern is `.outlineHidden()` (new dedicated method) or `.outline("hidden")`, not `.outline("none")`. Neither the library nor the guidelines currently teach this distinction.

This is also a guideline gap: `guidelines/web-development/fluent-html.md` (and CLAUDE.md) teach the pattern `.on("focus", t => t.ring("2").outline("none"))` implicitly through examples — but that pattern becomes wrong on v4. The RFC should propose both a code fix and a `✗ .outline("none") → ✓ .outlineHidden()` guideline rule.

## Rough idea (not a design)

Add a dedicated `.outlineHidden()` method to `tailwind-methods.ts` that emits `outline-hidden`. Add `"hidden"` to `TailwindOutline`. Update extractor L282. Update the ESLint auto-fix map to route `outline-hidden` class → `.outlineHidden()` and `outline-none` class → `.outline("none")` with a note. Add a `✗`/`✓` do-don't in `fluent-html.md` for the focus-ring pattern.
