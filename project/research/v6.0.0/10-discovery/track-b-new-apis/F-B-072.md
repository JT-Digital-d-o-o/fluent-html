# htmx-indicator CSS boilerplate copy-pasted into every app layout; no fluent-html primitive for loading states

## Problem

Every app that uses htmx loading indicators must: (1) copy-paste a 3-line CSS block into a `Style()` tag inside `<head>`, and (2) use raw `.setClass("htmx-indicator")` (or `.addClass("htmx-indicator")`) to mark spinner elements — bypassing the fluent-methods-only rule. There is no fluent helper for either.

## Evidence

The same CSS block appears verbatim in at least 4 layout files across 3 apps:

```ts
// storysell-ai/src/shared/components/layout.view.ts:97-98
Style(`
  .htmx-indicator { opacity: 0; transition: opacity 200ms ease-in; }
  .htmx-request .htmx-indicator, .htmx-request.htmx-indicator { opacity: 1; }
  .htmx-request button[type="submit"], .htmx-request input[type="submit"] {
    opacity: 0.5; pointer-events: none;
  }
  /* In-button loader: swap the idle label for a spinner while the request runs. */
  @keyframes hx-spin { to { transform: rotate(360deg); } }
  .hx-spinner { display: inline-block; width: 1rem; height: 1rem; ... }
`)
```

Identical structure in:
- `glimm/src/shared/components/layout.view.ts:74-75`
- `glimm/src/landing/views/landing.shell.ts:119-120`
- `glimm/src/shared/components/screen.view.ts:109-110`

The global loading bar is also re-implemented per app using raw string classes:

```ts
// storysell-ai/src/shared/components/layout.view.ts:51-57
export function LoadingBar() {
  return Div(
    Div("").w("full").h("1").background("primary").animate("pulse"),
  )
    .setId(layoutIds.globalLoading)
    .setClass("htmx-indicator")            // ← raw class string, not a fluent method
    .position("fixed").top("0").left("0").right("0").zIndex("50");
}
```

```ts
// glimm/src/shared/components/layout.view.ts:40-47 — verbatim copy of the same function
export function LoadingBar() {
  return Div(
    Div("").w("full").h("1").background("primary").animate("pulse"),
  )
    .setId(layoutIds.globalLoading)
    .setClass("htmx-indicator")
    .position("fixed").top("0").left("0").right("0").zIndex("50");
}
```

Inline htmx-indicator spans in controllers:

```ts
// jt-cut/src/projects/views/projects.render.view.ts:258
Span("Starting…").addClass("htmx-indicator"),
// jt-cut/src/projects/views/projects.render.view.ts:341
Span("Starting…").addClass("htmx-indicator"),
// jt-cut/src/projects/voiceover/voiceover.view.ts:260
Span("Generating...").addClass("htmx-indicator"),
```

mngmt invents its own variant class (`htmx-indicator-progress`) with a custom CSS rule for a progress bar upload indicator (`mngmt/src/attachments/attachments.components.ts:87,233-234`).

## Why it matters

Six separate layout files across at least 4 apps carry verbatim copies of the htmx-indicator CSS. This is pure boilerplate with no variation (the CSS is identical). Any app that forgets to include it gets broken loading states silently. The `.setClass("htmx-indicator")` call also violates the "fluent methods, not setClass" guideline — but there is no `.htmxIndicator()` method to replace it with.

The htmx.md guideline teaches `hx-indicator` attribute usage but doesn't mention the CSS requirement or provide a helper. New apps will copy-paste from an existing layout rather than reaching for a library primitive.

## Rough idea (not a design)

Add `.htmxIndicator()` as a fluent tag method that emits `class="htmx-indicator"` (analogous to how `.hidden()` emits `display: none`). Add `HtmxIndicatorStyles()` (or fold into a broader `HtmxDefaults()`) that returns the canonical `<style>` block to be placed in `<head>` — so every app's layout calls `HtmxIndicatorStyles()` instead of copy-pasting the CSS string. A `LoadingBar({ id })` built-in (fixed, top, full-width, indicator-class, pulsing) would remove the near-identical `LoadingBar()` functions in storysell and glimm.
