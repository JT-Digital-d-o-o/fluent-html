# CLAUDE.md index lists only 4 of 9 .behavior() variants — toggleClass, remove, focus, scrollTo, selectAll invisible to LLM

## Problem

`fluent-html` ships 9 built-in behaviors: `toggle`, `toggleClass`, `remove`, `clipboard`, `disable`, `focus`, `scrollTo`, `selectAll`, `back`. The `CLAUDE.md` index — the first file Claude Code reads — shows only 4 of them in its canonical example:

```ts
// CLAUDE.md:201 — only 4 shown
Button("Toggle").behavior("toggle", { target: ids.filterPanel })
Button("Copy").behavior("clipboard", { value: apiKey })
Button("Submit").behavior("disable")
A("Back").behavior("back").cursor("pointer")
```

The remaining 5 — `toggleClass`, `remove`, `focus`, `scrollTo`, `selectAll` — appear nowhere in `CLAUDE.md`. An LLM following the guidelines will never suggest them. Result: apps write inline `Script()` blocks or `addAttribute("hx-on:click", ...)` for interactions that existing `.behavior()` variants would handle cleanly.

## Evidence

**mngmt: Script() for toggle + focus — solvable with behavior("toggle") + behavior("focus") chained:**

```ts
// mngmt/src/comments/comments.components.ts:216
Script(`
  (function() {
    var toggle = document.getElementById('${toggleId}');
    toggle.addEventListener('click', function() {
      var form = document.getElementById('${formId}');
      if (form) { form.classList.toggle('hidden'); form.querySelector('textarea')?.focus(); }
    });
  })();
`)
```

This pattern — toggle visibility then focus a child — could be expressed as:
```ts
Button("Reply")
  .behavior("toggle", { target: formId })
  .behavior("focus", { target: textareaId })
```
…but developers don't know `behavior("focus")` exists.

**rideshare: uses behavior("toggleClass") correctly — the only app that discovered it:**

```ts
// rideshare/src/shared/components/tooltip.view.ts:75
.behavior("toggleClass", { target: id, class: VISIBLE_CLASS });
```

This is not documented in CLAUDE.md. It was found by a developer reading the TypeScript types directly.

**fluent-html behavior-methods.ts — all 9 exist:**

```ts
// fluent-html/src/core/behavior-methods.ts:11
export type BehaviorMap = {
  toggle:      { target: Id };
  toggleClass: { target: Id; class: string };
  remove:      { target: Id };
  clipboard:   { value: string };
  disable:     void;
  focus:       { target: Id };
  scrollTo:    { target: Id };
  selectAll:   void;
  back:        void;
};
```

## Why it matters

`.behavior()` is the guideline-mandated alternative to inline JS and `addAttribute("hx-on:...")`. The CLAUDE.md explicitly says "never raw inline JS; use `.behavior()`" — but without knowing all 9 behaviors exist, devs fall back to the forbidden patterns for any interaction not in the 4-item list. The mngmt Script() case is a direct example: the developer wrote 9 lines of JS for an interaction that already has a built-in behavior.

Frequency: 5 apps with Script() or hx-on for interactions covered by undocumented behaviors. Pain: medium — correctness issue (inline JS escaping risks) + guideline violation.

## Rough idea (not a design)

Add all 9 behaviors to the CLAUDE.md code block with a one-line comment describing each; keep the existing 4 examples, extend with:
```ts
Button("Delete").behavior("remove", { target: ids.row })
Input().behavior("selectAll")
Button("Jump").behavior("scrollTo", { target: ids.section })
Button("Reply").behavior("toggleClass", { target: ids.badge, class: "ring-2" })
```
Also add a note that `.behavior()` calls can be chained for multi-step interactions (toggle + focus). No code change needed.
