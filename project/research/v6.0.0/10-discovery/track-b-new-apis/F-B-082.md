# Generic Card({ title?, content }) reimplemented as a shared component in 5+ apps

## Problem

A generic content card (white/surface background, border, rounded corners, optional title heading) is independently reimplemented as `Card` in at least five apps. All have near-identical structure; the only differences are minor (title element tag, token names for border/shadow colors, padding value). None import it from a shared source — each app owns its own copy.

## Evidence

**glimm** and **storysell-ai** — literally the same file path and same signature:

```ts
// glimm/src/shared/components/ui.layout.components.ts:13
// storysell-ai/src/shared/components/ui.layout.components.ts:13
type CardProps = { title: string; content: View };
export function Card({ title, content }: CardProps) {
  return Div(
    H3(title).textSize("lg").fontWeight("semibold").margin("b", "4"),
    content,
  ).padding("6").rounded("2xl").background("slate-900/50").border().borderColor("slate-800");
  // storysell uses same structure; glimm uses different color tokens
}
```

**jt-cut** — shared component, `title` made optional:

```ts
// jt-cut/src/shared/components/ui.components.ts:104
type CardProps = { title?: string; content: View };
export function Card({ title, content }: CardProps) {
  return Div(
    ...(title ? [H3(title).textSize("lg").fontWeight("semibold").textColor("txt").margin("b", "4")] : []),
    content,
  ).background("white").rounded("2xl").shadow("sm").border().borderColor("border-ui").padding("6");
}
```

**rideshare** analytics component:

```ts
// rideshare/src/analytics/analytics.components.ts:111
export function Card(title: string, content: View) {
  return Div(
    H3(title).textSize("lg").fontWeight("semibold").margin("b", "4"),
    content,
  ).padding("6").rounded("2xl").background("slate-900/50").border().borderColor("slate-800");
}
```

**mngmt** — both in analytics view (private) and dashboard components (exported):

```ts
// mngmt/src/analytics/analytics.view.ts:51
function Card({ title, content }: CardProps): View {
  return Div(
    H3(title).textSize("lg").fontWeight("semibold").margin("b", "4"),
    content,
  ).padding("6").rounded("2xl").background("slate-900/50").border().borderColor("slate-800");
}
// mngmt/src/dashboard/dashboard.components.ts:131
export function Card({ children }: { children: View }): View {
  return Div(children).padding("4").rounded("lg").border().borderColor("surface").background("card-bg");
}
```

## Why it matters

Six apps/sites define a `Card` wrapper; the recon doc (§4) lists it alongside `EmptyState`, `Pagination`, and `PrimaryButton` as a helper "reimplemented in ≥3 projects — a near-certain missing built-in." Unlike the more complex stat card (F-B-081), this is a pure layout primitive with no logic — it should be trivial to ship as built-in and would delete a definition site in every consuming app.

The varying signatures (positional `title, content` in rideshare vs. props object in glimm/storysell/jt-cut; `children` in mngmt dashboard) also indicate a lack of a canonical shape to converge on.

## Rough idea (not a design)

`Card(...children)` as a variadic Tag-returning helper — same calling convention as `Div`/`Section` — plus an optional `CardHeader(title, actions?)` companion. Styled with neutral surface tokens so theme customization via context tokens applies. Subsumes all current per-app `Card`, `DashboardSection`, and simple panel patterns.
