# Skeleton loading components copy-pasted identically across apps with only color-token differences

## Problem

`SkeletonText`, `SkeletonRow`, and `SkeletonCard` are implemented in at least two apps with file-for-file identical structure and logic. The only difference is the background color token (`gray-200` in storysell-ai, `sand-2` / `foam` in glimm). This is the canonical pattern for a missing built-in: identical logic, per-app color customization.

## Evidence

```ts
// storysell-ai/src/shared/components/ui.loading.components.ts:7-21
export function SkeletonText({ lines = 3 }: SkeletonTextProps = {}) {
  const lineWidths = ["w-full", "w-3/4", "w-5/6", "w-2/3", "w-4/5"] as const;
  const items = Array.from({ length: lines }, (_, i) => lineWidths[i % lineWidths.length]);

  return Div(
    ForEach(items, (width) =>
      Div("")
        .h("4")
        .rounded()
        .background("gray-200")   // ← color token
        .animate("pulse")
        .addClass(width)           // ← width is a Tailwind fraction class; no fluent method
    ),
  ).flex().flexDirection("col").gap("3");
}
```

```ts
// glimm/src/shared/components/ui.loading.components.ts:7-21 (identical structure)
export function SkeletonText({ lines = 3 }: SkeletonTextProps = {}) {
  const lineWidths = ["w-full", "w-3/4", "w-5/6", "w-2/3", "w-4/5"] as const;
  const items = Array.from({ length: lines }, (_, i) => lineWidths[i % lineWidths.length]);

  return Div(
    ForEach(items, (width) =>
      Div("")
        .h("4")
        .rounded()
        .background("sand-2")     // ← only change: different brand color token
        .animate("pulse")
        .addClass(width)
    ),
  ).flex().flexDirection("col").gap("3");
}
```

`SkeletonCard` is similarly copy-pasted: storysell uses `gray-200` / `white` / `gray-200`, glimm uses `sand-2` / `foam` / `sand-2`. The structure and props (`hasTitle?: boolean`) are identical.

The recon doc (`02-app-patterns.md`) also notes skeleton components in storysell and glimm independently: "SkeletonText/SkeletonRow/SkeletonCard redefined identically in storysell/glimm" (§3.10), confirming this is a documented duplication.

## Why it matters

Two full files (~60 LOC each) of identical logic. Any bug fix or animation improvement must be applied in every app separately. The pattern also forces each app to use `.addClass(width)` for fractional widths (no fluent method covers `w-3/4` etc.) — which is a secondary API gap also requiring `addClass` as an escape hatch for fraction widths.

The recon doc already flagged this as a near-certain missing built-in (§3.10): "SkeletonText/SkeletonRow/SkeletonCard redefined identically in storysell/glimm — First-class API: Skeleton({ variant })."

## Rough idea (not a design)

A `Skeleton({ variant: "text" | "row" | "card", lines?, hasTitle? })` component that reads a configurable skeleton-color from a `SkeletonTheme` context (so apps set the base color once via context instead of forking the file). Alternatively, add `w("3/4")` overloads for Tailwind fraction widths to the `w()` method so the `addClass(width)` escape hatch isn't needed.
