# Modal component contradicts its own doc comment: says 'use .behavior(toggle)' but its own implementation can't

## Problem

The pps `Modal` component ships a doc comment that tells callers to use `.behavior("toggle")` to show/hide the modal. But the component itself uses raw JS-string helpers (`closeModalJs`, `showModalJs`) on its own close button and backdrop — because `behavior("toggle")` only toggles `hidden`, while the modal requires a synchronized `hidden` + `flex` two-class state.

This is a guideline consistency bug: the component's own source contradicts the recommended practice, and the recommended practice (`behavior("toggle")`) would visually break the modal if followed.

## Evidence

The doc comment says one thing:

```ts
// planet-positive-sport/src/shared/components/display/modal.ts:55-57
/**
 * Hidden by default — toggle visibility via HTMX or `.behavior("toggle")`.
 */
export function Modal({ id, title, body, footer, maxWidth = "lg", open = false }: ModalProps) {
```

But the implementation does another:

```ts
// planet-positive-sport/src/shared/components/display/modal.ts:41-52
export function closeModalJs(id: string): string {
  return `document.getElementById('${id}').classList.add('hidden'); document.getElementById('${id}').classList.remove('flex')`;
}
export function showModalJs(id: string): string {
  return `document.getElementById('${id}').classList.remove('hidden'); document.getElementById('${id}').classList.add('flex')`;
}
```

And the close button wires itself with the raw string:

```ts
// planet-positive-sport/src/shared/components/display/modal.ts:67
.addAttribute("hx-on:click", closeJs)
```

Meanwhile, `BehaviorMap` has no `showOverlay` / `hideOverlay` entry:

```ts
// fluent-html/src/core/behavior-methods.ts:11-21
export type BehaviorMap = {
  toggle:     { target: Id };  // only toggles 'hidden' — does NOT manage 'flex'
  toggleClass:{ target: Id; class: string };
  ...
};
```

If a caller followed the doc comment and used `.behavior("toggle", { target: id })`, clicking would toggle only `hidden` — leaving `flex` on the overlay permanently, or absent when visible, breaking centering.

## Why it matters

This is a documentation drift bug today (one app) but will scale into a cross-app inconsistency once a first-class `Modal` is built into fluent-html (seed B-3). The fix has two parts: (1) correct the doc comment immediately; (2) once `showOverlay`/`hideOverlay` behaviors ship (F-B-021), refactor `Modal` to use them and propagate the guideline. A first-class `Modal` with a broken doc comment would spread the misunderstanding fleet-wide.

## Rough idea (not a design)

Short-term: remove the `.behavior("toggle")` mention from the doc comment; replace with the actual pattern (`closeModalJs(id)` / `showModalJs(id)`). Long-term: once the new overlay behaviors land (F-B-021), update `Modal` to use `behavior("openModal")` / `behavior("closeModal")` internally, and update the doc + guidelines to reflect the correct idiomatic usage.
