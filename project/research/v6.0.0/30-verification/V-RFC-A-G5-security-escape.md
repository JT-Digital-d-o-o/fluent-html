# Verdict: RFC-A-G5 — security/escape lens

> You are an ADVERSARY. Your job is to KILL this RFC through the security/escape lens.
> Default to `reject` under uncertainty — a good API cut is cheaper than a bad API shipped.

## Attack

I tried to land an XSS via the new surface (`scopeReply` / `Context<T>.provide` / `formFor<T>`) and to make context-scoped, attacker-influenced data escape the renderer's escaping. Everything is grounded in the actual source.

- **security/escape failure mode 1 — the §11.3 "N/A" is a category error.** The RFC self-certifies escape-by-default as "N/A — emits no markup." Strictly true for the three new symbols: `scopeReply` (lines 97-106) returns the string `render()` already produced and owns only LIFO disposal; `provide` (lines 93-95) returns a branded `{ __ctxProvider, scope }` factory; `formFor` only constrains the field `name` to `keyof T & string`, which still routes through `escapeAttr` at render (`render.ts:225`). I confirmed there is no new emission path, no unsanitized interpolation, no attribute-name injection, no script sink in the new code. **But the RFC's entire thesis is to move `request.user` — the single most attacker-influenced object in the request — out of explicit `user: AuthUser` props and into an implicit ambient stack** that argument-less leaf components read via `AuthCtx.current`. The escaping question does not vanish; it loses its call-site visibility. Today `SidebarFooter({ user })` advertises tainted inflow; after this RFC `SidebarFooter()` silently pulls from a global. That is a security-*legibility* regression certified as "N/A."

- **security/escape failure mode 2 — text/attribute context reads ARE escaped (library survives this angle).** I verified the renderer escapes on the way out: `AuthCtx.current.name` as a child (`Div(user.name)`) hits `escapeHtml` (`render.ts`, charCode scan over `& < > " '`); as an attribute (`.setAlt`/`.setName`/`.setValue`) hits `escapeAttr` (`render.ts:213,225` → `escape.ts:37`, identical to `escapeHtml`). A stored-XSS `user.name = '"><script>…'` is neutralized — attribute breakout is prevented even for fully attacker-controlled context values. So "implicit values everywhere" does NOT create a text/attribute-context XSS regression. This kill attempt fails on the merits.

- **security/escape failure mode 3 — the flagship example is an unguarded URL sink (the sharp one).** `fastify.md:337` teaches `Img().setSrc(user.avatarUrl).setAlt(user.name)` where `user = request.user`. `avatarUrl` is user-settable (profile images). I checked every URL setter — `embedded.ts:17,123`, `links.ts:20,96`, `document.ts:96,167,203`, `forms.ts:320` — **none does scheme validation.** `escapeAttr` neutralizes quote/bracket breakout but does nothing to a `javascript:`/`data:` scheme (no `:` in its escape map). `<img>` makes `javascript:` mostly inert, but the guideline canonizes the user-controlled-URL-into-URL-attribute *shape*; a reader copying it onto `A().setHref(user.website)` or `Form().setAction(user.callbackUrl)` ships a live XSS that escaping cannot stop. The RFC lowers friction to this pre-existing sink AND models it as the recommended idiom, with §11.3 marked N/A.

- **security/escape failure mode 4 — nonce is the sharpest edge.** The headline example (lines 80-82) scopes `NonceCtx.provide(this.request.nonce)`. A CSP nonce is a security token whose only safe destination is the `nonce` attribute of `<script>`/`<style>` via the nonce-aware path (`renderWithNonce`/`setNonce`, `render.ts:40-47`, `tag.ts:157`). Making it ambient invites two failures the RFC never closes: leaking it into a generic attribute or `Raw()` (defeats CSP — an injected script reads the nonce), and the reader inferring 'the nonce is handled' when it still must be applied per inline tag. The RFC adds zero guidance on nonce freshness or flow.

- **security/escape failure mode 5 — context-into-Raw.** `Raw()` is the one explicit escape hatch (raw context in `render.ts`). Context makes `Raw(AuthCtx.current.bio)` — attacker-controlled unescaped markup — a one-keystroke reach from any leaf. Pre-existing hatch, newly trivial, untaught.

## Does it survive?

**Survives-with-changes.** The library is safe: I traced every sink the RFC touches and the escape-by-default contract genuinely holds at render time — `scopeReply`/`provide`/`formFor` emit nothing the renderer doesn't already escape, all context reads pass through `escapeAttr`/`escapeHtml`, and the branded `ContextProvider` prevents fabrication. There is no NEW sink and no escaping bypass, so a hard `reject` is unwarranted.

But this is an **adoption/guidelines RFC** whose deliverable is, by its own framing, 90% teaching, and guardrail §11.8 makes a mis-taught security property a defect equal to a code defect. The guideline edits (1) relocate the most-tainted object into an implicit channel while declaring escape "N/A," (2) canonize an unguarded user-controlled URL sink as the flagship example, and (3) elevate a CSP nonce into ambient scope with no flow or freshness constraint. Under §8 default-reject-under-uncertainty I will not pass the teaching as-is. The four `required_changes` are guideline-only, small, and fold into the existing `## Guidelines impact` section without touching the API.

## Guardrail check (§11.3 escape-by-default — this lens owns it)

No XSS *regression* from the new code: `scopeReply`/`provide`/`formFor` emit nothing the renderer does not already escape (`render.ts:202-225`, `stream.ts:122-151`); `provide`/`scopeReply` are pure stack push/pop + `Symbol.dispose`. The §11.3 status must change from **"N/A"** to **"pass-by-delegation, documented."** The escape property is real but currently *undocumented* for the dangerous ambient shape this RFC promotes, and the worked examples include one unguarded URL sink (`setSrc(user.avatarUrl)`) and one unguarded security token (`NonceCtx`) the guideline must caveat before this lens returns a clean pass. The §11.8 mirror of §11.3: an idiom that makes attacker-influenced data ambient must, in the same breath, name the two unsanitized destinations (URL-scheme attributes, `Raw()`) and the nonce flow constraint — otherwise the most-copied example IS the vulnerability.
