# prefer-set-method autofix breaks compile-clean code, and breaks the prune's successor

## Problem
`prefer-set-method` is an autofixing rule (template: `error`) whose attribute -> setter map is hand-kept (prefer-set-method.ts:5-110) and whose fix is a blind text swap (:164-175). Two defects:

1. **Value-blind.** `addAttribute` only takes strings (tag.d.ts:134). 8 of the 86 rows point at number-typed setters (`setMinlength`, `setMaxlength`, `setRows`, `setCols`, `setSize`, `setColspan`, `setRowspan`, `setSpan`), so every site the rule fixes for those attributes becomes `TS2345: Argument of type 'string' is not assignable to parameter of type 'number'`.
2. **Receiver-blind.** Rows fire on any receiver: `Input().addAttribute("size", "20")` -> `.setSize("20")`, but only `SelectTag` has `setSize` -> TS2339. Same for `label` on `Div`, `span` on `Span`, `wrap` on `Input`.

And the prune interaction: 10 rows (`cols, wrap, size, fill-rule, span, formtarget, formenctype, shape, coords, label`) target setters in the 9.0.0 prune set (F-C-101), whose successor is `addAttribute`. After the prune the rule flags the successor at error level and autofixes it into a TS2339 on a method that no longer exists. The map is outside the "extractor and ESLint re-derive, never hand-edit" contract (guardrail 9), so nothing forces it to follow the surface.

Full sweep (`home.ts`, one row per map entry on a factory that owns the setter, value `"1"`): 30 errors after fix; the 8 number-typed rows fail for any string value, the other 22 are closed unions rejecting `"1"` (the setter doing its job; a real value passes).
Fleet exposure: 53 sites across the 58 dedup repos use one of the 8 number-typed attributes through `addAttribute` (all in pre-7 repos, 0 canonical). Those repos inherit the template config when they migrate; `npm run lint:fix` then breaks each site.

## Why it matters
impact 2 (lint --fix produces a red build; the fix message claims "type safety and autocomplete"), pain 2 (the fix text is the thing an agent applies without re-reading; the TS2345 names neither the rule nor the cause), reach 2 (53 migration sites today; every future prune of a mapped setter). Hurts error quality and the verification loop (the lint layer an agent reaches, 4/4 in recon 02, emits compile errors).

## Rough idea (not a design)
Strongest layer: lint (derived). Generate the map from the element classes the same way `derive-fixable` derives from `fluent-html/class-vocab`: owner classes and parameter type per setter. Autofix only when the receiver chain starts at a factory whose class owns the setter and the setter's parameter accepts `string`; otherwise report with a suggestion. The 9.0.0 prune then drops rows by construction. Plugin patch, no lib change.
