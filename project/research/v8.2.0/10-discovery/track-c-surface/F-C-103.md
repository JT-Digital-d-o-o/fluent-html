# Pruning the 92 zero-use names as listed turns 16 of them into TS2551 self-heals; 14 compile and render the wrong thing

## Problem
Deleting a method changes what the checker suggests when an agent guesses the deleted name. The seed claims the zero-use set is "prunable at literally zero blast radius" (projects-template scorecard.md:163). Call-site blast radius is 0, but the error an agent gets after the prune is not neutral: for 16 of the 92 names TypeScript's spelling suggestion points at a *different, still-live* method, and applying it with the original arguments compiles in 14 cases and renders something else. This is the `.colspan` -> `colSpan` hazard (recon 02 probe #11b, seed A4) manufactured 14 more times by deletion.

| Pruned guess | TS2551 "Did you mean" | Suggestion with the original args | Rendered (8.1.0 dist) |
|---|---|---|---|
| `Div().hueRotate("90")` | `rotate` | compiles | `<div class="rotate-90">` (transform, not filter) |
| `Div().insetE("0")`, `insetS("0")` | `inset` | compiles | `<div class="inset-0">` (all four sides) |
| `Input().setDirname("q.dir")` | `setName` | compiles | `<input name="q.dir">` (overwrites the field name) |
| `Text("t").setDx("2")`, `setDy("3")` | `setX`, `setY` | compiles | `<text x="2">` (absolute, not offset) |
| `Text("t").setFontStyle("italic")` | `setStyle` | compiles | `<text style="italic">` (invalid CSS) |
| `RadialGradient().setFx("0.5")`, `setFy` | `setCx`, `setCy` | compiles | `<radialGradient cx="0.5">` (centre, not focal point) |
| `FeGaussianBlur().setIn("SourceGraphic")` | `setId` | compiles | `<feGaussianBlur id="SourceGraphic">` |
| `Track().setKind("captions")` | `setId` | compiles | `<track id="captions">` |
| `Td("x").setRowspan(2)` | `rowSpan` | compiles | `<td class="row-span-2">` (grid class, no `rowspan` attribute) |
| `Track().setSrclang("en")` | `setLang` | compiles | `<track lang="en">` |
| `Div().spaceX("4")` | `spaceY` | compiles | `<div class="space-y-4">` (wrong axis) |
| `Div().setHidden("until-found")` | `hidden` | TS2554 Expected 0 arguments | a second hop to `.hidden()` gives `display:none`, not until-found |
| `Div().setTranslate("no")` | `translate` | TS2554 Expected 2 arguments | n/a |

## Evidence (executed)
- Simulation: for each of the 92 names, `declare const v_<n>: Omit<<OwningClass>, P>; v_<n>.<n>;` where `P` is the union of all 92 names (the post-prune candidate set TypeScript searches). `tsc -p tsconfig.pp.json --pretty false` -> 76 TS2339, 16 TS2551 (`postprune.out`). Verbatim sample: `Property 'setRowspan' does not exist on type 'Omit<TdTag, P>'. Did you mean 'rowSpan'?`
- Applying each suggestion with the pruned call's arguments (`healed.ts`): tsc reports only `healed.ts(14,36) TS2554` (hidden) and `healed.ts(19,29) TS2554` (translate); the other 14 lines compile. `healed-run.mjs` renders the outputs in the table above.
- Reduced set (`postprune2.ts`, the 60 names of F-C-101 after excluding these 15 plus 17 others): 60 TS2339, 0 TS2551. Removing the 15 is sufficient; nothing else in the set self-heals.
- The same probe style finds no wrong-fix today for these names because the live name is an exact match; the hazard exists only after deletion, so no current test (test/setter-errors.test.ts pins `.src`/`.placeholder` guesses only) can see it.

## Why it matters
impact 3 (silent wrong output on tsc, eslint, extractor and runtime, same class as the open `.colspan` finding), pain 3 (the self-heal is one hop and the model accepts "Did you mean" by default; recon 02 #11 counted it as "yes, into a bug"), reach 2 (15 names, all element/attribute guesses an agent makes by analogy with live siblings: `setColspan` -> `setRowspan`, `spaceY` -> `spaceX`, `inset` -> `insetE`). Hurts silent-failure resistance and error quality. It also refutes the seed's "zero blast radius": the radius moved from call sites to diagnostics.

## Rough idea (not a design)
Strongest layer: type/CI. Add a deletion gate in the style of `test/setter-errors.test.ts`: for every name a release removes, compile an `Omit<OwningClass, Removed>` probe and fail if the first diagnostic is a TS2551 whose suggestion is not the documented successor. Run it on the 9.0.0 prune list; it removes these 15 names from the list (or forces a tombstone that names the successor, B2's lane). No prose needed; the gate replaces the "verified again at release time by grep" step (CHANGELOG.md:112).
