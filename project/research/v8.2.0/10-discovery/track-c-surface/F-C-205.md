# The addAttribute -> typed-setter redirect covers 57% of the typed attributes

## Problem
The prior uses `addAttribute` as its fallback when it cannot confirm a setter exists: 23 and 30 sites per run, and pp2 writes `addAttribute("for", id)` where pp1 wrote `setFor(id)`. The redirect is `prefer-set-method`, whose `ATTRIBUTE_TO_METHOD` is a hand-kept 82-entry table (`prefer-set-method.ts:5`) plus special cases for `aria-*`, `data-*`, `style`, `tabindex` (`:49-52`), and `prefer-toggle`'s boolean list. The lib's setters have grown past the table.

## Evidence (executed)
- Runtime walk of every `set*` method on all 8.1.0 element factories (call with a sample arg, render, diff the opening tag): 150 distinct attributes, excluding `aria-*`, `data-*`, `hx-*`, `class`, `id`. Handled by the two rules: 85. Unhandled: 65, including `lang`, `dir`, `popover`, `popovertarget`, `popovertargetaction`, `command`, `commandfor`, `closedby`, `contenteditable`, `spellcheck`, `enterkeyhint`, `autocapitalize`, `translate`, `nonce`, `integrity`, `decoding`, `fetchpriority`, `media`, `as`, `imagesizes`, `imagesrcset`, `srcdoc`, `srclang`, `kind`, `headers`, `abbr`, `cite`, `datetime`, `form`, `high`/`low`/`optimum`, `x`/`y`/`x1`/`x2`/`y1`/`y2` (`setX` is canonical-era rank 50, recon 01), and the SVG filter/gradient/mask attributes.
- Probe in the template (eslint, plugin 4.1.0): `addAttribute("popover","auto")`, `("lang","en")`, `("commandfor","dlg")`, `("closedby","any")` -> 0 reports; `("tabindex","0")` -> prefer-set-method; `("hidden","")` -> prefer-toggle.
- In the prior: `.addAttribute("lang", "en")` on the html element, 1 per run, unreported in both baseline lint runs.
- `guidelines/web-development/fluent-html.md:60`: "`addAttribute` is enforced by the `prefer-set-method` ESLint rule - `eslint --fix` rewrites the ✗ forms." The ✗ form shown at `guidelines/web-development/CLAUDE.md:339`, `htmx.md:603` and `fluent-html/CLAUDE.md:317` (`Div(...).addAttribute("popover", "auto")`) is one it does not rewrite.

## Why it matters
43% of the typed attribute surface has no redirect from the prior's fallback, and the gap widens with each setter release: the Commands/Popover setters the guidelines teach as the native path are all in it. Reach 2, impact 2, pain 2 (decision-closure: two ways stay open; evolvability: the table drifts by hand).

## Rough idea (not a design)
Derive, do not hand-keep (guardrail 9's rule applied to attributes): the lib exports an attribute -> setter table generated from the element classes (or the plugin runs this runtime walk at build), `prefer-set-method` re-derives at load, and a plugin test fails when a lib setter's attribute is unhandled. After that the three ✗ popover lines and the `fluent-html.md:60` claim are lint-backed and shrink to the enforcement comment.
