# README, the only doc the installed package ships, carries 4 claims that fail when executed and links 5 files the package omits

$C4 = <scratch>/wave1/C4

## Problem

`node_modules/fluent-html/` contains `LICENSE README.md dist package.json src` and nothing else (package.json:82-89 `files` lists only dist and src). In a consumer repo the README is the only prose about the library, and blind agents read it twice per run (02-agent-fitness-delta.md:162-164). Executed against 8.1.0, it is wrong in four places:

| README line | Claim | Executed result |
|---|---|---|
| :156-158 | `defineIds(["userList", "userCount"])`, `Div().setId(ids.userList) // id="user-list"`, `// hx-target="#user-list"` | `<div id="userList"></div>`, `<button hx-get="/users" hx-target="#userList">`, Partial `hx-target="#userList"`. Control: `defineIds(["user-list"])` renders `id="user-list"`. The comment is a false oracle (see F-C-407). |
| :167-170 | `Form<CreateUserReq>(f => f.input("email")…, f => f.input("password")…)` | With a concrete `CreateUserReq = { email: string; password: string }`: `TS2560: Value of type '(f: any) => any' has no properties in common with type 'FormState<CreateUserReq>'. Did you mean to call it?` plus TS7006 on both `f`. The overloads (forms.d.ts:209-213) are `(build)` or `(state, build)`; two builders never compile. |
| :71, :211 | `const card: Styler = (t) => …` | `TS2724: '"fluent-html"' has no exported member named 'Styler'. Did you mean 'Style'?` The suggestion points at a different type. `Styler` lives in the template (`src/shared/stylers.ts`), not the package (TS API export walk: 335 root exports, no `Styler`). |
| :266-267 | "a blind `.src()` guess now self-heals as \"Did you mean 'setSrc'?\"" | `TS2339: Property 'src' does not exist on type 'ImgTag'.` with no suggestion. The library's own test pins the opposite of the README: test/setter-errors.test.ts:64-67 asserts plain TS2339, and :77-80 explains `setSrc` is outside tsc's suggestion window. Only `.placeholder` heals. |

In the template scaffold, README.md:225 `hover: { bg: "primary-800" }` also fails (TS2820, no such token; "Did you mean primary-700").

The "Where everything else lives" table (README.md:33-36) and :271/:275 link `REFERENCE.md`, `generated/full-surface.md`, `FLUENT-STYLING.md`, `TAILWIND-SETUP.md`, `CHANGELOG.md`. None of the 5 exists in an installed copy (checked: wave0-2 scaffold, everyframe, na-cent). "See CHANGELOG.md for migration notes" (:271) points at nothing for every consumer.

## Evidence (executed)

- Block harness `node $C4/blocks.mjs $C4/probe blk readme README.md` (lib mode, README tokens shimmed): 11 ts blocks, 0 pseudo-code. Non-context failures on :168, :209-211; :197-198 and :209 were `any` artifacts and pass with concrete types (`$C4/probe/cl-readme-concrete.ts`).
- `$C4/probe/readme-p2.mjs` runs README.md:135-159 verbatim. :141-143 are correct (`/users?page=2`, `/users/7`, `"/users"`). :157-159 are wrong as shown above.
- `$C4/probe/cl-readme-claims.ts`: `.src` TS2339; `.placeholder` TS2551 "Did you mean 'setPlaceholder'?"; `.href` TS2339.
- `ls node_modules/fluent-html` in 3 installs -> 5 files; `grep -c` of the README links -> 6 link sites to 5 missing files.

## Why it matters

impact 2 x pain 2 x reach 3 / S. The shipped README is the blind agent's API map. Three of its examples fail on first compile or render, and one sends the agent to a wrong type (`Style`). The ids comment teaches a DOM contract the runtime does not keep, and nothing catches it: silent until a selector or a `RootedView<"user-list">` annotation disagrees. Dims: context-economy, verification-loop, silent-failure.

## Rough idea (not a design)

Layer: ci. Add a `test/readme.test.ts` that extracts every ```typescript block, compiles it against dist with a declared-context shim, renders the view, and checks each `// id=…` / `// →` comment byte-for-byte. The README can then only teach what runs. Fix the 4 claims now. Make the links absolute GitHub URLs, or add the files to `files`. Prose deleted: none needed; the gate replaces review.
