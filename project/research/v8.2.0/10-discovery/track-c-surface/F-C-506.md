# prefer-set-method's autofix rewrites to setters the receiver does not have

## Problem
`prefer-set-method` converts `.addAttribute("x", v)` into `.setX(v)` from a hand-kept, receiver-free map
(prefer-set-method.ts:5-111) and pastes the value verbatim (:161-175). Setters are per-class (385 setter slots
over 63 subclasses, recon 01) and several are number-typed, so the fix emits calls that do not exist on the
receiver or do not type-check. The template enables the rule at `error` (eslint.config.mjs:62), so `eslint --fix`
during an upgrade applies them. The map is also a second, drifting copy of the setter surface: 63 of 149 typed
single-attribute setters are missing (e.g. `fetchpriority`, `popovertarget`, `commandfor`, `closedby`, `datetime`,
`lang`, `integrity`, `decoding`), so `addAttribute` on those passes unflagged.

## Evidence (executed)
1. `lintfix/probe.ts` (16 lines, tsc-clean) -> eslint 4.1.0 reports 13 -> `--fix` -> tsc on `fixed.ts`:
   ```
   fixed.ts(3,10): error TS2339: Property 'setName' does not exist on type 'FormTag'.
   fixed.ts(4,11): error TS2339: Property 'setValue' does not exist on type 'Tag'.      (Li)
   fixed.ts(5,8):  error TS2339: Property 'setType' does not exist on type 'Tag'.       (Ol)
   fixed.ts(6,22): error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'. (setColspan)
   fixed.ts(7,24): error TS2345: ... 'number'.  (setMaxlength)
   fixed.ts(8,11): error TS2339: Property 'setSize' does not exist on type 'InputTag'.
   fixed.ts(9,22): error TS2345: ... 'number'.  (setRows)
   fixed.ts(11,9): error TS2339: Property 'setWidth' does not exist on type 'Tag'.     (Div)
   ```
   8/13 fixes break compilation. `Img().addAttribute("fetchpriority")`, `Button().addAttribute("popovertarget")`,
   `Input().addAttribute("enterkeyhint")` get no report.
2. Fleet (`autofix-exposure.cjs`, dedup corpus): 2,257 `addAttribute` sites hit the autofix branch, all in pre-7
   repos (canonical era: 0). For the 2,245 whose chain roots at a known factory: 1,837 fix cleanly, 362 target a
   setter the root class lacks, 46 feed a string literal into a number-typed setter: 408 (18.2%) in 10 repos. Top
   pairs: `El().addAttribute("fill")` 66, `El` height/width 60 each, `El` rx 57, `Textarea` rows 17, `Svg`
   stroke-linejoin/linecap 16 each, `Input` maxlength 15, `Table` width 12.
3. Coverage: map 86 entries vs 149 typed single-attribute setters from the runtime audit; 62 typed attributes
   unmapped plus `tabindex` report-only.
4. Pure prior (recon 02 pp1/pp2 copied to `lintfix/pp`): 37 reports, 27 autofixes, 0 new tsc errors: the model's
   own `addAttribute` targets (`name` on Meta, `src` on Script, `action`/`method` on Form, `for` on Label) happen to
   sit on receivers that have the setter. The breakage is concentrated in upgrade sweeps of older code.

## Why it matters
impact 2 x pain 2 x reach 2 / M = 4. evolvability: the 46 pre-7 consumer repos are upgraded on demand (S-26);
the template's `--fix` turns 408 compiling lines in 10 of them into tsc errors, a third autofix regression after
the two S-25 records. error-quality: the rule's message promises "type safety and autocomplete" for a method that
does not exist on the element. The hand-kept map drifts from the surface (63 typed attributes missing).

## Rough idea (not a design)
Lint layer, derived not hand-edited (the guardrail-9 pattern the class vocab already follows): at plugin load read
the lib's factory -> setter -> parameter-type table from `dist/`, resolve the chain's root factory, autofix only
when that class has the setter and the literal fits (number literal for number setters), report-only otherwise.
This also closes the 63 unmapped attributes and makes F-C-501's rename a regeneration instead of 11 hand edits.
