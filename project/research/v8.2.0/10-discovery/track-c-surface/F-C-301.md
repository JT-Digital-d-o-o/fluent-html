# One htmx request has six spellings; canonical code has already converged on two

## Problem

fluent-html 8.1.0 offers six ways to attach the same request to an element:

1. `.hxGet(endpoint, opts)` (`src/core/htmx-methods.ts:20`)
2. `.hxPost(endpoint, opts)` (`:21`)
3. `.setHtmx(route(opts))`, the route-callable path
4. `.setHtmx(hx(endpoint, opts))`, the ad-hoc path (`src/htmx.ts:419`)
5. `.setHtmx(endpoint, opts)`, a second `setHtmx` overload (`htmx-methods.ts:19`)
6. `.addAttribute("hx-get", …)`, the untyped hatch

The template adds 8 swap verbs on top (`.nav .tab .submit .fragment .poll .search .onChange .fire`).

The four library GET spellings are byte-identical. The guidelines teach them as "One job, four APIs" (`htmx.md:210`), with `hxGet`/`hxPost` as rung 4 (`:215`) and as the ✓ example at `:224`, `:250`, `:318` and `:511`.

The eslint rule that guards the untyped hatch names two of the dead spellings as its fix: `prefer-htmx-api.ts:42` says "Use the HTMX API (hxGet, hxPost, setHtmx)".

**Teaching of the zero-use spellings:**
- **guidelines:** `htmx.md:210` ("One job, four APIs"), `:215` (rung 4), and the ✓ examples at `:224`, `:250`, `:318`, `:511`.
- **REFERENCE.md:** 8 lines (`:115`, `:116`, `:290`, `:291`, `:405`, `:410`, `:416`, `:426`).
  - `tsc --strict` over REFERENCE.md's 10 htmx example lines gives 11 × TS2345 on 8.1.0, e.g. `Argument of type '"/api/items"' is not assignable to parameter of type 'ResolvedRoute | ExternalHref'`: 10 of 10 lines fail.
- **README.md:147** lists `hxGet`/`hxPost` among the branded sinks.
- **The one error text that names the ad-hoc path** is the template's `swap-verbs.ts:82`: "an ad-hoc `hx()` url has no def, so it goes through `.setHtmx()`". It names `setHtmx(hx())`, not the endpoint overload.

## Why it matters

- **Scoring:** impact 2 × pain 2 × reach 3 / effort M(2) = 6.
- **Context economy:** 4 lib-level spellings for one job, each taught.
- **Decision closure:** an agent reading `htmx.md` gets a 4-rung ladder where rungs 3 and 4 have 0 canonical app sites. The lint repair message steers toward rung 4.
- **Converge guardrail (§5.7):** "one way per job".
- **The two survivors are measured, not chosen:**
  - the template verbs (98.8%) over `setHtmx(route())` (1.1%);
  - `setHtmx(hx(url))` for the ad-hoc case, the only path the template's error text names.

## Rough idea (not a design)

Enforcement layer: **type** (the method stops existing, so a guess dies at TS2339). The same successor map can feed B2's named-successor redirect.

In the 9.0.0 major:
- delete `hxGet`, `hxPost` and the `setHtmx(endpoint, options)` overload;
- codemod `.hxGet(e, o)` → `.setHtmx(hx(e, o))` (hx defaults `method: "get"`, `htmx.ts:426`) and `.hxPost(e, o)` → `.setHtmx(hx(e, { ...o, method: "post" }))`.

Lockstep:
- `prefer-htmx-api`'s message names route callables and the swap verbs.
- **Prose deleted:**
  - `htmx.md` rung 4 (`:215`) and its examples (`:224-225`, `:250-253`, `:318`, `:511`);
  - REFERENCE.md's htmx section (10 non-compiling lines);
  - `README.md:147`'s mention.
