# defineIds accepts camelCase names and emits them verbatim while the README claims kebab output; docs and fleet split both ways

$C4 = <scratch>/wave1/C4

## Problem

`defineIds` is designed for kebab input. `KebabToCamel` maps `"user-list"` to the key `userList` (ids.d.ts:70-74), and the DOM id stays `user-list`. A camelCase name is accepted too, and emitted verbatim. That gives two ways to name ids with different DOM output, and the docs teach both:

- camelCase input: README.md:156, fluent-html/CLAUDE.md:281, gl/CLAUDE.md:279, gl/fastify.md:245.
- kebab input: src/ids.ts:17 and :137 (JSDoc), REFERENCE.md:813, :854, :1649, gl/htmx.md:7 and :86, gl/typescript.md:118.

README.md:157-158 teaches camel input and then claims kebab output: `// id="user-list"`, `// hx-target="#user-list"`.

## Evidence (executed)

- README.md:156-159 run verbatim (`$C4/probe/readme-p2.mjs`):
  - `<div id="userList"></div>`
  - `<button hx-get="/users" hx-target="#userList">↻</button>`
  - `<template type="partial" hx-target="#userList" …>`
  - Control: `defineIds(["user-list"])` gives key `userList` and renders `<div id="user-list"></div>`.
- Type level: with `defineIds(["userCount"])`, the RootedView JSDoc example (9d86871, `function UserCount(): RootedView<"user-count"> { return Span(…).setId(ids.userCount) }`) fails: `TS2322: Type 'Tag & Rooted<"userCount">' is not assignable to type 'RootedView<"user-count">'`. Following README pattern 2 and then the RootedView docs gives a compile error with no pointer to the id spelling.
- Fleet (`$C4/defineids.mjs`, 15 repos pinned 8.1.0):
  - App-authored: 125 `defineIds([…])` calls, 196 kebab entries, 109 camelCase, 52 single-word. 1 call mixes both.
  - camelCase appears in competify, everyframe, gzs/stem-50, na-cent, projects-template and website-sales-funnel-automation-system.
  - Vendored template core: 237 kebab, 3 camel. The layout's own id is `main-content` (template layout.routes.ts:3).

## Why it matters

impact 2 x pain 2 x reach 2 / M.

- A camel-defined id and a kebab id from the template or docs never match. Examples: a hand-written `#user-list` selector in CSS or a Playwright test, a `RootedView<"user-count">` annotation copied from the JSDoc, or a `hx-target` literal.
- Nothing reports it: the id and its selector agree with each other, so tsc, lint and runtime stay clean until two halves use different spellings.
- The README comment is a false oracle, and "one way per job" (§5.7) is violated inside a primitive that exists to remove string drift.

## Rough idea (not a design)

Layer: type. Make `defineIds` reject names containing an uppercase letter via a conditional on each element (`K extends Lowercase<K> ? K : "defineIds names are kebab-case: write 'user-list', read ids.userList"`), so the first error names the fix. Ship a lint rule (`define-ids-kebab`, autofix to kebab) in 8.2.0. Put the type constraint in 9.0.0 with a codemod over the 109 camel entries plus any string selectors that reference them (measured dry run required). Fix README.md:156-158, fluent-html/CLAUDE.md:281, gl/CLAUDE.md:279 and gl/fastify.md:245 now.
