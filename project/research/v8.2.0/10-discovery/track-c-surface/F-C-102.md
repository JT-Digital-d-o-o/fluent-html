# The method census counts only `.name(` calls; variant-object keys are invisible

## Problem
The census that certifies prune candidates (and ranks the README head) matches `\.name\(` and nothing else (method-census.mjs:224). Since 7.0.0 every vocab row is also an object key (`.md({ colStart: 1, rowStart: 2 })`, variant-keys.ts:12), and canonical-era code uses that form heavily. Those uses are uncounted, so a name the census reports as dead can be live:

| Name | Census (fleet / canonical) | Object-key sites | Where |
|---|---|---|---|
| `rowStart` | 0 / 0 (in the zero-use 92) | 9 | popri/src/app/canvas/views/canvas.components.ts:55-63 |
| `static` | 0 / 0 (in the 92) | 2 | everyframe-composer studio.components.ts:708, studio.subtitles.view.ts:517 |
| `brightness` | 0 / 0 (in the 92) | 2 | studio/src/app/auth/shared/auth.components.ts:100, studio/src/shared/ui/aperture.ts:102 |
| `invisible` | 0 / 0 (in the 92) | 1 | home-page/src/app/launcher/views/launcher.composer.view.ts:159 |
| `colStart` | 1 / 0 (listed legacy-only) | 11 | popri canvas.components.ts:55-63 |
| `rowSpan` | 1 / 0 (listed legacy-only) | 4 | popri canvas.components.ts:55-63 |
| `colSpan` | canonical 5 (near-dead) | 78 | canonical rank #201 -> #99 |

A prune driven by the census alone deletes 4 live keys: the 14 literals then fail with TS2353 in 4 canonical-era repos (popri, everyframe-composer, studio, home-page). The 8.0.0 prune's "no codemod needed" check was a grep over 3 trees (CHANGELOG.md:112), not a key census. A second, smaller defect: string contents count as calls (the 3 canonical `hxGet` sites are template-literal code samples).

## Evidence (executed)
- `node wave0-1/census-dedup.mjs --json` (the committed script with `.claude` skipped): 58 repos, 12,811 files, 246,098 method sites, 92 names at 0 fleet.
- `node objkey-census.mjs` (8.8 s): parses every `.ts` file with the TS compiler, collects keys of object literals passed to any tier-1 variant method or `.variant()`, plus literals typed `VariantStyleObject`/`StyleProps`, recursing into nested tier-1 keys. 3,777 key sites (3,762 canonical-era) over 86 method names. Zero-name keys with uses: `rowStart 9, static 2, brightness 2, invisible 1`; the other 38 zero-name keys (incl. the 5 tier-1 names as nested keys) have 0.
- Rank impact on the canonical-era head (method vs method+key): `px` #60 -> #34 and `py` #53 -> #46 enter the top 50, `setX`/`setY` leave; largest jumps `colSpan` #201 -> #99, `outline` #195 -> #96, `inline` #223 -> #149.
- `keys.ts` against `Omit<VariantStyleObject, "rowStart"|"static"|"brightness"|"invisible">`: `keys.ts(4,31): error TS2353: Object literal may only specify known properties, and 'rowStart' does not exist in type 'Pruned'.` (x4).

## Why it matters
impact 2 (the prune gate would have deleted 4 live names and broken 14 sites; the near-dead and legacy-only lists misfile `colStart`/`rowSpan`/`colSpan`), pain 2 (a TS2353 in a consumer repo after a "zero blast radius" major), reach 3 (86 names carry key uses; every prune/promote decision and the README head run on this script). Hurts the verification loop that the whole C track depends on.

## Rough idea (not a design)
Strongest layer: ci. Add the AST key pass to `scripts/census/method-census.mjs` as a second column (`--keys`), fold nested tier-1 keys onto their variant name, and drop string-literal/template contents from the method pass. Any prune RFC's verification reads method + key + raw-class counts. Tooling only: `scripts/` is not in package.json `files`, so no public-shape change (8.1.x).
