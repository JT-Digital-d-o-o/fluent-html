# Setter casing has one real outlier set (setCrossOrigin, setReferrerPolicy, setFetchPriority) and tsc self-heals 22 of 22 case-only guesses, so the F-D-160 rename is 3 names, not a sweep

$C4 = <scratch>/wave1/C4

## Problem

F-D-160 (v6.0.1, parked-major L-144) reported that setters "mix intercaps and lowercase tails" with "no rule a user can predict". It proposed renaming `setHttpEquiv`, `setCrossOrigin` and `setViewBox` to lowercase tails, claiming "the HTML attributes themselves are all lowercase" (F-D-160.md:30-31). Executed against 8.1.0, the surface does follow one rule: tail = the content attribute, camelized at hyphens. There are exactly 3 exceptions. Two of those 3 (`setReferrerPolicy`, `setFetchPriority`) were added after F-D-160.

## Evidence (executed)

Runtime map (`$C4/probe/setters.mjs`: call each setter on its factory and diff the emitted attributes), 158 setters:

| Class | Count | Examples |
|---|---|---|
| Tail = single-word attribute, lowercase | 118 | `setTabindex`->tabindex, `setMaxlength`, `setInputmode`, `setPopovertarget`, `setFormaction`, `setCommandfor`, `setClosedby` |
| Intercapped, attribute hyphenated (camelize rule) | 19 | `setHttpEquiv`->http-equiv, `setStrokeWidth`->stroke-width, `setFillRule`, `setFontSize` |
| Intercapped, attribute is camelCase SVG (verbatim) | 11 | `setViewBox`->viewBox, `setStdDeviation`, `setGradientUnits` |
| **Intercapped, attribute single-word lowercase (outliers)** | **3** | `setCrossOrigin`->crossorigin, `setReferrerPolicy`->referrerpolicy, `setFetchPriority`->fetchpriority |
| Other / unresolved | 7 | `setAria`, `setDataAttrs`, `setHtmx`, `setStyles`, `setAllow`, `setClasses`, `setMicrodata` |

F-D-160's `setViewBox -> setViewbox` would break the verbatim-attribute rule for 11 SVG setters, and `setHttpEquiv -> setHttpequiv` would break the camelize rule shared by 19.

Prior-spelling probe (`$C4/probe/cl-casing.ts`): the model's React/DOM-IDL spelling for 18 lowercase-tail setters, plus the lowercase-tail spelling for the 4 intercapped ones. All 22 get TS2551 with the right name, for example:

- `Property 'setTabIndex' does not exist on type 'Tag'. Did you mean 'setTabindex'?`
- `…'setColSpan'… Did you mean 'setColspan'?`
- `…'setCrossorigin'… Did you mean 'setCrossOrigin'?`
- `…'setHttpequiv'… Did you mean 'setHttpEquiv'?`

0 of these heals are pinned. test/setter-errors.test.ts:77-98 pins only the unprefixed `placeholder` and `autocomplete` heals.

Codemod size (dedup fleet / app-authored canonical):

- 23 lowercase-tail names whose DOM IDL is camelCase: 393 / 208 sites (10 of the 23 at 0).
- The 3 outliers plus `setHttpEquiv`: 60 / 7. `setCrossOrigin` 42/3, `setFetchPriority` 15/3, `setReferrerPolicy` 2/1, `setHttpEquiv` 1/0.

## Why it matters

impact 1 x pain 1 x reach 2 / S. The pain F-D-160 cited ("every compound setter is an autocomplete guess") costs one compile round, because tsc names the fix 22 of 22 times. What is left is a real two-way for 3 HTML attributes, which is §5.7's concern at 60 sites. A full sweep toward either convention would touch 393 sites for no error-quality gain. Dims: prior-alignment, decision-closure.

## Rough idea (not a design)

Layer: type (the rename) plus ci (pins). In the 9.0.0 codemod bundle, rename the 3 outliers to `setCrossorigin`, `setReferrerpolicy` and `setFetchpriority` (60 sites, receiver-checked; `setHttpEquiv` stays). Add the 22 case-only probes to test/setter-errors.test.ts, so a future rename or TS upgrade that breaks the heal fails CI. Close the rest of L-144.
