# Static inline CSS bypasses the typed surface; the guarding lint is hand-kept and half-blind

## Problem

**Doctrine** (`tailwind-methods.ts:456-457`, `CLAUDE.md:189-191`). An inline style has one way per case:
- a typed method when one exists;
- `.cssProp()` for static CSS with no utility;
- `.setStyle()` for runtime-computed values.

**Spellings that exist for the same attribute:**
- `.setStyle(string)` (replace)
- `.setStyles(object)` (replace)
- `.addStyle(decl)` (append)
- `.cssProp(prop, value)`
- `addAttribute("style", …)`

**The only guard on the static case** is `no-fluent-equivalent-in-setstyle`, set to error in the template.
- Its tables are hand-written at `:16` (UNIT_PROPS), `:46` (VALUE_PROPS), `:61` (COLOR_PROPS) and `:69` (KEYWORD_PROPS, which covers `display` and `position` only).
- They are not derived from the vocab, which guardrail §5.9 expects of ESLint.
- It misses keyword utilities the library has, e.g. `.tabularNums()` (`vocab.ts:146`) and `.wrap("anywhere")` (`vocab.ts:382`).

**The guidelines teach static `setStyle` as ✓:**
- `fluent-html.md:69`: `setStyle("background:linear-gradient(…)")`, which by the doctrine is `cssProp`.
- `fluent-html.md:85`: `setStyle("aspect-ratio:16/9")`, which is exactly `.aspect("video")`: it renders `class="aspect-video"`, and Tailwind's theme.css:490 defines `--aspect-video: 16 / 9`.

## Evidence (executed)

**Lint coverage probe.** 20 `Div().setStyle("prop:value")` lines, rule alone:
- **Flagged (10):** text-align, cursor, white-space, overflow, font-weight, opacity, z-index, display, position, width.
- **Missed (9 with a fluent method):**
  - font-variant-numeric → `.tabularNums()`
  - overflow-wrap → `.wrap()`
  - text-transform → `.uppercase()`
  - font-style → `.italic()`
  - pointer-events → `.pointerEvents()`
  - object-fit → `.object()`
  - visibility → `.invisible()`
  - user-select → `.select()`
  - text-decoration → `.underline()`
- **Correctly silent:** border-collapse (no fluent method).
- `aspect-ratio:16/9`: 0 findings.

**Census** (`$C3/twoway-census.mjs`, canonical app-authored, email files split out):

| Spelling / shape | Sites | Repos | Note |
|---|---|---|---|
| `.cssProp()` | 106 | 15 | the static survivor |
| `.setStyle("literal")` (static) | 18 | 4 | 11 are `font-variant-numeric:tabular-nums` (everyframe `golf-*.view.ts`, `rep-counting`, `stroke-reader`, `tour-de-france`); 3 `scroll-margin-top`; `aspect-ratio: 9 / 16`; `field-sizing: content`; `-webkit-font-smoothing: none` |
| `.setStyles({all literal})` non-email | 5 | 2 | 4 `animationTimeline`/`animationRange`; 1 `overflowWrap: "anywhere"` (`studio.review.details.view.ts:51`) |
| `.setStyle(\`…${x}…\`)` runtime | 77 | 16 | the documented runtime survivor |
| `.setStyles({…runtime})` non-email | 38 | 3 | |
| `.setStyles` in email files | 108 | 13 | email inline CSS, a separate job (71.5% of all canonical setStyles) |
| `.addStyle()` | 1 | 1 | |
| `addAttribute("style")` | 0 | 0 | 109 pre-7 |

**What the numbers say:**
- **Static inline CSS where the doctrine says typed or cssProp:** 23 sites. 12 of them have a typed method the rule misses; 11 should be `cssProp`.
- **Runtime:** `setStyle` holds 77 of 115 non-email sites (67%). `setStyles`'s majority job is email.
- **Replace semantics, probed:** `Div().setStyle("top: 1px").setStyles({ color: "red" })` → `style="color: red"`, so the first call is silently lost. `setStyles({…}).addStyle("top: 1px")` → both.

## Why it matters

- **Scoring:** impact 2 × pain 2 × reach 2 / effort M(2) = 4.
- **Decision closure:** the static case has three live answers (typed method, cssProp, setStyle), and the lint that should close it is blind to half the typed methods.
- **Verification loop:** a single-pass agent runs lint (recon 02 §1.2: 4/4 agents), and this rule is the only signal. It passes 12 sites that have a typed method.
- **Teaching:** the guidelines hand the agent a ✓ example with a typed equivalent.

## Rough idea (not a design)

**Lint** (8.2.0 eslint minor, lockstep): derive the rule's property/value → method table in `gen:vocab`.
- `load-design-system.ts` already compiles every vocab class through `candidatesToCss`. The declarations it emits are the table.
- This retires the 4 hand tables (§5.9: ESLint re-derives, never hand-edited).

**Second arm:** flag any all-literal `setStyle`/`setStyles` outside the email override as `.cssProp(…)`, with autofix for a single declaration.

**Prose deleted/corrected:**
- `fluent-html.md:69` (→ `cssProp`)
- `fluent-html.md:85` (→ `.aspect("video")`)
- `fluent-html.md:39-40`: two replace-style methods shown side by side.

**Not proposed:** removing `setStyles`, which email views need.
