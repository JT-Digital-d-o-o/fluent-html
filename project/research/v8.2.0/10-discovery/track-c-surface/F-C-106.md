# Tier-1 variant methods at zero on every channel

## Problem
Five of the 21 tier-1 variant methods (`after`, `checked`, `dark`, `even`, `odd`) have no use as a method, as a nested key (`.md({ dark: {…} })`), or through `.variant()`, in any of the 58 repos. Each is a `Tag` method, a nested `VariantStyleObject` key, a row in the tier-1 list every guided agent loads (CLAUDE.md:233), and a target of the 7.0.0 codemod (canonical-names.ts:23). The generic `.variant()` already covers them: `TailwindState` lists all five, and the fleet already spells other tier-1 prefixes through `.variant()` (canonical: `.variant("group-hover")` 10 sites next to `.groupHover()` 55; `focus-within` 2 next to 11; `focus-visible` 1 next to 22; `peer-checked` 1 next to 11), so the method form is a second way that nobody takes for these five.

## Evidence (executed)
- Method channel: 0 fleet / 0 canonical-era for all 5 (the census folds pre-7 `.on("dark", …)` onto `dark`, so pre-7 use is included).
- Key channel (AST over 2,926 variant object literals): 0 nested uses of the 5 names; `.variant()` first arguments (130 distinct) include none of them.
- Successor, top level: `.dark({ bg: "blue-500", text: "white" })` and `.variant("dark", { … })` both render `<div class="dark:bg-blue-500 dark:text-white"></div>`: 5/5 identical.
- Successor, nested: `.md({ dark: { bg } })` -> `md:dark:bg-blue-500`. `.variant("md:dark", …)` is TS2345 (`Argument of type '"md:dark"' is not assignable to parameter of type 'TailwindState | TailwindBreakpoint'`). `.variant("dark", { md: { bg } })` compiles and emits `dark:md:bg-blue-500`; the oracle gives the same declarations for `checked`/`even`/`odd`, the two `@media` blocks swap nesting order for `dark` (equivalent), and for `after` the `content: var(--tw-content)` declaration moves outside the breakpoint (not equivalent). 0 fleet sites use the nested form.
- Lint: in the simulated post-prune plugin (class-vocab shim without the 5), `dark:bg-night`, `after:`, `checked:`, `even:`, `odd:` in `addClass` autofix to `.variant("<name>", { bg: … })`; `md:dark:bg-night` becomes report-only. No hand edit in the plugin needed.
- Pure prior (recon 02 pp1/pp2): the 36 variant-prefix tokens it wrote are focus 12, focus-visible 7, lg 6, hover 4, active 2, placeholder 2, sm 2, disabled 1; none of the 5.

## Why it matters
impact 1 (5 methods and 5 nested keys off the surface; the tier-1 list shrinks from 21 to 16 names), pain 1, reach 3 (the tier-1 list sits in the always-loaded CLAUDE.md of every guided session). Hurts context economy and decision closure (two spellings for one variant).

## Rough idea (not a design)
9.0.0: remove the 5 from `DIRECT_VARIANTS`; methods and nested keys go together, eslint and the variant-object emitter re-derive. Successor `.variant(name, {…})`; the nested case is `.variant("dark", { md: {…} })` (document the `after` ordering difference or leave it, 0 uses). Retarget canonical-names.ts:23 to emit `.variant("dark", …)`. Enforcement: type. Prose: 5 names out of CLAUDE.md:233 / gl/CLAUDE.md:229 and the .ai mirror.
