# The dynamic-class redirect is wrong three ways for the prior's shared styles

## Problem
The prior shares styles as class-string constants: `const LABEL_CLASSES = "block text-sm font-medium text-slate-700"`, `controlClass(error)` returning a template of constants, `` `${CELL_CLASS} text-slate-600` ``. `no-dynamic-class-argument` reports every one at error with: ".addClass(LABEL_CLASSES) is invisible to the safelist extractor - styles can silently disappear in production. Use .when(...) / Match(...) with literal classes per branch, or defineTheme's staticManifest for token-driven values." (`no-dynamic-class-argument.ts:30`). For these sites:

1. **The claim is false.** Tailwind v4's own scanner reads literal strings in source. `npm run css` on the untouched pp1 and pp2 features in the scaffold: 0 of 93 and 0 of 88 distinct tokens are missing from `styles.compiled.css`, including constant-only ones such as `placeholder:text-slate-400` and `focus:ring-indigo-500`. All 15 canonical 8.1.0 projects (14 apps + the scaffold) use a bare `@import "tailwindcss";` (auto source detection).
2. **The named API does not exist.** `defineTheme` takes one `ThemeSpec` argument (`define-theme.d.ts:51`). `defineTheme({ colors: {...}, staticManifest: ["bg-primary"] })` -> `TS2353: Object literal may only specify known properties, and 'staticManifest' does not exist in type 'ThemeSpec'.`; a second argument -> `TS2554`. The real knob is the extractor option `generateFluentSafelist(files, { staticManifest })` (template `scripts/build-safelist.ts:38`). The wrong pointer appears in 3 enforcement messages (this rule; `no-dynamic-typed-styling-arg.ts:240` "add the token to staticManifest (defineTheme())"; extractor `safelist.ts:59`, same text) and 2 prose lines (`guidelines/web-development/CLAUDE.md:72`, `fluent-html/CLAUDE.md:72`).
3. **The idiom is missing.** 13 of the 16 flagged sites are presets (pp1: `CONTROL_CLASSES`, `EMPTY_STATE_CLASSES` x2, `LABEL_CLASSES`; pp2: `controlClass()` x3, `CELL_CLASS` x4 incl. compositions, `LABEL_CLASS` x2), 2 are status lookups (`whenMatch` / `MatchValue`), 1 is a ternary of presets (`whenElse`). The sanctioned shape for a shared style is a user-land `.apply(preset)` helper; the message names `.when`/`Match`.

## Evidence (executed)
- Baseline lint on pp1/pp2 in the template: 6 and 10 `no-dynamic-class-argument` errors, 0 fixes.
- `npm run css` (extractor + postcss/Tailwind) on the original pp1/pp2 code: rc 0; per-token lookup of the compiled CSS: 93/93 and 88/88 present.
- tsc probe of `defineTheme` with `staticManifest` against 8.1.0 dist: TS2353 and TS2554 as quoted.
- Fleet: `@import "tailwindcss";` in public/css of studio, stojnica, everyframe-composer, gzs/stem-50, sportoawards, na-cent, fl-um, competify, fluent-html-home-page, everyframe, competition, popri, website-sales-funnel-automation-system, home-page, and the scaffold.

## Why it matters
Every class constant the prior writes (16/16 sites, both runs) meets this message. Taken verbatim it leads to TS2353 or to `.when` branches that do not fit a shared style; the one shape that fits (`.apply`) is never named. Pain 3, reach 2, impact 2 (error-quality, decision-closure).

## Rough idea (not a design)
Lint message, plus a plugin test that compiles every API a message names against the pinned d.ts (the same test catches [[F-C-206]]'s `.children()`). Split the message by argument shape: identifier / const string / template of constants -> "make it a preset: `const label = (t: Tag) => t....`; `.apply(label)`"; conditional of constants -> `.whenElse`; record lookup -> `.whenMatch` / `MatchValue`. Replace "defineTheme's staticManifest" with the extractor option in all 5 places. Keep the error level (the raw-class policy stands) but drop "silently disappear" unless the argument has a computed hole. The two CLAUDE.md:72 lines then duplicate the lint and can go.
