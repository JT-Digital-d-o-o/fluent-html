# The ternary rule misses the prior's shapes and names a method that does not exist

## Problem
The prior's conditional views use three ternary shapes; the rule matches none of them:
- conditional child by spread: `...(notice ? [P(notice)...] : [])` (pp1 :204, :274), or a helper returning `message ? [P(message)...] : []` that the caller spreads (pp2 :269, :273). Idiom: `IfThen`.
- conditional modifier: `return highlighted ? row.addClass("bg-indigo-50") : row` (pp1 :96, :154, :255; pp2 :265). `role === selected ? option.addAttribute("selected", "") : option` appears verbatim in both runs. Idiom: `.when` / `.toggle(name, cond)`.
- class ternary: `.addClass(error ? CONTROL_ERROR_CLASSES : CONTROL_CLASSES)` (pp1 :266; pp2 :64). Idiom: `.whenElse`.

The rule matches a ternary passed directly (or inside an array literal) to a known element factory, and `const x = cond ? Tag : Tag` with element chains on both sides (`no-ternary-in-view-builder.ts:95-150`). When it does fire, its message is "Avoid ternary expressions as children in Div(). Use .when(condition, t => t.children(...)) instead." (`:83`). `Tag` has no `children` method in 8.1.0 (runtime prototype check: `children` false, `addChild` true).

## Evidence (executed)
- Baseline lint JSON for pp1/pp2 in the template: 0 `no-ternary-in-view-builder` reports; AST inventory (typescript 6.0.3) of views/layout: 10 non-value ternaries (the other 5 are string-value ternaries such as `n === 1 ? "member" : "members"`).
- Probe in the template (eslint + tsc):
  - `Div(c ? P("a") : P("b"))` -> reported with the message above.
  - `Div().when(c, (t) => t.children(P("a")))` -> `TS2339: Property 'children' does not exist on type 'Tag'.`
  - `Div(...(notice ? [P(notice)] : []))` and `sel ? o.toggle("selected") : o` -> no report.
  - `Div(IfThen(notice, (n) => P(n)))` -> compiles, no report.

## Why it matters
The guidelines teach `IfThen` / `.when` for these jobs; the prior never writes the one shape the rule sees, and when it would, the message leads to TS2339. Reach 2 (both runs), impact 2, pain 2.

## Rough idea (not a design)
Lint. Message: name `IfThen`/`IfThenElse` for children and `.when`/`.whenElse` for modifiers. Matching: a `SpreadElement` whose conditional has array-of-element / empty-array sides; `c ? r.m(...) : r` where one side is the other side's receiver; a conditional of class constants inside `addClass` (shared with [[F-C-203]]). The plugin test that compiles every API a message names (proposed in [[F-C-203]]) would have caught `.children()`.
