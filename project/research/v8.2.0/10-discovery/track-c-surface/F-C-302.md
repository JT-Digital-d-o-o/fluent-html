# Non-Tailwind class hooks go through setClass, not the sanctioned cssClass

## Problem

The escape-hatch doctrine assigns one method per job:
- `fluent-html/CLAUDE.md:192` and `guidelines/web-development/CLAUDE.md:190`: "Legit non-Tailwind class (JS hook, third-party) → `.cssClass(…)`".
- `tag.ts:153-157` says the same.

Canonical app code does the job with `.setClass()` at 3.4 times the rate of `.cssClass()` (85 vs 25 sites). The template teaches it that way:

```ts
Div(
  Div(H1(title)).setClass("header"),
  Div(...sections).setClass("content"),
  Div(footerText || "© __PROJECT_NAME__").setClass("footer"),
).setClass("container")          // templates/full-stack/src/infra/email/email.template.ts:51-54
```

`setClass` *replaces* the class attribute (`tag.ts:132-136`). `cssClass` appends (`tailwind-methods.ts:983`). So the taught hook spelling silently drops any class set earlier on the same tag.

## Evidence (executed)

**TypeScript-AST census** (`$C3/twoway-census.mjs`), canonical app-authored columns:

| Spelling | Sites | Repos | Origin of the sites |
|---|---|---|---|
| `.setClass("hook")` | **85** | 15 | 52 in `infra/email/email.template.ts` (4 per repo × 13 repos, including the template itself); 21 in `shared/ui/charts.ts` (`chart-hit`, `chart-ring`, `chart-tick`; 6 repos); 12 in `home-page/src/app/{contact,meeting}/*.email.ts` |
| `.cssClass("hook")` | 25 | 6 | 17 everyframe, 4 home-page, 1 each competify, fluent-html-home-page, gzs/stem-50, templates/web |
| `.setClasses([…])` | 0 | 0 | 78 in the dedup fleet, all pre-7 |

- Loser share: 85 / 110 = **77.3%**.
- Traced to two copied files: 73 of 85 (85.9%).
- All 85 arguments are non-Tailwind hook names.

**Replace vs append** (probe):

```
Div().p("4").setClass("header")   -> <div class="header"></div>
Div().p("4").cssClass("header")   -> <div class="p-4 header"></div>
Div().setClass("header")          -> <div class="header"></div>   (identical to .cssClass on a fresh tag)
```

**Lint.**
- The template's email exemplar gets 0 class-related findings from plugin 4.1.0 (3 findings, all `no-fluent-equivalent-in-setstyle` on its preheader `setStyles`).
- `setClass("container")` and `cssClass("container")` both lint clean ($C3/ui-lint/email/hook.ts). So a mechanical switch introduces no new lint error.
- **Oracle:** `container` is a real Tailwind 4.3.3 utility (`.container { width: 100%; @media (width >= 40rem) { max-width: 40rem } … }`). The other 7 hook names return null. Neither class-hatch rule notices the collision.

## Why it matters

- **Scoring:** impact 2 × pain 2 × reach 3 (15 of 16 canonical repos) / effort S(1) = 12.
- **The survivor is documented, but the exemplars teach the loser.** Every scaffolded app ships 4 setClass hook calls in its email template. Recon 01 §2.4 found an "identical vendored floor" of setClass 4 per template-derived app: this is it.
- **Decision closure:** the doctrine has one answer, while the code corpus agents learn from has the other at 77%.
- **Blind agents learn from exemplars** (recon 02 §2.4: 94/96 `src/` accesses). The exemplar decides the outcome.

## Rough idea (not a design)

**Template (strongest layer: the scaffold exemplar):**
- `email.template.ts:51-54` → `.cssClass(…)`. Output is byte-identical on these fresh tags.
- Re-vendor, which takes 52 of the 85 sites to 0.

**Lint (8.2.0, additive):**
- `prefer-cssclass-for-hooks` flags `setClass` whose argument has no Tailwind token and which is the chain's first class write.
- Autofix to `.cssClass` (identical bytes in exactly that case).

**9.0.0:** delete `setClasses` (0 canonical sites).

**Prose deleted:** the setClass rows of the README head (`README.md:64`, `:107`) once the census is regenerated (C4).
