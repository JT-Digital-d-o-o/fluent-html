# 21 of 46 root standalone exports have 0 canonical-era imports

$R = <scratch>/wave1/C-reseed

## Problem

The prune seed (L-153) and every C1 finding so far count methods. The census's standalone table covers 16 names; the root barrel exports 46 standalone values (functions and objects, factories and classes aside). Nobody had counted the other 30. An import census over all entry points finds 21 of the 46 with no canonical-era importer, each one also exported from a subpath, so the root copy is a second import path for a name nobody imports. Six of them (`id`, `clss`, `closest`, `find`, `next`, `previous`) are a converged two-way: they return exactly the htmx selector string an author can write directly, and canonical code writes the string.

## Evidence (executed)

**Import census** (`$R/import-census.mjs`, 58 repos, value imports and re-exports from `fluent-html` and its 10 subpaths):

| Group | Names | Canonical-era importers | Any era |
|---|---|---|---|
| 0 in any era (15) | `Doctype`, `EVENT_TABLE`, `HTMX_EVENTS`, `Repeat`, `clss`, `escapeAttr`, `extractId`, `find`, `isRawString`, `isTag`, `previous`, `renderToIterable`, `resolveSelector`, `sanitizeUrl`, `setDevChecks` | 0 | 0 |
| pre-7 only (6) | `id` 24 files / 2 repos, `El` 8 / 2, `closest` 6 / 2, `renderToStream` 5 / 5, `next` 2 / 1, `extractSelector` 1 / 1 | 0 | 46 files |
| live (25) | e.g. `IfThen` 545 app files / 16 repos, `defineRoutes` 252 / 16, `render` 22 / 15 (+391 vendored) | > 0 | |

- 21 of 21 are also exported from a subpath (`./core`, `./elements`, `./control`, `./htmx`, `./ids`, `./render`, `./behaviors`).
- Tooling consumers: 0 of the 21 in the eslint plugin (imports only `fluent-html/class-vocab` + `ThemeSpec`), the extractor, `packages/ui` or fluent-html-demos.
- Selector helpers, rendered against dist 8.1.0: `closest("form")` -> `closest form`, `find(".x")` -> `find .x`, `next()` -> `next`, `previous("li")` -> `previous li`, `id("team-list")` -> `#team-list`, `clss("row")` -> `.row`; `Button("x").setHtmx({ method: "get", endpoint: "/x", target: closest("tr") })` -> `<button hx-get="/x" hx-target="closest tr">x</button>`, the same bytes as the literal. `HxTarget` already accepts the string, so the helpers add no type safety; `id()` returns a plain `"#…"` string, a third id spelling beside `defineIds` objects and string ids.
- String form in use: 147 `"closest …"` / `"find …"` / `"findAll …"` / `"next …"` / `"previous …"` literals in the src of 16 of 16 canonical repos (vendored core included; `closest form` 36 in a 7-repo sample). Helper imports: 0.
- Teaching: REFERENCE.md:310-328 shows all 6 helpers, inside `hx("/api", …)` calls that F-C-408 measured as TS2345 on 8.1.0; the guidelines teach 0 of them.

## Why it matters

impact 1 x pain 1 x reach 2 / S = 2. Each root name is one more entry in the import completion list and in `index.d.ts`, with no exemplar and no canonical caller; for the selector helpers it is also a second spelling of an htmx selector. Dims: context-economy, decision-closure.

## Rough idea (not a design)

Layer: type (the export surface), 9.0.0. Remove the 21 from the root barrel, keep them on their subpath (no deletion, so the integration hooks `setDevChecks`, `renderToIterable`, `isTag` stay reachable); codemod rewrites the 46 pre-7 import sites' specifiers when those repos upgrade (0 canonical sites). Separately decide whether the 6 selector helpers go entirely (they return the literal). Delete REFERENCE.md:310-328. Extend `method-census.mjs` with an import census so standalones enter the next prune list.
