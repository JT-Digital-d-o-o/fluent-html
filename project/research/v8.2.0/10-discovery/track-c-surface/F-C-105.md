# The lint redirect for pruned utilities does not redirect

## Problem
The pure prior styles through raw class strings (recon 02: 41/39 `addClass` calls, 135/136 `no-tailwind-in-raw-class` findings per run), so `no-tailwind-in-raw-class` is where a pruned utility is met. For classes whose method was pruned, the rule does one of three things, none of which names the successor:

- **Generic message** (22/26 of the 8.0.0 sample): "... is a Tailwind 'place-items-center-*' utility with no fluent method. Use .cssProp() for arbitrary CSS, or file the vocab gap". The family label is the whole class plus `-*` in 14/22 (`place-items-center-*`, `snap-x-*`, `scheme-dark-*`, ...; none of those match a Tailwind class), no CSS property is named, and "file the vocab gap" invites re-adding a deliberately pruned row. 18/26 classes compile to a single declaration, so the exact successor (`.cssProp("place-items", "center")`) is derivable from the pinned oracle.
- **Autofix into a compile error** (4/26): a surviving row's prefix swallows the class: `scroll-mt-4` -> `.scroll("mt-4")`, `rotate-x-45` -> `.rotate("x-45")`, `scale-x-50` -> `.scale("x-50")`, `perspective-origin-center` -> `.perspective("origin-center")`; all four are TS2345 (e.g. `Argument of type '"mt-4"' is not assignable to parameter of type 'TailwindScrollBehavior'`).

Simulating the 9.0.0 prune (F-C-101's 60 names removed from the class-vocab the plugin derives from), 15 styling classes that autofix cleanly today regress:

| Class | Today | Post-prune |
|---|---|---|
| `bg-blend-multiply` | `.bgBlend("multiply")` | autofix `.bg("blend-multiply")` -> TS2345 |
| `col-end-2`, `row-end-3` | `.colEnd("2")`, `.rowEnd("3")` | autofix unchanged via hand rows derive-fixable.ts:114/:116 -> TS2339 (method gone) |
| `table`, `@container` | `.table()`, `.containerQuery()` | no report at all |
| 10 others (`auto-cols-min`, `caret-blue-500`, `inline-grid`, `scroll-smooth`, `transform-3d`, ...) | autofix | generic message; 5 with a `<class>-*` label that matches nothing |

The tier-1 half re-derives correctly: `dark:bg-night` -> `.variant("dark", { bg: "night" })` 5/5 post-prune (see F-C-106).

## Evidence (executed)
`node pruned80.mjs`: per class, `design.candidatesToCss([cls])` (non-`--tw` declarations) and the first `no-tailwind-in-raw-class` message on `Div().addClass(cls)`. Totals: 26 Tailwind classes, 22 generic, 4 autofix, 0 naming a property; 18 single-declaration. Bogus-label count: a label counts as bogus when `<root>-{1,2,4,50,100,0,x,y,auto,none}` all fail the oracle (14/22). `tsc -p tsconfig.fix80.json` on the 4 autofix outputs: 4x TS2345. Simulation: `node sim/lint.cjs <plugin>` for the real plugin and for the shimmed copy; outputs quoted in the table.

## Why it matters
impact 2 (the redirect is the only layer between the prior's `addClass("...")` and a working call for pruned utilities; today it names nothing or emits a compile error), pain 2 (4 + 3 autofixes look authoritative and break the build; "file the vocab gap" steers toward reversing a prune), reach 2 (38 roots pruned in 8.0.0, 15 more classes in 9.0.0; 0/192 pure-prior class tokens hit these roots in recon 02, so present-day reach is the migration and long tail). Hurts error quality and prior alignment (the prior's spelling gets no one-shot redirect).

## Rough idea (not a design)
Strongest layer: lint, derived from the oracle the lib already pins. For a token with no fluent method: if `candidatesToCss` yields one declaration, autofix (or suggest) `.cssProp("<prop>", "<value>")`; label the family with the design system's utility root; never autofix to a method whose value union rejects the argument (check the vocab row's literals before emitting); delete derive-fixable's hand rows for pruned methods in the same change as the vocab row. Deletes the "file the vocab gap" wording.
