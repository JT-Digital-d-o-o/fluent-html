# Numeric SVG setters: half accept numbers, half demand strings

## Problem
The SVG setter family types numeric attributes two ways. From the TS checker over dist d.ts: **30** numeric-valued
setters take `string` only (Circle `cx cy r`; Rect `x y rx ry`; Line `x1 y1 x2 y2`; Ellipse `cx cy rx ry`; Use `x y`;
SvgText and Tspan `x y dx dy fontSize letterSpacing`; SvgShape `opacity`), while **30** siblings take
`string | number` (Rect/Use/Svg `width height`, `strokeWidth strokeDashoffset strokeOpacity`, LinearGradient
`x1..y2`, RadialGradient `cx cy r fx fy`, Stop `offset stopOpacity`, Mask/Filter `x y width height`,
FeGaussianBlur `stdDeviation`). The same method name flips: `setX` is `string` on RectTag/UseTag/SvgTextTag/TspanTag
and `string | number` on MaskTag/FilterTag; `setCx` and `setX1` likewise. The model writes numbers.

## Evidence (executed)
1. Prior: the 8 context-withheld runs of F-C-501 (HTML page with an SVG icon). After the setter names heal
   (`prior/heal.cjs`), the residual tsc errors are 40 x `TS2345: Argument of type 'number' is not assignable to
   parameter of type 'string'.` = 5 per run in 8/8 runs (`Rect().setX(0).setY(0)`, `Text("Hi").setX(12).setY(12)
   .setFontSize(4)`). The same runs pass numbers to the `string | number` siblings (`setWidth(1)`, `setOffset(0)`,
   `setStdDeviation(2)`, `setStopOpacity(0.5)`), which compile. The error names no fix.
2. Census (`svgnum.cjs`, dedup corpus, argument shape of the 16 string-only names): canonical era 1,294 sites:
   701 `String(...)`/`.toString()`/`.toFixed()` wrappers, 566 numeric string literals (`"12"`), 27 other
   expressions, 0 number literals. Pre-7: 1,394 sites, 787 wrappers, 518 numeric string literals. Name totals
   (census fleet/canonical): setX 491/242, setY 489/242, setCx 279/131, setFontSize 209/44, setOpacity 52/45.
3. Where the wrappers live: 15 of 16 canonical repos (38-55 each); the template's own chart kit writes 47 of them
   in 5 files (`templates/full-stack/src/shared/ui/chart/chart.{primitives,line,funnel,donut,bar}.ts`, e.g.
   chart.primitives.ts:152-159), copied into every template-derived app. The exemplar corpus agents learn from
   teaches the wrapper.

## Why it matters
impact 1 x pain 2 x reach 3 / S = 6. prior-alignment: 40/40 numeric arguments in the experiment were numbers;
the type rejects the prior for half the family and accepts it for the other half. context-economy: 701 canonical
`String()` wrappers exist only to satisfy the narrower type. The error is loud (TS2345), so impact stays 1.

## Rough idea (not a design)
Type layer, additive: widen the 30 to `string | number` and `String()` inside the setter, exactly as the 30
siblings do (8.2.0, no codemod, no emitted-byte change for existing string callers). Optional follow-up in the
template: drop the 47 chart-kit wrappers. Prose deleted: none.
