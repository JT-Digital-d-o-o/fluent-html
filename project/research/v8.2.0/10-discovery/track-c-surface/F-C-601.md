# The template's type-scale guard still matches the pre-7 name `.textSize(`

$R = <scratch>/wave1/C-reseed

## Problem

The closed type scale is taught in both CLAUDE.md copies: "`.text()` sizes on the named scale, never `.text("rem", 0.82)`" (gl CLAUDE.md:233, fluent-html/CLAUDE.md:237; the unit overload is "an escape hatch" at :184 / :186). Its only enforcement is a template unit test, vendored into every app:

```ts
const offScale = /\.textSize\("(?:px|rem|em|%|vh|vw|dvh|svh|lvh)"/g;   // theme-tokens.test.ts:59
```

It was written on 2026-07-25 (226140a), against the varnoska drift of 198 `textSize("rem", N)` calls. Six days later 7.0.0 renamed `textSize` to `text` (canonical-names.ts:72). The codemod rewrote call sites through the AST with a receiver check; the guard is a regex in a test and was left as is. Since 7.0.0 the regex can only match code that fails tsc (`.textSize` is TS2339 on 8.1.0), so the guard passes every app by construction.

The lint layer pushes the other way. `prefer-unit-overload` (recommended, autofix; template config warn at eslint.config.mjs:76) carries `text` in UNIT_METHODS and rewrites the bracket form into the unit overload the prose forbids.

## Why it matters

impact 2 x pain 2 x reach 3 / S = 12. The rule is closed-scale doctrine (the 2026-07-25 varnoska lesson), the prose claims it is held, and the one executable holder has been inert for two months while 790 sites accumulated. Every layer an agent reaches is silent (tsc, eslint), and the lint actively converts the bracket form into the forbidden one. Dims: verification-loop (a green test that checks nothing), decision-closure (two spellings of a size, one banned in prose only), evolvability (renames silently retire string-encoded enforcement).

The same blind spot sizes the parked lowercase-tail setter rename (F-D-160, L-144). For the three outliers it would rename, string consumers outside any call site: prefer-set-method.ts:44 and :104 (`crossorigin: "setCrossOrigin"`, `referrerpolicy: "setReferrerPolicy"`; after a call-site-only codemod the autofix would emit the old name, TS2339), 6 guideline lines, 9 lib-doc lines, 7 lib test files. A rename plan needs a string sweep, measured, in its dry run.

## Rough idea (not a design)

Layer: ci now, lint next, type later. Upstream the popri-shaped guard (match `.text("<unit>", n)` and the `text: [unit, n]` key, with an explicit ratified-size set per project) and drop `text` from prefer-unit-overload's autofix set, or make its message name the scale. The strongest layer is type: remove `.text`'s unit overload in 9.0.0 (790-site codemod; 232 map to a named size, the rest need a ratified token), which would also delete the CLAUDE.md :184/:233 prose. Add "grep every renamed identifier across tests, lint maps and docs" as a measured step of any rename codemod.
