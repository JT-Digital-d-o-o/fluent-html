# `set*(undefined)` has four meanings

## Problem
The set/add rule (guardrail 8: set* overrides) holds for repeated values: the runtime audit calls every set*
twice and **263/263** override. It does not hold for `undefined`, the value TypeScript lets through on every
setter whose parameter is optional. The conditional idiom `setX(cond ? value : undefined)` compiles for all 172
such setters and does four different things:

```
Span("x").setLang("en").setLang(undefined)               -> <span lang="en">      (kept)
HTML().setLang("en").setLang(undefined)                   -> <html>                (cleared)
Div().setPopover("manual").setPopover(undefined)          -> <div popover="auto">  (switched to default)
Div().setContenteditable("false").setContenteditable(undefined) -> contenteditable="true"
Div().setSpellcheck("false").setSpellcheck(undefined)     -> spellcheck="true"
Input().setName("n").setName(undefined)                   -> <input>               (cleared: the 164)
```

The worst case is the three defaulted parameters: passing `undefined` to mean "no attribute" turns the
attribute on. `Div("Menu").setPopover(isMenu ? "manual" : undefined)` with `isMenu = false` makes the div a
popover, which the UA stylesheet hides.

## Evidence (executed)
1. `setadd-audit.mjs`: for every set* whose first parameter is optional (172 owner/method pairs from the TS
   checker over dist d.ts), render set(A), then set(A).set(undefined), compare with the bare element: 164 clear,
   5 keep (Tag.setPopovertargetaction, setLang, setDir, setTranslate, setForm), 3 re-emit their default
   (setPopover, setContenteditable, setSpellcheck; confirmed with non-default A in `probe1.mjs`), 1 restores its
   default (SvgTag.setXmlns -> the SVG namespace, benign).
2. Receiver dependence: Tag.setLang/setDir keep (tag.ts:565-572), HtmlTag.setLang/setDir clear
   (document.ts:25, :31): the same call on `Span` and on `HTML` has opposite semantics.
3. `tsprobe/probe3.ts`: `setPopover(isMenu ? "manual" : undefined)`, `setContenteditable(... : undefined)`,
   `setSpellcheck(... : undefined)`, `setLang(locale)` with `locale: string | undefined`,
   `setPopovertargetaction(... : undefined)`, `setForm(... : undefined)`: tsc rc=0, eslint has no rule.
4. `browser-popover.mjs` (Chromium): rendered `<div id="m" popover="auto">Menu content</div>`, computed
   `display: none`; `<div contenteditable="true">` -> `isContentEditable: true`.
5. Exposure (dedup census + call-shape grep): setPopover 10 fleet / 5 canonical, all bare calls; setLang 76/23,
   the 29 identifier-argument calls are `HTML().setLang(documentLang())` in the template layout (clears, fine);
   setPopovertargetaction 4/3 literal; setContenteditable, setSpellcheck, setDir, setTranslate, setForm 0/0.
   Observed misuse: 0.

## Why it matters
impact 2 x pain 3 x reach 1 / S = 6. silent-failure: an element disappears or becomes editable with every layer
green. decision-closure: the meaning of `set*(undefined)` depends on which of 172 setters, and for setLang/setDir
on which receiver; no prose states any of the four meanings. Reach 1 today (0 misuse sites), but the conditional
`cond ? v : undefined` shape is the one the prose steers toward for optional values (`bg: cond ? "primary-700" :
 undefined` in the variant-object rule).

## Rough idea (not a design)
Runtime layer: one meaning, "explicit undefined clears" (the 164-setter majority). For the 3 defaulted setters,
keep the documented bare-call default (`setPopover()` -> auto, pinned at native-interactivity.test.ts:14) by
branching on `arguments.length === 0`; for the 5 no-op setters drop the early return and delete the key. A parity
test walks every optional set* (the audit already does) and asserts A-then-undefined equals the baseline. Bytes
change only where `undefined` is passed after a value, which today renders the wrong attribute. Prose deleted: none.
