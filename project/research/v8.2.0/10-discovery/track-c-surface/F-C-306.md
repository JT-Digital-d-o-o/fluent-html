# @jtdigital/ui is a dead second component layer written in the losing style

## Problem

The instruction-set guardrail and its rulings name `@jtdigital/ui` as the place where components live:
- S-05: "Components are user-land (`@jtdigital/ui`)";
- L-411 (opinionated components), L-188 (breadcrumbs), L-236 (Stack/Row), L-190 (Container);
- `fluent-html/src/elements/forms.ts:524`: "the styled FieldError shell lives in @jtdigital/ui".

The package (`projects-template/packages/ui`, last `src` change 2026-08-03) is a second component layer beside the template's live `src/shared/ui` (e.g. `LoaderButton`, `shared/ui/button.ts:39`, 74 canonical-era sites per recon 01). It is written in the spellings the library converged away from:

```ts
function DismissButton(): View {
  return Div(P("×"))
    .cursor("pointer").text("lg").leading("none")
    .addClass("hover:opacity-70")                          // lint-blocked styling path
    .addAttribute("onclick", "this.parentElement.remove()"); // inline JS, dead under the template CSP
}                                                          // packages/ui/src/feedback/Alert.ts:55-62
```

Its components also take a `className?: string` prop and `.addClass(className)` it (11 files). That is the string-prop shape the typed surface exists to replace.

## Evidence (executed)

**Consumers.**
- `package.json` files naming `@jtdigital/ui` under `<org-root>` (excluding node_modules and `.claude`): 1, the package's own (`package.json:2`).
- `.ts` imports of `@jtdigital/ui`: 0.
- In the TypeScript-AST census the package is the second-largest source of canonical `addClass` calls: 18 of 65; home-page's blog views have 45.

**Lint.** Plugin 4.1.0 recommended, on a copy of `src/` (17 files):

| Rule | Severity | Count |
|---|---|---|
| no-dynamic-typed-styling-arg | error | 13 |
| no-dynamic-class-argument | error | 13 |
| no-tailwind-in-raw-class | error (autofix) | 10, e.g. `'hover:opacity-70' in .addClass() … Replace with: .hover({ opacity: "70" })` |
| no-superfluous-view-return-type | warn | 18 |

**Other measures.**
- **Type check:** `tsc --noEmit` against 8.1.0 exits 0. The 22 palette literals (`gray-200`, `gray-700`, …) compile because the package has no color opt-out; under the template's opt-out each is TS2345 (recon 02 probe 5).
- **Inline JS:** the 1 `onclick` is the only canonical-era `addAttribute("onclick")` in the corpus.

## Why it matters

- **Scoring:** impact 2 × pain 1 × reach 1 (0 consumers today) / effort S(1) = 2.
- **Decision closure:** the ruled home for components and the live component layer are different packages. An agent told "components are user-land in @jtdigital/ui" finds a package where 11 of 13 component files teach `addClass(…)` with `className` string props, next to 22 palette literals, the exact pure-prior divergences D3/D4 (recon 02 §2.3).
- **Converge (§5.7):** two component layers, one of them dead.

## Rough idea (not a design)

**Decision-gated:** it changes the package S-05 and 4 dispositions name.

- **Option A:** delete `packages/ui` and re-point S-05/L-411 and `forms.ts:524` at the template's `src/shared/ui`, the only layer with consumers and compiling exemplars.
- **Option B:** rewrite `packages/ui` in the typed style and publish it with at least one consumer:
  - 10 errors autofix;
  - 26 need `whenMatch`/`MatchValue` rewrites of the `colorMap[color][variant]` lookups;
  - `onclick` becomes `.behavior("remove", …)`.

Enforcement either way: run the plugin in `packages/ui` CI, which today has no lint script (`package.json` scripts: `build`, `dev`).
