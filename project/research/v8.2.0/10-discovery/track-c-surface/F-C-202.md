# htmx-2 names pass every layer the prior reaches, and the one hx lint redirects the wrong way

## Problem
The prior's htmx model is htmx 2: both runs load `unpkg.com/htmx.org@2.0.4`. It writes htmx attributes through `addAttribute`: pp1 `hx-disabled-elt="find button"` (views.ts:246), `hx-sync`, `hx-swap-oob`; pp2 `hx-on:htmx:before-swap` reading `event.detail.xhr` / `shouldSwap` (views.ts:226), `hx-swap-oob` x2. The only lint is `prefer-htmx-api`, whose trigger is a hand-kept set of 24 names that the typed API covers (`prefer-htmx-api.ts:4-29`); anything outside the set returns early. So the names that do nothing on htmx 4 get no report, and the names that work get a warn whose redirect is wrong.

## Evidence (executed)
1. Chromium via Playwright (fluent-html's node_modules), same page per bundle, POST fulfilled after 600 ms:

| | 4.0.0 (template-served) | 4.0.0-beta6 (lib pin) |
|---|---|---|
| button disabled mid-request, `hx-disabled-elt="find button"` | false | false |
| button disabled mid-request, `hx-disable="find button"` | true | true |
| `hx-on:htmx:before-swap` handler runs | 0 | 0 |
| `hx-on:htmx:before:swap` handler runs | 1 | 1 |

2. eslint (template config, plugin 4.1.0): `addAttribute("hx-disabled-elt"|"hx-on:htmx:before-swap"|"hx-ext"|"hx-disinherit", ...)` -> 0 reports; tsc -> 0 errors. In the prior runs, pp1 views.ts:246 and pp2 views.ts:226 carry no report in the baseline lint JSON. Recon 02 section 2.3 rows D9/D10 list `prefer-htmx-api` as the catching layer; the executed lint reports nothing there.
3. `addAttribute("hx-swap-oob", "true")` -> `Use the HTMX API (hxGet, hxPost, setHtmx) instead of .addAttribute("hx-swap-oob", ...)` (`:42`). Following it with the typed key: `Section("x").setId("team-members").setHtmx(teamRoutes.members({ swapOob: true }))` renders `<section id="team-members" hx-get="/team/members" hx-swap-oob="true">`; the prior's own form renders without `hx-get`. Recon 03 S14 executed the consequence (the swapped-in element keeps `hx-get` and becomes htmx-powered). `Partial(ids.x, ...)`, the 8.x replacement, is not named; `hxPost`, which is named, has 0 canonical-era call sites (recon 01 section 2.3).
4. `guidelines/web-development/htmx.md:228`: "never `addAttribute("hx-*", ...)`" marked `<!-- enforced: lint fluent-html/prefer-htmx-api`. The enforcement covers 24 names.

## Why it matters
Silent failure: double-submit protection and a 422 swap hook the author believes present are absent, with no error from tsc, eslint or the runtime. It recurs as a class in both runs (one inert htmx-2 name per run). Impact 3, pain 2, reach 2.

## Rough idea (not a design)
Lint, derived instead of hand-kept: build the hx attribute set from the pinned bundle (recon 03's S0 read-spy output is that list) and report at error any `addAttribute("hx-...")` literal the bundle never reads, naming the htmx-4 spelling where one exists (`hx-disabled-elt` -> the `disable:` option / `hx-disable`; `hx-on:htmx:before-swap` -> `htmx:before:swap`, and in the template the behaviors runtime, since the CSP blocks inline `hx-on`). Redirect text names the option key, and for `hx-swap-oob` names `Partial()`. This makes the enforced claim at htmx.md:228 true.
