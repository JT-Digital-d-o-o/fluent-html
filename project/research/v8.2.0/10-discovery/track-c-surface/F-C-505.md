# addAttribute + a typed setter on the same attribute emits the attribute twice

## Problem
The serializer writes attributes from three stores: schema storage fields (`_sk`, 74 `defineSchemaKeys` calls),
the `attributes` bag (`addAttribute` and the Tag-level setters), and `_htmx`. Only three bag keys are skipped
when a dedicated field exists (`id`, `class`, `style`, serialize.ts:253). Every other overlap is emitted twice:

```
Input().setName("a").addAttribute("name","b")                 -> <input name="a" name="b">
Input().setType("email").addAttribute("type","text")         -> <input type="email" type="text">
Form().setAction("/a").addAttribute("action","/b")          -> <form action="/a" action="/b">
Button().setHtmx(u,{target:"#b"}).addAttribute("hx-target","#a")
                                  -> <button hx-target="#a" hx-get="..." hx-target="#b">
Button().hxPost(u).addAttribute("hx-post","/raw")            -> <button hx-post="/raw" hx-post="https://...">
```

Duplicate attributes are an HTML parse error; the parser keeps the first. Call order does not matter
(`addAttribute("name","b").setName("a")` renders the same bytes). So for schema attributes the typed setter wins
silently, and for hx-* the untyped `addAttribute` wins over the typed `setHtmx`/`hxPost` silently: the
precedence is inverted between the two families, and neither matches a documented rule.

## Evidence (executed)
1. `dup-audit.mjs`: for every (class, set*) pair from the runtime audit, call the setter, derive the attribute(s)
   it emits, then `addAttribute(attr, "ZZ")` after and before it. 299 pairs tested; **280 emit the attribute
   twice** (135 distinct names, every subclass schema setter: `cite colspan rowspan scope name type value action
   href src viewBox stroke-width ...`). The 19 clean pairs are the Tag-level setters that write through the bag
   (`setRole`, `setTabindex`, `setLang`, `setAria`, `setDataAttrs`, ...), where the last write wins.
2. `probe2.mjs`: htmx overlap renders `hx-target` and `hx-post` twice with the bag copy first; `toggle("required")`
   + `addAttribute("required","")` renders once (the toggle path dedups, serialize.ts:266).
3. `browser-dup.cjs` (Chromium 149 via fluent-html's playwright): `{"name":"a","hxTarget":"#a","action":"/a",
   "type":"email"}`: schema setter value kept, addAttribute hx value kept, the other copy dropped.
4. Tests: test/attributes.test.ts:111-140 pins the id/class/style skip; no test covers any other overlap.
5. Exposure: fleet dedup corpus, 1,917 chains carry `addAttribute` (3,945 literal sites; 2,674 on attributes
   that have a typed setter, all pre-7); same-chain schema duplicates found: **0**. hx-* candidates by option-key
   heuristic: 12, the 2 inspected (buzzin login.ts:47, jt-cut voiceover.view.ts:109) are false positives. recon 02
   pure-prior code: 30 of 53 `addAttribute` calls (57%) target attributes that have a typed setter
   (`name`, `src`, `action`, `method`, `for`, `autocomplete`, `lang`, ...), 0 same-chain duplicates.

## Why it matters
impact 2 x pain 3 x reach 1 / S = 6. silent-failure: clean on tsc, eslint (`prefer-set-method` only flags the
`addAttribute` side for 86 mapped names), extractor and dev runtime; the browser discards one value. Invalid
HTML (duplicate attribute) is emitted by a library whose serializer comment says a bag value is "never silently
dropped" (serialize.ts:251-252). invariant-safety: the "dedicated setter wins" rule of 6.0.1 holds for 3 names
and is reversed for hx-*. Reach 1: 0 observed occurrences today; latent wherever a preset or later edit adds the
typed setter to a chain the model wrote with `addAttribute` (57% of the pure prior's calls are on such names).

## Rough idea (not a design)
Runtime layer in the one choke point: generalize serialize.ts:253 to skip a bag key whenever a schema field or
`buildHtmx` emitted the same attribute (typed setter wins, as for id/class/style), and emit hx-* before the bag
or skip bag hx-* keys the typed config produced. A parity test iterates every schema key and the 27 hx-* attribute
names (recon 03 §1) and asserts a single occurrence. Optional dev-mode warning naming the dropped `addAttribute`.
Bytes change only where invalid HTML is emitted today (8.1.x). Prose deleted: none.
