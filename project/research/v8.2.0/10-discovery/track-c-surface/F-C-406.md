# Guideline inline code grew from 153 to 176 blocks after the scorecard asked for pointers, 5 compilable blocks fail tsc on 8.1.0, and inline blocks cannot prove 36 of their 74 ✗ lines

$C4 = <scratch>/wave1/C4

## Problem

The 2026-08-14 scorecard's guidelines lever #1 was "actually shrink: convert the inline code blocks to pointers at compiling exemplars" (scorecard.md:185), and §5.12 says net guideline lines go down every release. Since then the corpus has grown, and the blocks it added are not checked by anything.

## Evidence (executed)

**Size, fd0ae85 (2026-08-14) vs HEAD 95067fa:**

| | Blocks (ts) | Lines | Chars | Lines in fences |
|---|---|---|---|---|
| fd0ae85 | 153 (140) | 2,384 | 135,253 | — |
| HEAD | 176 (163) | 2,804 | 168,905 | 1,159 (41.3%) |

**Pointers to template source in prose:** 15 mentions, 9 distinct paths. One is dead: fastify.md:373 `src/core/index.ts` does not exist in templates/full-stack/src/core.

**Compile oracle.** Each ts block was compiled in the template 3.7.0 scaffold (fluent-html 8.1.0, template theme, swap verbs and core exports auto-imported; unknown free names declared `any`, so only API errors remain):

- 36 of 163 are pseudo-code (syntax errors from `…` placeholders) and cannot be compiled at all. By file: CLAUDE.md 12/33, fastify.md 8/20, htmx.md 7/48, views.md 4/15, fluent-html.md 3/31, typescript.md 2/16.
- 127 compile. 5 fail tsc on a line with no ✗ marker:

| Line | Code | Diagnostic |
|---|---|---|
| views.md:84 | `Div(...children).flex().alignItems("center")` | TS2339 `Property 'alignItems' does not exist on type 'Tag'` (renamed `.items` in 7.0.0) |
| views.md:206 | `import { createRequiredContext } from "~/core/context"` | TS2307 (module does not exist) |
| fluent-html.md:27 | `A("Link").setHref("/page")` shown as the AnchorTag example | TS2345 `'"/page"' is not assignable to 'ResolvedRoute \| ExternalHref \| undefined'` (8.0.0 brand) |
| fluent-html.md:520 | `import type { TailwindPosition, TailwindTextAlign, TailwindFlexDirection, TailwindJustifyContent, TailwindAlignItems } from "fluent-html"` | TS2305 x5 (exported from `fluent-html/core` only, dist/src/core/index.d.ts:16) |
| CLAUDE.md:227 | `.md({ …, hover: { bg: "primary-800" } })` | TS2820 (no such template token; "Did you mean primary-700") |

**✗ lines.** The 127 compilable blocks carry 74 ✗-marked lines:

- 18 draw a tsc error on that line.
- 22 draw a template-eslint error (e.g. prefer-foreach, prefer-set-method, anchor-requires-cursor-pointer, template/return-the-render).
- 38 draw either.
- 36 draw neither when compiled alone, because their failure depends on context the block does not carry. Examples: htmx.md "`userRoutes.lsit() // ✗ typo — compile error`" and "`A(\"Count\").nav(userRoutes.count()) // ✗ Type 'Id<\"user-count\">' is not …`" are clean because `userRoutes` is not defined in the block. Others are prose-only rules (the ternary and `IfThen(!!x)` shapes).

Context cost: recon 02 measured the guided condition at +19,579 always-loaded tokens for blind−guided = 0 tsc errors and 0 of 25 acceptance checks (02-agent-fitness-delta.md:193-196).

## Why it matters

impact 2 x pain 2 x reach 3 / L. Inline blocks rot: 5 fail today, and 36 can never be compiled. Half the ✗ claims cannot be checked from the page that makes them. A fixture in the template would prove both halves: ✓ compiles, and ✗ carries `@ts-expect-error` or a RuleTester case. Dims: context-economy, verification-loop.

## Rough idea (not a design)

Layer: ci (template test suite). For each ✓/✗ pair, add a fixture file under the template's `tests/`, with `@ts-expect-error` on ✗ lines that tsc must reject and an eslint RuleTester case for lint-enforced ones. Replace the block with a one-line pointer. Do the 5 failing and 36 pseudo-code blocks first. Target: delete up to 1,159 fence lines. Re-run `$C4/blocks.mjs` as the acceptance measure.
