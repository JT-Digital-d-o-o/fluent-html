# The canonical-names codemod stops at the first live method in a chain

## Problem
`npm run codemod:canonical` rewrites a renamed call only when its receiver types as `Tag`. To survive a target repo that already links the renamed library, it walks back transitively, but only through other rename-source calls (`canonical-names.ts:161-170`).

Against 8.1.0, every type after the first renamed call in a chain is `any` until the file is rewritten. Any live method between two old names (`.background(x).rounded("lg").padding("4")`) therefore breaks the walk: the later old name is skipped and reported for manual review (:362). The tool runs once (:423-447), so the agent meets these skips as anonymous `Property 'padding' does not exist on type 'Tag'` on names the codemod's own map knows.

## Evidence (executed)
`$R2 = <scratch>/wave1/B-reseed/r2`

**Minimal repro** (`cm-min`, 8.1.0):
- `Div().background("white").rounded("lg").padding("4")` needs 2 passes.
- `Div().padding("4").rounded("lg").margin("2").shadow("md").textColor("red-500")` needs 3.
- Each live method between old names costs one more pass.
- `test/codemod-canonical.test.ts:293-296` pins only a chain made entirely of old names.

**Real upgrades** (`up/`): each repo copied with `fluent-html` overlaid to 8.1.0, codemod run from `dist/scripts/codemod`, each repo's own tsc.

| repo (pin) | tsc on 8.1 before | pass 1 rewritten / skipped | tsc after pass 1 | passes to fixpoint | later rewrites | skipped at fixpoint | tsc at fixpoint |
|---|---|---|---|---|---|---|---|
| jt-vault (5.9.1) | 1,370 | 2,373 / 287 | 474 | 3 + 1 empty | 250 + 32 | 4 | 367 |
| planet-positive-sport (5.11.0) | 3,664 | 5,722 / 3,186 | 1,860 | 6 + 1 empty | 1,854 + 611 + 201 + 51 + 6 | 54 | 518 |

- One run leaves 107 and 1,342 tsc errors that the same tool removes when re-run.
- 283/287 (98.6%) and 3,132/3,186 (98.3%) of the manual-review reports were automatable. The dry run over-reports manual work 72x and 59x.
- Own-version baselines: jt-vault has 20 pre-existing errors, planet-positive-sport 0.
- The remaining 4 / 54 skips are real (helper receivers, chains poisoned by 6.0.0-removed calls; see [[F-B-605]]).
- The 1245/1245 precedent (CHANGELOG.md:298) was measured on the template, whose chains do not interleave old and live names.

## Why it matters
impact 2 x pain 3 x reach 2 / S = 12.
- **evolvability.** Guardrail 11 makes breaking changes codemod-first with a measured dry run, and this dry run misreports what is automatable.
- **error-quality.** Each skipped site surfaces as an anonymous TS2339.
- **Reach.** 39 pre-7 repos upgrade through this tool on demand; 2/2 measured hit it.

## Rough idea (not a design)
Tooling, no public-shape change. Loop collect-and-apply until a pass rewrites 0 sites (re-typing between passes) and report only fixpoint skips. Alternatively, let the transitive walk pass through calls whose name is a live `Tag` method. Pin an interleaved chain in `codemod-canonical.test.ts`. The same loop is where the 6.0.0 rename and boolean-setter maps would go ([[F-B-605]]).
