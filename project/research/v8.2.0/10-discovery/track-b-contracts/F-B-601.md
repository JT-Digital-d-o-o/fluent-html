# PageResponse is a cast brand: deleting the #main-content setId compiles everywhere, and the next nav swaps the page into the clicked link

## Problem
The template says `reply.renderPage` demands the `Rooted<"main-content">` witness that `setId(layoutIds.mainContent)` stamps (layout.view.ts:278-279). It does not. `PageResponse` is `View & { readonly [pageResponse]: "layout" }` (:283) and `Layout` produces it with `as PageResponse` on both arms (:304, :309), so the brand certifies the cast, not the root. 8.1.0 shipped `Rooted<N>` for exactly this kind of check (`renderFragment` consumes it), but the full-page path never does.

Every app copies the cast: 16 layout functions in 14 canonical apps build `PageResponse` through 44 casts (including the vendored define-controller copy). Two apps already hand-wrote a second layout (website-sales-funnel-automation-system `AdminLayout`, everyframe `MarketingLayout`) whose authors had to remember the setId themselves.

## Evidence (executed)
`$R2 = <scratch>/wave1/B-reseed/r2`

- **Template scaffold** (wave0-2 teamapp, TS 6.0.3). Deleting the one `.setId(layoutIds.mainContent)` line: tsc exit 0, 0 errors over 163 program files (baseline identical); eslint on the file exit 0. `vitest --project unit`: 4 failed / 399 passed. The only guard is string-matching tests (`tests/view/layout.test.ts:138`).
- **Fleet** (`run-mut.sh`, each repo's own tsc). Removing all 18 `setId(layoutIds.mainContent)` sites leaves 15/15 canonical-era repos at 0 errors (baseline 0 in all 15).
- **Second layout only.** Removing the setId in wsfas `admin-layout.view.ts:265` or in everyframe `layout.view.ts:247`: tsc 0 errors in both. Caught only by hand-written tests (wsfas `tests/view/layout.test.ts` 2 failed; everyframe unit 12 failed of 630, base 0).
- **The contract lives in strings.** 161 `id="main-content"` assertion lines in 109 test files across 15 repos.
- **Runtime** (`rt/layout-rt.mjs`, Chromium; identical on htmx 4.0.0-beta6 and 4.0.0):

| scenario | #main-content after clicks | h1 count | console |
|---|---|---|---|
| every layout unrooted | 0, 0 | 2, 3 | 2x `htmx: '#main-content' on hx-target did not match any element` |
| second layout unrooted, then nav | 0, 1, 1 | 1, 2, 2 | 1 warning; the response lands inside the clicked anchor, URL still pushed |
| rooted control | 1, 1, 1 | 1, 1, 1 | 0 |

- **Prototype** (`tpl-proto`). `asPageResponse(mainContent, answer)`, whose parameter is `[M] extends [Rooted<"main-content">] ? M : M & "the #main-content root is missing: end the swap root with .setId(layoutIds.mainContent)"`, replaces both casts in `Layout`. Baseline: 0 errors, unit 403/403. Mutant: 1 error.

```
src/core/layout/layout.view.ts(234,25): error TS2345: Argument of type 'Tag' is not assignable to parameter of type 'Tag & "the #main-content root is missing: end the swap root with .setId(layoutIds.mainContent)"'.
```
The fix starts at char 128 of the 160-char line 1.

## Why it matters
impact 2 x pain 2 x reach 2 / S = 8.
- **invariant-safety.** The cross-file invariant every full-layout swap verb depends on is enforced by 161 copy-pasted string assertions, not by the type the comment claims.
- **silent-failure.** tsc and lint stay green on the broken layout. The symptom is a page nested inside a link plus one console warning.
- **Reach.** 15/15 canonical apps carry the cast; 2/15 have already written a second layout by hand.

## Rough idea (not a design)
Type layer, template-owned and additive. Export one checked constructor (a `pageResponse(main, answer)` gate) whose parameter requires `Rooted<"main-content">` with a message-literal fallback, and use it in `Layout` and every app layout. The 44 casts and the false comment go; the string tests stop being the only guard (keep one render test). No lib change: `Rooted` already ships.
