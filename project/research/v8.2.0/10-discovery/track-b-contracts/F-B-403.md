# The widened-Id gate exists in a test file, not on the sinks

## Problem
Commit 9d86871 lists a "`renderFragment`-style widened-Id gate: `string extends N` rejects a widened `Id`, which previously disabled the root check silently". In the lib it is a `declare function renderFragmentGated` inside `test/types/type-surface.test-d.ts:655`; nothing shipped uses it, and the CHANGELOG does not mention it. The shipped consumers are the template's `reply.renderFragment<N>(id: Id<N>, view: RootedView<NoInfer<N>>)` (`core/server/types.ts:71`) and the `.fragment`/`.search` verbs (`swap-verbs.ts:130-156`). A bare `Id` (the default `Id<string>`) infers `N = string`, `RootedView<string>` and `FragmentRoute<string>` accept any root or any fragment route, and the contract turns itself off. The template documents this in JSDoc prose (`types.ts:68-70`, `swap-verbs.ts:57-66`) instead of gating it.

The lib's own widening gates use the other idiom and name nothing: the exhaustive forms of `Match`, `MatchValue` and `whenMatch` reject a widened `string` with

```
m/m5-widened.ts(3,24): error TS2345: Argument of type 'string' is not assignable to parameter of type 'never'.
```

(3/3 identical, 110 chars; the fix, "add a default", appears nowhere).

Prototype gate (`id: string extends N ? "renderFragment needs a narrow Id (ids.userCount), not a widened Id: type the prop Id<N> ..." : Id<N>`, same on `.fragment`): lines 20, 21 and 25 (inside `Refresh`, where the mistake is) fail with the message as the parameter type, e.g. `error TS2345: Argument of type 'Id<string>' is not assignable to parameter of type '".fragment needs a narrow Id (ids.userCount), not a widened Id: type the prop Id<N>"'.`; lines 15-16 keep their ordinary id-naming errors. Collateral: 4 internal sites need a cast (`swap-verbs.ts:317` implementation, `define-controller.ts:385` materialization, `server.ts:180` decorator, `tests/unit/define-controller.test.ts:22`).

Fleet (TypeChecker census over each app's tsconfig, 14 8.1.0 apps, template-vendored `src/core` and tests excluded): `.fragment` 261, `renderFragment` 143, `.search` (targeted) 12, `Partial` 9 = 425 Id-sink arguments, 0 widened; `.setId` 331, 30 widened (`Id<string>`, e.g. the template-vendored `account.components.ts` `id: Id` prop in 12 apps). AST census: 72 bare `Id` annotations (props, return types of `createId` helpers) in 14 repos, each one a place a widened id can enter a sink. `workshop-toni` (7.0.0, pre-generic `Id`) excluded.

## Why it matters
impact 2 x pain 2 x reach 1 / M = 2. Invariant safety: the swap contract's one silent hole has 0 hits today but 72 entry points, and the only record of the gate is a test fixture. Decision closure: the repo has two widening-gate idioms, one of which (`never`) never names its fix.

## Rough idea (not a design)
Type layer: one idiom for every widening site, the `renderFragmentGated` shape (a conditional parameter that becomes a message literal naming the fix). Template: `renderFragment`, `.fragment`, targeted `.search`. Lib: the three `never` gates (`conditionals.ts:142`, `match-value.ts:22`, `tag.ts:353`) get a message such as "a widened string needs the partial form: pass a default". Deletes the JSDoc hole descriptions at `types.ts:68-70` and part of `swap-verbs.ts:57-66`. Record the gate in the CHANGELOG.
