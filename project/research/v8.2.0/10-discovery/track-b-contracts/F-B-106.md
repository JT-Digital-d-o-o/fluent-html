# Root-mismatch errors never name the fix, and two teachings disagree on what the fix is

($B1 = <scratch>/wave1/B1)

## Problem

`Rooted<N>` survives the control-flow primitives as designed (probes: chaining, `.apply`, `.when`, un-annotated
components, `IfThenElse`/`Match` with every arm rooted all compile; `ForEach` at the root, `IfThen`, a missing
`setId` all fail). The failures are correct but unreadable. Verbatim first diagnostics at
`reply.renderFragment(ids.teamCount, …)`:

- `IfThen(n > 0, () => Span(…).setId(ids.teamCount))`:
  `Argument of type '"" | (Tag & Rooted<"team-count">)' is not assignable to parameter of type 'RootedView<"team-count">'. / Type 'string' is not assignable to type 'RootedView<"team-count">'.`
- component annotated `: View`: `Argument of type 'View' is not assignable … / Type 'string' is not assignable to type 'RootedView<"team-count">'.`
- component annotated `: Tag`: 4 lines ending `Property '[__rootIdBrand]' is missing in type 'Tag' but required in type 'Rooted<"team-count">'.`
- `IfThenElse`/`Match` with one arm rooted at `#team-list`: 7 lines; RootedView distributes over View into
  `(Rooted<…> & string) | (Rooted<…> & Tag) | (Rooted<…> & View[])` on line 3; the id pair sits on line 7.

No message names `setId`, `IfThenElse`, or the annotation. The teaching is split: the lib JSDoc says annotate
`RootedView<N>` (ids.ts:53-55); the guidelines say never annotate (views.md:102, CLAUDE.md:366) and spend
25 lines teaching the reader to decode `Type 'string' is not assignable` as "someone annotated the view".

## Evidence (executed)

1. **Probes** (tsc 6.0.3, one fixture each, first diagnostic only):

   | Shape | Lines | Chars | Names a fix |
   |---|---|---|---|
   | r04 `: View` annotation | 2 | 215 | no |
   | r10 `: Tag` annotation | 4 | 456 | no |
   | r03 `IfThen` "" arm | 2 | 235 | no |
   | r05 `IfThenElse` wrong arm | 7 | 774 | no (ids on line 7) |
   | r09 `Match` wrong branch | 7 | 777 | no (ids on line 7) |

2. **Fleet** (regex over exported PascalCase functions in 16 canonical repos whose return chain ends in
   `.setId(xIds.y)`): 215 rooted components; 209 un-annotated, **0 annotated `RootedView`**, **6 annotated
   `: Tag`** (all gzs/stem-50: ThresholdsForm, WeightsForm, CriterionForm, PasswordCard, ScoreForm, SubmitGate),
   which erase the brand the same way `: View` does; the guideline warns only about `: View`.
3. **Prototype** (`$B1/proto-rf`, template copy): `renderFragment<N, V>(id: …, view: [V] extends [Rooted<NoInfer<N>>] ? V : NotRootedAt<NoInfer<N>>)`
   where `NotRootedAt<N>` is a template-literal sentence. First line now carries the fix in 5/5 shapes, e.g.
   r10: 1 line / 334 chars: `…is not assignable to parameter of type '"view is not rooted at #team-count: end its root chain with .setId(ids.x) for #team-count; a View/Tag return annotation erases that (annotate RootedView<\"team-count\">), and IfThen can render \"\" (use IfThenElse)"'`.
   Caveat measured: for the union shapes (r05, r09) the 2-line message loses the offending `#team-list`, so a
   design must keep the ordinary mismatch path for a union of rooted arms. Template app calls: 4/4 compile
   unchanged (the 3 internal errors come from the id-gate half, see [[F-B-102]]).

## Why it matters

impact 2 (each wrong guess costs a round trip with a message that points at `string`) x pain 2 x reach 2
(6 live erasing annotations; the prose exists because the message fails). Hurts error-quality and
decision-closure (annotate vs never annotate).

## Rough idea (not a design)

Type layer: a fluent-html-exported helper for consumer parameters that turns a missing brand into a sentence
naming `setId`, `IfThenElse` and the annotation, falling through to today's mismatch error when every arm is
rooted at some id. Deletes views.md:102-110, fastify.md:209-223 and CLAUDE.md:366 (25 lines) and settles the
annotate question in one place (the JSDoc at ids.ts:40-68 shrinks with it).
