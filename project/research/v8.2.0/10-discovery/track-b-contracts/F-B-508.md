# The palette opt-out is type-tested only when publishing

## Problem
`FluentColorConfig { defaultPalette: false }` switches the Tailwind palette off so `.bg("gray-100")` becomes a
compile error. Module augmentation is global, so its type test lives in a separate project
(`test/types/color-optout`) that the root `tsc` excludes. That project is compiled by `npm test` only.
CI (`test.yml`) runs `tsc --noEmit` on the root project and `npm run test:coverage`, which does not include it.
The opt-out is the configuration every template-derived app ships with, so its guard runs at `npm pack`
(`prepack`) and nowhere else.

## Evidence (executed)
`$B5 = <scratch>/wave1/B5`

Mutation in a scratch copy (`$B5/mutoptout`): `FluentColorConfig extends { defaultPalette: false }` changed to
a condition that never matches (palette always on).
```
== CI step: npx tsc --noEmit (root)
exit 0
== npm test-only step: tsc -p test/types/color-optout
color-optout.test-d.ts(33,1): error TS2578: Unused '@ts-expect-error' directive.
color-optout.test-d.ts(35,1): error TS2578: Unused '@ts-expect-error' directive.
color-optout.test-d.ts(37,1): error TS2578: Unused '@ts-expect-error' directive.
color-optout.test-d.ts(39,1): error TS2578: Unused '@ts-expect-error' directive.
```
`grep -n "color-optout" .github/workflows/*.yml` -> 0 hits; `package.json:65` (`test`) contains the step,
`:66` (`test:coverage`, the CI script) does not. Fleet reach: ripgrep for `defaultPalette: false` over
`<org-root>` (node_modules and .claude excluded) -> 15 repos outside the lib: competify,
competition, everyframe, everyframe-composer, fl-um, fluent-html-home-page, gzs/stem-50, na-cent, popri,
projects-template, sportoawards, stojnica, studio, test/kjkljkl, website-sales-funnel-automation-system.
Recon 02 probe #5 records the opt-out as the template default.

## Why it matters
reach 3 (15 repos), impact 2 (the rule "never write a palette literal" is enforced
only by this arm), pain 2 (a regression is invisible until publish, then blocks the release instead of the
PR). Dims: verification-loop, invariant-safety.

## Rough idea (not a design)
CI layer: add `tsc -p test/types/color-optout/tsconfig.json` to `test.yml` (or fold it into
`test:coverage`). Same for any future augmentation-scoped type project. No prose involved.
