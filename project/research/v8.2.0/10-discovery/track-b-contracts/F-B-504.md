# A typo'd overlay position becomes overlay content

## Problem
`overlay(position: OverlayPosition, ...content: View[])` and `overlay(...content: View[])`. `View` includes
`string`, so any string that is not one of the 9 positions resolves to the second overload and is rendered as
text. The closed union rejects nothing: its typo protection is absorbed by the sibling overload, at compile
time and at runtime alike.

## Evidence (executed)
`$B5 = <scratch>/wave1/B5`

Compile: `Div("card").overlay("top-rigth", Span("3"))` in `$B5/probe/probe.ts` produces no diagnostic on that
line (tsc --strict, dist 8.1.0).
Render (`$B5/probe/render.mjs`, dist 8.1.0):
```
typo    : <div class="relative"><div>card</div>
<div class="absolute top-1/2 left-1/2 -translate-x-1/2 -translate-y-1/2 z-10">top-rigth
<span>3</span></div></div>
correct : <div class="relative"><div>card</div>
<div class="absolute top-0 right-0 z-10"><span>3</span></div></div>
```
Scan (`$B5/overloads.mjs`): for every exported class, every method with 2+ signatures, every argument index
0-2, flag a closed string-literal parameter type where a sibling signature accepts `string`. Result: 1 hit,
`Tag.overlay arg0: OverlayPosition <- absorbed by View`. Exported functions (`overloads-fn.mjs`): 0 hits.
Pins (`$B5/mutate.mjs`): widening `OverlayPosition` -> 0 TS2578; `never` -> 0 errors (no test calls
`.overlay` with a position under type check). Fleet: all 10 census hits for `.overlay(` are `VideoStream`,
ffmpeg-SDK and Python-string receivers (renderbox, everyframe, varnoska, renderbox-sdk, home-page); 0 fluent
call sites.

## Why it matters
reach 1 (0 real sites; the method is taught in its own JSDoc), impact 2 (a visible stray word in the UI plus
a wrong position), pain 2 (clean on tsc and at render). Dims: silent-failure, invariant-safety.

## Rough idea (not a design)
Type layer: narrow the content overload so its first argument is `Exclude<View, string>` (a string first
argument then has to be a position), pin one typo and one position in `type-surface.test-d.ts`. With 0 real
call sites, Track C may prefer pruning `.overlay` outright.
