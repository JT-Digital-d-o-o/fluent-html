# A missing DU Match case still buries its fix on the last of 7 lines

## Problem
The seed (scorecard: "actionable line is last of 8") re-measured on 8.1.0. `Match(s, "status", { loading, error })` with `success` missing:

```
m/m1-missing-du.ts(7,18): error TS2769: No overload matches this call.
  Overload 1 of 4, '(value: string | number, cases: Partial<{ [x: string]: Thunk<View>; [x: number]: Thunk<View>; }> & NoExtraCases<string, string | number>, defaultView: Thunk<...>): View', gave the following error.
    Argument of type 'State' is not assignable to parameter of type 'string | number'.
      Type '{ status: "loading"; }' is not assignable to type 'string | number'.
  Overload 2 of 4, '(value: State, key: "status", cases: { loading: ...; error: ...; success: ...; } & NoExtraCases<...>): View', gave the following error.
    Argument of type '{ loading: () => Tag; error: (x: ...) => Tag; }' is not assignable to parameter of type '{ ... } & NoExtraCases<...>'.
      Property 'success' is missing in type '{ loading: () => Tag; ... }' but required in type '{ ... }'.
```

The first candidate shown is the value+default overload: a DU call with 3 arguments matches its arity, so tsc reports 2 failing candidates instead of 1. The model reads 385 chars about `string | number` before the only sentence that names the fix. At runtime the missing state renders the region empty.

impact 2 x pain 2 x reach 3 / M = 6. Error quality and context economy: the fix is present but costs ~1.1 KB of reading, and 8.1.0 moved it further down. The value form proves the short shape is reachable: one candidate gives a 2-line error.

## Rough idea (not a design)
Type layer: restructure the overload set so a DU call has exactly one arity-matching candidate (for example one DU signature with an optional default whose exhaustiveness is conditional on the default's presence), keeping `NoExtraCases` in `C`'s constraint (3e22e25's contextual-typing trap: the six narrowing tests in `type-surface.test-d.ts` must stay green). Pin the first diagnostic line in a probe test like `test/brand-errors.test.ts`.
