# Branded route sinks reject a raw path naming only 'ResolvedRoute | ExternalHref', and lint's autofix writes that error

## Problem

The 8.0.0 brand works: a raw path into a route sink fails to compile. The message names the brand, not the three producers that satisfy it (`routes.x.resolve()` / a route callable, `externalUrl(u)`, `assetUrl(p)`), which live in JSDoc at src/htmx.ts:20-32. The pure prior hits it on its first file: both pure-prior runs wrote `hx("/team/members", ...)` (recon 02 D2).

The eslint plugin then points the other way. `prefer-set-method` (error level in the template) reports `addAttribute("href", "/team")` as `Use .setHref("/team") instead...` and its autofix writes exactly that, which tsc rejects. The lint rule names a fix the compiler refuses.

s.ts(9,37): error TS2345: Argument of type 'string' is not assignable to parameter of type 'ResolvedRoute | ExternalHref | undefined'.

## Why it matters

impact 2 x pain 2 x reach 3 / effort S. Reach: every pure-prior run (2/2) and every pre-7 repo that upgrades: 552 `hx("...")` literal sites in 13 pre-7 repos each become this message, and 8.0.0 shipped no codemod for the brand (CHANGELOG.md:137). The lint/type disagreement is a decision-closure hole: two enforcement layers name opposite fixes.

## Rough idea (not a design)

Type layer: one shared message member on the 5 branded sinks (additive widening; the literal cannot carry user input, so the open-redirect guarantee is unchanged; S-03/L-428 untouched). Lint: `prefer-set-method` stops autofixing `href` (report with the producer names instead), per S-25's hand-edit bar.
