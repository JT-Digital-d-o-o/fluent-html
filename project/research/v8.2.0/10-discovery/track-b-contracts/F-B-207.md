# addAttribute('id'|'class'|'style') compiles and is dropped at render when the typed setter is also used

## Problem

`addAttribute` accepts the three keys that have dedicated storage. 6.0.1 chose runtime precedence (dedicated field wins) and parked the compile-time block (L-066). Recon 02 measured the consequence: `Div("x").p("4").addAttribute("class","mt-7")` renders `<div class="p-4">`; clean on tsc and eslint for class and id, extractor-invisible, no dev warning. Only `style` gets a lint (`prefer-set-method`).

## Evidence (executed)

`$B2 = <scratch>/wave1/B2`.

Census (recon-01 dedup corpus):

| key | canonical-era | pre-7 |
|---|---|---|
| `addAttribute("id", ...)` | 0 | 17 in 3 repos (15 literal values) |
| `addAttribute("class", ...)` | 0 | 0 |
| `addAttribute("style", ...)` | 0 | 109 in 20 repos (102 literal values) |
| pure-prior runs (pp1, pp2) | 0 and 0 (they used setId/addClass) | - |

Prototype (tag.d.ts copy):

```ts
addAttribute<const K extends string>(key: K extends "id" ? "addAttribute('id') is dropped when .setId() is also used: call .setId(ids.x)" : K extends "class" ? "addAttribute('class') is dropped when any typed class is set: use the typed methods (.p('4')) or .cssClass(name)" : K extends "style" ? "addAttribute('style') is dropped when .setStyle() is also used: call .setStyle(css) or .setStyles({ ... })" : K, value: string): this;
```

Before: p16-p18 compile. After:

```
p16-addattr-id.ts(2,43): error TS2345: Argument of type '"id"' is not assignable to parameter of type '"addAttribute('id') is dropped when .setId() is also used: call .setId(ids.x)"'.
p17-addattr-class.ts(2,43): error TS2345: Argument of type '"class"' is not assignable to parameter of type '"addAttribute('class') is dropped when any typed class is set: use the typed methods (.p('4')) or .cssClass(name)"'.
p18-addattr-style.ts(2,43): error TS2345: Argument of type '"style"' is not assignable to parameter of type '"addAttribute('style') is dropped when .setStyle() is also used: call .setStyle(css) or .setStyles({ ... })"'.
```

Still compiling: `addAttribute(k, v)` with `k: string`, `"data-testid"`, `"aria-label"`, `"hx-headers:inherited"` (template core/behaviors/runtime.ts:124). Scaffold, fl-um/na-cent/competify (10 addAttribute sites) and the lib's type-surface test: 0 new errors.

## Why it matters

impact 2 x pain 3 x reach 1 / effort S. Pain 3: the drop is silent on all 5 layers for class and id. Reach 1: 0 canonical-era sites and 0 pure-prior guesses, so the break costs nothing in the canonical fleet and the codemod applies only to pre-7 repos.

## Rough idea (not a design)

Type layer, 9.0.0 (semver-breaking even at 0 canonical sites). Not the rejected runtime throws (L-120, L-123): this is the compile-time block L-123 itself called the right long-term answer. Codemod: `addAttribute("id", x)` -> `.setId(x)`, `addAttribute("style", s)` -> `.setStyle(s)`, with a receiver check that merges when the chain already calls `setStyle`.
