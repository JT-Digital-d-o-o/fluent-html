# Type tests pin that an error exists, never what it says

## Problem
Every `@ts-expect-error` directive proves a line fails; none proves the failure is readable. The library
therefore has no way to notice when a contract's error degrades, and 12 existing contracts already fail with
text that names only `never` or `undefined`. In each of those 12 the test author wrote the fix into the
directive comment, where tsc never shows it. The discriminated `Match` missing-case (the B2 seed) is not
pinned at all.

## Evidence (executed)
`$B5 = <scratch>/wave1/B5`

`node $B5/strip-expect.mjs`: strips all directives from the compiled test set (root tsconfig + color-optout)
in memory and records the diagnostic that satisfies each.
```
directives: 155 by first code: { 2322: 25, 2339: 6, 2345: 99, 2353: 6, 2542: 1, 2554: 2, 2561: 4, 2769: 8, 2820: 4 }
diagnostic > 2 lines: 18
anonymous (never/undefined) satisfied directives: 12 of 155
```
The 12, with the fix the test comment states vs the text tsc prints:

| directive | comment (the fix) | diagnostic |
|---|---|---|
| routes.ts:712, :724 | only GET routes may declare a sitemap stance | `Type '"post"' is not assignable to type 'never'.` |
| routes.ts:716 | a param'd route must use "dynamic" or "exclude" | `Type '"/x/:id"' is not assignable to type 'never'.` |
| routes.ts:720 | a paramless route is one URL; use true | `Type '"/x"' is not assignable to type 'never'.` |
| type-safety.ts:448 | a wildcard route takes no declared params | `Type '"string"' is not assignable to type 'never'.` |
| type-surface.test-d.ts:86 | "ic" is not a :param in "/u/:id" | `Type '"number"' is not assignable to type 'never'.` |
| type-surface.test-d.ts:479 | a case key that is not in the union | `Type '() => Tag' is not assignable to type 'never'.` |
| type-safety.ts:531, :550, :588 | widened string needs a default (Match/whenMatch/MatchValue) | `Argument of type 'string' is not assignable to parameter of type 'never'.` |
| type-safety.ts:91, :94 | text input rejects min/step | `Argument of type '5' is not assignable to parameter of type 'undefined'.` |

Text-pinned diagnostics: `setter-errors.test.ts` (12 probe lines, asserts codes + message fragments) and
`brand-errors.test.ts` (5 lines, asserts `/not assignable to parameter of type 'ResolvedRoute/`): 17 total.

Discriminated `Match` missing case (`$B5/probe/match.ts`, dist 8.1.0):
```
match.ts(4,18): error TS2769: No overload matches this call.
  Overload 1 of 4, '(value: string | number, cases: Partial<…> & NoExtraCases<string, string | number>, …)', gave the following error.
    Argument of type 'State' is not assignable to parameter of type 'string | number'.
  …
      Property 'success' is missing in type '{ loading: () => Tag; error: … }' but required in type '{ loading: …; error: …; success: … }'.
diag lines 7 chars 1425 actionable at char 1116
```
8 directives call `Match(`/`whenMatch(`: the scalar missing case (`type-surface.test-d.ts:477`, 2 lines, names
`closed`), the `whenMatch` missing case, typo key, narrowing, return type, rooted branches, widened string.
0 cover a discriminated missing case.

Feasibility of text that names the fix:
- The lib already pins one message-literal gate: `renderFragmentGated` (`type-surface.test-d.ts:655-666`),
  whose error text is the instruction itself.
- A message-parameter tombstone names a pruned method's successor on line 1 (`$B5/probe/pruned2.ts`):
  `Argument of type '"center"' is not assignable to parameter of type '"placeItems was removed in 8.0.0: use .items("center").justify("center")"'`.
  A string-literal property tombstone does not work: TS2349 prints `Type 'String' has no call signatures`.
- The route checks cannot carry a message through the current mechanism: they intersect the inferred
  definitions with a check type, and an intersection of two distinct literals is `never`. Replacing `never`
  in `AllowedStance` with a message literal still prints `not assignable to type 'never'` (scratch copy
  `$B5/proto`, and `$B5/probe/gate2.ts`). The fix needs a non-intersecting gate, the B4 inference question.

## Why it matters
reach 3 (`defineRoutes` 1419 fleet sites and `Match` 353, each in 19/19 canonical repos, recon 01 §2.5),
impact 2, pain 3 (4/4 in-repo agents reached tsc, recon 02 §1.2, while the fix text sits in test comments
that the npm package never ships: `package.json` `files` = `dist/src/**` + `src/**/*.ts`). Dims: error-quality, verification-loop.

## Rough idea (not a design)
Type layer + test harness: generalize `setter-errors.test.ts` into one diagnostic-snapshot suite that asserts,
per contract, the code and that line 1 contains the fix keyword (route callable, `"dynamic"`, the missing case
name, the successor). Then convert the 12 never-gates to message gates (non-intersecting formulation) and the
test comments become redundant. Guideline prose that restates these rules (sitemap stance, splat params,
Match defaults) is deletable once the text is pinned.
