# Deleted behavior verbs fail without naming their successor

## Problem
Six behavior verbs were deleted (6.4.0 and earlier) and each has a named successor. The compiler knows none of
this: a deleted name fails exactly like a typo, with a message that names the type alias `keyof BehaviorMap`
(not even its 10 members). The mapping lives in two guideline paragraphs, and this repo's own `CLAUDE.md:316`
still presents `openDialog` as a kept legacy path. `BehaviorName`'s closure itself is unpinned: widening it
leaves every test green.

## Evidence (executed)
`$B5 = <scratch>/wave1/B5`

Today (`$B5/probe/beh.ts`, dist 8.1.0):
```
beh.ts(4,19): error TS2345: Argument of type '"disable"' is not assignable to parameter of type 'keyof BehaviorMap'.
beh.ts(5,19): error TS2345: Argument of type '"openDialog"' is not assignable to parameter of type 'keyof BehaviorMap'.
beh.ts(6,19): error TS2345: Argument of type '"dismissOnEscape"' is not assignable to parameter of type 'keyof BehaviorMap'.
```
Gate prototype in the same file (message literals abbreviated):
```ts
type Removed = { disable: "removed in 6.4.0: use the route option `{ disable: … }` (emits hx-disable)"; openDialog: "removed in 6.4.0: use Button().setCommand(…show-modal…)…"; dismissOnEscape: "removed in 6.4.0: use .behavior(…onEscape…)" };
declare function behavior<K extends BehaviorName | keyof Removed>(name: K extends keyof Removed ? Removed[K] : K, ...args: …): void;
```
```
beh.ts(13,10): error TS2345: Argument of type '"disable"' is not assignable to parameter of type '"removed in 6.4.0: use the route option `{ disable: … }` (emits hx-disable)"'.
beh.ts(14,10): error TS2345: Argument of type '"openDialog"' is not assignable to parameter of type '"removed in 6.4.0: use Button().setCommand(<show-modal>).setCommandfor(ids.dialog)"'.
beh.ts(15,10): error TS2345: Argument of type '"dismissOnEscape"' is not assignable to parameter of type '"removed in 6.4.0: use .behavior(<onEscape>, …)"'.
```
(Lines 14-15 abbreviated: the message literals' inner quotes are shown as <…>.) `behavior("toggle", { target })` and `behavior("back")` compile unchanged (0 diagnostics on lines 16-17).

Pins (`$B5/mutate.mjs`): widening `BehaviorName` with `(string & {})` -> 0 unused directives (no test rejects
any verb name at the type level); replacing it with `never` -> 31 errors in `behavior.test.ts` and
`security.test.ts` (accept direction pinned).

Fleet (ripgrep for `.behavior(` with any of openDialog, closeDialog, disable, formResetOnSwap, dismissOnEscape, scrollTo,
node_modules/.claude/dist excluded): 36 call sites, all `.behavior("disable")`, in 11 pre-7 repos (jt-vault-cloud 9,
redaction-renderbox 8, glimm 6, jt-i18n 5, planet-positive-sport 2, jt-draw, ttl, varnoska, storysell-ai,
tetstesttes, business-helper 1 each). Each is a compile error with no successor on upgrade to 8.x.

## Why it matters
reach 2 (36 sites / 11 repos on the upgrade path; `.behavior` 808 fleet sites), impact 2, pain 2 (the fix is
one guideline lookup away, and a blind agent does not have the guidelines, recon 02 §1.2). Dims: error-quality,
context-economy (two prose paragraphs exist only to carry this map), prior-alignment.

## Rough idea (not a design)
Type layer: the removed-verb gate above on `Tag.behavior` (keeps `jt:` augmentation, since `BehaviorName` is
still `keyof BehaviorMap`), a text-asserting probe per removed verb, and a type test that rejects one typo.
Deletes the "Deleted → successors" clause in `guidelines/web-development/CLAUDE.md:330` and the list in
`htmx.md:570` (guideline delta about -2 lines), and the stale `fluent-html/CLAUDE.md:316` example.
