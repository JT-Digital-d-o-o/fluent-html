# The fragment verbs' stance check has an undeclared-arm escape

($B1 = <scratch>/wave1/B1)

## Problem

`.fragment`, `.poll` and targeted `.search` reject a route that declares no `render` (the template's
`DeclaresNothing` sentence). Put that route in a conditional with a declared one and the check disappears:

```ts
Button("x").fragment(ids.teamList, cond ? routes.list() : routes.index());   // compiles
Button("x").fragment(ids.teamList, cond ? routes.index() : routes.list());   // compiles too
```

The template comment (swap-verbs.ts:93-94) blames first-member inference; measured, the order does not matter.
The cause is that `render` is optional on the bag (routes.ts:309), so inference of `S` from
`RenderTagged<Id<"team-list">> | RenderTagged<undefined>` drops the `undefined` and `NeedsStance<S>` sees a
declared stance. A declared `"page"` or `"none"` arm is still rejected (q04, q05), so the escape is exactly the
silent route, and silence is how the fleet writes pages.

## Evidence (executed)

1. **tsc** (tsc 6.0.3, one fixture each): q02 fragment frag-first **0 errors**, q03 page-first **0**, q06
   `.poll(cond ? list() : index())` **0**, q07 `.search(ids.teamList, cond ? …)` **0**; controls: q04 `render: "page"`
   arm 1 error, q05 `"none"` arm 1, q08 `.nav(cond ? index() : list())` 1, q09 wrong-id arm 1 (7 lines naming both ids).
2. **Chromium** (`$B1/rt/browser.mjs` S3; `cond=false` renders `hx-get="/b1" hx-target="#team-list" hx-swap="outerMorph"`,
   the page route answers the Layout htmx branch `<title>` + `#main-content`): `#main-content` count **1 -> 2**,
   `#team-list` replaced, on beta6 and 4.0.0. Sibling S4: `.nav(hx(routes.list.resolve()))` (bare HTMX, q10
   compiles 2/2) replaces `#main-content` with the fragment: count 1 -> 0, the next `.nav` logs
   `htmx: '#main-content' on hx-target did not match any element` (pinned as a known hole at
   type-surface.test-d.ts:563-568).
3. **Census** (regex, 15 repos pinned 8.1.0, app-authored): 1324 route defs; `render: xIds.y` 281, `render: "none"`
   158, **`render: "page"` 0**, undeclared 885 (66.8%). Live escape shapes: 1 ternary route argument at a verb
   (everyframe-composer projects.components.ts:378, `.nav`, correctly checked), 0 at fragment/poll/search; 0
   `.verb(hx(` sites.
4. **Fix prototypes**:
   - naive, required `render` on declared bags (`[S] extends [undefined] ? {render?: undefined} : {render: S}`):
     closes 4/4, but lib tsc 6 errors (5 type-surface pins of `RenderTagged<"page" | undefined>` + 1 overload)
     and template tsc 80 errors until `PageRoute` becomes `RenderTagged<"page"> | RenderTagged<undefined>`
     (then 0): breaking for the 15 fleet `PageRoute` aliases.
   - additive, a phantom key on declared stances only
     (`& (S extends undefined ? {} : { readonly [__declaredStance]: S })`): lib `npx tsc --noEmit -p tsconfig.json`
     **0 errors**; template full tsc **0 errors** with `PageRoute` untouched; q02/q03/q06/q07 now 1 error each
     (3 lines: `Property '[__declaredStance]' is missing in type 'RenderTagged<undefined>'`); q10 still compiles.

## Why it matters

impact 3 (a whole page lands inside a fragment slot, duplicating `#main-content`) x pain 2 (compiles, lints,
renders; visible only after the swap) x reach 1 (0 live instances; the shape is one ternary away in any list
filter). Also a decision-closure gap: the lib says `undefined` means "not yet declared" (routes.ts:114), the
template says it means "a page" (swap-verbs.ts:38-40, define-controller.ts:53-54), and 0/1324 defs declare `"page"`.

## Rough idea (not a design)

Type layer, lib-side and additive: the phantom stance key above, demanded by the fragment verbs. Settle the
meaning of silence in one sentence (routes.ts:114-116 or the template JSDoc, not both). Deletes the escape caveat
at swap-verbs.ts:93-96.
