# Nothing diffs diagnostic text across releases

## Problem
[[F-B-401]] (8.1.0's `NoExtraCases` replaced `Did you mean` with `not assignable to type 'never'`) came out of a single angle. No instrument in the repo would have caught it:
- `test/types` pins that errors exist, not what they say ([[F-B-502]]);
- the critic replayed recon-02's 30 lib-only fixtures on 8.0.0 and 8.1.0 and found 0 changed first diagnostics;
- CI (`test.yml`) runs no step that reads a diagnostic.

A release can lose a key name from the one message an agent reads, and no check goes red.

## Evidence (executed)
`$R2 = <scratch>/wave1/B-reseed/r2`.

`xver/gen.py` writes 58 one-line wrong-guess probes:
- Match (11 shapes: typo'd, missing and stale extra key, wrong discriminant, widened value; value and DU forms, with and without default), MatchValue 5, whenMatch 5;
- IfThen/IfThenElse 3, ForEach/ForEachKeyed 3, Form<T> 4;
- defineRoutes and route callables 8, defineIds 1;
- setters, variants, behaviors and hx options 14; hxResponse 4.

Each compiles with TS 6.0.3 against 7.0.1, 8.0.0 and 8.1.0. A valid control compiles on all three.

| transition | first diagnostics changed | lost key name or did-you-mean | grew |
|---|---|---|---|
| 7.0.1 -> 8.0.0 | 4 | 0 | 3 |
| 8.0.0 -> 8.1.0 | 17 | 4 | 9 |

**The 4 losses are all Match:**
- m01 value typo: TS2561 with `Did you mean`, 165 chars -> `TS2322 Type '() => Tag' is not assignable to type 'never'.`, 51 chars;
- m02 value typo with a default: the did-you-mean is lost;
- m04 DU typo with a default: TS2353 naming `okk` -> the same `never` line;
- m09 stale extra key: TS2353 naming `archived` -> `never`.

**Growth:**
- DU missing case 955 -> 1,110 chars (+16%);
- DU typo with a typed callback parameter 762 -> 885;
- value missing case 263 -> 305.

**Other findings from the sweep:**
- `Button().setHtmx(hx(routes.list(), { ... }))` changed from `Argument of type 'HTMX' is not assignable to parameter of type 'string'` (7.0.1) to `Argument of type 'RenderTagged<undefined>' is not assignable to parameter of type 'ResolvedRoute | ExternalHref'` (8.1.0). An internal phantom type now leads the message in 3/3 probes.
- 3 probes compile clean on all three builds: `A().setTarget('blank')`, `hxResponse(v).reswap('outerHtml')`, and a `:id` path with no `params` entry.
- On 8.1.0, 35 of 58 first diagnostics name the offending token, 6 do not, and 14 have no token to name.
- Recon-02's 33 standing fixtures hold one Match probe (p02, DU missing case), which is none of the 4 regressed shapes.

## Why it matters
impact 2 x pain 2 x reach 2 / S = 8. verification-loop and error-quality: any release that touches an overloaded export can degrade the message silently. F-B-401's regression alone reaches 50 value-form Match sites in 12 canonical repos.

## Rough idea (not a design)
CI layer, no public-shape change. Commit the matrix as golden first diagnostics per probe: code, offending token present, did-you-mean present, char count. Run it against the built d.ts in test.yml; fail on a lost token or did-you-mean and flag growth past a threshold. Every new type gate adds its own wrong-guess probe. This complements [[F-B-502]] (text pins inside test/types) and costs one tsc run per probe.
