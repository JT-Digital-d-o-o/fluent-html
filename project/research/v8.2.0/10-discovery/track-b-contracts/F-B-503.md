# HxSync's open tail admits typos that run the wrong request strategy

## Problem
`HxSync` is `'drop' | 'abort' | 'replace' | 'queue' | 'queue first' | 'queue last' | 'queue all' | (string & {})`.
The tail exists for the `<selector>:<strategy>` form, but it accepts any string, so a typo in the strategy
compiles, is emitted verbatim, and htmx falls back to `queue first` without a word. Guardrail 4 asks an open
union for a documented reason; the JSDoc (`src/htmx.ts:223-230`) lists the forms and gives none, and README,
REFERENCE (`:446-449`) and CHANGELOG mention no reason either.

## Evidence (executed)
`$B5 = <scratch>/wave1/B5`

`node $B5/sync-probe.mjs`: `Form(Input().setHtmx(hx(assetUrl("/slow"), { trigger: "go", sync, swap: "none" })))`
rendered from dist 8.1.0, three `go` events dispatched synchronously, server delays 300 ms.
```
beta6  "drop"                 requests reaching server: 1 | console: none
beta6  "dorp"                 requests reaching server: 2 | console: warning: htmx: 'dorp' on hx-sync did not match any element (x4)
beta6  "replcae"              requests reaching server: 2 | console: warning: htmx: 'replcae' on hx-sync did not match any element (x4)
beta6  "closest form:drop"    requests reaching server: 1 | console: none
beta6  "closest form:dorp"    requests reaching server: 2 | console: none
4.0.0  (identical counts and messages for all 7 values)
```
Mechanism, beta6 `htmx.js:708-713`: the strategy is `hxSync.split(":").pop()`, and anything not matching
`/^(drop|abort|replace|queue)/` becomes `"queue first"`; a bare typo is also read as a selector (`:717-722`),
hence the misleading "did not match any element" warning.

Closed alternative (`$B5/probe/sync-closed.ts`):
```ts
type SyncStrategy = "drop" | "abort" | "replace" | "queue" | "queue first" | "queue last" | "queue all";
type HxSyncClosed = SyncStrategy | `${string}:${SyncStrategy}`;
```
"drop", "queue all", "closest form:abort", "#other-form:drop", "this:replace" compile; output for the typos:
```
sync-closed.ts(4,7): error TS2322: Type '"dorp"' is not assignable to type 'HxSyncClosed'.
sync-closed.ts(5,7): error TS2322: Type '"closest form:dorp"' is not assignable to type 'HxSyncClosed'.
sync-closed.ts(6,7): error TS2820: Type '"replcae"' is not assignable to type 'HxSyncClosed'. Did you mean '"replace"'?
```
Pins today: widening is moot (already open); `$B5/close-open.mjs` shows closing the tail outright breaks exactly
1 test (`test/htmx.test.ts:98`, the selector form), which the template arm keeps compiling.
Fleet (ripgrep for `sync:` followed by a string literal, node_modules/.claude/dist excluded): every value found is valid under the closed
type: `"replace"` (the template `.search` verb in every 8.1 app, e.g. popri `src/core/htmx/swap-verbs.ts:344`,
plus gzs/stem-50 `thesis.sections.view.ts:114`), `"queue first"` (template tests), `"this:replace"`
(gzs/inovacije `library.view.ts:376`); 0 non-literal values.

## Why it matters
reach 2 (the `.search` verb emits it in every template-derived app; 2 app-authored sites), impact 2 (a typo
changes request concurrency: duplicate requests or lost aborts), pain 2 (0 console output for the selector
form). Dims: silent-failure, decision-closure, invariant-safety.

## Rough idea (not a design)
Type layer: the template-literal arm above, closing the union with no loss of expressiveness; pin one valid
selector form and one typo in `type-surface.test-d.ts`. Rejects only strings that already misbehave at runtime
(fleet dry run: 0 of the measured sites change), the same shape as the 6.1.1 sizing-union close (L-131).
