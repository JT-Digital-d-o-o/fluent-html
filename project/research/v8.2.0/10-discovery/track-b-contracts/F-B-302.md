# A raw route into a swap verb names no fix and renders garbage

`$B3` = `<scratch>/wave1/B3`.

## Problem

The verbs take a route callable's result. Every other shape an agent reaches for (a path string, the callable without `()`, `routes.x.resolve()`) fails with a diagnostic that names the parameter type and never the fix, and, once past tsc (a cast, JS, an `any`), renders an attribute htmx does not know.

## Evidence (executed)

tsc on the scaffolded template (6 probes, `$B3/tsc-b3-1.txt`):

| Probe | First diagnostic (verbatim, truncated) | Lines / chars |
|---|---|---|
| `A("Team").nav("/team")` | `TS2345 Argument of type 'string' is not assignable to parameter of type 'PageRoute'.` / `Type 'string' is not assignable to type 'HTMX'.` | 2 / 174 |
| `.nav(teamRoutes.index)` (uncalled) | `Argument of type '((options?: RouteHxOptionsFor<{ readonly method: "get"; ... }> \| undefined) => RenderTagged<...>) & RouteProperties<...>' is not assignable to parameter of type 'PageRoute'.` | 2 / 671 |
| `.nav(teamRoutes.index.resolve())` | `... 'ResolvedRoute' is not assignable to parameter of type 'PageRoute'.` / `... missing the following properties from type 'HTMX': endpoint, method` | 2 / 258 |
| `Form().submit("/team/invite")` | same as row 1 | 2 / 177 |
| `.fragment(ids.teamList, "/team/list")` | `... not assignable to parameter of type 'HTMX & { readonly render?: Id<"team-list"> ...` | 2 / 278 |
| `Input().search("/team/list")` | same as row 1 | 2 / 178 |

0/6 say "call the route". eslint (template config): 0 findings on the 6 files.

Runtime, `NODE_ENV=development` (dev checks on), 0 throws, 0 warnings:

- `.nav("/team")` -> `<a class="cursor-pointer" role="button" tabindex="0" hx-undefined="undefined" hx-target="#main-content" ...>`; same `hx-undefined` for `.resolve()`, `.submit`, `.fragment`, `.search`. Cause: the verb spreads a string (`{..."/team"}`), `_setHx` (`tag.ts:638-642`) stores it, `serialize.ts:140` writes `'hx-' + undefined`.
- `.nav(teamRoutes.index)` -> `hx-get="undefined"` (the callable carries `method` but no `endpoint`).

Chromium, lib `4.0.0-beta6` and template `4.0.0` (`$B3/browser-b3.json` S1): the 4 `hx-undefined` anchors/buttons/inputs: 0 requests, 0 console lines, nothing happens on click/input. The `hx-undefined` form: native submission, URL becomes `/start?` (a full reload). The uncalled callable: `GET /undefined` (404) and the address bar is pushed to `/undefined`.

Prototype (`$B3/hint/hint2.ts`, tsc --strict): parameter typed `{ readonly ["call the route: .nav(teamRoutes.index()); not a path string, .resolve(), or the uncalled callable"]?: never } & PageRoute`. The hint text starts at char 92 (string), 135 (uncalled callable), 99 (`.resolve()`) of line 1; `navD(teamRoutes.index())` compiles clean. The template already uses this device for the render-stance error (`swap-verbs.ts:81-83`).

## Why it matters

impact 2, pain 3 (the tsc text sends the agent to the `PageRoute`/`HTMX` declarations, and anything that slips past tsc is silent in the browser), reach 2: `.nav` is the most-used verb (1,012 8.x call sites, 2,475 verb sites in 8.x), and the pure prior writes raw route strings in 2/2 runs (recon 02 D2).

## Rough idea (not a design)

Type layer first (template, S-19): the inline hint intersection on `nav/tab/submit/search/onChange/fire` (and the fragment verbs' route arg). Runtime backstop (lib, 8.1.x: bytes change only for input that never worked): `_setHx` in dev throws when `method` is not one of the 5 `HxHttpMethod`s or `endpoint` is not a string, naming `routes.x()`. Lets the guideline lines that explain "verbs take a route callable" go.
