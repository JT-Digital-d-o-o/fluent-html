# hxResponse URL sinks bypass both the brand and the scheme filter

`$B3` = `<scratch>/wave1/B3`.

## Problem

8.0.0 branded the request-side route sinks and named "the open-redirect shape (`setHref(request.body.redirect)`)" as what the brand kills. The response-side redirect, the one htmx turns into `location.href = value`, was left as `redirect(url: string)` (`patterns.ts:264`), and its value is copied into the header verbatim: `sanitizeUrl` only runs on element attributes in `URL_ATTRS` (`serialize.ts:15`).

```ts
hxResponse(Empty()).redirect("javascript:alert(1)").pushUrl("javascript:x").location("//evil.test").getHeaders()
// {"HX-Redirect":"javascript:alert(1)","HX-Push-Url":"javascript:x","HX-Location":"//evil.test"}
// while Form().setAction("javascript:alert(1)") renders action="about:blank"
```

## Evidence (executed)

- tsc on the scaffolded template: `hxResponse(Empty()).redirect(request.query.next)`, `.redirect("/team")`, `.pushUrl(next)`, `.location(next)`: 0 errors. eslint (template config incl. `template/branded-redirect`): 0 findings. The same value into `reply.redirect(next)` (v11): `template/branded-redirect` error "reply.redirect() takes a ResolvedRoute ...". The rule gates on `isFastifyReplyReceiver` (`branded-redirect.mjs:61`).
- Chromium, a button posting to `/act` answered with `hxResponse(Empty()).redirect(x).getHeaders()` (`browser-b3.json` S4), lib `4.0.0-beta6` and template `4.0.0`:
  - `javascript:window.__pwned=1;void 0` -> `window.__pwned === 1` (script ran in the app's origin) on 2/2.
  - `https://evil.test/phish` -> navigates to evil.test on 2/2.
  - `//evil.test/x` (scheme-relative, passes any `startsWith("/")` check) -> navigates to `http://evil.test/x` on 2/2.
- Fleet (TS AST, dedup corpus): 18 call sites of the 4 URL methods in 12 repos (14 `redirect`, 3 `pushUrl`, 1 `replaceUrl`). The 8 sites in 8.x repos pass `externalUrl()` (3) or a `resolve()` result (5, incl. identifiers typed from `resolve()`), so a brand costs 0 edits there. Pre-7: 5 pass a `string`-typed identifier or member (e.g. `planet-positive-sport/src/auth/auth.controller.ts:965-967` `redirectAfterAuth(..., target: string)` fed `returnTo ?? "/"`, validated today by the app, not by any type).
- `test/brand-errors.test.ts:62` pins the open-redirect shape on `setHref` only; no test touches `HxResponse`.

## Why it matters

impact 3 (script execution or off-site redirect from a single unvalidated `next`/`returnTo`), pain 2 (the safe path, `reply.redirect`, is linted, so the unlinted twin is where a model that fights the lint ends up), reach 2 (12 repos use the sinks; every auth flow with a return target is a candidate). Hurts invariant-safety: the brand's stated purpose is not held on the sink htmx actually navigates with.

## Rough idea (not a design)

Runtime now (8.1.x, bytes change only for dangerous values): `getHeaders()` passes the four URL headers (and `HxLocationConfig.path`) through `sanitizeUrl`. Type next: `redirect/pushUrl/replaceUrl/location` take `ResolvedRoute | ExternalHref` (`"false"` stays a literal arm for push/replace); measured cost 0 in 8.x, 5 pre-7 sites for the codemod. Add the HX-Redirect shape to `brand-errors.test.ts`. Not the rejected URL-type framework (L-428): the existing brand and sanitizer, extended to 4 more sinks.
