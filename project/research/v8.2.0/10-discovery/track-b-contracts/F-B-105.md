# The root brand is never invalidated by a later id write

($B1 = <scratch>/wave1/B1)

## Problem

`setId` is `set*` (last write wins at runtime), but its brand is an intersection, so it accumulates:

- `Span("3").setId(ids.teamCount).setId(ids.teamList)` is `Tag & Rooted<"team-count"> & Rooted<"team-list">`,
  which TypeScript reduces to `never`. `never` is assignable to every parameter, so
  `reply.renderFragment(ids.teamCount, it)` and `reply.renderFragment(ids.teamList, it)` both compile. The only
  signal is a TS2339 if the chain continues (`.p("4")` -> `Property 'p' does not exist on type 'never'. The
  intersection … was reduced to 'never' because property '[__rootIdBrand]' has conflicting types`).
- `setId(ids.teamCount).setId(dynamicString)` keeps `Rooted<"team-count">`; the element renders `id="row-7"`.
- `.apply((t) => t.setId(ids.inviteForm))` and `.when(true, (t) => t.setId(ids.inviteForm))` return the outer
  `this`, so the brand stays `team-list` while the element renders `id="invite-form"`.

The template's `renderFragment` runtime ignores its id (server.ts:268 `_id: Id`), so nothing downstream checks.

## Evidence (executed)

1. **tsc** (r02, r08): shapes a, b, c of r02 and b, c of r08 compile (0 errors); only r02 d (chain after the
   double brand) fails, with the `never` reduction message above.
2. **Render** (`node $B1/rt/render.mjs`): `<span id="team-list">`, `<span id="row-7">`, `<div id="invite-form">` x2:
   the rendered id is the last write in 4/4, and differs from the brand the consumer checked.
3. **Chromium** (S2, beta6 and 4.0.0): the `#team-count` fragment route answering the double-setId view drops
   `#team-count` to 0 after one click; the second click logs `'#team-count' on hx-target did not match any element`
   and leaves 2 `#team-list` elements in the page.
4. **Prototype** (`$B1/libcopy`): an overload `setId(this: Rooted<string>, id?: string | Id): "setId: this view is
   already rooted …"` ahead of the existing two. `npx tsc --noEmit -p tsconfig.json`: the only new error is the
   overload/implementation compatibility at tag.ts:115, 0 in `test/**`. A 4-line fixture: typed-then-typed and
   typed-then-dynamic re-roots now fail at the consumer, a plain chain still compiles, the `.apply` re-root still
   compiles (2/3 mechanisms closed).
5. **Fleet**: 459 `.setId(` sites in 16 canonical repos; the 3 regex hits for a second `setId` in one chain are
   nested children; 13 `Component(…).setId(…)` sites wrap components whose bodies set no id. 0 live re-roots.

## Why it matters

impact 2 (a fragment answered at the wrong id deletes its own swap target) x pain 2 (the `never` collapse is
invisible unless a method follows) x reach 1 (latent). Hurts invariant-safety: `never` turns the strictest
branded parameter into an accept-all.

## Rough idea (not a design)

Type layer for the chain: reject `setId` on a receiver that already carries `Rooted<string>`. Dev-throw layer
for what types cannot see (`.apply`/`.when` callbacks): the template's `renderFragment` asserts in dev that the
rendered root carries `id="N"` (it already receives `N`). No prose to delete; none teaches re-rooting.
