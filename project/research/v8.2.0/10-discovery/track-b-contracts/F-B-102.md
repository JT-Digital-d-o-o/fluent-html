# The widened-Id gate never reached its consumers

($B1 = <scratch>/wave1/B1)

## Problem

Commit 9d86871 lists a "renderFragment-style widened-Id gate: `string extends N` rejects a widened `Id`, which
previously disabled the root check silently". The gate is a `declare function renderFragmentGated` inside
`test/types/type-surface.test-d.ts:655-666`. The real `renderFragment` (template `core/server/types.ts:71`) is
`renderFragment<N extends string>(id: Id<N>, view: RootedView<NoInfer<N>>)`, and its own JSDoc concedes the hole:
"An id widened to bare `Id` infers `N` as `string`, and `RootedView<string>` accepts a view rooted anywhere - the
check switches itself off." The same inference disables the route check at `.fragment` and `.search`
(`FragmentRoute<NoInfer<N>>` with `N = string` accepts every declared fragment route).

## Evidence (executed)

1. **Fleet declarations**: `grep -c "string extends N"` on `src/core/server/types.ts` in the 15 repos pinned
   8.1.0: **0/15**; all 15 carry the ungated signature.
2. **Probes** (tsc 6.0.3, `$B1/app/run-probe.sh`):
   - r06: `answer(reply, target: Id)` -> `reply.renderFragment(target, Span("x").setId(ids.teamList))` called with
     `ids.teamCount`, and `reply.renderFragment(t /* : Id */, Span().setId(ids.inviteForm))`: **0 errors**.
   - q12: `function Refresh(p: { target: Id }) { return Button().fragment(p.target, routes.count()) }` called with
     `ids.teamList`, and `Input().search(t /* : Id */, routes.count())`: **0 errors**. The narrow control
     `.fragment(ids.teamList, routes.count())` fails with a 7-line error naming both ids.
3. **Gate prototype** (`$B1/proto-rf`, `id: string extends N ? "renderFragment needs a narrow Id (ids.x), not a widened Id" : Id<N>`):
   r06 now reports 2 one-line errors naming the fix (182 chars). Full template tsc: 3 errors, all internal
   (define-controller.ts:385 widened call, server.ts decorator implementation signature, the define-controller
   unit-test stub); the 4 template app calls (payments x2, renderbox x2) compile unchanged. r11: the
   `Id<`ranking-row-${string}`>` family id gzs/stem-50 uses compiles (exit 0).
4. **Fleet call shapes** (regex over app + core `src/`, 15 repos): 175 `renderFragment(` calls = 160 `xIds.y`,
   13 template-internal `id` (define-controller, `Id<string>`), 2 family ids (gzs/stem-50). Targeted
   `.fragment(`/`.search(`: 278 calls, 239 `xIds.y`, 39 non-literal (props, `host.*`); 119 fields/props typed
   bare `Id` (includes the 15 copies of `SwapOptions.invalid`).

## Why it matters

impact 2 (a wrong root or wrong route compiles; the runtime result is the target-morphed-away failure measured in
[[F-B-104]]) x pain 2 (nothing reports it; the guideline has to teach generic props instead) x reach 2 (the
reusable-control shape is taught at fastify.md:225-237 and views.md:111-113; 39 non-literal targets exist today).
Hurts invariant-safety.

## Rough idea (not a design)

Type layer: export the gate from fluent-html (e.g. `NarrowId<N>`, additive) so the template's `renderFragment`,
`.fragment` and `.search` share one definition, and pin it on the real consumer instead of a test-local
declaration. Lets fastify.md:225-237's `Row(p: { target: Id })` bullet and views.md:111-113 go (about 5 lines).
