# An optional boolean in IfThen, IfThenElse, .when or .whenElse fails with an error that names no fix

## Problem
6.3.0 made a `boolean | null | undefined` value a compile error on the nullable overloads of `IfThen`, `IfThenElse`, `.when` and `.whenElse` (CHANGELOG.md:381: use an explicit comparison, `x === true`). The gate is `value: boolean extends T ? never : T | null | undefined` (src/control/conditionals.ts:28, :64; src/core/tag.ts:296, :319).

The input that hits it is an optional boolean prop (`open?: boolean`), and the error names neither the cause nor the fix:

```
ob.ts(19,25): error TS2769: No overload matches this call.
  Overload 1 of 2, '(condition: boolean, then: Thunk<Tag>): "" | Tag', gave the following error.
    Argument of type 'boolean | undefined' is not assignable to parameter of type 'boolean'.
      Type 'undefined' is not assignable to type 'boolean'.
  Overload 2 of 2, '(value: never, then: (value: boolean) => Tag): "" | Tag', gave the following error.
    Argument of type 'boolean | undefined' is not assignable to parameter of type 'never'.
      Type 'undefined' is not assignable to type 'never'.
```

The fix appears in only two places, and tsc shows neither: the comments of the three lib pins (test/type-safety.ts:514, :523, :540, 'compare explicitly') and the CHANGELOG. 0 guideline lines teach it.

## Evidence (executed)
`$R2 = <scratch>/wave1/B-reseed/r2`

- **Probe** (TS 6.0.3, 8.1.0 dist): `IfThen(p.open, ...)`, `Div().when(p.open, ...)`, `IfThenElse(p.user?.admin, ...)`. 3/3 give TS2769: 7/7/8 lines, 561/576/612 chars, 0 name a fix.
- **Fleet** (`ob-census.sh`, canonical era, app `src/`). 35 call sites in 13 of 16 repos convert the condition to get past the gate:
  - `=== true` 23 (11 repos), `!!` 7, `?? false` 4, `Boolean(` 1;
  - e.g. `IfThen(row.read?.hasAudio === true` at everyframe-composer studio.voice.view.ts:269.
  - The two pre-7 upgrades in [[F-B-604]] hit the same gate 6 and 9 times.
- **Prototype.** Replace `never` with the literal `"an optional boolean is ambiguous here: compare explicitly (x === true) or default it (x ?? false)"`.

| variant | fix position (IfThen / .when / IfThenElse) | message length |
|---|---|---|
| 8.1.0 | none / none / none | 561 / 576 / 612 |
| A: literal only | line 5 char 397 / line 2 char 151 / line 5 char 422 | 843 / 858 / 894 |
| B: literal, gate overload declared first | line 2 char 147 / line 2 char 151 / line 2 char 147 | 843 / 858 / 894 |

`.when` already declares its gate overload first, so A and B agree for it. Variant B over the scaffold plus competify, everyframe-composer, wsfas and na-cent (1,407 `IfThen`/`IfThenElse`/`.when`/`.whenElse` sites): 0 new errors in all 5.

## Why it matters
impact 2 x pain 2 x reach 3 / S = 12.
- **error-quality.** The most natural input to a conditional, an optional boolean prop, gets a 7-line two-overload error whose only nouns are `boolean` and `never`.
- **decision-closure.** The fix was decided in 6.3.0, but only the CHANGELOG states it.
- **Reach.** 13 of 16 canonical repos carry the workaround.

## Rough idea (not a design)
Type layer, additive in what it accepts:
- a message literal in place of `never` in the 4 gates;
- the gate overload declared first, so the fix prints in the first overload header;
- the 3 pins repointed to assert the text.

This does not reopen [[L-065]] (the false-skip dispatch decision); only the error text changes. The same message-gate pattern applies to the Match/MatchValue/whenMatch widened gates ([[F-B-403]]).
