# At the codemod fixpoint the upgrade residue is 6.0.0 removals and removed exports that no tombstone source names

## Problem
[[F-B-203]]'s tombstone source is the 7.0.0/8.0.0 codemod maps plus the 8.0.0 prune list: 94 names. The fleet's 39 pre-7 repos (pins 5.7.0 to 6.5.0) also call names that 6.0.0 removed, and neither the codemod nor that source covers them. After the codemod has done its work, these are what remain, and they fail anonymously:

```
src/vault/components/filter-bar.view.ts(109,80): error TS2339: Property 'setSelected' does not exist on type 'OptionTag'.
src/admin/emission-factors/views/emission-factors.detail.view.ts(20,3): error TS2305: Module '"fluent-html"' has no exported member 'formFor'.
```

## Evidence (executed)
`$R2 = <scratch>/wave1/B-reseed/r2`

- **Surface history.** `surface-hist.mjs` walks the runtime of the 11 installed fleet versions (5.7.0 to 8.1.0). 118 method names existed in some version and are gone in 8.1.0. F-B-203's 94 are all among them. The other 24:
  - the 18 boolean setters (CHANGELOG.md:693, successor `.toggle(name)`);
  - `setToggles`;
  - `flex1` (:707);
  - `setCrossorigin`, `setReferrerpolicy`, `setSvgOpacity` (:703);
  - `hxOn` (:354).
- **Fleet** (`unc-census.sh`, dedup corpus): 242 call sites of the 24 across 27 pre-7 repos (setToggles 98, setCrossorigin 46, flex1 43, setSelected 11, setDefer 11, ...), 0 in the canonical era.
- **Upgrade residue at the codemod fixpoint** (the [[F-B-604]] runs). Fluent property errors left:
  - jt-vault 16: setSelected 9, setChecked 3, setDisabled 2, setCrossorigin 2;
  - planet-positive-sport 50: flex1 34, on 5, setDefer 4, setCrossorigin 4, at 2, setOpen 1.
  - 59 of the 66 are on the 24 uncovered names; the other 7 (`on`, `at`) are in F-B-203's set.
- **A 118-name type-only tombstone set** (`up/lib118`: F-B-203's 94 with dual SVG messages, plus 24 entries taken from the CHANGELOG successors) turns jt-vault 16/16 and planet-positive-sport 52/52 property errors into TS2684 naming the successor on line 1. Example: `... method's 'this' of type '"setSelected() was removed in 6.0.0: use .toggle('selected') (or .toggle('selected', cond))"'`. The 5 TS2339 left in jt-vault are Prisma model fields, not fluent names.
- **Removed root exports.** 19 exports (formFor, createContext, createRequiredContext, OOB, withOOB, Overlay, the fold and algebra set, addClassToMatching) fail as TS2305 with no successor. `gone-imports.mjs`: 92 import specifiers in 7 pre-7 repos (formFor 79, createContext 12, createRequiredContext 1). The successors are written only in CHANGELOG.md:709 (`Form<T>`), :730 (framework layer) and :506 (`Partial`).

## Why it matters
impact 2 x pain 2 x reach 2 / M = 4. error-quality on the upgrade path: once the documented tool has run, the compile errors that remain are exactly those whose successor appears only in a 1,550-line CHANGELOG. Reach: 27 repos / 242 call sites, plus 7 repos / 92 imports.

## Rough idea (not a design)
Type layer plus tooling.
- Derive the tombstone source from the published surface history: every name any released version exposed that 8.x lacks, with successors from one removal table keyed by version, rather than from the 7.0 codemod maps.
- Add the 6.0.0 pure renames and the boolean-setter rewrite (`.setDisabled(x)` -> `.toggle("disabled", x)`) to the codemod.
- For removed exports, a d.ts tombstone cannot help a bare import, so a generated import lint rule (or a codemod import rewrite) names the successor.

Use the same generator as [[F-B-602]]. Tombstones are not aliases ([[L-389]]): nothing removed becomes callable.
