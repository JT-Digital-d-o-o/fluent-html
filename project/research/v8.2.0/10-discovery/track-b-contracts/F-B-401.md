# NoExtraCases erased the did-you-mean on a typo'd or stale Match case

## Problem
8.1.0 made `Match` infer its cases object `C` so the return type carries the branch types (commit 3e22e25). Inference switches off excess-property checking, and `NoExtraCases<C, Allowed>` (`src/control/conditionals.ts:85-87`) restores the rejection by mapping every extra key to `never`. The rejection survived; the message did not. A stale case key after an enum rename now reads:

```
m/m11-stale-rename.ts(8,3): error TS2322: Type '() => Tag' is not assignable to type 'never'.
```

On 8.0.0 the same fixture read:

```
m/m11-stale-rename.ts(8,3): error TS2353: Object literal may only specify known properties, and 'closed' does not exist in type '{ active: Thunk<View>; pending: Thunk<View>; archived: Thunk<View>; }'.
```

The 8.1.0 text names neither the key (only its column), nor the allowed members, nor a fix. When the typo replaces a real member (`clossed` for `closed`), 8.1.0 reports only the `never` line; 8.0.0 said `Did you mean to write 'closed'?`.

## Evidence (executed)
`tsc --strict --pretty false` (TypeScript 6.0.3) on identical fixtures, against `dist/` 8.1.0 and against `git archive 6de9c1f dist` (8.0.0):

| Fixture | Overload | 8.0.0 | 8.1.0 |
|---|---|---|---|
| m4 value exhaustive, `clossed` for `closed` | value | TS2561 `... 'clossed' does not exist in type {...}. Did you mean to write 'closed'?` (229 chars) | TS2322 `Type '() => Tag' is not assignable to type 'never'.` (91) |
| m11 value exhaustive, stale `closed` after rename to `archived` | value | TS2353 names `closed` and the 3 allowed keys (201) | TS2322 `... 'never'.` (94) |
| m10 value + default, `actve` | value+default | TS2769 containing `Did you mean to write 'active'?` (1386) | TS2769 containing `Type '() => Tag' is not assignable to type 'never'.` (1305) |
| m8 DU + default, `eror` | DU+default | TS2561 `Did you mean to write 'error'?` + TS7006 | TS2322 `Type '(x: any) => Tag' is not assignable to type 'never'.` + TS7006 |
| m3 / m12 DU exhaustive, typo / stale | DU | excess-property text, did-you-mean kept | unchanged (reported inside TS2769) |

3 of 4 overloads regressed. The type test pins the rejection only (`test/types/type-surface.test-d.ts:479-480`, `@ts-expect-error`), so the message change passed CI, although the repo already pins message text elsewhere (`test/brand-errors.test.ts`, `test/setter-errors.test.ts`).

Prototype (scratch copy of `dist/`), `[K in Exclude<keyof C, Allowed>]: ` + a template literal `'${K & string}' is not a member of the matched union: fix the typo or delete the stale case`:

```
m/m4-typo-value.ts(7,3): error TS2322: Type '() => Tag' is not assignable to type '"'clossed' is not a member of the matched union: fix the typo or delete the stale case"'.
```

173 chars, one line, names key and fix; m11 175 chars; m8 264 chars (incl. the TS7006). A fixture of valid calls (DU exhaustive with narrowed `(x) => Span(x.message)`, DU + default, value exhaustive) compiles with 0 diagnostics on the prototype, so the contextual typing that 3e22e25's constraint placement protects survives. The same change applied to `src/control/conditionals.ts` in a scratch lib copy: `npx tsc --noEmit -p tsconfig.json` (5.9.3, includes `type-surface.test-d.ts`) exit 0. A variant that interpolates `Allowed` distributes into a 3-member union message (246 chars), so the message must not interpolate the union.

Reach (TS AST over 3,334 app-authored files, 16 canonical-era repos): value-form exhaustive `Match` 50 sites in 12 repos; value+default 0; DU+default 0; DU exhaustive (unaffected) 104 sites in 16 repos.

## Why it matters
impact 2 x pain 2 x reach 2 / S = 8. Error quality: a stale key is what an enum rename leaves behind, and the message went from self-healing to naming nothing. The change is a string in an internal type: nothing newly compiles or stops compiling, so it fits 8.1.x.

## Rough idea (not a design)
Type layer: replace `never` in `NoExtraCases` with a message literal naming the key and the fix (not the allowed union), and pin the first line of the text in a `setter-errors`-style probe test so the next signature change cannot drop it silently. No guideline prose to delete.
