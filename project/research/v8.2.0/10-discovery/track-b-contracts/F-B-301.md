# Swap verbs never stamp action or method on a form

`$B3` = `<scratch>/wave1/B3`.

## Problem

fluent-html 8.0.0 left `FormTag.setAction` unbranded on the stated ground that "forms route through the swap verbs, which stamp the action from a route callable" (`CHANGELOG.md:133`). The verbs do not. `keepAnchorReachable` (`swap-verbs.ts:252-256`) gives an `<a>` its `href` so it works without JS; there is no form counterpart. The template's own sign-in form renders:

```html
<form hx-post="/auth/signin" hx-target="#main-content" hx-swap="outerMorph show:top" hx-push-url="true" hx-indicator="#global-loading" hx-disable="findAll button" hx-status:422="swap:outerMorph target:#login-form push:false">
```

No `method`, no `action`. Any native submission (JS off, htmx blocked, or a submit before the `defer`-loaded htmx has run, `layout.view.ts:203-205`) is a GET to the current URL with every field in the query string.

## Evidence (executed)

- `tsx $B3/app/render-login.mts` on the scaffolded template (fluent-html 8.1.0): the form tag above, 0 `action`, 0 `method`.
- `node $B3/race.mjs`: page with the rendered login form and `<script src="/js/htmx.min.js" defer>` served after 2.5 s. `typeof window.htmx` at submit = `undefined`; the server receives `GET /auth/signin?email=ana%40example.si&password=hunter2-secret`; final URL carries the password. Identical on lib `4.0.0-beta6` and template `4.0.0`.
- `node $B3/browser-b3.mjs` S3 (JS disabled): same URL on both bundles.
- `node $B3/forms.mjs` (TS AST over the dedup corpus, 58 repos): 1,037 Form chains carry a verb (`nav/submit/fragment/fire/search/onChange/tab`); 8 also call `setAction`; 1,029 do not. By era: 8.x 718/726, 7.x 43/43, pre-7 268/268. 144 actionless forms contain a password field, 84 of them in 8.x, covering all 15 8.x repos (template-derived `login.view.ts`, `register.view.ts`, `reset-password.view.ts`, `account.page.view.ts`). 3 of the 26 repos are flagged scratch-looking in recon 01.
- The 8 hand-written exceptions show the need: `gzs/stem-50/src/shared/ui/search.ts:57-59` chains `.submit(submitRoute).setAction(submitRoute.endpoint).setMethod("get")` with a comment that "action + method stay the no-JS half" read "off the very route the verb posts to, so the two halves cannot address different endpoints".
- The template's own swap-verb decisions assume a no-JS render path exists (`project/pm/swap-verbs/decisions.md:58`: "the htmx and no-JS renders cannot drift"); without an action the no-JS request never reaches that handler.

## Why it matters

impact 3 (credentials land in access logs, history and Referer on any native submit), pain 2 (invisible on every layer: tsc, eslint, extractor, unit and browser suites all run with htmx loaded), reach 3 (every 8.x repo). It is also the premise that parked L-075, so the raw-string sink question (F-B-304) was decided on a false fact.

## Rough idea (not a design)

Runtime layer, template-owned: a `keepFormSubmittable(tag, route)` next to `keepAnchorReachable` that stamps `setMethod(route.method === "get" ? "get" : "post")` and `setAction(route.endpoint)` on a `FormTag` unless one is already set. "Already set" needs a read, which by L-085 should be a library accessor (`FormTag.getAction()`, additive, the `getEnctype` precedent). No prose to delete; it removes the need for the hand-written half in stem-50-style components.
