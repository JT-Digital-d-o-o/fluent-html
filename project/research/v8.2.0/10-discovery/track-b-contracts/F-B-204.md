# The set* prefix puts 80% of setter call sites outside tsc's did-you-mean window

## Problem

The 8.0 plan (scorecard.md:31-32) expected privatized storage to turn the `.src()` guess into `Did you mean 'setSrc'?`. It cannot: TypeScript only suggests a candidate whose length differs by at most `max(2, floor(0.34 * len))` and whose edit distance is under `floor(0.4 * len) + 1` (typescript.js:3493-3496). The `set` prefix adds 3 characters, so every attribute name under 9 characters (`id type href name src value rel alt for min max action method target`) gets an anonymous TS2339 by construction. Where TS does suggest, it sometimes suggests a Tailwind method instead of the setter.

## Evidence (executed)

`$B2 = <scratch>/wave1/B2`. One probe per (class, own setter) slot from the 8.1.0 runtime walk: `declare const t: E.ImgTag; t.src(undefined as never)`; 9 bare names that collide with a live Tag method (`hidden content fill stroke opacity transform translate wrap list`) excluded.

| outcome on 8.1.0 | slots | distinct setters | canonical-era call sites |
|---|---|---|---|
| TS2551 naming the setter | 78 (26.5%) | 49 | 1,317 (17.4%) |
| TS2551 naming a different member | 13 (4.4%) | 7 | 173 (2.3%) |
| anonymous TS2339 | 203 (69.0%) | 93 | 6,063 (80.3%) |

The top of the anonymous column by call sites: `setType` 697, `setId` 513, `setAria` 460, `setHref` 366, `setHtmx` 267, `setRel` 187, `setName` 174, `setSrc` 157.

The 13 misdirections: `Img/Iframe.loading -> leading`, `Input.accept -> accent`, `Input/Meter.min -> minW`, `Input/Meter/Progress.max -> maxW`, `Meta.charset -> caret`, `Td/Th.colspan -> colSpan`, `Td/Th.rowspan -> rowSpan`. Following them: 9 end in a second anonymous error (`Argument of type '1' is not assignable to parameter of type 'TailwindMinWidth'`, `'"lazy"' ... 'TailwindLeading'`, `'"utf-8"' ... 'TailwindColor'`); 4 compile (`Td("x").rowSpan(2)`, `Th("x").colSpan(2)` and the recon's colspan pair), emitting a grid class instead of the attribute.

Prototype: a generator emits, per class, `src(this: "ImgTag has no src(): use .setSrc(...)", ...args: unknown[]): any;` via module augmentation. After:

```
p12-src.ts(2,24): error TS2684: The 'this' context of type 'ImgTag' is not assignable to method's 'this' of type '"ImgTag has no src(): use .setSrc(...)"'.
p11-colspan.ts(2,24): error TS2684: The 'this' context of type 'TdTag' is not assignable to method's 'this' of type '"TdTag has no colspan(): use .setColspan(...)"'.
```

294/294 slots name the real setter on line 1; the scaffold compiles unchanged.

Design constraints the prototype hit:
- Partial coverage creates new misdirections: tombstoning only the 216 non-self-healing slots made `ButtonTag.commandfor` answer `Did you mean 'command'?` (a tombstone) instead of `setCommandfor`. All-or-none.
- A subclass redeclaring a Tag-level name with its own message (`HtmlTag.lang/dir`) makes the subclass unassignable to `Tag` (template `layout.view.ts:196` failed). Declare each name once, at the highest class that has the setter.
- `class`/`classes` would name `setClass`, which the template lints as an error for Tailwind strings: those 2 messages need curation.

## Rough idea (not a design)

Type layer, generated from the element classes (the same source as the runtime walk), one entry per bare name; lockstep: test/setter-errors.test.ts pins TS2684 + the setter name instead of the anonymous TS2339 it pins today. Deletes the guideline prose that teaches the `set*` prefix rule by example.
