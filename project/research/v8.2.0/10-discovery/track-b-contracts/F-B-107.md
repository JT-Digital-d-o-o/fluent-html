# The validation half of the swap contract is unchecked

($B1 = <scratch>/wave1/B1)

## Problem

8.1.0 types the success half of a swap (the route's `render` stance, `renderPage`/`renderFragment`, `Rooted<N>`).
The 422 half is outside it by construction: `.submit(route, { invalid: ids.form })` takes a bare `Id`
(swap-verbs.ts:189) and emits `hx-status:422="swap:outerMorph target:#form push:false"`; the handler answers
`reply.code(422).renderView(isHtmxRequest(request) ? Form(props) : Page(props))` (sign-in.controller.ts:26),
and `renderView` takes `View[]` and claims nothing (answer.ts:32-34 says so). Nothing connects the id at the call
site to the root of the view the handler sends. An outer morph with an unrooted 422 view deletes the target id,
so every later rejected submit has nowhere to land.

## Evidence (executed)

1. **Chromium** (`node $B1/rt/browser422.mjs`, Playwright chromium, lib beta6 bundle and the template's served
   4.0.0 bundle; form built with the real `.submit(routes.invite(), { invalid: ids.inviteForm })`, server answers
   422 twice):

   | 422 view | beta6: #invite-form after 1st / 2nd | 4.0.0 | Console |
   |---|---|---|---|
   | rooted at #invite-form (control) | 1 / 1 | 1 / 1 | 422 only |
   | same form without `setId` | **0 / 0** | **0 / 0** | `htmx: '#invite-form' on hx-target did not match any element` |

   The unrooted variant compiles: the handler path is `renderView(View[])`.
2. **Reach**:
   - Phase-2 (recon 02): 4/4 in-repo agents (blind1/2, guided1/2) wrote `.submit(teamRoutes.invite(), { invalid: teamIds.inviteForm })`
     plus `reply.code(422).renderView(…)`: the unchecked path is the default idiom, and each agent had to root
     the form correctly with no type support.
   - Fleet (regex, comment lines stripped): 76 app-authored `{ invalid:` sites in 15/16 canonical repos;
     of 114 app-authored `renderView(` sites in the 15 repos pinned 8.1.0, 59 sit in a 4xx branch
     (`code(4xx)`/`status(4xx)` on the same or previous line), 5 carry `Partial`, 2 `hxResponse`.
   - Live mismatches: a same-repo `setId(<same id>)` cross-check finds a matching root for every real
     `invalid:` site (the 17 misses are 15 JSDoc copies of answer.ts:33, one comment, one unrelated data field),
     so 0 detected today; the check proves presence, not that the 422 view is that root.

## Why it matters

impact 2 (after the first rejected submit, validation feedback stops rendering with no error) x pain 2 (only a
second failed submit in a browser shows it) x reach 3 (every form in every generated feature). Hurts
invariant-safety.

## Rough idea (not a design)

Type layer: the 422 region becomes a route-def fact like `render` (e.g. `invalid: ids.form`), read by the verbs
off the tagged bag, replacing the call-site `SwapOptions.invalid` (converge: one place states it), and the handler
gets a rooted exit (`renderInvalid(view: RootedView<N>)`-shaped) so the 422 root is checked. Additive in the lib
(an optional `RouteDef` key); template changes the verbs and answer types. Lets answer.ts:32-34 and the
guideline's hand-kept 422 idiom text shrink.
