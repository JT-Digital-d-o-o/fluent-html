# Three layers disagree on whether a status target may be an Id

`$B3` = `<scratch>/wave1/B3`.

## Problem

`hx(url, { target: ids.x })` compiles because `HxOptions` accepts `Id` in 5 selector fields (`htmx.ts:358-362`). The same value one level down, in a status bag, or in the raw `HTMX` bag the verbs and `setHtmx` take, or in `hxResponse().retarget()`, is `string`-only. The lint and the runtime both treat an `Id` there as the right answer.

## Evidence (executed)

`v13-status-target.ts` on the scaffolded template (fluent-html 8.1.0, plugin 4.1.0):

| Line | tsc | eslint | Render |
|---|---|---|---|
| `hx(route, { method: "post", target: ids.inviteForm })` | clean | clean | `hx-target="#invite-form"` |
| `hx(route, { method: "post", status: { 422: { target: ids.inviteForm } } })` | TS2322, 5 lines / 454 chars; the actionable `Type 'Id<"invite-form">' is not assignable to type 'string'.` is the last line | clean | `hx-status:422="target:#invite-form"` (correct: `Id.toString()` returns the selector) |
| `status: { 422: { target: "#invite-form" } }` | clean | `fluent-html/no-raw-ids`: `Avoid hardcoded target: "#invite-form". Use defineIds() for type-safe targets (e.g. ids.inviteForm).` | same bytes |
| route-level `teamRoutes.invite({ status: { 422: { target: ids.inviteForm } } })` | TS2322, same 5 lines | clean | same bytes |

So the lint's suggested fix is a type error, the type error's first line blames the whole `Partial<Record<HxStatusKey, ...>>`, and the only form all three layers accept is a third spelling, `ids.inviteForm.selector`.

Fleet (TS AST, dedup corpus): 118 htmx-bag selector fields are written as `x.selector`: 72 inside status bags (71 pre-7 route-level 422 bags such as `updateProfile`, `signin`; 1 8.x `sportoawards/src/app/entry/views/entry.components.ts:454`), 16 in 8.x `setHtmx` raw bags that are the vendored `swap-verbs.ts:321` (`target: target.selector`), 5 app-level 8.x. Plus 2 8.x `hxResponse(Empty()).retarget(layoutIds.mainContent.selector)` (`competify/src/app/demo/demo.plugin.ts:59`, `na-cent/src/app/demo/demo.plugin.ts:87`). The template's `{ invalid }` option exists partly to hide this (`swap-verbs.ts:202`), and its comment at `:208-209` states the cause ("setHtmx stores the HTMX verbatim, it does not run resolveSelector").

## Why it matters

impact 2, pain 2 (a lint/type contradiction is a loop an agent can burn several turns in), reach 2 (every hand-written 422 route bag; 22 live 8.x conversions). Decision-closure: three accepted spellings for one selector.

## Rough idea (not a design)

Type layer, additive: `HxTarget | Id` / `string | Id` on `HxStatusConfig.target/select`, the `HTMX` bag selector fields, `retarget`, `reselect`, `HxLocationConfig.target`; `buildHtmx`/`buildStatusConfig`/`HxResponse` call `resolveSelector`. Then fix the `ids.ts:22-23,:90` JSDoc to show the Id, and the template can drop its `.selector` constants. Does not touch L-063 (the `string` arm stays).
