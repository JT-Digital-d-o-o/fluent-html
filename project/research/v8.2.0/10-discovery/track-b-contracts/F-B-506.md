# Raw-string swap-verb call is unpinned and its error names no fix

## Problem
`A("Team").nav("/team")` is the pure-prior guess the scorecard ranks as leverage item #1 (L-084). On 8.1.0 it
still fails with a message that names two type aliases and no way forward, and at runtime it renders a broken
anchor. No test anywhere pins either the rejection or its text, so a change that widens `PageRoute` (or makes
the error worse) ships green.

## Evidence (executed)
`$B5 = <scratch>/wave1/B5`

1. Current diagnostic (`$B5/probe/nav.ts`, the template's own signature `nav(route: PageRoute)`):
   ```
   nav.ts(6,5): error TS2345: Argument of type 'string' is not assignable to parameter of type 'PageRoute'.
     Type 'string' is not assignable to type 'HTMX'.
   ```
2. Runtime, template verbs bundled against dist (`$B5/nav-render.mjs`, NODE_ENV=development, no throw):
   ```
   raw   : <a class="cursor-pointer" role="button" tabindex="0" hx-undefined="undefined" hx-target="#main-content" hx-swap="outerMorph show:top" hx-push-url="true" hx-indicator="#global-loading">Team</a>
   route : <a class="cursor-pointer" href="/team" hx-get="/team" hx-target="#main-content" ...>Team</a>
   ```
3. Pin census. Lib: `$B5/strip-expect.mjs` strips all 155 `@ts-expect-error` directives in the compiled test
   set and records what satisfies each: 0 involve a string argument to a verb. `type-surface.test-d.ts:549-575`
   declares `navVerb` and calls it with `stanceRoutes.*()` and `anyHtmx` only. Template:
   the two compile-probe suites (`define-controller-compile.test.ts`, `resolved-route-compile.test.ts`) define
   43 probe fixtures; the verb probes (`:922-954`) pass route callables or a laundered `HTMX` bag, the
   resolved-route red path (`:246-256`) covers concat query, hand-rolled bag and `setHref` literal.
   A ripgrep over template tests for any swap-verb call (nav, submit, fragment, poll, tab, search, onChange,
   fire) with a string-literal argument: 0 hits. eslint plugin 4.1.0 `src/rules/*.ts`: no
   rule matches a string literal in `.nav(` (`prefer-nav-for-internal-links` targets `A().setHref`).
4. A gate that names the fix, as a merged Tag method (`$B5/probe/navm.ts`):
   ```ts
   type NavArg<R> = R extends string ? "a swap verb takes a route callable result (e.g. `teamRoutes.index()`), not a URL string" : R;
   interface FluentCustomMethods { nav2<const R extends PageRoute | string>(route: NavArg<R>): this; }
   ```
   Output: `A("Team").nav2("/team")` -> `TS2345: Argument of type '"/team"' is not assignable to parameter of type
   '"a swap verb takes a route callable result (e.g. `teamRoutes.index()`), not a URL string"'` (1 line);
   `A("Team").nav2(teamRoutes.index()).p("4")` compiles; a `render: "none"` route is still rejected (the stance
   error keeps working, its text now carries the message arm in the union).

## Why it matters
reach 3: every template-derived 8.1 app exposes the verbs (`.nav` 1451 canonical-era census sites, recon 01
§5); the pure prior writes the string form first (recon 02 D2, probe #1). impact 3 and pain 3: the error
never names the route callable, and the runtime result (`hx-undefined`) passes tsc-free code paths such as
`as any` or JS without a warning. Dims: error-quality, silent-failure, verification-loop.

## Rough idea (not a design)
Strongest layer is type: a conditional gate on the verb parameter (the same message-literal technique the lib
already pins for `renderFragmentGated` at `type-surface.test-d.ts:655-666` and the template uses for the
`.fragment` stance error, recon 02 #29 fix at char 225), plus a text-asserting probe in a harness like
`test/brand-errors.test.ts`. The swap verbs stay in the template (S-19); the lib can export the gate type so
all verbs share it. Lets the "never setHref / use route callables" bullets in the guidelines shrink to the
error text.
