# cssProp's property union lags the platform by one TypeScript major

`$E7` = `<scratch>/track-e/E7`

## Problem

The guidelines route every CSS property with no Tailwind utility through `.cssProp()` (CLAUDE.md:191), and the 8.0.0 prune promised that pruned CSS "stays reachable" there (CHANGELOG.md:112). The property argument is the closed alias `CssPropertyName`, generated from `CSSStyleDeclaration` in the installed compiler's `lib.dom.d.ts`. The lib builds with typescript 5.9.3 (`^5.0.0`), so the union stops at that file.

TypeScript 6.0.3, which the canonical apps run (C-69), moved the properties to `CSSStyleProperties` and added 27. The fleet needs some of them, finds them rejected, and writes around the hatch:

```ts
// everyframe/src/app/home/home.view.ts:291-297
// `animation-timeline` and `animation-range` have no Tailwind utility and are not in `.cssProp`'s
// property union, so they ride the inline style
t.animate("[rulein_520ms_cubic-bezier(.16,1,.3,1)_both]")
  .setStyles({ animationTimeline: "view()", animationRange: "entry 5% entry 45%" })
```

- sportoawards builds a CSS-only scroll-spy from `view-timeline-name`, `animation-timeline` and `timeline-scope`, all through `setStyle` because "these properties post-date fluent's `cssProp` list" (jump-nav.ts:9-24), and an auto-growing textarea through `setStyle("field-sizing: content")` (entry.components.ts:174).
- everyframe-composer counts textarea rows on the server "rather than `field-sizing: content`, which is not in the typed CSS list here" (studio.voice.view.ts:410).
- fluent-html-home-page and home-page keep their scroll timelines in hand-written CSS.

`fieldSizing` was pruned in 8.0.0 two months after `field-sizing` became Baseline (2026-06-16), and its named successor `.cssProp("field-sizing", ...)` does not compile.

## Evidence (executed)

- Union diff: `npm pack typescript@6.0.3`, parse `interface CSSStyleProperties` with the generator's own regex: 462 names vs 436 today, **+27 / -0**: anchor-name, anchor-scope, animation-range, animation-range-end, animation-range-start, animation-timeline, dynamic-range-limit, field-sizing, font-language-override, font-variant-emoji, math-shift, position-anchor, position-area, position-try, position-try-fallbacks, position-try-order, position-visibility, scroll-timeline, scroll-timeline-axis, scroll-timeline-name, text-autospace, text-justify, timeline-scope, view-timeline, view-timeline-axis, view-timeline-inset, view-timeline-name.
- Generator on TS 6: the compiled `emit-css-props.js` resolved against typescript 6.0.3 (`$E7/gen-ts6`) throws `emit-css-props: parsed only 0 properties from lib.dom.d.ts - the parser is stale`, because the first `interface CSSStyleDeclaration {` in the TS 6 file is the iterator augmentation. typescript 7.0.2 ships no `lib/lib.dom.d.ts` in its main package (`find` returns 0 files), so the read path breaks there too.
- Fleet (`$E7/mine.mjs`, then a scan of every setStyle/setStyles/cssProp/variant argument and authored CSS line for the 27 names): 8 setStyle/setStyles sites in everyframe and sportoawards, 6 CSS lines in fluent-html-home-page and home-page, 2 `supports-[...]` guards (everyframe ts-sdk-motion.view.ts:667, gzs/stem-50 info.ts:45), 0 pre-7 repos. With the everyframe-composer workaround: 5 canonical repos.
- Probe (`$E7/probe1`): 7 calls written from the fleet sites give 7x `TS2345 ... not assignable to parameter of type 'CssPropertyName'` against 8.1.0 types. With the 27 names added to a scratch build (`$E7/lib`), 0 errors. Tailwind 4.3.3 `candidatesToCss` returns the expected declaration for 7/7.

## Why it matters

impact 2 x pain 2 x reach 2 / S = **8**.

- evolvability: the union is pinned to the compiler the lib builds with, and the generator breaks on the compilers its consumers run.
- decision-closure: setStyle, the runtime-value hatch, becomes the static-value path for a whole feature family; inline styles also cannot sit under a variant, so `supports-[...]` and `motion-reduce` forms need a second channel.
- One app moved UI logic to the server to avoid the gap.

## Rough idea (not a design)

Type layer, additive. Teach the generator to read `CSSStyleProperties` when present (or source the list from a pinned data package, the way the Tailwind oracle is pinned), regenerate, and pin a CI check that the union is a superset of the previous one. Pure widening of a hatch the guidelines already teach, so no prose is added; RFC-C-01's no-method redirect then also autofixes `field-sizing-content`.
