# A declared route query map answers 400 to the blank value every filter control sends

## Problem

The template turns a route's declared `query` map into a coercing Ajv schema (`register-route.ts:46-63`): `"number"` becomes `{ type: "number" }`, a tuple becomes `{ enum: [...] }`. Every GET filter bar submits the whole form on every gesture (`.onChange` and `.search` widen `include` to `closest form`), and HTML spells "no value" as `""`: an unset select sends `status=`, a cleared number input sends `fitMin=`. Neither schema accepts `""`, so the router answers 400 and the morph replaces the region the reader was typing in.

The fleet met it twice in one week, and both fixes pushed the blank into the domain:
- competify `e7448d0`: "an unset select arrives as `status=`, a value neither query declared". Fix: `""` added to the enum (`organise.routes.ts:15`) plus a normalizer per feature (`organise.schema.ts:32`, `judge.schema.ts:27`).
- wsfas `4a8715d9`: "the two floors were number inputs whose blank sends \"\", which a \"number\" param refuses: every live search, the no-JS submit and the CSV link answered 400". Fix: number inputs rewritten as fixed-step selects with a `""` member (`companies.routes.ts:191,193`), `page` retyped `"string"` and parsed by hand (`:207`).

The template's own payments filter does the same by hand: `Type.Literal("")` arms in its querystring (`payments.schema.ts:48,51`) and a handler that coerces `""` to `undefined`.

## Evidence (executed)

- `node blank/blank.mjs` (Fastify 5.12.1 from the template, `declaredMapSchema` copied verbatim, query `{ department: "string", status: ["DRAFT","SUBMITTED"], fitMin: "number", page: "number" }`):

| URL | today | with blank-as-absent |
|---|---|---|
| `/ideas?status=&department=&q=` | 400 | 200, handler sees `{ q: "" }` (undeclared key untouched) |
| `/ideas?fitMin=&page=` | 400 | 200, handler sees `{}` |
| `/ideas?status=DRAFT&page=2` | 200 | 200 |
| `/ideas?status=DRAFTT` | 400 | 400 |
| `/ideas?page=abc` | 400 | 400 |

- `python3 qmaps.py canon`: 266 declared query maps in 15 of 16 canonical repos, 90 `"number"` keys and 406 enum keys; `scan.py` finds only 36 tuples that list `""` (wsfas 35, competify 1), so every other key 400s on a blank today.
- History: the 2 commits above, 5 endpoints. Workarounds counted: 36 `""` tuple members, 2 normalizers, 17 `Type.Literal("")` sites in 7 canonical repos (template payments, vendored).

## Why it matters

impact 2 × pain 2 × reach 3 / S = 12. The failure is loud (400), but each repair spreads a sentinel through routes, types, services and tests, and the typed contract (`ResolveQuery` keys are optional) is only honest once a blank is absent. It is also the runtime half F-E-501 needs to admit `""` for optional fields. Dimensions: invariant-safety, verification-loop.

## Rough idea (not a design)

Framework layer, runtime enforcement: a `preValidation` hook registered by `registerRoute` for declared query maps deletes `""` values of declared keys before Ajv runs. Scope it to querystrings: in a POST body a cleared text field can mean "clear this value", so bodies keep their `""` (the wsfas number-body fixes 33b6c71d and 704ba03a stay app-level). An integration test walks a rendered filter bar's blank submit. Prose it retires: the "empty string is a legal value of this query" comments the fleet now writes per route.
