# An untouched Form<T> select submits an option the user never chose

## Problem

A single `<select>` with no `selected` option shows and submits its first option. `f.select` (`src/elements/forms.ts:495-502`) marks the option equal to the bound value and does nothing when none matches, so two shapes post a value nobody picked, with no error at any layer:

1. **The bound value is not among the options.** wsfas `655ce831`: "CLASSIFY writes CompanySize.LARGE for a 250+ company, but the CRM edit form offered no LARGE option, so an untouched save posted SOLO". The prefill was `size: company.size as UpdateCompanyBody["size"]` (`companies.detail.view.ts:143`), a cast types cannot see through.
2. **A required select with no placeholder.** stem-50 `9a1603a`: "Both dropdowns rendered without a leading empty option, so the browser pre-selected the first row. A visitor who ... never opened the company select still submitted a valid enquiry, stored against whichever company sorts first, whose contact was then e-mailed". `required` could not help: per HTML, a select is only "missing" while its placeholder label option (first child, value `""`) is selected.

The commit also notes the same defect left in `auth.register.view.ts`; the census below finds one more still at HEAD.

## Evidence (executed)

- **Browser** (`node select-submit-probe.mjs`, forms rendered by 8.1.0, Chromium, Firefox, WebKit, click submit without touching the select): `unlisted -> ?size=SOLO` and `noPlaceholder (required) -> ?companyId=c1` on all 3 engines, 6/6.
- **Prototype checks** (`lib-p5b`: guard 1 in the compiled binding, guard 2 in the compiled serializer; logging instead of throwing so suites keep running), run with `vitest run tests/view` on node_modules overlays (`vitest-p5.sh`):
  - stem-50 at `9a1603a^`: flags `companyId` and `facultyId` (the 2 incident selects) and `universityId`.
  - 15 canonical repos at HEAD, 5,835 view tests: 1 flag, stem-50 `faculties.form.view.ts:79-80` (admin create form, `universityId` required, no placeholder: the incident shape, still live). 0 false positives. A broader first draft ("no placeholder" without `required`) flagged 21 selects whose intended default is option 1 (wsfas filter selects led by `all`), which is why guard 2 keys on `required`.
  - Guard 1 on the wsfas shape (`p5-unit.mjs`): `[F-E-504] unlisted-value f.select("size") bound="LARGE" first="SOLO" n=5`.

## Why it matters

impact 3 × pain 3 × reach 2 / S = 18. Silent data corruption: a saved field rewritten on an untouched save, a third party e-mailed on a choice the user never made. Nothing compiles, lints or 400s differently; both incidents were found by QA reading results. Dimensions: silent-failure, verification-loop (every existing view test that renders the form starts catching it).

## Rough idea (not a design)

Dev-throw, in the existing `devChecks` family (off under `NODE_ENV=production`, so the render hot path is untouched in production). Guard 1 lives in the binding, the only code holding value and options together. Guard 2 lives at the select's serialize step and applies to raw `Select()` too, keyed on the HTML rule (required, not multiple, no selection, first option value not `""`). F-E-501 is the compile-time half for literal vocabularies; this catches runtime values and casts. Prose it retires: the "lead with an empty option" rule apps restate in comments and view tests.
