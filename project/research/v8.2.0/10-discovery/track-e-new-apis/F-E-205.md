# Swap verbs lack a targeted .onChange, so 4 apps hand-roll 17 change triggers and stem-50 forks core

## Problem

`.onChange(route)` always morphs `#main-content`. When a control's change must refresh only a sibling region, a full-content morph would land on the control the user is still holding. This is the case for a score panel, an autosaving editor, or a file input that uploads on select. `.search` already has a targeted overload for exactly this reason, but `.onChange` does not. Apps fall back to two workarounds:

- `trigger: "change"` in the route options of `.fragment`/`.submit`, which the guidelines name as the thing never to hand-roll.
- Raw `setHtmx`.

stem-50 copied the template's core file and added the overload itself.

## Evidence (executed)

- **Per-file divergence** (blob match against all template history): `swap-verbs.ts` is genuinely modified in 4 of 15 apps.
  - stem-50 is the only one with an API change: the targeted overload plus `options`, 62 diff lines.
  - The other three apps change comments only.
- **Hand-rolled census** (app-authored lines, comments stripped):
  - everyframe-composer: 14 `trigger: "change"` bags, 8 of them upload-on-select with `encoding: "multipart/form-data"`.
  - sportoawards: 1, inside `.fragment`.
  - home-page: 1, raw `setHtmx` with target and `sync: "replace"`.
  - stem-50: 1 raw `setHtmx` debounced autosave, plus 3 calls to its fork.
  - Total: 17 hand-rolled sites in 4 apps, plus 3 fork calls.
  - Every hand-rolled route is POST, so form collection still works. The cost is the bypassed verb (no `{ invalid }` routing, no stance check), not a dropped field.
- **Compile and render** (`verbs/probe.ts`, stem-50's swap-verbs.ts against fluent-html 8.1.0 dist):
  - `tsc` exit 0.
  - `@ts-expect-error` holds for a wrong-id target and for an undeclared page route aimed at a fragment target.
  - Rendered: `<select hx-post="/jury/entries/e1/score" hx-target="#score-summary" hx-swap="outerMorph" hx-trigger="change" hx-include="closest form" hx-indicator="#global-loading" hx-status:422="swap:outerMorph target:#score-form push:false">`.

## Why it matters

impact 2 x pain 2 x reach 2 / S = 8. The one sanctioned shape (a verb) is missing for a gesture 4 apps need. The workaround discards the fragment stance check that 8.1.0 and the template built for every other verb. Dimensions: decision-closure, prior-alignment.

## Rough idea (not a design)

Upstream stem-50's overload unchanged: `target` plus `FragmentRoute<NoInfer<N>>` plus `NeedsStance`, and `SwapOptions` on both arms. Then delete the prose caveat that `.onChange` goes untargeted. The type layer holds it. A debounce option (stem-50's autosave, 1 site) can wait for a second user.
