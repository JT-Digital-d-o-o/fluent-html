# Scroll containers have no typed snap or scrollbar calls

`$E7` = `<scratch>/track-e/E7`

## Problem

Every canonical scroll-snap rail also hides its scrollbar, and neither half has a typed call:

```ts
// competify/src/app/home/views/landing.components.ts:224-233 (Carousel)
Div(ForEach(items, (item) => Div(render(item)).cssProp("scroll-snap-align", "start")))
  .flex().gap("4").overflow("x", "auto")
  .cssProp("scroll-snap-type", "x mandatory")
  .cssProp("scrollbar-width", "none")
```

everyframe does the same through `.cssClass("hscroll")` and a hand-written rule (`styles.css:214-215`: `scrollbar-width: none` plus `::-webkit-scrollbar { display: none }`). Tailwind 4.3.0 added `scrollbar-none`, `scrollbar-thin`, `scrollbar-gutter-*`, `scrollbar-thumb-<color>` and `scrollbar-track-<color>` (588 classes), under the same names the pre-7 apps used through a plugin. fluent-html lists the whole `scrollbar` root as backlog in `IGNORED_ROOTS` (vocab-coverage.test.ts:59), and `snap` as pruned (:46).

Lint answers (eslint 4.1.0): `'scrollbar-none' ... is a Tailwind 'scrollbar-none-*' utility with no fluent method. Use .cssProp() for arbitrary CSS, or file the vocab gap`, and the same for `snap-x` and `snap-mandatory`. Method guesses: `.scrollbar("none")` -> `TS2551 ... Did you mean 'scroll'?`; `.snap("x")` -> `TS2339`.

## Evidence (executed)

- `node $E7/fam.mjs` (58 dedup repos):

| Family | TS sites | Authored CSS lines | Repos (canonical) |
|---|---|---|---|
| scrollbar | 27 (renderbox 13, jt-cut 3, rideshare 3, competify 2, ...) | 18 (buzzin, everyframe, jt-chess, planet-positive-sport, pregled-nepremicnin-dashboard) | 12 (3: competify, everyframe, everyframe-composer) |
| snap | 10 (competify 4, everyframe 2, glimm 2, jt-cut 2) | 2 (everyframe) | 4 (2: competify, everyframe) |

- Pre-7 class strings use the 4.3.0 names verbatim: `scrollbar-thin` (gzs/inovacije, jt-chess, jt-cut), `scrollbar-thumb-[#6FA63F]`, `scrollbar-thumb-border-ui`, `scrollbar-track-transparent`.
- Dates: first `scroll-snap` commit competify 2026-09-16, everyframe 2026-09-03, both after the 2026-08-14 prune.
- Canonical values: `scroll-snap-type` x mandatory 3; `scroll-snap-align` start 2, center 1; `scrollbar-width` none 3. All map to `snap-x snap-mandatory`, `snap-start`, `snap-center`, `scrollbar-none`.
- Sketch (`$E7/lib` + `$E7/probe2`): the restored snap overloads and the four scrollbar methods compile on tsc 5.9.3 and 6.0.3; `@ts-expect-error` on `.scrollbar("hidden")` and `.snap("x", "strict")` holds. Render: `snap-x snap-mandatory`, `snap-start`, `scrollbar-none`, `scrollbar-thin scrollbar-thumb-[#6FA63F]`. Tailwind 4.3.3 returns a rule for each.

## Why it matters

impact 2 x pain 1 x reach 3 / M = **3**.

- evolvability: a Tailwind release added a first-party family the fleet already used by name, and the watch parked it.
- prior-alignment: the prior writes `scrollbar-none` / `snap-x`; both end in a generic hatch message.
- pain stays 1: cssProp works for `scrollbar-width` and `scroll-snap-*`; the thumb/track colors need a two-value `scrollbar-color` declaration by hand.

## Rough idea (not a design)

Type layer, additive. Restore the 8.0.0 snap rows (`snap`, `snapAlign`; `snapStop` has 0 demand) and add `scrollbar`, `scrollbarGutter`, `scrollbarThumb`, `scrollbarTrack` rows (color rows reuse the theme color union like `accent`). Delete the two IGNORED_ROOTS entries. No prose added.
