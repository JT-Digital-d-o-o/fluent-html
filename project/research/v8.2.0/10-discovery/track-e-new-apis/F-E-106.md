# No timer behavior for transient feedback

## Problem
An older template emitted `hxResponse(view).trigger("showToast", { message })` after uploads and deletes. That code is vendored into 27 repos, but nothing in the template, the behavior pack or 26 of those 27 repos listens for `showToast`. The header is sent and dropped.

The current template deleted its own emitters with a comment saying exactly that. As a result it now gives no transient confirmation at all.

The one canonical app that built a toast, gzs/stem-50, could not dismiss it client-side:
- App JS is banned.
- The behavior event table is closed.
- A keyframe fade needs hand-written CSS (see [[F-E-103]]).

So the toast fetches its own removal: `trigger: load delay:4s` → GET `/ui/toast/dismiss` → empty region. That costs one request per toast. Its integration tests assert the dead `showToast` header too.

## Evidence (executed)
- **grep over every repo** (`.ts`/`.js`/`.html`, node_modules, dist and .claude skipped):
  - 54 `trigger("showToast"` sites in 27 repos, 18 of them in 9 canonical repos.
  - 19 other mentions: comments, tests, one design mockup, and jt-vault's inline `document.body.addEventListener("showToast", …)`. jt-vault is pre-7 and its listener is an inline script.
- **gzs/stem-50 `toast.ts`:**
  - 91 lines plus a dismiss route.
  - 4 toast emits in 3 controller/service files.
  - Its header comment (:4-12) records why each client-side path was closed.
- **Feasibility inside today's fence:**
  - `FxCtx.after(ms, f)` is an element-scoped timeout (`define.ts:50`).
  - Extension verbs can bind `afterSwap` (home-page registers `jt:navLit` and `jt:rise` that way).
  - The lifecycle walk starts at `detail.elt` and climbs (`runtime.ts:446-448`), so the carrier must sit on an ancestor of every trigger (the layout root). There it re-scans the region, the same shape home-page's `jt:rise` uses.
  - No core change and no S-21 reopen is needed.

## Why it matters
- **Score:** impact 2 × pain 2 × reach 2 / M(2) = 4.
- **Silent:** 26 repos ship a feedback path that never shows, and their tests pin the dead header.
- **No supported pattern:** the template has no transient-feedback pattern, so each app either builds a server round-trip or drops the feature.

## Rough idea (not a design)
- Add `jt:dismiss` to the template pack, with an optional `animateOut` that reuses the core `remove` verb's transition fallback.
- Deliver toasts as `Partial(toastRegion, Notice(...))`: SSR-first, no HX-Trigger payload contract.
- Delete the vendored `showToast` emitters with a template sync.
- The toast markup stays user-land (src/shared/ui), honoring L-411.
- Enforcement: runtime, plus an acceptance-matrix fixture (ADR-07 requires fixtures).
