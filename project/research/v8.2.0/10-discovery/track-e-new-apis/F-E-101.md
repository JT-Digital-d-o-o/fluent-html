# Read-only accessors getId() and getName()

## Problem
The template's FormGroup (vendored into every scaffolded app) wired label and control by reading the control's name back off the Tag:

```ts
function inputName(input: Tag): string | undefined {
  const name = (input as { name?: unknown }).name;
  return typeof name === "string" ? name : undefined;
}
...
Label(label).setFor(fieldId), input.setId(fieldId)
```

8.0.0 made every storage field protected and `_`-prefixed. The cast bypasses the type check, so the read compiles, lints and returns `undefined`. `setFor(undefined)` emits no `for`, and `setId(undefined)` actively removes the id that `Form<T>`'s `f.input()` had stamped. Result in home-page at 8.1.0:

```html
<form><div><label>Display name *</label>
<input type="text" name="name" value="Ann"></div></form>
```

The template later fixed its own copy by making `name` a required prop that restates the field name (the comment says the value is private, so any reader is an internal). Apps that synced before that fix still ship the broken copy. A third app reads the private `_id` / `_name` directly.

## Evidence (executed)
- **AST/grep over the 58-repo dedup corpus** (scratch `funcs.jsonl`, cast regex):
  - The `inputName` cast is defined in 23 repos: 12 canonical, 11 pre-7.
  - everyframe-composer has a second shape, `controlFieldId`, which reads `_id` / `_name` through `as unknown as`.
- **FormGroup call sites that pass neither `htmlFor` nor `name`**, so they rely on the read:
  - Broken today at 8.1.0: competition 26, fl-um 17, home-page 15, sportoawards 11. That is **69 sites**.
  - Working only because the field is still public at 7.0.0: workshop-toni 26 (checked with `node -e`: `'name' in Input().setName('x')` is true at 7.0.0).
  - Pre-7 repos that break on upgrade: varnoska 17, storysell-system 21, storysell-system-define-feature-exp 21, workshop-alenka 19, workshop-sasa 19, jt-present 10, jtdigital-blog 9, tetstesttes 10, home-page-define-feature 15.
  - At risk on upgrade: 167 sites in total.
- **Runtime renders (tsx against each repo's own installed fluent-html):**
  - home-page `FormGroup({ input: f.input("name") })` renders `<label>` with no `for`. The input has no `id`, because the binding's id was cleared.
  - competition renders the same output.
- **Silent:** home-page `tsc --noEmit` exits 0 and `eslint` on both files exits 0.
- **Workaround cost:** gzs/stem-50 uses the fixed template FormGroup and restates the name at 45 of its 48 calls (`name: "title"` plus `f.input("title")`). 1 of those 48 deliberately differs: a composite date field.
- **What a guess gets today:** `Input().getName()` and `.getId()` fail with TS2551 "Did you mean 'setName'?" (scratch `tprobe/probe.ts`). The heal points at the setter, not at a read.
- **Sketch:** monkeypatched `getId`/`getName` over the existing storage fixes all three input shapes (`f.input`, `.setName`, an explicit `setId`):

  ```html
  <label for="email">…<input id="email" …>
  <label for="bio-2">…<textarea id="bio-2" name="bio">
  ```

## Why it matters
- **Score:** impact 3 × pain 3 × reach 3 / S = 27.
- **Impact:** an accessibility contract (label-to-control association) is lost on every form field of 4 shipped apps.
- **Pain:** it compiles, lints and renders. No layer flags it. It surfaced only by rendering.
- **History:** the 8.0.0 CHANGELOG predicted this case: "a new legitimate read should become a library accessor, not a cast". This is that read, measured.
- **Dims:** silent-failure, invariant-safety, prior-alignment (the agent heal steers to `setName`).

## Rough idea (not a design)
- Add `getId()` on Tag and `getName()` on the named-control subclasses, read-only, next to the existing `getClass()` and `getEnctype()`.
- Template FormGroup reads `input.getId() ?? input.getName()` and drops the duplicated `name` prop.
- Extend `codemod:storage-fields` to rewrite the `(x as { name?: unknown }).name` cast.
- Enforcement: type. The accessor exists, and a cast into `_`-storage can be flagged by a lint rule on `as { _\w+` / `as { name?: unknown }`.
- Prose deleted: the template comment explaining why the name is restated.
