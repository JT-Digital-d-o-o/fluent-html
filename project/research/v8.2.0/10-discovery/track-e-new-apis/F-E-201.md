# Form<T> binding has no field hint, so 56 hints in 9 apps are never linked to their control

## Problem

`Form<T>` links the label (`for`) and the error (`aria-invalid` plus `aria-describedby`) to the bound control. It has no member for the third standard part of a field, the hint. Apps write the hint as a plain sibling paragraph, so a screen reader never announces it with the control. The obvious manual fix also fails. `setAria` overwrites per key, so `.setAria({ describedby: "email-hint" })` replaces the `email-error` id the binding wrote. The error message then stops being announced, with no diagnostic.

## Evidence (executed)

- **Census (15 canonical apps, app-authored code):**
  - 56 literal `hint: "..."` arguments in 9 apps: stem-50 25, popri 8, everyframe-composer 7, sportoawards 4, home-page 3, studio 3, fl-um 2, wsfas 2, workshop-toni 2.
  - 106 hint props or declarations in 11 apps.
  - `describedby` appears once in app code, and that hit is a comment.
  - 10 apps define their own field wrapper that renders the hint as an unlinked `P(hint)` (see F-E-202).
- **Probe** (`probe-hint-before.mjs`, run against 8.1.0 dist):
  - Case A, today's shape: `<input ... aria-describedby="email-error">` followed by `<p>We only use it for receipts</p>`. The hint is not linked.
  - Case B, the manual link: `<input ... aria-describedby="email-hint">`. The error span `email-error` is now orphaned.
- **Prototype** (scratch copy of the lib):
  - `hint()` keeps a per-name registry of bound controls and patches them when called, so it works before or after the control.
  - Output: `aria-describedby="email-hint email-error"`. A hint called before the control gives `aria-describedby="email-hint"`. A radio group links every option to `plan-hint plan-error`.
  - `tsc` rejects a misspelled field name (`@ts-expect-error` holds).
  - `node --test dist/test/forms.test.js dist/test/form-for.test.js`: 74/74 pass.

## Why it matters

impact 2 x pain 2 x reach 3 / S = 12. This is an accessibility gap that compiles, lints and renders. The one in-system fix (`setAria`) silently breaks the error link that 8.x shipped on by default (L-032). Dimensions: silent-failure, invariant-safety, decision-closure.

## Rough idea (not a design)

Add `hint` to `FormBinding<T>`, typed by `keyof T` like every other member. The type layer holds the field name. The runtime holds the id join (hint first, then error). It needs no prose beyond one line in the Form<T> section of fluent-html.md. Lockstep: the template's field wrapper (F-E-202) consumes it.
