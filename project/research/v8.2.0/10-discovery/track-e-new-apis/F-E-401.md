# A rejected submit has no checked exit

($E4 = <scratch>/track-e/E4)

## Problem

The template types the success half of a swap (renderPage, renderFragment with RootedView<N>) but leaves the
validation half to the uncontracted renderView (answer.ts:32-34). So every form handler writes the same fork by hand:

```ts
function renderInviteRejected(request, reply, user, invite) {
  reply.code(422).renderView(isHtmxRequest(request) ? InviteForm({ state: invite }) : TeamPage({ user, listing, invite }));
  return reply;
}
```

The 4 in-repo agents wrote it under the same name (copied from sign-in.controller.ts:26), and the pure prior (pp2)
reinvented it from scratch with `request.headers["hx-request"] === "true"`. Nothing checks that the htmx half is
rooted at the id the call site's `{ invalid }` names, or that the no-JS half is a Layout page.

## Evidence (executed)

- **Agent runs** (recon 02 Team task, 6 runs; E4's 4 new runs were denied by the permission classifier, see overflow):
  5/6 hand-wrote the fork (blind1:33, blind2:34, guided1:114, guided2:103, pp2 handlers.ts:46-53); pp1 skipped the no-JS half.
- **Fleet** (`$E4/corpus.py`, app-authored corpus of 58 repos, a ternary on `isHtmxRequest(` within 300 chars of `code|status(4xx)`):
  42 sites / 21 repos (canonical era 36 / 15). App-authored (outside src/app/auth and templates/): **23 sites / 8 repos**
  (canonical 21 / 6: gzs/stem-50 x8, na-cent x5, everyframe-composer x2, fl-um x2, website-sales-funnel x2, stojnica x1, ...).
  Every one is the same named helper shape (`renderCreateRejected`, `renderRejected`, ...).
- **Prototype** (`$E4/proto`, scaffold 6f63b33 + guided1's feature applied, `$E4/proto.diff`): a 9-line decorator + an
  8-line type; guided1's controller drops its 16-line helper and 3 imports.
  - `npx tsc --noEmit`: 0 errors.
  - Negative probes (`$E4/zz-probe.keep.ts`), each a compile error today's renderView accepts:
    region rooted at another id: `Type 'Tag & Rooted<"members-panel">' is not assignable to type 'RootedView<"invite-form">'`;
    unrooted region: `Property '[__rootIdBrand]' is missing in type 'Tag'`;
    page that is not a Layout: `Property '[pageResponse]' is missing in type 'Tag & Rooted<"invite-form">'`.
  - `vitest --project integration tests/integration/team.test.ts`: **6/6 pass**, including "rejected htmx invite answers 422
    with the invite card alone" and "rejected no-JS invite answers the whole page".

## Why it matters

impact 2 (an unrooted 422 view strands every later submit, F-B-107's Chromium run) x pain 2 (clean compile, visible only on
the second rejected submit) x reach 3 (every form; 5/6 runs) / S = 12. Moves invariant-safety (the last unchecked
answer in a form flow) and decision-closure (one exit instead of a copied helper).

## Rough idea (not a design)

Enforcement layer: type (RootedView<NoInfer<N>> + PageResponse on the two thunks). Thunks, so the page half's extra queries
run only for no-JS posts. If C-54 lands the region on the route def, the decorator can read it from the route instead of
taking `id`. Deletes answer.ts:32-34's "unchecked" paragraph and the sign-in comment block that explains the fork.
