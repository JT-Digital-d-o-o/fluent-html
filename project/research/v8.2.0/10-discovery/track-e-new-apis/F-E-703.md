# Table border model has no method

`$E7` = `<scratch>/track-e/E7`

## Problem

The template's own analytics table writes its border model through the hatch, so every scaffold starts with it:

```ts
// projects-template/templates/full-stack/src/app/analytics/views/cohorts.view.ts:222-223
.cssProp("border-collapse", "separate")
.cssProp("border-spacing", "2px")
```

Tailwind spells these `border-separate border-spacing-0.5`. The eslint plugin already believes the typed spelling exists and autofixes into it, but the types reject it:

| Guess | eslint 4.1.0 | tsc 6.0.3 on the fixed code |
|---|---|---|
| `Table().addClass("border-collapse")` | `Replace with: .border("collapse"). [autofix]` | `TS2769: No overload matches this call` (9 lines, the union printed twice) |
| `Table().addClass("border-spacing-0")` | `Replace with: .border("spacing-0"). [autofix]` | `TS2769: No overload matches this call` |
| `Table().borderSpacing("0")` | n/a | `TS2339: Property 'borderSpacing' does not exist on type 'Tag'` |

After the autofix, eslint reports 0 messages and tsc fails: the lint and the types disagree about one name.

## Evidence (executed)

- `node $E7/fam.mjs` (58 dedup repos; class strings, cssProp, setStyle/setStyles, authored CSS):

| Slice | Sites | Repos |
|---|---|---|
| canonical, app-authored TS | 22 (17 cssProp, 5 setStyle) | 9: everyframe 7, everyframe-composer 4, competify 2, popri 2, projects-template 2, sportoawards 2, studio 2, fluent-html-home-page 1 (+ home-page CSS) |
| of which the template's cohorts pair | 14 | 7 copies |
| pre-7 class strings | 8 | 4: renderbox 3, jt-vault 2, vabilo30 2, varnoska 1 |
| authored CSS | 4 | home-page, jtdigital-blog, planet-positive-sport, pm-gui |

- Values: `border-collapse` separate 8, collapse 1; `border-spacing` 2px 7, 0.25rem 1. All map to `border-separate`, `border-collapse`, `border-spacing-0.5`, `border-spacing-1`.
- Sketch (`$E7/lib` + `$E7/probe2`): `"collapse" | "separate"` added to the first `border()` overload and a `borderSpacing` method. The template rewrite `Table().border("separate").borderSpacing("0.5")` compiles on tsc 5.9.3 and 6.0.3 and renders `class="border-separate border-spacing-0.5"`. Tailwind 4.3.3 returns `border-collapse: separate` and the border-spacing rule for both.

## Why it matters

impact 2 x pain 1 x reach 3 / S = **6**.

- error-quality: the plugin's one-shot fix fails tsc with a 9-line TS2769.
- prior-alignment: `border-collapse` is a static Tailwind utility under the merged `border` prefix, like `border-dashed`, which `.border()` already takes.
- reach: the hatch ships in every scaffold through the template.
- pain stays 1: the cssProp form works.

## Rough idea (not a design)

Type layer, additive. Add `collapse` and `separate` to the merged `.border()` value family, and a `borderSpacing` row for the compound `border-spacing` prefix (the `textShadow` precedent). The plugin re-derives and its existing fix starts compiling; `border-spacing-*` moves from `.border("spacing-0")` to `.borderSpacing("0")`. The template's cohorts view becomes the exemplar. No prose added.
