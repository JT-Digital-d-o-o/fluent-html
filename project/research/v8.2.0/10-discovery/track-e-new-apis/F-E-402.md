# No field shell for Form<T> in the component layer

($E4 = <scratch>/track-e/E4)

## Problem

The template's only field shell, `FormGroup({ label, input, name })`, predates the typed binding. It renders its own
`Label().setFor(name)`, calls `input.setId(name)` (form.ts:37) and has no error slot. Wrapping a bound control in it
overwrites the binding's prefixed id and never renders the message, while the control still carries the binding's
`aria-describedby` pointing at an element that does not exist. RFC-C-04 deletes packages/ui, whose `FormField` was the
only shell with an error slot, and moves only `selectStyle`. So every feature with a validated form writes its own shell.

## Evidence (executed)

- **Agent runs** (recon 02, 6 runs; E4's 4 new runs were denied, see overflow): 5/6 wrote a named shell (blind1:415
  InviteField, guided1:482 Field, guided2:404 InviteField, pp1 formField, pp2 textField + roleField); blind2 repeated
  `Div(Label("Name", f.input(...)), f.error("name"))` inline 3 times (feature.patch:384-386). 0/6 used FormGroup.
- **Rendered** (`npx tsx` in `$E4/proto`): `Form<Req>({ values, errors: { email: "Enter a valid email" }, idPrefix: "invite" },
  f => [FormGroup({ label: "Email", name: "email", input: f.input("email", "email") })])` emits
  `<label for="email">` + `<input id="email" ... aria-invalid="true" aria-describedby="invite-email-error">` and **no**
  element with id `invite-email-error`, and no message text.
- **Fleet** (`$E4/corpus.py`, app-authored): FormGroup wrapping `f.input|select|textarea|checkbox(` at **440 sites / 23 repos**
  (canonical 149 / 7); FormGroup total 646 / 42 (193 / 16). 42 of the wrapped sites sit in 11 files that bind `errors`
  (canonical 38 / 5); 7 of those 11 files render `f.error(` separately, by hand, next to the FormGroup.
- **Prototype** (`$E4/proto.diff`): the `Field` in api_sketch compiles (tsc 0); rendered with the same state it emits
  `<label for="invite-email">`, `<input id="invite-email" ... aria-describedby="invite-email-error">` and
  `<span id="invite-email-error">Enter a valid email</span>`. `name: "emial"` fails with
  `TS2820: Type '"emial"' is not assignable to type '"name" | "email"'. Did you mean '"email"'?` (T is inferred from the
  direct `f` prop, one level, not through a wrapper chain).

## Why it matters

impact 2 (validation messages silently missing, aria-describedby dangling) x pain 2 (tsc, lint and the css build are
clean; only a screen reader or a 422 in the browser shows it) x reach 3 (5/6 runs, 23 repos) / S = 12. Moves
silent-failure and decision-closure (one shell instead of a helper per feature).

## Rough idea (not a design)

Add `Field` to src/shared/ui/form.ts built from the binding's own `f.label` / `f.error`; either retire FormGroup's
`setId` (codemod over the 440 bound sites) or restrict FormGroup to unbound inputs. Enforcement: type (keyof T on `name`),
plus a template lint that flags `FormGroup({ input: f.* })`. Lets the guideline's hand-composed field example go.
