# The brand focus ring as typed calls

($EG = <scratch>/track-e/E-gaps)

## Peer capability

- **Tailwind 4**: `outline-2 outline-accent outline-offset-3` is the documented focus ring; `outline-<width>`, `outline-<color>` and `outline-offset-<n>` are all first-class.
- **fluent-html 8.1.0**: `.outline()` takes only the 5 style keywords; `.ring()` (a box-shadow) is the only typed focus indicator. The brand book asks for an outline.

## Problem

The brand book makes the ring part of the brand ("The accent focus ring (`outline: 2px solid accent, offset 3px`) is part of the brand", guidelines/brand-book/CLAUDE.md:176). There is no typed way to write it, so apps either hand-write CSS (home-page styles.css:191-192, na-cent styles.css:34-35) or spell it through `cssProp` with a raw `var(--color-...)` (website-sales stylers.ts:69-76; popri canvas.components.ts:369-374, whose comment says "`outline-offset` has no styling method at all"). A cssProp value is a string: a renamed theme token is not a compile error there. The lib's own oracle test samples `outline("2")` (test/vocab-validity.test.ts:131), so the class is known valid and the type forbids it.

## Evidence (executed)

1. **Design corpus**: 31 distinct outline width, color or offset tokens, 406 occurrences, 5 canonical repos (everyframe, home-page, studio, popri, sportoawards). Compiling every eslint-plugin 4.1.0 autofix chain for the 4,301 mapped design tokens (`$EG/design/emit.cjs`, theme tokens augmented so only real gaps remain): the outline family fails tsc on 8.1.0; on the prototype 282 occurrences compile, and the other 118 are `outline-offset-*` that the 4.1.0 autofix spells `.outline("offset-2")`, which compile once eslint re-derives from the new `outlineOffset` row (RFC-C-01's contract).
2. **TS hatches**: 6 cssProp outline / outline-offset sites in 2 canonical repos, both with comments naming the gap; 46 `focus`/`focusVisible` ring styles elsewhere are the fallback.
3. **Prototype** (`$EG/lib` + `$EG/vocab-probe`): the outline row becomes a group (style | width | color, like ring), plus an `outlineOffset` row; `gen:vocab --check` OK; the brand ring renders `focus-visible:outline-2 focus-visible:outline-accent focus-visible:outline-offset-3`, popri's target ring renders `target:outline-2 target:outline-primary target:outline-offset-4`; `Div().outline("7")` is a compile error. Every emitted class passes the 4.3.3 oracle.

## Why it matters

impact 2 (the focus indicator is an a11y requirement the brand pins; today it lives outside the typed class contract), pain 2 (apps write CSS or untyped cssProp and say so in comments), reach 2 (design use in 5 repos, code workarounds in 4). Hurts prior-alignment and decision-closure.

## Rough idea (not a design)

Two vocab changes: widen the outline row to style | width | color (the merged-prefix pattern ring already uses) and add `outlineOffset`. Watch the merged-prefix collision class (a theme color token named like a style keyword) that the defineTheme cluster tracks. Prose: the brand book's CSS phrasing can point at the typed ring; net guideline lines do not grow.
