# No timed dismiss in the behaviors runtime

($E4 = <scratch>/track-e/E4)

## Problem

A toast ("Task deleted", gone after a few seconds, with a close button) is the feedback half of E4's task (d). The close
button is covered (`.behavior("remove")`). The timer is not: every built-in verb fires from a delegated user event in a
closed table (events.ts:23-36), lifecycle verbs walk only the ancestors of the request's trigger (runtime.ts:365-386), and
the guidelines ban app JS and hand-written CSS. Apps therefore fake the timer with a server round-trip or break the CSS rule.

## Evidence (executed)

- **Agent run**: E4's task (d) run was denied (see overflow), so recurrence here is from the fleet, not from transcripts.
- **Fleet** (`rg` over the 58 repos): 7 auto-dismiss sites in 5 repos, three workarounds:
  - server round-trip: `trigger: load delay:${TOAST_SECONDS}s` to a `/ui/toast/dismiss` route that answers the empty region
    (gzs/stem-50, 8.1.0, toast.ts:86), the same with `click, load delay:${duration}ms` (gzs/inovacije x2, pregled-nepremicnin);
  - hand-written CSS: a `.toast` keyframe ending on `visibility: hidden` in styles.css (storysell-system + its exp copy).
  - Two comments name the gap: stem-50 toast.ts:4-12 ("The usual ways ... a setTimeout or a CSS keyframe, and both are
    unavailable here") and storysell-system form.ts:105-106 ("the behaviors pack has no timed auto-dismiss verb").
  - Demand without a receiver: `.trigger("showToast", ...)` at 54 sites / 27 repos (canonical 18 / 9), a listener in 1 repo
    (jt-vault, pre-7); the template removed its copy because nothing listened (files.controller.ts:49-51).
- **Prototype** (`$E4/libcopy`, `$E4/timed-remove.diff`: 1 option in map.ts + specs.ts, a 7-line sweep in runtime.ts):
  - Size (`node scripts/build-behaviors.mjs`): baseline 5977 B min / 2671 B gz; with the option **6149 B min / 2729 B gz**,
    i.e. +172 / +58, which exceeds the 6144 B min budget by 5 B and stays inside the 2816 B gz budget.
  - Chromium (`node $E4/rt/toast-probe.mjs`, lib beta6 and template 4.0.0 bundles, `afterMs: 400`): toast present at +100/150 ms
    and gone at +600/650 ms for **3/3 deliveries** (first paint, outerHTML swap into #toast-region, `Partial(ids.toastRegion, ...)`
    riding a #main-content answer) on **2/2 bundles**, no console errors.

## Why it matters

impact 2 (each toast costs a request plus a route, or a CSS rule the guidelines forbid) x pain 2 (an agent following the
rules cannot build it and stops at a dismiss-only toast) x reach 2 (5 repos, 1 canonical, plus 9 canonical repos firing a
toast event into the void) / M = 4. Moves decision-closure and evolvability.

## Rough idea (not a design)

Runtime enforcement with a type on the option (`afterMs?: number`). M, not S, because the min budget needs either 5 B of
golf or the ADR-12 amendment build-behaviors.mjs:44-45 already flags. With it, a toast is `Partial(ids.toastRegion, Toast(...))`
from any handler plus one option: no endpoint, no CSS, no listener contract (so L-404's receiver objection does not apply).
