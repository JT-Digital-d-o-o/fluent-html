# A filter form costs one verb per control, and the one-call guess is dead

($E4 = <scratch>/track-e/E4)

## Problem

The template's `.search` is input-shaped: `trigger: input changed delay:300ms`, `include: "this"` (swap-verbs.ts:337-350).
A filter form therefore needs `.search(route({ include: "closest form" }))` on every text input, `.onChange(route())` on
every select and `.submit(route())` on the form so Enter does not fall through to a native GET reload (the template says
so itself at event-log.view.ts:75 and payments.admin-list.view.ts:61). Forget the include and the other filters drop out of
the request; forget the `.submit` and Enter reloads the page. The one-call shape agents reach for, `Form(...).search(route)`,
compiles (the verb is on every Tag) and is dead: `changed` compares `form.value`, which is undefined (htmx.js:819-828).

## Evidence (executed)

- **Agent runs** (recon 02, 6 runs; E4's dashboard run was denied, see overflow): 4/4 in-repo runs put `.search` on the
  input and repeated the same route in a second verb on the enclosing form for Enter (blind1:351/353, blind2:339/341,
  guided1:558/562, guided2:492/496), each with a comment explaining why; 4/4 also grepped htmx.js for `collectFormData` /
  `closest("form")` to learn what a GET sends. The pure prior (pp2 views.ts:131) wrote the one-attribute form trigger
  `input delay:250ms, submit`, the shape proposed here.
- **Fleet** (`$E4/corpus.py`, app-authored): 40 filter forms (same file + same route carrying `.search`/`.onChange` and ≥2 verbs)
  in 16 repos (canonical 33 / 11) spend **130 verb calls**; 13 forms / 6 repos are app-authored outside the vendored
  analytics and payments modules. **48 of 57** `.search` sites restate `include: "closest form"` (canonical 43 / 49).
- **Chromium** (`node $E4/rt/filter-probe*.mjs`, Playwright, lib htmx 4.0.0-beta6 and template 4.0.0; form with a search
  input and a status select; gestures: type "abc", select "paid", Enter):

  | Variant | type abc | select paid | Enter | URL after |
  |---|---|---|---|---|
  | A template 3-verb (include restated) | 1 req, all fields | 1 req, all fields | 1 req, no reload | unchanged |
  | D agent pair (no include) + plain select | 1 req `?q=abc` (status dropped) | **0 req** | 1 req | unchanged |
  | C naive `submit, input changed delay, change` on the form | **0 req** | 1 req | 2 req + AbortError in console | unchanged |
  | F shipped verb `Form(...).search(route)` | **0 req** | **0 req** | **native full-page GET** | changed by reload |
  | E prototype receiver-aware `.search` on the form | 1 req, all fields | 1 req, all fields | 1 req, no reload | `?q=abc&status=paid` |

  Identical on both bundles. The prototype (`$E4/proto.diff`, 12 lines in swap-verbs.ts, tsc 0) emits
  `hx-trigger="submit, input delay:300ms target:\"input:not([type=checkbox]):not([type=radio]), textarea\", change target:\"select, input[type=checkbox], input[type=radio]\"" hx-replace-url="true" hx-sync="replace"`.

## Why it matters

impact 2 (dropped filters, page reload on Enter, filters lost on reload) x pain 2 (tsc and lint clean; visible only in a
browser) x reach 3 (16 repos, 4/4 runs) / S = 12. Moves silent-failure (the dead guess becomes the working path),
prior-alignment (pp2's own shape) and decision-closure (one verb per filter form).

## Rough idea (not a design)

Runtime enforcement inside the verb: a FormTag branch in `p.search`, same name, no type change. The input branch stays for a
lone box. `replaceUrl: true` makes reload and shared links keep the filters (the dashboard requirement), worth a row in the
htmx grammar contract test. Deletes the two "Enter in the search box" comment blocks and the `include: "closest form"`
paragraphs in swap-verbs.ts and the htmx guideline.
