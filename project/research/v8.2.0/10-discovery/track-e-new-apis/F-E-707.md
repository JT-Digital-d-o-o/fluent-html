# transform-origin has no method

`$E7` = `<scratch>/track-e/E7`

## Problem

fluent-html ships `rotate`, `scale` and `transform` but not the origin they turn around. The canonical sites write it through the hatch next to typed transform calls:

```ts
Div().hidden().absolute().neg("top-px").left("0").h("px").w("full").cssProp("transform-origin", "left")   // everyframe ts-sdk-motion.view.ts:664
```

`Div().addClass("origin-left")` -> eslint 4.1.0 `'origin-left' ... is a Tailwind 'origin-*' utility with no fluent method. Use .cssProp() for arbitrary CSS, or file the vocab gap`; `Div().origin("left")` -> `TS2339`.

## Evidence (executed)

- `node $E7/fam.mjs` (58 dedup repos): 36 sites in 10 repos. TS: 7 in 4 repos (everyframe 3, workshop-toni 1, planet-positive-sport 2, tela 1). Authored CSS: 29 lines in 7 repos, 22 of them in storysell-system and its scratch copy, which weakens the CSS count.
- Canonical values: left 2, center 1, bottom left 1; 4/4 map to `origin-left`, `origin-center`, `origin-bottom-left`.
- Sketch (`$E7/lib` + `$E7/probe2`): `.origin("left")`, `.origin("bottom-left")` compile on tsc 5.9.3 and 6.0.3 and render the classes; Tailwind 4.3.3 returns `transform-origin: 0` and `0 100%`; `@ts-expect-error` on `.origin("middle")` holds.

impact 1 x pain 1 x reach 2 / S = **2**. The cssProp form works and the canonical TS reach is 2 repos; filed because L-159 asked for the sweep to be re-run and this is its measured result. Lowest of the E7 set.
