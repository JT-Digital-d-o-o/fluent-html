# Handlers parse htmx 4's HX-Target by hand

## Problem

htmx 4 sends `HX-Target` and `HX-Source` as `${tag}#${encodeURI(id)}` (htmx 4.0.0 `#buildIdentifier`, unchanged since alpha7). htmx 2 sent a bare id. The template knows this and wrote a parser, `hxTargetId` (server.ts:394), but kept it module-private. Apps that need the same answer re-derive it:

- competify and na-cent copied it verbatim into `demo.plugin.ts`. Their comment cites the template function as module-private.
- workshop-toni wrote an `endsWith("#main-content")` variant (family.plugin.ts:20).
- time-to-live kept the htmx-2 shape, `request.headers["hx-target"] === hoursIds.hoursAdminResults.id` (hours.admin.controller.ts:119), while serving htmx 4.0.0-alpha7. That compare can never be true, so the "results region only" branch is dead and the filter answers a full page into the region.

History restore is a second header shape no reader models. On Back, 4.0.0 sends `hx-history-restore-request: true` plus `hx-request-type: full` with no `hx-request`, and beta6 sends only the restore header. The template's own fixture (render-context.test.ts:88) sends `hx-request: true` with it, which matches neither bundle.

## Evidence (executed)

- **Census** (`g.mjs` over the 58-repo dedup corpus, `.ts`, tests excluded):
  - 30 raw reads of `hx-target`, `hx-source` or `hx-current-url` across 21 repos.
  - 15 are vendored template `server.ts` copies, one per template-derived repo.
  - 15 are app-authored in 8 repos: jt-vault 5, planet-positive-sport 4, and 1 each in competify, na-cent, workshop-toni, home-page, time-to-live and rideshare. The canonical app-authored ones are 4 sites / 4 repos.
- **Runtime oracle** (`oracle.mjs P2`; beta6 and 4.0.0). A button `#b` with `hx-target="#hours-admin-results"` sends:
  - `hx-target: div#hours-admin-results`, `hx-source: button#b`, `hx-request-type: partial`, `hx-current-url: http://probe.test/`
  - A form submit sends `hx-target: form#f`.
  - Results:

    | Reader | Result |
    |---|---|
    | time-to-live compare | `false` |
    | template `hxTargetId()` | `hours-admin-results` |
    | workshop-toni `endsWith` | `true` |

- **Restore headers** (`p6.mjs`, `out-p6.json`): `/b` via a `.nav`-shaped link, then `history.back()`. The restore GET carries:
  - 4.0.0: `{hx-history-restore-request: true, hx-request-type: full}`
  - beta6: `{hx-history-restore-request: true}`
- **Sketch** (`tpl/src/core/htmx/hx-request-info.ts`; tsc exit 0 against fastify and fluent-html 8.1.0):
  - Fed the captured headers, `hxTargets(req, hoursIds.hoursAdminResults)` returns `true` where the bare compare gives `false`.
  - The restore shape yields `{htmx: false, type: "full", historyRestore: true}`, and `form`-only targets yield `targetId: null`.
  - `hxTargets(req, "hours-admin-results")` is a consumed `@ts-expect-error`, so a string id does not compile.

## Why it matters

impact 2 x pain 2 x reach 2 / S = 8.

- **silent-failure:** a branch is dead with no error.
- **invariant-safety:** the region a request swaps into is the request-side half of the render-stance contract (`RenderTagged`). Today the handler can only reach it by string surgery, and only by copying private code.

## Rough idea (not a design)

Export `hxRequestInfo` and `hxTargets(request, id: Id)` from the template's htmx-request.ts, then re-express `hxTargetId` and `isHtmxRequest` on them. Typing the id parameter as `Id` makes the htmx-2 compare unwritable (type layer), and fixing the restore fixture keeps the tests honest. No lib change.
