# Motion tokens have no typed seam

`$E7` = `<scratch>/track-e/E7`

## Problem

Tailwind 4 names animations and easings through the `--animate-*` and `--ease-*` theme namespaces, and the canonical apps declare them in `@theme`. fluent-html types colors, spacing, fontSize, radius, shadow, fonts and the shadow families through `FluentCustom*` seams, but `TailwindAnimate` and `TailwindEase` are closed with no seam (tailwind-types.gen.ts:180, :293). So a declared token cannot be named, and authors copy its value into an arbitrary literal:

```ts
// everyframe/public/css/styles.css:144   --animate-scan: scan 8s linear infinite;
.animate("[scan_8s_linear_infinite]")             // everyframe home.view.ts:896
// website-sales-funnel styles.css:79      --animate-mk-ignite: mkIgnite 0.62s var(--ease-brand) both;
.animate("[var(--animate-mk-ignite)]")            // layout.components.ts:88
.ease("[cubic-bezier(.2,.7,.2,1)]")               // na-cent, 5 sites: the brand book's one easing
```

The lint path closes into a loop: `Span().addClass("animate-mk-ignite")` -> eslint 4.1.0 `Replace with: .animate("mk-ignite"). [autofix]` -> tsc `TS2345: Argument of type '"mk-ignite"' is not assignable to parameter of type 'TailwindAnimate'`.

## Evidence (executed)

- `node $E7/rawgrep.mjs 'arbMotion=...'` over 58 repos: 15 canonical app-authored arbitrary sites in everyframe (8), na-cent (5), home-page (1), website-sales-funnel (1), plus the website-sales-funnel layout bridge in `src/core/layout` = 16.
- Restated tokens: everyframe declares `--animate-scan`, `--animate-grain`, `--animate-cut` and restates all three as arbitrary values (home.view.ts:111, :896; marketing.components.ts:86), with `.cssClass("grain")` as an extra hook (:80). website-sales-funnel bridges `--animate-mk-ignite` and `--ease-brand` through `var()`; its stylesheet comment explains the bridge.
- Brand easing: `guidelines/brand-book/CLAUDE.md:134` mandates one easing, `cubic-bezier(.2, .7, .2, 1)`; na-cent writes it as a literal 5 times.
- Token declarations in canonical authored CSS (`$E7/css-authored2.json`): 9 `--animate-*` (everyframe 3, website-sales-funnel 6) and 1 `--ease-*`; 8 canonical repos keep `@keyframes` in hand-written CSS.
- Sketch (`$E7/lib`): a `FluentCustomAnimate` seam added to `TailwindAnimate` and exported; `declare module "fluent-html" { interface FluentCustomAnimate { "mk-ignite": true } }` makes `Span().animate("mk-ignite")` compile on tsc 5.9.3 and 6.0.3, while `@ts-expect-error` on `.animate("mk-ignit")` holds. Render: `class="animate-mk-ignite"`. Tailwind 4.3.3 with the app's `@theme` returns `animation: var(--animate-mk-ignite)`, and with `--ease-brand` returns `transition-timing-function: var(--ease-brand)` for `ease-brand`.

## Why it matters

impact 2 x pain 2 x reach 2 / M = **4**.

- decision-closure: one token, two spellings (the token in CSS, its value restated in TS) that drift independently.
- error-quality: the lint's fix for a declared token does not compile.
- prior-alignment: `animate-<token>` is the Tailwind 4 spelling for a theme animation.

## Rough idea (not a design)

Type layer, additive, tokens only. Add `FluentCustomAnimate` and `FluentCustomEase` seams to the two unions, `animate` and `ease` families to `ThemeSpec`, and two rows to the extractor's `CSS_NAMESPACE` and manifest tables (lockstep: extractor). `@keyframes` stay in the app's CSS, so defineTheme stays a token emitter. No prose added beyond the existing seam pattern.
