# defineTheme has no animation tokens

## Problem
The house rule bans hand-written CSS, and `defineTheme` is the sanctioned way to add design tokens. But `ThemeSpec` covers only colors, spacing, fontSize, radius, shadow and fonts. `.animate()` accepts only Tailwind's 4 built-ins plus `[arbitrary]`.

An app that wants its own motion therefore writes `@keyframes` in `public/css/styles.css` and references it in one of two ways:
- an untyped arbitrary string: `.animate("[rulein_520ms_cubic-bezier(.16,1,.3,1)_both]")`
- a hand-written class plus `cssClass`

A misspelled keyframe name in either path compiles and renders an element that never animates.

website-sales did exactly what `defineTheme` would do, by hand:
1. It wrote `@theme { --animate-mk-ignite: …; @keyframes mkIgnite {…} }` in its stylesheet.
2. The closed union then rejected `.animate("mk-ignite")`, so it fell back to `.animate("[var(--animate-mk-ignite)]")`.

gzs/stem-50 went further. Its toast dismissal became a server round-trip because "a `@keyframes` block would require [hand-written CSS], since `defineTheme` covers tokens only, not animations".

**Tailwind 4.3.3 executed** (`theme-anim.mjs`: prototype `themeToCss` → `@tailwindcss/node` compile):
- `--animate-rise` plus a nested `@keyframes rise` inside `@theme` yields `.animate-rise { animation: var(--animate-rise) }` and `md:animate-rise`.
- Only used keyframes ship: `idleSway` was declared and dropped.

**Type sketch** (a copy of `dist` d.ts with a `FluentCustomAnimate` seam, `ThemeSpec.animate/keyframes`, and the union widened):
- `Div().animate("rise")` and `Div().md({ animate: "rise" })` compile.
- `Div().animate("rsie")` fails with TS2345 "not assignable to parameter of type 'TailwindAnimate'".

**Today:**
- `Div().animate("rise")` fails with TS2345.
- `animate:` in a ThemeSpec literal fails with TS2353 (scratch `tprobe/probe.ts`).

## Why it matters
- **Score:** impact 2 × pain 2 × reach 3 / M(2) = 6.
- **What it closes:** a house-rule violation present in half the canonical fleet, and an untyped string channel where a typo animates nothing.
- **Follow-on:** once keyframes live in the theme, scroll-driven reveals need only the `.cssProp` widening of [[F-E-104]]. That absorbs home-page's `jt:rise` IntersectionObserver verb.

## Rough idea (not a design)
- **Library:**
  - Add the Tailwind v4 `animate` namespace and a `keyframes` map to `ThemeSpec`.
  - Add a `FluentCustomAnimate` seam that `TailwindAnimate` includes.
  - Add a define-time warn when an animate token's first word names neither a declared keyframe nor a built-in, next to `warnOnAmbiguousTokens`.
- **Extractor:** emit both inside `@theme`, and add the `animate` manifest prefix.
- **Enforcement:** type for the token, boot/ci through `gen:vocab --check` for the union.
- **Gate:** if curation reads keyframes as outside "tokens-only" (v6 defineTheme design), the `animate` half alone still removes the arbitrary strings, and the lane becomes decision-gated for the keyframes half.
