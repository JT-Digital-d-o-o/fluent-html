# `cond && value` cannot bind in IfThen, IfThenElse, .when or .whenElse, though the runtime handles it

## Capability
`IfThen(job.status === "FAILED" && job.error, (e) => P(e))`: one expression that guards on a condition and binds a nullable value, the shape the React prior writes (`{cond && <X/>}`). The runtime already does the right thing: `typeof false === "boolean"` takes the condition branch (src/control/conditionals.ts:34, :69; src/core/tag.ts:299, :321), so `then` never receives `false`. The overloads still type the bound value as `T` (`false | string`), so the call fails inside the callback.

## Problem
Verbatim, fluent-html 8.1.0 (`$E6/proto/before/sketch-before.ts`):
```
sketch-before.ts(5,56): error TS2345: Argument of type 'string | false' is not assignable to parameter of type 'View'.
  Type 'boolean' is not assignable to type 'View'.
sketch-before.ts(8,69): error TS2345: Argument of type 'NonNullable<string | false>' is not assignable to parameter of type 'string'.
```
5/5 forms fail (IfThen, IfThen with a status comparison, IfThenElse, .when, .whenElse). The error lands on `Span(b)` inside the callback and names no fix. The fleet writes the longer coerce-bind instead: `IfThen(job.status === "FAILED" ? job.error : null, (error) => ...)` (fl-um/src/app/redaction/views/redaction.components.ts:39), `IfThen(props.hasMore ? props.nextCursor : null, (cursor) => ...)` (website-sales-funnel-automation-system/src/shared/ui/timeline.components.ts:276).

Runtime, executed on the built prototype: `IfThen(false && "Pro", ...)` -> `<div></div>`, `IfThen(true && null, ...)` -> `<div></div>`, `IfThen(true && "Pro", ...)` -> `<div><p>badge:Pro</p></div>`, `.when(false && "T", ...)` -> no title, `.when(true && "T", ...)` -> `title="T"`. `true && ""` runs the branch (L-065 semantics, unchanged).

## Evidence (executed)
- AST census (`$E6/scan3.mjs`, app-authored, 58 repos): `IfThen/IfThenElse(cond ? value : null, (v) => ...)` 219 fleet / 56 canonical (32 distinct) in 14/16 canonical repos, plus 198 / 81 length coerce-binds (F-E-601). `IfThen/.when(a && b, (v) => ...)` with a callback parameter: 0 fleet sites (`$E6/scan5.mjs`): the short form is absent because it does not compile.
- Typed dry run (`$E6/anddry.mjs`, each app's TS 6.0.3, d.ts redirected per run): 120 canonical `IfThen/IfThenElse/.when/.whenElse(c ? v : null, f)` sites; 112 have a boolean-typed `c`. Rewriting those 112 to `c && v` (78 files, 13 repos): 157 new diagnostics against the shipped 8.1.0 .d.ts (TS2322 `'false | CohortRetentionResult' is not assignable`, TS2769, TS2339 `Property 'points' does not exist on type 'false'`), 0 against the prototype.
- Regression check (`$E6/fleetcheck.mjs`): shipped HEAD .d.ts vs prototype .d.ts over 15 canonical apps (4,890 files, 2,610 conditional sites): 0 diagnostics added, 0 removed. `$E6/sanity.mjs` proves the redirect (65 mapped .d.ts reads; an in-memory probe using `IfThen(ok && b, (s) => Span(s))` in the competition app compiles with 0 diagnostics).
- Prototype (`$E6/proto/lib`): lib + test tsc 0 errors, 410/410 runtime tests; `$E6/proto/after/sketch.ts` keeps both pins: an optional boolean is still rejected, and `IfThen(isAdmin && count, (n) => Span(n))` is still an error (n: number is not a View).
- Agents (`$E6/agent/`, 3 blind runs): JobError 3/3 used a workaround, 0/3 wrote `&&`: run1 `Match(job.status, { FAILED: () => IfThen(job.error || null, ...) }, () => "")`, run2 the same with `() => Empty()`, run3 `IfThen(job.status === "FAILED" ? job.error : null, ...)`.

## Why it matters
impact 2 x pain 1 x reach 3 / effort S(1) = 6. The type is dishonest (a value the callback can never receive is in its parameter type) and the failure surfaces inside the callback with no fix named. Pain stays 1: the ternary workaround is short and no fleet or agent site was caught writing `&&`. Dims: prior-alignment, error-quality.

## Rough idea (not a design)
Type layer only: `Exclude<T, false>` (IfThen/IfThenElse) and `Exclude<NonNullable<T>, false>` (.when/.whenElse) on the value-overload callbacks; implementation bodies cast the callback (4 lines). Pin `cond && value` narrowing and the unchanged rejections in test/types. Land with C-10 (same four gates, message literal) so the signatures change once. Open: also reject `true | V` (`cond || value`), where the runtime calls `then()` with no argument; 0 fleet sites measured, so not proposed.
