# Form<T> control values are bare string: an option, radio or hidden value the bound field cannot take compiles clean

## Problem

`FormBinding<T>` constrains every field **name** to `keyof T`, but every **value** is `string` (`src/elements/forms.ts:436,446,451,453,454`). A value the field can never take compiles and ships.

competify at `e7448d0^`, the route and the filter bar it serves:

```ts
// src/app/organise/organise.routes.ts:3
const ideaFilters = { department: "string", status: ["DRAFT", "SUBMITTED"], q: "string" } as const;
// src/app/organise/views/organise.ideas.view.ts:106-108
f.select("status", [
  { value: "", label: c.allStatuses },
  ...IDEA_STATUSES.map((status) => ({ value: status, label: statusLabel(status) })),  // incl. SCREENED, RETURNED
])
```

The fix commit (`e7448d0`, "filter bars answered 400 on an unset select and on the new idea statuses") says both filter bars "refused ordinary use". The same shape sat in `judge.list.view.ts:116-117` (`scored: "yes" | "no"` with a `""` option). The view's `Form<IdeaFilters>` type already said `status?: "DRAFT" | "SUBMITTED"`; the binding just never looked at it.

The repair tooling the fleet wrote is runtime: competify pins the enum in `tests/unit/filter-queries.test.ts:20-22`; wsfas wrote a 62-line markup parser (`tests/unit/support/form-controls.ts`) so a view test can refuse "a select option outside its vocabulary".

## Evidence (executed)

Scratch root `track-e/E5/` under the run scratchpad. TypeScript 5.9.3. `lib-base` = 8.1.0 dist copy; prototypes patch only `dist/src/elements/forms.d.ts`.

1. **Type probe** (`probe-p6.ts`, 5 `@ts-expect-error` lines). 8.1.0: 5 TS2578 "Unused '@ts-expect-error'", so all 5 wrong literals compile: `radio("opt", "c")` on `opt?: "a" | "b"` (the exact L-113 killer), a `""` option on a required union field, `hidden("n", "forty")` on a number field, `checkbox("tags", "z")` on `("x" | "y")[]`, and the competify stale status list. Sketch: 0 errors (5/5 rejected), while runtime-built `{ value: string }[]` options, a `string` radio value and a generic-T `hidden` all compile.
2. **The incident commit** (`git archive e7448d0^`, node_modules overlay, `tsc --noEmit`). 8.1.0: 0 errors. Strict variant (p1, single signature, no blank admission): 3 errors, exactly the 3 sites the fix changed. Blank-strict overload variant (p3): 2. Shipping variant (p6): 1, `organise.ideas.view.ts(108,7) TS2322 ... Type '"SCREENED"' is not assignable to type '"" | "DRAFT" | "SUBMITTED"'`. The `""` half is handled at runtime by F-E-502.
3. **Fleet break** (`tsc-diff.sh`, each of the 16 canonical repos type-checked against 8.1.0 and the prototype, new errors only). p1 strict: 30 new errors in 10 of 15 repos, all helper-built `{ value: string }[]` lists or generic helpers (type-only, no runtime bug), which is why the shipping form admits unprovable strings. p3: 9 in 5 repos (8 are the template's `payments.admin-list.view.ts:44,53` `""` options, vendored in 4 repos, where the view type `PaymentFilters` lacks the `""` its typebox querystring admits; 1 home-page). p4 and p6: **1 new error in 1 of 16**: `home-page/src/app/content-panel/views/content-panel.components.ts:60`, `f.radio("visibility", visibility)` inside `<T extends VisibilityReq>`, where `T["visibility"]` is deferred. Fix at the site: type the helper's binding as `FormBinding<VisibilityReq>` or pass the value as `string`.
4. **Error quality.** The recorded agent guess (8.2.0 `_overflow.md:113`: Option tags passed to `f.select`) keeps its 8.1.0 first line, `TS2739 Type 'OptionTag' is missing ... value, label`. An overload encoding (p3/p4) pushed it to line 3 under TS2769; the single-signature encoding does not.
5. **Census** (`scan.py`, app-authored canonical code): `f.select` 80 sites in 12 of 16 repos, `f.radio` 24 in 7, `{ value: "", label }` options 40 in 11.

## Why it matters

impact 3 × pain 2 × reach 3 / M = 9. The bug class (a select vocabulary that disagrees with the field or the route) 400s every live search or posts a value the server refuses; today only a runtime test or QA finds it. Dimensions: invariant-safety, silent-failure, error-quality.

## Rough idea (not a design)

Type layer, additive: `FieldValue<T, K>` strips `undefined`/`null` before distributing, maps numbers and booleans to their template-literal spellings and arrays to their element, and admits `""` for optional keys (true only together with F-E-502). `Checked` lets a non-literal `string` through, so helper-built lists keep compiling. For checkbox, map a boolean field to `string` so RFC-A-07's valued boolean boxes stay legal (0 fleet sites hit this in p6, but the runtime contract allows it). Guardrail 4 note: generic helpers over a field union fail closed (the 1 measured site); the breaking-change lens rules whether that site rides 8.2.0 or the change waits for 9.0.0. Pin both directions in `test/types/`. Prose it retires: the README's "values are strings" framing of `f.select`.
