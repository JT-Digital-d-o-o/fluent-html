# htmx-2 event names compile and never fire under htmx 4

## Problem

htmx 4 renamed every lifecycle event to the colon form (`htmx:after:settle`, `htmx:before:swap`). It also dropped some outright (`htmx:beforeSend`, `htmx:sendError`, `htmx:timeout`). Client code still written with htmx-2 names compiles, lints clean and is never called.

In workshop-toni (canonical, 7.0.0, serving 4.0.0-beta4) `src/app/story/client/story.ts:193-194` registers `mount` on `htmx:afterSettle` and `onPageTurn` on `htmx:afterRequest`. Neither handler runs after any swap. The same class sits in 5 more repos serving htmx 4 alpha7 (jt-cut, jt-draw, jt-draw2, renderbox, ttl), 19 sites in all. 0 of the 6 repos load a compat extension.

Types do not help. htmx 4.0.0's `htmx.d.ts` types `HtmxEventMap` and augments `DocumentEventMap`, but both `addEventListener(type: string, ...)` and `htmx.on(event: string, ...)` keep string fallbacks.

## Evidence (executed)

- **Census** (`mine.mjs` then `ev.mjs`):
  - Served versions were read from `public/js/htmx.min.js` or the CDN pin in `src`.
  - The 6 htmx-4 repos have 19 listener sites with htmx-2 camelCase names (bundled duplicates excluded).
  - The 4 htmx-2 repos (buzzin, cms, jt-chess, jt-vault) are correct as written.
- **Runtime** (`oracle.mjs P3`; beta6 and 4.0.0). Capture listeners were registered for 14 names, then a 200 swap and a 500 swap ran:
  - `htmx:afterSettle`, `htmx:afterRequest`, `htmx:afterSwap`, `htmx:beforeSwap`, `htmx:beforeSend`, `htmx:sendError` and `htmx:responseError` fired 0 times.
  - `htmx:after:settle`, `after:request`, `after:swap`, `before:swap` and `before:request` fired 2 times each, and `htmx:response:error` fired 1 time.
  - alpha7 core (`npm pack htmx.org@4.0.0-alpha7`) contains 0 htmx-2 names.
- **Types** (`evprobe/probe.ts`, `tsc` with DOM lib against htmx.org 4.0.0's own `.d.ts`):
  - `document.addEventListener("htmx:afterSettle", ...)` and `htmx.on("htmx:afterSettle", ...)` both compile (exit 0).
  - `const x: keyof HTMLElementEventMap = "htmx:afterSettle"` gives `TS2820 ... Did you mean '"htmx:after:settle"'?`. The information exists and only a checked channel is missing.
- **Derived rule** (`evrule/htmx-event-name.cjs`, run through ESLint 8 Linter with @typescript-eslint/parser on the 10 client files):
  - The allowed set is 30 `HtmxEventMap` keys plus 36 names dispatched by `dist/ext/*.js`. The compat shims are excluded, since they contain the old names.
  - Result: 19 reports in 6 files, 0 reports on the 10 correct sites in 4 repos (planet-positive-sport, rideshare, jtdigital-landing-page, storysell-ai).
  - 16 of 19 messages carry a did-you-mean, for example `"htmx:afterSettle" is not an htmx 4.0.0 event, so this listener never fires. Did you mean "htmx:after:settle"?`. The other 3 (`beforeSend`, `sendError`, `timeout`) have no 1:1 successor.

## Why it matters

impact 2 x pain 3 x reach 2 / S = 12.

- **silent-failure:** dead handlers produce no error anywhere.
- **verification-loop:** the only signal is a human noticing that audio or a sidebar did not update. The scan already recorded the ttl instance (htmx4-capability-scan.md, "Two live bugs"). The pain is 3 because nothing in tsc, lint or runtime ever reports it.

## Rough idea (not a design)

One eslint-plugin rule whose name set is computed from the installed `htmx.org` at lint time, so it never drifts. That answers L-409's objection. The enforcement layer is lint. It lets the template drop any prose list of event names, and C-85 can reuse the same derivation for config keys.
