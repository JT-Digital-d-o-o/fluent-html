# Template FormGroup re-stamps the bound control's id, so 10 apps re-implement Field and idPrefix forms emit duplicate ids

## Problem

The template's only field wrapper is `FormGroup({ label: string, input: Tag, name: string })`. It renders its own `Label(label).setFor(name)` and calls `input.setId(name)`, because it cannot read the id the binding gave the control (form.ts:16-20 says so). This has two effects:

- **Duplicate ids.** Under `Form<T>({ idPrefix })`, the binding names the control `craft-comment`, and FormGroup renames it back to `comment`. Two rubric sheets on one page then emit duplicate ids, and the second label focuses the first textarea.
- **No hint or error slot.** The wrapper has neither, so apps write their own.

## Evidence (executed)

- **Duplicate-id probe** (`verbs/formgroup.ts`): two `Form<Sheet>({ idPrefix: "craft" | "story" })` forms through the vendored template FormGroup.
  - Output: `<textarea id="comment" ... aria-describedby="craft-comment-error">` and `<textarea id="comment" ... aria-describedby="story-comment-error">`.
  - `duplicate ids: [ 'comment' ]`. Both labels carry `for="comment"`.
- **Live occurrence:** competition renders 7 FormGroup calls inside idPrefix forms (judging.views.ts:130,138; entries.components.ts:62-74,95). Its fork derives the id from the input name and still calls `input.setId` (competition/src/shared/ui/form.ts:27,36).
- **Re-implementation census** (definitions in app-authored lines, template-origin lines excluded):
  - Field: 14 defs in 8 apps.
  - FormField: 3 in 3 apps.
  - FieldLabel: 4 in 3 apps.
  - Forked FormGroup: 4 in 4 apps.
  - Union of the above: 10 of 15 apps. A `fieldLabel` styler is also re-declared 25 times in 7 apps.
  - The template FormGroup is still called 177 times in 8 apps.
- **Sketch** (`lib/field-sketch.ts`, scratch build with F-E-201):
  - A Field taking `label: LabelTag` from `f.label` renders `id="craft-comment"` / `id="story-comment"`, `for` matching, and `aria-describedby="craft-comment-hint craft-comment-error"`.
  - `duplicate ids: []`.
  - `tsc` rejects `f.label("coment")`.

## Why it matters

impact 2 x pain 2 x reach 3 / S = 12. The template component teaches the one pattern that breaks the binding's id contract. Ten apps paid for their own wrapper, and the bug class is silent: valid HTML, no lint, no type error. Dimensions: silent-failure, decision-closure, context-economy.

## Rough idea (not a design)

Ship a `Field` in src/shared/ui/form.ts that only lays out pieces the binding produced (`f.label`, the control, `f.hint`, `f.error`), and retire FormGroup's `name` + `setId`. The type layer already checks every field name through `FormBinding<T>`. It needs no generics, so S-04's wrapper-inference dead end does not apply. In views.md, the FormGroup example can be replaced line for line.
