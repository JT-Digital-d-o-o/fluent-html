# Option values are untyped in the typed binding

($E4 = <scratch>/track-e/E4)

## Problem

`Form<T>` closes field **names** to `keyof T`, but not field **values**: `select(name, options: readonly SelectOption[])` with
`SelectOption = { value: string; label: string }` (forms.ts:436-446) and `radio(name, value: string)`. A role field typed
`"owner" | "admin" | "member"` accepts `{ value: "ownr" }`, and a select missing a member compiles. Every run also had a
label record (`ROLE_LABELS`) for the badge and the table, and had to adapt it into the array shape by hand.

## Evidence (executed)

- **Agent runs** (recon 02, 6 runs; E4's wizard run, with a plan radio group, was denied, see overflow): 4/4 in-repo runs
  built `{ value, label }[]` from `ROLE_LABELS` (blind1:287, blind2:293, guided2:327 via `.map`; guided1:393-397 as a literal
  array with a hand-written `satisfies readonly { value: MemberRole; label: string }[]` to get the closure the binding does
  not give). pp1/pp2 hand-built `Option` loops with `selected`.
- **Fleet** (`$E4/corpus.py`, app-authored): `.map(x => ({ value: x, label: ... }))` where value is the item itself:
  **34 sites / 11 repos** (canonical 30 / 8), 13 / 5 with an explicit label lookup (`STATE_LABELS[state]`, `roleLabel(role)`).
  Binding calls: `f.select(` 78 (30 inline arrays, 6 inline `.map`, 42 identifiers), `f.radio(` 31 / 9 repos (24 non-literal values).
  `SelectOption[]` annotations: 16 / 5 repos (8 / 4 canonical), the upper bound on array call sites the narrowing can break.
- **Sketch** (`$E4/sketch-select`, against the shipped dist, runtime shim over the real binding):
  - Positive block (record form, array form, optional union `plan?`, open `string` and `number` fields): `tsc` rc 0 on
    **5.9.3 and 6.0.3**; `node sketch.ts` renders `<option value="admin" selected>` from the record.
  - Negative block, 4/4 rejected, first diagnostics verbatim:
    `TS2820: Type '"ownr"' is not assignable to type 'NonNullable<"owner" | "admin" | "member">'. Did you mean '"owner"'?`;
    `TS2345 ... Property 'member' is missing in type '{ owner: string; admin: string; }'`;
    `TS2353: Object literal may only specify known properties, and 'guest' does not exist`;
    `TS2345: Argument of type '"platinum"' is not assignable to parameter of type 'NonNullable<"free" | "pro" | "enterprise" | undefined>'`
    (the optional union L-113 saw collapse to `string` stays closed).
  - Control: the shipped binding accepts both `f.select("role", [{ value: "ownr", ... }])` and `f.radio("plan", "platinum")`.

## Why it matters

impact 2 (a misspelled or stale option posts a value the server schema then rejects with a generic 400) x pain 2 (clean
compile) x reach 3 (4/4 runs, 11 repos) / M = 6. Moves invariant-safety, error-quality (the first diagnostic names the
literal) and context-economy (one call instead of an adapter per select).

## Rough idea (not a design)

Enforcement: type. 8.2.0 ships the record overload and the generic `SelectOption<V>` defaulting to `string` (additive for
every existing call); narrowing array values and `radio` values for literal-union fields can break the up-to-16 sites that
annotate `SelectOption[]`, so that half rides the 9.0.0 codemod with a measured dry run. Error text should print the union
without the `NonNullable<...>` wrapper. Deletes the guideline's `{ value, label }` adapter example.
