# No change-triggered fragment verb

## Problem
The guidelines say "never hand-rolled `trigger:` bags" and name `.onChange` as the verb for control changes. But the template's `.onChange(route)` accepts only a page route and always morphs `#main-content`.

An autosaving section, a slider whose summary updates, or a file input that uploads on pick all need a fragment target. Apps therefore pass `trigger` through the route options of `.fragment`:

```ts
.fragment(libraryIds.libraryBody, libraryRoutes.upload({ query, encoding: "multipart/form-data", trigger: "change" }))
.fragment(bind.target, { ...bind.route, trigger: AUTOSAVE })
```

gzs/stem-50 forked the framework file instead, adding `onChange(target, route, options)` with `include: "closest form"`. It is now the only canonical app whose `swap-verbs.ts` declares a verb the template lacks.

## Evidence (executed)
- **Signature diff** of `interface FluentCustomMethods` in all 15 canonical app `swap-verbs.ts` against the template:
  - stem-50 has +2 (both `onChange` overloads).
  - workshop-toni differs only by its pre-stance 7.0.0 signatures.
  - The other 13 are identical.
- **grep `trigger\s*:`** over canonical app code, classified by the receiving call. 20 change triggers sit on fragment swaps:
  - everyframe-composer 14: uploads ×8, addTake ×3, setColours, setEmphasisWords, subtitlesTune / saveCaption
  - sportoawards 4
  - gzs/stem-50 1 (autosave with `input changed delay`)
  - home-page 1
  - The remaining hits are non-htmx (service enums, comments).
- **Default-trigger reliance:** competify `judge.score.view.ts:149` puts `.fragment` on a range input and relies on htmx's default `change` trigger for inputs. That is one more site where the gesture is implicit.

## Why it matters
- **Score:** impact 2 × pain 2 × reach 2 / S = 8.
- **One gesture, three spellings:** a raw route option, a spread constant, and a fork. The forked file drifts from every future template verb fix.
- **`include` drift:** the route-option spelling silently drops the template's `include: "closest form"` default, so the request carries what the triggering element includes rather than the whole form.

## Rough idea (not a design)
- Upstream stem-50's overload: same stance types as `.fragment`, `include` defaulting to `closest form`, `SwapOptions` for the 422 target.
- Add a lint redirect: a template rule flags `trigger: "change"` inside a route call passed to `.fragment` and names `.onChange(target, route)`. That rule is the one prose line it replaces.
- Enforcement: type (stance) plus lint.
