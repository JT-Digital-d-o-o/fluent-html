# renderWithNonce does not stamp hx-nonce

## Problem

Every template-derived app ships a per-request-nonce CSP with `'strict-dynamic'` and no `'unsafe-eval'` (security-headers.ts:58-61). htmx 4 evaluates trigger filters (`keydown[key=='Enter']`), `js:` vals and `js:` confirm with `Function`/`AsyncFunction`, so under that CSP they throw. everyframe-composer's caption pad saves on `change, keydown[key=='Enter']` (projects.pad.view.ts:500). The Enter half never sends.

htmx 4.0.0 ships the remedy, `ext/hx-csp.js`, which does three things:

- It strips the `hx-*` attributes from any element whose `hx-nonce` differs from the page nonce.
- It promotes a same-origin response's CSP nonce, so swapped fragments rendered with their own request nonce work.
- With `safeEval:true` it runs htmx's eval through nonce'd script injection.

Nobody can turn it on today. `renderWithNonce` stamps the nonce only on `<script>`/`<style>`, so with hx-csp enabled every fluent-rendered htmx element is stripped.

## Evidence (executed)

- **Incident** (`p8.mjs`, `out-p8.json`; Chromium; beta6 and 4.0.0). The template CSP header, the composer's textarea shape, Enter pressed:

  | Setup | Requests | Console |
  |---|---|---|
  | Template CSP | 0 | `Evaluating a string as JavaScript violates the following Content Security Policy directive because 'unsafe-eval' is not an allowed source` |
  | Same element with `hx-nonce`, hx-csp and `safeEval:true` | 1 | `#out` becomes `saved` |

- **Gate** (`p4b.mjs`, `out-p4b.json`; beta6 and 4.0.0). Page and fragment are rendered by fluent-html under the template CSP. The page has a save button, the composer textarea, a fragment loader, and `Raw('<div id="gadget" hx-get="/evil" hx-trigger="load">')`:

  | Setup | Requests |
  |---|---|
  | Shipped 8.1.0, no hx-csp | `/evil, /save, /cap, /frag, /inner`: the gadget fires on load |
  | Shipped 8.1.0 + hx-csp | none: all fluent htmx stripped |
  | Prototype + hx-csp | `/save, /cap, /cap, /frag, /inner`: Enter and change both save, the fragment rendered with a different response nonce is promoted and its inner button works, the gadget is blocked |

- **Prototype** (`scratch/track-e/E3/lib`, a copy of 8.1.0 with node_modules symlinked; 13 changed lines in serialize.ts):
  - `renderWithNonce("N1", ...)` emits `<button ... hx-post="/save" hx-target="#out" hx-nonce="N1">`. Partial templates also get stamped, the Raw gadget stays unstamped, and `render()` is byte-identical.
  - `renderToStreamWithNonce` output equals `renderWithNonce`.
  - The compiled suites (stream, security, htmx, patterns, escape, elements, attributes, composition, control-flow, fuzz, routes, ids) pass: 748 tests, 0 fail.
- **Cost** (`bench.mjs`): median of 7 x 300 renders of a 200-row tree with 200 htmx buttons. `renderWithNonce` goes from 0.155 to 0.175 ms (x1.127). `render()` stays at 0.153 ms (x1.00).
- **Config**: `HtmxConfig({ extensions: "hx-csp", safeEval: true })` fails with TS2353 (`'safeEval' does not exist in type 'HtmxGlobalConfig'`), which ties into C-85.

## Why it matters

impact 3 x pain 2 x reach 1 / S = 6.

- The capability covers two things: htmx attribute injection through `Raw()` sinks (22 canonical app sites in 5 repos, including CMS HTML in home-page blog.article.view.ts:113), and every eval-dependent htmx feature under the shipped CSP.
- The reach is 1 because only 1 canonical incident is measured. The eval-dependent fleet sites are 3 trigger filters in 3 repos and 3 `js:` vals in 1 repo.
- **silent-failure:** the dead Enter-save.
- **evolvability:** htmx 4's security extension is unusable with fluent output.

## Rough idea (not a design)

Stamp `hx-nonce` beside the existing render-time nonce in both emitters. This is additive bytes on the nonce path only, and htmx ignores the attribute without the extension. Add `safeEval` to the typed config (C-85). Let the template layout load `hx-csp.js` with the config. The enforcement layer is runtime (the hx-csp gate), plus a template smoke row.

One design question remains for verification: an `hx-nonce` on a non-script element is readable by CSS attribute selectors, which browsers hide only for `script[nonce]`. Measure that against a per-request nonce before shipping.
