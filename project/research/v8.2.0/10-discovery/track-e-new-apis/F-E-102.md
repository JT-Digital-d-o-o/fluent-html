# FormBinding has no hint member

## Problem
Field components across the fleet take a `hint` prop and render it as a bare paragraph under the control:

```ts
IfThen(hint, (text) => P(text).text("xs").text("text-dim").m("t", "1"))   // gzs/stem-50/src/shared/ui/form.ts:42
```

The hint has no id and the control's `aria-describedby` never names it, so a screen reader announces the field without its help text. `Form<T>` already wires the error message this way (`markInvalid`, forms.ts:476-477), but there is no hint member.

The obvious user-land fix makes it worse. A component cannot read the control's current `aria-describedby` (no accessor, see [[F-E-101]]), so `setAria({ describedby })` replaces the error link.

## Evidence (executed)
- **AST count** (scratch `hints.mjs`) over canonical app code: `hint:` passed to a capitalized component in 64 call sites in 11 of 16 canonical repos.
  - 51 of them sit beside an `input`/`control`/`field` prop.
  - Callees: FormGroup 18, Field 18, TextField 9, StudioOption 4, StudioField 3, others 12.
- **grep `describedby|describedBy`** over canonical app code (core excluded): 1 hit. It is a comment in workshop-toni (`family.components.ts:110`) about `f.error`.
- **Render** of stem-50 FormGroup with a hint and an error:

  ```html
  <input id="title" name="title" aria-invalid="true" aria-describedby="title-error">
  <p>Do 120 znakov.</p>
  ```

  The hint is unlinked. everyframe-composer's FormGroup gives the same result.
- **User-land wiring attempt** (`probe-hint2.ts`): stamping `setAria({ describedby: "title-hint" })` on the control emits `aria-describedby="title-hint"`. The `title-error` link is gone.

## Why it matters
- **Score:** impact 2 × pain 3 × reach 3 / M(2) = 9.
- **Pain:** silent. No type, lint or runtime signal, and 0 of 51 are wired.
- **Reach:** 11 of 16 canonical repos.
- **Instruction-set check:** this is a wiring primitive with library-owned ids, the same category as the shipped `f.error` and `f.label`. It is not the FieldHint *component* that L-198 cut to user-land.

## Rough idea (not a design)
- `f.hint(name, ...children)` renders an unstyled element with id `${controlId(name)}-hint`.
- The binding composes `aria-describedby` as a list (hint, then error), so `markInvalid` appends instead of setting.
- Order independence: the binding records controls by name, so `f.hint` before or after `f.input` both link.
- Enforcement: type. The member exists and the name is constrained to `keyof T`.
- Teaching: the template's FormGroup takes `f` + `name` and renders `f.hint`. Its "hint" prose shrinks to the one member.
