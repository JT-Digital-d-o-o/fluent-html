# The setClass-family lint rules predate 7.0: 10 of 13 variant-then-setClass wipes pass silently, and 5 messages prescribe addClass or a nonexistent .children

## Problem
`setClass` replaces every class written before it. The template enables `no-setclass-after-fluent-modifier` and `no-setclass-in-when-apply-callback` at error, with the comment that they catch "a silent wipe of everything set before them". The rules still describe the 6.x surface:

- The modifier set is `VOCAB_METHODS` plus five hand-appended names, `"on", "at", "addClass", "apply", "when"` (gen-vocab.mjs:54-58). `.on`/`.at` were removed in 7.0.0 (`typeof Tag.prototype.on` is `undefined`). The 21 tier-1 variant methods (the lib exports them as `DIRECT_VARIANTS`), `.variant`, `.whenElse`, `.whenMatch` and `.cssClass` are absent: 25 class writers the rule does not see.
- The callback rule checks only `.when` argument 2 and `.apply` (`:32-36`), not `.whenElse`/`.whenMatch` branches.
- Five messages prescribe `addClass()` (4) or `.children()` (1). `addClass` is `@internal` ("not a styling API", tag.d.ts:85-93) and lint-blocked for Tailwind tokens; `.children` does not exist.

## Evidence (executed)
13 probes in a scaffolded template app; `tsc` 0 errors; template ESLint config; render against the 8.1.0 dist:

| Probe | Lint | Render |
|---|---|---|
| `.p('4').setClass('js-hook')` | error (after `.p()`) | `class="js-hook"` |
| `.when(ok, t => t.p('4')).setClass(...)` | error | `class="js-hook"` |
| `.p('4').when(ok, t => t.setClass('js-a'))` | error | `class="js-a"` |
| `.hover({ bg: 'primary' }).setClass(...)` | none | `class="js-hook"` (alone: `hover:bg-primary`) |
| `.md(...)`, `.focus(...)`, `.sm().lg().dark()`, `.variant('data-[state=open]', ...)`, then `.setClass` | none (4) | `class="js-hook"` |
| `.whenElse(...)`, `.whenMatch(...)`, `.cssClass('js-map')`, then `.setClass` | none (3) | `class="js-hook"` |
| `.p('4').whenElse(ok, t => t.setClass(...), ...)`, same with `.whenMatch` | none (2) | `class="js-a"` |

10/13 are silent on tsc, lint and a `NODE_ENV=development` render (no warning).

Advice probe (each rule's suggested rewrite, same config): `.p('4').addClass('mt-2')`, `.when(ok, t => t.addClass('font-bold'))`, `.when(ok, t => t.addClass('text-center'))` -> 3/3 `no-tailwind-in-raw-class` errors (`'mt-2' in .addClass() bypasses the typed surface. Replace with: .mt("2")`); `.when(ok, t => t.children(Span('a')))` -> `TS2339: Property 'children' does not exist on type 'Tag'`.

Reach: TypeScript AST scan of 6,093 canonical-era files (16 repos): 85 `setClass`/`setClasses` calls, 0 after any modifier, 0 inside `whenElse`/`whenMatch` callbacks.

## Why it matters
Silent failure: the classes vanish from the markup with tsc, lint and the dev runtime all green, in the exact shape the template config claims to block. Reach 1 today (0 fleet sites), so this is a latent hole with a wrong-fix message attached: an author who does hit the rules is sent to an internal method that the next rule rejects.

## Rough idea (not a design)
lint layer. Build the modifier set from the lib at load (`classVocab` + `DIRECT_VARIANTS` + the composition methods), dropping the hand list; treat `whenElse`/`whenMatch`/`variant` callbacks like `when`/`apply`; point the messages at `.cssClass()` (non-Tailwind hooks) and `IfThenElse` (ternary children). No prose.
