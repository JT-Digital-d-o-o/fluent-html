# The bench regression gate never runs and cannot see construction

## Problem
Guardrail 2 says bench regression is a verification input. The only automated form of that is `BENCH_GATE=1` in `bench/render.ts:250-266`, and it has two holes:
1. **It never runs.** `.github/workflows/test.yml:24-36` runs `npm ci`, `tsc --noEmit`, `build`, `gen:vocab --check`, `test:coverage`; `publish.yml` runs `npm test`; `docs.yml` runs typedoc. `grep -rn bench .github/` = 0 hits. Commit 297bb10 ("bench-in-CI") changed `bench/render.ts` and `dist/`, 0 files under `.github/`, while `project/pm/render-spine/todo.md:73` marks "Wire bench/ into CI" done.
2. **Its build+render floor does not build.** `for (const [name, make, floor] of FLOORS) { const view = make(); measure(name, () => render(view), 500) }`: `make()` runs once, outside the timed closure, so the "build+render realistic" row is a second render-only row.

The printed scenarios share the blind spot: 7 of 8 time `render()` of a tree built once; the one build+render scenario (`:227`) uses a page with 0 variant objects and 0 param'd routes. The two construction costs found in this run (F-D-401, F-D-402) sit outside every scenario. The memory section (`:181-188`) reports a `heapUsed` delta over 100 iterations, which a young-generation scavenge truncates.

## Evidence (executed)
- `NODE_ENV=production BENCH_GATE=1 SPIN=<n> node gate-probe.mjs`: imports the lib's own `dist/bench/render.js` unmodified after wrapping `Tag.prototype.addClass` with busy work (construction-only slowdown):
  - SPIN=0: printed "Build+render realistic (per req)" 18.51K ops/s; gate "build+render realistic" 33.99K (floor 2000), passes. The gate row is 1.84x the real per-request number.
  - SPIN=3000: printed Build+render drops to **631 ops/s (x0.034)**; gate rows "render realistic page" 34.08K, "build+render realistic" **33.70K**, "render flat" 6.46K: `✓ bench gate passed`.
- Memory section, `node --expose-gc dist/bench/render.js` x3 vs the same with `--max-semi-space-size=512 --min-semi-space-size=512` x3: "Flat page construction" 6,000.8 / 6,032.3 / 6,047.5 KB vs 38,367.4 / 38,690.8 / 38,660.9 KB (6.4x under-report); "Flat page render" 21,555.8 KB vs 54,065.9-54,116.8 KB (2.5x); realistic rows unchanged (6.7 MB both), because their allocation fits in one semi-space.
- What the current scenarios do show (5 interleaved reps each, `run-matrix.mjs` + `summarize.mjs`, load1 9.5-11.0 then 3.2-5.3): 8.1.0 vs 7.0.1 in production, paired medians x0.96-x1.02 on all 8 scenarios (Build+render realistic 17,590 vs 17,420 ops/s, the CHANGELOG's 7.0.1 figure was 17.2K/17.4K); heap rows within 1% across 7.0.1, 8.0.0 and 8.1.0; dev checks cost x0.87-0.92 on build+render (4 runs; 7.0.1 x0.90) and x0.95-1.00 on pre-built renders. So the bench reports "no regression since 7.0.1" while variant construction is 2.4x slower than pre-7.0 (F-D-401) and param'd routes take 40% of a list page (F-D-402).
- Spread under this run's load: 1.9% to 53.1% per scenario across 5 reps; paired interleaved ratios stay within ±4% where medians agree, which is why a relative, same-machine comparison works where an absolute floor cannot.
