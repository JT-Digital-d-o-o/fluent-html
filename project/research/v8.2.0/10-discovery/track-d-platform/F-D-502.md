# The lib tests its emitted grammar on htmx 4.0.0-beta6, a bundle only 2 of 16 canonical apps serve

## Problem
`htmx.org` is a devDependency of the lib pinned to `4.0.0-beta6` (package.json:131, commit c60a484). It is the bundle the acceptance matrix serves (`test/acceptance/app.mjs:32`): the only browser run of the behaviors runtime and the only executed check of anything fluent emits. The template moved to 4.0.0 on 2026-08-28 (bf4baca) and the fleet followed. The lib's matrix now certifies a runtime 2 of 16 apps run, and the runtime 13 of 16 apps run is never exercised by the lib.

The lib also declares 0 `peerDependencies`, so nothing tells a consumer that the emitted grammar (`hx-status:*`, `outerMorph`, `<template type="partial">`, `hx-config` JSON) targets htmx 4, while `npm install htmx.org` resolves `latest` = 2.0.11 (recon 02 D8: a pure-prior agent wrote an htmx 2.0.4 CDN tag and no layer caught it).

## Evidence (executed)
Served bundle per canonical repo (`version = '...'` read from `public/js/htmx.min.js`):

| Served | Repos |
|---|---|
| 4.0.0 | 13: competify, competition, everyframe, everyframe-composer, fluent-html-home-page, gzs/stem-50, home-page, popri, projects-template (full-stack), sportoawards, stojnica, studio, website-sales-funnel-automation-system |
| 4.0.0-beta6 | 2: fl-um, na-cent (both pin lib 9d86871 by sha) |
| 4.0.0-beta4 | 1: workshop-toni (lib 7.0.0) |

- `npm view htmx.org dist-tags`: `{ latest: '2.0.11', next: '4.0.0' }`; `time`: beta6 2026-07-23, 4.0.0 2026-08-28, no later 4.x.
- Re-ran the lib's acceptance matrix from a scratch copy of `test/acceptance` serving `projects-template/templates/full-stack/public/js/htmx.min.js` (4.0.0), port 4795, `CI=1`: `69 passed (19.2s)`, chromium.
- Recon 03 section 2.3 (same two bundles, 145 emitted names): 1 name changes behavior, `Partial('closest tr', ...)`, processed on 4.0.0 only (row 23). The bump fixes 1 mismatch and breaks 0 measured.
- `require('./package.json').peerDependencies` in the lib: `undefined`.

## Why it matters
Reach 3: every behaviors-runtime and grammar guarantee the lib makes is measured against beta6 while 13/16 apps and the template serve 4.0.0, and the two htmx.js files differ in 421 lines (recon 03), including partial-target resolution and the `ctx.sourceElement` re-pointing that feeds the runtime's `onAfterSwap`. Guardrail 10 says every emitted name exists in the pinned bundle; the pinned bundle is not the served one. Evolvability: each further htmx bump is a three-way skew (lib pin, template vendored copy, fleet copies) with no single constant.

## Rough idea (not a design)
8.1.x: bump the devDependency to 4.0.0 (emitted bytes unchanged; the matrix is green on it). Then make the pin one source that the lib matrix, the template `htmx:vendor` script and the template grammar-contract test all read (ci layer), and consider an optional `htmx.org: >=4 <5` peer (install-time warning, not a runtime dependency) so an htmx 2 install is flagged.
