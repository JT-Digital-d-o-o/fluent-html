# Playwright's WebKit is not a Safari oracle

`$R` = `<scratch>/wave1/D-reseed`

## Problem

This closes the critic's D gap. F-D-301 (closedby), F-D-307 (popover=hint) and F-D-308 (selectedcontent) took their Safari columns from BCD 8.1.3 alone, with no engine run behind them. F-D-301's own remedy, and L-261's open CI decision, both assume that adding Playwright's `webkit` project gives the matrix a Safari column.

Executed, it does not. Playwright ships trunk WebKit builds that carry features the shipping Safari lacks, and the set changes with each Playwright release:
- The lib pins `@playwright/test` 1.61.1, which brings WebKit 26.5 (r2311).
- npm latest 1.63.0 brings r2359 (labelled 26.6).

A backdrop-click assertion for `setClosedby("any")` fails on r2311, which is correct for Safari. It passes on r2359, which is wrong for Safari. A routine Playwright bump would therefore turn F-D-301's proposed row green while the Safari gap stands.

## Evidence (executed)

The same lib-rendered markup (`dist/` 8.1.0) runs on every engine:
- Playwright engines: `$R/wk-probe.mjs`.
- Safari's engine: `$R/syswk/probe.swift`, a WKWebView on the system WebKit framework, which is the engine Safari on this machine runs.

| Feature | Safari 26.6.2 engine (WebKit 21624.5.1.11.3, macOS 26.6.2 25G83) | PW WebKit 26.5 r2311 (lib pin 1.61.1) | PW WebKit 26.6 r2359 (npm latest 1.63.0) | PW WebKit 26.6 r2369 (1.64.0-alpha-2026-10-01) | BCD 8.1.3 Safari 27 |
|---|---|---|---|---|---|
| `closedBy` IDL | no | no | yes | yes | preview |
| backdrop click closes a `closedby="any"` dialog | n/a (reflection only) | **no** | **yes** | yes | n/a |
| `popover="hint"` reflects as | `manual` | `manual` | `hint` | `hint` | preview |
| `HTMLSelectedContentElement`; `<selectedcontent>` kept inside `<select>` | undefined; no | yes; yes, mirrors the selected option (`A Alpha` to `B Beta`) | yes | yes | 27 |
| `CSS.supports("appearance","base-select")` | false | true | true | true | n/a |
| Present (the 4 non-click rows) | **0/4** | **2/4** | **4/4** | **4/4** | |

Reference engines: Chromium 149 has 4/4. Firefox 151 has 2/4 (closedby, hint); its parser drops `<button>` and `<selectedcontent>` from the select (children `option, option`).

The same run reproduces these round-1 claims on all 3 Playwright WebKit builds, so each now holds on 3 engines:
- `setCommand("show-modal")` opens the dialog; system Safari reflects `command` too.
- `setPopovertarget` opens a popover from `Button` only; `A`, `Div`, `Span` and `Li` open 0/4 (F-D-302).
- The taught `anchorName` + `positionAnchor` pair and the implicit anchor give identical placement, top 219 / left 298 (F-D-305).
- `.behavior("onClickOutside", { action: "remove" })` on a closedby-less dialog deletes it on its own opening click (F-D-301's fallback claim).
- 4/4 ARIA 1.3 names reflect, system Safari included (F-D-303).
- The `autocorrect` IDL is present, system Safari included (F-D-306).
- `setHidden("until-found")`: fragment navigation to a descendant removes `hidden` on all Playwright engines; system Safari reflects `until-found`.

Limits:
- Synthesized NSEvent clicks in the WKWebView harness did not reach the DOM (control button 0/1), so the Safari 26.6.2 column is reflection-only. Where r2311 reflects `closedBy` as false, its real-input backdrop click is dead, which is consistent.
- Safari 27 is not installable on macOS 26.6.2, so its column stays BCD-only.

## Why it matters

impact 2 x pain 2 x reach 2. 21 `setClosedby` sites in 11 repos depend on a Safari answer, and the multi-engine decision L-261 is about to buy the wrong oracle.

- **verification-loop**: the engine CI would add reports Safari-absent features as working.
- **evolvability**: the answer flips on a devDependency bump nobody reviews for this.
- **silent-failure**: a green WebKit row on a gesture that is dead in Safari.

## Rough idea (not a design)

ci layer, 8.1.x. Keep two WebKit columns with different jobs:
- Playwright WebKit as the trunk preview.
- A Safari column from the system engine (a WKWebView probe on a macOS runner that records the Safari build) for platform-feature rows.

Pin Playwright exactly and record which WebKit revision each bump brings. The per-engine expected values for F-D-301's backdrop row come from the Safari column, not from "passes on webkit".
