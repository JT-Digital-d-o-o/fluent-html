# `location()` is typed against an HX-Location contract that no bundle implements

`$S` = `<scratch>/wave1/D1`.

## Problem

`HxLocationConfig` (`patterns.ts:156-166`) types 9 keys. htmx 4.0.0's own `HtmxAjaxOptions`, which the `HX-Location` JSON is handed to, has `push`/`replace`/`selectOOB` that fluent cannot express, and fluent's `handler` has 0 readers in any bundle. The string arm is passed verbatim (`patterns.ts:325`) and on beta4-beta6 a string containing a comma or whitespace is parsed as HCON options with no `path`.

## Evidence (executed)

Button posts, server answers with `hxResponse(Empty()).location(...).getHeaders()`, Chromium, 4 bundles:

| Header | beta4 / beta5 / beta6 | 4.0.0 |
|---|---|---|
| `/loc?tags=a,b` | `GET /undefined`, URL `/undefined`, page shows the 404 body | `GET /loc?tags=a,b`, URL `/loc?tags=a,b` |
| `/loc?q=a b` | `GET /undefined`, URL `/undefined` | `GET /loc?q=a%20b` |
| `{"path":"/loc","target":"#out","swap":"innerHTML"}` | `/loc`, history +1 | same |
| `{...,"replace":"/replaced"}` (key untyped in fluent) | URL `/loc`, history +1: replace ignored, push forced | URL `/replaced`, history +0 |
| `{...,"push":"false"}` (key untyped in fluent) | URL `/`, history +0 | same |

Mechanism: beta6 `htmx.js:688` routes any path matching `/[\s,]/` to `HCON.parse`, takes `opts.path` (undefined) and requests the string `undefined`; `:693` forces `push` even when `replace` is set. 4.0.0 `:657-663` parses, uses options only when `parsed.path != null`, and pushes only when neither `push` nor `replace` is given (release note #3939). A route-built URL is safe on every bundle (`resolve({ tags: "a,b c" })` -> `/r?tags=a%2Cb%20c`); the failure needs a raw string, which `location(config: string | …)` accepts.

## Why it matters

impact 2 × pain 2 × reach 1. Reach is low today: 0 `.location(` sites in the 16 canonical repos and the template. The defect is in the contract: the typed surface cannot say "navigate but replace history" although the runtime the template serves supports it, and it offers `handler`, which does nothing. On the lib's pinned runtime the raw-string failure is a navigation to `/undefined` with no console output.

## Rough idea (not a design)

Layer: type. Additive in 8.2.0: `push?: boolean | string`, `replace?: boolean | string`, `selectOOB?: string` (only meaningful after [[F-D-101]]). 9.0.0: delete `handler`; type the string arm and `path` as `ResolvedRoute | ExternalHref` like `setHref` (8.0.0 brand), which removes the raw-string path entirely. Generating the key list from htmx.d.ts is [[F-D-103]].
