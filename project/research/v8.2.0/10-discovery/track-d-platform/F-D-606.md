# The recommended preset ships rules the template dropped as unreachable, and 4 rules with no tests

`$R` = `<scratch>/wave1/D-reseed`

## Problem

Template 3.6.1 removed seven rules from its configs as having "no reachable target" (`projects-template/CHANGELOG.md:154-158`). The plugin's `recommended` preset (`src/index.ts:70-106`) still ships 6 of them:
- `no-unnecessary-spaces-in-setclass`
- `no-duplicate-classes-in-setclass`
- `no-conflicting-classes-in-setclass`
- `no-empty-setclass`
- `no-conditional-in-setclass`
- `prefer-nav-for-internal-links`

The set diff is 30 recommended rules vs 24 in the template config, with 0 template-only.

`prefer-nav-for-internal-links` is the clearest case. It matches only `A(...).setHref("/literal")` (`src/rules/prefer-nav-for-internal-links.ts:60-80`), and since 8.0.0 that call is TS2345 (`ResolvedRoute | ExternalHref | undefined`). The plugin's own peer is `fluent-html >=8.0.0` (`package.json:47`). So the only code the rule can fire on either fails tsc or sits outside the plugin's supported range. Its fix text names `.nav(route)`, a template-owned verb: `A("Settings").nav(r.index())` is TS2339 on bare fluent-html 8.1.0.

The suite does not see this, because the rule's 3 invalid fixtures (`test/rule.test.js:1682-1697`) all fail tsc against 8.1.0. Separately, 4 recommended rules have no test case at all, with 0 references in `test/` (only README and `src/index.ts`):
- `no-multiple-setclass-in-chain` (error in recommended and in the template)
- `no-duplicate-classes-in-setclass`
- `no-empty-setclass`
- `no-unnecessary-spaces-in-setclass`

## Evidence (executed)

**Fleet run** (`$R/rules/navfleet.mjs`: ESLint 10.11.0 `Linter`, `@typescript-eslint/parser`, plugin 4.1.0, only this rule on):
- Canonical era: 0 reports over 5,653 files.
- Pre-7: 266 reports over 7,158 files in 19 repos (renderbox 157, jt-vault 17, gzs/inovacije 16, buzzin 13, ...), all pinned to fluent-html 5.x or 6.x.

**Fixture compile.** `$R/rules/capture.cjs` writes `cases.json` (29 suites, 214 invalid fixtures); `mk.mjs` + tsc 5.9.3 `--strict` compile each against `dist/src/index.d.ts`, with free identifiers declared `any`. Result: 28/214 fail tsc.
- Rules whose every invalid fixture fails: `prefer-nav-for-internal-links` 3/3 (raw `setHref("/...")`), `no-innerhtml-swap` 3/3 (raw `hx("/api", ...)`), and `require-satisfies-variant-object` 4/4. The last is by design: it flags an un-annotated object that TS also rejects.
- `no-raw-ids` 3/5 and `anchor-requires-cursor-pointer` 3/5 fail for the same raw-route reason.

**`.nav` probe:** `p.ts(3,15): error TS2339: Property 'nav' does not exist on type 'AnchorTag'.`

**The 4 untested rules** fire on an obvious positive and stay quiet on the negative, 4/4, on ESLint 10.11.0 (`$R/rules/untested.mjs`). That is a coverage gap, not a defect today.

## Why it matters

impact 1 x pain 1 x reach 1. 0 of 16 canonical configs use `recommended` (F-D-509), so the cost falls on the next adopter and on the suite.

- **verification-loop**: fixtures that cannot compile on the supported lib test nothing a supported user writes.
- **context-economy**: a rule message points to a method the lib lacks.

## Rough idea (not a design)

Plugin patch (8.1.x):
- Mirror the template's 3.6.1 removals in `recommended`.
- Delete `prefer-nav-for-internal-links`, or retarget it at the raw-string sinks that still compile (F-B-205).
- Add a CI step that type-checks every invalid fixture against `fluent-html#main` and fails a rule whose fixtures all stop compiling.
- Add cases for the 4 untested rules.
