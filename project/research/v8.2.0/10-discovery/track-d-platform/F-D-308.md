# <selectedcontent> reached a second engine and is the last element without a factory

`$D3` = `<scratch>/wave1/D3`

## Problem

L-276 deferred customizable select as below-the-line. Safari 27 (2026-09-14) shipped `<selectedcontent>`, so it now runs in Chrome 135+ and Safari 27; Firefox has not shipped it (bug 1974276).

The lib's factory set covers 132 element names. A runtime census against BCD 8.1.3 shows that this is every non-deprecated, non-experimental element except `<selectedcontent>`. The prior guess `Selectedcontent()` is not exported.

## Evidence (executed)

**Factory census** (`coverage.mjs`). The BCD elements without a factory are:
- `selectedcontent`.
- 6 experimental single-engine elements: `camera`, `geolocation`, `install`, `microphone`, `model`, `usermedia`.
- 16 deprecated ones.

**Composability probe.** `Select(Button(El("selectedcontent")), Option(Span("🇸🇮"), "Slovenija").setValue("si")).setName("country").cssProp("appearance", "base-select")` compiles clean under tsc 5.9.3 and renders:

```html
<select class="[appearance:base-select]" name="country"><button><selectedcontent></selectedcontent></button>
<option value="si"><span>🇸🇮</span>
Slovenija</option></select>
```

`Select`/`Option` already take variadic `View` children (`forms.ts:579`, `:602`), so rich options need no change.

**Fleet:** 0 sites use `selectedcontent`.

## Why it matters

- **reach 1**, **impact 1**, **pain 1**.

Dimensions:
- **evolvability**: a platform move nobody recorded.
- **prior-alignment**: an agent following the one-factory-per-element convention gets a missing-export error.

The instruction-set test (S-05) holds: it composes today, so a factory is a convenience only.

## Rough idea (not a design)

Keep parked until the third engine ships, with the reopen trigger surfaced by the F-D-304 watch. Then add a plain `Selectedcontent()` factory, a one-line `El` wrapper like `Search`/`Hgroup`, for convention parity and autocomplete. No prose.
