# Declared peer ranges admit versions that crash, and the plugin's recommended preset cannot load on the ESLint major all 16 installs run

## Problem
The peer ranges are the only machine-readable compatibility contract between the three packages and their hosts, and none of them describes what is tested:

- plugin `eslint: ">=7.0.0"`: 13 of 31 rule files read `context.sourceCode`, which exists from ESLint 8.40. The suite runs on 8.57.1 only.
- plugin `configs.recommended` is eslintrc-shaped (`plugins: ["fluent-html"]`, index.ts:71). ESLint 10 removed eslintrc and every plugin-4.1.0 install runs 10.x, so the 31-rule preset cannot be used anywhere it is installed; the README's flat-config example enables 1 rule.
- plugin `fluent-html: ">=8.0.0"` and extractor `fluent-html: "*"` have no upper bound, and the extractor has no lower bound although it imports 7.0.0-only exports.

## Evidence (executed)
- ESLint 8.39.0 (installed in scratch, inside the declared `>=7.0.0`), `Linter.verify` of one probe snippet per rule: 27/32 ok, 5 throw: `no-duplicate-classes-in-setclass` (`Cannot read properties of undefined (reading 'getLocFromIndex')`), `prefer-variadic-children`, `prefer-foreach`, `no-dynamic-typed-styling-arg` (`reading 'getText'`), `match-subset-default` (`reading 'parserServices'`).
- ESLint 10.11 flat config `export default [fluentHtml.configs.recommended]` -> `A config object has a "plugins" key defined as an array of strings.` Fleet: 16/16 plugin-4.1.0 installs run ESLint 10.5 to 10.10; 0/16 configs (14 apps + 2 templates) reference `configs.recommended`; each hand-lists 26 to 34 `fluent-html/` entries copied from the template.
- Extractor 83e81d2 dist installed beside the fleet's fluent-html 6.5.0 (copied from jt-present/node_modules): `SyntaxError: The requested module 'fluent-html/class-vocab' does not provide an export named 'DIRECT_VARIANTS'` at import. npm reports no peer conflict for `*`. 28 fleet extractor installs (on 2.0.0 or 1.1.1) sit on lib <7.

## Why it matters
Reach 1 in today's fleet: every 4.1.0 install happens to pair with ESLint 10 and lib 8.1. The cost is at the edges the lockstep crosses next: a pre-7 app that bumps the extractor to `#main` (as the template tracks) dies at import instead of at install; a lib 9.0.0 prune satisfies both open ranges; a project outside the template cannot load the recommended rule set at all. Evolvability; error quality (the failure surfaces as a TypeError or SyntaxError far from its cause).

## Rough idea (not a design)
Install-time layer: bound the peers to the tested ranges, ship a flat `recommended` (object `plugins`), and run the plugin suite on the ESLint major consumers use (F-D-503). Closes L-279 and L-335.
