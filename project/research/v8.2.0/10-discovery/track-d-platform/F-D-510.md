# gen:vocab --check covers 3 lib artifacts; the eslint plugin's vocab snapshot that 6 rules read has no gate, so a new vocab row passes lint and fails the build

## Problem
Guardrail 9 and settled row S-12 say the extractor and ESLint "re-derive at load and are never hand-edited", with `gen:vocab --check` as the gate. The check covers the lib's 3 generated files (`tailwind-types.gen.ts`, `css-props.gen.ts`, `variant-object.gen.ts`). The plugin is split: its autofix tables derive at load (`derive-fixable.ts:131`), but its detection sets come from `src/vocab.generated.ts`, a committed snapshot written by `scripts/gen-vocab.mjs` from `../../fluent-html/dist` (the sibling checkout, in whatever state it is) plus 5 hand-appended names. The snapshot's pin, `test/vocab-drift.mjs`, runs only on a developer machine (0 workflows in the plugin).

Snapshot readers: `no-dynamic-typed-styling-arg` (VOCAB_METHODS), `prefer-unit-overload` (UNIT_METHODS, VOCAB_UNITS), `no-fluent-equivalent-in-setstyle` (VOCAB_UNITS), `no-setclass-after-fluent-modifier` (FLUENT_MODIFIERS), and via `tailwind-token.ts:9` `no-tailwind-in-raw-class` and `no-tailwind-in-cssclass` (TAILWIND_ROOTS): 6 rules.

## Evidence (executed)
- In sync today: `node test/vocab-drift.mjs` -> `159 methods, 37 unit methods, 9 units in sync`; snapshot `TAILWIND_ROOTS` vs the lib's pinned design system (`loadDesignSystem()`, tailwindcss 4.3.3) -> 1073 vs 1073, 0 only-in-lib, 0 only-in-plugin.
- Simulation (scratch copy of the plugin dist, ESLint 10.11 flat `Linter`): `Div().bg(color); Div().p(pad);` with the shipped snapshot -> 2 `no-dynamic-typed-styling-arg` errors; with `bg` removed from `VOCAB_METHODS` (what a method added in 8.2.0 looks like to a plugin that was not re-snapshotted) -> 1 error, `.bg(color)` passes. The extractor derives from the installed lib and still throws on `.bg(color)` at `npm run css`.
- The generator hand-appends `"on", "at", "addClass", "apply", "when"` (gen-vocab.mjs:54-58), 2 of them removed in 7.0.0 (F-D-507).

## Why it matters
8.2.0 is the additive lane, and additions land as vocab rows (guardrail 9). Each one opens a window in which lint says a dynamic arg is fine and the build says it is not, or `prefer-unit-overload` misses a new unit method, until someone reruns the plugin's generator beside a fresh lib build and ships the plugin. Reach 1 today (0 drift measured); evolvability for every future vocab change.

## Rough idea (not a design)
Load-time derivation for the plugin's method sets (it already requires `fluent-html/class-vocab`), then delete `vocab.generated.ts` and its drift test; the lib's `gen:vocab --check`, which already runs in CI, stays the only vocab gate. TAILWIND_ROOTS needs either the pinned design system at load or a lib export of the root list (a lib-side addition).
