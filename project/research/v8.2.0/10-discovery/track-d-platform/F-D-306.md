# autocorrect became Baseline on 2026-09-11 with no typed path

`$D3` = `<scratch>/wave1/D3`

## Problem

`autocorrect` is the only HTML attribute that became Baseline inside this review window: Chrome 153 on 2026-09-08 closed the gap, and web-features marks it Baseline low on 2026-09-11. The lib types its siblings (`setAutocapitalize`, `setSpellcheck`, `setEnterkeyhint`, `setContenteditable`) but not `autocorrect`.

The guideline lists those siblings under "(never `addAttribute`)" (`gl/fluent-html.md:90`). An agent disabling iOS autocorrection on a username field therefore meets:
- TS2339 on the natural `setAutocorrect("off")` guess.
- TS2345 on `.toggle("autocorrect")`.
- A written rule that forbids the only path that compiles.

v6.2.0 RFC-B-07 skipped `autocorrect` for being "non-Baseline or Safari-historic" (`RFC-B-07.md:311-313`). That reason expired on 2026-09-11. The skip is not in the prior ledger.

## Evidence (executed)

- **Platform:** BCD 8.1.3 lists `autocorrect` at chrome 153, firefox 136, safari 14.1; web-features gives Baseline low 2026-09-11. Runtime: Firefox 151 reflects the IDL (`input.autocorrect === false` after `autocorrect="off"`); Chromium 149 predates 153 and has no IDL.
- **Lib:** `grep autocorrect src/` finds 0. tsc 5.9.3 gives TS2339 (`setAutocorrect` on `InputTag`) and TS2345 (`"autocorrect"` is not a `BooleanAttribute`).
- **Fleet:** 0/12,811 files use `autocorrect`. The whole keyboard-hint family is at 0 sites: `setAutocapitalize` 0, `setSpellcheck` 0, `setEnterkeyhint` 0, all three in recon 01's zero-use list. The six phase-2 generated features (recon 02) contain 0 keyboard-hint attributes.

## Why it matters

- **reach 1**, **impact 1**, **pain 1**.

Dimensions:
- **evolvability**: a Baseline flip reached no lib file; see F-D-304.
- **decision-closure**: the prose rule and the type surface disagree, so there is no legal way to write it.

The low reach is why the setter itself is parked: S-23 requires an addition to earn its place, and neither the census nor the generation runs show demand.

## Rough idea (not a design)

Keep the setter parked with a reopen trigger: the first fleet site, or a pure-prior probe that writes `autocorrect`. Resolve the contradiction now, in one of two ways:
- **Option 1:** add `setAutocorrect("on" | "off")` (closed, type layer) next to `setAutocapitalize`.
- **Option 2:** make `gl/fluent-html.md:90` name `autocorrect` as a sanctioned `addAttribute` exception.

The decision belongs with the zero-use keyboard family as a whole (C1 prune input).
