# setClosedby("any") is taught as complete native light-dismiss, but Safari 27 ships no closedby

`$D3` = `<scratch>/wave1/D3`

## Problem

The lib JSDoc, the `ClosedBy` union doc and both CLAUDE.md copies present `Dialog(...).setClosedby("any")` as the whole click-outside + Esc story, and `guidelines/web-development/htmx.md:591` forbids the alternative: "never hand-roll backdrop/Esc JS". ADR-06 (`src/behaviors/map.ts:30-31`) keeps modal dialogs out of the behavior system on the same premise.

BCD 8.1.3 (published 2026-09-24, after Safari 27 shipped on 2026-09-14) records `dialog.closedby` as Chrome 134, Firefox 141, Safari `preview`, Safari iOS `false`. Safari 27 treats `closedby` as an unknown attribute. On Safari the backdrop click does nothing; Esc still closes (the native close request for modal dialogs), which is why nothing looks broken in a quick check.

Every layer is clean: tsc, eslint, extractor, dev runtime. Acceptance row 28 is titled "closes via closedby" but asserts only Escape and the close button.

## Evidence (executed)

**Fleet (dedup corpus, 58 repos, 12,811 files).** 21 `setClosedby("any")` sites in 20 files across 11 repos:
- gzs/stem-50 7, everyframe-composer 4, sportoawards 2
- 1 each: website-sales-funnel-automation-system, everyframe, home-page, workshop-toni, na-cent, varnoska (6.3.0), popri, fl-um

10 of the 11 repos are canonical-era. 0 of the 20 files use `onClickOutside` or any other backdrop handler (e.g. `na-cent/src/app/transactions/views/transactions.detail.view.ts:86`, `fl-um/src/shared/ui/dialog.ts:32`). The template and `packages/ui` ship no dialog component, so each app follows the guideline directly.

**Browser probe** (`browser-probe.mjs`). The HTML is lib-rendered: `<button id="open" command="show-modal" commandfor="dlg">` + `<dialog id="dlg" closedby="any">`. The "stripped" rows remove only the attribute, which is what an engine without `closedby` sees.

| Engine | closedby | Open via command | Open after backdrop click (5,5) | Open after Esc |
|---|---|---|---|---|
| Chromium 149 | any | true | **false** | false |
| Chromium 149 | stripped | true | **true** | false |
| Firefox 151 | any | true | **false** | false |
| Firefox 151 | stripped | true | **true** | false |

Row 28's assertions (Escape, close button) pass 2/2 with the attribute stripped, so the matrix cannot detect the gap. WebKit is not installed locally (recon 03 §5), and the matrix runs in no CI workflow.

**The lib's only click-outside primitive is no fallback.** The natural guess is `.behavior("onClickOutside", …)` on the `<dialog>` with `closedby` absent (`dialog-fallback*.mjs`):
- **`action: "remove"`**: the dialog is deleted by the click on its own opener (`present:false` right after clicking `#open`), 2/2 engines.
- **`action: "hide"`**: the opening click stamps class `hidden` while `open` becomes `true`, and a backdrop click leaves it open, 2/2 engines.

The cause is `outsideScan` (`runtime.ts:406-411`): it treats the native `command` invoker as an outside click.

## Why it matters

- **reach 3**: 21 sites in 11 repos.
- **impact 2**: the taught dismissal gesture does nothing on the current Safari; Esc and explicit buttons still work.
- **pain 2**: silent on all five layers, and the teaching forbids the workaround.

Dimensions:
- **silent-failure**.
- **verification-loop**: no layer or acceptance row can observe it.
- **evolvability**: a non-Baseline feature is taught unconditionally, with no support signal on the typed surface (see F-D-304).

## Rough idea (not a design)

**Runtime layer.** In the behaviors asset, when `!('closedBy' in HTMLDialogElement.prototype)`, close an open `dialog[closedby="any"]` on a click whose target is the dialog and whose point lies outside its border box. Leave `closerequest` to the native Esc path. This touches ADR-06 (dialogs are not behaviors) under the S-21 lock and the L-260 asset-size gate, hence decision-gated.

**Non-gated part (8.1.x, ci).** Add a backdrop-click assertion to row 28, and run row 28 on WebKit.

If the shim is declined, `htmx.md:591` and the two JSDoc claims have to name the Safari gap.
