# No CI run has ever exercised the lib, the eslint plugin and the extractor together

## Problem
Five repos move in lockstep (ALGORITHM section 0), and the three packages meet in exactly one place: projects-template, whose full-stack template installs `fluent-html#main`, `eslint-plugin-fluent-html#main` and `fluent-html-tailwind-extractor#main` (templates/full-stack/package.json:81, :108, :109) and whose `verify` script scaffolds and compiles the module combinations (`tests/full-stack-compile.test.ts`, which also runs the htmx grammar-contract test), then lints. That job has never reached `verify`. The two tool repos have no CI at all, and the lib's own workflow ran once for the whole 6.x to 8.1 span on main.

## Evidence (executed)

|---|---|---|
| projects-template | `ci.yml` verify job | 114/114 runs `failure`, all at step `Run pnpm install --frozen-lockfile` (first 2026-08-14T08:41Z, last 2026-09-24T07:09Z). 38 of them ran after 853ffb2 (2026-09-07) added the credential step; the latest log prints `PRIVATE_REPOS_TOKEN is not set`, then `ERR_PNPM_GIT_FETCH_FAILED` for `@jtdigital/pm-gui`. `pnpm run verify` has executed 0 times on a runner. |

Running `test/rule.test.js` on ESLint 10.11 first needs its 2 RuleTester constructors ported off eslintrc `parserOptions`; then 377 cases pass and 3 suites fail on ESLint 9+ RuleTester assertions (output equals code x2, unasserted suggestions x1). |

| 14 canonical app repos | none | 0/14 have `.github/workflows`. |

The reds this gate would have shown were found by hand or not at all: the extractor's skewX fixture (F-D-501, unnoticed), and the template's `selfhosted-helpers.test.ts:139` and guidelines pin (recorded in the template's untracked `project/pm/ci-green/prd.md`).

## Why it matters
Impact 3: guardrails 9 and 10 (class-string and runtime-grammar contracts) are specified as CI gates, and the grammar-contract test, the scaffold compile and the lint of template code against the plugin exist only inside the job that has not run. Reach 3: every 8.x change reaches 16 repos through `#main` with no executed cross-repo check. Verification loop and evolvability: 8.2.0's vocab rows and the htmx bump (F-D-502) would land with no gate that sees all three packages at once.

## Rough idea (not a design)
ci layer. Give the lockstep one gate that can pass: the template job with its credential set (the template's ci-green story holds the one-step fix), or an install split so the two private packages do not block the public-package verify. Add a minimal workflow to each tool repo that runs its suite against `fluent-html#main` on the ESLint major consumers run. No prose.
