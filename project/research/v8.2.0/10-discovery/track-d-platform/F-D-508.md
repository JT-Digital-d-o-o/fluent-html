# 13 of 93 JSDoc @example blocks shipped in the 8.1.0 d.ts fail the template's lint config, 11 at error level

## Problem
The d.ts files are where agents learn the API when no prose is loaded (recon 02 section 2.2: the blind runs made 36 and 39 reads of `dist/src/*.d.ts` or `src/*.ts`). 13 of their examples show code the template's lint config rejects, most at error level, including the escape hatches the lint closure exists to remove. The `apply()` example reads `t.setClass("rounded shadow p-4 bg-white")` and `t.addClass("border-red-500 text-red-700")`; the `MatchValue` example feeds `.bg()` a `MatchValue(...)`, which both `no-dynamic-typed-styling-arg` and the extractor reject.

## Evidence (executed)
Extracted every `@example` block from the 68 `.d.ts` files of 8.1.0's `dist/src` (96 blocks; 3 are fragments that do not parse), wrapped each in a module, and ran ESLint 10.11 with the projects-template config. 15 blocks are lint-red; 2 are deliberate contrasts (`tag.d.ts:57` string `setId`, `ids.d.ts:48` `: View` marked as the wrong form), leaving 13:

| src | Example | Rule (template severity) |
|---|---|---|
| core/tag.ts:130 | `Div("Content").setClass("container mx-auto")` | no-tailwind-in-raw-class (error) |
| core/tag.ts:366 | `apply()` presets built with Tailwind strings in `setClass`/`addClass` | no-tailwind-in-raw-class (error) x6 |
| core/tag.ts:187, :428 | `setStyle("color: red; font-size: 16px")`, `setStyles({ width: "100px", height: "50px" })` | no-fluent-equivalent-in-setstyle (error) x3 |
| core/tag.ts:225 | `addAttribute("data-testid", "my-div")` | prefer-set-method (error) |
| core/raw-string.ts:24 | `Div(Raw('<svg>...</svg>'))` | no-raw-icon-string (error) |
| control/match-value.ts:12 | `MatchValue(...)` result into `.bg()` | no-dynamic-typed-styling-arg (error); the extractor throws on it too (F-D-504) |
| control/iteration.ts:151, control/conditionals.ts:21 | `A(...)` without a cursor (iteration.ts:151 also uses the palette literal `.text("gray-400")`) | anchor-requires-cursor-pointer (error) x2 |
| patterns.ts:320 | `hxResponse(...).location({ target: "#main", swap: "innerHTML" })` | no-raw-ids, no-innerhtml-swap (error) |
| patterns.ts:383 | `hxResponse(Div([H2(...), P(...)]))` | prefer-variadic-children (error) |
| elements/forms.ts:14, :174 | `setName("email")`, `setName("comment")` | prefer-form-for (warn) |

Totals: 20 findings, 18 at error; 11 of the 13 blocks carry at least one error.

## Why it matters
Reach 3: the d.ts ships in all 16 canonical repos and is the documentation layer blind agents read. Pain 2: copying an example produces a lint loop, and for `MatchValue` a failed css build. Context economy and prior alignment: the library's own docs contradict its own enforcement, the gap guardrail 12 is meant to close.

## Rough idea (not a design)
ci layer on the lib: extract the `@example` blocks, lint them with the plugin's rule set in `test.yml`, and keep deliberate wrong-form examples behind an explicit marker. Rewrite the 13 examples with the typed methods, `Form<T>`, `.cssProp`, `ids.*` and variadic children. No guideline prose.
