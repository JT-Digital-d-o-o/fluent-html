# Extractor drops a class when a single-argument fluent call ends with a trailing comma

`$R` = `<scratch>/wave1/D-reseed`

## Problem

`splitTopLevel` (`extract.ts:72-94`) pushes the empty text after a trailing comma as one more argument, so `.bg(\n  "accent",\n)` counts as 2 args. There are three outcomes, by emit kind:

- **prefix/value kinds (54 of 159 vocab methods, e.g. `bg`, `font`, `items`, `gridCols`, `opacity`, `cursor`, `z`).** The arity guard (`:154-155`) reads the call as a name collision and skips it: 0 classes, 0 ledger rows, build green.
- **Variant objects (21 tier-1 methods + `.variant`).** `.hover(\n  { bg: "x" },\n)` fails the `endsWith("}")` test (`:276`), and `.variant("x", {...},)` fails `args.length !== 2` (`:286`): 0 classes, 0 rows.
- **Variable-arity kinds (75 methods: spacing 6, sizing 33, custom 17, optional 19).** The empty argument makes `parseLiteralArgs` return null, so a literal call becomes an "unresolved" row. The default `"error"` policy then fails the build with "use a non-literal argument ... Inline the literal, or add the token to staticManifest (defineTheme())" (`safelist.ts:59`). F-D-504 shows that remedy does not exist.

## Evidence (executed)

`$R/ext/probe.mjs` and `probe2.mjs` (extractor HEAD 83e81d2 dist, lib 8.1.0 vocab):

| Call | classes | ledger rows |
|---|---|---|
| `.bg("accent")` | `bg-accent` | 0 |
| `.bg(\n "accent"\n)` | `bg-accent` | 0 |
| `.bg(\n "accent",\n)` | none | 0 |
| `.gridCols(\n "3",\n)` | none | 0 |
| `.hover(\n { bg: "primary-700" },\n)`, `.md(\n { px: "8" },\n)`, `.variant(\n "data-[state=open]",\n { bg: "accent" },\n)` | none | 0 |
| `.p(\n "4",\n)`, `.text(...,)`, `.maxW(...,)`, `.rounded("t","lg",)`, `.w("px",180,)`, `.cssProp(...,)` | none | 1 each |

End to end in a scaffold copy (`$R/app`: template 3.7.0, TS 6.0.3, plugin 4.1.0), with `P("tinted note").bg(\n "partial/10",\n).text("partial").hover(\n { bg: "warning-700" },\n)`:
- `tsc --noEmit`: 0 errors. `eslint`: 0 messages. `npm run css`: exit 0.
- Render: `<p class="bg-partial/10 text-partial hover:bg-warning-700">`.
- Compiled CSS: 0 rules for `bg-partial/10` and `hover:bg-warning-700`. Controls `text-partial`, `bg-info/20`, `hover:bg-danger-700` and `ml-7` are present, 4/4 (the last three from a one-line control view).
- Adding `.ml(\n "6",\n)` makes `npm run css` exit 1 with `unresolved .ml("6",)`.

Reach (`$R/ext/fleet2.mjs`, 5,653 files in the 16 canonical repos, the extractor's own receiver guard applied):
- 0 of 60,793 vocab/variant calls carry the shape. The 1 hit, `f.select(name, options,)`, is form binding and is arity-guarded correctly.
- Only 30 of the 60,793 calls wrap at all.
- But 14,496 of 15,921 (91%) multi-line argument lists in the same files end with a trailing comma, so by house style a wrapped fluent call would take one.
- Prettier 3.9.9 does not produce the shape: 3/3 long single-argument fluent calls stay on one line.

## Why it matters

impact 2 (an unstyled element on the prefix/variant arms; a false build break on the rest) x pain 3 (silent on tsc, eslint, the extractor's own ledger and the build) x reach 1 (0 sites today).

- **silent-failure**: the class reaches the HTML and never reaches the CSS.
- **evolvability**: the extractor is the only layer between a typed call and its CSS, and it has no fixture for argument formatting.

## Rough idea (not a design)

Extractor patch (8.1.x): drop a trailing empty segment in `splitTopLevel` before counting, and add trailing-comma fixtures for each emit kind and both variant scanners. No prose.
