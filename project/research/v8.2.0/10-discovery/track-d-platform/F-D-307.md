# popover="hint" now ships in 2 of 3 engines; PopoverState still rejects it

`$D3` = `<scratch>/wave1/D3`

## Problem

`PopoverState` is closed to `"auto" | "manual"` (`html-types.ts:193`), so `setPopover("hint")` is TS2345. The guideline marks the untyped `addAttribute("popover", …)` ✗ (`gl/htmx.md:603`), which leaves an agent building a tooltip with no sanctioned path.

L-272 parked this on the expectation "native tooltip; cross-engine 2026". Since then, per BCD 8.1.3, Firefox 153 (2026-07-21) and Chrome 151 (2026-07-28) ship it; Safari is at preview.

## Evidence (executed)

- **tsc 5.9.3:** `TS2345: Argument of type '"hint"' is not assignable to parameter of type 'PopoverState | undefined'.`
- **Runtime:** `popover="hint"` reflects `"hint"` in Chromium 149 and Firefox 151. Chromium 149 already reflects it although BCD lists Chrome 151.
- **Fallback:** an unrecognized `popover` value reflects `"manual"` in 2/2 engines (`fallback-values.mjs`). On Safari 27 a hint popover therefore degrades to manual: no light-dismiss, and it does not close other auto popovers.
- **Status:** web-features 3.40.0 gives `popover-hint` baseline false.
- **Fleet:** 0 sites use `hint`; `setPopover(` appears at 10 sites.

## Why it matters

- **reach 1**, **impact 1**, **pain 1**.
- **Dimension, evolvability:** the second engine landed without the lib or the ledger noticing.

It stays parked for the same reason F-D-301 exists: shipping a two-engine value without a support note teaches a silently degraded behavior.

## Rough idea (not a design)

Keep parked with an explicit reopen trigger: Safari stable ships `popover=hint`, detected by the F-D-304 watch rather than by a future review. Then add `"hint"` to `PopoverState` (type layer), with a generated support note stating the manual fallback.
