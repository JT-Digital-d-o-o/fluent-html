# Guidelines teach the subset-plus-default Match/whenMatch shape that match-subset-default rejects at error

## Problem
The guideline corpus presents the subset-plus-default shape as correct:

```typescript
Match(status, {
  active: () => Span("Active"),
  error:  () => Span("Error"),
}, () => Span("Unknown"))
```

(`guidelines/web-development/CLAUDE.md:115-118`, copied verbatim to fluent-html/CLAUDE.md and projects-template/CLAUDE.md), plus `Button(l).whenMatch(tone, { danger: t => t.bg("danger") }, t => t.bg("surface-3"))  // subset needs a default fn` (fluent-html.md:183), "a subset of cases needs an explicit `defaultFn`" (CLAUDE.md:210, fluent-html.md:193) and "pattern matching + optional default" (fluent-html.md:360-363). eslint-plugin 4.1.0 ships `match-subset-default`, set to error in the template config, and it rejects exactly this shape whenever the discriminant is a union.

## Evidence (executed)
- Scaffolded template app (plugin 4.1.0, type-aware parser services): the CLAUDE.md shape with `status: 'active' | 'error' | 'pending'` -> `Match over 'Status' carries a default that silently absorbs: pending. Add an explicit case per member and delete the default...`; the fluent-html.md:183 line with `tone: 'danger' | 'neutral' | 'success'` -> `whenMatch over 'Tone' carries a default that silently absorbs: neutral, success.` 2/2. The rule's advised rewrite (one case per member, no default) lints clean.
- Each canonical repo's own ESLint config over its `src`: competify 244, competition 199, everyframe 215, everyframe-composer 362, fl-um 148, fluent-html-home-page 124, gzs/stem-50 246, home-page 245, na-cent 271, popri 189, sportoawards 190, stojnica 93, studio 178, website-sales-funnel-automation-system 466 files: 3,170 files, 0 errors, 0 warnings. All 14 configs enable the rule. `grep -rn "eslint-disable.*match-subset-default"` over the same trees: 0.
- 15/15 canonical repos' CLAUDE.md contain the `Match(status, {` subset block.
- Recon 02 section 2.1: guided1's 2 lint findings (`team.invite.view.ts:32,55`) were this rule on this shape; the blind runs (no prose) produced 0.

## Why it matters
Decision closure: the prose and the enforcement layer give opposite answers for the same code, and every guided session loads the losing one (reach 3: always-loaded in 15/15 repos). The fleet already follows the rule (0 violations, 0 disables), so the prose buys nothing and costs one lint loop per use. Context economy: 8+ always-loaded lines whose only measured effect is an error.

## Rough idea (not a design)
Enforcement over prose (guardrail 12): the rule already carries the doctrine and its message names the fix. Delete the subset example at CLAUDE.md:115-118 (or make it exhaustive), the `// subset needs a default fn` line at fluent-html.md:183 and the sentence at CLAUDE.md:210 / fluent-html.md:193; about -8 guideline lines, mirrored into the two copies. MatchValue's subset idiom stays with L-330.
