# Four Baseline ARIA 1.3 names are missing from the closed AriaAttributeName, and tsc's did-you-mean redirects three of them to a different attribute

`$D3` = `<scratch>/wave1/D3`

## Problem

`AriaAttributeName` is closed on purpose, so that a typo is a compile error (`aria-types.ts:3-5`). It stopped at 47 names. All three engines now reflect four more ARIA 1.3 attributes, but the union rejects them:
- `aria-braillelabel` and `aria-brailleroledescription`: Baseline 2024-09-16.
- `aria-colindextext` and `aria-rowindextext`: Baseline 2025-12-12.

The rejection is worse than an anonymous error. TS2561 suggests a *different, existing* ARIA attribute for three of the four. Applying the suggestion for `brailleroledescription` gives `roledescription`. That compiles, passes lint and emits `aria-roledescription`, which changes the role every screen-reader user hears, not only the braille output.

Lint then closes the loop:
1. The correct hatch, `addAttribute("aria-brailleroledescription", …)`, is an **error** under the template's `prefer-set-method`.
2. That rule points to `setAria({ brailleroledescription })`, promising "aria typos become compile errors".
3. That call is the TS2561 that redirects to `roledescription`.

The only form that passes every layer is the untyped escape arm `setAria({ "aria-brailleroledescription": … })`.

## Evidence (executed)

**Platform.** BCD 8.1.3 `api.Element` reflects 51 ARIA attribute names. Diffed against the union, exactly 4 are missing, and 0 lib names are unreflected:

| Name | Reflected in | Baseline (web-features 3.40.0, by key) |
|---|---|---|
| braillelabel | C107 F125 S18 | low 2024-09-16 |
| brailleroledescription | C107 F125 S18 | low 2024-09-16 |
| colindextext | C128 F119 S26.2 | low 2025-12-12 |
| rowindextext | C128 F119 S26.2 | low 2025-12-12 |

Runtime: `k in Element.prototype` is true for all 4 in Chromium 149 and Firefox 151.

**tsc 5.9.3** (`probe/probe.ts`), verbatim:
- `(7,17) TS2353: Object literal may only specify known properties, and 'braillelabel' does not exist in type 'AriaAttrs'.`
- `(8,17) TS2561: … 'brailleroledescription' does not exist in type 'AriaAttrs'. Did you mean to write 'roledescription'?`
- `(9,19) TS2561: … 'colindextext' … Did you mean to write 'colindex'?`
- `(10,32) TS2561: … 'rowindextext' … Did you mean to write 'rowindex'?`

**Applying the suggestion** (`probe/fixed.ts`, `render.mjs`):
- `Button("Star").setAria({ roledescription: "btn" })`: 0 tsc errors, 0 lint messages, renders `<button aria-roledescription="btn">Star</button>`.
- `colindex`/`rowindex` take `number`: the string value fails TS2322, and a numeric rewrite compiles and emits `aria-colindex="2"`, which overrides the computed column index.

**Accessibility tree** (CDP `Accessibility.getFullAXTree`, Chromium 149):

| Rendered | role | roledescription |
|---|---|---|
| `<button aria-roledescription="btn">` (did-you-mean applied) | button | **btn** |
| `<button aria-brailleroledescription="btn">` (intended) | button | null |

**Lint** (eslint 10.0.3, plugin 4.1.0 `dist`). On `addAttribute("aria-brailleroledescription", "btn")`: `Use .setAria({ brailleroledescription: … }) instead of .addAttribute("aria-brailleroledescription", …). Typed setters give autocomplete and validation (e.g. aria typos become compile errors).` The template sets this rule to `error` (`templates/full-stack/eslint.config.mjs:62`).

**Fleet:** 0 of 12,811 files use any of the four names.

## Why it matters

- **reach 1**: 0 fleet uses.
- **impact 2**: a wrong ARIA attribute changes assistive-tech output for every user.
- **pain 3**: compiler and lint jointly steer a correct name into a different attribute, silently.

Dimensions:
- **error-quality**: the diagnostic names the wrong fix.
- **silent-failure**.
- **evolvability**: the closed list froze at its audit date; see F-D-304.

## Rough idea (not a design)

**Type layer.**
- Add the four names to `AriaAttributeName` and `AriaAttrs`, all `string`-valued.
- Add one `test/types/` line per name.

The `aria-${string}` arm stays for the non-standard tail. No prose to delete: none teaches these names.
