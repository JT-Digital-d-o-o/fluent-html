# The lib's only htmx runtime is a beta that 2 of 16 canonical apps serve

`$S` = `<scratch>/wave1/D1`.

## Problem

`package.json:131` pins `htmx.org` to `4.0.0-beta6` (c60a484, 2026-08-14). htmx 4.0.0 shipped 2026-08-28; projects-template bumped the same day (bf4baca); the lib has not moved in 34 days. The acceptance matrix is the only place any lib test touches a bundle (`test/acceptance/app.mjs:32`), so every runtime claim fluent-html can make is a claim about beta6. The fleet does not run beta6.

## Evidence (executed)

**Fleet runtime census** (dedup corpus, 58 repos; vendored bundle version string + sha256, else CDN URL):

**The bump, executed** on a scratch copy (`$S/libga`: package.json pin `4.0.0`, `node_modules/htmx.org` -> 4.0.0, all other deps symlinked): `tsc` build clean; 36 unit files **2159/2159 pass**; `tsc -p test/types/color-optout` exit 0; `CI=1 playwright test` **69/69 pass** (18.8 s); the app's `/assets/htmx.js` served `version="4.0.0"`. Cost of the bump: `package.json:131` + the lockfile entry.

**What the bump changes**, executed in Chromium through the typed emitter (`dist/` 8.1.0) on each bundle:

All 6 favor 4.0.0. Measured benign: `htmx:after:swap` for a detached source is dispatched with `e.target = document` on the betas and re-pointed to the swapped-in target on 4.0.0 (4.0.0:1297); the behaviors runtime's drawer close-on-nav result is identical on 4/4 bundles (P3: body unlocked, drawer closed, with and without pushUrl).

**No test observes any of the 6.** The full battery is green on both pins (2159 unit + 69 acceptance = 2228), which is only possible if no test asserts any of these behaviors: unit tests never load a bundle, and the 69 rows hand-write `hx-*` attributes (recon 03 §3/§5).

## Why it matters

impact 2 × pain 2 × reach 3. Reach is the fleet: 13/16 canonical apps and the template run a runtime the lib never executes; the lib's tests represent 2/16. A regression in 4.0.0-only behavior (rows 2-6 above) cannot turn anything in fluent-html red. Evolvability: every future bump starts from a stale base and inherits two bumps' worth of unobserved deltas. Silent-failure: row 1 is a destructive difference (a wiped region) that flips with the runtime and has no row.

## Rough idea (not a design)

Bump now (8.1.x: devDependency only). Strongest layer that holds it: runtime (acceptance rows) plus boot/ci (the matrix already runs from the pin, so the pin is the contract). Add one acceptance row per delta above, emitted through `setHtmx`/`Partial`/`hxResponse`, not hand-written attributes (this overlaps the A1 grammar gate, L-006). Prose it lets us delete: `guidelines/web-development/htmx.md:389` ("Three 4.0.0-beta4 runtime facts") and `:282`'s beta4 aside become row-backed facts.
