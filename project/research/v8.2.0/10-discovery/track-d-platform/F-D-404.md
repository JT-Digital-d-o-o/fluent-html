# The decided class merger's real per-request cost

## Problem
The 2026-08-14 decision (family-keyed, memoized, last-write-wins merge at serialize time; `fluent-html-batch/decisions.md:41-45`) priced the memoized merge at "≈ noise" on 7.2.0 and argued an inline build would cost "one `Map.get` per styled tag". That holds for a tree rendered many times. Real SSR builds the tree per request, so every `_class` is a freshly concatenated cons string: `Map.get` must flatten and hash it on every lookup. The decision's measured outliers on realistic build+render (−10%, −22%) were attributed to the prototype's extra walk; inline, the lookup itself is the cost.

## Evidence (executed)
Prototype (scratch copy of 8.1.0, `merge/`): classifier derived at load from `classVocab` (prefix map, group rows resolved by literal sets / numeric / size tokens / palette + `defineTheme` token registry), key = variant chain + family, last write wins, `Map` memo capped at 10,000, inlined at `serialize.ts:228`. Sanity: `check-merge.mjs` reproduces the decision's fixes (`.apply(card).p("4")` -> `bg-surface rounded-card p-4`; base + `.when` tint -> `bg-danger/10`; `.hover({bg}).hover({bg})` -> last) and keeps the documented multi-family idioms (`border-b border-line`, `text-lg text-primary text-center`, `focus:ring-2 focus:ring-primary/40`, `px-8 p-6`). Env `MERGE_MODE=memo|nomemo|off|gated` selects the variant in one build.

Paired ratios vs the unmodified 8.1.0 dist, `NODE_ENV=production`, median [min..max]:

| scenario | run A (bench matrix, 5 reps) | run B (7 reps) | run C (7 reps) |
|---|---|---|---|
| build+render realistic, memo | x0.885 [0.80..1.04] | x0.928 [0.87..1.06] | x0.886 [0.87..0.90] |
| build+render list50 (preset + `.when` per row), memo | – | x0.933 [0.89..1.07] | x0.943 [0.92..0.95] |
| render of a pre-built tree, memo | x0.94-1.02 (7 scenarios) | x0.996 | x0.980 |
| realistic, memo cleared each op (first render of each distinct string) | – | 13,725 vs 18,906 ops/s (x0.73) | 12,879 vs 17,875 (x0.72) |
| no memo (naive) | variant-heavy x0.038, realistic build+render x0.43 | list50 x0.216 | – |
| flag off (one boolean) | x0.999 | x1.007 | – |
| composition-gated (see below) | – | – | realistic x0.953, list50 x0.940 |
| same build, gating field only (`off`) | – | – | realistic x0.948, list50 x0.996 |

- Mechanism, `node micro-hash.mjs` (2e6 ops, median of 7): build a 10-token class string 69.4 ns; build + `Map.get` 195.9 ns; `Map.get` on the same string object 6.9 ns. The lookup on a fresh string costs ~127 ns, 18x the cached-hash case.
- Memo cardinality: list50 needs 7 entries, bounded. But the memo keys on the whole `_class`, which also carries `cssClass`/`setClass` content the decision excludes from merging. A per-row hook class (`.cssClass(`js-row-${i}`)`) fills the 10K cap and every later string misses: x0.188 (memo) vs x0.197 (no memo). Fleet today: `dyn-class-census.mjs` over the 16 dedup canonical repos (comments stripped, app-authored filter) finds 16 non-literal class-string sites in 2/16 repos, all bounded (enum lookups, `className` props in `packages/ui`, `language-${language}`), 0 unbounded; 1 non-literal unit overload. The hazard is latent, reach 1.
- Composition bit (`gated`): `_m = 1` set in `apply`, `when`, `whenElse`, `whenMatch` and `applyVariantObject`; merge only when set. All four decided repro idioms still merge. On the realistic page (0 composition calls) the lookup cost disappears (x0.953, same as the field alone x0.948); on list50, where every row composes, it stays (x0.940). Trade-off: a direct same-family repeat in one chain (`.p("6").p("8")`) is no longer merged (degrades to today's behavior).
- Load during runs: load1 3.2-5.3 (runs B, C), 3.2-4.1 (run A); other agents active.

## Why it matters
impact 2 x pain 2 x reach 3 / M. Default-on at the next major, this lands on every styled tag of every request in every app: 6-12% of build+render, larger than the 7.0.1 dev-check budget (~12%, dev only) and invisible to the current bench (F-D-403), whose pre-built scenarios show x0.98-1.00. Guardrail 2 makes bench regression a verification input for the merger's build; without a per-request scenario the verifier sees noise. Dimensions: silent-failure (perf), evolvability (the build scope carries a cost model that does not hold).

## Rough idea (not a design)
Input to decision item (3), no change to the decision itself: measure the merger on per-request build+render, not pre-built renders; key the work off something cheaper than a fresh string (a per-tag composition bit set by the composition primitives is the cheapest measured option); never let an insert-until-full memo freeze on unbounded keys (clear-on-cap or exclude `cssClass`/`setClass` content from the key). Enforcement: ci (bench scenario) + runtime. No prose deleted.
