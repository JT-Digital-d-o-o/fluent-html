# htmx-2 names pass every fluent layer

`$S` = `<scratch>/wave1/D1`.

## Problem

The model's prior still writes htmx 2 (recon 02: `hx-disabled-elt` in pp1, `hx-on:htmx:before-swap` + `event.detail.xhr` in pp2). Every such name is inert or re-meant under htmx 4, and fluent's layers let them through. The eslint plugin's `prefer-htmx-api` holds a hand-kept 24-name set and returns silently for any name outside it (`prefer-htmx-api.ts:63`). htmx 4.0.0 ships the migration table itself (`dist/scripts/upgrade-check.py`), naming each successor.

## Evidence (executed)

Probe: 10 attributes from htmx's `REMOVED_ATTRS`/`RENAMED_ATTRS` (`hx-disabled-elt hx-vars hx-params hx-ext hx-disinherit hx-inherit hx-request hx-history hx-prompt hx-disable`) and 3 htmx-2 `hx-on` event forms (`hx-on::before-request`, `hx-on:htmx:before-swap`, `hx-on:htmx:afterSwap`), each via `.addAttribute`.

| Layer | Result |
|---|---|
| `tsc --strict` against dist 8.1.0 | exit 0 (15/15 lines compile) |
| eslint-plugin-fluent-html 4.1.0, all 32 rules enabled | 1/13 flagged: line 12 bare `hx-disable`, `prefer-htmx-api`: "Use the HTMX API (hxGet, hxPost, setHtmx) instead of .addAttribute("hx-disable", ...)" |
| htmx 4.0.0 `upgrade-check.py` on the rendered HTML | 11/13 flagged, each with the successor ("hx-disabled-elt → rename to hx-disable", "hx-disable → rename to hx-ignore", "hx-on:htmx:afterswap uses old event name ... → use hx-on:htmx:after:swap"); misses the 2 kebab-case hx-on forms |

The one fluent flag misdirects: bare `hx-disable` is htmx 2's "disable processing", whose htmx-4 successor is `ignore: true` (`hx-ignore`); the message points at `setHtmx`, whose `disable` key emits the htmx-4 disabled-elements selector. The rule's set has 24 names; 4.0.0 web-types has 49 (it lacks `hx-ignore`, `hx-status:*`, `hx-query`, `hx-morph-skip`, `hx-on`).

Fleet: canonical app-authored `addAttribute("hx-…")` = 0 (17 sites, all vendored template core). The class shows up in raw client strings instead: workshop-toni `story.ts:193-194` listens for `htmx:afterSettle` and `htmx:afterRequest` (0 occurrences in the beta4 bundle it serves and in 4.0.0), and everyframe's `layout.scripts.ts:347-349` records the same bug after it was fixed.

## Why it matters

impact 2 × pain 2 × reach 2. Reach: 2/2 pure-prior runs produced at least one htmx-2 name; 1/16 canonical repos ships 2 inert htmx-2 listeners; 0 app-authored `addAttribute` sites. Error quality: where a layer fires, it names the wrong fix. Prior alignment: the successor table exists upstream and is not consulted.

## Rough idea (not a design)

Layer: lint (tsc cannot help: `addAttribute(name: string, …)` is the explicit untyped hatch). Derive the rule's data from the pinned htmx package in the same generator as [[F-D-103]]: known-name set from web-types, successor map from upgrade-check's tables. Report unknown and htmx-2 `hx-*` names, and `htmx:<camelCase>` string literals anywhere, with the successor in the message. eslint lockstep (guardrail 9: re-derive, never hand-edit). Prose deletable: the htmx-2 migration asides in `guidelines/web-development/htmx.md` (e.g. the `show:window:top` and `hx-disabled-elt` notes) once a rule names them.
