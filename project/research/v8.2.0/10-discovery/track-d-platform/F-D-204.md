# .variant() rejects 156 of 331 valid Tailwind 4.3.3 variants

## Problem
The variant vocabulary is hand-kept in `tailwind-types.template.txt`. The only code that reads `design.getVariants()` is a sanity count. The eslint plugin keeps its own hand list. Tailwind 4.1 added 11 variants: 3 were typed (`details-content`, `user-valid`, `user-invalid`) and 8 were not. There is no layer-clean spelling for a responsive `max-*` or a pointer media query:

```ts
Div().variant("max-md", { hidden: true })               // TS2345 '"max-md"' is not assignable to 'TailwindState | TailwindBreakpoint'
Div().variant("[@media(width<48rem)]", { hidden: true }) // TS2345 (valid Tailwind arbitrary variant; the union only has `[&${string}]`)
Div().addClass("max-md:hidden")   // eslint error, autofix -> .variant("max-md", …) -> TS2345
Div().setClass("max-md:hidden")   // eslint error, same autofix
Div().cssClass("max-md:hidden")   // no-tailwind-in-cssclass: "Replace with: .variant(\"max-md\", …)" -> TS2345
Div().addClass("pointer-coarse:p-4")  // 0 lint messages: head unknown to the plugin, raw string passes silently
Div().variant("backdrop", { bg: "black/60" })  // TS2345; authors fall back to .variant("[&::backdrop]", …)
```

## Evidence (executed)
- `enum/variants.mjs` expands 4.3.3 `getVariants()` into 392 concrete strings (static names plus functional names × values) and checks each with `candidatesToCss([v + ":flex"])`: 331 valid. Each valid string is assigned to `Parameters<Tag["variant"]>[0]` in a generated TS file: 156 are rejected. The typed union's 135 literal members all compile (0 invalid). Breakdown of the 156:
  - 13 with no typed spelling at all: `max-sm`..`max-2xl` (5) and the 4.1 media variants `inverted-colors`, `pointer-none/coarse/fine`, `any-pointer-none/coarse/fine`, `noscript` (8).
  - 53 reachable only through the `[&…]` arbitrary selector: 25 `group-<state>` and 25 `peer-<state>` outside `GroupPeerState` (`peer-placeholder-shown`, `group-first`, `peer-empty`, ...), plus `first-letter`, `first-line`, `backdrop`.
  - 90 with a typed alias: `min-<bp>` (5), `@min-<size>` (13), named `in-<state>` (36) and `has-<state>` (36) via their bracket forms.
- The oracle confirms the Tailwind side: `max-sm:hidden` gives `@media (width < 40rem)`, `pointer-coarse:p-4` gives `@media (pointer: coarse)`, `noscript:hidden` gives `@media (scripting: none)`, `backdrop:bg-black/60` gives `::backdrop`.
- Plugin: `isKnownVariantHead` over the 331 valid variants reports 11 unknown (`first-letter`, `first-line`, `backdrop`, `inverted-colors`, the six pointer variants, `noscript`). Raw `addClass("pointer-coarse:p-4")` and `addClass("noscript:hidden")` produce 0 messages from the error-level `no-tailwind-in-raw-class` (scaffold probe lines 18-19). Of the 156 typed-rejected heads, 145 get an autofix into a non-compiling `.variant("…")` (F-D-202).
- Fleet: 7 `.variant("[&::backdrop]", …)` sites in 5 canonical repos (everyframe-composer 3, sportoawards 2, popri 1, website-sales-funnel 1). 2 of them carry comments naming the missing `backdrop:` variant. They style native `<dialog>` backdrops, the pattern the lib promotes through `setClosedby`/Invoker Commands. Pre-7: 28 raw `max-sm:` heads in filmplast-v2.

## Why it matters
impact 2 × pain 2 × reach 2 / M = 4. Tailwind's variant list is the second half of the platform surface, and nothing watches it. The 4.1 media variants shipped 18 months before this run with no signal. For `max-*` the enforcement layers form a closed loop: every message points at another layer's error.

## Rough idea (not a design)
Type layer, generated. Derive the variant unions from `getVariants()` in `gen:vocab`, keeping the tier-1 methods hand-picked. Emit the plugin's head table from the same source, which guardrail 9 already requires. Add a variant coverage watch next to the root watch, with an IGNORED list for anything deliberately untyped. That makes the "Tier-1 … Everything else: `.variant(...)`" prose line redundant except for the tier-1 list.
