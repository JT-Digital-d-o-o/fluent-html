# The typed surface needs tailwindcss >= 4.2.0, and nothing declares it

## Problem
The lib validates its vocab against exactly 4.3.3, and only in its own CI. What an app installs is governed by ranges that admit every 4.x. `insetS`/`insetE` emit `inset-s-*`/`inset-e-*`, the 4.2.0 spelling (4.1 used `start-*`/`end-*`, and 4.2.0 dropped 240 `start-*`/`end-*` class-list entries). `textShadow`/`dropShadow` colors need 4.1. An app resolving an older 4.x gets classes Tailwind silently drops. No layer reports it: tsc and eslint are version-blind, and the extractor peers `>=4.0.0` with no validation (F-D-207).

## Evidence (executed)
- `skew.mjs` compiles the 11,768 typed-reachable classes (the F-D-201 enumeration) on each installed version:

| tailwindcss | classes with no CSS | families |
|---|---|---|
| 4.0.17 | 793 | inset-s/e 176, text-shadow*, drop-shadow colors |
| 4.1.18 | 194 | inset-s-* 97, inset-e-* 97 |
| 4.2.4 | 0 | |
| 4.3.0 / 4.3.1 / 4.3.2 | 0 | |

- `diff.mjs`: 4.3.0 to 4.3.1 to 4.3.2 to 4.3.3 add or remove 0 utility roots, 0 variants and 0 `getClassList()` entries. The template's locked 4.3.1 against the lib's 4.3.3 pin is inert today, consistent with recon 03's 564/564 on both.
- Declarations. fluent-html has no `peerDependencies`. The extractor declares `tailwindcss >=4.0.0` (optional). The template and all 15 canonical-era apps declare `^4.0.0`. Installed today: 14 × 4.3.3, 1 × 4.3.2, template 4.3.1, so reach is 0 apps below the floor. Pre-7 repos on 3.4.19 (22 of 42) move to v4 when they upgrade, and they would take whatever their lockfile and range resolve.

## Why it matters
impact 2 × pain 2 × reach 1 / S = 4. The floor moved once without a trace (the `insetS` spelling), and the next vocab row that uses a 4.3-only utility will move it again. The `^4.0.0` ranges would still accept an old lockfile.

## Rough idea (not a design)
Package-manager layer, the only one that sees the app's installed version at install time. Declare `peerDependencies.tailwindcss: ">=4.2.0 <5"` on the lib and the extractor, and raise the template range to `^4.2.0`. Keep a `MIN_TAILWIND_VERSION` beside `PINNED_TAILWIND_VERSION`, and have the oracle compile the vocab on both, so a row that needs a newer Tailwind moves the floor in the same change. No prose to delete.
