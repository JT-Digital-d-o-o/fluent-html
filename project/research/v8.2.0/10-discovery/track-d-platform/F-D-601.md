# htmx 4.0.0 lets an older .search response win and drops form-level changed triggers; the fixes are unreleased

`$R` = `<scratch>/wave1/D-reseed`

## Problem

F-D-101 measures the beta6 to 4.0.0 bump as 6 deltas, all in 4.0.0's favor, and F-D-102 shows `.search` losing keystrokes on the betas. The bump target has two defects of its own, both on shapes the template and apps rely on.

1. **sync replace race (new in 4.0.0).** 4.0.0 introduced a `RequestQueue` (`htmx.js:119`) whose `continue()` frees the current slot for whichever request finishes, including the one `replace` just aborted. With three requests A, B, C: B aborts A, A's cleanup frees B's slot, C starts without aborting B, and a slower B lands last (htmx#4027). The template's `.search` verb is built on the opposite claim: "`replace` abandons the in-flight request and runs the newest, so the last keystroke wins" (`swap-verbs.ts:331`).
2. **`changed` on a form never fires (beta4 through 4.0.0).** `changed` compares `fromElt.value`; a `<form>` has none, so `undefined === undefined` and the event is dropped from the first keystroke on (`htmx.js:789-795`). gzs/stem-50's thesis autosave puts `change, input changed delay:1200ms` on the form (`thesis.sections.view.ts:108-118`), so it saves only on blur.

Both are fixed on htmx `four-dev` (#4028 on 2026-09-11, #4035 on 2026-09-17). npm's newest 4.x is still 4.0.0. tsc, eslint, the extractor and the dev runtime see nothing. The template's own regression row for this guarantee is `test.skip` (`htmx-smoke.spec.ts:260`, L-010), and its uniform 1200 ms lag cannot see the race anyway.

## Evidence (executed)

Harness `$R/htmx/replace-race.mjs`. Lib 8.1.0 `dist/` renders the template `.search` attribute bag (`trigger: "input changed delay:300ms"`, `sync: "replace"`, `target: "#main-content"`, `swap: "outerMorph"`, `include: "closest form"`) over a server that echoes the query into the input and filters a list. Chromium 149. Playwright types `a`, `b`, `c` with 400 ms between keys (each past the 300 ms debounce), then waits 2.5 s. Wrong = the final results are not for `abc`.

| Bundle | A: queries under 3 chars answer in 1500 ms, `abc` in 50 ms (htmx#4027 shape) | B: seeded uniform 50-1500 ms per response, 20 trials |
|---|---|---|
| 4.0.0-beta6 (lib pin) | 5/5 wrong (input rewritten to `ab`, the F-D-102 defect) | 10/20 wrong (7 end `ab`, 3 end `ac`: lost keystrokes) |
| **4.0.0** (13/16 canonical apps) | **5/5 wrong**: input `abc`, results for `ab` | **4/20 wrong**: input `abc`, results for `ab` |
| four-dev @ 372c6e3 (unreleased) | 0/5 | 0/20 |
| 4.0.0 with `sync: "queue last"` | 0/5 | 0/20 |
| 4.0.0, uniform 1200 ms (the skipped template row's lag) | 0/5 | n/a |

The 4 stale B trials all have `ab` slower than `abc` by more than the 400 ms typing gap (e.g. `a:1080|ab:1024|abc:575`).

Form-level `changed` (`$R/htmx/form-changed.mjs`): a lib-rendered `Form(Textarea, Button)` with `trigger: "change, input changed delay:1200ms"`, `sync: "replace"`, outerMorph. Type `hello`, wait 2 s, type ` world`, wait 2 s, blur.

| Bundle | POSTs while typing (4 s) | after blur |
|---|---|---|
| 4.0.0-beta6 | 0 | 1 |
| 4.0.0 | 0 | 1 |
| four-dev @ 372c6e3 | 2 | 3 |

Reach (`$R/htmx/sc2.mjs`, TypeScript AST over `src/` of the 16 canonical repos):
- 57 `.search` calls on `Input` / form-binding receivers in 12 repos.
- 52 of them in the template + 9 apps that serve 4.0.0: 19 app-authored, 33 in vendored template views (analytics event-log/users, payments admin-list).
- Raw `sync: ...replace` outside the verb: 2 app sites, both commented as newest-wins (gzs/stem-50 autosave, competify `closest form:replace` tick).
- Form-level `changed` triggers: 1 (gzs/stem-50).

## Why it matters

impact 2 (a live filter settles on results for a query the user typed past; an autosave-as-you-type never saves until blur) x pain 3 (timing-dependent, silent on all five layers, the guard row is skipped and blind) x reach 3 (10 of the 13 repos on 4.0.0 carry `.search`).

- **silent-failure**: wrong results with no signal.
- **verification-loop**: no row on any bundle observes either behavior.
- **evolvability**: bumping to 4.0.0 (F-D-101's fix) trades the beta keystroke loss for this race; the next safe target is an unreleased build.

## Rough idea (not a design)

Runtime + ci, 8.1.x. Until htmx releases #4028, `.search` emits `sync: "queue last"` (measured 0/25 wrong on 4.0.0, at the cost of waiting for the in-flight request), and the verb's comment stops claiming what 4.0.0 does not do. Add a lib acceptance row that emits the sync bag through `hx()`/`setHtmx` with asymmetric latency on the served bundle, and un-skip the template row with asymmetric lag. Treat the four-dev fixes as the next pin bump. A lint for `changed` on a `Form` receiver would catch the autosave shape (1 site).
