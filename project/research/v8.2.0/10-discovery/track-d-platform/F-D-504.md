# Three tool errors and the always-loaded CLAUDE.md prescribe defineTheme()'s staticManifest, which does not exist and would not clear the error

## Problem
When a typed styling method gets a non-literal argument, three tools stop the author, and all three name the same second remedy:

- extractor throw (`safelist.ts:59`): `Inline the literal, or add the token to staticManifest (defineTheme()).`
- `no-dynamic-typed-styling-arg` (error in the template config, `:240`): `...or add the token to staticManifest (defineTheme()).`
- `no-dynamic-class-argument` (`:30`): `...or defineTheme's staticManifest for token-driven values.`

The always-loaded CLAUDE.md says the same at line 72 in all three copies (guidelines, fluent-html, projects-template): a variable-driven token "belongs in `defineTheme()`'s `staticManifest`"; `fluent-html.md:349` repeats it.

`defineTheme()` has no `staticManifest`. The extractor option of that name only adds classes to the safelist (`safelist.ts:81`); the unresolved-call throw at `:84-86` fires regardless of it. Taken literally the remedy is a type error; taken as the extractor option it does not clear the build error. The template itself tells authors to keep that list empty (`scripts/build-safelist.ts`: `DYNAMIC_SAFELIST` is "Intentionally EMPTY").

## Evidence (executed)
- Probe in a scaffolded template app: `defineTheme({ colors: { brand: '#123456' }, staticManifest: ['bg-primary', 'bg-danger'] } as const satisfies ThemeSpec)` -> `TS2353: Object literal may only specify known properties, and 'staticManifest' does not exist in type 'ThemeSpec'.`
- `Object.keys(defineTheme({ colors: { brand: '#123' } }))` -> `['colors']`. `grep -rn staticManifest fluent-html/src fluent-html/dist/src` -> 0 hits.
- Extractor 83e81d2 on `Div('x').bg(MatchValue(tone, { ok: 'success', err: 'danger' }))`: default options -> throws `fluent-safelist: 1 fluent call(s) use a non-literal argument the scanner can't resolve.`; with `{ staticManifest: ['bg-success', 'bg-danger'] }` -> throws the same error. Only `onUnresolved: 'warn'` passes (and then emits no class).
- ESLint 10.11 with the template config on `.bg(BG[status])`: `no-dynamic-typed-styling-arg` error ending `or add the token to staticManifest (defineTheme())`.
- Fleet: 15/15 canonical repos carry the staticManifest sentence in 3 vendored files each (`CLAUDE.md`, `.ai/web-development/CLAUDE.md`, `.ai/web-development/fluent-html.md`); 15/15 run the extractor with `onUnresolved: "error"`; 14/15 keep `DYNAMIC_SAFELIST` empty (everyframe lists 2 classes).

## Why it matters
Pain 3: this is the message an agent gets at the layer that catches dynamic args (recon 02 probe #21: the extractor caught 1 of 33 probes, this shape), and half of its advice leads either to TS2353 or to a manifest edit after which the build still fails. Reach 3: the prose line is in the always-loaded CLAUDE.md of 15/15 canonical repos. Error quality and decision closure: two tools and the guideline disagree with the template on whether the manifest is a remedy at all.

## Rough idea (not a design)
The messages are the enforcement layer: fix their text so each names only remedies that clear it (inline the literal; branch with `.when()`/`.whenMatch()`/`Match` so each branch is literal). Delete the staticManifest clause from 3 messages and 4 prose lines (guideline delta about -4, plus 2 README lines). If a token-from-variable escape is wanted, that is a design question (an extractor option that suppresses a named call), not a sentence.
