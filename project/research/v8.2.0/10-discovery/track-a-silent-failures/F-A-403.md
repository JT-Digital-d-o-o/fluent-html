# setStyle/setStyles after an anchor or view-transition emitter erases it

## Problem
Since 6.1.1, `anchorName`, `positionAnchor`, `positionArea` and `viewTransitionName` write inline style through `addStyle` (`tailwind-methods.ts:1004-1010`). They share the `_style` slot that `setStyle`/`setStyles` replace (`tag.ts:189-191, 433-438`). A trailing style setter therefore silently deletes the anchor wiring:

```ts
Div(items).setId(menu).setPopover().positionAnchor(menu).positionArea("bottom").setStyle(`--menu-w: ${w}px`)
// -> <div id="menu" style="--menu-w: 240px" popover="auto">   (position-anchor/position-area gone)
```

The guidelines give the opposite mental model. They call these "class emitters" with `[anchor-name:--<id>]` comments (gl/fluent-html.md:471-476) and tell the reader to safelist them (gl/htmx.md:615). The author therefore has no reason to expect a style setter to interact with them. CLAUDE.md steers runtime values to `.setStyle(...)`, which is exactly the call that erases them.

## Evidence (executed)
- **Render (dist 8.1.0).** All three shapes lose the emitter:
  - `positionAnchor+positionArea` then `setStyle`
  - `anchorName` then `setStyles`
  - `viewTransitionName` then `setStyle`
  - The reversed order keeps every declaration, so the outcome depends on call order.
- **Browser (Chromium).** Trigger bottom is at 61px.
  - Popover anchored only: top 61px, left 47px.
  - Anchor then `setStyle`: top 0px, left 0px (the UA popover default).
  - `setStyle` then anchor: 61px again.
- **Static layers.** tsc 0 on `tpl/src/app/probes/a4.ts:15-17`. eslint 4.1.0 flags only the literal `min-width` (`no-fluent-equivalent-in-setstyle`). The dynamic custom property and `setStyles({ "view-transition-name": … })` pass.
- **Fleet (dedup).** 66 emitter calls; 0 are followed by a replacing setter today. The hazard is latent.

## Why it matters
impact 2 × pain 3 × reach 1 / effort S = 6.
- The anchored menu or view transition detaches with no signal on any layer.
- The fault depends on call order, so it can appear or disappear on an unrelated refactor.
- The teaching corpus still describes the pre-6.1.1 class behaviour and a safelist step that no longer applies. That is 6 lines of wrong prose loaded into context.

## Rough idea (not a design)
Serialize layer, 8.1.x, since it only changes bytes in the clobber case, which never worked:
- The four emitters append to their own slot, which is merged after `_style` at render. `set*` keeps replacing the author's style (S-08), and the emitters stop being user style.
- Delete gl/htmx.md:615 (the safelist advice) and the class comments at gl/fluent-html.md:474-476 and gl/htmx.md:610-612. Net guideline lines go down.
