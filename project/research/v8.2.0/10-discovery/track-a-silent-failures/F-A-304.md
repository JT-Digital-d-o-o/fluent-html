# Dev aliasing guard is order-dependent

## Problem

The aliasing gate asks one question at mutation time: does this tag already have more than one parent
(`tag._p > 1`, dev-checks.ts:95)? Parents are counted when a constructor or `addChild` takes the tag
(tag.ts:92, :388). So a mutation made while the instance has 0 or 1 parents passes, even when the same
instance is parented again afterwards and the mutation lands in every copy. Iteration helpers build their
result array before any parent takes it, so every per-item mutation of one captured instance runs at
`_p == 0`. `ForEachKeyed` itself mutates what `renderItem` returns (`.setId(String(keyOf(item)))`,
iteration.ts:134), so one shared row gets every key in turn and keeps the last.

## Evidence (executed)

`$A3` = `<scratch>/wave1/A3`.

```
$ node $A3/alias-probe.mjs
P1b ForEach, shared badge mutated in item 2 of 3   NO THROW -> all 3 rows <span class="text-danger">
P1c ForEach, shared badge mutated in item 3 of 3   THROW: <span>.addClass() mutates a tag that is a child of 2 parents
P2  ForEach callback returns one captured Li, mutating it per item   NO THROW -> <li>x y z</li> x3
P3  ForEachKeyed renderItem returns a shared row   NO THROW -> <li id="3">row</li> x3
P4  ForEachKeyed overrides author setId on the row  NO THROW -> Li("x").setId("user-row-7") renders id="7"
P5  Intersperse non-thunk separator mutated during iteration   NO THROW -> both gaps text-primary
P7  module-scope Tag reused across 2 renders (dev)   THROW: already been rendered
```

The same data item decides whether the dev guard fires: P1b and P1c differ only in which row is late.
P3 emits three identical ids into a keyed list, which defeats the idiomorph keyed matching `ForEachKeyed`
exists for. P4 replaces an id the author set on the row root with the raw key.

Fleet (`alias-census.mjs`, TypeScript AST, 58 dedup repos, 9,713 non-test files): 3,247 `ForEach` /
`ForEachKeyed` / `ForEachElse` / `Intersperse` / `Repeat` calls; 0 callbacks mutate a Tag bound outside
the callback (5 raw hits were object-property names, checked by hand); 0 module-scope Tag constants; 0
`ForEachKeyed` callbacks calling `setId`; 2 non-thunk `Intersperse` separators, both strings
(everyframe-composer captions.components.ts:256, onboarding.how-it-works.view.ts:252). 0 repos call
`setDevChecks`; 0 direct writes to public `.child`/`.toggles`.

## Why it matters

impact 2: duplicated state or duplicate ids across rows, dev-only guard promise broken. pain 2: the guard
exists and passes, so a developer trusts it. reach 1: 0 live instances; presets-as-functions teaching and
the 7.0.1 guards hold in the fleet. Hurts silent-failure and verification-loop (the 5 aliasing tests at
test/dev-checks.test.ts:83-117 all take both parents before mutating).

## Rough idea (not a design)

Dev-throw layer, dev-only cost: iteration helpers check result identity (a `Set` over Tag results, only
when `devChecks`), which catches P2, P3 and P5 at the call; `countParents` records a mutation stamp and
throws when a tag gains a parent after being mutated since its previous parenting, which catches P1b.
`ForEachKeyed` could refuse to overwrite an id already present on the row root in dev (P4). Parked on
reach 0; no prose to delete.
