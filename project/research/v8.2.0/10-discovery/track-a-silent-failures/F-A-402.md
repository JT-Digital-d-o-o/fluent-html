# behavior("toggle") flips the `hidden` class only; an attribute-hidden target never shows

## Problem
fluent-html offers two ways to hide an element. `.hidden()` emits `class="hidden"`. `.toggle("hidden")` emits the HTML `hidden` attribute, and the `setHidden` JSDoc (`tag.ts:601`) calls it "plain hiding". The behaviors runtime understands only the first.

`toggle`, `onEscape`/`onClickOutside` with `action: "hide"`, and the `force` option all test and flip `classList` (`runtime.ts:41, 201-202, 215-216`). Take a panel hidden the documented way:

```ts
Button("Filters").behavior("toggle", { target: ids.panel })
Div(...).setId(ids.panel).toggle("hidden")
```

The first click adds `class="hidden"` to an element the attribute already hides. The second click removes the class. The attribute stays, and Tailwind v4 preflight's `[hidden]{display:none !important}` keeps the panel hidden forever. The two ways of hiding carry no type distinction, and the guideline table says only "toggle `hidden`" (htmx.md:551).

## Evidence (executed)
- **Browser.** Chromium, shipped `dist/fluent-behaviors.8.1.0.js`, Tailwind 4.3.3 CSS. `checkVisibility()` over initial, click 1 and click 2:
  - attribute-hidden panel: `false, false, false`
  - class-hidden panel: `false, true, false`
  - DOM after click 2: `<div id="pa" hidden="" class="">`. 0 page errors.
- **Static layers.** tsc 0 and eslint 4.1.0 0 messages on `tpl/src/app/probes/a4.ts:10-13`. The extractor has nothing to check, and the dev runtime does not throw.
- **Acceptance matrix.** `test/acceptance/app.mjs:56` injects `.hidden{display:none}` into every page. The class contract is assumed, and no row hides a target with the attribute.
- **Fleet (dedup).**
  - `.toggle("hidden")`: 8 sites in 4 repos; the 5 canonical app-authored ones are shown by app JS, not by a behavior.
  - Behavior-toggle targets: the 3 canonical ones checked use `.hidden()`.
  - The template's listbox pack also uses the class.
  - Reach today is 0 live instances. The hazard is carried by the JSDoc and by the vanilla/htmx prior (`el.hidden = !el.hidden`).

## Why it matters
impact 3 × pain 3 × reach 1 / effort S = 9. The control does nothing, and every layer is clean. This is a decision-closure gap: there are two hiding forms and the runtime honours one. The library's own JSDoc names the other form as the default.

## Rough idea (not a design)
Runtime layer. Showing removes both the `hidden` class and the `hidden` attribute; hiding keeps adding the class. The wire grammar is unchanged (S-21), and the emitted bytes are unchanged. Add a matrix row with an attribute-hidden target. Replace "toggle `hidden`" at htmx.md:551 with the one contract, which is shorter than the current ambiguity, and drop "Plain hiding is `.toggle(\"hidden\")`" from the `setHidden` JSDoc.
