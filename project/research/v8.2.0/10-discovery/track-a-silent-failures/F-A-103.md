# hx-status values are emitted unquoted

## Problem
`buildStatusConfig` joins `key:value` pairs with spaces and never quotes a value. htmx 4 parses the attribute with HCON, which splits on whitespace, so any value containing a space is torn apart. The types invite exactly those values: `HxStatusConfig.target` is `HxTarget` (`closest ${string}`, `find ${string}`, ...) and `HxStatusConfig.swap` is the full `HxSwap` (style + modifiers).

```ts
status: { 422: { target: "closest form", swap: "outerHTML", push: false } }
// emits hx-status:422="swap:outerHTML target:closest form push:false"
// HCON: { swap: "outerHTML", target: "closest", form: true, push: false }
```

## Evidence (executed)
`node probe3.mjs` (Chromium, a7/b4/b6/ga), 422 response `<form id="form">FORM-ERR</form>`:

| hx-status:422 value | a7 | b4 | b6 | ga |
|---|---|---|---|---|
| fluent today `target:closest form` | lands nowhere | nowhere (+warn `'closest' on hx-target did not match any element`) | nowhere (+warn) | nowhere (+warn) |
| quoted `target:"closest form"` | form swapped | swapped | swapped | swapped |
| JSON `{"target":"closest form"}` | swapped | swapped | swapped | swapped |

Modifier inside the status swap (scrolled box at scrollTop 900, response 422):

| value | a7 | b4 | b6 | ga |
|---|---|---|---|---|
| main swap `innerHTML scroll:top`, 200 (control) | 0 | 0 | 0 | 0 |
| fluent today `swap:innerHTML scroll:top` | 900 | 900 | 900 | 900 |
| quoted `swap:"innerHTML scroll:top"` | 0 | 0 | 0 | 0 |
| `swap:innerHTML` (no modifier baseline) | 900 | 900 | 900 | 900 |

`node probe.mjs S` also executed the three keys recon 03 left static-only: `select:#form`, `replace:/replaced` and the `4xx` wildcard all work 4/4, so the defect is confined to values with spaces.

Fleet (`census.mjs`, dedup corpus): spaced status targets 0 sites (the template's `{ invalid }` takes an `Id`, safe); status swaps carrying a modifier 5 sites, all in planet-positive-sport (`swap: "outerMorph scroll:top"` on the 422 re-render, htmx beta4, lib 5.11.0 which emits the same unquoted form at `render.js:137`): those five re-renders never reset scroll.

## Why it matters
impact 2 (validation errors land nowhere, or land without the requested scroll), pain 3 (tsc, lint, extractor, dev runtime all clean; b4/b6/ga emit only a console warning, a7 nothing), reach 2 (5 live sites; every `HxStatusConfig` value with a space). The v6.0.1 disposition treated the swap split as a byte-level no-op; it is a runtime difference on every bundle. Scorecard: silent-failure, invariant-safety.

## Rough idea (not a design)
Enforcement layer: runtime (serializer) + ci row. Emit each value HCON-quoted (`target:"closest form"`, `swap:"outerHTML show:top"`) or emit the JSON object form HCON accepts when the value starts with `{`. Lane 8.1.x: bytes change only for forms that never worked (values without spaces stay byte-identical if quoting is applied only when needed). Pin each key with an executed row in the F-A-101 oracle.
