# Color tokens named like scale keys hijack merged prefixes with no diagnostic

## Problem

Merged methods (`.text`, `.border`, `.ring`, `.outline`, `.stroke`, `.insetRing`) resolve size vs
color by the value. Tailwind 4.3.3 resolves a functional `text-lg` to `--color-lg` when that color
exists, dropping the font-size. So a project color named `lg` or `2` re-points every `.text("lg")`
or `.border("2")` in the app. The type union has the name in both arms (no error), `defineTheme`
only compares custom families against each other, and the vocab oracle loads the stock theme.

```ts
colors: { ..., lg: "#0e7490", "2": "#94a3b8" }
H2("Big promo").text("lg")          // compiled: .text-lg{color:var(--color-lg)}   (no font-size)
Div("card").border("2").border("line") // compiled: .border-2{border-color:var(--color-2)} (no width)
```

Static utilities are affected differently: a color named `center` makes `text-center` emit
`text-align:center; color:var(--color-center)` and `bg-center` add `background-color`.

## Evidence (executed)

`$A2 = <scratch>/wave1/A2`.

- `node $A2/collide-enum.mjs`: every stock non-color class of 20 color-accepting prefixes from
  `design.getClassList()` = 1,588 classes / 1,434 suffix names; with all names registered as
  `--color-*`, 1,485 classes change CSS (1,431 names).
- `node $A2/collide-enum2.mjs` (property-level): 65 names remove the stock property from 82 classes;
  the plausible token names among them: `0 1 2 3 4 8` (border/ring/outline/stroke/inset-ring widths,
  23 classes) and `xs sm base lg xl 2xl 3xl 4xl 5xl 6xl 7xl 8xl 9xl` (13 text sizes) = 19 names,
  36 classes. `ring-inset` gains `--tw-ring-color`.
- `node $A2/collide-detail.mjs` (single token each): `text-lg` stock `font-size: var(--text-lg); line-height: …` -> with `--color-lg` `color: var(--color-lg);`; `border-2` -> `border-color: var(--color-2);`; `ring-2` -> `--tw-ring-color: var(--color-2);`; `text-center` -> `text-align: center; color: var(--color-center);`.
- Full pipeline on the probe app (template theme + `lg`, `"2"`): tsc exit 0, eslint exit 0,
  `npm run css` exit 0, **defineTheme warnings: 0**; compiled CSS `.text-lg{color:var(--color-lg)}`,
  `.border-2{border-color:var(--color-2)}`; render `<h2 class="text-lg font-semibold">`.
- Bounds: the stock-theme typed domain is clean (`$A2/typed-domain-oracle.mjs`: 10,026/10,026
  type-admitted literal classes compile), and every class the 16 canonical apps safelist compiles
  under their own theme (`$A2/fleet-oracle.mjs`: 8,129 classes, 39 null = 37 non-Tailwind markers
  `group`/`peer`/`htmx-indicator` + 2 phantom sample strings). The hole is token naming, not the vocab.
- Reach: `node $A2/theme-census.mjs`: 30/58 repos carry color tokens (defineTheme or `@theme`);
  0 use any of the 19 names (template names closest: `text`, `bg`, `line`, which do not collide).

## Why it matters

impact 2 (size or width silently replaced by a color on every call site of that value) x pain 3
(0 diagnostics on every layer, and the break lands far from the token definition) x reach 1
(0/30 repos today; tokens are role names by guideline) / effort S. It is the one merged-prefix
disambiguation failure the 29/29 family probe cannot see, because that probe runs on the stock theme.

## Rough idea (not a design)

Type layer if feasible: gen:vocab derives the reserved set (19 plausible names, or all 65) from the
pinned design system and `ThemeKeys<…, "colors">` maps a reserved key to an error-bearing type;
fallback dev-warn in `warnOnAmbiguousTokens` against the same generated list. Oracle: a
property-landing check that loads a project theme.
