# Losing override is live at 97 sites in 11 of 16 canonical-era repos; the decided merger is unbuilt

## Problem

`Tag` storage is append-only (`addClass` concatenates, src/core/tag.ts:161-174) and the serializer emits
`_class` verbatim (src/render/serialize.ts:227-228). A preset or component base followed by a same-family
override emits both classes, and Tailwind's stylesheet order, not call order, picks the winner. Numeric
scales win only when the override sorts later; color tokens sort alphabetically; display keywords sort
alphabetically. No layer reports it: tsc, eslint 4.1.0, the extractor, the Tailwind build and the dev
runtime are all clean (recon 02 probes #28b/#28c).

The fix was decided on 2026-08-14 (fluent-html-batch decisions.md:41-45: family-keyed, memoized,
last-write-wins at serialize time; opt-in flag in a minor, default-on next major; fleet re-render diff
gate) and is unbuilt at 8.1.0 (0 merge code in `src/`). fluent-html's own decision log was never revised:
`project/pm/decisions.md:94` still reads "No runtime class merger ever (append-only stays)", and
CHANGELOG.md:228 still says the fix "needs a decision". An implementer working from the lib's log refuses
the build.

## Evidence (executed)

`$A3` = `<scratch>/wave1/A3`.

**Method** (`override-census.mjs`): TypeScript AST over every non-generated `.ts` file of the 16
canonical-era repos of the dedup corpus (15 apps pinned 8.1.0/7.0.0 + projects-template incl.
`packages/ui`; `.claude/` worktrees skipped). For each outermost fluent chain (124,885), class writes are
collected in call order from direct literal calls, tier-1 variant objects and `.variant()`, `.when` /
`.whenElse` / `.whenMatch` branches, `.apply(preset)` (4,530 preset references resolved, including across
imports; 60 unresolved), and user-component bases (1,580 resolved). Each class is computed by calling the
8.1.0 dist method. Family = the CSS property set Tailwind 4.3.3 emits for the class, with the repo's
`theme.ts` tokens loaded. A pair counts only when the earlier write fires whenever the later one does
(unconditional, or an ancestor branch); two independent `.when()` branches are excluded (28 such would-lose
pairs not counted). Winner: `design.getClassOrder`, then re-checked by byte offset in the repo's own
`public/css/styles.compiled.css`.

## Why it matters

impact 3: validation borders, danger text, disabled cursors, danger hover tints and headings render the
wrong state in production. pain 3: silent on all 5 layers; the prose rule (views.md:126, 2026-07-25,
prose-only) preceded 96/97 sites and the merger decision preceded 89/97, so prose did not hold and the
library's own log blocks the fix. reach 3: 11/16 canonical-era repos, 21/32 pre-7 repos. Hurts
silent-failure and verification-loop (no layer can see a cross-file preset conflict), and context-economy
(a prose-only rule plus template docstrings that do not work).

## Rough idea (not a design)

Strongest layer is runtime: build the decided merge inline at the class emit (serialize.ts:227-228)
behind an opt-in render flag in 8.2.0, default-on in 9.0.0. Derive the family key at gen:vocab time from
the pinned oracle's property set (guardrail 9: re-derived, never hand-edited; one key for the merged
prefixes and for arbitrary values). Use this census as the fleet re-render diff gate corpus: the 97
canonical sites are the expected class-attr deltas, the 127 LUCK sites should produce shorter class
strings with unchanged computed style. Revise pm/decisions.md:94 and CHANGELOG.md:228 in the same change.
When default-on, delete views.md:126-133 (8 lines) and the template docstrings at layout.ts:14 and
:27-28. Display keywords need a carve-out first (see F-A-302).
