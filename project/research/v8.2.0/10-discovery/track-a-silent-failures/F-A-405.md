# setDownload(true|false) name the downloaded file "true"/"false"

## Problem
`setDownload` is typed `string | boolean`, which invites `setDownload(true)` ("make it a download") and `setDownload(isExport)`. The serializer stringifies the value, so the attribute becomes the suggested file name:

```ts
A("Export").setHref(url).setDownload(true)   // <a download="true">  -> saved as true.<ext>
A("Open").setHref(url).setDownload(false)    // <a download="false"> -> still downloads, as false.<ext>
```

## Evidence (executed)
- **Browser (Chromium).** Link to `/files/report.csv`:
  - `true` saves as `true.txt`.
  - `false` saves as `false.txt`, so the download is not suppressed.
  - `""` saves as `report.csv`, which is what `true` should mean.
- **Static layers.** tsc accepts both booleans (the declared type), and eslint is silent.
- **Fleet (dedup).** 15 `setDownload(` sites: file names, `""` x4 and one bare call. None passes a boolean, so fixing the boolean arms changes no live output.

## Why it matters
impact 2 × pain 2 × reach 1 / effort S = 4. Two of the four argument shapes the type admits never worked (the bare call is F-A-404). L-029 deferred this as "a separate issue". The browser measurement shows that `false` is actively wrong, not only cosmetic.

## Rough idea (not a design)
Serializer, 8.1.x: `true` becomes bare `download` and `false` omits the attribute. Emitted bytes change only for values that never produced the intended file, which is within the 8.1.x lane rule. The alternative is to narrow the parameter to `string` in 9.0.0; the codemod dry run is 0 sites.
