# Non-Latin-1 hx-headers values kill the request

## Problem
HTTP header values must be ISO-8859-1; `fetch` throws on anything else. The typed `headers` bag accepts any string and the serializer passes it through as JSON, which htmx parses back into the same Unicode string before calling `fetch`. The library already knows this constraint: `HxResponse` runs its JSON through `toHeaderSafeJson` (the 6.3.0 "hxresponse latin1" fix), but only on the response side. In a fleet that serves Slovene (č, š, ž), any user-derived value in a request header stops the request.

## Evidence (executed)
`node probe.mjs H` (Chromium, 4 bundles), `Button(...).setHtmx(hx(u, { target: "#t", headers }))`:

| headers | emitted | requests reaching server | #t | error |
|---|---|---|---|---|
| `{ "X-Who": "Toni" }` | `hx-headers="{&quot;X-Who&quot;:&quot;Toni&quot;}"` | 4/4 | new | none |
| `{ "X-Who": "Tonič" }` | `hx-headers="{&quot;X-Who&quot;:&quot;Tonič&quot;}"` | 0/4 | old | `TypeError: Failed to execute 'fetch' on 'Window': Failed to read the 'headers' property from 'RequestInit': String contains non ISO-8859-1 code point.` |

tsc and eslint: clean (tsprobe line 18). The only signal is an `htmx:error` event; the control silently does nothing.

Fleet: a narrow grep for a `headers:` key inside `hx(`/`setHtmx(`/`hxGet(`/`hxPost(`/route-callable bags in app code returns 0 sites; the template's only request header (`hx-headers:inherited` with the ASCII behaviors stamp, `templates/full-stack/src/core/behaviors/runtime.ts:124`) is safe.

## Why it matters
impact 2 (the request never fires), pain 3 (clean on every layer; fails only for some users' data, so it passes every English-language test), reach 1 (0 current sites). Scorecard: silent-failure.

## Rough idea (not a design)
Enforcement layer: dev-throw. At serialize, reject a header value with a code point above U+00FF and name the fix (`encodeURIComponent` it and decode server-side, or send it in `vals`). JSON-escaping in the attribute does not help, because htmx JSON-parses it back before `fetch`. Pin with an executed row.
