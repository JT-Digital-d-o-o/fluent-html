# Bare calls to optional-arg setters compile and render nothing

## Problem
Most element setters declare their value optional (`setAlt(alt?: string)`, `setDownload(download?: string | boolean)`), so `undefined` clears. The same `?` also admits a **bare call**, which compiles and renders nothing.

The library is inconsistent about what a bare call means:
- `setPopover()`, `setContenteditable()`, `setSpellcheck()` and `setSandbox()` emit a default.
- `setDownload()` and `setCrossOrigin()` emit nothing, although HTML gives both `download` and `crossorigin` a meaning when present and empty.

Authors who write the bare form mean "turn it on" (`download`) or "empty" (`alt=""` for a decorative image), and get neither:

```ts
A("Download").setHref(route.resolve(...)).setDownload()   // -> <a href="...">Download</a>
Img().setSrc(url).setAlt().setLoading("lazy")            // -> <img src="..." loading="lazy">  (no alt)
```

## Evidence (executed)
- **Surface.** One bare call per setter slot (414 slots, Tag base included) under tsc 6.0.3: 187 compile. At runtime, 181 of those render unchanged and 6 emit a default.
- **Fleet (dedup corpus, code only).** 4 bare calls to the 181, and **4/4 lose the author's intent**:
  - everyframe-composer (8.1.0): `experiments.stage.view.ts:188` `.setDownload()`, `library.components.ts:37` `.setAlt()`
  - planet-positive-sport (5.11.0): `auth-layout.view.ts:84` `.setAlt()`
  - tela (5.7.0): `projects.ts:789` `.setAutocomplete()`
- **Browser (Chromium).**
  - The bare `setDownload()` link navigates to the file (text/plain served inline) instead of downloading.
  - The bare `setAlt()` image has no `alt` attribute, so assistive tech falls back to the file name.
- **Static layers.** tsc 0 and eslint 0 on the fixture (only the unrelated cursor rule fires).

## Why it matters
impact 2 × pain 3 × reach 2 / effort M = 6.
- Two of the four live sites are on the current canonical version, one of them an accessibility defect.
- The code reads as correct, and no layer can tell a bare call apart from an intended clear.
- Bare-call semantics differ across setters (default vs nothing), so the prior cannot learn one rule.

## Rough idea (not a design)
Type layer: `value?: T` becomes `value: T | undefined` on the 181 no-op slots. Explicit `undefined` still clears (L-164), and the bare call becomes `TS2554 Expected 1 arguments, but got 0` with the parameter name. The change is breaking, so it goes in 9.0.0, codemod-first. The measured dry run is 4 sites fleet-wide, all of them bugs, and each needs a human value (`""`). No prose is involved.
