# hx-config mode: dead per element, unchecked globally

## Problem

- `HxConfig.mode` (`htmx.ts:245`) is a closed, typed per-element key. Both bundles overwrite it unconditionally after merging: beta6 `htmx.js:459` and 4.0.0 `htmx.js:422`, with the comment "mode is security-sensitive, never allow per-element override". The typed knob emits bytes that never take effect.
- The global key that does work, `HtmxGlobalConfig.mode` (`patterns.ts:138`), is typed `string`. A typo therefore compiles, and `fetch` throws on every htmx request on the page.

This is the second half of recon 03 seed 2. F-A-104 covers `credentials`.

## Evidence (executed)

`mode.mjs` uses two origins, 127.0.0.1:47811 (page) and :47812 (CORS-enabled endpoint that logs `Sec-Fetch-Mode`), across 3 engines × beta6 and 4.0.0:

```
V1 no config (control)                hits: 0   (default mode same-origin; 'Request mode is "same-origin"')
V2 per-element config {mode:'cors'}    hits: 0   12 of 12 (engine x bundle x value) identical to V1
V3 per-element config {mode:'no-cors'} hits: 0
V4 global HtmxConfig({mode:'cors'})    hits: OPTIONS sec-fetch-mode=cors; GET sec-fetch-mode=cors; swapped 6/6
```

`mode2.mjs` is same-origin:

```
control (no config)              hits 1, swapped   6/6
HtmxConfig({mode:'cros'})        hits 0            6/6  (Chromium: "Failed to read the 'mode' property from 'RequestInit'"; Firefox: "'cros' ... is not a valid value for enumeration"; WebKit: "Type error")
HtmxConfig({mode:'same-origin'}) hits 1, swapped   6/6
```

- tsc 5.9.3 exits 0 for both `hx(…, { config: { mode: "cors" } })` and `HtmxConfig({ mode: "cros" })`. eslint (32 rules) reports 0 diagnostics on either line (`$R/tsprobe/probe.ts:26-27`).
- The lib's tests pin the dead per-element emission at `test/htmx.test.ts:130` and `:148`. `:130` also pins `credentials: true`, which F-A-104 showed makes `fetch` throw.
- Fleet: 0 `mode:` values in any config bag. All 58 `HtmxConfig(` calls across 46 repos set `defaultSwap` only.

## Why it matters

- impact 2: the per-element knob is a no-op, and the global typo kills every request.
- pain 1: the console shows a fetch error.
- reach 1: 0 fleet sites.

It hurts silent-failure, and decision-closure: an open `string` where the platform has a 4-member enum, and a closed key where htmx accepts none.

## Rough idea (not a design)

The enforcement layer is type.
- Remove `mode` from `HxConfig`. That is breaking, but 0 fleet sites means a 0/0 codemod.
- Narrow `HtmxGlobalConfig.mode` to `"cors" | "same-origin" | "no-cors" | "navigate"`.
- Rewrite `test/htmx.test.ts:130` and `:148`.

This belongs in the same RFC as F-A-104's `credentials` repair, so that the `hx-config` bag is fixed once, in the 9.0.0 bundle.
