# Element-state keys forced through the request bag

## Problem
`HTMX` requires `endpoint` and `method`, and `buildHtmx` always opens with `hx-<method>="..."`. Three keys in the same bag describe the element, not a request: `preserve`, `boost`, `swapOob`. To set one through the typed API an author must invent an endpoint, and that endpoint ships:

```html
<div id="p" hx-get="/unused" hx-preserve="false">NEW</div>
<a id="b" href="/page2" hx-get="/page2" hx-boost="true">boosted</a>
<div id="oob" hx-get="/invented" hx-swap-oob="true"><span>oob-new</span></div>
```

## Evidence (executed)
`node probe.mjs B` and `node probe2.mjs`:

| typed input | a7 | b4 | b6 | ga |
|---|---|---|---|---|
| `preserve: true` | preserved (OLD) | OLD | OLD | OLD |
| `preserve: false` | preserved (OLD) | OLD | OLD | OLD |
| `boost: true` on `<a>`, clicked | not boosted, 1 htmx GET, URL `/` | same | same | same |
| `swapOob: true` content, then click the swapped-in node | fires `GET /invented`, swaps `INVENTED` in | same | same | same |

`probe2.mjs` (b6, ga): after clicking the typed boosted anchor, `a#b.innerHTML` = `<p id="p2">PAGE2</p>` and the URL stays `/` (`HX-Request-Type: partial`, no `HX-Boosted`); the untyped control `<div hx-boost="true"><a href="/page2">` navigates to `/page2` and swaps the body. So `boost: true` turns a link into a widget that stuffs the next page into itself.

tsc/eslint: clean (tsprobe lines 10-12). Fleet (`census.mjs`): typed `preserve:` 0 app sites, `boost: true` 0 (2 in lib tests), `swapOob:` 0 (5 in lib tests); `hx-swap-oob` appears only as hand-written literals (29 sites / 10 repos, 9 in the lib).

## Why it matters
impact 2 (a flag that cannot be turned off; a boost that breaks navigation; swapped-in content that makes requests to an endpoint nobody meant), pain 3 (every layer clean, including the byte tests that pin these strings), reach 1 (0 typed sites; the keys earn nothing today). Scorecard: silent-failure, decision-closure.

## Rough idea (not a design)
Enforcement layer: type. 9.0.0: remove `preserve`, `boost`, `swapOob` from `HTMX`/`HxOptions` (codemod dry run: 0 fleet sites, 7 lib test sites) and, only if a use case earns it (S-23), add endpoint-free setters that emit presence semantics (`hx-preserve` bare, never `"false"`). Until then an 8.1.x serializer fix can gate `hx-preserve` on truthiness like `hx-ignore` (L-009's own suggestion). Related open design: typed `:inherited` (L-102) is the htmx-4 way to express container-level keys like boost.
