# A JSON data value containing <!--<script> swallows the rest of the page through Script(JSON.stringify(x))

## Problem
`sanitizeRawContent` (serialize.ts:210) rewrites only `</script` inside a script body. The HTML tokenizer has a second exit-suppressing path: `<!--` followed by `<script` puts the script into the double-escaped state, where the real `</script>` no longer closes the element. The parked rationale (L-012) was that this "only matters inside the raw-JS escape hatch". It does not: the fleet serializes data into script bodies for JSON-LD and JSON data islands, and a data value (a product name, a blog title such as "How <!--<script> tags work") is enough.

For JSON-typed scripts a byte-safe transform exists that L-012 said was missing: in valid JSON `<` can only occur inside strings, where `<` parses to the identical value.

## Evidence (executed)
`jsonld-probe.mjs`: a Document with `Script(JSON.stringify({"@type":"Product",name:"Deluxe <!--<script> set"})).setType("application/ld+json")` in the head, then `Main(H1, P)`, an app `Script`, and a `Footer` in the body:
```
Script(JSON.stringify(x)) (lib default)            {"h1":null,"footer":null,"bodyChildren":0,"appScriptRan":0,"ldScriptLen":200}
Script(JSON.stringify(x).replace(/</g,'\\u003c'))  {"h1":"Deluxe set","footer":"footer","bodyChildren":3,"appScriptRan":1,"ldScriptLen":62}
```
The unprotected render loses all 3 body children and the app script never runs; nothing errors.

Fleet (grep over the dedup corpus): 15 repos emit `application/ld+json`; 14 route it through a `jsonLdScript` helper that hand-rolls `.replace(/</g, "\\u003c")` (template full-stack seo.meta.ts:39 and 13 copies). 2 sites do not: the template's own **web** starter (templates/web/src/shared/seo.ts:127, fed a blog title by `BlogPostingSchema` at :169) and workshop-toni narration.components.ts:63 (`application/json`). gzs/inovacije library.view.ts:76 goes through `Raw("<script ...>" + JSON.stringify(...))`, which gets no sanitizing at all.

## Why it matters
impact 2 (the whole body disappears for every visitor of that page) x pain 3 (no error; tsc, lint, extractor and the render are clean; the page looks empty) x reach 2 (16 repos put data in script bodies; the escape is known tribal knowledge copied 14 times and missed in the template's web starter) / effort S.

## Rough idea (not a design)
Runtime layer in the serializer: in the `script` render context, when the element's `type` is a JSON MIME (`application/json`, `application/ld+json`, `importmap`), replace `<` with `<` in string and RawString children. Bytes change only where `<` occurs inside JSON strings, with an identical parse; 8.1.x-eligible. It makes the 14 hand-rolled `.replace` calls redundant (idempotent: `<` contains no `<`). Non-JSON scripts keep the closer-only rule (L-012's corruption concern applies to JS, not JSON).
