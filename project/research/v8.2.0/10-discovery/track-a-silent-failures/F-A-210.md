# The theme manifest ships a dead cross-product and is a hand-kept vocab copy

## Problem

When `theme` is passed, `generateFluentSafelist` adds `themeToManifest(theme)`: every color token x 17
prefixes, every spacing token x 31, etc. Its stated purpose is tokens used behind variables. With the
default `onUnresolved: "error"` (16/16 canonical apps) any variable argument fails the build first,
so the manifest can never be the thing that styles a call; it only adds CSS. It also masks extractor
false negatives for color classes (a dropped `bg-<token>` is re-added by the manifest), which makes
the drop census in [[F-A-203]] undercount. And the prefix list is hand-maintained inside the
extractor, which the class-string contract (S-12, guardrail 9) says must be re-derived from class-vocab.

## Evidence (executed)

- Probe app (template theme, auth module): safelist with manifest 493 classes, without 135 (358
  manifest-only); compiled CSS 59,181 vs 19,339 bytes, gzip 8,580 vs 4,835.
- Fleet (16 canonical apps; tokens from `$A2/theme-census.json`, classes from the extractor over
  `src/**/*.ts`): 15/16 pass `theme` (everyframe calls `themeToCss` separately); manifest-only
  classes 8,508 against 7,341 classes those apps' fluent calls emit (e.g. stojnica 890, website-sales-
  funnel-automation-system 776, na-cent 627).
- Drift vs class-vocab (rows whose values include `--color`: bg text border divide shadow ring
  gradient from via to fill stroke accent caret decoration textShadow dropShadow insetShadow
  insetRing): the manifest lists `ring-offset` and `placeholder`, which no fluent method emits, and
  omits `text-shadow`, `drop-shadow`, `inset-shadow`, `inset-ring`.

## Why it matters

impact 1 (bytes, and a masked verification signal) x pain 1 x reach 3 (15/16 apps) / effort S.
The extractor is still `3.0.0-unreleased`, so removing or deriving it now costs no migration.

## Rough idea (not a design)

CI/contract: delete the unconditional manifest (or gate it on `onUnresolved !== "error"`), and if a
prefix list survives, generate it from class-vocab like the extractor's other tables. Deletes the
README text describing the safety net.
