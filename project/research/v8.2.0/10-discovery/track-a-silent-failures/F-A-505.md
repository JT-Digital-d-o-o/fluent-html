# Under the template CSP, htmx executes every <script> in a swapped fragment regardless of nonce

## Problem
htmx 4 re-creates every `<script>` in swapped content (and in `Partial` template content) with `document.createElement('script')` (#processScripts, unconditional, no config key turns it off). The template CSP carries `'strict-dynamic'`, which trusts any non-parser-inserted script created by an already-trusted script. htmx.js is nonced, so every script it re-creates runs, with the page nonce, a fresh per-request nonce from `renderWithNonce`, or no nonce at all. The result is a CSP whose XSS backstop depends on how the user arrived: parser-inserted markup on a full page load is blocked, the identical markup reached by `.nav()` executes.

The template records the opposite. layout.view.ts:220-221 (2026-06-27): "htmx re-runs scripts in swapped content under a fresh nonce that the frozen document CSP rejects". That was true for the CSP of that day (nonce, no strict-dynamic). Three days later 6a5135c added `'strict-dynamic'`; nothing re-checked the claim, and the parked `no-inline-script` rule (L-341) and `no-dynamic-raw` lint (L-024) were deferred on the belief that CSP catches what escaping misses.

## Evidence (executed)
`frag-script-probe.mjs`: page CSP = template CSP with page nonce A; a button swaps a fragment (outerHTML) whose body is rendered by fluent 8.1.0:
```
                                       template CSP (today)     2026-06-27 CSP (nonce, no strict-dynamic)
                                       beta6     4.0.0          beta6     4.0.0
script, no nonce (Raw injection)       ran 1     ran 1          ran 0 (1 CSP err)   ran 0 (1 CSP err)
script, fresh nonce (renderWithNonce)  ran 1     ran 1          ran 0 (1 CSP err)   ran 0 (1 CSP err)
script, page nonce                     ran 1     ran 1          ran 1     ran 1
script inside Partial(), fresh nonce   ran 1     ran 1          ran 0 (1 CSP err)   ran 0 (1 CSP err)
```
Today: 8/8 execute, 0 CSP errors. Old CSP: 2/8 (page nonce only).

`fullload-probe.mjs` (4.0.0, template CSP): `Div(Raw("<p>CMS body</p><script>...</script>")).setId("main-content")`:
```
full page load                       scriptRan 0, cspBlocked 1
htmx nav (outerMorph #main-content)  scriptRan 1, cspBlocked 0
```
Reach: 16/16 canonical-era repos carry the template's security-headers CSP (grep for contentSecurityPolicy: 51/58 fleet repos, 16/16 canonical). Canonical app code has 22 app-authored `Raw()` sites (01-shipped-surface.md section 2.4), e.g. home-page blog.article.view.ts:112 `Raw(trackLinks(props.content))` in the swapped main region. 0 acceptance rows and 0 template e2e rows swap a script under the CSP (03-runtime-contracts.md section 5; htmx-smoke.spec.ts has 1 CSP row, full-load only).

## Why it matters
impact 3 (the defense-in-depth layer for XSS is absent on the path users take most in an htmx app) x pain 2 (0 console errors; the template's own comment tells readers the opposite) x reach 3 (every canonical-era app ships this CSP) / effort M. Hurts silent-failure resistance and the verification loop (no row measures CSP on a swap).

## Rough idea (not a design)
Strongest feasible layer is lint: ship the parked `no-inline-script` (Script with a body outside the shell) and a `Raw()`-with-non-literal rule (L-341, L-024), because CSP can no longer be counted on for swapped regions. Add one Playwright row that swaps a nonce-less script and asserts it does not run (it fails today, by design of the row). Delete the false sentence at layout.view.ts:220-221 and correct htmx-fragment-swaps/decisions.md. Dropping `'strict-dynamic'` restores blocking (2/8) but needs a nonce-propagating gtag loader; that trade is the template's call.
