# Components shipped as a package are invisible to the safelist

## Problem

Guardrail 5 (S-05) puts components in user-land `@jtdigital/ui`. The safelist pipeline only scans
the app's `src/**/*.ts`, and `globFiles` skips `node_modules`. A component package's fluent calls
run at render time from `node_modules/@jtdigital/ui/dist`, so their classes are emitted into HTML but
never safelisted: those components render unstyled, clean on tsc and lint. Adding the package's dist
to the glob instead fails the default build on its dynamic calls.

## Evidence (executed)

- `grep -l @jtdigital/ui` over the 16 canonical apps' package.json: 0 hits; the template's `src/`
  imports it 0 times. `projects-template/packages/ui` has 0 matches for safelist/extractor/@source.
- `scanFluent` over `packages/ui/src` (17 files): 47 classes, **20 unresolved-ledger calls**; over
  `packages/ui/dist` (16 .js files): 18 classes, 5 ledger calls (would throw under `onUnresolved: "error"`).
- Classes of the package not produced by the template's `src/**/*.ts` scan nor its theme manifest:
  11/47 (`w-5 rounded-lg cursor-not-allowed text-red-600 text-gray-500 text-gray-700 bg-white
  border-gray-200 focus:outline-none text-gray-900 text-gray-600`); the palette literals also
  contradict the role-token rule the template enforces.

## Why it matters

impact 3 (a consumed component renders with no styling beyond coincidental overlap) x pain 2
(silent; the fix needs knowledge of the extractor's glob) x reach 1 (0 consumers today) / effort M.
It blocks the architecture the guardrail prescribes rather than a current app.

## Rough idea (not a design)

Build layer: a component package runs the extractor on itself at publish and ships its class list
(0 ledger rows required), and apps fold it in through `staticManifest` or an extractor
`packages: [...]` option. No prose.
