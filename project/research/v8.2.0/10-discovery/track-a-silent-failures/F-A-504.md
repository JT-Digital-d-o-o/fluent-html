# The '\n' sibling separator renders a visible space before punctuation

## Problem
Both serializer loops join sibling children with `'\n'` (serialize.ts:357 and :445). In normal flow the browser collapses that newline to a space, so `P("We sent a sign-in link to ", Strong(email), ". Open it...")` renders "...to ana@example.com . Open it...". The model's prior (JSX, lit templates, plain HTML typed on one line) is that adjacent children touch. L-030 recorded the textarea/pre corruption from the same line and was deferred; the inline-punctuation effect is the visible one, and it is live in auth, legal and marketing copy across the canonical fleet. No layer sees it: tsc, lint, the extractor and `toContain` tests are all clean.

The instruction set has no way to put text flush against an element, so 5 canonical-era repos wrote their own escape route, each with a comment naming the separator; 5 of the 7 drop to `Raw(render(...))`, and one of those hand-escapes the data with `escapeHtml` inside `Raw` (competify landing.social-proof.view.ts:97), which turns a whitespace bug into an XSS-by-omission surface.

7/7 show the space.

Census (`sep-census.mjs`, TS AST, dedup corpus): 69 app sites where an element sibling is followed by text starting with `. , ; : ! ? ) ] } % » ” ’ …` or preceded by text ending in an opening bracket; 31 in canonical-era code across 9 repos (competify, everyframe, fl-um, gzs/stem-50, home-page, sportoawards, studio, website-sales-funnel-automation-system, workshop-toni). Split of the 31: 17 bare-string punctuation, 12 punctuation wrapped in an inline tag (`Span(".")`), 2 opening bracket before a tag.

Workarounds citing the separator (grep for the comment wording plus manual review): 7 sites in 5 canonical repos: competify x3 and home-page x1 (`Raw(\`${render(word)}${mark}\`)`), fluent-html-home-page `specimenParts` ("Array children and variadic children are both newline-separated by the serializer"), everyframe (switched a code line to a flex row so whitespace text drops), popri (moved the full stop inside the highlighted span).

Breaking cost of the obvious fix (`sep-reliance.mjs`): in canonical-era code 743 adjacent text/inline sibling pairs rely on the separator for their visible gap (e.g. `"sent to", Strong(x)`), 22 are hurt by it, 144 are neutral. Removing the separator wholesale would glue 743 pairs; it is not the fix.

## Why it matters
impact 2 (visible typo-grade defects in sign-in, registration and legal copy; pushes authors onto Raw) x pain 2 (clean on every layer; spotted only by eye) x reach 3 (9 canonical repos with live sites, 5 with workarounds) / effort M. Hurts silent-failure resistance and prior alignment.

## Rough idea (not a design)
Runtime layer, 8.1.x-eligible: in both loops, skip the `'\n'` when the next sibling is a string whose first char is closing punctuation, or the previous sibling is a string whose last char is an opening bracket. Bytes change only where the output is wrong today (19 of 31 sites); the check is one charCode read per string sibling in multi-child arrays (bench it under guardrail 2). The 12 tag-wrapped cases (`Span(".")`) go to a lint rule that suggests moving the punctuation into a bare string. That lets the 5 `Raw(render())` workarounds be deleted.
