# .behavior() bypasses the dev mutation gate; gate coverage is pinned by 3 spot checks

## Problem

8.0.0 privatized element storage and gated every element setter (L-058 shipped-since). The gate's
contract says it is "Called by every Tag primitive that writes to the instance" (dev-checks.ts:78-84).
The behavior mixin is registered on `Tag.prototype` from `src/behaviors/emit.ts:113` and writes
`this.attributes` directly, with no `assertMutable` call, so it is the one public mutator that neither
the mutate-after-render nor the aliased-child guard sees. The test file pins the gate with 3 spot checks
(test/dev-checks.test.ts:157-176) and has no enumeration, which is how a mixin outside `tag.ts` slipped.

## Evidence (executed)

`$A3` = `<scratch>/wave1/A3`.

The probe instantiates all 133 factories from `dist/src/elements/index.js`, walks each prototype chain,
finds an argument vector that changes the render for each public method, then (a) renders a fresh tag
and calls the method, (b) parents a fresh tag twice and calls the method:

```
$ node $A3/devcheck-probe.mjs      # 0.12 s
{ "total": 509, "guarded": 504, "silentCount": 1,
  "getters": ["Tag.getClass", "FormTag.getEnctype"], "noEffect": ["Tag.variant", "Tag.overlay"],
  "silent": ["Tag.behavior[\"toggle\",{\"target\":{\"id\":\"foo\",...}}] afterRender=SILENT alias=SILENT"] }
$ node $A3/devcheck2.mjs
variant  | throw: <div>.addClass() mutates a tag that has already been rendered | throw: ... child of 2 parents
overlay  | no-throw-no-change (wraps this in a new parent)
behavior-2nd-verb | SILENT mutate-after-render: <button data-behavior="clipboard" data-behavior-clipboard-value="k">x</button>
                  | SILENT alias: <div><button data-behavior="clipboard" ...>x</button></div>
```

So 506 methods mutate `this` (509 minus 2 getters minus `overlay`) and 505 are gated. A same-verb repeat
after render throws, but from `.behavior`'s duplicate-verb check ("duplicate verb on one element"), in
production as well, with a message that does not name the reuse.

Fleet hazard today: 0 aliased or module-scope Tag instances in 58 repos (F-A-304 census), so no live
misrender; `.behavior` has 808 fleet / 370 dedup canonical-era call sites (recon 01 §2.1).

## Why it matters

impact 2: in dev, a cached or aliased tag gains a verb on every parent without the throw the guard
promises. pain 1: needs aliasing first. reach 1: 0 live instances. It is a verification-loop defect: the
guard's coverage is asserted in a comment and 3 tests, not measured.

## Rough idea (not a design)

Dev-throw layer: `if (devChecks) assertMutable(this, "behavior")` at the top of the mixin (no emitted
byte changes, 8.1.x). The larger win is the sweep: the probe above is 74 lines and runs in 0.12 s; as a
test it pins "every public method that changes the render is gated" for all current and future mixins
(template-registered verbs go through `setHtmx`, already gated).
