# ForEachKeyed raw keys collide across lists

## Problem

`ForEachKeyed` writes `String(keyOf(item))` as the row root's `id` (`iteration.ts:133`), and ids share one document-wide namespace. The JSDoc states the rule (`:120-121`, "unique within the page; bake a prefix into keyOf"). All 5 teaching examples (both CLAUDE.md copies, `htmx.md:258`, `views.md:197`, README:191) write `ForEachKeyed(users, (u) => u.id, …)`.

When the same key appears in two keyed lists on one page, the collision goes unreported:
- the page has duplicate ids;
- idiomorph cannot match rows by key, so the "keyed" upgrade reverts to recreating rows, losing the focus, scroll and transition state it exists to keep.

An author cannot namespace the key with `.setId()` on the row, because `ForEachKeyed` overwrites it (F-A-304 probe P4).

## Evidence (executed)

`keyed3.mjs` tags every `<li>` with a JS expando, then morph-reorders the users list (`Dan,Bor,Ana,Cene`) with `outerMorph`:

```
b6 | control: one keyed list                      | node kept: 4/4 | new nodes: 0
ga | control: one keyed list                      | node kept: 4/4 | new nodes: 0
b6 | two keyed lists, raw ids 1..4 (taught shape) | node kept: 0/4 | new nodes: 4
ga | two keyed lists, raw ids 1..4 (taught shape) | node kept: 0/4 | new nodes: 4
b6 | two keyed lists, prefixed keys               | node kept: 4/4 | new nodes: 0
ga | two keyed lists, prefixed keys               | node kept: 4/4 | new nodes: 0
```

`keyed.mjs` shows the duplicate ids before the swap: `1x2, 2x2, 3x2`.

The collision is live in the fleet. popri's `MentorWall` (`mentor.wall.view.ts:248-253`) renders two lists on one page:
- the wall, keyed by `comment.id` (`:142`), over `commentsByBlock`, which holds all comments;
- "my notes", keyed by `comment.id` (`:223`), over `myComments`, the mentor's own comments (`mentor.service.ts:510-514`).

Each of the mentor's own block comments appears in both. Rendering popri's `MentorWall` from its source (`wall.ts`, popri's tsx, swap verbs loaded) with one own comment outputs:

```
elements with id 3f2a9c1e-0000-4000-8000-000000000001 : 2
<article id="3f2a9c1e-…" class="relative rounded-card border-2 b… | <div id="3f2a9c1e-…" class="rounded-card bg-surface-2 p-4"
```

Fleet census (`keyed-census.mjs`, dedup corpus, TS AST):
- 77 `ForEachKeyed` calls in 9 repos.
- `keyOf` shapes: 66 raw field, 6 function reference, 4 prefixed template, 1 template with a leading expression.
- 15 files hold 2 or more keyed lists, 10 of them in everyframe-composer.

All 8 checked repos use UUID primary keys, so collisions need the same entity in two lists, as in popri, rather than equal integers across tables.

Checks: tsc 0 and eslint 0 (32 rules) for two raw-keyed lists in one view (`$R/tsprobe/probe.ts:41`).

## Why it matters

- impact 2: rows are recreated on morph (0/4 kept), and duplicate ids are invalid HTML.
- pain 2: nothing visible until focus or scroll is lost mid-interaction.
- reach 2: the taught shape is raw at 66/77 sites, 15 multi-list files, and 1 measured live collision.

It hurts silent-failure and invariant-safety.

## Rough idea (not a design)

The enforcement layer is dev-throw. Under `devChecks`, the serializer keeps one `Set` of emitted ids per render and throws on a repeat, naming the id. That catches this collision, the duplicate-id checkbox group (F-A-603), and the shared-row case (F-A-304 P3) with a single check. The cost is dev-only, so guardrail 2 holds. Changing the 5 taught examples to a prefixed key (`` (u) => `user-${u.id}` ``) costs 0 net lines. Additive, so 8.2.0.
