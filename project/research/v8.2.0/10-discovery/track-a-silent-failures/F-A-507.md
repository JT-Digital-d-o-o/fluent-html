# Attribute collisions serialize three different ways

## Problem
serialize.ts:133-136 states one rule, "dedicated field (when set) > generic bag". `buildAttrs` implements three:
1. `id`/`class`/`style`: the bag value is skipped at :253, so `Div("x").p("4").addAttribute("class","mt-7")` renders `class="p-4"` (mt-7 gone; the line's own comment says "never silently dropped").
2. Every other typed attribute: both are emitted, typed first; the HTML parser keeps the first and drops the second, so the typed setter wins through invalid markup (`<a href="/typed" href="/bag">`).
3. `hx-*`: the bag is emitted before `buildHtmx`, so the parser keeps the **bag** value and discards the typed `setHtmx` one: the precedence is inverted.
No layer reports any of the three: tsc accepts `addAttribute(string, string)`, eslint's `no-raw-ids`/`no-tailwind-in-raw-class` do not cover `addAttribute("id"|"class")` (recon 02 probes 16-17), no dev warning exists.

## Evidence (executed)
`dup-probe.mjs` against dist 8.1.0: walked all element factories, 379 setter slots, 135 distinct `_sk` attribute names; for each, set the typed field and `addAttribute(sameName, "BAG")`:
```
typed + addAttribute -> duplicate attr emitted: 135/135, single: 0
class: <div class="p-4">x</div>      id: <div id="main">x</div>      style: <div style="color: red">x</div>
htmx:  <button hx-target="#bag" hx-get="/bag" hx-get="/typed" hx-target="#main" hx-swap="innerHTML">
Chromium keeps: button hx-target "#bag", hx-get "/bag" (bag wins 2/2); a href "/typed"; input type "email" (typed wins)
```
Census (dedup corpus, non-test): 3969 `addAttribute` call sites scanned; same-chain collisions in canonical-era code: 0 for every category. Literal-key tally: canonical-era `addAttribute` writes 0 typed or reserved names (17 are `hx-headers:inherited`/`hx-preserve`, 28 other); pre-7 code writes 2462 typed-attribute names and 126 reserved (`class`/`id`/`style`), all latent until those repos upgrade.

## Why it matters
impact 2 (a value the author wrote vanishes, or a typed htmx target is silently overridden) x pain 2 (clean on tsc and lint; the output is invalid HTML that browsers repair) x reach 1 (0 canonical sites today; 2588 pre-7 sites meet it on upgrade, and the pure-prior agent writes `addAttribute` 23-30 times per run, recon 02 D5) / effort S. Hurts silent-failure resistance and decision closure (three precedences for one gesture).

## Rough idea (not a design)
Dev-throw layer in 8.2.0: when a render finds a bag key that the tag also writes through a typed field, the id/class/style storage or its htmx config, throw naming both calls and the typed setter to keep; outside dev, emit each name once with the typed value (bytes change only for output that is invalid HTML today). The compile-time exclude of `addAttribute("id"|"class"|"style")` stays the parked-major L-066 for 9.0.0.
