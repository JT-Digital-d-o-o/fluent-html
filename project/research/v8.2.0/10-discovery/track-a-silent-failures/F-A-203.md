# Extractor text matching: false ledger rows break the default build, and the workarounds are blind spots

## Problem

The extractor finds fluent calls by regex over raw source (`\.${method}\s*\(`), including the
contents of strings. Any non-fluent call or code sample that shares one of the 159 vocab method
names (`.scale`, `.list`, `.text`) and has a non-literal argument becomes an unresolved ledger row,
and the default `onUnresolved: "error"` fails the css build. Four of 16 canonical apps hit this and
each hand-wrote a different glob exclusion to get green again. Everything in an excluded file is
then invisible to the safelist with no signal; everyframe's `dev.samples.ts:6-10` documents moving
code into a separate file so the scanner would not see it, and warns in prose that the file "must
never contain fluent styling calls" (nothing enforces that).

The same guards that suppress some false positives also create silent false negatives: a single-arg
call with a trailing comma on any of the 53 `prefix`-shape methods, a 3-arg `.variant(n, {…},)`, and
a capitalized receiver (`Card.bg("surface")`) produce no class and no ledger row.

## Evidence (executed)

`$A2 = <scratch>/wave1/A2`.

- `node $A2/app-safelist-run.mjs`: each app's own installed extractor (3.0.0-unreleased) over
  `src/**/*.ts` with `onUnresolved: "error"`, nothing written: **THROWS in everyframe (6),
  everyframe-composer (3), home-page (3), website-sales-funnel-automation-system (1)**; OK in 12.
- `node $A2/ledger-rows.mjs`: the 13 rows are `v.scale({ w: 1920, h: 1080 })` x5 and
  `rb.jobs.list(opts?: …)` (sample strings, everyframe), `alg.text(layer.value)`, `alg.list(…)` x2
  (template-literal code sample, home-page), `stream.scale({…})` x3 (fluent-ffmpeg,
  everyframe-composer), `governor.scale(prefetch)` (worker). 9 inside string contents, 4 real
  non-fluent receivers.
- The 4 filters exclude 5 + 5 + 22 + 24 = 56 files. `node $A2/excluded-census.mjs` (TS checker):
  those files hold 0 typed fluent styling calls today, so no class is lost yet; the exclusions are
  path-based and unguarded.
- `node $A2/drop-census.mjs` (typed ground truth: a call counts when `checker.getResolvedSignature`
  lands in `fluent-html/dist`): 16 apps, 3,628 files, 55,614 vocab calls + 2,735 variant calls; the
  extractor misses 0 of them; every one of the 13 ledger rows resolves to a non-fluent declaration.
  Wall time 32.5 s for all 16 (`time node drop-census.mjs`).
- Silent-skip shapes via `scanFluent`: `.cursor(\n "help",\n)` 0 classes / 0 ledger;
  `.p(\n "7",\n)` 0 / 1 (loud); `.variant(\n "aria-expanded",\n { bg: "surface-3" },\n)` 0 / 0;
  `Card.bg("surface")` 0 / 0. Full pipeline on the probe app: `Div("?").cursor(\n "help",\n)` and
  `.z(\n "40",\n)` -> tsc 0, eslint 0, css exit 0; `cursor-help`, `z-40` ABSENT from compiled CSS;
  dev render emits `class="cursor-help"`, `class="z-40"`. Fleet today: 0 such sites (drop census).
- Phantom classes from strings: `node $A2/fleet-oracle.mjs` finds `text-centre` and
  `hover:bg-blue-60` safelisted from string labels in
  `fluent-html-home-page/src/app/home/views/home.output.view.ts:74,80`.

## Why it matters

impact 2 (build failures that push apps into unguarded exclusions; latent unstyled output) x pain 2
(the failure message points at code that is not fluent; the fix each app invented is a blind spot)
x reach 2 (4/16 canonical apps carry a workaround) / effort M. It is also a verification-loop
cost: the ledger is only trustworthy if it has no false rows.

## Rough idea (not a design)

CI/build layer. A type-aware scan (the app's own `typescript`, already a devDependency in 16/16
apps; ~2 s per app measured) decides "is this fluent" by declaration, not by name, which removes
both the false rows and the guard-induced silent skips, and lets the 4 apps delete their filters.
Minimum version: skip string/template-literal contents and turn guard skips on typed shapes into
ledger rows.
