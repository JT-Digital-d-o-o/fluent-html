# Same-property overrides lose to Tailwind's sort order at 59 call sites in 7/16 canonical apps

## Problem

fluent-html emits every styling call into one append-only `class` attribute. When a chain sets the
same CSS property twice (a preset through `.apply()`, then a direct call; or a base, then a
`.when()` branch), both classes ship and the winner is whichever rule Tailwind happens to sort later
in the stylesheet, not the call the author wrote last. Two live examples on 8.1.0:

```ts
// home-page/src/app/contact/views/contact.view.ts:101-106 (fieldShell sets .border("hairline"))
f.input(name, type).apply(fieldShell)...when(errors[name] !== undefined, tt => tt.border("accent"))
// compiled CSS: .border-accent @84179 precedes .border-hairline @86223 -> the error border never shows

// competify/.../preglednice.checklist.view.ts:68 (monoLabel sets .tracking("widest"), components.ts:79)
Span(tool.phase).apply(monoLabel).text("px", 11).tracking("wider")
// compiled CSS: .tracking-wider @85126 precedes .tracking-widest @85215 -> "wider" loses
```

tsc, eslint, the extractor, the Tailwind oracle and the dev runtime are all clean on both.

## Evidence (executed)

Harness `$A2 = <scratch>/wave1/A2`.

1. `node $A2/override-census2.mjs`: for each of the 16 canonical-era apps (dedup corpus, recon 01), a
   TS program over `src/**/*.ts` (the safelist glob); every top-level fluent chain is linearized,
   resolving `.apply(fn)` to its declaration and descending into `.when/.whenElse/.whenMatch`
   callbacks. A pair counts when both classes share a Tailwind utility root and a CSS property
   whose value does not read `var(--tw-*)` (so `p` vs `px`, `text-sm` vs `leading-*`, `border` vs
   `border-dashed` are excluded, matching the decision's out-of-scope list). Loss = the override's
   `getClassOrder` key sorts before the base's.
   - 188 pairs in 10/16 apps; **63 lose, at 59 distinct call sites, in 7/16 apps**: competify 18
     sites, everyframe-composer 15, sportoawards 13, home-page 6, na-cent 4,
     website-sales-funnel-automation-system 2, fl-um 1.
   - By mechanism (losing/total): apply-then-direct 54/157, apply-then-conditional 6/19,
     direct-then-conditional 2/8, apply-then-apply 1/3.
   - By property: font-size 17, letter-spacing 15, color 6, padding-block 5, background-color 5,
     border-color 4, font-weight 4, padding-inline 2, max-width 2, margin-top 1, gap 1, padding-top 1.
   - Conditional (state) overrides that never render: home-page contact/meeting error borders
     (3 sites), na-cent money.components.ts:64, everyframe-composer projects.pad.view.ts:335 and :494,
     website-sales-funnel-automation-system prospects.board.view.ts:51.
2. `node $A2/override-matrix.mjs`: 2,070/4,140 = 50.0% of ordered same-property pairs lose over 12
   families (p, px, gap, text size, text color and bg on the template tokens + tints, rounded, font
   weight, shadow, border width, opacity, w). The order is unrelated to intent: `text-xs` then
   `text-sm` loses, `font-light` then `font-bold` loses, `p-8` then `p-4` loses,
   `bg-surface` then `bg-danger/10` loses.
3. Both example sites re-checked against each app's committed `public/css/styles.compiled.css`
   (byte offsets above).

## Why it matters

impact 3 (a written style never applies; for `.when` overrides the whole state is invisible) x
pain 3 (clean on all 5 layers; the idiom is taught: `.apply(preset)` + override) x reach 3 (7/16
canonical apps, 59 sites) / effort L. The record also contradicts itself: the merger was decided on
2026-08-14 (`projects-template/.../fluent-html-batch/decisions.md:41-45`) while fluent-html's own
`project/pm/decisions.md:94` still says "No runtime class merger ever".

## Rough idea (not a design)

Runtime enforcement, as decided: family-keyed, memoized last-write-wins at the serialize class emit,
family classifier derived from class-vocab + the defineTheme token registry, opt-in in 8.2.0 and
default-on in 9.0.0. This census is the fleet diff gate: every one of the 63 pairs should flip, and
the 125 winning pairs should not change. Deletes the guideline prose that warns about preset
overrides.
