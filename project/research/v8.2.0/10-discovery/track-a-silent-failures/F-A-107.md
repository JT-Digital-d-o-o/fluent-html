# Drawer close-on-nav reads htmx-2 event detail

## Problem
`onAfterSwap` closes an open drawer on navigation when either the swap target contains the drawer or the swap pushed a URL:

```ts
const swapTarget = e.target instanceof Element ? e.target : null;
const pushUrl: unknown = d?.ctx?.pushUrl ?? d?.pushUrl;
if (contains || (pushUrl != null && pushUrl !== false)) closeDrawer();
```

Both inputs are htmx-2 assumptions. htmx 4's detail is `{ ctx }` with the key `ctx.push`, never `pushUrl`; and htmx 4 dispatches `htmx:after:swap` on `ctx.sourceElement` (the clicked link), so `e.target` is the trigger, not the swapped region. The pushUrl gate can never fire, and the contains gate tests the wrong element. `closeOn` defaults to including `"nav"`, so every drawer promises this.

## Evidence (executed)
`node probe.mjs D` (Chromium, fluent-behaviors.8.1.0.js + each bundle). Drawer opened by its carrier; a link inside the drawer does a `.nav()`-shaped swap (`hx-target="#main-content" hx-swap="outerMorph" hx-push-url="true"`); the drawer lives outside `#main-content`:

| | a7 | b4 | b6 | ga |
|---|---|---|---|---|
| drawer open after nav | true | true | true | true |
| body `overflow-hidden` after nav | true | true | true | true |
| URL | /navpage | /navpage | /navpage | /navpage |
| after:swap `e.target.id` / `ctx.target.id` | in / main-content | in / main-content | in / main-content | in / main-content |
| `ctx.push` / `ctx.pushUrl` | "true" / undefined | same | same | same |
| control: swap replaces a region containing the drawer | closed, unlocked | same | same | same |

The control passes only through the reconciliation sweep (`drawer && !drawerOpen()`), because the drawer node was replaced. Acceptance row 10 ("pushUrl swap runs the FULL close routine", rows.spec.mjs:118) uses exactly that shape (`hx-target="#arena"`, arena contains the drawer, app.mjs:97-112), so it passes without the pushUrl gate ever running.

Fleet: `behavior("drawer"` appears in 1 htmx app (na-cent `app-shell.ts:395`), which keeps its sidebar inside `#main-content` ("the frame sits inside `#main-content`", app-shell.ts:426-427) and so rides the sweep; templates/web has no htmx. Any layout with the drawer in the shell and content in `#main-content` (the template's own layout split) gets a menu that stays open over the new page with scrolling locked.

## Why it matters
impact 2 (mobile nav covers the page and scroll is locked until Escape/backdrop), pain 3 (the matrix is green, the row that claims to cover it passes by another path), reach 1 (0 live layouts hit it today). Scorecard: silent-failure, evolvability. Guardrail S-13 counts `HTMX_EVENTS` as the runtime's only htmx literals; the detail shape is an htmx contract too and is unchecked.

## Rough idea (not a design)
Enforcement layer: runtime (asset) + ci row. Read `d.ctx.push` (and `d.ctx.target` for the contains check) with the htmx-2 keys as fallback only if a supported bundle still sends them; add a generated matrix row with the drawer outside the swapped region; add the detail keys to the F-A-101 oracle. Lane 8.1.x (runtime fix, no public shape change; S-21 requires the matrix to stay green).
