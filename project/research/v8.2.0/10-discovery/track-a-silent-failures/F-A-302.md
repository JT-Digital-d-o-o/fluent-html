# The hidden class loses to 15 of 20 display utilities; hide verbs and the merger's display family both break on it

## Problem

Tailwind 4.3.3 sorts same-property utilities by name, so the `hidden` utility (`display: none`) comes
after `block contents flex flow-root grid` and before `inline inline-block inline-flex inline-grid
inline-table list-item table table-caption table-cell table-column table-column-group table-footer-group
table-header-group table-row table-row-group`. Any element that carries one of those 15 classes cannot be
hidden by adding the `hidden` class.

The lib's own behavior runtime hides by adding that class: `toggle` (runtime.ts:212-218),
`onEscape`/`onClickOutside` with `action: "hide"` (`actOn`, runtime.ts:192-203). So a toggle whose target
has `.inlineFlex()`, `.inlineBlock()`, `.inline()`, `.inlineGrid()`, `.table()`, `.tableRow()` or
`.tableCell()` adds `hidden` and the element stays on screen. The `display?` option (L-248) only sets
`style.display` when showing; it does not help hiding. The acceptance fixtures toggle a bare `Div`
(fixtures.ts:25-28, app.mjs:98-99), so 0/69 matrix rows exercise it.

The same ordering splits the decided merger (F-A-301) on the display family:
- SSR conditional hide written after a display class never hides today, and last-write-wins would fix it:
  gzs/stem-50 `TierBadge` (evaluation.score.view.ts:282-294) is `.inlineBlock() ... .when(!earned, t =>
  t.hidden())`, documented as "All three tiers are rendered, only the earned one visible"; its client verb
  `jt:scoreSlider` re-picks by toggling the same class (score-slider.ts:34).
- `hidden` written before a display class works today only because `hidden` sorts after `flex`, and
  last-write-wins would drop it: everyframe-composer studio.components.ts:780-803 renders a listbox menu
  `.hidden() ... .flex().flex("col")` behind `.behavior("toggle")` and `onClickOutside` hide; a merged
  render would open the menu on page load. 13 more pre-7 sites in renderbox share the shape.

Fleet (static, same census as F-A-301): display-family pairs canonical 4 dead + 5 luck, pre-7 15 dead + 29
luck. Of the dead: 1 never-hides (stem-50 above), 3 layout overrides that lose (`inline-flex` -> `flex`,
everyframe home.view.ts:901; `inline-block` -> `block`, workshop-toni story.done.view.ts:39), and 14
`hidden`-first chains that a display-family last-write merge would un-hide (everyframe-composer 1,
renderbox 13). Hide-verb targets (`toggle`, `onEscape`/`onClickOutside` hide) joined to their `setId`
elements: 95 canonical + 40 pre-7 targets, 0 carry a hidden-beating display utility today.

The robust primitive already exists: Tailwind preflight (preflight.css:396-398) ships
`[hidden]:where(:not([hidden='until-found'])) { display: none !important; }`, which beats every display
utility; fluent emits the attribute through `.toggle("hidden")`.

## Why it matters

impact 3: a hide that does not hide (unearned badges, menus, panels) is visible wrong state; in the
runtime case it is the library's own verb. pain 3: tsc, eslint, extractor, Tailwind build, dev runtime
and the 69-row acceptance matrix are all green. reach 1: 1 live site and 0 of 135 hide-verb targets
today, but any `.inlineFlex()` badge or `.tableRow()` row put behind `toggle` hits it, and the merger
build (F-A-301) needs a decision here before it can pass its own fleet diff gate, whose premise ("every
delta should be one of today's bugs") is false for the 14 hidden-first sites. Hurts silent-failure,
invariant-safety (verb contract vs class vocabulary) and verification-loop.

## Rough idea (not a design)

Runtime layer: in the three hide paths set the `hidden` attribute alongside the class, and clear both
when showing (SSR `.hidden()` markup stays valid; the wire grammar and the 10 verbs are unchanged, so
S-21 holds if the matrix stays green). Add matrix rows for `toggle` on `inline-flex` and `table-row`
targets. For the merger, keep `hidden` out of the display family (it is a runtime state class the lib's
verbs flip) so hidden-first markup renders as today, and teach conditional hiding as `.toggle("hidden",
cond)` via the existing typed attribute path rather than new prose.
