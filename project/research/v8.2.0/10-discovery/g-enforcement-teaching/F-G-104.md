# Taught output comments disagree with rendered output

## Problem

The corpus annotates code with what it emits: `// id="user-list"`, `// ✓ [anchor-name:--user-menu]`, `// <ins cite datetime>`. Agents copy those strings into selectors, tests, CSS and safelists. No layer checks them. 28 such lines were rendered against dist 8.1.0 (template verbs via tsx). 8 are false. 4 more behavioral sentences are refuted by executing them.

## Evidence (executed)

**False output claims (8).**
- **README.md:157** `Div().setId(ids.userList) // id="user-list"` → `<div id="userList"></div>`.
- **README.md:158** `// hx-target="#user-list"` → `hx-target="#userList"`.
  - Why: `defineIds` keeps a camelCase key verbatim. Only kebab keys map: `defineIds(["user-list"]).userList.id === "user-list"`.
  - An agent that hand-writes `#user-list` in CSS, a test or `addAttribute("hx-target", …)` misses silently.
- **gl/htmx.md:610** `// ✓ [anchor-name:--user-menu]` → `style="anchor-name: --userMenu"`.
- **gl/htmx.md:612** `// ✓ [position-anchor:--user-menu] position-area-bottom` → `style="position-anchor: --userMenu; position-area: bottom"`.
- **gl/fluent-html.md:474-476** (the same three class claims) → inline style.
- **gl/fluent-html.md:248** `// ✓ [view-transition-name:…]` → `style="view-transition-name: heroImage"`. It does work: Chromium computes `viewTransitionName` = "hero" on both bundles.
- Since 6.1.1 (CHANGELOG.md:524) these 4 methods are not class-vocab rows (classVocab lookup: 0 of 4).

**Refuted behavioral claims (4).**
- **gl/htmx.md:614**: "the tailwind-extractor classifies those two classes as **unresolved** — safelist them in the build". `generateFluentSafelist` on the taught snippet (`anchorName(ids.userMenu)`, `positionAnchor(ids.userMenu).positionArea("bottom")`) returns `/* fluent-html: no render-time classes found */` with 0 unresolved rows. There is nothing to safelist.
- **gl/fluent-html.md:249**: `Img().addAttribute("style", "view-transition-name: hero") // ✗ untyped inline style, not purge-safe`. The ✓ line above it renders the same `style` attribute. The contrast describes pre-6.1.1 bytes.
- **gl/CLAUDE.md:231**: "`(t: Tag)` widens the return and breaks the chain". tsc: `Button("Go").apply((t: Tag) => t.p("4").bg("primary")).setType("submit")` compiles clean, because `apply(...fns: ((tag: this) => unknown)[]): this` (dist/src/core/tag.d.ts:217).
- **gl/htmx.md:215**: "the endpoint is a route callable, a `.resolve()`, …". `Button("Load").hxGet(itemRoutes.list)` → TS2345. Forced past tsc, it emits the function's source text into `hx-get`.

**Claims that hold (20):** `command`/`commandfor`, `popover="auto"`, `formmethod`, `closedby`, `hx-ignore`, `<li id="42">`, `hx-disable="this"` / `"findAll button"`, `data-user-id`, `[mask-repeat:no-repeat]`, `ins`/`del`/`q`/`blockquote` `cite`/`datetime`, `<div>Hello</div>`.

## Why it matters

impact 2 × pain 2 × reach 2 / S. Output comments are the most copyable text in a snippet. A wrong one yields a selector that matches nothing, or safelist work for classes that do not exist. The (t: Tag) sentence is the stated reason for a rule, and it is false. Hurts decision-closure (the docs argue for a rule with a wrong fact) and context-economy (paragraphs that direct dead work).

## Rough idea (not a design)

The strongest layer is **ci**: an output-assertion pass in the [[F-G-101]] lane. For ✓ lines whose trailing comment states emitted markup (`<tag …>`, `attr="…"`, `[prop:…]`, a class list), render the line (lib + template verbs) and substring-compare. Prose deleted outright:
- gl/htmx.md:614 (safelist paragraph)
- the rationale clause in gl/CLAUDE.md:231
- the "route callable" clause at gl/htmx.md:215
- gl/fluent-html.md:249 (the ✗ line is lint-held by `prefer-set-method` anyway)
