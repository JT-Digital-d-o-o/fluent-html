# Taught ✗ f.input(name, "checkbox"|"radio") is held by no layer

## Problem

gl/fluent-html.md:133 teaches "use `f.checkbox(name, value?)` / `f.radio(name, value)`, never `f.input(name, \"checkbox\")`" and shows `f.input("notify", "checkbox") // ✗ silently emits value="true", never checked`. The description is accurate. Nothing enforces the rule: the typed binding accepts the input type, the lint has no rule, and the runtime emits a control that forgets its state.

## Evidence (executed)

- `Form<{ notify: boolean; plan: "free" | "pro" }>({ values: { notify: true, plan: "pro" } }, (f) => [f.input("notify", "checkbox"), f.input("plan", "radio")])` in the template:
  - tsc: 0 diagnostics
  - eslint (plugin 4.1.0, template config): 0 messages
  - render: `<input id="notify" type="checkbox" name="notify" value="true">` and `<input id="plan" type="radio" name="plan" value="pro">`, with no `checked`. A saved `true`/`"pro"` re-renders unchecked.
  - `f.checkbox("notify")` renders `… checked`.
- Fleet (rg, node_modules/.claude/dist excluded): 10 `f.input(…, "checkbox"|"radio")` sites. 7 are in everyframe-composer (canonical era), 3 in pre-7 storysell repos. The comparison is 124 `f.checkbox`/`f.radio` sites in 81 files.
  - 3 everyframe sites re-implement `f.radio` by hand: `.setValue(x).toggle("checked", x === draft.formula)` (projects.new.view.ts:105, studio.voice.view.ts:171, studio.template.view.ts:138).
  - library.picker.view.ts:329 sets no `checked`.

## Why it matters

impact 2 × pain 2 × reach 2 / M. A preference or radio selection silently resets on every server re-render (422, morph). The taught "never" is violated 10 times in the fleet and caught 0 times. Hurts silent-failure and decision-closure (two ways to bind a checkbox, one broken).

## Rough idea (not a design)

The strongest layer is **type**: `FormBinding.input`'s input-type parameter excludes `"checkbox" | "radio"`, for example via an overload whose parameter type is a branded message naming `f.checkbox(name)` / `f.radio(name, value)`. Narrowing a public signature is breaking, so this goes in 9.0.0 with a codemod: 10 sites, where `f.input(n, "radio").setValue(v).toggle("checked", …)` maps to `f.radio(n, v)`. An 8.2.0 lint rule can hold it until then. Prose deleted: gl/fluent-html.md:133's "never" clause and the :136 ✗ line.
