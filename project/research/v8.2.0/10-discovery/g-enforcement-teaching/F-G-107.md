# README teaches Styler, which the lib does not export; the reason given for it is false

## Problem

README.md §7 is headed "…`.when` / `.whenElse` / `.whenMatch` + `Styler`" (:203) and shows `const card: Styler = (t) => t.p("6")…` (:211). `Styler` is a template type (`src/shared/stylers.ts:7`: `export type Styler = <T extends Tag>(t: T) => T`), not a fluent-html export. gl/CLAUDE.md:231 mandates it: "never a hand-written `(t: Tag) => …` … `(t: Tag)` widens the return and breaks the chain". fluent-html/CLAUDE.md:250 marks the hand-written `(t: Tag)` preset ✓.

## Evidence (executed)

- The export walk (TS checker over `fluent-html` root) has 335 names. `Styler` is not among them, and not in any of the 10 subpath exports.
- The README snippet compiled against bare fluent-html 8.1.0 fails with `TS2304: Cannot find name 'Styler'.` and `TS7006: Parameter 't' implicitly has an 'any' type.`
- In the template, `const ctaTag = (t: Tag) => t.p("4").bg("primary"); Button("Go").apply(ctaTag).setType("submit")` compiles with 0 diagnostics, because `apply` returns `this` (tag.d.ts:217). The chain does not break, so the stated reason for the rule is false against 8.1.0.

## Why it matters

impact 1 × pain 2 × reach 2 / S. The README head is the package's only shipped prose, and blind agents read it. Its styling section names a type they cannot import. The rule that pushes `Styler` rests on a false fact, and the two CLAUDE.md copies give opposite verdicts. Hurts decision-closure.

## Rough idea (not a design)

The strongest layer is **type**: export `type Styler` and `StylerFor<T>` from the lib root (types only, additive, 8.2.0). The README then compiles bare, and the template deletes `src/shared/stylers.ts:7-9`, which L-165 already proposed. Delete the chain-break clause at gl/CLAUDE.md:231 either way. If the export is declined, remove `Styler` from README §7 and let [[F-G-101]]'s README lane hold it.
