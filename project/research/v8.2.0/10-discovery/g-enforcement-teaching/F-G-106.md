# The guidelines write Span(n) with a number 7 times; the lib rejects it and drops it

## Problem

The teaching corpus reaches for a number child whenever it shows a count:
- `export function UserCount(p: { n: number }) { return Span(p.n).setId(ids.userCount); }  // ✓` (gl/views.md:109)
- `Span(n).fragment(ids.userCount, userRoutes.count())  // ✓` (gl/CLAUDE.md:289, gl/htmx.md:9, :113)
- `reply.renderView(Partial(ids.navBadge, Span(n)), …) // ✓` (gl/fastify.md:204)
- `Span(count).fragment(…)` (gl/htmx.md:221, :361)

`View` is `Tag | string | RawString | View[]` (types.d.ts:4, restated at gl/fluent-html.md:517), so tsc rejects all of these. The runtime is worse than the type. A number that reaches `render` through `any`, JSON or JS is dropped without a trace, because serialize.ts:362 says "Unknown view kind → emit nothing".

## Evidence (executed)

- tsc, gl/views.md:109 verbatim in the scaffolded template: `TS2345: Argument of type 'number' is not assignable to parameter of type 'View'.` The message does not name `String(n)`.
- Render, dist 8.1.0:
  - `Span(5)` → `<span></span>`
  - `Td(3.5)` → `<td></td>`
  - `Span("a", 7, "b")` → `<span>a\n\nb</span>`
  - no throw, no dev warning
- Prior evidence from the fleet (rg, node_modules/.claude/dist excluded): 627 call sites convert by hand. 432 are `Factory(String(x))`, 191 are ``Factory(`${x}`)``, 4 are `.toString()`. The guideline authors, themselves agents, wrote the unconverted form 7 times.

## Why it matters

impact 2 × pain 2 × reach 3 / S. Counts, prices and totals are in every app. The type forces a conversion the prior does not make: the docs' authors miss it 7 of 7 times and the fleet pays it 627 times. The runtime turns the untyped path into a blank cell. Hurts prior-alignment and silent-failure.

## Rough idea (not a design)

The strongest layer is **type + runtime**: ship the accepted L-025. Add `number` to `View` and stringify it in serialize (and in the stream path). This is additive, so 8.2.0. The runtime half fixes behavior that never worked, so it could go in 8.1.x. The 7 taught lines then become correct as written, and ~627 `String()` wrappers become optional; converge says keep one form, a codemod question. If the lib change is declined, the fallback is to fix the 7 lines and let [[F-G-101]]'s lane hold them. Prose deleted: none required.
