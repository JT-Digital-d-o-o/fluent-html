# README's Form<T> example drops every field after the first

## Problem

README.md §3 "Typed forms" teaches:

```typescript
Form<CreateUserReq>(                     // T = the controller's request type — import it
  f => f.input("email").setType("email"),    // "emial" would be a compile error
  f => f.input("password").setType("password"),
)
```

`Form` has three overloads: `(...children)`, `(build)` and `(state, build)` (src/elements/forms.ts:532-536). The runtime dispatch (forms.ts:539-541) takes `args[0]` as the builder whenever it is a function and ignores the rest. So the taught call renders only the first field, with no throw and no dev warning. tsc rejects the call, but its message points at the wrong fix.

## Evidence (executed)

- `render(Form(f => f.input("email").setType("email"), f => f.input("password").setType("password")))` against dist 8.1.0 → `<form><input id="email" type="email" name="email"></form>`. The password input is missing.
- `tsc -p tsconfig.probe.json` in the scaffolded template, with `type CreateUserReq = { email: string; password: string }`:
  - `TS7006 Parameter 'f' implicitly has an 'any' type` ×2
  - `TS2560: Value of type '(f: any) => any' has no properties in common with type 'FormState<CreateUserReq>'. Did you mean to call it?`
  - The suggested fix (call it) is wrong. The real fix is one builder returning an array: `Form<SignInReq>((f) => [ … ])`, which is how the template's exemplar is written (templates/full-stack/src/app/auth/sign-in/login.view.ts:40).
- Fleet: 518 files call `Form<T>(`; `rg -U` for the two-builder shape finds 0. The defect has not spread yet.
- Exposure: the README is the package's only shipped prose. Both blind recon runs read it twice (recon 02 §2.2).

## Why it matters

impact 3 (a form field vanishes; a login or register form posts without its password) × pain 2 × reach 2 / S. The Form<T> API has 446 builder sites fleetwide. The README is the first thing a blind agent reads. Any JS or `as any` path that gets past tsc ships the silent drop.

## Rough idea (not a design)

- Fix README.md:167-170 to `Form<CreateUserReq>((f) => [f.input("email").setType("email"), f.input("password").setType("password")])`.
- Runtime layer: in `Form()`, dev-throw when `typeof args[0] === "function" && args.length > 1`, with a message that names the array form. This is an 8.1.x change: it only affects a call shape that never worked.
- The README compile lane ([[F-G-101]]) keeps it fixed.
- Prose deleted: none needed. The comment "`emial` would be a compile error" becomes true once the example compiles.
