# No lane compiles the 203 taught TypeScript blocks: 24 ✓/unmarked lines fail tsc

## Problem

The teaching corpus is 8 files with TypeScript fences: 203 blocks, 1,201 lines, 161 ✓ lines, 137 ✗ lines. No test in fluent-html, projects-template or guidelines compiles any of them. The template's meta test skips fences by construction (`guidelines-enforcement.test.ts:90`), and `guidelines-tokens.test.ts` runs a palette regex only. So a taught line that stopped compiling (or never did) stays taught. 24 ✓/unmarked lines in 7 of the 8 files fail tsc today.

## Why it matters

impact 2 × pain 2 × reach 3 / M. Every guided agent loads gl/CLAUDE.md (26,230 vs 6,651 starting tokens, recon 02). Blind agents read the README 2× per run. A taught line that fails tsc costs a fix cycle whose TS message names no fix (TS2560 suggests calling the builder), or is silently wrong at runtime (#1, #18). This is the `Partial()` shape one layer up: taught, tsc-clean in nobody's CI, never executed. Hurts decision-closure (✓ code the compiler refutes), context-economy (a ✗ line that restates a tsc/lint rule is paid prose) and verification-loop.

## Rough idea (not a design)

The strongest layer is **ci**:
- A template root test extracts every ```typescript fence from `.ai/web-development/**` + root CLAUDE.md, auto-imports fluent-html + template names, declares free identifiers, and compiles in the scaffold tsconfig.
- ✓ and unmarked lines must have 0 semantic diagnostics. ✗ lines must draw at least 1 tsc or template-lint hit, and a quoted error text must appear in the chain.
- A lib twin does the same for README fences against `dist/`.

Prose this lets us delete: the 48 ✗ lines the lane proves tsc- or lint-held can shrink to one pointer per rule. The "✗ compile error" narration becomes an assertion. The ✗ lines that no layer holds become a measured list for the enforcement ledger.
