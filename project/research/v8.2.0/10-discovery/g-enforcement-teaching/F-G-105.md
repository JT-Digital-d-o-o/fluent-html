# prefer-set-method's hand-kept map leaves 64 typed setters unenforced

## Problem

The corpus teaches "never `addAttribute` for standard props" per attribute, for example:
- gl/fluent-html.md:500: "Typed `cite`/`datetime` setters — never `addAttribute` for these"
- :466: "don't also `addAttribute(\"headers\", …)`"
- ✗ `addAttribute("popover", "auto")` at gl/CLAUDE.md:339, gl/htmx.md:603, fluent-html/CLAUDE.md:317
- ✗ `addAttribute("closedby", "any")` at gl/htmx.md:595

The rule meant to hold this is `prefer-set-method`. Its attribute → setter map (`ATTRIBUTE_TO_METHOD`, prefer-set-method.ts:5) is a hand-written list of 86 entries. It does not re-derive from the lib the way the extractor and eslint class tables re-derive from vocab rows (guardrail 9's spirit). Every setter added since the list was written is unenforced.

## Evidence (executed)

- **Runtime walk of 8.1.0.** Every exported element factory's prototype chain has 158 `set*` names.
  - 86 are map targets. All 86 exist, so the map is not stale, only short.
  - `setTabindex` is special-cased (:139).
  - 64 remain unmapped: `setAbbr setAs setAutocapitalize setCapture setCite setClosedby setCommand setCommandfor setContenteditable setDatetime setDecoding setDir setEnterkeyhint setFetchPriority setForm setHeaders setHidden setHigh setImagesizes setImagesrcset setIntegrity setKind setLang setLow setMedia setNonce setOptimum setPopover setPopovertarget setPopovertargetaction setSpellcheck setSrcdoc setSrclang setTranslate setX setY` and 27 SVG presentation setters.
- **Lint probe** (`a.ts`, template config, plugin 4.1.0):
  - `addAttribute("popover"|"closedby"|"cite"|"datetime"|"headers"|"popovertarget"|"commandfor"|"fetchpriority", …)`: **0 messages** on all 8, and tsc is clean too.
  - Only `"tabindex"` and `"type"` draw `prefer-set-method` (`Use .setTabindex(n) instead of .addAttribute("tabindex", …)`).
- **Snippet lint run ([[F-G-101]]):** the 4 taught ✗ `addAttribute("popover"|"closedby")` lines pass lint and tsc.

## Why it matters

impact 2 × pain 1 × reach 3 / S. Every template app runs this lint (template eslint.config.mjs enables 25 of the plugin's 32 rules). The pure prior routes attributes through `addAttribute` (23-30 calls per pure-prior run, recon 02 D5), and only the mapped subset gets redirected. Prose repeats the rule attribute by attribute because the lint does not carry it. Hurts decision-closure (two ways stay open for 64 attributes) and context-economy.

## Rough idea (not a design)

The strongest layer is **lint**: generate `ATTRIBUTE_TO_METHOD` from the lib's setter surface, for example a gen artifact emitted beside the vocab or produced by a runtime walk like the one here, mapping the attribute name to the setter. The eslint plugin then consumes it instead of hand-editing. Special cases (aria/data/style/tabindex) stay as they are. Prose deleted:
- gl/fluent-html.md:500 (the "never addAttribute" sentence)
- the `addAttribute("headers")` clause at :466
- the 4 ✗ `addAttribute("popover"|"closedby")` lines
- the "Specialized tag methods" ✗ example in both CLAUDE.md copies can shrink to a lint pointer
