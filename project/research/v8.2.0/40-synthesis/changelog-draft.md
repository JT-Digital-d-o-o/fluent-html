## 8.1.1

### Security

- **Every URL fluent hands to htmx is scheme-sanitized, and no `data:` URL reaches an htmx sink.** The request endpoint (`hx-get`, `hx-post`, …), `hx-push-url`, `hx-replace-url`, a status bag's `push`/`replace`, and `hxResponse().redirect()`, `.pushUrl()`, `.replaceUrl()` and `.location()` now pass the setters' sanitizer, with one stricter rule: at these sinks every `data:` URL becomes `about:blank`, because htmx fetches it and swaps the body in as HTML whatever its media type. Without a CSP, 8.1.0 ran attacker script in 87 of 138 measured cells (`hx(externalUrl("javascript:…"))`, `.redirect("javascript:…")`, a `data:image/png,<img onerror>` endpoint, …); 8.1.1 runs it in 0 of the 132 cells these sinks cover. A status `push`/`replace` string is also percent-encoded for whitespace, `,` and quotes, so it can no longer carry a second HCON key: `push: "/ok text:'<script>…'"` replaced the response body even under the template CSP (6/6). Values without such characters emit the same bytes: 0 changed in 92,038 instrumented serializations across 14 live repos. (RFC-A-05)
- - **A JSON-typed script body carries no `<`.** `sanitizeRawContent` rewrote only `</script`, so data holding `<!--<script>` in an `application/ld+json`, `application/json`, `importmap` or `speculationrules` body put the tokenizer in its double-escaped state: the real `</script>` stopped closing the element and the rest of the page became script text (20/32 payload and type pairs per engine on Chromium 149, Firefox 151 and WebKit 26.5; body children 0, no error anywhere). A script whose type (set by `setType`, else the attribute bag) is `importmap`, `speculationrules` or a JSON MIME type (`application/json`, `text/json`, any `+json` subtype) now gets every `<` written as `<`, which parses to the same value (32/32 per engine; 18,752/18,752 parse-identical in a parse5 fuzz). This also fixes a JSON string holding `</SCRIPT>`, which 8.1.0 parsed back lowercased. JS, module and style bodies keep the closer-only rule, byte-identical, and code that already escapes `<` (25 fleet helpers) renders byte-identical. (RFC-A-06)

### Fixed

- ### 📖 Fixed: `setClosedby("any")` docs name the Safari gap

The `setClosedby` and `ClosedBy` JSDoc and REFERENCE.md called `closedby="any"` the replacement for hand-rolled backdrop handling. Safari 27 ships no `closedby`: Playwright WebKit 26.5 leaves the dialog open after a backdrop click, while Chromium 149 and Firefox 151 close it. The docs now teach the pairing that closes it on all three: an inner panel carrying `.behavior("onClickOutside", { action: "click", target: <close button id> })`, where the close button is `setCommand("close")`. Style the panel, not the `Dialog`: a click on the dialog's own padding counts as outside the panel and closes it. (C-67)

- ### ✨ Added: `setClassMerge(theme)`, an opt-in merge where the later class of a family wins

- **Off by default.** With no call every emitted byte equals 8.1.0.
- **A family** is the class's selector shape plus its exact CSS property set under the pinned Tailwind 4.3.3, per variant chain. `p-6 p-4` merges; `px-8 p-6`, `border-b border-line` and `text-lg text-primary` stay. - **Never merged:** `hidden`, cross-prefix pairs, important classes, and unknown words (`cssClass("h-captcha").h("12")` keeps both). Raw-sink tokens that are real utilities are merged.
- **The theme is the registry** (`text-danger` is a color, `text-display` a size). `setClassMerge(true)` is a type error: without the registry 31 of 108 dead pairs stay broken. `setClassMerge(false)` turns it off.
- **Storage is untouched:** `getClass()` still returns every write.
- **Boundary:** a class a client behavior flips (`toggleClass`, clipboard `feedback.class`) loses its earlier same-family class as a fallback once merged (fleet sites today: 0).
- **Cost with the merge on:** x0.938 to x0.970 on per-request build+render, x1.072 on prebuilt renders, x0.271 on a page where every element has a unique class string. Import: +0.67 ms, +211 KB heap.
