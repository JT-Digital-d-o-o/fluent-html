## c2-class-surface

- **lib/tw-check.ts:50 (BracketKind "multi") against tools/gen-grammar.mjs KINDS.multi "[0_0_2px]"**: The "multi" kind matches any value that starts with a number and has an underscore, but the generator probed only `[0_0_2px]`. The kind is open on border* and outline*, so `border-[1px_solid_var(--brand)]`, `border-t-[2px_dashed_var(--x)]` and `border-[1px_var(--x)]` compile. Tailwind writes them as `border-color: 1px solid var(--brand)`, an invalid declaration that paints nothing, and the variable is not a theme colour. It fails silent, not open on the palette, since nothing is painted. Probe a v3-style shorthand such as `[1px_solid_#123456]` per root, or narrow multi to all-length values.
- **lib/tw-check.ts:33 (Num) on TwNumRoot spacing roots; TextSize `${TextSize}/${string}`**: Small type-side over-acceptances that Tailwind has no rule for: spacing steps that are not multiples of 0.25 (`p-0.3`, `mt-1.3`) and any line-height name after a text size (`text-sm/foo`). None of these is a likely mistake.
- **lib/tw-check.ts CheckBase arbitrary property arm**: A misspelled property name in an arbitrary property compiles in plain mode (for example `[dispaly:flex]`). Tailwind writes a rule for it, but the declaration does nothing. This is a follow-up for the lint layer or a property list.
- **lib/tw-grammar.gen.ts TwFuncRoot (filter, backdrop-filter), same root cause**: filter and backdrop-filter also became open bracket roots in 7de7097. A drop-shadow colour outside the theme now compiles through them, although drop-shadow-[…] and [filter:…] refuse the same value. The fix is to add filter and backdrop-filter to the painted set (read in colour mode, as ColourProperty already does for `filter`).
- **lib/tw-check.ts Num / SplitOk on TwNumRoot, and `text` with `${TextSize}/${string}`**: Some real-looking numeric spellings compile with no CSS rule (TW-1 failing open on edge cases). Num accepts anything TS reads as `${number}`, and the text line-height modifier is any string.
- **lib/tw-check.ts (fraction roots) / tools/gen-grammar.mjs**: False negative with a wrong message. Tailwind 4's ratio spelling aspect-3/2 (the docs' own example) and aspect-16/9 are refused as "not a Tailwind class". aspect is missing from TwFracRoot.
- **lib/tw-check.ts CheckBase ColourMiss (split choice in the message)**: When a token fails every split, the first line names a misleading split, so an agent cannot act on the text.
- **lib/tw-check.ts LiteralOnly message / classes.ts cls.token**: TW-4's fix text tells the agent "one class from data is cls.token(value)". That steers a computed class such as `bg-${tone}` into cls.token, which checks nothing against the theme. Tailwind's scan cannot see the computed class, so the element renders with a class that has no rule and is silently unstyled.
- **out/check-time-preview.tsv**: No preview row at HEAD. The last rows are d3249f4, taken before 7de7097 enlarged TwFuncRoot (244 roots), which every SplitOk step reads. Load averages were 55 to 147 on 10 cores during every recorded run.
- **lib/tw-check.ts: SplitOk's TwFuncRoot arm (Arbitrary) and Variant**: Some bracket, paren and container-variant spellings get the wrong answer. A paren value that is not a variable compiles (`w-(180px)`), and so does an empty bracket (`p-[]`, `w-[]`). Container queries are inverted: `@-[400px]:flex` compiles with no rule, while Tailwind's own `@[400px]:flex` is refused. Named containers are refused too (`@container/main`, `@md/main:flex`).
- **lib/tw-grammar.gen.ts / lib/tw-check.ts (fail-closed false negatives)**: Several classes that Tailwind 4.3.3 still compiles are refused with `✗ '…' is not a Tailwind class`. That text is wrong and does not give the modern spelling, so an agent cannot act on it: `flex-shrink-0`, `flex-grow`, `break-words`, `overflow-ellipsis`, `start-0`, `end-0`, `aspect-4/3`, `bg-gradient-to-r`, `decoration-clone`, `bg-primary/(--alpha)`, `max-w-screen-lg`, `aria-foo:`. `flex-shrink-0` and `break-words` are very common in agent output. `start-0` and `end-0` fail because start and end are in TwNegRoot but not TwNumRoot.
- **lib/tw-check.ts CheckBase / ColourMiss on overlapping colour roots**: On a root that is also a prefix of another colour root, the message names the wrong split. `cls("text-shadow-[0_1px_0_red]")` reads `✗ 'text-shadow-[0_1px_0_red]': 'shadow-[0_1px_0_red]' after 'text-' is not a colour`, which treats it as a text colour instead of a shadow colour. ColourMiss gives a union over every split, and tsc shows the first member.
- **lib/tw-check.ts ClassShaped / Shaped (TW-6)**: Class text given as a string child is read as content in a few shapes. Tokens split by a newline or a tab are not split (`div("flex\ngap-4")`). An arbitrary-property token is not class-shaped (`div("[color:red] p-4")`), and neither is a leading `!` (`div("!p-4 flex")`). These are rare, but each renders class names as visible text.
- **lib/classes.ts LiteralOnly message, cls.token, exported Cls constructor**: The TW-4 fix text sends an agent to an unchecked path. It says "one class from data is cls.token(value)", so the natural fix for `cls(`bg-${tone}/20`)` is `cls.token(`bg-${tone}`)`. That accepts any plain token (`cls.token("bg-gray-100")` compiles and renders), and Tailwind's scanner never sees the class, so it gets no rule. `new Cls("bg-gray-100")` also compiles with no cast. Both predate c2 (the baseline had cls.token and the same hint), so this is a follow-up for the out-of-scope table or for wording that points at a Record<…, Cls> table first.
- **lib/tw-check.ts:296-305 (ClassShaped / AllShaped)**: TW-6 splits tokens only on ' ', so class text with a newline or tab used as a string child is read as text. The common multi-line template form (newline right after the backtick) and `flex\n  gap-4` both compile with no cls(). cls() itself accepts multi-line lists (probe cl-lines), so dropping cls() from one of them is a plausible mistake. It fails open, but only on this spelling.
- **lib/tw-check.ts:269-271 (Chk splits on newline or tab only after the whole token fails) and Arbitrary at line 30**: If two classes are joined by a bare newline (an unindented continuation line) or a tab, and both the first and the last of them end in ']', the whole run passes as one bracket value of the first root. The split never happens, so the second class is not checked. At run time merge() splits on \s+ and renders it, including a palette colour.
- **lib/index.ts:2 (export { Cls, … })**: Cls is exported as a value, so new Cls("bg-gray-100") forges a class list that skips the grammar. Forge row 5 (registered: tsc refuses with "Property 'Cls' does not exist") stays open. Rows 1, 6 and 7 (El, Url, Trusted) are open the same way, so this belongs to the later brand chunk. `Record<Status, Cls>` needs only `export type { Cls }`. The attribute is escaped at classAttr, so the forge is not an XSS.
- **lib/tw-check.ts messages and grammar coverage (refused, so these fail closed)**: Some refusals give text an agent cannot act on, or refuse valid v4 classes. bg-[var(--color-primary)], ring-(--color-primary) and similar read "is not a colour" when the value is a theme colour; the fix is bg-primary. shadow-[inset_0_0_0_1px_var(--color-line)] reads "is not a colour". aspect-4/3, aspect-16/9 and break-words read "is not a Tailwind class", though Tailwind 4.3.3 writes rules for them. shadow-lg/20 and @[400px]: are refused. [mask-image:linear-gradient(to_bottom,black,transparent)] is refused while mask-[…] with the same value compiles.
- **tools/gen-theme.mjs:44**: When a theme resets a namespace other than colour (for example --radius-*: initial, as fluent-html apps close the radius scale), the grammar still accepts Tailwind's default scale (rounded-lg, text-sm, md:). - **lib/tw-check.ts CheckToken, first arm (T extends `!${infer R}`)**: A leading `!` is stripped before the variants, so `!md:p-4` is accepted. Tailwind 4.3.3 has no rule for it (the important mark goes after the variants or at the end). This is an uncommon spelling, so it is a follow-up.
- **lib/tw-check.ts Arbitrary / Variant (`[${string}]`, `@-[…]`, `group-…/${string}`)**: Empty or malformed brackets and modifiers are accepted although Tailwind has no rule for them: `w-[]`, `p-[]`, `data-[]:flex`, `aria-[]:flex`, `group-[]:flex`, `min-[]:flex`, `group-hover/:flex`, `@-[400px]:flex`, and `-bg-linear-[1px]`. All of them are crafted or unlikely, so this is a follow-up. A systematic sweep of every TwFuncRoot with [1px], [center], [2], [50%], (--x) and [var(--x)] found no other false positive.
- **lib/tw-check.ts SplitOk (TwFuncRoot arm on non-colour roots)**: The Tailwind v3 variable shorthand is accepted on non-colour roots: `w-[--sidebar]`, `h-[--header]`, `p-[--gap]`. Tailwind 4 writes `width: --sidebar`, which the browser drops. The oracle emits a rule, so this is not a grammar false positive by the spec's measure.
